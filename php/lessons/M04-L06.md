## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam ekosistem PHP yang terus berevolusi (terutama sejak transisi PHP 7 ke PHP 8.x), manajemen *Deprecation* (penyusutan fitur) dan *Backward Compatibility* (BC / kompatibilitas mundur) adalah pilar utama dalam rekayasa perangkat lunak skala enterprise. 

**Siklus Hidup Fitur PHP:**
1. **Active**: Fitur direkomendasikan dan didukung penuh.
2. **Deprecated**: Fitur ditandai usang. Zend Engine akan memancarkan (emit) `E_DEPRECATED` (dari core PHP) atau `E_USER_DEPRECATED` (dari *userland code*). Kode masih berjalan, tetapi developer diperingatkan.
3. **Removed**: Fitur dihapus sepenuhnya pada rilis mayor berikutnya (mengakibatkan `Fatal Error` jika dipanggil).

**Mengapa Deprecation Ada?**
Deprecation adalah mekanisme *graceful degradation*. Alih-alih langsung merusak aplikasi (breaking changes) saat pembaruan versi, PHP memberikan masa transisi (biasanya 1-2 minor version) agar developer dapat memigrasikan *codebase* mereka.

**Strategi Backward Compatibility (BC):**
Untuk menjaga agar kode dapat berjalan di berbagai versi PHP (misal: library open-source), engineer menggunakan teknik:
- **Polyfilling**: Menyediakan implementasi *userland* dari fungsi bawaan PHP yang baru untuk versi PHP yang lebih lama.
- **Feature Detection**: Memeriksa ketersediaan fungsi/kelas di runtime alih-alih bergantung pada versi PHP secara hardcode.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi komprehensif menangani deprecation, membuat polyfill, dan memancarkan deprecation di *userland*.

```php
<?php

declare(strict_types=1);

/**
 * KASUS 1: Polyfilling (Backward Compatibility)
 * Mensimulasikan fungsi `json_validate` (baru di PHP 8.3) untuk PHP < 8.3
 */
if (!function_exists('json_validate')) {
    function json_validate(string $json, int $depth = 512, int $flags = 0): bool {
        if ($flags !== 0 && $flags !== JSON_INVALID_UTF8_IGNORE) {
            throw new ValueError('json_validate(): Argument #3 ($flags) must be a valid flag');
        }
        json_decode($json, null, $depth, $flags);
        return json_last_error() === JSON_ERROR_NONE;
    }
}

/**
 * KASUS 2: Menangani PHP Core Deprecation (Dynamic Properties di PHP 8.2+)
 * Menggunakan Attribute untuk transisi yang aman tanpa memicu E_DEPRECATED
 */
#[\AllowDynamicProperties]
class LegacyDataTransferObject {
    public string $id;
    
    // Properti dinamis akan diizinkan di class ini tanpa memicu E_DEPRECATED di PHP 8.2
}

/**
 * KASUS 3: Memancarkan Userland Deprecation
 * Memberitahu pengguna library bahwa metode ini akan dihapus di versi v2.0
 */
class PaymentGateway {
    /**
     * @deprecated Gunakan processPayment() sebagai gantinya. Akan dihapus di v2.0.
     */
    public function charge(float $amount): bool {
        // Memancarkan warning ke log, tapi eksekusi tetap berlanjut
        trigger_error(
            'Method ' . __METHOD__ . ' is deprecated since v1.5, use processPayment() instead.',
            E_USER_DEPRECATED
        );
        
        return $this->processPayment($amount);
    }

    public function processPayment(float $amount): bool {
        // Logika pemrosesan pembayaran modern
        return true;
    }
}

// --- Pengujian ---

// 1. Test Polyfill
$isValid = json_validate('{"key": "value"}'); 
echo $isValid ? "Valid JSON\n" : "Invalid JSON\n";

// 2. Test Legacy DTO
$dto = new LegacyDataTransferObject();
$dto->id = "123";
$dto->dynamic_field = "Ini tidak akan memicu E_DEPRECATED di PHP 8.2 berkat Attribute"; 

// 3. Test Userland Deprecation
$gateway = new PaymentGateway();
// Akan mencetak E_USER_DEPRECATED ke error log atau output (tergantung konfigurasi php.ini)
$gateway->charge(100.00); 
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: 
  Saat Zend Engine menemui kode yang *deprecated*, ia akan membuat *opcode* khusus atau memicu fungsi internal `php_error_docref()` dengan level `E_DEPRECATED`. Jika `error_reporting` di `php.ini` dikonfigurasi untuk menyembunyikan `E_DEPRECATED` (misal: `error_reporting = E_ALL & ~E_DEPRECATED`), pesan tidak akan dikirim ke *SAPI (Server API)*, tetapi *overhead* pengecekan di level C (Zend Engine) tetap terjadi.
- **Alokasi Memori / Resource**: 
  Memancarkan ribuan `E_DEPRECATED` dalam satu *request lifecycle* (misalnya di dalam *loop* besar) akan secara drastis meningkatkan konsumsi I/O (jika di-log ke disk) dan memori. Ini sering menjadi penyebab utama degradasi performa aplikasi *legacy* saat di-upgrade ke versi PHP baru tanpa penyesuaian kode.
- **Trade-offs**: 
  Menulis kode yang 100% *Backward Compatible* (mendukung PHP 7.4 hingga 8.3) membutuhkan banyak blok `if/else` (seperti `version_compare`) dan *polyfills*. Ini meningkatkan ukuran *codebase* dan kompleksitas *Cyclomatic*. Trade-off-nya adalah stabilitas versus kebersihan/modernitas kode.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan **Rector** (berbasis AST) untuk melakukan *upgrade* kode secara otomatis (misal: mengubah array `[]` lama, menghapus fungsi usang).
  - Gunakan **PHPStan** atau **Psalm** untuk mendeteksi pemanggilan fungsi/metode yang *deprecated* secara statis sebelum kode masuk ke *production*.
  - Buat *Error Handler* khusus di lingkungan CI/CD (Testing) yang mengubah `E_DEPRECATED` menjadi `ErrorException`. Ini memaksa tim untuk memperbaiki *deprecation* agar *pipeline* bisa hijau (lulus).
- **Don'ts**:
  - **JANGAN PERNAH** menggunakan *Error Control Operator* (`@`) seperti `@deprecated_function()`. Di balik layar, operator `@` mengubah status `error_reporting` menjadi 0 sebelum eksekusi fungsi, lalu mengembalikannya lagi. Ini sangat lambat dan menyembunyikan *Fatal Error* jika terjadi di dalam fungsi tersebut.
  - Jangan mengabaikan file `UPGRADING` dan `UPGRADING.INTERNALS` di repositori resmi PHP saat merencanakan migrasi versi.
- **Edge Cases**:
  - Perubahan perilaku diam-diam (*Silent behavior changes*). Terkadang fungsi tidak di-*deprecate*, tetapi perilakunya berubah (misal: fungsi pengurutan `usort` di PHP 8.0 yang sekarang stabil / *stable sort*). *Unit test* adalah satu-satunya jaring pengaman di sini.

### 5. Tantangan Eksplorasi Mandiri

1. **Custom Error Handler**: Tulis sebuah fungsi menggunakan `set_error_handler()` yang menangkap `E_DEPRECATED` dan `E_USER_DEPRECATED`, lalu mencatatnya ke dalam file `deprecations.log` khusus tanpa menghentikan eksekusi script.
2. **Polyfill Challenge**: Fungsi `str_contains()` diperkenalkan di PHP 8.0. Tulis sebuah *polyfill* yang aman dan efisien untuk fungsi ini agar kode Anda bisa berjalan di PHP 7.4, menggunakan `strpos()`.
3. **Static Analysis Integration**: Instal `phpstan/phpstan-deprecation-rules` via Composer pada proyek PHP Anda, lalu jalankan analisis untuk menemukan penggunaan fungsi bawaan PHP yang sudah usang.
