### 1. Konsep & Arsitektur Mendalam

Composer bukan sekadar manajer dependensi deklaratif; di dalamnya terdapat subsistem otomasi berbasis *event-driven architecture*. Composer Scripts dan Automation Hooks menyediakan mekanisme bagi developer untuk mengeksekusi logika kustom—baik berupa instruksi shell CLI maupun eksekusi fungsi PHP statis—pada tahapan siklus hidup (*lifecycle*) Composer.

```
+-----------------------------------------------------------------------+
|                           Composer CLI                                |
|  (e.g., composer install / update / dump-autoload / run-script)       |
+-----------------------------------+-----------------------------------+
                                    |
                                    v
+-----------------------------------------------------------------------+
|             EventDispatcher (Composer\EventDispatcher)                |
|  1. Menangkap Lifecycle Hook (misal: post-autoload-dump)              |
|  2. Membaca konfigurasi dari root composer.json ["scripts"]           |
+-----------------------------------+-----------------------------------+
                                    |
         +--------------------------+--------------------------+
         |                                                     |
         v (Tipe 1: Shell / CLI Command)                       v (Tipe 2: PHP Static Callback)
+---------------------------------+           +---------------------------------+
|   ProcessExecutor (proc_open)   |           |    call_user_func / Reflection  |
| - Sub-proses OS terisolasi      |           | - Berjalan di runtime Composer  |
| - Platform dependent            |           | - Akses ke Composer Context     |
| - Eksekusi bin/tool eksternal   |           | - Autoloader dependency aktif   |
+---------------------------------+           +---------------------------------+
```

#### Arsitektur EventDispatcher
Composer mengimplementasikan `Composer\EventDispatcher\EventDispatcher`. Saat sebuah perintah seperti `composer install` dipanggil, alur kerjanya memicu serangkaian event secara kronologis:

1. **Command Events**: Memicu hook sebelum dan sesudah perintah Composer dijalankan (misal: `pre-install-cmd`, `post-install-cmd`, `pre-update-cmd`, `post-update-cmd`).
2. **Installer Events**: Memicu hook saat paket diekstraksi, diperbarui, atau dihapus (misal: `pre-package-install`, `post-package-install`).
3. **Autoload Events**: Dipicu saat generator autoloader selesai mengompilasi peta kelas (misal: `pre-autoload-dump`, `post-autoload-dump`).
4. **Custom Scripts / Aliasing**: Perintah buatan sendiri (misal: `composer test`, `composer phpstan`) yang menggabungkan beberapa instruksi shell ke dalam satu alias.

#### Mode Eksekusi: CLI Command vs. PHP Callback
Composer mendukung dua paradigma eksekusi dalam skripnya:
- **CLI Commands (Shell Strings)**: String perintah shell mentah (seperti `phpunit` atau `@php artisan cache:clear`). Composer akan mengeksekusinya melalui sub-proses menggunakan abstraksi `Symfony\Component\Process` atau kelas internal `Composer\Util\ProcessExecutor`.
- **PHP Callbacks (Static Methods)**: Berupa string yang mereferensikan kelas dan metode statis yang dapat dipanggil: `"Namespace\\Class::method"`. Composer memanggilnya langsung di dalam runtime PHP yang sedang aktif menjalankan Composer, memberikannya akses ke instance `Composer\Script\Event`, manipulasi I/O terminal secara terprogram, dan akses ke konfigurasi internal paket.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi konfigurasi `composer.json` yang memadukan script alias kustom, automasi siklus hidup, dan integrasi class hook berbasis PHP.

#### File: `composer.json`
```json
{
    "name": "enterprise/automation-suite",
    "type": "project",
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    },
    "autoload-dev": {
        "psr-4": {
            "App\\Tests\\": "tests/",
            "App\\Build\\": "build/"
        }
    },
    "scripts": {
        "quality:lint": "phpcs --standard=PSR12 src/",
        "quality:analyze": "phpstan analyse src/ --level=max",
        "test": "phpunit --colors=always",
        "check-all": [
            "@quality:lint",
            "@quality:analyze",
            "@test"
        ],
        "post-autoload-dump": [
            "App\\Build\\DeploymentHooks::postAutoloadDump"
        ],
        "post-install-cmd": [
            "@php -r \"file_exists('.env') || copy('.env.example', '.env');\""
        ]
    },
    "scripts-descriptions": {
        "check-all": "Menjalankan seluruh pipeline validasi kode: Linting, Static Analysis, dan Unit Tests."
    }
}
```

#### File: `build/DeploymentHooks.php`
```php
<?php

declare(strict_types=1);

namespace App\Build;

use Composer\Script\Event;
use Composer\IO\IOInterface;

final class DeploymentHooks
{
    /**
     * Hook yang dieksekusi otomatis setelah autoloader di-dump.
     * Menerima instance Composer\Script\Event untuk interaktivitas runtime.
     */
    public static function postAutoloadDump(Event $event): void
    {
        $io = $event->getIO();
        $composer = $event->getComposer();
        
        $io->write("<info>[Hook] Memulai post-autoload-dump automation...</info>");

        // Mengecek apakah Composer dijalankan dalam mode dev
        $isDevMode = $event->isDevMode();
        $io->write(sprintf("<comment>[Hook] Environment context: %s</comment>", $isDevMode ? 'Development' : 'Production'));

        // Contoh: Validasi integritas environment lokal
        self::verifyEnvironmentSetup($io);

        // Contoh: Ekstraksi konfigurasi paket
        $rootPackage = $composer->getPackage();
        $io->write(sprintf("<info>[Hook] Paket Aktif: %s v%s</info>", $rootPackage->getName(), $rootPackage->getPrettyVersion()));
    }

    private static function verifyEnvironmentSetup(IOInterface $io): void
    {
        $requiredExtensions = ['pdo', 'mbstring', 'intl'];
        $missing = [];

        foreach ($requiredExtensions as $ext) {
            if (!extension_loaded($ext)) {
                $missing[] = $ext;
            }
        }

        if (!empty($missing)) {
            $io->writeError(sprintf(
                "<error>[Critical] Ekstensi PHP berikut wajib diinstal: %s</error>",
                implode(', ', $missing)
            ));
            
            // Menghentikan siklus Composer secara eksplisit dengan exit code bukan 0
            exit(1);
        }

        $io->write("<info>[Hook] Seluruh ekstensi PHP prasyarat terpenuhi.</info>");
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
1. **Resolusi Eksekusi**:
   Saat Composer membaca blok `"scripts"`, ia memvalidasi apakah string tersebut merupakan static call method PHP (`is_callable`) atau sub-process execution.
   - Jika method PHP terdeteksi, Composer memerlukan file tersebut sudah ter-autoload. Inilah sebabnya mengapa static script callback **tidak dapat** dipanggil pada hook `pre-install-cmd` jika dependensi autoloader belum di-generate untuk pertama kali.
   - Jika perintah shell dieksekusi, Composer memanggil fungsi `proc_open()` melalui `ProcessExecutor`. Lingkungan PATH sistem akan dievaluasi ulang, dan direktori `vendor/bin` secara otomatis ditambahkan ke variabel lingkungan `PATH` lokal proses tersebut, memungkinkan eksekusi binary (seperti `phpunit` atau `phpstan`) tanpa path absolut `vendor/bin/phpunit`.

2. **Macro `@php`**:
   Saat menggunakan `@php`, Composer mencari binary PHP yang persis sama dengan yang sedang mengeksekusi Composer saat itu menggunakan helper `PhpExecutableFinder`. Ini menjamin konsistensi versi runtime PHP CLI dan konfigurasi `php.ini` antara Composer dan skrip anak.

#### Alokasi Memori & Resource
- **PHP Static Callbacks**: Berjalan di dalam proses memori Composer yang sama. Jika Composer memiliki batas memori (`memory_limit`) sebesar 2GB, alokasi memori method statis berbagi alokasi heap dengan struktur objek Composer (seperti *dependency pool*, *package repository graph*). Objek besar yang ditinggalkan di memori oleh hook tidak akan dibersihkan hingga proses Composer selesai secara keseluruhan.
- **Sub-proses CLI**: Menghasilkan proses OS yang benar-benar baru via *forking* (POSIX) atau spawning subprocess (Windows). Alokasi memori Composer tidak terganggu oleh konsumsi memori script shell eksternal tersebut.

#### Trade-offs

| Aspek | CLI String Commands | PHP Static Method Callback |
| :--- | :--- | :--- |
| **Portabilitas OS** | Berisiko gagal di platform silang (Unix vs Windows pathing, syntax shell `&&` vs `;`). | **Cross-platform**: 100% konsisten selama engine PHP berjalan. |
| **Akses Konteks** | Terisolasi. Hanya bisa berkomunikasi via Argv, Stdout, Stderr, dan Exit Code. | Mendalam. Memiliki akses penuh ke instance internal Composer (`$event->getComposer()`). |
| **Dependency State** | Bisa dijalankan sebelum dependensi Composer terpasang sepenuhnya. | Bergantung pada availability `vendor/autoload.php`. |
| **Overhead** | Menimbulkan proses I/O OS baru via `proc_open`. | Cepat, in-memory execution via Zend VM direct dispatch. |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Prefix `@php`**: Selalu gunakan `@php bin/console ...` alih-alih `php bin/console ...`. Ini mencegah *binary mismatch* di server yang memiliki multi-versi PHP terpasang.
- **Gunakan `post-autoload-dump` untuk Operasi Cache/Proxy Generation**: Hook ini adalah titik paling aman dalam siklus Composer karena autoloader telah sepenuhnya dikompilasi, dependensi baru sudah terpetakan, tetapi proses instalasi secara formal belum ditutup.
- **Manfaatkan Event Aliasing**: Gabungkan perintah testing dan linting di bawah script alias kustom untuk memastikan seluruh engineer lokal dan continuous integration (CI) mengeksekusi parameter pengujian yang identik.

#### Don'ts
- **Jangan Letakkan Operasi Berbahaya/Destruktif di Hook Otomatis**: Jangan pernah menaruh migrasi database (`doctrine:migrations:migrate`) langsung pada `post-install-cmd` tanpa flag konfirmasi non-interaktif atau validasi environment. Hal ini dapat merusak database staging atau production saat deployment tanpa pengawasan.
- **Jangan Mengandalkan Autoload di Hook `pre-*`**: Hindari memanggil callback PHP kustom pada hook `pre-install-cmd` atau `pre-update-cmd`, karena class autoloader mungkin belum ada (pada instalasi pertama) atau berada dalam kondisi *out-of-sync*.

#### Edge Cases
- **Pemberian Flag `--no-scripts` di Pipeline Docker/CI**:
  Dalam optimasi build Docker multi-stage, `composer install --no-scripts --no-autoloader` sering dijalankan terlebih dahulu untuk memanfaatkan *layer caching*. Hook siklus hidup Anda **tidak akan dieksekusi** pada tahap ini. Pastikan arsitektur aplikasi tidak bergantung sepenuhnya pada hook Composer agar container dapat dibangun dengan benar.
- **Argumen Dinamis (`--`)**:
  Composer mendukung penerusan argumen ke script kustom menggunakan delimiter `--`.
  Contoh: `composer test -- --filter UserTest`. Pastikan script Anda tidak menabrak parsing argumen bawaan jika meneruskan input dinamis.

### 5. Tantangan Eksplorasi Mandiri

1. **Membuat Automated Git Pre-commit Symlinker**:
   Buat sebuah class static hook PHP yang terdaftar pada event `post-install-cmd`. Hook ini harus mendeteksi apakah direktori `.git/hooks` ada di root project. Jika ada, salin atau lakukan symlink script bash dari direktori `bin/git-hooks/pre-commit` ke `.git/hooks/pre-commit` secara cross-platform (tangani perbedaan Windows symlink privilege dan Unix file permissions).
   
2. **Pendeteksi Drift Dependencies**:
   Implementasikan custom script Composer `"analyze:unused"` yang memanfaatkan static callback. Didalamnya, baca metadata dependensi langsung dari instance `$event->getComposer()->getPackage()->getRequires()` dan bandingkan dengan token AST dari direktori `src/` untuk mendeteksi dependensi di `composer.json` yang tidak pernah di-*import* dalam namespace kode.
