### 1. Konsep & Arsitektur Mendalam

Fitur unggah berkas (*file upload*) merupakan salah satu vektor serangan paling kritis pada aplikasi web modern. Serangan umum mencakup **Remote Code Execution (RCE)** lewat eksekusi skrip berbahaya (misalnya mengunggah web shell `.php`), **Cross-Site Scripting (XSS)** via payload berkas format SVG/HTML, **Local File Inclusion (LFI)** atau **Directory Traversal** lewat manipulasi nama berkas, hingga **Denial of Service (DoS)** akibat konsumsi disk/memori berlebih (misalnya *decompression bomb* atau berkas berukuran raksasa).

Secara arsitektural, pengamanan berkas membutuhkan pendekatan berlapis (*defense-in-depth*):

```
[ Klien (HTTP Multipart) ]
          │
          ▼
[ Web Server (Nginx/Apache) ]  ──► Batasan payload kasar (client_max_body_size)
          │
          ▼
[ PHP SAPI Engine ]            ──► Parsing RFC 1867, validasi php.ini, alokasi temp file
          │
          ▼
[ Application Layer ]
  ├── 1. Validasi Error Code ($_FILES['error'])
  ├── 2. Validasi Batasan Ukuran ($size)
  ├── 3. Inspeksi Magic Bytes / MIME Asli (ext/fileinfo via libmagic)
  ├── 4. Sanitasi/Regenerasi Identitas Berkas (UUID/Random Byte + Strict Extension Mapping)
  ├── 5. Content Sanitization (Re-encoding gambar via GD/Imagick)
          │
          ▼
[ Isolated Storage ]           ──► Di luar Document Root / Object Storage (S3) tanpa hak eksekusi
```

#### Mengapa Client-Side MIME Type Tidak Dapat Dipercaya?
Ketika berkas diunggah, peramban mengirimkan header multipart:
```http
Content-Disposition: form-data; name="avatar"; filename="shell.php"
Content-Type: image/jpeg
```
Nilai `Content-Type` ini diteruskan langsung oleh PHP ke array superglobal `$_FILES['avatar']['type']`. Nilai ini **murni input pengguna** yang dapat dimanipulasi dengan mudah via proxy seperti Burp Suite atau cURL.

Validasi yang aman harus mengabaikan `$_FILES['avatar']['type']` dan ekstensi asli berkas secara parsial. Sebagai gantinya, aplikasi wajib membaca **Magic Bytes** (*file signature*) langsung dari bitstream berkas fisik di disk menggunakan ekstensi `fileinfo` (`finfo`), yang memanfaatkan pustaka sistem `libmagic`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern menggunakan PHP 8.2+ yang menerapkan enkapsulasi verifikasi berkas, pemetaan MIME-ke-ekstensi yang ketat (*allowlist*), serta isolasi penyimpanan.

```php
<?php

declare(strict_types=1);

namespace App\Security;

use RuntimeException;
use InvalidArgumentException;
use finfo;

enum AllowedMimeType: string
{
    case JPEG = 'image/jpeg';
    case PNG  = 'image/png';
    case WEBP = 'image/webp';
    case PDF  = 'application/pdf';

    /**
     * Petakan MIME type yang divalidasi ke ekstensi yang aman.
     * Mencegah eksploitasi double-extension atau null-byte.
     */
    public function safeExtension(): string
    {
        return match ($this) {
            self::JPEG => 'jpg',
            self::PNG  => 'png',
            self::WEBP => 'webp',
            self::PDF  => 'pdf',
        };
    }
}

final class SecureFileUploader
{
    private finfo $finfo;

    public function __construct(
        private readonly string $storageDirectory,
        private readonly int $maxFileSizeInBytes = 2 * 1024 * 1024 // 2MB
    ) {
        if (!is_dir($this->storageDirectory) && !mkdir($this->storageDirectory, 0750, true)) {
            throw new RuntimeException("Gagal menginisialisasi direktori penyimpanan aman.");
        }

        // Inisialisasi libmagic database
        $this->finfo = new finfo(FILEINFO_MIME_TYPE);
    }

    /**
     * Memproses dan menyimpan berkas yang diunggah secara aman.
     *
     * @param array{
     *     name: string,
     *     type: string,
     *     tmp_name: string,
     *     error: int,
     *     size: int
     * } $fileArray Representasi satu item dari $_FILES
     * @return string Path absolut berkas yang tersimpan
     */
    public function upload(array $fileArray): string
    {
        // 1. Validasi error status bawaan PHP SAPI
        $this->assertUploadSuccess($fileArray['error']);

        // 2. Cegah LFI/Arbitrary File Insertion via mekanisme internal PHP
        if (!is_uploaded_file($fileArray['tmp_name'])) {
            throw new InvalidArgumentException("Berkas tidak valid atau bukan diunggah via POST multipart.");
        }

        // 3. Batasi ukuran berkas fisik
        if ($fileArray['size'] > $this->maxFileSizeInBytes || filesize($fileArray['tmp_name']) > $this->maxFileSizeInBytes) {
            throw new InvalidArgumentException("Ukuran berkas melebihi batas maksimum ({$this->maxFileSizeInBytes} bytes).");
        }

        // 4. Verifikasi MIME type menggunakan Magic Bytes (bukan dari $_FILES['type'])
        $detectedMime = $this->finfo->file($fileArray['tmp_name']);
        if ($detectedMime === false) {
            throw new RuntimeException("Gagal mendeteksi signature berkas.");
        }

        $mimeEnum = AllowedMimeType::tryFrom($detectedMime);
        if ($mimeEnum === null) {
            throw new InvalidArgumentException("Tipe berkas '{$detectedMime}' tidak diizinkan.");
        }

        // 5. Sanitasi tambahan: Jika berupa raster image, verifikasi integritas data
        if (in_array($mimeEnum, [AllowedMimeType::JPEG, AllowedMimeType::PNG, AllowedMimeType::WEBP], true)) {
            $this->validateImageIntegrity($fileArray['tmp_name'], $mimeEnum);
        }

        // 6. Buat nama berkas baru yang acak (kriptografis) & pasang ekstensi yang terpercaya
        $randomFileName = sprintf(
            '%s.%s',
            bin2hex(random_bytes(16)),
            $mimeEnum->safeExtension()
        );

        $destination = $this->storageDirectory . DIRECTORY_SEPARATOR . $randomFileName;

        // 7. Pindahkan berkas dari temporary directory dengan fungsi atomic move
        if (!move_uploaded_file($fileArray['tmp_name'], $destination)) {
            throw new RuntimeException("Gagal memindahkan berkas yang diunggah ke tujuan akhir.");
        }

        // 8. Terapkan least-privilege permission (Read/Write hanya oleh user web server)
        chmod($destination, 0640);

        return $destination;
    }

    private function assertUploadSuccess(int $errorCode): void
    {
        match ($errorCode) {
            UPLOAD_ERR_OK => null,
            UPLOAD_ERR_INI_SIZE, UPLOAD_ERR_FORM_SIZE => throw new InvalidArgumentException("Ukuran berkas melampaui batasan konfigurasi."),
            UPLOAD_ERR_PARTIAL => throw new InvalidArgumentException("Berkas hanya terunggah sebagian."),
            UPLOAD_ERR_NO_FILE => throw new InvalidArgumentException("Tidak ada berkas yang diunggah."),
            UPLOAD_ERR_NO_TMP_DIR => throw new RuntimeException("Direktori temporary sistem hilang."),
            UPLOAD_ERR_CANT_WRITE => throw new RuntimeException("Gagal menulis berkas ke disk."),
            UPLOAD_ERR_EXTENSION => throw new RuntimeException("Proses unggah dihentikan oleh ekstensi PHP."),
            default => throw new RuntimeException("Kesalahan unggah yang tidak diketahui (Code: {$errorCode})."),
        };
    }

    /**
     * Memastikan payload gambar bukan polyglot (misal: kode PHP disisipkan dalam EXIF/data JPEG)
     */
    private function validateImageIntegrity(string $filePath, AllowedMimeType $type): void
    {
        // getimagesize membaca struktur header gambar secara parsial
        $imageInfo = @getimagesize($filePath);
        if ($imageInfo === false) {
            throw new InvalidArgumentException("Berkas gambar corrupt atau termanipulasi.");
        }

        // Opsional: Untuk keamanan absolut terhadap PHP-polyglot,
        // render ulang citra untuk melenyapkan payload pada EXIF metadata:
        /*
        $img = match($type) {
            AllowedMimeType::JPEG => @imagecreatefromjpeg($filePath),
            AllowedMimeType::PNG  => @imagecreatefrompng($filePath),
            AllowedMimeType::WEBP => @imagecreatefromwebp($filePath),
            default => null,
        };
        if ($img === false) {
            throw new InvalidArgumentException("Citra gagal di-decode.");
        }
        imagejpeg($img, $filePath, 85); // Tulis ulang citra bersih
        imagedestroy($img);
        */
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Alur RFC 1867 di Engine PHP
1. **SAPI Parsing:** Saat web server (misal: PHP-FPM) menerima request `POST` ber-header `multipart/form-data`, PHP langsung mem-parse stream tersebut sebelum script user berjalan.
2. **Spooling Disk:** PHP membaca stream byte per byte. Bagian non-file dimasukkan ke `$_POST`. Konten berkas di-stream langsung ke direktori sementara (`sys_get_temp_dir()` atau konfigurasi `upload_tmp_dir`) dengan nama unik berformat `phpXXXXXX`.
3. **Internal Hash Table Registration:** Engine PHP mendaftarkan path temporary tersebut ke tabel internal SAPI: `SG(rfc1867_uploaded_files)`.
4. **Fungsi `is_uploaded_file()` & `move_uploaded_file()`:**
   - `is_uploaded_file()` mengecek langsung apakah path berkas terdaftar di hash table `SG(rfc1867_uploaded_files)`. Hal ini mencegah penyerang mengarahkan `$fileArray['tmp_name']` ke berkas sensitif sistem seperti `/etc/passwd`.
   - `move_uploaded_file()` melakukan pemeriksaan hash table internal tersebut, lalu memanggil *system call* `rename()` (atau copy-and-unlink jika melintasi filesystem partition/mount point berbeda) dan menghapus entri dari hash table agar path tersebut tidak bisa digunakan dua kali.

#### Alokasi Memori / Resource
- Unggahan berkas di PHP **tidak membebani `memory_limit`** skrip secara langsung karena engine tidak memuat seluruh berkas ke memori PHP (RAM). PHP melakukan buffer streaming langsung dari socket web server ke disk (`upload_tmp_dir`).
- Namun, skrip dibatasi oleh `post_max_size` (total seluruh body POST) dan `upload_max_filesize` (per berkas individu). Jika berkas melebihi batasan ini, PHP SAPI mengabaikan parsing berkas tersebut dan mengisi `$_FILES['avatar']['error']` dengan `UPLOAD_ERR_INI_SIZE`.

#### Trade-offs: Static Analysis vs. Content Re-Encoding
- **Magic Bytes Verification (libmagic):** Cepat dan efisien (hanya membaca ~128 byte pertama berkas), tetapi rentan terhadap **Polyglot Attacks** (berkas valid sebagai gambar JPEG, namun memiliki payload script PHP valid di dalam chunk metadata EXIF/Comment).
- **Image Re-Encoding (GD / Imagick):** Menghancurkan seluruh struktur metadata non-standar, secara efektif menetralkan polyglot webshell. **Trade-off:** Membutuhkan alokasi RAM yang besar untuk parsing uncompressed pixel buffer (misal: 4K PNG memerlukan puluhan Megabyte RAM) serta meningkatkan konsumsi CPU.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Simpan di Luar Document Root:** Selalu letakkan folder unggahan di luar folder web public (misal di `/var/app/storage/`, bukan `/var/app/public/storage/`). Akses berkas via route controller menggunakan output streaming (`readfile()` atau `fpassthru()`) dengan header kontrol akses yang ketat.
- **Header Keamanan Saat Serving Berkas:**
  ```http
  Content-Disposition: attachment; filename="document.pdf"
  X-Content-Type-Options: nosniff
  Content-Type: application/pdf
  ```
  `X-Content-Type-Options: nosniff` memblokir peramban untuk menebak tipe berkas jika ada inkonsistensi MIME.
- **Isolasi Partisi:** Jika memungkinkan, mount direktori unggahan dengan flag `noexec` pada fstab OS untuk memblokir eksekusi binary langsung di level kernel.

#### Don'ts
- **Jangan Menggunakan Nama Berkas Pengguna:** Jangan pernah menggunakan `$_FILES['file']['name']` asli pada storage. Karakter seperti `../../`, *null-byte* (`%00`), atau format UTF-8 tersembunyi dapat menyebabkan path traversal atau overwrite berkas sistem.
- **Jangan Percayai Format SVG:** SVG pada dasarnya adalah dokumen XML. Mengizinkan unggahan berkas SVG berarti membuka celah **Stored XSS** (via tag `<script>`) dan **XML External Entity (XXE)** injection. Perlakukan SVG layaknya file `.html` berbahaya kecuali diproses melalui parser/sanitizer XML khusus (*DOMPurify/svg-sanitizer*).
- **Hindari Blacklist Extension:** Jangan menggunakan pendekatan blacklist seperti melarang `.php`, `.phtml`, atau `.exe`. Penyerang dapat membypass dengan `.php7`, `.phps`, `.pht`, atau file override konfigurasi seperti `.htaccess` atau `.user.ini`.

#### Edge Cases
- **Double Extensions:** Berkas bernama `payload.php.png`. Jika server Apache dikonfigurasi buruk dengan modul mime yang membaca ekstensi dari kanan ke kiri, berkas ini bisa dieksekusi sebagai script PHP. Solusinya: Hapus seluruh ekstensi bawaan dan gantikan secara deterministik via hasil resolusi MIME libmagic.
- **File Injection via Temp Directory:** Jika direktori sistem temporary (`/tmp`) memiliki permission publik dan penyerang memiliki akses Local File Inclusion (LFI), penyerang dapat memanggil temporary file sebelum PHP menghapusnya di akhir lifecycle eksekusi script. Tetapkan `upload_tmp_dir` ke lokasi terisolasi dalam direktori aplikasi.

### 5. Tantangan Eksplorasi Mandiri

1. **Uji Penetrasi Polyglot PHP-JPEG:** Buat berkas gambar valid menggunakan tools manipulasi EXIF (`exiftool -Comment='<?php phpinfo(); ?>' image.jpg`). Verifikasi apakah class `SecureFileUploader` di atas mendeteksi berkas tersebut sebagai `image/jpeg`. Uji bagaimana pemanggilan fungsi GD (`imagecreatefromjpeg`) menetralkan script tersebut.
2. **Implementasi Streaming Secure Downloader:** Buat sebuah controller PHP yang membaca berkas dari direktori privat, melakukan validasi hak akses user (authorization check), lalu mengalirkan berkas tersebut menggunakan *chunked buffer transfer* (`fopen()`, `fread()`, `fpassthru()`) tanpa memuat seluruh berkas ke memori PHP. Bandingkan profil penggunaan memorinya saat membaca berkas berukuran 500MB.
