## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam PHP, memproses dataset berukuran masif (seperti file log jutaan baris atau jutaan *record* dari database) menggunakan *array* tradisional akan memicu *Fatal Error: Allowed memory size exhausted*. Hal ini terjadi karena *array* memuat seluruh data ke dalam RAM secara bersamaan.

**Generators** hadir sebagai solusi elegan untuk masalah ini melalui konsep **Lazy Evaluation**. Generator menyediakan cara mudah untuk mengimplementasikan *iterators* tanpa *overhead* atau kompleksitas dalam membuat kelas yang mengimplementasikan *interface* `Iterator`. 

Secara arsitektur, fungsi generator terlihat seperti fungsi biasa, namun alih-alih melakukan `return` satu kali, fungsi ini menggunakan *keyword* `yield` berkali-kali. Setiap kali `yield` dipanggil, fungsi akan mengembalikan nilai ke *caller*, lalu **menjeda (pause)** eksekusinya, menyimpan seluruh *state* (variabel lokal, *pointer* instruksi), dan akan **melanjutkan (resume)** dari titik tersebut saat nilai berikutnya diminta.

Generator di PHP pada dasarnya adalah **State Machine** yang diimplementasikan di level *engine* (Zend Engine).

### 2. Implementasi & Contoh Kasus Nyata

Kasus paling umum di industri adalah membaca file CSV berukuran raksasa (misal: 5GB) pada server dengan RAM terbatas (misal: 128MB).

```php
<?php
declare(strict_types=1);

/**
 * Membaca file CSV secara efisien menggunakan Generator.
 * 
 * @param string $file Path ke file CSV
 * @return Generator|iterable
 */
function readMassiveCsv(string $file): Generator 
{
    $handle = fopen($file, 'r');
    if (!$handle) {
        throw new RuntimeException("Gagal membuka file: $file");
    }

    try {
        // Membaca baris per baris, tidak pernah memuat seluruh file ke memori
        while (($data = fgetcsv($handle)) !== false) {
            // yield mengembalikan data dan menjeda eksekusi fungsi ini
            yield $data;
        }
    } finally {
        // Blok finally memastikan resource file selalu ditutup,
        // bahkan jika loop dihentikan lebih awal (break) oleh caller.
        fclose($handle);
    }
}

// Penggunaan:
// Memori yang digunakan akan tetap konstan (O(1)), terlepas dari ukuran file.
foreach (readMassiveCsv('data_transaksi_5GB.csv') as $index => $row) {
    // Proses data per baris
    // echo "Baris {$index}: " . $row[0] . "\n";
    
    if ($index === 1000) {
        break; // Generator akan otomatis memanggil blok finally dan menutup file
    }
}
```

**Contoh Lanjutan: Delegasi Generator (`yield from`) dan Pengembalian Nilai**

```php
<?php
function getActiveUsers(): Generator {
    yield 'Alice';
    yield 'Bob';
}

function getArchivedUsers(): Generator {
    yield 'Charlie';
    yield 'Dave';
}

function getAllUsers(): Generator {
    // yield from mendelegasikan iterasi ke generator/iterable lain
    yield from getActiveUsers();
    yield from getArchivedUsers();
    
    return "Semua user berhasil dimuat!"; // PHP 7+ mendukung return di Generator
}

$users = getAllUsers();
foreach ($users as $user) {
    echo $user . PHP_EOL;
}
// Mengambil nilai return setelah iterasi selesai
echo "Status: " . $users->getReturn() . PHP_EOL; 
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: Saat Anda memanggil fungsi generator (misal: `readMassiveCsv()`), Zend Engine **tidak mengeksekusi** kode di dalamnya. Ia hanya menginisialisasi dan mengembalikan objek internal dari kelas `Generator`. Eksekusi kode baru benar-benar dimulai ketika metode `next()` dipanggil secara implisit oleh konstruksi `foreach`. Saat bertemu `yield`, Zend Engine menyimpan *Instruction Pointer* (IP) dan *Call Frame* saat ini, lalu mengembalikan kontrol ke *caller*.
- **Alokasi Memori / Resource**: Pada fungsi biasa, variabel lokal dialokasikan di *Call Stack* dan dihancurkan saat fungsi selesai (`return`). Pada Generator, *Call Frame* (yang berisi variabel lokal) dialokasikan di **Heap Memory** agar *state*-nya bisa bertahan (persisted) di antara pemanggilan `yield`. Ini membuat penggunaan memori menjadi **O(1)** (konstan) terhadap jumlah data, bukan **O(N)**.
- **Trade-offs**: Meskipun sangat efisien secara memori, Generators memiliki *overhead* CPU (waktu eksekusi) yang sedikit lebih tinggi dibandingkan *array* biasa karena adanya proses *context switching* (jeda dan lanjut) yang berulang-ulang di level Zend Engine. Gunakan Generator untuk dataset besar, namun tetap gunakan *array* biasa untuk dataset kecil.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan tipe kembalian (Return Type) `Generator` atau `iterable` pada fungsi Anda.
  - Selalu gunakan blok `try...finally` di dalam generator jika Anda membuka *resource* eksternal (seperti koneksi database atau *file handle*). Ini menjamin *resource* ditutup jika *caller* melakukan `break` di tengah iterasi.
  - Gunakan `yield from` untuk meratakan (*flatten*) array multi-dimensi atau menggabungkan beberapa generator agar kode lebih deklaratif.

- **Don'ts**:
  - Jangan gunakan Generator jika Anda perlu mengakses data secara acak (*random access* seperti `$data[500]`). Generator bersifat *forward-only* (hanya maju).
  - Jangan mencoba melakukan iterasi ulang (*rewind*) pada Generator yang sudah mulai berjalan. PHP akan melempar `Exception: Cannot rewind a generator that was already run`.

- **Edge Cases**:
  - **Bi-directional Communication**: Generator di PHP tidak hanya bisa mengeluarkan data (`yield`), tapi juga bisa menerima data dari luar menggunakan metode `$generator->send($value)`. Ini adalah fondasi dari *Coroutines* dan *Asynchronous Programming* di PHP (seperti yang digunakan oleh framework Amp atau Swoole).

### 5. Tantangan Eksplorasi Mandiri

1. Buatlah sebuah fungsi generator `fetchDatabaseCursor(PDO $pdo, string $query)` yang mengeksekusi query SQL dan melakukan `yield` pada setiap baris hasil menggunakan `PDO::FETCH_ASSOC`, sehingga Anda bisa memproses jutaan baris dari database tanpa kehabisan memori.
2. Pelajari dan implementasikan konsep *Coroutine* sederhana: Buat generator yang melakukan `yield` sebuah tugas, lalu gunakan metode `$generator->send($hasil)` untuk mengirimkan hasil pemrosesan kembali ke dalam generator tersebut.
3. Buatlah generator yang membaca direktori log yang berisi ratusan file `.log`, lalu gunakan `yield from` untuk membaca isi setiap file secara berurutan seolah-olah mereka adalah satu aliran data (*stream*) tunggal.
