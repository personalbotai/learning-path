### 1. Konsep & Arsitektur Mendalam

Secara arsitektural, keamanan aplikasi web modern bergantung pada isolasi konteks eksekusi di sisi klien (*client-side sandbox*). Pondasi utamanya adalah **Same-Origin Policy (SOP)** yang diimplementasikan secara ketat oleh browser. Sebuah *origin* didefinisikan secara unik oleh triplet: **Skema/Protokol**, **Host/Domain**, dan **Port**. Jika salah satu elemen berbeda, browser menganggapnya sebagai konteks asing (*cross-origin*).

```
https://api.domain.com:443  vs  https://app.domain.com:443  --> Beda Origin (Subdomain beda)
http://domain.com:80        vs  https://domain.com:443      --> Beda Origin (Skema & Port beda)
```

SOP melarang dokumen atau skrip yang dimuat dari satu origin untuk membaca resource atau berinteraksi secara bebas dengan resource dari origin lain. Namun, arsitektur decoupled modern (misal: frontend SPA di S3/Cloudflare Pages dan backend API di PHP/Laravel/Symfony) menuntut interaksi cross-origin. Di sinilah **CORS (Cross-Origin Resource Sharing)** dan **HTTP Security Headers** berperan.

```
+------------------+         (1) OPTIONS (Preflight)          +--------------------+
|                  | ---------------------------------------> |                    |
|                  | <--------------------------------------- |                    |
|  Browser Client  |         (2) 204 No Content + CORS Header |  PHP Application   |
| (Origin: app.io) |                                          |  (Host: api.io)    |
|                  |         (3) Actual Request (POST/PUT)    |                    |
|                  | ---------------------------------------> |                    |
|                  | <--------------------------------------- |                    |
+------------------+         (4) 200 OK + Payload + Sec Headers +--------------------+
```

#### Mekanisme CORS: Simple Request vs Preflight
1. **Simple Request**: Request yang menggunakan method `GET`, `HEAD`, atau `POST` dengan `Content-Type` terbatas pada `application/x-www-form-urlencoded`, `multipart/form-data`, atau `text/plain`, serta tanpa custom headers. Browser langsung mengeksekusi request dan menyertakan header `Origin`. Server merespons, dan browser memeriksa apakah header `Access-Control-Allow-Origin` mengizinkan origin tersebut untuk membaca data respons.
2. **Preflight Request**: Jika request menggunakan method mutasi (`PUT`, `DELETE`, `PATCH`) atau membawa custom header (seperti `Authorization`, `X-Correlation-ID`) atau `Content-Type: application/json`, browser *wajib* mengirimkan request pendahuluan ber-method `OPTIONS` (*preflight*). Backend PHP harus merespons request `OPTIONS` ini dengan header izin eksplisit sebelum browser mengirimkan *actual request*.

#### HTTP Security Headers: Pertahanan Berlapis (Defense-in-Depth)
Selain CORS, browser membutuhkan instruksi deterministik dari PHP runtime untuk memitigasi vektor serangan umum:
- **Content-Security-Policy (CSP)**: Mengontrol resource (skrip, gaya, gambar, frame) yang diizinkan untuk dimuat dan dieksekusi oleh browser. Mitigasi utama untuk Cross-Site Scripting (XSS).
- **Strict-Transport-Security (HSTS)**: Memaksa browser hanya berkomunikasi via HTTPS, memitigasi serangan Man-in-the-Middle (MitM) dan SSL Stripping.
- **X-Content-Type-Options**: Mematikan fitur *MIME-type sniffing* browser (`nosniff`) yang sering dieksploitasi untuk mengeksekusi file non-executable sebagai skrip.
- **X-Frame-Options / CSP `frame-ancestors`**: Mencegah serangan *Clickjacking* dengan melarang halaman dirender di dalam `<iframe>`.
- **Referrer-Policy**: Mengontrol seberapa banyak informasi path/query yang bocor ke server pihak ketiga saat user menavigasi link keluar.
- **Permissions-Policy**: Membatasi akses peramban ke API perangkat keras (kamera, mikrofon, geolokasi).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern *middleware* keamanan berbasis PHP 8.2+ yang menangani kalkulasi origin dinamis, preflight short-circuiting, penanganan kredensial, dan injeksi *security headers*.

```php
<?php

declare(strict_types=1);

namespace Infrastructure\Http\Middleware;

use Closure;

/**
 * Class SecurityHeadersMiddleware
 * Menangani evaluasi CORS deterministik dan injeksi header keamanan HTTP.
 */
final readonly class SecurityHeadersMiddleware
{
    /**
     * @param array<string> $allowedOrigins Daftar origin eksplisit yang diizinkan
     * @param bool $isProduction Flag lingkungan deployment
     */
    public function __construct(
        private array $allowedOrigins = [
            'https://admin.example.com',
            'https://app.example.com',
        ],
        private bool $isProduction = true
    ) {}

    /**
     * Entry point pemrosesan request HTTP.
     *
     * @param array<string, mixed> $server Superglobal $_SERVER yang diabstraksi
     * @param Closure $next Pipeline eksekusi berikutnya
     * @return void
     */
    public function handle(array $server, Closure $next): void
    {
        $origin = $server['HTTP_ORIGIN'] ?? null;
        $requestMethod = strtoupper($server['REQUEST_METHOD'] ?? 'GET');

        // 1. Tangani Header Keamanan Global (Non-CORS)
        $this->applyGlobalSecurityHeaders();

        // 2. Evaluasi dan Terapkan Konfigurasi CORS
        if ($origin !== null) {
            $this->applyCorsHeaders($origin);

            // 3. Short-circuit Preflight Request (OPTIONS)
            if ($requestMethod === 'OPTIONS') {
                $this->terminatePreflightRequest();
                return;
            }
        }

        // Lanjutkan ke handler/controller berikutnya jika bukan preflight
        $next();
    }

    /**
     * Mengatur HTTP Security Headers untuk mitigasi serangan sisi klien.
     */
    private function applyGlobalSecurityHeaders(): void
    {
        // Cegah eksekusi MIME-sniffing
        header('X-Content-Type-Options: nosniff');

        // Mitigasi Clickjacking (Fallback untuk browser lama yang belum support CSP frame-ancestors)
        header('X-Frame-Options: DENY');

        // Kontrol privasi URL referer
        header('Referrer-Policy: strict-origin-when-cross-origin');

        // Matikan akses fitur hardware/device API yang sensitif
        header('Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=()');

        // Content Security Policy (CSP) ketat
        $csp = [
            "default-src 'self'",
            "script-src 'self'",
            "style-src 'self' 'unsafe-inline'", // Diizinkan inline jika menggunakan framework CSS tertentu
            "img-src 'self' data: https:",
            "font-src 'self'",
            "connect-src 'self' " . implode(' ', $this->allowedOrigins),
            "frame-ancestors 'none'",
            "base-uri 'self'",
            "form-action 'self'",
        ];
        header('Content-Security-Policy: ' . implode('; ', $csp));

        // HSTS (HTTP Strict Transport Security) - Hanya aktif di Production
        if ($this->isProduction) {
            // Berlaku 1 tahun, terapkan ke subdomain, dan registrasikan ke HSTS Preload list
            header('Strict-Transport-Security: max-age=31536000; includeSubDomains; preload');
        }
    }

    /**
     * Menghitung dan mengatur Access-Control-* headers secara dinamis.
     */
    private function applyCorsHeaders(string $clientOrigin): void
    {
        // Validasi Origin secara ketat (Strict In-Array Check)
        if (in_array($clientOrigin, $this->allowedOrigins, true)) {
            // Berikan izin hanya untuk origin yang cocok, BUKAN wildcard (*)
            header("Access-Control-Allow-Origin: {$clientOrigin}");
            
            // Wajib jika aplikasi menggunakan session cookie atau Authorization header
            header('Access-Control-Allow-Credentials: true');
            
            // Beritahu proxy/CDN bahwa respons bervariasi bergantung pada header Origin request
            header('Vary: Origin');
        } else {
            // Origin tidak terdaftar: Jangan kirim Access-Control-Allow-Origin
            // Browser akan memblokir payload secara otomatis
            return;
        }

        header('Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS');
        header('Access-Control-Allow-Headers: Content-Type, Authorization, X-Requested-With, X-Correlation-ID');
        header('Access-Control-Expose-Headers: Content-Length, X-Request-ID');
        
        // Cache preflight request di browser klien selama 10 menit (600 detik)
        // Mengurangi latency round-trip request berulang
        header('Access-Control-Max-Age: 600');
    }

    /**
     * Menghentikan siklus request untuk preflight OPTIONS secara instan.
     */
    private function terminatePreflightRequest(): void
    {
        http_response_code(204); // No Content
        header('Content-Length: 0');
        header('Content-Type: text/plain; charset=UTF-8');
        exit(0);
    }
}

// ============================================================================
// CONTOH INTEGRASI SIKLUS HIDUP REQUEST
// ============================================================================

$middleware = new SecurityHeadersMiddleware(
    allowedOrigins: [
        'https://dashboard.company.internal',
        'http://localhost:3000' // Local dev
    ],
    isProduction: false
);

$middleware->handle($_SERVER, function () {
    // Controller Logic
    header('Content-Type: application/json; charset=utf-8');
    echo json_encode([
        'status' => 'success',
        'message' => 'Data sensitif berhasil diakses lintas origin.',
    ], JSON_THROW_ON_ERROR);
});
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Zend Engine SAPI Header Buffer
Ketika fungsi `header()` dipanggil di PHP:
1. PHP tidak langsung mengirim baris string teks tersebut ke socket TCP.
2. Di dalam Zend Engine, fungsi tersebut memodifikasi struktur data internal C yang berada di `sapi_globals.headers` (struktur `sapi_headers_struct`).
3. Header-header ini dikumpulkan dalam sebuah *linked list* di memori proses PHP-FPM / CLI.
4. Header baru akan benar-benar di-*flush* (dikirim ke web server seperti Nginx/Apache via protokol FastCGI) saat:
   - Buffer output terisi penuh (`output_buffering` di `php.ini` terlampaui).
   - Terjadi output eksplisit pertama (perintah `echo`, `print`, atau ada karakter spasi/HTML di luar tag `<?php`).
   - Eksekusi skrip selesai.
5. Jika ada output terkirim sebelum pemanggilan `header()`, runtime PHP akan melempar peringatan fatal: `"Cannot modify header information - headers already sent by (output started at...)"`.

#### Preflight Short-Circuit Optimization
Menjalankan framework framework lengkap (booting autoloader, membaca konfigurasi, resolving dependency injection container) hanya untuk menjawab request `OPTIONS` menghabiskan resource CPU server secara sia-sia. Dengan melakukan intercept pada level terdepan (Middleware atau Front Controller) dan memanggil `http_response_code(204)` disusul `exit(0)`, siklus hidup PHP diputus lebih awal. Alokasi memori framework di-abort, dan respon dikembalikan dalam hitungan sub-milidetik.

#### Trade-offs & Resource
- **Header `Vary: Origin`**: Wajib ditambahkan jika nilai `Access-Control-Allow-Origin` bersifat dinamis. Konsekuensinya: CDN/Reverse Proxy (seperti Varnish, Cloudflare) akan mengalokasikan entri cache terpisah untuk setiap domain unik. Jika Anda memiliki ribuan origin dinamis, ini dapat menyebabkan *cache fragmentation* / *cache thrashing*.
- **CSP Nonce vs Strict Dynamic**: Menggunakan nonces (`'nonce-RANDOM'`) pada CSP membutuhkan *cryptographically secure pseudo-random number generator* (CSPRNG) di setiap request dari PHP (`random_bytes()`), yang mematikan kapabilitas caching respon statis penuh di layer HTTP Reverse Proxy.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Strict Match List**: Selalu gunakan pencocokan *exact/hash-map* (`in_array(..., true)`) terhadap daftar putih (*whitelist*) domain frontend.
- **Kombinasikan `Access-Control-Allow-Credentials: true` dengan Origin Terpilih**: Format ini legal secara spesifikasi W3C.
- **Setel `Access-Control-Max-Age`**: Tanpa header ini, browser (terutama Chrome/WebKit) dapat mengirimkan request `OPTIONS` setiap kali sebelum pemanggilan `fetch()` atau `XMLHttpRequest` terjadi.

#### Don'ts
- **JANGAN PERNAH Memadukan Wildcard dan Kredensial**:
  ```php
  // FATAL SECURITY FLAW / BROWSER AKAN MENOLAK:
  header('Access-Control-Allow-Origin: *');
  header('Access-Control-Allow-Credentials: true');
  ```
  Spesifikasi CORS secara eksplisit melarang penggunaan `*` jika kredensial (seperti Cookie atau HTTP Auth) diizinkan karena risiko eksfiltrasi data via session hijacking.
- **JANGAN Memantulkan Nilai Origin Tanpa Validasi (Origin Reflection Attack)**:
  ```php
  // VULNERABLE TERHADAP CORS MISCONFIGURATION EXPLOITATION:
  if (isset($_SERVER['HTTP_ORIGIN'])) {
      header("Access-Control-Allow-Origin: {$_SERVER['HTTP_ORIGIN']}"); // Jangan lakukan ini!
      header('Access-Control-Allow-Credentials: true');
  }
  ```
  Pola ini membuka celah di mana attacker dapat membuat situs `evil-hacker.com`, memicu request ke API Anda, dan browser akan memproses pertukaran data sensitif karena API memvalidasi origin penyerang secara membabi buta.
- **JANGAN Mengabaikan Header `Vary: Origin`**: Jika origin Anda tentukan secara dinamis di PHP namun lupa menyetel `header('Vary: Origin')`, CDN dapat meng-cache respons yang memiliki header `Access-Control-Allow-Origin: https://site-a.com`, lalu menyajikannya ke pengguna yang mengakses dari `https://site-b.com`, menyebabkan error CORS acak pada klien.

#### Edge Cases
- **Origin: "null"**: Browser mengirim header `Origin: null` pada context tertentu: saat file HTML dibuka via protokol `file://`, redirect lintas-origin yang tidak transparan, atau dari dalam sandboxed `<iframe>`. Jangan masukkan string `"null"` ke dalam whitelist.
- **Regex Validation Pitfall**: Jika memvalidasi origin menggunakan regex, hati-hati terhadap *character unescaped dots*:
  ```php
  // SALAH: domain regex tidak di-escape
  preg_match('/https:\/\/app.example.com/', $origin);
  // Match terhadap: https://appxexample.com (Attacker domain!)
  
  // BENAR:
  preg_match('/^https:\/\/app\.example\.com$/', $origin);
  ```

### 5. Tantangan Eksplorasi Mandiri

1. **Simulasi CORS Exploitation via Sandboxed Environment**:
   - Bangun sebuah script PHP sederhana yang menyetel `Access-Control-Allow-Origin: $_SERVER['HTTP_ORIGIN']` dan memuat data rahasia dari `$_SESSION`.
   - Jalankan local server terpisah menggunakan `python3 -m http.server 8080` dan buat script `fetch()` dengan `{ credentials: 'include' }`. Amati bagaimana kredensial berhasil bocor ke origin lain, lalu perbaiki kode PHP Anda menggunakan strict whitelist.
2. **CSP Nonce Generation Engine**:
   - Buat class PHP murni yang menghasilkan *cryptographically secure nonce* (`bin2hex(random_bytes(16))`).
   - Terapkan nonce tersebut ke dalam header `Content-Security-Policy: script-src 'nonce-...';`.
   - Cetak dua tag `<script>` di HTML: satu dengan atribut `nonce` yang valid dan satu tanpa `nonce`. Amati penolakan eksekusi di browser DevTools Console.
3. **Analisis Paket Header dengan cURL**:
   - Lakukan inspeksi preflight manual menggunakan terminal:
     ```bash
     curl -I -X OPTIONS http://localhost:8000/api \
          -H "Origin: https://app.example.com" \
          -H "Access-Control-Request-Method: POST" \
          -H "Access-Control-Request-Headers: Authorization"
     ```
   - Pastikan status code mengembalikan `204` dan seluruh kumpulan header `Access-Control-*` serta security headers terpasang dengan presisi.
