## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam ekosistem PHP, memahami siklus hidup HTTP (HTTP Lifecycle) dan standar PSR-7 adalah fondasi utama untuk membangun aplikasi modern yang *scalable* dan *testable*. 

**Siklus Hidup HTTP di PHP (Shared Nothing Architecture)**
Berbeda dengan Node.js atau Go di mana server HTTP berjalan terus-menerus di dalam *event loop*, PHP secara tradisional menggunakan arsitektur *Shared Nothing*. 
1. **Request Masuk**: Klien mengirim HTTP Request ke Web Server (Nginx/Apache).
2. **FastCGI/SAPI**: Web Server meneruskan request ke PHP-FPM melalui protokol FastCGI. SAPI (Server API) menerjemahkan data FastCGI menjadi variabel superglobal PHP (`$_GET`, `$_POST`, `$_SERVER`).
3. **Bootstrap & Eksekusi**: Zend Engine melakukan inisialisasi (RINIT - Request Initialization). Script PHP dieksekusi dari awal (state kosong).
4. **Response & Teardown**: Script menghasilkan output (HTML/JSON) dan HTTP Headers. Setelah selesai, Zend Engine membersihkan seluruh memori yang digunakan (RSHUTDOWN). Tidak ada *state* atau memori yang dibagikan antar request.

**PSR-7: HTTP Message Interfaces**
Secara historis, developer PHP memanipulasi request dan response menggunakan variabel global (`$_GET`, `$_POST`) dan fungsi imperatif (`header()`, `echo`). Pendekatan ini sangat sulit diuji (*mocking*) dan mengikat aplikasi pada *environment* web server.

PSR-7 (PHP Standard Recommendation 7) hadir untuk mengabstraksi pesan HTTP menjadi antarmuka (Interfaces) berorientasi objek. Konsep inti PSR-7 adalah **Immutability** (Ketidakberubahan). Objek Request dan Response tidak dapat diubah setelah dibuat. Jika Anda ingin memodifikasi header atau status, metode tersebut akan mengembalikan *instance* (klon) baru. Ini mencegah *side-effect* yang tidak terduga saat objek di-passing melalui berbagai *Middleware*.

### 2. Implementasi & Contoh Kasus Nyata

Untuk menggunakan PSR-7, kita membutuhkan implementasi konkret (seperti `nyholm/psr7` atau `guzzlehttp/psr7`). Contoh di bawah ini mendemonstrasikan bagaimana menangkap request, memprosesnya, dan mengembalikan response menggunakan standar PSR-7.

```php
<?php

require 'vendor/autoload.php';

use Nyholm\Psr7\Factory\Psr17Factory;
use Nyholm\Psr7Server\ServerRequestCreator;
use Psr\Http\Message\ServerRequestInterface;
use Psr\Http\Message\ResponseInterface;

// 1. Inisialisasi Factory (PSR-17) untuk membuat objek PSR-7
$psr17Factory = new Psr17Factory();

// 2. Menangkap Request dari environment global PHP (SAPI)
$creator = new ServerRequestCreator(
    $psr17Factory, // ServerRequestFactory
    $psr17Factory, // UriFactory
    $psr17Factory, // UploadedFileFactory
    $psr17Factory  // StreamFactory
);
$request = $creator->fromGlobals();

/**
 * Handler utama aplikasi (Bisa berupa Controller atau Action)
 */
function handleRequest(ServerRequestInterface $request, Psr17Factory $factory): ResponseInterface
{
    // Mengambil query parameter (?name=Budi)
    $queryParams = $request->getQueryParams();
    $name = $queryParams['name'] ?? 'Guest';

    // Membaca HTTP Header (Case-insensitive)
    $userAgent = $request->getHeaderLine('user-agent');

    // Membuat payload JSON
    $payload = json_encode([
        'message' => "Hello, $name!",
        'client' => $userAgent
    ]);

    // 3. Membuat Response
    $response = $factory->createResponse(200);
    
    // IMMUTABILITY IN ACTION: 
    // Setiap pemanggilan 'with...' mengembalikan instance baru.
    // Kita harus menugaskannya kembali ke variabel.
    return $response
        ->withHeader('Content-Type', 'application/json')
        ->withHeader('X-Powered-By', 'PHP-PSR7')
        ->withBody($factory->createStream($payload));
}

// 4. Eksekusi Handler
$response = handleRequest($request, $psr17Factory);

// 5. Emit Response (Mengirim kembali ke Web Server / Klien)
// Di framework modern, ini ditangani oleh Emitter (misal: laminas/laminas-httphandlerrunner)
header(sprintf(
    'HTTP/%s %s %s',
    $response->getProtocolVersion(),
    $response->getStatusCode(),
    $response->getReasonPhrase()
));

foreach ($response->getHeaders() as $name => $values) {
    foreach ($values as $value) {
        header(sprintf('%s: %s', $name, $value), false);
    }
}

echo $response->getBody();
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: Saat `ServerRequestCreator::fromGlobals()` dipanggil, ia membaca memori C-level yang dialokasikan oleh SAPI (melalui variabel `$_SERVER`, `$_FILES`, dll) dan memetakannya ke dalam struktur objek PHP. Proses ini terjadi di *userland* (kode PHP), bukan di level Zend Engine C, sehingga ada sedikit *overhead* komputasi dibandingkan mengakses `$_GET` secara langsung.
- **Alokasi Memori / Resource (Streams)**: PSR-7 menggunakan `StreamInterface` untuk *body* dari Request dan Response. Alih-alih memuat seluruh *body* (misalnya file upload 50MB) ke dalam RAM sebagai *string*, PSR-7 membungkus *resource handle* PHP (seperti `php://temp` atau `php://memory`). Jika data melebihi batas memori tertentu (biasanya 2MB di `php://temp`), PHP secara otomatis memindahkannya ke disk (file sementara), mencegah *Fatal Error: Allowed memory size exhausted*.
- **Trade-offs**: 
  - *Kelebihan*: Interoperabilitas tinggi. Anda bisa menukar framework (misal dari Slim ke Mezzio) tanpa mengubah logika domain karena keduanya mengerti PSR-7. Sangat mudah diuji (*unit testing*).
  - *Kekurangan*: Sifat *Immutable* berarti setiap kali Anda memanggil `$request->withHeader()`, PHP melakukan proses `clone` pada objek tersebut. Pada aplikasi dengan ratusan modifikasi header/request di *middleware*, ini menciptakan *garbage collection overhead* (banyak objek sementara yang dibuat dan dibuang).

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Selalu gunakan *Type Hinting* pada antarmuka (`Psr\Http\Message\ServerRequestInterface`), bukan pada implementasi konkret (seperti `Nyholm\Psr7\ServerRequest`).
  - Gunakan `getHeaderLine('Accept')` alih-alih `getHeader('Accept')` jika Anda hanya menginginkan string yang dipisahkan koma, karena `getHeader()` mengembalikan array.
  - Selalu *return* hasil dari metode mutator: `$response = $response->withStatus(404);`.
- **Don'ts**:
  - Jangan pernah menggunakan `$_GET`, `$_POST`, atau `$_FILES` di dalam *Controller* atau *Service* Anda jika sudah menggunakan PSR-7. Ambil data murni dari objek `$request`.
  - Jangan menggunakan `echo` atau `die()` di dalam logika aplikasi. Selalu kembalikan objek `ResponseInterface` dan biarkan *Emitter* di ujung siklus hidup yang mencetaknya.
- **Edge Cases**:
  - **Rewinding Streams**: Jika Anda membaca *body* request di sebuah *middleware* (misal untuk *logging* JSON payload) menggunakan `$request->getBody()->getContents()`, *pointer* stream akan berada di akhir. Jika *controller* mencoba membacanya lagi, hasilnya akan kosong. Anda **harus** melakukan `$request->getBody()->rewind()` setelah membacanya.

### 5. Tantangan Eksplorasi Mandiri

1. **Buat Middleware Sederhana**: Buatlah sebuah fungsi yang menerima `ServerRequestInterface` dan sebuah *closure* (sebagai *next middleware*). Modifikasi request dengan menambahkan header `X-Request-ID` (berisi UUID), teruskan ke *closure*, lalu catat waktu eksekusi (dari awal hingga response dikembalikan) dan tambahkan sebagai header `X-Response-Time` pada `ResponseInterface` sebelum mengembalikannya.
2. **Streaming File Besar**: Buatlah sebuah *endpoint* yang mengembalikan file video berukuran 1GB menggunakan PSR-7. Gunakan `fopen()` dan `StreamFactory` untuk memasukkan *resource* tersebut ke dalam *body* Response tanpa menyebabkan *Out of Memory* (OOM) pada PHP. (Petunjuk: Jangan gunakan `file_get_contents`).
