## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Membuat dan menerbitkan Composer package adalah transisi dari sekadar "pengguna" ekosistem PHP menjadi "kontributor". Sebuah package pada dasarnya adalah direktori berisi kode PHP yang diorganisir dengan standar tertentu, dideskripsikan oleh file `composer.json`, dan didistribusikan melalui *registry* (umumnya **Packagist**).

**Arsitektur Distribusi Package:**
1. **Source of Truth (VCS):** Kode sumber dan *release tags* disimpan di Version Control System (seperti GitHub/GitLab).
2. **Registry (Packagist):** Bertindak sebagai indeks metadata. Packagist tidak menyimpan kode Anda; ia hanya membaca `composer.json` dari repositori Git Anda dan mengindeks versi, dependensi, dan lokasi unduhan.
3. **Client (Composer CLI):** Saat *end-user* menjalankan `composer require vendor/package`, Composer melakukan *dependency resolution* menggunakan algoritma SAT (Boolean Satisfiability Problem) solver, mencari metadata di Packagist, lalu mengunduh *zipball* langsung dari GitHub/GitLab ke direktori `vendor/`.

**Mengapa Standarisasi Penting?**
Tanpa standar **PSR-4 (Autoloader)**, pengguna harus melakukan `require` atau `include` secara manual untuk setiap file. Composer mengabstraksi ini dengan men-generate satu file `vendor/autoload.php` yang memetakan *namespace* ke struktur direktori fisik secara dinamis di *runtime*.

### 2. Implementasi & Contoh Kasus Nyata

Kita akan membuat package utilitas sederhana bernama `TextSummarizer` yang kompatibel dengan PHP 8.2+.

**Langkah 1: Inisialisasi `composer.json`**
Jalankan `composer init` di terminal, atau buat file `composer.json` secara manual:

```json
{
    "name": "acme/text-summarizer",
    "description": "A robust text summarization utility for PHP 8.2+",
    "type": "library",
    "license": "MIT",
    "autoload": {
        "psr-4": {
            "Acme\\TextSummarizer\\": "src/"
        }
    },
    "autoload-dev": {
        "psr-4": {
            "Acme\\TextSummarizer\\Tests\\": "tests/"
        }
    },
    "require": {
        "php": "^8.2"
    },
    "require-dev": {
        "phpunit/phpunit": "^10.0"
    }
}
```

**Langkah 2: Implementasi Kode (Modern PHP)**
Buat direktori `src/` dan tambahkan file `Summarizer.php`.

```php
<?php

declare(strict_types=1);

namespace Acme\TextSummarizer;

use InvalidArgumentException;

/**
 * Class Summarizer
 * Menggunakan fitur modern PHP 8.2 (readonly class) untuk immutability.
 */
readonly class Summarizer
{
    public function __construct(
        private string $endString = '...'
    ) {}

    /**
     * Memotong teks berdasarkan batas karakter tanpa memotong kata di tengah.
     */
    public function summarize(string $text, int $maxLength = 100): string
    {
        if ($maxLength <= 0) {
            throw new InvalidArgumentException('Max length must be greater than 0.');
        }

        if (mb_strlen($text) <= $maxLength) {
            return $text;
        }

        // Mencari spasi terakhir sebelum batas maxLength
        $truncated = mb_substr($text, 0, $maxLength);
        $lastSpace = mb_strrpos($truncated, ' ');

        if ($lastSpace !== false) {
            $truncated = mb_substr($truncated, 0, $lastSpace);
        }

        return $truncated . $this->endString;
    }
}
```

**Langkah 3: Menerbitkan Package**
1. Inisialisasi Git: `git init && git add . && git commit -m "Initial commit"`
2. Buat tag rilis (SemVer): `git tag v1.0.0`
3. Push ke GitHub: `git push origin main --tags`
4. Login ke [Packagist.org](https://packagist.org/), klik "Submit", dan masukkan URL repositori GitHub Anda. Packagist akan otomatis membaca tag `v1.0.0` dan membuatnya tersedia untuk diunduh.

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (Autoloading):** 
  Saat pengguna menginstal package Anda, Composer membaca blok `autoload.psr-4` dari `composer.json` Anda dan menambahkannya ke file `vendor/composer/autoload_psr4.php`. Di *runtime*, ketika PHP menemui `new \Acme\TextSummarizer\Summarizer()`, fungsi `spl_autoload_register` milik Composer akan memecah *namespace* tersebut, mencocokkannya dengan *prefix* `Acme\TextSummarizer\`, dan menerjemahkannya menjadi *path* absolut `/vendor/acme/text-summarizer/src/Summarizer.php`, lalu melakukan `require` secara otomatis.
- **Alokasi Memori / Resource:** 
  Pencarian file dinamis PSR-4 memakan sedikit siklus CPU (I/O stat). Di *production*, pengguna disarankan menjalankan `composer dump-autoload --optimize` (atau `-o`). Ini akan mengubah pemetaan PSR-4 dinamis menjadi *Classmap* statis (array 1-to-1 antara nama class dan path file) di `autoload_classmap.php`, yang secara drastis mengurangi latensi I/O disk dan penggunaan memori saat *class loading*.
- **Trade-offs (Dependency Resolution):** 
  Composer menggunakan SAT solver untuk menyelesaikan dependensi. Jika package Anda mensyaratkan `guzzlehttp/guzzle: "^7.0"` dan package lain di proyek pengguna mensyaratkan `guzzlehttp/guzzle: "^6.0"`, Composer akan gagal (Dependency Hell). Oleh karena itu, package *library* harus se-fleksibel mungkin dalam mendefinisikan versi dependensi.

### 4. Best Practices & Common Pitfalls

- **Do's:**
  - **Gunakan `.gitattributes`:** Tambahkan file `.gitattributes` dengan isi `/tests export-ignore` dan `/.github export-ignore`. Ini mencegah direktori testing dan CI ikut terunduh saat pengguna menjalankan `composer require`, sehingga ukuran *zipball* package Anda menjadi sangat kecil dan ringan.
  - **Patuhi Semantic Versioning (SemVer):** Format `MAJOR.MINOR.PATCH`. Naikkan MAJOR jika ada *breaking changes* (perubahan yang merusak kompatibilitas mundur), MINOR untuk fitur baru, PATCH untuk *bugfix*.
  - **Tentukan Batasan Versi PHP:** Selalu definisikan `"php": "^8.1"` (atau versi minimum yang Anda dukung) di blok `require`.
- **Don'ts:**
  - **JANGAN commit `composer.lock` untuk Library:** File `composer.lock` hanya boleh di-commit untuk *Project* (seperti aplikasi Laravel/Symfony). Untuk *Library/Package*, `composer.lock` harus diabaikan (`.gitignore`), karena Composer pengguna akhir-lah yang akan menentukan versi spesifik dari dependensi Anda berdasarkan konstrain di `composer.json`.
  - **Jangan Terlalu Ketat pada Dependensi:** Hindari menggunakan versi eksak seperti `"monolog/monolog": "3.2.0"`. Gunakan *caret* operator `^3.2` agar package Anda bisa berdampingan dengan package lain yang membutuhkan versi minor/patch yang berbeda.
- **Edge Cases:**
  - **Namespace Collision:** Selalu gunakan *Vendor Prefix* yang unik (misal: nama GitHub Anda atau nama perusahaan) untuk menghindari bentrok nama class dengan package lain.

### 5. Tantangan Eksplorasi Mandiri

1. Buatlah sebuah package PHP sederhana (misalnya: *Password Generator* atau *Slugifier*), lengkapi dengan unit test menggunakan PHPUnit, dan publikasikan ke Packagist.
2. Konfigurasikan GitHub Actions di repositori package Anda untuk menjalankan PHPUnit secara otomatis setiap kali ada *push* atau *Pull Request* ke branch `main`.
3. Eksplorasi penggunaan PHPStan (Static Analysis Tool) dengan menambahkannya ke `require-dev` di `composer.json` Anda, dan pastikan kode package Anda lolos analisis pada level maksimum (Level 9).
