## 📖 Konsep Mendalam

### 1. Siklus Hidup Eksekusi (PHP Lifecycle)
PHP mengeksekusi kode melalui tahapan berikut:
1. **Module Init (MINIT)**: Terjadi sekali saat proses PHP (PHP-FPM master / CLI) dimulai. Ekstensi di-load dan konstanta global diinisialisasi.
2. **Request Init (RINIT)**: Dijalankan sebelum setiap request masuk. Environment dievaluasi (`$_GET`, `$_POST`, `$_SERVER`), dan memory manager mengalokasikan pool baru.
3. **Execution**: Kode PHP di-tokenize (Lexing), diparsing menjadi Abstract Syntax Tree (AST), lalu dikompilasi menjadi Zend Opcodes. Jika OPcache aktif, tahap parsing dilewati dan Opcodes langsung dieksekusi di Zend Engine VM.
4. **Request Shutdown (RSHUTDOWN)**: Setelah response terkirim, variabel dihancurkan, resource dilepas, dan garbage collector membersihkan pool memori request.
5. **Module Shutdown (MSHUTDOWN)**: Dijalankan saat proses PHP-FPM/CLI dimatikan total.

```php
<?php
// Cek status runtime PHP
declare(strict_types=1);

echo "PHP Version : " . PHP_VERSION . PHP_EOL;
echo "Server API  : " . PHP_SAPI . PHP_EOL;
echo "OPcache     : " . (function_exists('opcache_get_status') && opcache_get_status() ? 'Enabled' : 'Disabled') . PHP_EOL;

if (PHP_SAPI === 'cli') {
    global $argc, $argv;
    echo "Jumlah Argumen: {$argc}" . PHP_EOL;
    foreach ($argv as $idx => $arg) {
        echo "  [{$idx}] => {$arg}" . PHP_EOL;
    }
}
```

## ⚠️ Best Practices & Common Pitfalls
- **Stateless Isolation**: Jangan pernah mengasumsikan state memori persisten di antara dua request HTTP pada mode PHP-FPM standar; setiap request memiliki memori yang terisolasi total.
- **CLI Exit Codes**: Selalu gunakan `exit(0)` untuk sukses dan `exit(1)` (atau angka positif lainnya) untuk kegagalan agar skrip automasi/CI dapat mendeteksi status dengan akurat.
