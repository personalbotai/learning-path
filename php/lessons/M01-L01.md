## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

PHP modern bukan sekadar bahasa *templating* untuk HTML, melainkan *general-purpose scripting language* yang ditenagai oleh **Zend Engine**. Untuk memahami PHP secara mendalam, kita harus memahami arsitektur utamanya: **Shared-Nothing Architecture** dan **SAPI (Server Application Programming Interface)**.

**Shared-Nothing Architecture**
Berbeda dengan Node.js atau Go di mana *state* (seperti koneksi database atau variabel global) dapat bertahan di memori antar *request*, PHP secara default menghancurkan seluruh *state* dan memori setelah satu *request* selesai. 
*   **Keuntungan:** Sangat stabil. Jika satu *request* mengalami *memory leak* atau *fatal error*, *request* lain tidak akan terpengaruh.
*   **Kelemahan:** *Overhead* tinggi karena aplikasi (dan *framework*) harus melakukan *bootstrapping* dari nol pada setiap *request*. (Masalah ini dimitigasi oleh **OPcache** dan arsitektur modern seperti Laravel Octane/Swoole).

**SAPI (Server API)**
SAPI adalah antarmuka yang menghubungkan PHP dengan dunia luar. Dua SAPI yang paling sering digunakan adalah:
1.  **CLI SAPI (Command Line Interface):** Digunakan untuk menjalankan *script* di terminal (cronjobs, *queue workers*, *migrations*). Tidak memiliki batasan waktu eksekusi (`max_execution_time = 0`).
2.  **FPM SAPI (FastCGI Process Manager):** Digunakan di *production* bersama Nginx atau Apache. FPM mengelola *pool* dari *worker processes* PHP untuk menangani *request* HTTP secara konkuren.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah skrip hibrida yang mendemonstrasikan bagaimana PHP mendeteksi SAPI yang sedang berjalan dan menangani siklus *request* dasar.

```php
<?php
declare(strict_types=1);

/**
 * Skrip ini dapat dijalankan melalui Terminal (CLI) atau Web Browser (FPM/Built-in Server).
 * 
 * Cara menjalankan via CLI: php script.php "Budi"
 * Cara menjalankan via Web: php -S localhost:8000 script.php
 */

// 1. Mendeteksi Environment (SAPI)
$sapi = php_sapi_name();

if ($sapi === 'cli' || $sapi === 'phpdbg') {
    // --- SIKLUS CLI ---
    // $argv adalah array bawaan PHP yang berisi argumen dari terminal
    $name = $argv[1] ?? 'Developer';
    
    echo "🚀 Menjalankan PHP via Command Line Interface (CLI)\n";
    echo "Halo, {$name}!\n";
    echo "Memory Limit CLI: " . ini_get('memory_limit') . "\n";
    
    // Exit code 0 menandakan eksekusi sukses tanpa error
    exit(0); 
}

// --- SIKLUS WEB REQUEST (FPM / Built-in Server) ---
// Mengatur header HTTP
header('Content-Type: application/json');

// Mengambil data dari superglobal $_SERVER yang di-inject oleh Web Server
$requestMethod = $_SERVER['REQUEST_METHOD'] ?? 'UNKNOWN';
$requestUri = $_SERVER['REQUEST_URI'] ?? '/';

// Simulasi pemrosesan request
$response = [
    'status' => 'success',
    'message' => 'Request berhasil diproses',
    'data' => [
        'sapi_used' => $sapi,
        'method' => $requestMethod,
        'endpoint' => $requestUri,
        'memory_limit_web' => ini_get('memory_limit'),
        'php_version' => PHP_VERSION
    ]
];

// Output JSON ke client
echo json_encode($response, JSON_PRETTY_PRINT);
```

**Penjelasan Perintah CLI Esensial:**
*   `php -v`: Mengecek versi PHP dan status Zend Engine/OPcache.
*   `php -m`: Melihat daftar ekstensi (modul) yang dimuat di memori.
*   `php -i`: Menampilkan konfigurasi lengkap (sama dengan `phpinfo()`).
*   `php --ini`: Mengetahui lokasi file `php.ini` yang sedang digunakan.
*   `php -S localhost:8000`: Menjalankan *built-in web server* untuk *development* lokal.

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (Zend Engine Lifecycle)**:
  Setiap kali file PHP dieksekusi, Zend Engine melakukan 4 tahap utama:
  1.  **Lexing/Tokenizing:** Kode sumber PHP dipecah menjadi *tokens* (potongan makna terkecil, misal: `T_ECHO`, `T_VARIABLE`).
  2.  **Parsing:** *Tokens* disusun menjadi **AST (Abstract Syntax Tree)**, sebuah struktur pohon yang merepresentasikan logika program.
  3.  **Compilation:** AST dikompilasi menjadi **Opcodes** (instruksi tingkat rendah yang dipahami oleh Zend Virtual Machine).
  4.  **Execution:** Zend VM mengeksekusi Opcodes tersebut.
  *(Catatan: Jika **OPcache** diaktifkan, tahap 1-3 akan di-bypass pada request berikutnya, dan PHP langsung mengeksekusi Opcodes dari shared memory).*

- **Alokasi Memori / Resource**:
  PHP menggunakan *Zend Memory Manager* (ZendMM). Saat *request* masuk, ZendMM meminta blok memori besar dari OS dan mengelolanya sendiri untuk variabel PHP. Ketika *request* selesai (RSHUTDOWN - *Request Shutdown*), seluruh memori yang dialokasikan untuk *request* tersebut langsung dibebaskan (*freed*), terlepas dari apakah *Garbage Collector* berjalan atau tidak.

- **Trade-offs**:
  *Shared-nothing* membuat PHP sangat kebal terhadap *memory leak* jangka panjang di level aplikasi web. Namun, *trade-off*-nya adalah CPU *overhead* untuk inisialisasi *framework* (seperti *loading* ratusan file class Laravel/Symfony) pada setiap *request*.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan **Docker** (seperti Laravel Sail) atau *isolated environments* (seperti Laravel Herd / Valet) untuk instalasi lokal agar versi PHP dan ekstensi identik dengan *production*.
  - Pahami bahwa `php.ini` untuk CLI dan FPM biasanya **berbeda**. Selalu cek konfigurasi di *environment* yang tepat.
  - Gunakan CLI untuk tugas berat (*cron*, *queue processing*) karena tidak dibatasi oleh *timeout* web server.

- **Don'ts**:
  - **Jangan pernah** menggunakan *built-in server* (`php -S`) di *production*. Server ini bersifat *single-threaded* dan akan memblokir *request* lain jika ada satu *request* yang berjalan lambat.
  - Jangan mengabaikan ekstensi. Banyak fitur PHP (seperti `mbstring`, `pdo_mysql`, `gd`, `curl`) bukan bagian dari *core* dan harus diinstal/diaktifkan secara eksplisit.

- **Edge Cases**:
  - **Max Execution Time:** Di web (FPM), skrip akan dihentikan paksa (biasanya setelah 30 detik) untuk mencegah *server hang*. Di CLI, skrip bisa berjalan berhari-hari (cocok untuk *daemon/worker*).
  - **Memory Limit Exhaustion:** Membaca file besar (misal CSV 2GB) ke dalam variabel array sekaligus akan memicu `Fatal error: Allowed memory size exhausted`. Gunakan *Generators* (`yield`) atau baca file baris-per-baris.

### 5. Tantangan Eksplorasi Mandiri

1.  Gunakan fungsi `token_get_all()` pada sebuah file PHP sederhana dan cetak hasilnya. Amati bagaimana Zend Engine melihat kode Anda sebagai kumpulan *tokens*.
2.  Jalankan perintah `php --ini` di terminal Anda. Kemudian buat file `info.php` berisi `<?php phpinfo();` dan jalankan di browser. Bandingkan lokasi file `php.ini` yang di-load oleh keduanya. Apakah sama atau berbeda?
3.  Buat sebuah *router* sederhana menggunakan *built-in server* PHP (`php -S localhost:8000 router.php`). Tangkap *request* ke `/api/users` dan `/api/posts`, lalu kembalikan response JSON yang berbeda berdasarkan URI tersebut.
