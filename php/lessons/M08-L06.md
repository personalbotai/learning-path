## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Continuous Integration (CI) dan Continuous Deployment (CD) adalah metodologi otomatisasi siklus rilis perangkat lunak. Dalam ekosistem PHP modern (PHP 8.x), CI/CD bukan sekadar menjalankan skrip *copy-paste* via FTP atau SSH, melainkan orkestrasi pipeline berbasis verifikasi deterministik: *linting*, *static analysis*, pengujian unit/integrasi, hingga pembuatan *deployable artifact*.

```
   [Developer Push]
          │
          ▼
   GitHub Repository (Event Trigger: push / pull_request)
          │
          ▼
   GitHub Actions Orchestrator
          │
          ├──> Job 1: Coding Standards & Linting (Pint / PHP-CS-Fixer)
          ├──> Job 2: Static Analysis (PHPStan / Psalm)
          ├──> Job 3: Automated Testing Matrix (PHPUnit - 8.2, 8.3)
          │          │
          │          └──> Service Containers (MySQL / Redis)
          │
          └──> Job 4: Build & Deploy (Jika semua Job lulus di branch master/main)
                     │
                     └──> SSH / Container Registry (Docker) / Cloud Target
```

#### Arsitektur GitHub Actions
GitHub Actions dibangun di atas konsep hierarkis:
1. **Workflows**: Berkas deklaratif YAML di direktori `.github/workflows/` yang merespons *event* spesifik (`push`, `pull_request`, `schedule`, atau `workflow_dispatch`).
2. **Runners**: Mesin virtual terisolasi (secara *default* berbasis VM Azure Hyper-V/KVM untuk Ubuntu, Windows, atau macOS) yang mengeksekusi *jobs*. Runner bersifat *ephemeral*—dibuat saat *job* dijadwalkan dan dimusnahkan seketika setelah selesai.
3. **Jobs & Steps**: Job adalah kumpulan langkah (*steps*) yang berjalan secara sekuensial dalam *runner* yang sama. Secara *default*, antar-*job* berjalan paralel kecuali didefinisikan relasi dependensi via `needs:`.
4. **Action Components**: Modul *reusable* yang ditulis dalam JavaScript (Node.js runtime di runner) atau Docker container. Di PHP, aksi de-facto standar industri adalah `shivammathur/setup-php`.

#### Alasan CI/CD Krusial untuk Runtime PHP
PHP adalah bahasa bertipe dinamis dengan eksekusi berbasis interpretasi *bytecode* (Zend Engine OPcodes). Tidak ada fase kompilasi *ahead-of-time* (AOT) bawaan yang memvalidasi integritas biner aplikasi sebelum runtime. Bug fatal seperti `TypeError`, *deprecated signature*, atau `Call to undefined method` hanya akan terdeteksi saat *execution path* kode tersebut tersentuh di produksi. 

Oleh karena itu, CI pipeline bertindak sebagai **"Kompilator Sintetis"** melalui integrasi:
- **Linting & AST Inspection** (Parallel-lint, PHP-CS-Fixer).
- **Type-inference engines** (PHPStan, Psalm) yang membangun *Abstract Syntax Tree* (AST) untuk memverifikasi tipe tanpa mengeksekusi kode secara langsung.
- **Dynamic verification** (PHPUnit, Pest) untuk memvalidasi *business logic* dan *state transitions*.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah pipeline CI/CD komprehensif untuk aplikasi PHP modern. Pipeline ini mengimplementasikan validasi kode, pengujian lintas versi PHP (Matrix), *dependency caching*, *database services*, dan *stage-gated deployment*.

```yaml
# .github/workflows/ci-cd.yml
name: PHP CI/CD Enterprise Pipeline

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

# Menghentikan build yang sedang berjalan jika ada commit baru pada branch/PR yang sama
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read

jobs:
  # =========================================================================
  # STAGE 1: Code Quality & Static Analysis
  # =========================================================================
  quality-gate:
    name: Code Quality & Linting
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Setup PHP Environment
        uses: shivammathur/setup-php@v2
        with:
          php-version: '8.3'
          extensions: mbstring, intl, dom
          tools: composer:v2, cs2pr
          coverage: none

      - name: Validate Composer Configuration
        run: composer validate --strict --check-lock

      - name: Get Composer Cache Directory
        id: composer-cache
        run: echo "dir=$(composer config cache-files-dir)" >> $GITHUB_OUTPUT

      - name: Cache Composer Dependencies
        uses: actions/cache@v4
        with:
          path: ${{ steps.composer-cache.outputs.dir }}
          key: ${{ runner.os }}-composer-${{ hashFiles('**/composer.lock') }}
          restore-keys: ${{ runner.os }}-composer-

      - name: Install Dependencies
        run: composer install --prefer-dist --no-progress --no-interaction --optimize-autoloader

      - name: Run Static Analysis (PHPStan)
        run: ./vendor/bin/phpstan analyse --error-format=github --level=8 src/

  # =========================================================================
  # STAGE 2: Automated Tests with Matrix Strategy & Services
  # =========================================================================
  test-suite:
    name: Tests (PHP ${{ matrix.php-version }})
    needs: quality-gate
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        php-version: ['8.2', '8.3']

    # Layanan pendukung integration tests (Database & Cache)
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: root_password
          MYSQL_DATABASE: testing_db
        ports:
          - 3306:3306
        options: --health-cmd="mysqladmin ping" --health-interval=10s --health-timeout=5s --health-retries=3

      redis:
        image: redis:7-alpine
        ports:
          - 6379:6379
        options: --health-cmd="redis-cli ping" --health-interval=10s --health-timeout=5s --health-retries=3

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Setup PHP Environment
        uses: shivammathur/setup-php@v2
        with:
          php-version: ${{ matrix.php-version }}
          extensions: mbstring, pdo_mysql, redis, pcov
          coverage: pcov

      - name: Cache Composer Dependencies
        uses: actions/cache@v4
        with:
          path: ~/.composer/cache/files
          key: ${{ runner.os }}-php-${{ matrix.php-version }}-composer-${{ hashFiles('**/composer.lock') }}

      - name: Install Dependencies
        run: composer install --prefer-dist --no-progress --no-interaction

      - name: Execute Tests with Coverage Threshold
        env:
          DB_HOST: 127.0.0.1
          DB_PORT: 3306
          DB_DATABASE: testing_db
          DB_USERNAME: root
          DB_PASSWORD: root_password
          REDIS_HOST: 127.0.0.1
        run: ./vendor/bin/phpunit --coverage-text --min-coverage=80

  # =========================================================================
  # STAGE 3: Production Deployment
  # =========================================================================
  deploy-production:
    name: Deploy to Production
    needs: test-suite
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    runs-on: ubuntu-latest
    environment:
      name: production
      url: https://api.production.example.com
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Configure SSH Key
        run: |
          mkdir -p ~/.ssh
          echo "${{ secrets.SSH_PRIVATE_KEY }}" > ~/.ssh/id_rsa
          chmod 600 ~/.ssh/id_rsa
          ssh-keyscan -H ${{ secrets.PRODUCTION_HOST }} >> ~/.ssh/known_hosts

      - name: Trigger Remote Deployment (Atomic Symlink Deployment)
        run: |
          ssh ${{ secrets.SSH_USER }}@${{ secrets.PRODUCTION_HOST }} << 'EOF'
            set -e
            cd /var/www/app
            git fetch origin main
            git reset --hard origin/main
            composer install --no-dev --prefer-dist --optimize-autoloader --no-interaction
            php bin/console doctrine:migrations:migrate --no-interaction
            php bin/console cache:clear
            sudo systemctl reload php8.3-fpm
          EOF
```

#### Komponen Kritis dalam Script:
1. `concurrency.cancel-in-progress: true`: Mencegah pemborosan komputasi. Jika commit kedua di-*push* sebelum komit pertama selesai diuji, *job* komit pertama langsung dihentikan.
2. `tools: cs2pr`: Utility untuk menerjemahkan luaran alat analisis statis (Checkstyle format) langsung ke baris kode di tab *Pull Request File Changes* GitHub via GitHub Annotations.
3. `services:`: GitHub Actions secara otomatis membuat Docker network internal. Aplikasi pengujian dapat langsung menghubungi `127.0.0.1:3306` karena port di-ekspos ke host runner VM.
4. `environment`: Menggunakan fitur proteksi rilis GitHub (misalnya: membutuhkan *manual approval* dari Tech Lead sebelum *job* `deploy-production` berjalan).

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Virtualisasi Runner**: Ketika GitHub memicu *workflow*, *job request* masuk ke antrean *backend* GitHub Actions. Orchestrator mengambil VM Ubuntu standar (biasanya Azure Standard_DS2_v2: 2 vCPU, 7 GB RAM).
- **Mekanisme `setup-php`**: Aksi `shivammathur/setup-php` tidak mengompilasi PHP dari *source code* (karena memakan waktu 15–20 menit). Aksi ini mengunduh biner PHP yang sudah di-*pre-compile* khusus untuk arsitektur OS runner dari mirror GitHub releases milik maintainer, lalu melakukan symlink binary ke `/usr/bin/php` dan menginjeksi path ke `$GITHUB_PATH`.
- **Ekstensi PHP Dinamis**: Ekstensi C yang diminta via `extensions:` diaktifkan dengan menginjeksikan direktif `extension=nama_ekstensi.so` ke dalam berkas `php.ini` khusus runner (`/etc/php/{version}/cli/conf.d/`).

#### Alokasi Memori / Resource
- **SAT Solver Composer**: Saat `composer install` berjalan, Composer memuat seluruh pohon dependensi ke RAM untuk mengevaluasi *dependency graph* melalui algoritma SAT (*Boolean Satisfiability*). Composer dapat mengonsumsi RAM > 1.5 GB. Runner menyediakan 7 GB RAM, menjadikannya stabil, tetapi direktif memory CLI default PHP sering kali dibatasi (`128M`). Action `setup-php` secara otomatis mengonfigurasi `memory_limit = -1` (unlimited) untuk CLI context guna mencegah `Fatal error: Allowed memory size exhausted`.
- **Code Coverage Overhead: PCOV vs Xdebug**:
  - `Xdebug` memodifikasi *execution engine* Zend VM secara mendalam dengan menyisipkan *handler* pada setiap *opcode* PHP untuk melacak *line execution* dan *stack traces*. Ini menghasilkan *performance penalty* masif (pengujian berjalan **300% hingga 800% lebih lambat**).
  - `PCOV` hanya mengaitkan diri (*hooks*) pada kompilator Zend (`zend_compile_file`) dan hanya mendeteksi apakah suatu *basic block* dari opcode dieksekusi atau tidak. Overhead PCOV berada di bawah **15%**, menghemat waktu eksekusi CI dan tagihan *GitHub Actions billing minutes*.

#### Trade-offs
| Pendekatan | Keuntungan | Kerugian |
| :--- | :--- | :--- |
| **Matrix Strategy (Banyak Versi)** | Mendeteksi inkompatibilitas PHP (misal: deprecation notice di PHP 8.3 vs 8.2) sebelum produksi. | Mengalikan konsumsi menit CI (2 versi = 2x durasi komputasi). |
| **Monolithic Job (Lint+Test+Deploy)** | Startup overhead runner hanya terjadi 1 kali. | Gagal menerapkan *fail-fast*; debugging sulit; tidak ada paralelisasi. |
| **Modular Jobs (Stages terpisah)** | Pengecekan kualitas awal dapat menggagalkan pipeline dalam hitungan detik tanpa menjalankan DB. | Setiap job baru memerlukan inisialisasi VM dan *checkout code* ulang. |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `composer.lock` yang Terkunci**: Selalu jalankan `composer install` (bukan `composer update`) di CI. Ini memastikan *environment* CI 100% deterministik dan identik dengan *environment* lokal developer.
- **Terapkan Caching Dependensi Secara Ketat**: Cache direktori `~/.composer/cache` menggunakan *hash* berkas `composer.lock` sebagai *cache key*. Ini memangkas waktu unduhan paket jaringan eksternal.
- **Validasi Composer Metadata**: Selalu jalankan `composer validate --strict --check-lock` untuk memverifikasi bahwa `composer.lock` sinkron dengan `composer.json`.

#### Don'ts
- **Menjalankan Xdebug di Tahap Static Analysis / Non-Coverage**: Jangan aktifkan modul Xdebug jika hanya menjalankan PHPStan atau PHP-CS-Fixer.
- **Hardcoding Kredensial & Secrets**: Jangan pernah menulis token API, SSH key, atau password database di dalam skrip YAML. Selalu gunakan `secrets.NAMA_SECRET` dan GitHub Action Environments.
- **Mengabaikan Strict Types di Testing Engine**: Membiarkan *error reporting* mengabaikan `E_DEPRECATED` atau `E_NOTICE`. CI harus menggunakan konfigurasi:
  ```ini
  error_reporting = E_ALL
  display_errors = On
  ```

#### Edge Cases
- **Cache Poisoning**: Terjadi ketika dependensi yang di-*cache* korup akibat interupsi jaringan pada run sebelumnya. Solusi: Gunakan kunci cache dinamis dengan menambahkan *runner OS* dan *hash file lock*: `${{ runner.os }}-composer-${{ hashFiles('**/composer.lock') }}`.
- **Privileged Docker Services Port Collision**: Jika menjalankan integration test pada *self-hosted runner* (bukan *GitHub-hosted runner*), port seperti `3306` atau `6379` mungkin sudah digunakan oleh sistem operasi host runner. Gunakan *dynamic port mapping* alih-alih *hardcoding* port.

### 5. Tantangan Eksplorasi Mandiri

1. **Optimasi Caching PHPStan Result Cache**:
   Konfigurasikan GitHub Actions untuk menyimpan dan me-*restore* cache internal PHPStan (`/tmp/phpstan` atau direktori *result cache* defaultnya). Ukur perbedaan waktu eksekusi *Static Analysis* pada *pull request* yang hanya mengubah satu berkas dengan dan tanpa PHPStan *result cache*.
2. **Implementasi Security Vulnerability Scanning**:
   Tambahkan *step* baru di dalam *Quality Gate* yang mengeksekusi pemeriksaan kerentanan keamanan dependensi secara otomatis menggunakan `enlightn/security-checker` atau CLI bawaan `composer audit --locked`. Buat skenario kegagalan CI dengan memasang dependensi versi lama yang memiliki CVE aktif.
