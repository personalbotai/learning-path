### 1. Konsep & Arsitektur Mendalam

Observabilitas modern dibangun di atas tiga pilar utama: **Metrics**, **Logs**, dan **Traces** (Telemetry Data). Dalam ekosistem PHP yang bersifat *share-nothing* dan *ephemeral* (setiap request mengalokasikan dan menghancurkan heap memory sendiri), instrumentasi performa (APM) menghadirkan tantangan arsitektural yang unik dibanding runtime persisten seperti Go atau Node.js.

```
[ HTTP Request ] 
       │
       ▼
[ Nginx Reverse Proxy ]
       │ (Unix Domain Socket / TCP)
       ▼
[ PHP-FPM Master Process ]
  ├── Worker 1 ──► [ OpenTelemetry Extension / Hook ] ──► [ OTel Collector ] (gRPC/HTTP)
  ├── Worker 2 ──► [ App Code / SQL Query / Curl ]            │
  └── Worker N                                                ├──► [ Prometheus / Grafana ]
                                                              └──► [ Jaeger / Tempo ]
```

#### Arsitektur OpenTelemetry (OTel) pada PHP
Secara native, runtime PHP mengeksekusi bytecode via Zend Engine. Untuk mengumpulkan distributed trace tanpa menambahkan overhead I/O yang masif di dalam lifecycle request:
1. **Auto-Instrumentation via C Extension (`ext-opentelemetry`)**:
   Extension mengaitkan callback pada *internal engine hooks* (seperti `zend_execute_ex` atau observer API di PHP 8.2+). Hal ini memungkinkan inspeksi pemanggilan fungsi (`PDO::query`, `curl_exec`, dsb.) secara deterministik di level C sebelum dan sesudah eksekusi opcode.
2. **Context Propagation**:
   Trace ID dan Span ID didistribusikan melintasi service boundary melalui HTTP Header standar W3C (`traceparent: 00-{trace-id}-{span-id}-{trace-flags}`).
3. **Export Pipeline**:
   Payload trace tidak dikirimkan langsung ke backend tracing (misal: Jaeger, Tempo) satu per satu secara sinkron karena akan memblokir FPM worker. Telemetri diekspor menggunakan OpenTelemetry Collector agent lokal (via transport Unix domain socket atau gRPC/Protobuf) secara non-blocking atau di flush pada fase `fastcgi_finish_request()` / request termination.

#### Anatomi Zero-Downtime Deployment
Model eksekusi PHP berbasis disk reading: Zend OPcache memetakan file PHP ke dalam *shared memory* (SHM) dan mengindeks file berdasarkan *real path*. Permasalahan zero-downtime deployment pada PHP-FPM adalah:
- **Atomic Symlink Switch**: Mengubah pointer direktori `current -> releases/20260330_v2` adalah operasi atomic di level filesystem UNIX.
- **OPcache Invalidation Pitfall**: OPcache menyimpan cache opcode berdasarkan `realpath` file. Jika symlink berganti tanpa memvalidasi realpath cache (`opcache.revalidate_path=1`), worker bisa mengeksekusi kombinasi fatal antara file rilis lama dan rilis baru secara inkonsisten (race condition).
- **Reloading PHP-FPM Tanpa Memutus Koneksi**: Memanfaatkan POSIX signal `SIGUSR2` pada master process PHP-FPM. Master process akan membaca konfigurasi baru, mempertahankan open listening socket, membiarkan worker aktif menyelesaikan request yang sedang berjalan (*graceful shutdown*), dan melakukan *spawn* worker baru yang membaca kode rilis teranyar.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi distributed tracing manual menggunakan SDK OpenTelemetry PHP, korelasi log berbasis context, serta konfigurasi script zero-downtime deployment.

#### A. Manual Instrumentation & Trace Context Propagation

Pastikan dependensi terpasang:
```bash
composer require open-telemetry/sdk open-telemetry/exporter-otlp open-telemetry/transport-grpc
```

```php
<?php

declare(strict_types=1);

namespace App\Telemetry;

use OpenTelemetry\API\Globals;
use OpenTelemetry\API\Trace\SpanKind;
use OpenTelemetry\API\Trace\StatusCode;
use OpenTelemetry\Context\Context;
use OpenTelemetry\Context\Propagation\TraceContextPropagator;
use Psr\Log\LoggerInterface;
use Throwable;

final class InstrumentedOrderService
{
    public function __construct(
        private readonly LoggerInterface $logger,
        private readonly \PDO $db
    ) {}

    public function processCheckout(array $requestHeaders, array $cartData): string
    {
        $tracer = Globals::tracerProvider()->getTracer('io.app.order-service', '1.2.0');
        
        // 1. Ekstrak Parent Context dari W3C Traceparent Header
        $parentContext = TraceContextPropagator::getInstance()->extract($requestHeaders);

        // 2. Buat Span Baru dengan Parent Context
        $span = $tracer->spanBuilder('checkout_transaction')
            ->setParent($parentContext)
            ->setSpanKind(SpanKind::SPAN_KIND_SERVER)
            ->setAttribute('order.items_count', count($cartData['items']))
            ->startSpan();

        // Aktivasi Scope Span pada Context eksekusi saat ini
        $scope = $span->activate();

        try {
            $traceId = $span->getContext()->getTraceId();
            $spanId = $span->getContext()->getSpanId();

            // 3. Log Correlation: Injeksi trace_id dan span_id ke Structured Log
            $this->logger->info('Memulai checkout pesanan.', [
                'trace_id' => $traceId,
                'span_id'  => $spanId,
                'user_id'  => $cartData['user_id']
            ]);

            // Database Span (Internal Operation)
            $dbSpan = $tracer->spanBuilder('db.order.insert')
                ->setSpanKind(SpanKind::SPAN_KIND_CLIENT)
                ->setAttribute('db.system', 'mysql')
                ->startSpan();

            $stmt = $this->db->prepare('INSERT INTO orders (user_id, total) VALUES (:uid, :total)');
            $stmt->execute([
                ':uid' => $cartData['user_id'],
                ':total' => $cartData['total']
            ]);
            $orderId = $this->db->lastInsertId();
            $dbSpan->end();

            $span->setStatus(StatusCode::STATUS_OK);
            return (string) $orderId;
        } catch (Throwable $e) {
            // Tangkap exception dan tandai span gagal
            $span->recordException($e);
            $span->setStatus(StatusCode::STATUS_ERROR, $e->getMessage());
            
            $this->logger->error('Checkout gagal: ' . $e->getMessage(), [
                'trace_id' => $span->getContext()->getTraceId(),
                'exception' => $e
            ]);
            
            throw $e;
        } finally {
            // Scope dan Span HARUS selalu ditutup
            $scope->detach();
            $span->end();
        }
    }
}
```

#### B. Zero-Downtime Deployment Hook Script (Deployer / Bash)

Script orkestrasi ini mengeksekusi atomic symlink, pre-heating cache, dan graceful reload tanpa me-drop koneksi FastCGI yang antre di socket buffer.

```bash
#!/usr/bin/env bash
set -euo pipefail

DEPLOY_PATH="/var/www/app"
RELEASE_ID=$(date +%Y%m%d%H%M%S)
TARGET_DIR="${DEPLOY_PATH}/releases/${RELEASE_ID}"
CURRENT_SYMLINK="${DEPLOY_PATH}/current"
FPM_SOCKET="/run/php/php8.3-fpm.sock"

echo "==> 1. Setup workspace rilis baru: ${TARGET_DIR}"
mkdir -p "${TARGET_DIR}"
git clone --depth 1 --branch main https://github.com/org/repo.git "${TARGET_DIR}"
cd "${TARGET_DIR}"

echo "==> 2. Install dependencies & build production artifacts"
composer install --no-dev --prefer-dist --optimize-autoloader --no-interaction
php artisan config:cache
php artisan route:cache

echo "==> 3. Atomic Symlink Switch"
# Gunakan ln -sfn untuk mengganti target symlink secara atomik
ln -sfn "${TARGET_DIR}" "${CURRENT_SYMLINK}.tmp"
mv -Tf "${CURRENT_SYMLINK}.tmp" "${CURRENT_SYMLINK}"

echo "==> 4. Invalidation & Preheating OPcache via FastCGI"
# OPcache terisolasi dalam SHM PHP-FPM, CLI tidak bisa membersihkan cache FPM.
# Kita gunakan cachetool untuk invoke opcode purge langsung ke FastCGI socket.
cachetool opcache:reset --fcgi="${FPM_SOCKET}"

echo "==> 5. Graceful Reload PHP-FPM"
# Kirim sinyal SIGUSR2 ke master process FPM untuk reload worker tanpa drop connection
kill -USR2 "$(pgrep -f 'php-fpm: master process')"

echo "==> Deployment Sukses Rilis: ${RELEASE_ID}"
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Zend Engine Observer API
Pada PHP 8.2+, auto-instrumentasi OpenTelemetry memanfaatkan **Zend Observer API** (`zend_observer_fcall_register`).
- Saat file PHP dikompilasi menjadi bytecode (opline arrays), compiler memanggil callback observer.
- Callback menyuntikkan instruksi khusus sebelum opcode fungsi pertama dieksekusi (`begin`) dan setelah instruksi return diproses (`end`).
- Ini mengeliminasi monkey-patching userland method atau extension jadul yang merusak inline cache processor di dalam CPU.

#### Alokasi Memori / Resource
- **Traces**: Span yang dibuat di heap memori PHP tidak boleh membengkak. Jika buffer spans melewati batas konfigurasi (`OTEL_BSP_MAX_QUEUE_SIZE`), SDK akan mulai men-drop spans baru guna memproteksi memory limit worker (`memory_limit = 128M`).
- **Shared Memory (SHM) OPcache**: Pada atomic symlink switch, jika `opcache.revalidate_path = 0`, OPcache me-resolve symlink hanya sekali pada stat file pertama dan menyimpan *inode pointer*. Tanpa purge cache (`opcache_reset()`), worker FPM yang masih hidup akan mengeksekusi bytecode dari inode rilis lama yang sudah terhapus di filesystem.

#### Trade-offs
| Pendekatan Tracing | Overhead Latensi | Akurasi & Granularitas | Kebutuhan Infrastruktur |
| :--- | :--- | :--- | :--- |
| **C Extension (`ext-opentelemetry`)** | Sangat Rendah (~1-3%) | Tinggi (Hook langsung di Zend VM Engine) | Harus compile/install ekstensi `.so` |
| **Pure Userland (Composer SDK)** | Sedang (~5-15%) | Terbatas pada framework/middleware layer | Cukup via composer, mudah di-deploy |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Korelasikan Log dengan Traces**: Selalu inject `trace_id` dan `span_id` ke dalam format JSON payload log aplikasi (Monolog context processor). Ini memangkas Mean Time to Resolution (MTTR) di log aggregation engine (Loki, Elasticsearch).
- **Gunakan Local OTel Collector Agent**: Kirim telemetri dari PHP-FPM ke daemon collector lokal (via UDS/localhost) menggunakan transport gRPC non-blocking, bukan langsung ke cloud endpoint lintas regional internet.
- **Set `listen.backlog` yang Cukup pada PHP-FPM**: Saat master FPM menerima sinyal `SIGUSR2`, request baru akan ditahan di level TCP/Socket buffer OS. Set minimal `listen.backlog = 65535` pada pool config FPM dan kernel OS (`net.core.somaxconn`) untuk mencegah error `502 Bad Gateway` selama worker spawning.

#### Don'ts
- **Jangan Jalankan `php artisan opcache:clear` via CLI**: CLI PHP memiliki alokasi shared memory OPcache yang terpisah dengan daemon PHP-FPM. Perintah reset OPcache via CLI **tidak berdampak** pada web traffic FPM.
- **Jangan Menggunakan Synchronous HTTP Exporter**: Menembak REST API APM backend secara sinkron di tengah execution flow akan menunda response time ke client sebesar durasi latensi network eksternal.

#### Edge Cases
- **OPcache Cache Stale Locks**: Jika melakukan `opcache_reset()` saat traffic FPM mencapai ribuan concurrent connection, server dapat mengalami *stampede effect* (CPU spike ke 100%) karena ratusan worker secara bersamaan mengompilasi ulang ribuan file PHP dari disk.
- *Mitigasi*: Lakukan *pre-heating* (compile cache secara selektif) menggunakan script CLI yang menembak route internal sebelum traffic dialihkan secara penuh.

   Jalankan load testing sederhana menggunakan `k6` atau `wrk` (500 req/sec) ke aplikasi PHP-FPM lokal. Eksekusi script symlink switch dan FPM reload via `kill -USR2`. Amati apakah ada persentase error status HTTP non-200 yang muncul selama transisi.
2. **Kustom Manual Span Sub-Query**:
   Modifikasi layer koneksi database Anda untuk membungkus query SQL ke dalam OpenTelemetry Child Span. Tangkap metrik waktu eksekusi statement SQL mentah dan pastikan parameter sensitif (seperti password/token) disanitasi sebelum dimasukkan ke dalam attribute span metadata.
