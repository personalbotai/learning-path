### 1. Konsep & Arsitektur Mendalam

Unit Testing adalah pengujian unit terkecil dalam perangkat lunak—biasanya berupa metode (*method*) atau fungsi (*function*)—secara terisolasi dari dependensi eksternal (seperti database, jaringan, atau sistem berkas). Dalam ekosistem PHP, **PHPUnit** adalah standar *de facto* yang mengimplementasikan arsitektur pengujian keluarga **xUnit** (arsitektur pengujian modular yang dipelopori oleh Kent Beck).

Secara arsitektural, PHPUnit beroperasi berdasarkan konsep **Four-Phase Test**:
1. **Setup**: Mempersiapkan *System Under Test* (SUT) dan dependensi atau kondisi awalnya.
2. **Exercise**: Menjalankan method atau aksi yang ingin diverifikasi.
3. **Verify**: Memeriksa hasil eksekusi menggunakan metode penegasan (*assertions*).
4. **Teardown**: Mengembalikan lingkungan ke kondisi semula untuk menghindari polusi status (*state pollution*) antar-pengujian.

```
+-----------------------------------------------------------+
|                      PHPUnit Test Runner                  |
+-----------------------------------------------------------+
                             |
                   (Reflection & Attributes)
                             v
+-----------------------------------------------------------+
|                   TestCase (SUT Runner)                   |
|  +-----------------------------------------------------+  |
|  | setUp() -> testMethod() -> tearDown()               |  |
|  |               |                                     |  |
|  |               v (asserts)                           |  |
|  |      [AssertionFailedError / Pass]                  |  |
|  +-----------------------------------------------------+  |
+-----------------------------------------------------------+
```

Di tingkat runtime, PHPUnit bukan sekadar pustaka utilitas; ia adalah *command-line runner* mandiri. PHPUnit membaca file konfigurasi (`phpunit.xml`), memindai direktori yang ditentukan, dan menggunakan **PHP Reflection API** untuk membaca metadata class, atribut (seperti `#[Test]`, `#[DataProvider]`), serta metode pengujian. 

Setiap pengujian dieksekusi secara independen. Kegagalan assertion tidak menghentikan seluruh test suite, melainkan melempar sebuah *exception* internal (`PHPUnit\Framework\AssertionFailedError`) yang ditangkap oleh Test Runner, dicatat sebagai *failure*, lalu runner melanjutkan pengujian berikutnya.

### 2. Implementasi & Contoh Kasus Nyata

Kita akan menguji logika bisnis perhitungan diskon belanja (`DiscountCalculator`) dengan aturan tertentu: diskon bertingkat, batas minimal transaksi, dan proteksi nilai negatif.

#### Unit yang Diuji (System Under Test): `src/DiscountCalculator.php`

```php
<?php

declare(strict_types=1);

namespace App;

use InvalidArgumentException;

final class DiscountCalculator
{
    private const MINIMUM_AMOUNT_FOR_DISCOUNT = 100_000;
    private const TIER_ONE_THRESHOLD = 500_000;
    
    /**
     * Menghitung nilai diskon berdasarkan subtotal belanja.
     * Aturan:
     * - Subtotal < 100.000: 0%
     * - Subtotal 100.000 s/d 499.999: 5%
     * - Subtotal >= 500.000: 10%
     *
     * @throws InvalidArgumentException jika nilai subtotal negatif
     */
    public function calculate(int $subtotal): int
    {
        if ($subtotal < 0) {
            throw new InvalidArgumentException('Subtotal cannot be negative.');
        }

        if ($subtotal < self_MINIMUM_AMOUNT_FOR_DISCOUNT) {
            return 0;
        }

        if ($subtotal < self::TIER_ONE_THRESHOLD) {
            return (int) round($subtotal * 0.05);
        }

        return (int) round($subtotal * 0.10);
    }
}
```

#### Pengujian: `tests/DiscountCalculatorTest.php`

Modern PHPUnit (v10+) mengutamakan penggunaan PHP 8 Attributes dibandingkan docblock annotations tradisional (`@test`).

```php
<?php

declare(strict_types=1);

namespace Tests;

use App\DiscountCalculator;
use InvalidArgumentException;
use PHPUnit\Framework\Attributes\DataProvider;
use PHPUnit\Framework\Attributes\Test;
use PHPUnit\Framework\TestCase;

final class DiscountCalculatorTest extends TestCase
{
    private DiscountCalculator $calculator;

    /**
     * Dijalankan sebelum setiap metode test dieksekusi.
     * Mengisolasi instance calculator agar fresh di setiap test.
     */
    protected function setUp(): void
    {
        parent::setUp();
        $this->calculator = new DiscountCalculator();
    }

    /**
     * Dijalankan setelah setiap metode test dieksekusi.
     */
    protected function tearDown(): void
    {
        unset($this->calculator);
        parent::tearDown();
    }

    #[Test]
    public function it_throws_exception_when_subtotal_is_negative(): void
    {
        // 1. Setup & Expectation
        $this->expectException(InvalidArgumentException::class);
        $this->expectExceptionMessage('Subtotal cannot be negative.');

        // 2. Exercise (harus melempar exception ke Test Runner)
        $this->calculator->calculate(-1);
    }

    #[Test]
    #[DataProvider('provideDiscountScenarios')]
    public function it_calculates_correct_discount_for_various_subtotals(
        int $subtotal,
        int $expectedDiscount
    ): void {
        // Exercise
        $actualDiscount = $this->calculator->calculate($subtotal);

        // Verify: Gunakan assertSame untuk strict checking (value & type)
        $this->assertSame(
            $expectedDiscount,
            $actualDiscount,
            "Failed asserting that subtotal {$subtotal} produces {$expectedDiscount} discount."
        );
    }

    /**
     * Data Provider: Menyediakan dataset edge cases dan boundary values.
     * 
     * @return array<string, array{subtotal: int, expectedDiscount: int}>
     */
    public static function provideDiscountScenarios(): array
    {
        return [
            'zero subtotal' => [
                'subtotal' => 0,
                'expectedDiscount' => 0,
            ],
            'below minimum threshold' => [
                'subtotal' => 99_999,
                'expectedDiscount' => 0,
            ],
            'exact minimum threshold (5%)' => [
                'subtotal' => 100_000,
                'expectedDiscount' => 5_000,
            ],
            'just below tier one threshold (5%)' => [
                'subtotal' => 499_999,
                'expectedDiscount' => 25_000, // round(499999 * 0.05) = 24999.95 -> 25000
            ],
            'exact tier one threshold (10%)' => [
                'subtotal' => 500_000,
                'expectedDiscount' => 50_000,
            ],
            'large transaction (10%)' => [
                'subtotal' => 2_000_000,
                'expectedDiscount' => 200_000,
            ],
        ];
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: 
  Saat perintah `vendor/bin/phpunit` dijalankan:
  1. PHPUnit menginisialisasi runtime, mendaftarkan custom error/exception handler miliknya sendiri via `set_error_handler()` dan `set_exception_handler()`. Tujuannya adalah mencegat semua error bawaan PHP (notice, warning, deprecated) dan mengubahnya menjadi *Test Failure* atau *Test Deprecation*.
  2. Test suite membaca AST (*Abstract Syntax Tree*) atau memanfaatkan `ReflectionClass` untuk mencari class turunan `TestCase`.
  3. Setiap instance `TestCase` **diinstansiasi sekali per metode test** yang ada. Jika sebuah class memiliki 10 method pengujian, PHPUnit membuat 10 object berbeda dari class tersebut guna menjaga isolasi status (*state isolation*).
  4. Pemanggilan Assertion (`$this->assertSame()`) mengevaluasi constraint. Jika kondisi `false`, ia melakukan `throw new AssertionFailedError()`. PHPUnit menangkap exception ini pada level runner, menandai pengujian sebagai *Failed*, merekam baris kode dan *diff output*, kemudian melanjutkan ke test berikutnya tanpa merusak stack proses PHP secara keseluruhan.

- **Alokasi Memori / Resource**:
  Secara bawaan, PHPUnit menyimpan referensi semua instance `TestCase` yang telah dieksekusi di memori hingga seluruh *test suite* selesai dijalankan. Ini dilakukan agar PHPUnit dapat mencetak ringkasan, analisis code coverage, dan statistik eksekusi di akhir proses. 
  
  Dampaknya: Jika Anda menginisialisasi object besar pada property class di `setUp()` tanpa menghapusnya (`unset()`) di `tearDown()`, memori tersebut tidak akan dibersihkan oleh Zend Garbage Collector. Pada ribuan test, hal ini menyebabkan *Memory Leak* (error `Allowed memory size exhausted`).

- **Trade-offs**:
  - **In-Process vs Process Isolation**: Secara default, semua unit test berjalan dalam satu proses PHP utama. Ini sangat cepat, namun rentan jika ada kode yang memodifikasi variabel superglobal (`$_SERVER`, `$_ENV`), konstanta runtime (`define()`), atau status static. Menjalankan pengujian dalam proses terpisah (`#[RunInSeparateProcess]`) memberikan isolasi mutlak, tetapi memicu overhead spawn sub-proses PHP yang menurunkan performa secara masif (bisa lebih lambat 10x–50x).

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - **Gunakan `assertSame()` alih-alih `assertEquals()`**: `assertSame()` melakukan perbandingan identitas/tipe ketat (`===`), sedangkan `assertEquals()` menggunakan perbandingan longgar (`==`). Di PHP, `assertEquals(0, 'string')` bisa bernilai `true` karena aturan *type juggling* (pada versi PHP tertentu), yang berpotensi meloloskan bug fatal.
  - **Jaga Aturan *Single Responsibility Test***: Satu metode pengujian sebaiknya hanya memverifikasi satu perilaku (*behavior*), bukan satu workflow raksasa dengan belasan assertion yang tidak berhubungan.
  - **Deskriptif dalam Menamai Test**: Gunakan format yang jelas seperti `it_calculates_correct_discount_when_...` atau `test_cannot_withdraw_more_than_balance()`. Nama test berfungsi sebagai dokumentasi sistem hidup (*executable documentation*).

- **Don'ts**:
  - **Jangan membuat dependensi antar-test**: Hindari mengandalkan urutan eksekusi (misal: Test B hanya bisa jalan jika Test A sukses). Walaupun PHPUnit memiliki fitur `#[Depends]`, over-use fitur ini mengubah unit test menjadi fragile integration test.
  - **Jangan gunakan Logic (if/else/for) di dalam Test Method**: Jika Anda membutuhkan perulangan atau pengujian ragam input, gunakan `#[DataProvider]`. Adanya `if` atau `switch` di dalam test menandakan pengujian tersebut rentan memiliki bug tersendiri.

- **Edge Cases**:
  - **Floating-point Imprecision**: Jangan pernah menggunakan `assertSame()` atau `assertEquals()` standar untuk tipe data `float` hasil kalkulasi (seperti `0.1 + 0.2 === 0.3` yang bernilai `false` di tingkat representasi IEEE 754). Gunakan `assertEqualsWithDelta($expected, $actual, $delta)` untuk memberikan toleransi presisi (misal: `$delta = 0.0001`).

### 5. Tantangan Eksplorasi Mandiri

1. **Investigasi Type Juggling**: Buat test menggunakan `assertEquals()`, lalu uji perbandingan array kosong `[]` dengan `false`, atau integer `0` dengan string kosong `""`. Amati hasilnya, kemudian ubah ke `assertSame()` dan telaah pesan kegagalan (*failure diff*) yang dihasilkan PHPUnit.
2. **Implementasi Exception Code Assertion**: Tambahkan kode error khusus (*custom error code*) pada `InvalidArgumentException` di `DiscountCalculator`. Modifikasi test pengujian exception agar memvalidasi tidak hanya class dan pesan exception, tetapi juga kode error tersebut menggunakan metode `$this->expectExceptionCode(...)`.
3. **Deteksi Memory Leak Sederhana**: Buat test suite yang menginstansiasi array besar (misal: 100.000 elemen) ke dalam properti `$this->largeData` pada `setUp()`. Jalankan 50 pengujian serupa tanpa method `tearDown()`, lalu bandingkan konsumsi memori puncaknya (`memory_get_peak_usage()`) dengan pengujian yang menggunakan `unset($this->largeData)` di `tearDown()`.
