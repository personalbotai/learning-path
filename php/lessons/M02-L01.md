## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam paradigma OOP modern di PHP (khususnya sejak PHP 8.0+), **Class** bertindak sebagai *blueprint* terstruktur yang mendefinisikan *state* (properties) dan *behavior* (methods), sedangkan **Object** adalah instansiasi konkret di memori runtime (*heap*).

Sebelum PHP 8.0, pendefinisian *Data Transfer Object* (DTO) atau *Value Object* membutuhkan penulisan kode berulang (*boilerplate*) yang redundan. Sebuah variabel harus ditulis minimal 4 kali:
1. Deklarasi *property*.
2. Parameter *type-hint* di `__construct()`.
3. Parameter nama di signature `__construct()`.
4. Operasi penugasan nilai: `$this->prop = $prop`.

```
[ Traditional Pipeline ]
Property Definition ---> Param Signature ---> Local Param ---> Assign to $this
         │                      │                    │               │
         └──────────────────────┴── 4x Redundansi ───┴───────────────┘
```

**Constructor Property Promotion (CPP)** diperkenalkan untuk mengeliminasi redundansi ini secara radikal. CPP adalah *syntactic sugar* tingkat kompilator yang memungkinkan deklarasi *property* dan inisialisasi nilainya dieksekusi langsung dari *signature* constructor.

#### Arsitektur Kompilasi
Pada fase *parsing* dan *Abstract Syntax Tree (AST) lowering* di Zend Engine:
- Ketika kompilator mendeteksi visibilitas (`public`, `protected`, atau `private`) pada parameter `__construct()`, Zend Engine secara otomatis mendaftarkan parameter tersebut sebagai *member property* dari kelas target sekaligus parameter konstruktor.
- Kompilator menyisipkan *opcode* `ZEND_ASSIGN` implisit tepat sebelum instruksi pertama di dalam tubuh *constructor block* dieksekusi.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengimplementasikan `PaymentTransaction` DTO yang *immutable* menggunakan kombinasi Constructor Property Promotion, `readonly` (PHP 8.1+), *Union Types*, dan validasi invarian domain.

```php
<?php

declare(strict_types=1);

namespace App\Domain\Payment;

use InvalidArgumentException;
use DateTimeImmutable;

enum TransactionStatus: string 
{
    case PENDING = 'pending';
    case SETTLED = 'settled';
    case FAILED  = 'failed';
}

final class PaymentTransaction
{
    // Property non-promoted tetap dapat digabungkan dengan CPP
    public readonly DateTimeImmutable $createdAt;

    /**
     * Constructor Property Promotion
     * Visibilitas langsung mengubah parameter menjadi property instance.
     */
    public function __construct(
        public readonly string $transactionId,
        public readonly float $amount,
        public readonly string $currency,
        public private(set) TransactionStatus $status = TransactionStatus::PENDING, // Asymmetric Visibility (PHP 8.4+)
        ?DateTimeImmutable $createdAt = null
    ) {
        // 1. Eksekusi Invariant Validation
        $this->guardValidAmount($this->amount);
        $this->guardValidCurrency($this->currency);

        // 2. Inisialisasi Property Non-promoted
        $this->createdAt = $createdAt ?? new DateTimeImmutable();
    }

    private function guardValidAmount(float $amount): void
    {
        if ($amount <= 0) {
            throw new InvalidArgumentException("Nilai transaksi harus lebih besar dari 0. Diberikan: {$amount}");
        }
    }

    private function guardValidCurrency(string $currency): void
    {
        if (strlen($currency) !== 3) {
            throw new InvalidArgumentException("Mata uang harus 3 karakter ISO-4217. Diberikan: {$currency}");
        }
    }

    public function markAsSettled(): void
    {
        if ($this->status !== TransactionStatus::PENDING) {
            throw new \LogicException("Hanya transaksi bertransisi PENDING yang dapat diubah ke SETTLED.");
        }
        
        $this->status = TransactionStatus::SETTLED;
    }
}

// === RUNTIME EXECUTION ===
try {
    $trx = new PaymentTransaction(
        transactionId: 'TX-98231',
        amount: 1500000.50,
        currency: 'IDR'
    );

    echo "ID: {$trx->transactionId}" . PHP_EOL;
    echo "Amount: {$trx->amount} {$trx->currency}" . PHP_EOL;
    echo "Status: {$trx->status->value}" . PHP_EOL;
    echo "Created: {$trx->createdAt->format('Y-m-d H:i:s')}" . PHP_EOL;

    // Mutasi status via encapsulation
    $trx->markAsSettled();
    echo "New Status: {$trx->status->value}" . PHP_EOL;

    // Direct mutation error test (jika melanggar asymmetric visibility / readonly):
    // $trx->amount = 2000000.0; // Fatal Error: Cannot modify readonly property
} catch (InvalidArgumentException $e) {
    echo "Validation Error: " . $e->getMessage();
}
```

#### Komponen Kunci:
1. **Promoted Visibility**: `public readonly string $transactionId` mendefinisikan *property* `$transactionId` dan menerima argumen saat instansiasi.
2. **Execution Timing**: Tubuh konstruktor (`guardValidAmount`, dll.) dieksekusi **setelah** nilai di-*assign* ke *promoted property*.
3. **Hybridisasi**: Parameter `$createdAt` tidak dipromosikan karena memerlukan pemrosesan *fallback* sebelum disimpan ke *property*.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (Zend VM)
Pada tahap kompilasi kode konvensional vs CPP:

*Konvensional:*
```php
class Standard {
    public string $id;
    public function __construct(string $id) {
        $this->id = $id;
    }
}
```
*Constructor Property Promotion:*
```php
class Promoted {
    public function __construct(public string $id) {}
}
```

Secara bytecode (Opline Level), Zend Engine menghasilkan instruksi yang identik:
- `RECV $id` (menerima argumen fungsi).
- `ASSIGN_OBJ this, 'id'` (menempatkan nilai argumen ke slot *offset* objek).
- `OP_DATA $id`.

CPP **bukan** mekanisme *reflection-based* dinamis di runtime, melainkan transformasi murni di AST *compiler*. Tidak ada penalti performa sama sekali pada runtime execution.

#### Alokasi Memori & Struct Object
Di level C (Core Zend Engine), setiap objek direpresentasikan oleh struct `zend_object`:

```c
struct _zend_object {
    zend_refcounted_h gc;
    uint32_t          handle;
    zend_class_entry *ce;
    const zend_object_handlers *handlers;
    HashTable        *properties;
    zval              properties_table[1]; // Flexible array member
};
```

1. Ketika objek diinstansiasi (`new`), Zend Engine mengalokasikan blok memori untuk `zend_object` beserta buffer statis `properties_table`.
2. Properti yang dideklarasikan melalui CPP menempati indeks terindeks langsung (*fixed property slots*) di `properties_table`, yang memungkinkan operasi baca/tulis bernilai $O(1)$ tanpa perlu mencari *hash key* di *HashTable* `$properties`.
3. Flag `readonly` menandai `zval` tersebut dengan restriksi tulis: setelah inisialisasi dari *state* `IS_UNDEF`, modifikasi berikutnya melempar `Error` exception.

#### Trade-offs
- **Keterbacaan Signature**: Constructor dengan lebih dari 5 promoted properties dapat menurunkan keterbacaan kode (*code smell* Constructor Over-injection).
- **Tooling & Reflection**: Reflection API memetakan parameter ini ke dua entitas sekaligus: `ReflectionParameter` dan `ReflectionProperty`. Komponen framework yang mengandalkan analisis *docblock* parameter harus menyesuaikan cara membaca metadata.

### 4. Best Practices & Common Pitfalls

#### Do's:
- **Gunakan bersama `readonly`**: Ideal untuk DTO, Command, Value Object, dan Event. Ini menjamin *immutability* tanpa *boilerplate* *getter/setter*.
- **Letakkan *promoted properties* di awal**: Jika mencampurkan *promoted* dan *non-promoted parameters*, letakkan *promoted properties* tanpa default value di awal *signature*.
- **Terapkan `strict_types=1`**: Menjamin tipe data yang dipromosikan tidak mengalami koersi implisit yang tidak terduga.

#### Don'ts:
- **Jangan gunakan type `callable` pada Promoted Property**: `callable` valid sebagai tipe parameter fungsi, namun **ilegal** sebagai tipe *property* di PHP.
  ```php
  // FATAL ERROR: Property cannot have type callable
  public function __construct(public callable $callback) {}
  ```
- **Jangan mempromosikan parameter pada Abstract Constructor atau Interface**: Definisi *abstract constructor* tidak boleh memiliki visibilitas pada parameternya.

#### Edge Cases:
- **Variadic Parameters**: Variadic arguments (`...$args`) tidak dapat dipromosikan ke properti karena ambiguitas pemetaan satu parameter array ke satu definisi *property*.
- **Duplikasi Atribut (PHP Attributes)**: Atribut yang disematkan pada *promoted property* dapat menargetkan parameter, properti, atau keduanya tergantung `Attribute::TARGET_*`:
  ```php
  #[Assert\NotBlank] // Menempel pada Property ATAU Parameter?
  public function __construct(
      #[Assert\NotBlank] public string $sku
  ) {}
  ```
  Secara *default*, atribut diterapkan ke kedua konteks jika target atribut mendukung `TARGET_PARAMETER | TARGET_PROPERTY`.

### 5. Tantangan Eksplorasi Mandiri

1. **Refactoring Legacy Codebase**: Ambil salah satu kelas *Service* atau *Value Object* lawas yang memiliki minimal 5 dependencies/properties dengan constructor standar. Refaktor menggunakan CPP + `readonly`. Analisis perbedaan jumlah *Line of Code* (LoC) dan kemudahan pembacaan.
2. **Inspeksi Reflection**: Buat script menggunakan `ReflectionClass`, `ReflectionProperty`, dan `ReflectionParameter`. Periksa objek yang menggunakan Constructor Property Promotion. Temukan bagaimana method `isPromoted()` pada `ReflectionParameter` bekerja dan bagaimana atribut terikat ke properti tersebut.
3. **Bytecode Comparison**: Jika Anda memiliki akses ke CLI dengan extension VLD (*Vulcan Logic Dumper*) atau menggunakan Opcache dump (`php -d opcache.opt_debug_level=0x10000`), bandingkan opcode yang dihasilkan dari kelas yang menggunakan inisialisasi manual versus Constructor Property Promotion. Buktikan kesetaraan instruksi assembly-nya.
