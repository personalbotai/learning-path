### 1. Konsep & Arsitektur Mendalam

Manajemen sesi pada aplikasi web berbasis HTTP bersifat *stateful abstraction* di atas protokol yang *stateless*. PHP mengimplementasikan abstraksi ini melalui ekstensi bawaan (`ext/session`). Dalam arsitektur web modern, sesi rentan terhadap dua vektor serangan identitas utama: **Session Hijacking** dan **Session Fixation**.

```
Session Hijacking (Pencurian Sesi Aktif):
[Victim] --- (Session ID Valid) ---> [Server]
   |
[Attacker] (Mencuri via XSS/Sniffing) -> Menggunakan ID -> [Server Mengizinkan]

Session Fixation (Penanaman ID Sesi):
[Attacker] --- (Dapatkan ID Kosong: "XYZ") ---> [Server]
[Attacker] --- (Menjebak Victim pakai "XYZ") -> [Victim]
[Victim]   --- (Login menggunakan ID "XYZ")  -> [Server (Mengaktifkan "XYZ")]
[Attacker] --- (Menggunakan ID "XYZ") -------> [Server Mengizinkan Akses Victim]
```

#### Session Hijacking (Pembajakan Sesi)
Serangan di mana penyerang mendapatkan *Session ID* (SID) sah milik korban yang telah terautentikasi. Begitu SID diperoleh, penyerang mengirimkan SID tersebut dalam *header* `Cookie` untuk menyamar sebagai korban tanpa perlu mengetahui kredensial asli.

Vektor eksploitasi Session Hijacking mencakup:
1. **Cross-Site Scripting (XSS)**: Skrip berbahaya membaca `document.cookie` jika atribut `HttpOnly` tidak diaktifkan.
2. **Man-in-the-Middle (MitM)**: Penyadapan lalu lintas jaringan tanpa enkripsi TLS/HTTPS yang tepat, atau jika atribut `Secure` absen pada cookie.
3. **Information Leakage**: SID bocor melalui *Referer header* (bila SID ditaruh di URL via `trans_sid`), log server, atau caching proxy.

#### Session Fixation (Fiksasi Sesi)
Berbeda dengan hijacking yang bersifat *reaktif* (mencuri setelah korban login), fixation bersifat *proaktif*. Penyerang menentukan SID terlebih dahulu, menanamkannya pada peramban korban, lalu menunggu korban mengautentikasi sesi tersebut.

Mekanismenya bekerja sebagai berikut:
1. Penyerang menginisialisasi sesi anonim di server target dan mendapatkan SID (misal: `PHPSESSID=attacker_fixed_id`).
2. Penyerang menyuntikkan ID ini ke peramban korban melalui *Query Parameter* (jika URL-based session aktif), manipulasi *subdomain cookie tossing*, atau XSS minor.
3. Korban melakukan autentikasi (login) menggunakan form normal.
4. Jika server **tidak meregenerasi SID** saat status autentikasi berubah, data pengguna yang telah terverifikasi akan diikatkan ke `attacker_fixed_id`.
5. Penyerang dapat langsung mengakses seluruh hak akses korban menggunakan ID yang sama.

Secara arsitektural, pertahanan terhadap dua serangan ini memerlukan **State Transition Lifecycle** yang deterministik:
- ID sesi harus memiliki entropi kriptografis tinggi (*CSPRNG*).
- Status autentikasi anonim dan terotentikasi harus memiliki ruang *namespace* dan siklus hidup ID yang terputus (wajib rotasi ID via `session_regenerate_id(true)`).
- Penolakan terhadap ID yang diinisiasi oleh klien tanpa catatan server sebelumnya (`session.use_strict_mode = 1`).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi *Session Manager* tingkat produksi pada PHP 8.2+ yang mengamankan siklus hidup sesi, menangani mitigasi fixation via regenerasi deterministik, dan memitigasi hijacking via *fingerprint validation*.

```php
<?php

declare(strict_types=1);

namespace App\Security;

use RuntimeException;

final class SecureSessionManager
{
    private const SESSION_LIFETIME = 1800; // 30 Menit idle timeout
    private const REGENERATE_INTERVAL = 300; // Rotasi berkala tiap 5 menit

    /**
     * Mengonfigurasi engine session PHP ke level maksimal sebelum boot.
     */
    public static function configure(): void
    {
        if (session_status() === PHP_SESSION_ACTIVE) {
            throw new RuntimeException('Konfigurasi sesi harus dipanggil sebelum session_start()');
        }

        // Terapkan opsi INI secara programmatic
        ini_set('session.use_strict_mode', '1');
        ini_set('session.use_cookies', '1');
        ini_set('session.use_only_cookies', '1');
        ini_set('session.trans_sid_hosts', '');
        ini_set('session.use_trans_sid', '0');

        // Parameter Cookie: Modern, Strict, & Encrypted context
        session_set_cookie_params([
            'lifetime' => 0, // Sesi peramban (dihapus saat browser ditutup)
            'path' => '/',
            'domain' => '', // Default host domain
            'secure' => true, // Wajib HTTPS
            'httponly' => true, // Cegah pembacaan via JS (Anti-XSS Hijacking)
            'samesite' => 'Strict', // Mitigasi CSRF & Context-leaking
        ]);
    }

    /**
     * Memulai sesi dan memvalidasi integritas state.
     */
    public static function start(): void
    {
        if (session_status() === PHP_SESSION_NONE) {
            self::configure();
            session_start();
        }

        self::validateSessionIntegrity();
    }

    /**
     * Menjalankan proses login yang aman dari Session Fixation.
     */
    public static function login(int $userId, string $role): void
    {
        // 1. Wajib: Hapus session storage lama dan alokasikan Session ID baru (Anti-Fixation)
        if (!session_regenerate_id(true)) {
            throw new RuntimeException('Gagal meregenerasi ID sesi.');
        }

        // 2. Kosongkan state data anonim
        $_SESSION = [];

        // 3. Masukkan state autentikasi baru
        $_SESSION['auth_user_id'] = $userId;
        $_SESSION['auth_role'] = $role;
        $_SESSION['last_activity'] = time();
        $_SESSION['created_at'] = time();
        
        // 4. Bind fingerprint: User-Agent + Network Subnet
        $_SESSION['client_fingerprint'] = self::generateFingerprint();
    }

    /**
     * Menghancurkan seluruh jejak sesi (Logout).
     */
    public static function logout(): void
    {
        if (session_status() !== PHP_SESSION_ACTIVE) {
            return;
        }

        $_SESSION = [];

        // Hapus cookie sesi dari peramban
        $params = session_get_cookie_params();
        setcookie(
            session_name(),
            '',
            time() - 42000,
            $params['path'],
            $params['domain'],
            $params['secure'],
            $params['httponly']
        );

        session_destroy();
    }

    /**
     * Validasi status idle, expiration, dan penyesuaian fingerprint client.
     */
    private static function validateSessionIntegrity(): void
    {
        $currentTime = time();

        // Cek Idle Timeout
        if (isset($_SESSION['last_activity']) && ($currentTime - $_SESSION['last_activity'] > self::SESSION_LIFETIME)) {
            self::logout();
            throw new RuntimeException('Sesi telah kedaluwarsa karena inaktivitas.');
        }
        $_SESSION['last_activity'] = $currentTime;

        // Cek Keberadaan Fingerprint untuk Sesi Terautentikasi
        if (isset($_SESSION['auth_user_id'])) {
            if (!isset($_SESSION['client_fingerprint']) || !hash_equals($_SESSION['client_fingerprint'], self::generateFingerprint())) {
                // Terdeteksi anomali pada sesi: Kemungkinan Session Hijacking
                self::logout();
                throw new RuntimeException('Anomali sesi terdeteksi. Akses ditolak.');
            }

            // Regenerasi ID berkala untuk mempersempit window of opportunity eksploitasi
            if ($currentTime - ($_SESSION['created_at'] ?? $currentTime) > self::REGENERATE_INTERVAL) {
                session_regenerate_id(true);
                $_SESSION['created_at'] = $currentTime;
            }
        }
    }

    /**
     * Membuat signature deterministik dari identitas klien.
     */
    private static function generateFingerprint(): string
    {
        $userAgent = $_SERVER['HTTP_USER_AGENT'] ?? 'UNKNOWN_UA';
        
        // Catatan: Hanya gunakan /24 subnet untuk IPv4 agar toleran terhadap rotasi IP load balancer
        $ip = $_SERVER['REMOTE_ADDR'] ?? '0.0.0.0';
        $ipSubnet = self::extractIpSubnet($ip);

        return hash_hmac('sha256', $userAgent . '|' . $ipSubnet, 'APP_INTERNAL_HMAC_SECRET_KEY');
    }

    private static function extractIpSubnet(string $ip): string
    {
        if (filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_IPV4)) {
            $parts = explode('.', $ip);
            return $parts[0] . '.' . $parts[1] . '.' . $parts[2] . '.0';
        }

        if (filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_IPV6)) {
            // Ambil hextet pertama untuk IPv6
            $parts = explode(':', $ip);
            return $parts[0] . ':' . ($parts[1] ?? '0');
        }

        return 'unknown';
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (`ext/session`)
1. **Inisialisasi via `session_start()`**:
   - Runtime PHP memicu modul `PS_MOD(files)` (default) atau handler sesi kustom (misalnya Redis/Memcached).
   - PHP mengekstrak ID dari `$_COOKIE[session_name()]`.
   - **Mekanisme Strict Mode (`session.use_strict_mode = 1`)**:
     Jika klien mengirimkan `PHPSESSID=attacker_id`, runtime tidak langsung membuatkan berkas penyimpanan untuk ID tersebut. Runtime memanggil fungsi handler `read()`. Jika handler mengembalikan string kosong (artinya ID belum pernah ada di storage server), PHP mengenali anomali ini, **menolak** SID tersebut, dan memanggil generator CSPRNG engine (`php_random_bytes()`) untuk membuat SID baru. Ini menggagalkan uninitialized fixation secara absolut.

2. **Proses `session_regenerate_id(bool $delete_old_session = true)`**:
   - Runtime membangkitkan string ID acak baru sepanjang 128-bit (jika menggunakan default SHA-256 via CSPRNG).
   - *Locking mechanism*: Runtime mempertahankan kunci eksklusif (`flock`) pada media penyimpanan.
   - Jika argumen `$delete_old_session = true` diberikan, PHP memicu `unlink()` terhadap file session lama (atau instruksi `DEL` di Redis) dan menerbitkan header HTTP `Set-Cookie` baru ke buffer output FastCGI (SAPI).
   - File baru dialokasikan dengan nama `sess_<new_id>`.

#### Alokasi Memori / Resource
- Sesi PHP disimpan di memori proses (Zend Engine Memory Manager) di dalam superglobal array `$_SESSION`.
- Saat script selesai dieksekusi (atau saat `session_write_close()` dipanggil), engine melakukan serialisasi string (menggunakan format `php` atau `php_serialize`), menulisnya ke storage backend, dan melepas file lock.
- Penulisan data sesi bersifat blocking. Operasi I/O disk/network memegang *write-lock*, sehingga request paralel dari klien yang sama akan terblokir (*session lock wait*) sampai request pertama membebaskan lock.

#### Trade-offs
| Opsi / Konfigurasi | Keuntungan | Biaya / Trade-off |
|---|---|---|
| `session_regenerate_id(true)` | Mencegah Session Fixation seutuhnya. | Terjadinya *race condition* bila terdapat banyak *request* paralel (misal via AJAX) saat ID baru belum diterima peramban. |
| User-Agent & Subnet Binding | Memitigasi Session Hijacking jika SID dicuri. | Sesi dapat mendadak *invalid* jika pengguna beralih jaringan (misal: Wi-Fi ke data seluler/dynamic routing). |
| `SameSite=Strict` | Kebocoran SID via link pihak ketiga mustahil. | Tautan masuk dari email/situs lain akan membuat pengguna tampak seperti tamu (*guest*), menuntut login ulang. |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Aktifkan `session.use_strict_mode = 1`**: Ini adalah proteksi fundamental lapis pertama dari engine PHP.
- **Panggil `session_regenerate_id(true)` pada setiap mutasi hak akses**: Lakukan saat login, logout, perubahan role (misal: dari *user* ke *admin*), dan perubahan password.
- **Tutup sesi lebih awal jika memungkinkan**: Jalankan `session_write_close()` sesegera mungkin jika script tidak lagi perlu memodifikasi data `$_SESSION`, untuk meminimalkan durasi *concurrency lock*.
- **Gunakan Session Store Terpusat (Redis/Memcached)**: Jangan mengandalkan file storage default `/tmp` di lingkungan server horizontal (*clustered/load-balanced*), karena validasi *strict mode* akan gagal jika request berpindah node.

#### Don'ts
- **JANGAN mengandalkan IP Address utuh (`REMOTE_ADDR`) sebagai kunci mutlak**: Pengguna dengan jaringan seluler (4G/5G) atau proxy korporat sering berganti IP publik secara acak di tengah sesi. Gunakan subnet level (/24) atau hindari strict-blocking tanpa validasi MFA lanjutan.
- **JANGAN biarkan Session Fixation melalui parameter URL**: Pastikan `session.use_trans_sid = 0` dan `session.use_only_cookies = 1`.
- **JANGAN gunakan `session_regenerate_id(false)`**: Membiarkan session lama tanpa dihapus meninggalkan "ghost session" yang masih aktif dan dapat dimanfaatkan penyerang yang sudah memiliki ID tersebut.

#### Edge Cases
- **Race Conditions saat Regenerasi ID via AJAX**:
  Jika SPA (Single Page Application) mengeksekusi 5 request paralel bersamaan saat session diregenerasi, request 2-5 akan mengirimkan ID lama yang baru saja dihapus oleh request 1, mengakibatkan sesi hangus (*logged out* palsu).
  *Solusi industri*: Buat skema *grace-period* (toleransi 5–10 detik) pada distributed cache (Redis) di mana Session ID lama dialihkan (*alias*) ke Session ID baru sebelum benar-benar di-`DEL`.

### 5. Tantangan Eksplorasi Mandiri

1. **Uji Penetrasi Session Fixation Mandiri**:
   Buat dua skrip terpisah (`unprotected_login.php` dan `protected_login.php`). Gunakan cURL untuk menyimulasikan serangan penanaman cookie:
   ```bash
   # Kirim Session ID buatan penyerang
   curl -k -b "PHPSESSID=penyerang123456789" https://localhost/unprotected_login.php -d "user=admin&pass=secret"
   ```
   Amati apakah direktori penyimpanan sesi server Anda (`/var/lib/php/sessions` atau `/tmp`) membuat file bernama `sess_penyerang123456789`. Perbaiki hingga respons server menghasilkan header `Set-Cookie` dengan ID yang sepenuhnya baru.

2. **Implementasi Custom `SessionHandlerInterface` dengan Grace Period**:
   Tulis kelas implementasi kustom untuk antarmuka bawaan PHP `\SessionHandlerInterface` berbasis Redis. Tambahkan mekanisme di mana ketika ID sesi diregenerasi, ID lama tetap dapat membaca state yang sama (status *read-only*) selama tepat 10 detik guna mencegah *broken requests* pada aplikasi yang mengeksekusi banyak panggilan *Fetch/AJAX* serentak.
