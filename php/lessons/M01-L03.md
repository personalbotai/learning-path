## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sejak PHP 7 dan puncaknya pada PHP 8.0, PHP mengalami pergeseran paradigma dari bahasa yang bertipe dinamis longgar (*loosely typed*) menjadi bahasa yang mendukung *type-safety* dan paradigma fungsional modern. Salah satu evolusi paling signifikan terjadi pada sistem evaluasi ekspresi dan kontrol alur: introduksi operator modern (*null-safe*, *null coalescing*, *spaceship*) serta struktur ekspresi `match`.

```
                    ┌──────────────────────────────┐
                    │      Subjek Evaluasi         │
                    └──────────────┬───────────────┘
                                   │
         ┌─────────────────────────┴─────────────────────────┐
         ▼                                                   ▼
┌─────────────────────────────────┐         ┌─────────────────────────────────┐
│        switch ($val)            │         │        match ($val)             │
├─────────────────────────────────┤         ├─────────────────────────────────┤
│ • Statement (tanpa return)      │         │ • Expression (mengembalikan val)│
│ • Loose Equality (==)           │         │ • Strict Equality (===)         │
│ • Fall-through (perlu break)    │         │ • Tidak ada fall-through        │
│ • Tidak wajib exhaustif         │         │ • Exhaustive (UnhandledMatchErr)│
│ • Opcodes: ZEND_CASE/ZEND_JMP   │         │ • Dioptimasi via jump/equality  │
└─────────────────────────────────┘         └─────────────────────────────────┘
```

#### Statement vs. Expression
Secara arsitektural di level parsing engine (Bison parser PHP), perbedaan fundamental antara `switch` dan `match` terletak pada klasifikasi gramatikalnya:
- **`switch` adalah *Statement***: Bertujuan mengeksekusi blok instruksi berdasarkan percabangan alur kontrol. `switch` tidak menghasilkan nilai (*evaluates to void*), membutuhkan mutasi variabel eksternal untuk menyimpan hasil, dan memiliki perilaku *fall-through* warisan bahasa C (eksekusi terus merembes ke `case` berikutnya kecuali dihentikan secara eksplisit oleh `break`).
- **`match` adalah *Expression***: Bertujuan menghasilkan sebuah nilai (*evaluates to a value*). `match` dapat langsung di-assign ke variabel, di-return oleh fungsi, atau dilempar sebagai argumen fungsi lain. `match` tidak mendukung multi-line statement di dalam cabangnya (*arm*) dan tidak memiliki konsep *fall-through*.

#### Loose Equality vs. Strict Identity
- `switch` bekerja menggunakan evaluasi **Loose Comparison (`==`)**. Sebelum PHP 8.0, hal ini menjadi sumber celah keamanan kritis (misalnya `"0" == "admin"` dievaluasi menjadi `true` jika terjadi *type juggling* string ke integer). Meskipun aturan *type comparison* diperketat di PHP 8.0, `switch` tetap mengizinkan konversi tipe implisit.
- `match` bekerja menggunakan **Strict Comparison (`===`)**. Baik nilai maupun tipe data dievaluasi secara identik tanpa *type coercion*.

### 2. Implementasi & Contoh Kasus Nyata

Berikut implementasi komparatif antara operator modern (`??`, `<=>`, `?->`), `switch`, dan `match` dalam domain sistem pemrosesan transaksi *e-commerce*.

```php
<?php

declare(strict_types=1);

namespace App\Billing;

enum PaymentStatus: string
{
    case PENDING = 'pending';
    case AUTHORIZED = 'authorized';
    case SETTLED = 'settled';
    case FAILED = 'failed';
    case REFUNDED = 'refunded';
}

final class Customer
{
    public function __construct(
        public readonly ?string $tier = null,
        public readonly ?Profile $profile = null
    ) {}
}

final class Profile
{
    public function __construct(public readonly ?string $locale = null) {}
}

final class Transaction
{
    public function __construct(
        public readonly string $id,
        public readonly float $amount,
        public readonly PaymentStatus $status,
        public readonly ?Customer $customer = null
    ) {}
}

final class TransactionProcessor
{
    /**
     * Menggunakan Spaceship Operator (<=>) untuk custom sorting.
     * Mengembalikan: -1 jika $a < $b, 0 jika $a == $b, 1 jika $a > $b.
     *
     * @param Transaction[] $transactions
     * @return Transaction[]
     */
    public function sortByAmountDescending(array $transactions): array
    {
        usort($transactions, static function (Transaction $a, Transaction $b): int {
            // Evaluasi perbandingan nilai float secara presisi
            return $b->amount <=> $a->amount;
        });

        return $transactions;
    }

    /**
     * Contoh penggunaan Match Expression vs Switch.
     * Match mengembalikan nilai secara instan dengan pengecekan exhaustif.
     */
    public function resolveCommissionRate(Transaction $transaction): float
    {
        return match ($transaction->status) {
            PaymentStatus::SETTLED    => 0.025,
            PaymentStatus::AUTHORIZED => 0.010,
            PaymentStatus::PENDING    => 0.000,
            PaymentStatus::FAILED, 
            PaymentStatus::REFUNDED   => 0.000, // Multi-condition branch
        }; // Tidak perlu default jika semua enum tercover secara exhaustif
    }

    /**
     * Demonstrasi Null-safe (?->) dan Null Coalescing (??, ??=).
     */
    public function resolveNotificationLocale(Transaction $transaction, ?string $fallbackLocale = null): string
    {
        // 1. Null-coalescing assignment operator: assign hanya jika bernilai null
        $fallbackLocale ??= 'en_US';

        // 2. Null-safe operator (?->): rantai dereference objek tanpa risiko Fatal Error jika $customer null
        // 3. Null-coalescing operator (??): fallback jika rantai ekspresi bernilai null
        return $transaction->customer?->profile?->locale ?? $fallbackLocale;
    }

    /**
     * ANTI-PATTERN LAMA: Menggunakan switch statement untuk mapping nilai.
     * Rentan bug karena mutable state ($rate) dan lupa 'break'.
     */
    public function resolveCommissionRateLegacy(Transaction $transaction): float
    {
        $rate = 0.0;
        switch ($transaction->status) {
            case PaymentStatus::SETTLED:
                $rate = 0.025;
                break;
            case PaymentStatus::AUTHORIZED:
                $rate = 0.010;
                break;
            case PaymentStatus::FAILED:
            case PaymentStatus::REFUNDED:
            case PaymentStatus::PENDING:
                $rate = 0.0;
                break;
            default:
                throw new \InvalidArgumentException('Status tidak valid.');
        }

        return $rate;
    }
}

// === RUNTIME EXECUTION TEST ===
$customer = new Customer(tier: 'VIP', profile: new Profile(locale: 'id_ID'));
$trx1 = new Transaction('TX-01', 500_000.0, PaymentStatus::SETTLED, $customer);
$trx2 = new Transaction('TX-02', 1_250_000.0, PaymentStatus::PENDING, null);

$processor = new TransactionProcessor();

echo "Commission Rate TX-01 : " . ($processor->resolveCommissionRate($trx1) * 100) . "%\n";
echo "Commission Rate TX-02 : " . ($processor->resolveCommissionRate($trx2) * 100) . "%\n";
echo "Locale TX-01          : " . $processor->resolveNotificationLocale($trx1) . "\n";
echo "Locale TX-02 (Default): " . $processor->resolveNotificationLocale($trx2) . "\n";

$sorted = $processor->sortByAmountDescending([$trx1, $trx2]);
echo "Highest Amount        : " . $sorted[0]->id . " (" . $sorted[0]->amount . ")\n";
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### 1. Kompilasi Zend VM Opcodes
Ketika PHP mengompilasi kode sumber menjadi *Opcodes* (instruksi perantara yang dijalankan oleh Zend VM):

*   **`switch` Statement**:
    Zend Engine memancarkan opcode berurutan: `ZEND_CASE`, yang diikuti oleh `ZEND_JMPZNZ` (jump conditional). Jika tidak ada `break`, *jump target* tidak melompati blok kode case berikutnya, menyebabkan eksekusi mengalir ke bawah (*fall-through*). 
    
    Jika nilai `case` berupa integer/string konstan, Opcache dapat mengoptimasi *switch* menjadi *Jump Table* (`ZEND_SWITCH_LONG` atau `ZEND_SWITCH_STRING`), yang memungkinkan *lookup* $O(1)$. Namun perbandingannya tetap menggunakan semantik `is_equal` (`==`).

*   **`match` Expression**:
    Struktur internal `match` menghasilkan *opcode* yang mengevaluasi subjek hanya **satu kali** ke dalam variabel temporer VM (`~T`). Kemudian, engine melakukan perbandingan menggunakan semantik `is_identical` (`===`).
    
    Ekspresi pada setiap cabang (*arm expression*) dievaluasi secara *lazy* (hanya dievaluasi ketika kondisi cabang tersebut terpenuhi). Jika tidak ada kondisi cabang yang cocok dan blok `default` tidak ditemukan, Zend Engine langsung menginterupsi eksekusi dan melempar `\UnhandledMatchError` pada level engine, menghindari *silent failure*.

#### 2. Mekanisme Alokasi Memori & Stack
- Operator **Null-safe (`?->`)**:
  Secara internal, `?->` tidak membuat *intermediate copy* dari objek ke stack. Compiler menyuntikkan instruksi pengecekan tipe implisit (`ZEND_FETCH_OBJ_R` atau penangan jump khusus). Jika operan sebelah kiri bernilai `IS_NULL`, eksekusi segera berhenti dari rantai evaluasi tersebut (*short-circuit*) dan mengembalikan `IS_NULL` secara instan tanpa alokasi memori heap tambahan untuk panggilan metode atau properti berikutnya.

- Operator **Spaceship (`<=>`)**:
  Diterjemahkan langsung menjadi satu instruksi virtual machine: `ZEND_SPACESHIP`. Instruksi ini mengembalikan nilai C scalar `-1`, `0`, atau `1` secara langsung di tingkat C runtime PHP tanpa perlu melakukan 2 kali evaluasi perbandingan (`$a < $b` lalu `$a > $b`), menghemat siklus clock CPU secara signifikan dalam algoritma pengurutan data (*sorting*).

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `match` untuk Mapping Data**: Gantikan `switch` dengan `match` setiap kali kamu perlu memetakan suatu nilai ke nilai lain (misalnya mapping status, HTTP methods, atau factory pattern sederhana).
- **Manfaatkan Enums Bersama `match`**: Mengombinasikan PHP 8.1+ Enums dengan `match` memberikan jaminan tipe absolut di level compile-time dan runtime. Jika kamu menambah case baru pada enum, `match` yang belum mengatasinya akan langsung melempar `UnhandledMatchError` dan mengidentifikasi bug lebih dini.
- **Gunakan Null Coalescing (`??`) daripada `isset() ?: `**: `??` menggabungkan operasi pengecekan eksistensi key array/variabel sekaligus validasi `null` tanpa memicu `E_WARNING: Undefined array key`.

#### Don'ts
- **Hindari Side-Effects Kompleks dalam Cabang `match`**: Cabang `match` dirancang untuk ekspresi tunggal. Menaruh logika pemanggilan fungsi yang memutasi database atau melempar side-effects acak di dalam cabang match merusak keterbacaan kode (*code readability*). Jika butuh blok eksekusi prosedural multi-baris yang masif, gunakan polimorfisme/strategy pattern atau `switch`.
- **Jangan Mengabaikan Type Juggling pada `switch`**:
  ```php
  $action = 0;
  switch ($action) {
      case 'view':   // Di PHP < 8.0, 0 == 'view' bernilai TRUE!
          renderView();
          break;
      case 0:
          handleDefault();
          break;
  }
  ```
  Meskipun PHP 8.0 memperketat perbandingan string-ke-angka, perbandingan non-striktif `switch` tetap membawa risiko implisit jika bekerja dengan data tipe campuran (*mixed types*).

#### Edge Cases
- **Pengecekan Tipe Boolean pada `match`**: 
  Saat menggunakan trik evaluasi ekspresi `match(true)`, urutan cabang (*arm order*) sangat menentukan.
  ```php
  $score = 85;
  $grade = match (true) {
      $score >= 80 => 'A',
      $score >= 70 => 'B',
      default      => 'C',
  };
  // Cabang pertama yang bernilai identical strict (true === ($score >= 80))
  // akan langsung dieksekusi; cabang di bawahnya tidak akan dievaluasi.
  ```
- **Ketidakcocokan Nilai Float**: Hati-hati membandingkan `float` di dalam `match`. Karena `match` menggunakan `===`, ketidakpresisian floating-point IEEE 754 (misalnya `0.1 + 0.2 === 0.3` bernilai `false`) akan menyebabkan cabang gagal terpilih dan memicu `UnhandledMatchError`.

### 5. Tantangan Eksplorasi Mandiri

1. **Analisis Opcodes**: Pasang ekstensi VLD (*Vulcan Logic Dumper*) pada CLI PHP kamu, atau jalankan perintah `php -d opcache.opt_debug_level=0x10000 script.php` pada PHP 8+. Tulis kode sederhana menggunakan `switch` dan `match`, lalu bandingkan daftar urutan *opcode* yang dihasilkan kedua struktur tersebut. Analisis perbedaan jump instruction-nya.
2. **Refactoring Legacy Code**: Cari blok kode lama yang menggunakan percabangan `switch` bertingkat (*nested switch*) atau rantai `if-elseif-else` yang mengevaluasi nilai konstan. Ubah seluruh implementasi tersebut menjadi satu ekspresi `match` yang deterministik, lengkap dengan custom exception handling untuk cabang tak terduga.
