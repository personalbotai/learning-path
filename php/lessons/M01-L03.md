# 3. Operator, Match Expression vs Switch

**ID**: M01-L03 | **Duration**: 15 m | **Level**: Semua | **Track**: PHP

## 🎯 Tujuan Pembelajaran
- Memahami kelemahan struktural `switch` dan keunggulan `match` expression di PHP 8.x.
- Menguasai operator modern: Nullsafe (`?->`), Null Coalescing (`??`), dan Spaceship (`<=>`).
- Menerapkan branching logika yang type-safe dan ekspresif.

## 📖 Konsep Mendalam

### Perbandingan: `match` vs `switch`
1. **Strict Equality**: `switch` menggunakan `==` (rawan bug type coercion), sedangkan `match` selalu menggunakan `===`.
2. **Expression Return**: `match` menghasilkan nilai (dapat langsung di-assign ke variabel atau di-return).
3. **No Fallthrough**: `match` tidak memerlukan keyword `break`.
4. **Exhaustive Check**: Melemparkan `UnhandledMatchError` jika tidak ada cabang yang cocok dan tidak disediakan `default`.

```php
<?php
declare(strict_types=1);

$httpStatus = 404;

// Menggunakan match expression
$pesan = match ($httpStatus) {
    200, 201 => 'Request Berhasil',
    400 => 'Bad Request',
    401, 403 => 'Akses Ditolak (Unauthorized/Forbidden)',
    404 => 'Halaman atau Resource Tidak Ditemukan',
    500 => 'Internal Server Error',
    default => 'Status Tidak Dikenal',
};

echo "HTTP {$httpStatus}: {$pesan}" . PHP_EOL;
```

## ⚠️ Best Practices & Common Pitfalls
- **Gunakan Match untuk Nilai Balikan**: Gunakan `match` jika kamu ingin mengevaluasi kondisi menjadi sebuah nilai. Pertahankan `switch` hanya jika ada blok kode prosedural panjang dengan efek samping ganda di tiap case.
