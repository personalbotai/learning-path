### 1. Konsep & Arsitektur Mendalam

**PHP Data Objects (PDO)** adalah lapisan abstraksi akses basis data (*database access abstraction layer*) yang terintegrasi secara *native* di dalam PHP runtime sebagai ekstensi berbasis C. Berbeda dengan *Object-Relational Mapping* (ORM) yang memetakan tabel ke model objek bisnis, PDO menyeragamkan Application Programming Interface (API) untuk berinteraksi dengan berbagai Real-Time Database Management System (RDBMS) seperti MySQL, PostgreSQL, SQLite, hingga Oracle.

```
+-------------------------------------------------------+
|                    Aplikasi PHP                       |
+-------------------------------------------------------+
                           |
                           v
+-------------------------------------------------------+
|                     PDO Core                          |
|         (Ekstensi C: Interface & Abstraksi)           |
+-------------------------------------------------------+
         |                     |                     |
         v                     v                     v
+-----------------+   +-----------------+   +-----------------+
|    pdo_mysql    |   |    pdo_pgsql    |   |   pdo_sqlite    |  <-- Driver Layer
+-----------------+   +-----------------+   +-----------------+
         |                     |                     |
         v                     v                     v
+-----------------+   +-----------------+   +-----------------+
|     mysqlnd     |   |    libpq        |   |   sqlite3 lib   |  <-- Low-level Client Libs
+-----------------+   +-----------------+   +-----------------+
         |                     |                     |
         v                     v                     v
      [ MySQL ]           [ PostgreSQL ]         [ SQLite ]
```

Arsitektur PDO terbagi menjadi dua komponen utama:
1. **PDO Core**: Menyediakan antarmuka seragam (class `PDO`, `PDOStatement`, `PDOException`) dan menangani *lifecycle* dasar operasi basis data.
2. **PDO Driver**: Modul spesifik database (misal: `pdo_mysql`, `pdo_pgsql`) yang mengimplementasikan protokol komunikasi database menggunakan *low-level client libraries* (seperti `mysqlnd` untuk MySQL atau `libpq` untuk PostgreSQL).

#### Evolusi Error Handling: Kenapa Exception Mode Krusial?

Secara historis, PDO menyediakan tiga strategi penanganan galat via atribut `PDO::ATTR_ERRMODE`:

1. `PDO::ERRMODE_SILENT`: Mengikuti paradigma warisan bahasa C. Kesalahan kueri hanya menyetel properti *error code* (`PDO::errorCode()` / `PDO::errorInfo()`) tanpa memutus eksekusi kode. Pola ini berbahaya di lingkungan produksi karena developer sering kali lupa memvalidasi *return value* setiap pemanggilan fungsi, yang berujung pada *silent data corruption*.
2. `PDO::ERRMODE_WARNING`: Memancarkan standard PHP E_WARNING. Tidak menghentikan alur program secara otomatis, tetapi mengotori output stream jika `display_errors` aktif.
3. `PDO::ERRMODE_EXCEPTION`: Memvalidasi prinsip *fail-fast*. Ketika komunikasi socket terputus, autentikasi gagal, atau sintaks kueri salah, PDO langsung menginstansiasi dan melemparkan objek `PDOException`. 

Mulai PHP 8.0, `PDO::ERRMODE_EXCEPTION` dijadikan sebagai *default mode*. Pendekatan ini memungkinkan transaksi ACID diisolasi dan di-*rollback* secara atomik di dalam blok `try-catch`, serta mencegah eksekusi instruksi kritis berikutnya jika dependensi data gagal diambil.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi *Database Connection Factory* yang *thread-safe*, menerapkan *strict typing*, konfigurasi atribut defensif, dan sanitasi pengecualian untuk mencegah kebocoran kredensial dalam *stack trace*.

```php
<?php

declare(strict_types=1);

namespace Infrastructure\Database;

use PDO;
use PDOException;
use RuntimeException;

final class ConnectionFactory
{
    private ?PDO $connection = null;

    /**
     * @param array<string, string|int> $config
     */
    public function __construct(
        private readonly array $config
    ) {}

    public function getConnection(): PDO
    {
        if ($this->connection instanceof PDO) {
            return $this->connection;
        }

        // Susun Data Source Name (DSN)
        $dsn = sprintf(
            '%s:host=%s;port=%d;dbname=%s;charset=%s',
            $this->config['driver'] ?? 'mysql',
            $this->config['host'] ?? '127.0.0.1',
            $this->config['port'] ?? 3306,
            $this->config['database'] ?? 'forge',
            $this->config['charset'] ?? 'utf8mb4'
        );

        $options = [
            // Paksa pelemparan PDOException untuk setiap error SQL/Koneksi
            PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
            
            // Kembalikan baris sebagai associative array secara default
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
            
            // Matikan emulasi; delegasikan prepared statement langsung ke database engine
            PDO::ATTR_EMULATE_PREPARES => false,
            
            // Timeout koneksi dalam hitungan detik
            PDO::ATTR_TIMEOUT => 5,
        ];

        try {
            $this->connection = new PDO(
                $dsn,
                (string) ($this->config['username'] ?? ''),
                (string) ($this->config['password'] ?? ''),
                $options
            );

            return $this->connection;
        } catch (PDOException $e) {
            // CRITICAL: Jangan biarkan PDOException mentah keluar ke unhandled exception handler
            // Objek PDOException membawa argumen konstruktor PDO yang berisi DSN, User, dan Password.
            
            // Catat error asli ke sistem log privat/internal
            error_log(sprintf('[DB Connection Error] Code: %s, Message: %s', $e->getCode(), $e->getMessage()));

            // Lempar runtime exception generik ke lapisan presentasi/aplikasi
            throw new RuntimeException('Basis data tidak dapat diakses. Silakan coba beberapa saat lagi.', (int) $e->getCode());
        }
    }
}

// ==========================================
// Contoh Penggunaan
// ==========================================

$config = [
    'driver'   => 'mysql',
    'host'     => '127.0.0.1',
    'port'     => 3306,
    'database' => 'production_app',
    'username' => 'db_user',
    'password' => 'SuperSecretP@ssw0rd!',
    'charset'  => 'utf8mb4',
];

$factory = new ConnectionFactory($config);

try {
    $db = $factory->getConnection();
    
    // Verifikasi koneksi aktif
    $stmt = $db->query('SELECT VERSION() AS version');
    $result = $stmt->fetch();
    
    echo "Koneksi Berhasil. Database Server Version: " . $result['version'] . PHP_EOL;

} catch (RuntimeException $e) {
    echo "Aplikasi Menangkap Kesalahan: " . $e->getMessage() . PHP_EOL;
}
```

#### Penjelasan Komponen Kunci:
- **`PDO::ATTR_EMULATE_PREPARES => false`**: Memaksa PHP menggunakan fitur *Native Prepared Statements* dari RDBMS daripada mengemulasikannya di memori runtime PHP via *string-escaping*. Ini menjamin tipe data integer/float dikembalikan sebagai tipe asli PHP (bukan string) saat menggunakan `mysqlnd`.
- **Sanitasi Exception**: Konstruktor `PDO` menyimpan kredensial di dalam properti internal *trace*. Menangkap `PDOException` dan menggantinya dengan `RuntimeException` mencegah tereksposnya kata sandi pada halaman log/crash dump seperti Whoops atau Sentry publik.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
1. **DSN Parsing**: Ketika `new PDO(...)` dipanggil, Zend Engine mem-parsing string DSN di lapisan C (`pdo_dbh.c`). Parameter seperti `charset`, `host`, dan `dbname` diekstrak ke dalam struktur C `pdo_data_src_parser`.
2. **Driver Dispatch**: PDO Core mencocokkan skema DSN (misal `mysql:`) dengan tabel *internal driver hash registry*. PDO memanggil fungsi *hook* inisialisasi driver spesifik: `pdo_mysql_handle_factory()`.
3. **Socket Initialization**: Driver menginstansiasi koneksi I/O network menggunakan *Native Driver* (`mysqlnd`). Jika host diatur ke `localhost` pada sistem berbasis UNIX, driver secara otomatis menggunakan *UNIX Domain Socket* (misal `/var/run/mysqld/mysqld.sock`), bukan TCP/IP stack (`127.0.0.1`), yang menghemat *packet overhead* dan alokasi *ephemeral port*.

#### Alokasi Memori / Resource
- Objek `PDO` di Zend Engine diwakili oleh struktur data C `pdo_dbh_t` (*database handle*). Di dalam `pdo_dbh_t`, terdapat pointer ke tabel virtual method (`pdo_dbh_ops`) yang memetakan fungsi-fungsi dasar: `connect`, `quoter`, `preparer`, dan `closer`.
- Setiap koneksi PDO mengonsumsi satu *File Descriptor* (FD) di level Kernel Linux untuk socket I/O.
- Berbeda dengan Node.js atau Go yang memiliki *in-memory connection pool* bawaan, model proses PHP-FPM adalah *Shared-Nothing Architecture*. Setiap worker PHP-FPM memegang instance memori terisolasi. Jika ada 50 worker PHP-FPM yang aktif melayani request, akan ada 50 koneksi TCP simultan yang terbuka ke server database, kecuali Anda menggunakan proxy koneksi perantara seperti ProxySQL atau PgBouncer.

#### Trade-offs
- **Abstraksi vs Native Feature**: PDO menyamaratakan perilaku database. Fitur-fitur eksklusif driver RDBMS tertentu terkadang tidak dapat diakses tanpa menyetel *driver-specific attributes* (misal `PDO::MYSQL_ATTR_INIT_COMMAND`).
- **Overhead**: Lapisan abstraksi PDO memanggil fungsi melalui *indirect function call* (pointer via virtual method table) di tingkat C, yang memiliki overhead instruksi CPU nanodetik lebih lambat dibanding pemanggilan langsung ekstensi prosedural primitif. Namun, bottleneck utama aplikasi web adalah I/O Latency jaringan, sehingga trade-off ini tergolong *negligible* dibanding nilai keamanan dan standardisasinya.

### 4. Best Practices & Common Pitfalls

#### Do's:
- **Gunakan Encoding `utf8mb4`**: Jangan pernah menggunakan charset `utf8` pada MySQL di DSN PDO. `utf8` pada MySQL adalah implementasi cacat (hanya mendukung maksimal 3-byte characters). Selalu tentukan `charset=utf8mb4` untuk mendukung penuh standard RFC 3629 (termasuk emoji dan karakter Asia kompleks).
- **Atur Timeout Rendah**: Selalu deklarasikan `PDO::ATTR_TIMEOUT`. Jika database down atau mengalami *network partition*, worker PHP tidak boleh menggantung (*hanging*) tanpa batas waktu hingga *PHP-FPM execution timeout* terlampaui.
- **Konfigurasi Fetch Mode Secara Terpusat**: Selalu pasang `PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC` untuk menghindari duplikasi data di memori. Mode default lama (`PDO::FETCH_BOTH`) mengembalikan data ganda (indeks numerik dan indeks asosiatif), yang melipatgandakan penggunaan memori RAM PHP.

#### Don'ts:
- **Jangan Mengabaikan Masking Kredensial**: Jangan pernah melempar `PDOException` hingga ke level framework exception handler tanpa modifikasi. Trace `PDO->__construct('mysql:...', 'root', 'mypass')` akan tercetak jelas dalam *stack trace string*.
- **Hindari `PDO::ATTR_PERSISTENT` Sembarangan**: Penggunaan *persistent connection* (`PDO::ATTR_PERSISTENT => true`) pada PHP-FPM dapat menyebabkan *state leakage*. Status transaksi yang belum di-commit, *lock*, atau *temporary tables* dapat terbawa ke request pengguna lain pada siklus worker PHP-FPM yang sama.
- **Jangan Lakukan Concatenation pada DSN**: Hindari membuat string DSN menggunakan input mentah dari *user-request*. Ambil murni dari konfigurasi file environment (`.env`).

#### Edge Cases:
- **MySQL Gone Away**: Jika koneksi idle melebihi konfigurasi `wait_timeout` pada MySQL, server akan menutup socket secara sepihak. Saat PDO mengeksekusi kueri berikutnya, ia akan melemparkan `PDOException` dengan error code `2006 (MySQL server has gone away)`. PDO tidak memiliki mekanisme *auto-reconnect* internal ketika exception mode menyala; aplikasi harus mengimplementasikan mekanisme *retry* atau me-reset instance connection.

### 5. Tantangan Eksplorasi Mandiri

1. **Simulasi Leakage & Sanitasi Error Trace**:
   Sengaja buat koneksi dengan password yang salah ke database lokal Anda. Tangkap objek `PDOException` dan cetak output dari metode bawaan `$e->getTraceAsString()`. Buktikan bahwa kata sandi basis data Anda terlihat jelas dalam teks trace tersebut. Tulis sebuah middleware class pembersih (*scrubber*) yang memvalidasi dan membuang informasi kredensial tersebut sebelum dikirimkan ke logger sistem.

2. **Benchmarking Emulated vs Native Prepared Statements**:
   Tulis sebuah skrip PHP untuk mengeksekusi kueri `SELECT` sebanyak 5.000 kali dalam sebuah perulangan:
   - Jalankan skrip pertama dengan opsi `PDO::ATTR_EMULATE_PREPARES => true`.
   - Jalankan skrip kedua dengan opsi `PDO::ATTR_EMULATE_PREPARES => false`.
   - Ukur konsumsi memori puncak (`memory_get_peak_usage()`) dan total waktu eksekusi. Analisis mengapa terjadi perbedaan performa dan tipe data (gunakan `var_dump()` untuk memverifikasi tipe integer yang dikembalikan dari field integer basis data).
