### 1. Konsep & Arsitektur Mendalam

Membangun REST API performan berskala produksi menuntut kontrol ketat terhadap tiga aspek: konsumsi resource infrastruktur (*Rate Limiting*), efisiensi pengambilan dataset (*Pagination*), dan integritas serialisasi data ke klien (*API Resource Formatting*).

```
[ Client Request ] 
       │
       ▼
┌──────────────────────────────────────────────┐
│ 1. Rate Limiter Middleware                   │ ──► [ Redis: Atomic Token Check / Decr ]
│    (429 Too Many Requests jika exhausted)    │
└──────────────────────────────────────────────┘
       │ (Pass)
       ▼
┌──────────────────────────────────────────────┐
│ 2. Query Layer & Pagination Engine           │ ──► [ RDBMS: B-Tree Index Keyset Seek ]
│    (Keyset/Cursor vs. Offset-based Scan)     │
└──────────────────────────────────────────────┘
       │ (PDO Recordset Hydration)
       ▼
┌──────────────────────────────────────────────┐
│ 3. API Resource Formatter                    │ ──► [ Anti-Corruption Layer / JSON Serialization ]
│    (Transformasi, Eager Load Guard)          │
└──────────────────────────────────────────────┘
       │
       ▼
[ Client Response (JSON + Headers) ]
```

#### Rate Limiting: Algoritma dan Konkurensi
Rate limiting membatasi frekuensi request dari identitas tertentu (IP, API Token, atau User ID) dalam jendela waktu spesifik. 
- **Fixed Window Counter**: Membagi waktu ke dalam slot statis (misal: 1 menit). Rentan terhadap *burst traffic* di batas antar-jendela (dapat menerima 2x limit jika request datang di detik ke-59 dan detik ke-01 jendela berikutnya).
- **Sliding Window Counter / Log**: Menggabungkan hitungan dari jendela sebelumnya dengan bobot persentase jendela saat ini, atau mencatat timestamp setiap request dalam Redis Sorted Set (`ZSET`). Menghilangkan kelemahan fixed window dengan overhead memori yang tetap terukur.
- **Token Bucket**: Bucket diisi token pada laju konstan (*refill rate*). Tiap request mengonsumsi token. Jika bucket kosong, request ditolak. Algoritma ini menoleransi burst terkontrol hingga kapasitas maksimal bucket tercapai.

Di layer runtime, implementasi rate limiting stateful harus di-offload ke in-memory store seperti Redis menggunakan operasi atomik atau skrip Lua untuk mencegah *race condition* antar worker PHP-FPM.

#### Pagination: Offset vs Keyset (Cursor)
- **Offset Pagination (`LIMIT x OFFSET y`)**: Mesin database (seperti MySQL InnoDB) harus menelusuri $y + x$ index record, membaca data dari disk/buffer pool, lalu membuang $y$ record pertama dan hanya mengembalikan $x$ record. Kompleksitasnya adalah $\mathcal{O}(N)$ terhadap nilai offset. Pada data jutaan baris, `OFFSET 1000000` memicu I/O disk masif dan CPU spike.
- **Keyset / Cursor Pagination (`WHERE id > :cursor ORDER BY id ASC LIMIT x`)**: Menggunakan index B-Tree secara langsung untuk melompat ke node target (*index seek*), kemudian membaca sejumlah $x$ baris berikutnya. Kompleksitasnya adalah $\mathcal{O}(\log N + M)$ di mana $M$ adalah ukuran limit, konstan terlepas seberapa dalam data diakses.

#### API Resource Formatting (Data Transformation Layer)
Resource Formatter bertindak sebagai *Anti-Corruption Layer* (ACL) antara skema relasional database dan kontrak publik API. Mengembalikan raw model dari ORM secara langsung melanggar prinsip *encapsulation*, berisiko membocorkan *internal state* (seperti `password_hash`, metadata multi-tenant), dan mengunci skema database agar identik dengan struktur JSON klien. Formatter juga mengisolasi logika transformasi tipe data primitif (casting ISO-8601 UTC string, boolean flag, dan nested relation).

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut menunjukkan implementasi modern berbasis PHP 8.2+ yang mencakup:
1. Rate Limiting atomik via Redis (Sliding Window Log).
2. Keyset (Cursor) Pagination Engine.
3. API Resource Formatter yang aman dari N+1 query problem.

```php
<?php

declare(strict_types=1);

namespace App\Http;

use Redis;
use PDO;
use RuntimeException;

// =========================================================================
// 1. RATE LIMITER (Redis Sliding Window Log via Atomic Pipeline)
// =========================================================================
final readonly class SlidingWindowRateLimiter
{
    public function __construct(
        private Redis $redis,
        private int $maxAttempts = 60,
        private int $decaySeconds = 60
    ) {}

    /**
     * Mengevaluasi apakah request diizinkan dan mengembalikan sisa kuota.
     * @return array{allowed: bool, limit: int, remaining: int, retry_after: int}
     */
    public function hit(string $identifier): array
    {
        $key = "rate_limit:{$identifier}";
        $currentTime = microtime(true);
        $windowStart = $currentTime - $this->decaySeconds;

        // Eksekusi atomik menggunakan Redis Pipeline / Multi-Exec
        $this->redis->multi();
        // Hapus entri di luar sliding window
        $this->redis->zRemRangeByScore($key, '-inf', (string) $windowStart);
        // Tambah hit saat ini dengan timestamp sebagai score & member
        $this->redis->zAdd($key, $currentTime, (string) $currentTime);
        // Hitung total hit dalam window aktif
        $this->redis->zCard($key);
        // Set TTL untuk mencegah resource leak pada key yang ditinggalkan
        $this->redis->expire($key, $this->decaySeconds);
        
        $results = $this->redis->exec();
        $currentHits = (int) $results[2];

        $allowed = $currentHits <= $this->maxAttempts;
        $remaining = max(0, $this->maxAttempts - $currentHits);
        
        // Kalkulasi retry-after berdasarkan elemen tertua dalam window
        $retryAfter = 0;
        if (!$allowed) {
            $oldest = $this->redis->zRange($key, 0, 0, true);
            if (!empty($oldest)) {
                $oldestTimestamp = (float) array_key_first($oldest);
                $retryAfter = (int) ceil($oldestTimestamp + $this->decaySeconds - $currentTime);
            }
        }

        return [
            'allowed' => $allowed,
            'limit' => $this->maxAttempts,
            'remaining' => $remaining,
            'retry_after' => max(0, $retryAfter),
        ];
    }
}

// =========================================================================
// 2. CURSOR PAGINATION ENGINE (Keyset Based)
// =========================================================================
final readonly class CursorPaginator
{
    public function __construct(private PDO $pdo) {}

    /**
     * @return array{data: array<int, array<string, mixed>>, next_cursor: ?string, has_more: bool}
     */
    public function paginate(int $perPage = 15, ?string $cursor = null): array
    {
        // Decode cursor: base64 encoded record ID
        $afterId = 0;
        if ($cursor !== null) {
            $decoded = base64_decode($cursor, true);
            if ($decoded !== false && ctype_digit($decoded)) {
                $afterId = (int) $decoded;
            }
        }

        // Ambil $perPage + 1 untuk mendeteksi ketersediaan halaman berikutnya tanpa COUNT(*)
        $sql = "SELECT id, title, content, author_id, created_at 
                FROM articles 
                WHERE id > :after_id 
                ORDER BY id ASC 
                LIMIT :limit";

        $stmt = $this->pdo->prepare($sql);
        $stmt->bindValue(':after_id', $afterId, PDO::PARAM_INT);
        $stmt->bindValue(':limit', $perPage + 1, PDO::PARAM_INT);
        $stmt->execute();

        /** @var array<int, array<string, mixed>> $rows */
        $rows = $stmt->fetchAll(PDO::FETCH_ASSOC);

        $hasMore = count($rows) > $perPage;
        if ($hasMore) {
            array_pop($rows); // Hapus record indikator ke-(perPage + 1)
        }

        $lastRow = end($rows);
        $nextCursor = ($hasMore && $lastRow !== false) 
            ? base64_encode((string) $lastRow['id']) 
            : null;

        return [
            'data' => $rows,
            'next_cursor' => $nextCursor,
            'has_more' => $hasMore,
        ];
    }
}

// =========================================================================
// 3. API RESOURCE TRANSFORMATION
// =========================================================================
final class ArticleResource
{
    /**
     * @param array<string, mixed> $article
     * @return array<string, mixed>
     */
    public static function toArray(array $article): array
    {
        return [
            'id' => (int) $article['id'],
            'title' => (string) $article['title'],
            'snippet' => mb_substr((string) $article['content'], 0, 100) . '...',
            'author_id' => (int) $article['author_id'],
            'published_at' => (new \DateTimeImmutable((string) $article['created_at']))
                ->format(\DateTimeInterface::ATOM),
            '_links' => [
                'self' => "/api/v1/articles/{$article['id']}",
            ],
        ];
    }

    /**
     * @param array<int, array<string, mixed>> $collection
     * @return array<int, array<string, mixed>>
     */
    public static function collection(array $collection): array
    {
        return array_map([self::class, 'toArray'], $collection);
    }
}

// =========================================================================
// 4. HTTP DISPATCHER ENTRYPOINT
// =========================================================================
// Inisialisasi dependensi
$redis = new Redis();
$redis->connect('127.0.0.1', 6379);

$pdo = new PDO('mysql:host=127.0.0.1;dbname=app;charset=utf8mb4', 'root', 'secret', [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_EMULATE_PREPARES => false,
]);

$rateLimiter = new SlidingWindowRateLimiter($redis, maxAttempts: 5, decaySeconds: 60);
$clientIp = $_SERVER['REMOTE_ADDR'] ?? '127.0.0.1';

// Evaluasi Rate Limiting
$rateLimitStatus = $rateLimiter->hit($clientIp);

header('Content-Type: application/json; charset=UTF-8');
header("X-RateLimit-Limit: {$rateLimitStatus['limit']}");
header("X-RateLimit-Remaining: {$rateLimitStatus['remaining']}");

if (!$rateLimitStatus['allowed']) {
    header('HTTP/1.1 429 Too Many Requests');
    header("Retry-After: {$rateLimitStatus['retry_after']}");
    echo json_encode([
        'error' => 'Too Many Requests',
        'message' => 'Rate limit exceeded. Please retry later.',
        'retry_after_seconds' => $rateLimitStatus['retry_after'],
    ], JSON_THROW_ON_ERROR);
    exit;
}

// Eksekusi Paginasi & Formatting
$cursor = isset($_GET['cursor']) ? (string) $_GET['cursor'] : null;
$paginator = new CursorPaginator($pdo);
$paginatedResult = $paginator->paginate(perPage: 2, cursor: $cursor);

$responsePayload = [
    'data' => ArticleResource::collection($paginatedResult['data']),
    'meta' => [
        'per_page' => 2,
        'has_more' => $paginatedResult['has_more'],
        'next_cursor' => $paginatedResult['next_cursor'],
    ],
];

echo json_encode($responsePayload, JSON_THROW_ON_ERROR | JSON_UNESCAPED_SLASHES);
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Redis Pipeline & Memory Layout
Pada class `SlidingWindowRateLimiter`, pemanggilan `$redis->multi()` dan `$redis->exec()` mengaktifkan mode *pipelining* di level network socket. Seluruh perintah dipadatkan ke dalam satu frame TCP request menuju server Redis, mengeksekusi instruksi secara berurutan dalam satu thread Redis tanpa terinterupsi perintah dari koneksi lain, dan mengembalikan seluruh respons dalam satu balasan network. 

Struktur data internal Redis untuk `ZSET` menggunakan gabungan **Hash Table** dan **SkipList**. Operasi penambahan dan penghapusan (`ZADD`, `ZREM`) membutuhkan kompleksitas waktu $\mathcal{O}(\log M)$ di mana $M$ adalah jumlah total hit dalam window. Memori dialokasikan per node dalam SkipList, sehingga sliding window memakan alokasi memori yang proporsional terhadap volume traffic, bukan sekadar sebuah single counter integer seperti pada Fixed Window.

#### Alokasi Memori: Keyset vs. Offset Scan
Saat menjalankan `OFFSET 1000000 LIMIT 15`:
1. Storage Engine (InnoDB) membaca index root B-Tree, menelusuri branch level hingga ke leaf level.
2. Karena engine diminta membaca 1.000.015 record, InnoDB harus memuat blok-blok halaman (*InnoDB Buffer Pool*) dari storage ke RAM untuk 1 juta record tersebut.
3. Seluruh baris dimuat ke memori thread server MySQL, dihitung hingga mencapai offset, lalu 1.000.000 baris dibuang secara cuma-cuma.

Sebaliknya, pada Keyset Pagination:
```sql
WHERE id > :after_id ORDER BY id ASC LIMIT 15
```
Engine melakukan operasi *B-Tree search* langsung ke posisi leaf node bernilai `after_id` dengan kompleksitas $\mathcal{O}(\log N)$, lalu melakukan pemindaian sequential sejauh 15 pointer record berikutnya. Memory buffer pool RDBMS tetap dingin (*cache friendly*), dan I/O read tetap minimum.

#### Hydration & Serialization Cost di PHP
Ketika PDO membaca data dari MySQL wire protocol, data tersebut diubah menjadi struktur memori internal PHP: `zval` (Zend Values). 
- Jika Anda menggunakan ORM berat (seperti Doctrine atau Laravel Eloquent) untuk puluhan ribu record, PHP harus mengalokasikan objek utuh beserta array metadata, state tracking, dan dynamic property hashes untuk setiap baris.
- Menggunakan raw PDO array atau `ReadOnly DTO` menurunkan jejak memori (*peak memory usage*) hingga 80-90% dibandingkan menginstansiasi full Model instance sebelum di-passing ke JSON encoder.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan HTTP Spec Headers secara Tepat**: Selalu sertakan `X-RateLimit-Limit`, `X-RateLimit-Remaining`, dan `Retry-After` (khusus status 429) agar klien (seperti mobile app atau API SDK) dapat mengimplementasikan strategi *Exponential Backoff*.
- **Terapkan Keyset/Cursor Pagination untuk Dataset Besar**: Khusus untuk tabel dengan jutaan baris atau fitur infinite-scrolling realtime.
- **Eager Load Relasi Sebelum Formatter**: Jika API Resource membutuhkan data relasi (misal `$article->author->name`), pastikan query telah meng-eager load relasi tersebut di query builder.
- **Pilih Column Projection yang Spesifik**: Hindari `SELECT *`. Tarik hanya field yang dibutuhkan Resource Formatter guna mengurangi alokasi memori PDO dan konsumsi bandwidth antara database dan server PHP-FPM.

#### Don'ts
- **N+1 Query di dalam Resource Formatter**: Menjalankan query DB di dalam method `toArray()` adalah anti-pattern fatal:
  ```php
  // FATAL BUG: Menyebabkan 100 query tambahan untuk 100 item
  'author' => User::find($article['author_id'])->name, 
  ```
- **Menggunakan `COUNT(*)` untuk Pagination Skala Besar**: Menjalankan `SELECT COUNT(*)` pada tabel InnoDB jutaan baris memicu pembacaan clustered index yang sangat lambat karena InnoDB harus memverifikasi isolasi transaksi (MVCC). Gunakan teknik *slice checking* (`LIMIT perPage + 1`) untuk mendeteksi halaman berikutnya tanpa perlu mengetahui total count.
- **Exposing Internal Identifiers**: Jangan mengekspos auto-increment integer ID jika data bersifat sensitif terhadap estimasi bisnis (*enumeration attack*). Pertimbangkan decoding/encoding UUID v7 atau Hashids di tingkat Resource Formatter.

#### Edge Cases
- **Clock Drift**: Jika menggunakan multi-node Redis cluster atau server PHP yang berbeda, sinkronisasi waktu NTP (Network Time Protocol) yang buruk dapat menyebabkan sliding window rate limiter menghitung mundur atau mengizinkan burst traffic ilegal.
- **Penghapusan Data saat Paging**: Pada Keyset pagination, jika record dengan cursor ID dihapus oleh proses lain tepat setelah dibaca, klien masih aman meminta `WHERE id > :deleted_id` karena B-Tree index tetap dapat menemukan posisi tetangga terdekat dari ID tersebut tanpa memicu crash atau lompatan data ganda.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Token Bucket dengan Redis & Lua Script**:
   Ubah arsitektur `SlidingWindowRateLimiter` menjadi algoritma *Token Bucket* menggunakan skrip Redis Lua (`EVAL`). Pastikan proses kalkulasi *refill rate* dan konsumsi token dieksekusi secara 100% atomik di dalam engine Redis untuk meminimalkan latensi round-trip network.

2. **Keyset Pagination Multi-Kolom**:
   Modifikasi `CursorPaginator` agar mendukung sorting data non-unique, seperti pengurutan berdasarkan `created_at DESC, id DESC`. Rancang struktur composite cursor (gabungan timestamp dan ID) yang di-encode ke Base64, serta rumuskan klausa SQL `WHERE (created_at, id) < (:cursor_time, :cursor_id)` dengan index komposit yang optimal di MySQL/PostgreSQL.
