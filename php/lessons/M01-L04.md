## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Struktur kontrol adalah fondasi alur eksekusi (control flow) dalam bahasa pemrograman imperatif. Di dalam PHP, instruksi dieksekusi secara sekuensial dari atas ke bawah kecuali jika dialihkan oleh struktur kondisional (`if`, `else`, `switch`, `match`) atau perulangan (`for`, `foreach`, `while`).

#### Evolusi Pengecekan Null & Kondisional
Sebelum PHP 8.0, navigasi relasi objek yang dalam (*deep object graph*) mengharuskan pengecekan `null` bertingkat untuk menghindari fatal error `Uncaught Error: Call to a member function on null`. Pendekatan konvensional menggunakan rantai `isset()`, `empty()`, atau kondisional bersarang:

```php
// Pendekatan Imperatif Tradisional (Pre-PHP 8.0)
$country = null;
if ($user !== null) {
    $profile = $user->getProfile();
    if ($profile !== null) {
        $address = $profile->getAddress();
        if ($address !== null) {
            $country = $address->country;
        }
    }
}
```

Pola ini menghasilkan *boilerplate code* masif dan meningkatkan kompleksitas siklomatis (*cyclomatic complexity*). PHP 7.0 memperkenalkan *Null Coalescing Operator* (`??`), namun operator ini terbatas pada ekspresi `isset` (array key dan variabel) dan tidak dapat memitigasi pemanggilan method berantai pada objek bernilai `null`.

#### Nullsafe Operator (`?->`)
PHP 8.0 memperkenalkan **Nullsafe Operator** (`?->`). Operator ini mengevaluasi ekspresi di sisi kiri: jika operan tidak bernilai `null`, eksekusi dilanjutkan ke pemanggilan method atau akses properti berikutnya. Jika bernilai `null`, seluruh rantai evaluasi dihentikan (*short-circuited*) dan ekspresi langsung mengembalikan nilai `null` tanpa mengeksekusi sisa rantai operasi.

#### `match` vs `switch`
PHP 8.0 juga mendesain ulang paradigma percabangan nilai dengan ekspresi `match`:
- **Evaluasi Tipe**: `switch` menggunakan perbandingan longgar (*loose comparison* `==`), yang sering memicu *type juggling bugs* (misal: `0 == 'foo'` bernilai `true` di PHP < 8.0). `match` menggunakan perbandingan ketat (*strict identity* `===`).
- **Return Value**: `switch` adalah sebuah *statement* struktural (tidak menghasilkan nilai), sedangkan `match` adalah sebuah *expression* (menghasilkan nilai yang bisa langsung di-assign ke variabel atau di-return).
- **Fallthrough & Exhaustiveness**: `switch` mengeksekusi blok kode berikutnya secara implisit jika tidak dihentikan dengan `break` (*fallthrough*). `match` tidak mendukung fallthrough dan mewajibkan penanganan seluruh kemungkinan nilai (*exhaustive check*), memicu `UnhandledMatchError` jika tidak ada *arm* yang cocok dan klausa `default` diabaikan.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern pemrosesan data transaksi checkout e-commerce yang menggabungkan Nullsafe Operator, Guard Clauses, dan Ekspresi `match`.

```php
<?php

declare(strict_types=1);

namespace App\Billing;

enum PaymentStatus: string
{
    case PENDING = 'pending';
    case SETTLED = 'settled';
    case FAILED = 'failed';
    case REFUNDED = 'refunded';
}

final class Address
{
    public function __construct(
        public readonly string $city,
        public readonly string $countryIso
    ) {}
}

final class CustomerProfile
{
    public function __construct(
        private readonly ?Address $shippingAddress
    ) {}

    public function getShippingAddress(): ?Address
    {
        return $this->shippingAddress;
    }
}

final class Customer
{
    public function __construct(
        public readonly int $id,
        private readonly ?CustomerProfile $profile
    ) {}

    public function getProfile(): ?CustomerProfile
    {
        return $this->profile;
    }

    public function calculateRiskModifier(): float
    {
        // Simulasi kalkulasi berat
        return 1.25;
    }
}

final class Order
{
    public function __construct(
        public readonly string $orderId,
        public readonly ?Customer $customer,
        public readonly PaymentStatus $paymentStatus,
        public readonly float $baseAmount
    ) {}
}

final class OrderProcessor
{
    /**
     * Memproses pesanan menggunakan Guard Clauses, Nullsafe Operator,
     * Null Coalescing, dan Expression Match.
     */
    public function process(Order $order): string
    {
        // 1. Guard Clause: Eliminasi state transaksi gagal seawal mungkin
        if ($order->paymentStatus === PaymentStatus::FAILED) {
            return "Order {$order->orderId} ditolak: Status Pembayaran Gagal.";
        }

        // 2. Nullsafe Operator + Short-circuiting evaluation
        // Jika $order->customer bernilai null, calculateRiskModifier() TIDAK AKAN dieksekusi.
        $risk = $order->customer?->calculateRiskModifier() ?? 1.0;

        // 3. Nullsafe Operator berantai untuk navigasi deep-graph
        $countryIso = $order->customer
            ?->getProfile()
            ?->getShippingAddress()
            ?->countryIso ?? 'ID'; // Fallback default 'ID'

        // 4. Match Expression untuk resolusi fee berdasarkan Enum
        $handlingFee = match ($order->paymentStatus) {
            PaymentStatus::PENDING => 5000.0,
            PaymentStatus::SETTLED => 0.0,
            PaymentStatus::REFUNDED => 15000.0,
            // Tidak membutuhkan default karena semua kasus Enum PaymentStatus sudah ter-cover
        };

        $finalAmount = ($order->baseAmount * $risk) + $handlingFee;

        return sprintf(
            "Order %s diproses untuk negara [%s]. Total: IDR %.2f",
            $order->orderId,
            $countryIso,
            $finalAmount
        );
    }
}

// --- Driver Code ---
$orderTanpaCustomer = new Order(
    orderId: 'ORD-001',
    customer: null,
    paymentStatus: PaymentStatus::PENDING,
    baseAmount: 100000.0
);

$processor = new OrderProcessor();
echo $processor->process($orderTanpaCustomer) . PHP_EOL;
// Output: Order ORD-001 diproses untuk negara [ID]. Total: IDR 105000.00
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (Zend VM Opcodes)
1. **Nullsafe Short-Circuiting**:
   Ketika skrip di-compile menjadi bytecode (Opcodes), ekspresi `$user?->getProfile()?->getAddress()` dikonversi oleh Zend Compiler menjadi instruksi kondisional bertingkat.
   - Opcode generator mengemisikan instruksi pemeriksaan null mirip dengan `ZEND_JMP_NULL`.
   - Jika operan sisi kiri adalah `IS_NULL`, Zend VM memodifikasi *Instruction Pointer* (IP) untuk langsung melompati instruksi `ZEND_INIT_METHOD_CALL` dan `ZEND_DO_FCALL`, kemudian langsung meletakkan tipe data `IS_NULL` ke register hasil penampung (*temporary variable*).
   - Argument yang dioperasikan pada method chain tersebut tidak dievaluasi (*non-eager evaluation*), mencegah pemborosan cycle CPU untuk method/fungsi yang tidak relevan.

2. **Jumping Mechanics pada `match`**:
   Berbeda dengan `switch` yang di-compile menjadi rantai opcode kondisional linier (`ZEND_IS_EQUAL` diikuti `ZEND_JMPNZ`), ekspresi `match` dengan nilai literal/konstanta dioptimalkan oleh PHP compiler menggunakan **Jump Table** (struktur data berbasis *Hashtable* di C). Pencarian cabang target menjadi operasi berkecepatan $\mathcal{O}(1)$ rata-rata, dibandingkan dengan $\mathcal{O}(N)$ pada `switch`.

#### Alokasi Memori / Resource
- **Pencegahan Frame Stack Allocation**: Pemanggilan method `$obj?->method()` pada target `null` melewati alokasi *Call Frame Stack* (`zend_execute_data`). Memori lokal fungsi target tidak pernah diinisiasi.
- **Copy-On-Write (COW) pada Iterasi**:
  Pada loop `foreach ($array as $value)`, PHP mereferensikan array zval yang sama dan hanya meningkatkan `refcount`. Modifikasi array di dalam loop akan memicu duplikasi memori secara fisik (*COW*). Pemilihan antara perulangan berbasis *by-value* versus *by-reference* (`foreach ($array as &$value)`) memengaruhi apakah zval didekonstruksi menjadi referensi langsung (`IS_REFERENCE`).

#### Trade-offs
- **Abstraksi vs Enkapsulasi (Law of Demeter)**: Penggunaan `?->` yang terlalu panjang (`$a?->getB()?->getC()?->getD()`) dapat menjadi *code smell*. Meskipun aman dari *Null Pointer Exception*, pola ini menandakan tingginya *coupling* antar objek dan melanggar prinsip *Tell, Don't Ask*.
- **Silent Failures**: Penggunaan `?->` yang tidak disiplin dapat menyembunyikan inkonsistensi data domain. Objek yang semestinya wajib ada (misal: order harus selalu memiliki *invoice*) menjadi terabaikan secara hening (*silent degradation*) alih-alih melempar exception sedini mungkin.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Guard Clauses**: Balik logika kondisional bersarang dengan *early return* atau *early throw* untuk mereduksi kedalaman indentasi.
- **Kombinasikan `?->` dengan `??`**: Karena Nullsafe Operator mengembalikan `null` saat short-circuit, gabungkan dengan Null Coalescing Operator untuk mendefinisikan nilai cadangan secara eksplisit:
  ```php
  $timeout = $config?->getNetwork()?->getTimeout() ?? 30;
  ```
- **Prioritaskan `match` daripada `switch`**: Gunakan `match` untuk seluruh operasi pemetaan (*mapping*) nilai satu-ke-satu demi keamanan tipe (*strict type safety*).

#### Don'ts
- **Menulis ke Properti Menggunakan Nullsafe (Write-Context)**: Nullsafe operator dilarang digunakan dalam konteks penulisan referensi atau assignment.
  ```php
  // FATAL COMPILE ERROR: Can't use nullsafe operator in write context
  $user?->profile->name = 'John'; 
  ```
- **Menggunakan `?->` pada Array Access**: Nullsafe operator hanya bekerja pada *object property* dan *object method*, tidak dapat digunakan pada array indexing.
  ```php
  // SYNTAX ERROR
  $data?['user']?['id']; 

  // Solusi: Gunakan null coalescing
  $id = $data['user']['id'] ?? null;
  ```
- **Mengabaikan Side Effects dalam Argumen**:
  Perhatikan bahwa argumen tidak akan pernah dieksekusi jika objek utama bernilai `null`:
  ```php
  // Logger TIDAK AKAN menulis log jika $repository null
  $repository?->save($logger->log('Saving data...'));
  ```

#### Edge Cases
- **Pemeriksaan `empty()` dan `isset()` terhadap Nullsafe Chain**:
  `isset($user?->profile)` tidak valid di PHP dan akan menghasilkan parse error. Nullsafe operator secara fundamental adalah ekspresi pembacaan nilai, bukan variabel atau properti target pengecekan *zval reference*.

### 5. Tantangan Eksplorasi Mandiri

1. **Inspeksi Bytecode (Opcode Analysis)**:
   Buat dua berkas PHP: satu menggunakan pengecekan manual bersarang (`if ($a !== null && $a->getB() !== null)`), dan satu menggunakan Nullsafe Operator (`$a?->getB()`). Analisis perbedaan instruksi VM yang dihasilkan menggunakan CLI:
   ```bash
   php -d opcache.enable_cli=1 -d opcache.opt_debug_level=0x10000 file.php
   ```
   Identifikasi keberadaan instruksi `JMP` dan bandingkan kompleksitas opcodenya.

2. **Refaktorisasi Anti-Pattern**:
   Diberikan blok kode *legacy* berikut:
   ```php
   function resolveTax($user, $type) {
       $rate = 0;
       switch ($type) {
           case 'standard':
               $rate = 0.11;
               break;
           case 0: // Waspada type juggling!
               $rate = 0.0;
               break;
           default:
               $rate = 0.05;
       }
       if ($user != null) {
           if ($user->getAddress() != null) {
               return $user->getAddress()->isExempt() ? 0 : $rate;
           }
       }
       return $rate;
   }
   ```
   Rancang ulang fungsi tersebut menjadi fungsi modern, strictly typed, bebas bug *type juggling*, dan mengimplementasikan `match`, `?->`, serta *guard clause*.
