## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

GraphQL adalah bahasa kueri (query language) untuk API dan runtime untuk mengeksekusi kueri tersebut menggunakan sistem tipe (type system) yang Anda definisikan untuk data Anda. Berbeda dengan REST yang menggunakan pendekatan *resource-based* dengan banyak endpoint, GraphQL beroperasi pada satu endpoint tunggal (biasanya `POST /graphql`) di mana klien secara eksplisit meminta bentuk data yang mereka butuhkan.

**Mengapa GraphQL ada?**
REST sering kali mengalami masalah **Over-fetching** (mengambil data lebih dari yang dibutuhkan klien) dan **Under-fetching** (klien harus melakukan *multiple round-trips* ke beberapa endpoint untuk merangkai data). GraphQL menyelesaikan ini dengan memberikan kontrol penuh kepada klien atas *payload* respons.

**Arsitektur GraphQL di PHP:**
Implementasi standar de-facto di ekosistem PHP adalah library `webonyx/graphql-php`. Arsitekturnya terdiri dari:
1.  **Schema:** Kontrak yang mendefinisikan kapabilitas API (Types, Queries, Mutations, Subscriptions). Di PHP, ini bisa dibangun menggunakan *Code-First* (mendefinisikan class PHP) atau *Schema-First* (mem-parsing file `.graphql` / SDL).
2.  **Resolvers:** Fungsi murni (pure functions) atau metode yang bertanggung jawab untuk mengambil data aktual untuk setiap *field* dalam skema.
3.  **Execution Engine:** Saat *request* masuk, engine akan:
    *   **Lexing & Parsing:** Mengubah string kueri menjadi *Abstract Syntax Tree* (AST).
    *   **Validation:** Memeriksa AST terhadap Skema (apakah field ada? apakah tipe argumen benar?).
    *   **Execution:** Berjalan menelusuri AST (biasanya secara *breadth-first*) dan memanggil *resolvers* terkait, lalu merangkai hasilnya menjadi JSON.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi *Code-First* menggunakan `webonyx/graphql-php`. Kita akan membuat API sederhana untuk mengambil data `User` beserta `Post` yang mereka tulis.

*Prasyarat: `composer require webonyx/graphql-php`*

```php
<?php
declare(strict_types=1);

require_once __DIR__ . '/vendor/autoload.php';

use GraphQL\Type\Definition\ObjectType;
use GraphQL\Type\Definition\Type;
use GraphQL\Type\Schema;
use GraphQL\GraphQL;

// --- 1. Mock Data (Biasanya dari Database/ORM) ---
$users = [
    1 => ['id' => 1, 'name' => 'Budi Santoso', 'email' => 'budi@example.com'],
    2 => ['id' => 2, 'name' => 'Siti Aminah', 'email' => 'siti@example.com'],
];

$posts = [
    1 => ['id' => 101, 'user_id' => 1, 'title' => 'Belajar GraphQL PHP'],
    2 => ['id' => 102, 'user_id' => 1, 'title' => 'Arsitektur Microservices'],
    3 => ['id' => 103, 'user_id' => 2, 'title' => 'Optimasi Database'],
];

// --- 2. Definisi Tipe (Types) ---
$postType = new ObjectType([
    'name' => 'Post',
    'fields' => [
        'id' => Type::nonNull(Type::int()),
        'title' => Type::string(),
    ]
]);

$userType = new ObjectType([
    'name' => 'User',
    'fields' => function() use (&$postType, $posts) {
        return [
            'id' => Type::nonNull(Type::int()),
            'name' => Type::string(),
            'email' => Type::string(),
            // Field relasi dengan resolver kustom
            'posts' => [
                'type' => Type::listOf($postType),
                'resolve' => function ($user) use ($posts) {
                    // Filter posts berdasarkan user_id
                    return array_filter($posts, fn($post) => $post['user_id'] === $user['id']);
                }
            ]
        ];
    }
]);

// --- 3. Definisi Root Query ---
$queryType = new ObjectType([
    'name' => 'Query',
    'fields' => [
        'user' => [
            'type' => $userType,
            'args' => [
                'id' => Type::nonNull(Type::int()),
            ],
            'resolve' => function ($rootValue, array $args) use ($users) {
                return $users[$args['id']] ?? null;
            }
        ],
        'users' => [
            'type' => Type::listOf($userType),
            'resolve' => function () use ($users) {
                return $users;
            }
        ]
    ],
]);

// --- 4. Setup Schema & Eksekusi ---
try {
    $schema = new Schema([
        'query' => $queryType,
    ]);

    // Mengambil raw input dari request body (JSON)
    $rawInput = file_get_contents('php://input');
    $input = json_decode($rawInput, true);
    $query = $input['query'] ?? '{ users { id name posts { title } } }'; // Default query untuk testing
    $variableValues = $input['variables'] ?? null;

    // Eksekusi GraphQL
    $result = GraphQL::executeQuery($schema, $query, null, null, $variableValues);
    $output = $result->toArray();

} catch (\Exception $e) {
    $output = [
        'errors' => [
            ['message' => $e->getMessage()]
        ]
    ];
}

// --- 5. Output Response ---
header('Content-Type: application/json; charset=UTF-8');
echo json_encode($output);
```

**Penjelasan Kode:**
*   **`ObjectType`**: Mendefinisikan entitas. Perhatikan penggunaan *closure* (`function() use (...)`) pada `fields` di `$userType`. Ini adalah teknik *Lazy Loading* tipe untuk mencegah *circular dependency* (misal: User punya Post, Post punya User).
*   **`resolve`**: Fungsi ini menerima 4 argumen secara default: `$rootValue` (hasil dari parent resolver), `$args` (argumen kueri), `$context` (state global seperti user login), dan `$info` (metadata AST).
*   **`GraphQL::executeQuery`**: Engine utama yang memproses string kueri terhadap skema yang telah didefinisikan.

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: Saat kueri `{ users { name posts { title } } }` dieksekusi, engine GraphQL PHP tidak mengambil semua data sekaligus. Ia berjalan secara hierarkis:
  1. Memanggil resolver `users` (mengembalikan array 2 user).
  2. Untuk setiap user, engine melihat field `name` (diambil langsung dari array key) dan `posts`.
  3. Engine memanggil resolver `posts` **dua kali** (satu untuk setiap user) untuk mendapatkan data post.
- **Alokasi Memori / Resource**: Karena GraphQL mem-parsing string menjadi AST (berupa objek-objek PHP di memori), kueri yang sangat besar atau sangat dalam (*deeply nested*) akan mengkonsumsi RAM secara signifikan pada proses PHP.
- **Trade-offs**: Fleksibilitas di sisi klien dibayar dengan kompleksitas di sisi server. Caching HTTP standar (seperti Varnish/CDN) sulit diterapkan karena semua request menggunakan `POST /graphql`. Solusinya biasanya menggunakan *Persisted Queries* atau caching di level resolver/Redis.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - **Gunakan DataLoader pattern:** Pisahkan logika *fetching* data dari resolver untuk mengatasi masalah N+1. Gunakan library seperti `overblog/dataloader-php`.
  - **Pisahkan Business Logic:** Resolver **tidak boleh** berisi logika bisnis atau query SQL langsung. Resolver hanya bertugas sebagai jembatan (delegator) ke *Service* atau *Repository layer*.
  - **Gunakan Pagination Berbasis Kursor (Relay Connection):** Untuk list data yang panjang, hindari offset/limit standar. Gunakan spesifikasi *Relay Cursor Connections* untuk pagination yang konsisten.

- **Don'ts**:
  - **Jangan abaikan Security (Query Depth & Complexity):** Klien jahat dapat mengirim kueri bersarang tanpa batas (misal: `user { posts { author { posts { ... } } } }`). Ini akan menyebabkan *Denial of Service* (DoS). Selalu batasi *Query Depth* dan *Query Complexity* di konfigurasi `webonyx`.
  - **Jangan mengekspos error internal:** Secara default, exception PHP bisa bocor ke respons GraphQL. Gunakan *Error Formatter* kustom untuk menyembunyikan *stack trace* di production.

- **Edge Cases**:
  - **N+1 Problem:** Ini adalah jebakan paling umum. Jika Anda mengambil 100 User, dan setiap User meminta Post-nya, GraphQL akan melakukan 1 query untuk User, dan 100 query terpisah untuk Post (Total 101 Query). *DataLoader* mengumpulkan (batching) 100 ID user tersebut dan melakukan 1 query `WHERE user_id IN (...)`.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Mutation:** Tambahkan `MutationType` pada skema di atas untuk memungkinkan klien membuat `Post` baru (`createPost(userId: Int!, title: String!): Post`).
2. **Selesaikan N+1 Problem:** Integrasikan library `overblog/dataloader-php` ke dalam kode di atas. Ubah resolver `posts` pada `$userType` agar menggunakan DataLoader alih-alih melakukan filter array secara langsung.
3. **Limitasi Kompleksitas:** Cari tahu cara menggunakan `DocumentValidator::addRule()` pada `webonyx/graphql-php` untuk membatasi kedalaman kueri (Query Depth) maksimal menjadi 3 level. Uji dengan mengirimkan kueri yang bersarang dalam.
