## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Secara historis, PHP adalah bahasa bertipe dinamis yang melakukan *type resolution* saat *runtime* melalui Zend Engine. Pendekatan ini menawarkan fleksibilitas prototyping yang cepat, namun membawa risiko fatal di level enterprise: *type coercion bug*, *undefined method call*, dan kegagalan tak terduga (*runtime crashes* seperti `TypeError` atau fatal error) ketika aplikasi menerima input yang tidak diantisipasi.

**Static Analysis** memverifikasi kebenaran program tanpa mengeksekusi kodenya. Dua kakas (*tooling*) standar industri terdepan di ekosistem modern PHP adalah **PHPStan** dan **Psalm**. Keduanya bertindak sebagai *compile-time type checker* virtual yang berjalan di atas PHP CLI.

```
       Source Code (.php)
               │
               ▼
      [Lexer & Parser] (nikic/php-parser)
               │
               ▼
     [Abstract Syntax Tree (AST)]
               │
      [Symbol Table Indexer] <─── Static Reflection (PHPStan/Psalm Core)
               │
     [Control Flow Graph (CFG)]
               │
               ├──► Type Inference Engine (Bidirectional)
               ├──► Constraint Solver (Type Narrowing / Guard Analysis)
               └──► Purity & Immutability Checker (Psalm)
               │
               ▼
     [Diagnostic Reporter] ──► (PHPStan L9 / Psalm L1 Violation List)
```

#### Perbedaan Filosofis Level Max: PHPStan Level 9 vs Psalm Level 1

*   **PHPStan Level 9**:
    *   Skala PHPStan bergerak dari **Level 0 (paling longgar)** hingga **Level 9 (paling ketat)**.
    *   Level 0–4 fokus pada sintaks dasar, variabel tak terdefinisi, metode yang tidak ada, dan jumlah argumen.
    *   Level 5–8 fokus pada validasi tipe argumen, *return type*, *strict nullability*, hingga pemeriksaan eksplisit pada akses array/properti.
    *   **Level 9 fokus pada `mixed`**: Tipe `mixed` dianggap sebagai entri ilegal jika tidak divalidasi secara eksplisit. Anda tidak dapat melewatkan tipe `mixed` ke dalam fungsi yang meminta tipe konkret tanpa melakukan *runtime assertion* atau *type narrowing*.

*   **Psalm Level 1**:
    *   Skala Psalm bergerak terbalik dari **Level 8 (paling longgar)** hingga **Level 1 (paling ketat)**.
    *   Psalm dirancang dengan model tipe berbasis aljabar yang lebih ekspresif (mendukung *dependent types*, *literal types*, *taint analysis* untuk keamanan siber, dan *purity tracking*).
    *   **Level 1 melarang segala bentuk inferensi bertipe implicit-any**: Tidak ada `MissingReturnType`, tidak ada `MixedAssignment`, tidak ada `MixedArgument`. Psalm Level 1 menuntut sistem tipe deterministik penuh: setiap *closure*, koleksi (*generics*), percabangan, dan properti harus memiliki tipe terverifikasi matematis.

### 2. Implementasi & Contoh Kasus Nyata

Konfigurasi berikut menempatkan mesin analisa pada status *pedantic/level max*.

#### 1. Konfigurasi `phpstan.neon`
```neon
parameters:
    level: 9
    paths:
        - src
    checkExplicitMixed: true
    checkGenericClassInNonGenericObjectType: true
    checkMissingIterableValueType: true
    treatPhpDocTypesAsCertain: false
```

#### 2. Konfigurasi `psalm.xml`
```xml
<?xml version="1.0"?>
<psalm
    errorLevel="1"
    resolveFromConfigFile="true"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xmlns="https://getpsalm.org/schema/config"
    xsi:schemaLocation="https://getpsalm.org/schema/config config.xsd"

    findUnusedCode="true"

    <projectFiles>
        <directory name="src" />
        <ignoreFiles>
            <directory name="vendor" />
        </ignoreFiles>
    </projectFiles>
</psalm>
```

#### 3. Kode Produksi: Implementasi Repository Generik Type-Safe

Kode berikut mendemonstrasikan pola penulisan yang lolos verifikasi **PHPStan Level 9** dan **Psalm Level 1** tanpa mengorbankan keamanan kompilasi (*compile-time safety*).

```php
<?php

declare(strict_types=1);

namespace App\Infrastructure;

use InvalidArgumentException;
use RuntimeException;

/**
 * Interface dasar untuk identitas entitas.
 */
interface EntityInterface
{
    public function getId(): string;
}

final readonly class User implements EntityInterface
{
    public function __construct(
        private string $id,
        private string $email
    ) {}

    public function getId(): string
    {
        return $this->id;
    }

    public function getEmail(): string
    {
        return $this->email;
    }
}

/**
 * Generic Type Safe Collection / Repository Container.
 *
 * @template T of EntityInterface
 * @psalm-immutable
 */
final readonly class EntityCollection
{
    /**
     * @param array<string, T> $items
     */
    private function __construct(
        private array $items
    ) {}

    /**
     * Named constructor yang menjamin type safety dari array mentah.
     *
     * @template TEntity of EntityInterface
     * @param class-string<TEntity> $classType
     * @param list<mixed> $rawPayloads
     * @return self<TEntity>
     * 
     * @throws InvalidArgumentException
     */
    public static function fromRawPayloads(string $classType, array $rawPayloads): self
    {
        /** @var array<string, TEntity> $typedMap */
        $typedMap = [];

        foreach ($rawPayloads as $index => $payload) {
            // Evaluasi tipe mixed: PHPStan L9 / Psalm L1 melarang interaksi langsung tanpa narrowing
            if (!is_array($payload)) {
                throw new InvalidArgumentException("Payload pada indeks {$index} bukan array.");
            }

            $id = $payload['id'] ?? null;
            if (!is_string($id) || $id === '') {
                throw new InvalidArgumentException("Payload memerlukan key 'id' bertipe non-empty-string.");
            }

            if ($classType === User::class) {
                $email = $payload['email'] ?? null;
                if (!is_string($email) || !filter_var($email, FILTER_VALIDATE_EMAIL)) {
                    throw new InvalidArgumentException("Field 'email' invalid pada ID: {$id}");
                }

                // Instansiasi tipe secara spesifik
                /** @var TEntity */
                $entity = new User($id, $email);
                $typedMap[$id] = $entity;
                continue;
            }

            throw new RuntimeException("Instansiasi untuk tipe {$classType} belum terdaftar.");
        }

        return new self($typedMap);
    }

    /**
     * Menemukan entity berdasarkan ID dengan conditional non-null return.
     *
     * @param non-empty-string $id
     * @return T
     * @throws RuntimeException
     */
    public function getOrFail(string $id): EntityInterface
    {
        // Pengecekan eksplisit mencegah return null terselubung
        if (!array_key_exists($id, $this->items)) {
            throw new RuntimeException("Entitas dengan ID {$id} tidak ditemukan.");
        }

        return $this->items[$id];
    }

    /**
     * Mengambil seluruh entity dalam bentuk array terindeks.
     *
     * @return list<T>
     */
    public function toList(): array
    {
        return array_values($this->items);
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Static Reflection vs Runtime Reflection
PHP tradisional menggunakan `ReflectionClass` bawaan Zend Engine yang memuat (*loading*) file ke dalam alokasi memori runtime PHP (mengikutsertakan eksekusi kode level global dan memicu side-effects). 

PHPStan dan Psalm modern mengimplementasikan **Static Reflection**:
1. Berkas PHP dibaca murni sebagai berkas teks lalu diurai oleh AST Parser (`nikic/php-parser`).
2. Parser menghasilkan *nodes* data struktur memori tanpa memicu eksekusi kode internal, deklarasi fungsi global, atau ketergantungan ekstensi native C.
3. Keduanya membangun **Symbol Table**: indeks peta relasi kelas, interface, fungsi, serta signature docblock.

#### Type Narrowing & Control Flow Graph (CFG)
Ketika kakas membaca baris bersyarat:
```php
if (!is_string($id) || $id === '') { ... }
```
Mesin analisa membangun *Control Flow Graph* (CFG). Di dalam cabang `if`, tipe dari `$id` adalah `mixed \ non-string | ""`. Namun, setelah statement `throw`, jalur eksekusi tersebut terputus (*terminating statement*). Mesin secara otomatis menyimpulkan (narrowing) tipe `$id` pada sisa blok kode berikutnya sebagai `non-empty-string`.

#### Alokasi Memori & CPU Resource
- Parsing puluhan ribu file ke dalam AST mengonsumsi memori besar (rentan *OOM / Out of Memory*).
- Kakas static analysis menggunakan arsitektur **Parallel Worker Threads/Processes**. Proses master membagi berkas menjadi batch-batch kecil via IPC (*Inter-Process Communication*), sementara worker menganalisis AST dalam isolasi memori lokal dan mengembalikan hanya ringkasan diagnostik (*errors*).
- Menggunakan skema *invalidation cache* (seperti SHA1 hash file) sehingga hanya file yang termodifikasi yang akan di-parse ulang pada eksekusi berikutnya.

#### Trade-offs
| Keuntungan | Konsekuensi / Trade-off |
| :--- | :--- |
| Mencegah 99% bug `TypeError` di production | *Initial boilerplate* tinggi: Penulisan DocBlock generics (`@template`) memakan waktu |
| Refactoring besar dapat dilakukan tanpa rasa cemas | Waktu build CI/CD bertambah untuk menganalisis puluhan ribu node |
| Dokumentasi kode hidup (*self-documenting types*) | Kurva belajar tim: pemahaman mendalam tentang aljabar tipe mutlak diperlukan |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Tipe Array Spesifik**: Ganti tipe generik PHP `array` dengan format Psalm/PHPStan yang detail: `list<string>`, `array<string, int>`, atau array shapes `array{id: string, retries: int}`.
- **Terapkan `@psalm-immutable` dan `readonly`**: Kurangi *state mutation bugs* dengan memaksa pembuatan objek baru daripada memanipulasi properti yang ada.
- **Manfaatkan *Type Assertions***: Jika harus berhadapan dengan data dynamic (misal: JSON payload dari API luar), buatlah *guard functions* terpisah dengan anotasi:
  ```php
  /**
   * @psalm-assert-if-true non-empty-string $value
   */
  function isNonEmptyString(mixed $value): bool {
      return is_string($value) && trim($value) !== '';
  }
  ```

#### Don'ts
- **Menggunakan `@phpstan-ignore-line` atau `/** @var any */` Tanpa Alasan Jelas**: Hal ini merusak validitas jaminan matematis static analyzer. Gunakan file `baseline` jika Anda mengadopsi static analysis pada sistem *legacy*.
- **Asumsi Keberadaan Array Key Tanpa Isset / Array-Key-Exists**:
  ```php
  // BURUK (Gagal di Level Max):
  function getAge(array $data): int { return $data['age']; } // MixedArrayAccess!

  // BENAR:
  /** @param array{age: int} $data */
  function getAge(array $data): int { return $data['age']; }
  ```
- **Menggunakan Dynamic Properties**: Memasukkan properti kelas di runtime tanpa dideklarasikan eksplisit di class body akan langsung ditolak pada Psalm L1/PHPStan L9.

#### Edge Cases: Truthy vs Nullish & Strict Comparison
Hati-hati terhadap evaluasi tipe implisit:
```php
// Berbahaya: String "0" dievaluasi sebagai false!
if (!$payload['string_number']) { ... }

// Level Max mewajibkan pengecekan strict:
if (!isset($payload['string_number']) || $payload['string_number'] === '') { ... }
```
Static analysis level tinggi akan menandai dead-code jika Anda memeriksa kondisi yang tidak mungkin terjadi berdasarkan tipe yang sudah disimpulkan sebelumnya (*Impossible condition check*).

### 5. Tantangan Eksplorasi Mandiri

1. **Refactoring Dynamic Array-Shape**:
   Ambil fungsi *legacy* yang memproses associative array tanpa deklarasi tipe (misalnya `$data = json_decode($json, true);`). Konfigurasikan Psalm Level 1 dan perbaiki kode tersebut menggunakan validasi defensif dan *Array Shapes* (`array{name: string, status: 'ACTIVE'|'INACTIVE'}`) sampai nol *diagnostic error*.
2. **Penerapan Custom Static Analysis Rule**:
   Rancang satu *custom rule* sederhana menggunakan API internal PHPStan (`PHPStan\Rules\Rule`) yang mendeteksi dan melarang pemanggilan fungsi `rand()` atau `mt_rand()`, dan memaksa developer menggunakan fungsi kriptografis aman `random_int()`.
