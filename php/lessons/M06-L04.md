## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam pengembangan aplikasi web, prinsip utama keamanan adalah **"Never Trust User Input"**. Data yang masuk dari luar (HTTP POST/GET, headers, CLI arguments) pada dasarnya adalah *untrusted data*. PHP menyediakan mekanisme bawaan melalui ekstensi `ext/filter` untuk menangani hal ini secara efisien di level C, daripada mengandalkan *Regular Expression* (Regex) di level *userland* PHP yang rawan kesalahan dan lambat.

Terdapat dua konsep fundamental yang sering disalahartikan:
1. **Validation (Validasi)**: Memeriksa apakah data memenuhi kriteria tertentu (misal: apakah ini format email yang valid? apakah ini angka integer?). Validasi **tidak mengubah** data asli. Ia hanya mengembalikan data tersebut jika valid, atau `false` jika tidak.
2. **Sanitization (Sanitasi)**: Membersihkan atau memodifikasi data dengan menghapus karakter yang tidak diinginkan atau berbahaya (misal: menghapus tag HTML, membuang karakter non-numerik). Sanitasi **mengubah** bentuk data.

**Arsitektur `ext/filter`**:
Ekstensi ini diimplementasikan langsung di dalam *core* PHP menggunakan bahasa C. Ketika Anda memanggil `filter_var()`, PHP tidak mengeksekusi script regex yang panjang, melainkan menjalankan *state machine* atau *parser* C yang sangat dioptimalkan (misalnya, validasi email menggunakan parser yang mematuhi RFC 822/5322).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern (PHP 8+) untuk memproses payload dari form registrasi. Perhatikan bahwa sejak PHP 8.1, `FILTER_SANITIZE_STRING` telah di-*deprecated*, sehingga kita menggunakan `htmlspecialchars()` untuk sanitasi string berbasis HTML.

```php
<?php
declare(strict_types=1);

class InputProcessor {
    /**
     * Memproses dan memvalidasi payload input massal.
     */
    public static function processRegistration(array $rawData): array|false {
        // Definisi aturan filter untuk filter_var_array
        $filters = [
            'email' => [
                'filter' => FILTER_VALIDATE_EMAIL,
            ],
            'age' => [
                'filter' => FILTER_VALIDATE_INT,
                'options' => [
                    'min_range' => 18,
                    'max_range' => 120
                ]
            ],
            'website' => [
                'filter' => FILTER_VALIDATE_URL,
                'flags'  => FILTER_FLAG_PATH_REQUIRED // URL harus memiliki path, misal: domain.com/profile
            ],
            // Untuk string, kita ambil raw-nya dulu, lalu sanitasi manual (PHP 8.1+ Best Practice)
            'bio' => [
                'filter' => FILTER_UNSAFE_RAW
            ]
        ];

        // Eksekusi filter di level C (sangat cepat)
        $processedData = filter_var_array($rawData, $filters);

        // Jika ada key yang tidak ada di $rawData, filter_var_array mengembalikan null untuk key tersebut.
        // Jika validasi gagal, ia mengembalikan false.
        
        if ($processedData['email'] === false) {
            throw new InvalidArgumentException("Format email tidak valid.");
        }
        if ($processedData['age'] === false) {
            throw new InvalidArgumentException("Umur harus berupa angka antara 18 - 120.");
        }

        // Sanitasi manual untuk string (Mencegah XSS saat di-render ke HTML)
        if ($processedData['bio'] !== null) {
            $processedData['bio'] = htmlspecialchars(
                $processedData['bio'], 
                ENT_QUOTES | ENT_SUBSTITUTE, 
                'UTF-8'
            );
        }

        return $processedData;
    }
}

// --- Contoh Penggunaan ---
$payload = [
    'email'   => 'user@example.com',
    'age'     => '25', // String numerik akan di-cast dan divalidasi sebagai int
    'website' => 'https://example.com/portfolio',
    'bio'     => '<script>alert("XSS")</script> Halo, saya developer!'
];

try {
    $cleanData = InputProcessor::processRegistration($payload);
    var_dump($cleanData);
    /* Output:
       'email' => string(16) "user@example.com"
       'age' => int(25)
       'website' => string(29) "https://example.com/portfolio"
       'bio' => string(64) "&lt;script&gt;alert(&quot;XSS&quot;)&lt;/script&gt; Halo, saya developer!"
    */
} catch (Exception $e) {
    echo "Error: " . $e->getMessage();
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: 
  Fungsi seperti `filter_var()` beroperasi dengan membaca struktur internal `zval` (Zend Value) dari variabel PHP. Untuk validasi seperti `FILTER_VALIDATE_INT`, C-engine PHP akan mencoba melakukan *type-casting* internal dan memeriksa batas memori (berdasarkan arsitektur 64-bit atau 32-bit sistem) tanpa memicu *fatal error* di *userland*.
- **Alokasi Memori / Resource**: 
  - **Validasi**: Sangat efisien secara memori. Jika data valid, PHP seringkali hanya mengembalikan referensi ke `zval` asli atau membuat `zval` skalar baru (seperti `int` atau `bool`).
  - **Sanitasi**: Memerlukan alokasi memori baru. Karena string di PHP bersifat *immutable* (tidak bisa diubah di tempat yang sama), sanitasi akan memicu mekanisme *Copy-on-Write* (CoW). Engine akan mengalokasikan blok memori baru untuk string yang sudah dibersihkan, yang berarti penggunaan memori akan meningkat sementara (spike) jika Anda mensanitasi payload berukuran besar (misal: artikel blog berukuran MB).
- **Trade-offs**: 
  Menggunakan `filter_var` jauh lebih cepat daripada `preg_match` untuk standar umum (email, IP, URL). Namun, `filter_var` sangat kaku. Jika Anda memiliki aturan bisnis spesifik (misal: "Email harus berakhiran `@perusahaan.com`"), Anda tetap harus mengkombinasikannya dengan Regex atau fungsi string standar.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan `filter_input_array(INPUT_POST, $args)` untuk memproses seluruh form secara massal daripada memanggil `$_POST['key']` satu per satu. Ini mencegah *Undefined array key warning*.
  - Selalu gunakan `htmlspecialchars()` dengan flag `ENT_QUOTES` saat akan menampilkan input user ke browser (Output Encoding).
  - Gunakan flag `FILTER_NULL_ON_FAILURE` jika Anda ingin membedakan antara "input kosong/tidak ada" (`null`) dan "input ada tapi tidak valid" (`false`).
- **Don'ts**:
  - **JANGAN** gunakan `FILTER_SANITIZE_STRING`. Fitur ini sudah *deprecated* di PHP 8.1 dan dihapus di PHP 9.0.
  - Jangan mengandalkan sanitasi untuk keamanan *Database*. Sanitasi input tidak mencegah SQL Injection. Gunakan *Prepared Statements* (PDO/MySQLi) untuk interaksi database.
  - Jangan memvalidasi alamat IP menggunakan Regex. Selalu gunakan `filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_IPV4 | FILTER_FLAG_IPV6)`.
- **Edge Cases**:
  - **Email RFC 822**: `filter_var('test@localhost', FILTER_VALIDATE_EMAIL)` mungkin mengembalikan `true` di beberapa versi karena secara teknis valid menurut RFC lama. Jika Anda butuh domain dengan TLD (seperti `.com`), Anda harus menambahkan validasi ekstra (misal mengecek keberadaan titik `.` pada domain).

### 5. Tantangan Eksplorasi Mandiri

1. **Buat Middleware Validasi**: Rancang sebuah class `RequestValidator` yang menerima array multidimensi (seperti payload JSON dari API) dan menggunakan kombinasi `filter_var_array` dan *callback* (`FILTER_CALLBACK`) untuk memvalidasi struktur bersarang (nested array).
2. **Benchmark Performance**: Tulis script menggunakan `microtime(true)` untuk membandingkan waktu eksekusi antara memvalidasi 100.000 alamat email menggunakan `filter_var($email, FILTER_VALIDATE_EMAIL)` dibandingkan dengan menggunakan `preg_match()` dengan regex email standar. Amati perbedaan penggunaan CPU dan memorinya.
3. **Eksplorasi Filter IP**: Buat fungsi yang mendeteksi apakah IP pengunjung adalah IP Publik atau IP Lokal/Private (seperti `192.168.x.x` atau `127.0.0.1`). Gunakan `filter_var` dengan kombinasi flag `FILTER_FLAG_NO_PRIV_RANGE` dan `FILTER_FLAG_NO_RES_RANGE`.
