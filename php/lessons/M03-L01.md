## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum PHP 8.0, ekosistem PHP sangat bergantung pada **Docblock Annotations** (`/** @Route("/api/users") */`) untuk menyematkan metadata ke dalam kode. Pendekatan warisan ini memiliki kelemahan mendasar:
1. **Unstructured String Data**: Anotasi hanyalah komentar teks biasa. Engine PHP memperlakukannya sebagai *token stream* komentar (`T_DOC_COMMENT`).
2. **Runtime Overhead**: Framework memerlukan parser pihak ketiga (misalnya `doctrine/annotations`) yang membaca teks docblock via Reflection, lalu melakukan *lexing/parsing* menggunakan regex atau AST parser berbasis *userland* pada saat runtime.
3. **Fragil terhadap Konfigurasi OpCache**: Jika directive `opcache.save_comments=0` diaktifkan untuk menghemat memori, seluruh metadata docblock akan dibuang dari bytecode cache, menyebabkan aplikasi berbasis anotasi *crash*.
4. **Ketiadaan Validasi Kompilasi**: Typo pada nama kelas atau argumen dalam docblock tidak terdeteksi oleh engine hingga parser *userland* memprosesnya.

```
+-------------------------------------------------------------+
| Era PHP < 8.0 (Docblock Annotation)                         |
| Source Code -> Lexer -> Docblock Comment -> Userland Parser |
| (doctrine/annotations regex) -> Object Metadata             |
+-------------------------------------------------------------+
                              vs
+-------------------------------------------------------------+
| Era PHP >= 8.0 (Native Attributes)                          |
| Source Code -> Zend Lexer -> AST -> Opcodes/Bytecode Cache  |
|                                     |                       |
|                                     v                       |
|                            Zend Engine Internal             |
|                         (Native Metadata Struct)            |
+-------------------------------------------------------------+
```

**Attributes (Metadata Kelas Satu)** menyelesaikan masalah ini dengan menjadikan metadata sebagai bagian dari sintaksis inti bahasa PHP. 
- Dideklarasikan dengan sintaks `#[AttributeName(arg: $val)]`.
- Dikompilasi langsung ke dalam **Abstract Syntax Tree (AST)** oleh Zend Compiler.
- Mendukung *static type-checking*, resolusi *namespace*, autocompletion IDE, dan verifikasi parameter secara *native*.
- Bersifat **Lazy Loaded**: Engine tidak menginstansiasi objek atribut ke memori saat file di-load, melainkan hanya saat dipanggil secara eksplisit melalui **Reflection API**.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengimplementasikan sistem HTTP Routing deklaratif menggunakan atribut kustom dengan batasan target (*target flags*) dan validasi tipe bawaan PHP.

```php
<?php

declare(strict_types=1);

namespace App\Core\Attributes;

use Attribute;

// 1. Definisikan Atribut dengan batasan target dan flags
#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
class Route
{
    public function __construct(
        public readonly string $path,
        public readonly string $method = 'GET'
    ) {
    }
}

#[Attribute(Attribute::TARGET_METHOD | Attribute::IS_REPEATABLE)]
class Middleware
{
    public function __construct(
        public readonly string $middlewareClass
    ) {
    }
}
```

```php
<?php

declare(strict_types=1);

namespace App\Http\Controllers;

use App\Core\Attributes\Route;
use App\Core\Attributes\Middleware;

class UserController
{
    #[Route(path: '/api/v1/users', method: 'GET')]
    #[Middleware('App\Http\Middleware\Authenticate')]
    #[Middleware('App\Http\Middleware\RateLimit')]
    public function listUsers(): array
    {
        return [
            ['id' => 1, 'name' => 'Alice'],
            ['id' => 2, 'name' => 'Bob'],
        ];
    }
}
```

```php
<?php

declare(strict_types=1);

namespace App\Core\Router;

use App\Core\Attributes\Route;
use App\Core\Attributes\Middleware;
use ReflectionClass;
use ReflectionMethod;

class AttributeRouter
{
    /**
     * Memindai controller dan mengekstraksi metadata routing secara instan.
     */
    public function registerRoutes(string $controllerClass): array
    {
        $routes = [];
        $reflectionClass = new ReflectionClass($controllerClass);

        foreach ($reflectionClass->getMethods(ReflectionMethod::IS_PUBLIC) as $method) {
            // Ambil atribut Route dari method
            $routeAttributes = $method->getAttributes(Route::class);

            if (empty($routeAttributes)) {
                continue;
            }

            // Ambil instance pertama dari #[Route]
            /** @var Route $routeInstance */
            $routeInstance = $routeAttributes[0]->newInstance();

            // Ambil atribut Middleware yang repeatable
            $middlewareAttributes = $method->getAttributes(Middleware::class);
            $middlewares = [];

            foreach ($middlewareAttributes as $middlewareAttr) {
                /** @var Middleware $middlewareInstance */
                $middlewareInstance = $middlewareAttr->newInstance();
                $middlewares[] = $middlewareInstance->middlewareClass;
            }

            $routes[] = [
                'path' => $routeInstance->path,
                'http_method' => $routeInstance->method,
                'action' => [$controllerClass, $method->getName()],
                'middlewares' => $middlewares,
            ];
        }

        return $routes;
    }
}

// Eksekusi Runtime
$router = new AttributeRouter();
$compiledRoutes = $router->registerRoutes(App\Http\Controllers\UserController::class);

print_r($compiledRoutes);
```

#### Penjelasan Komponen Kunci:
1. `#[Attribute(...)]`: Menandai class sebagai atribut valid. Argumen konstanta bitwise seperti `Attribute::TARGET_METHOD` mengunci agar atribut tidak bisa dipasang sembarangan (misal di properti).
2. `Attribute::IS_REPEATABLE`: Mengizinkan atribut dideklarasikan lebih dari satu kali pada target yang sama (contoh: rantai `$middlewares`).
3. `ReflectionAttribute::newInstance()`: Titik pemisah antara metadata statis dan eksekusi dinamis. Konstruktor atribut baru dieksekusi di sini.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
1. **Compilation Phase**:
   - Ketika PHP Compiler membaca file, lexer mengenali token `#[` sebagai `T_ATTRIBUTE`.
   - Nama class atribut di-*resolve* terhadap *use-statements* (*Fully Qualified Class Name* / FQCN) pada tahap kompilasi.
   - Argumen atribut disimpan sebagai array ekspresi konstanta (*constant expressions*) di dalam struktur data internal `zend_attribute`.
2. **OpCache Storage**:
   - Struktur `zend_attribute` disimpan langsung ke dalam *shared memory* oleh OpCache bersama dengan `zend_class_entry` atau `zend_function`.
   - Parameter `opcache.save_comments=0` **tidak memengaruhi** Atribut, karena atribut adalah bagian dari representasi biner opcode, bukan komentar teks.
3. **Lazy Instantiation**:
   - Pemanggilan `$reflectionMethod->getAttributes()` **hanya** mengembalikan array dari objek internal `ReflectionAttribute`. Objek kelas atribut *belum* diinstansiasi di sini.
   - Objek baru dibuat ketika method `ReflectionAttribute::newInstance()` dieksekusi. Ini meminimalisasi alokasi memori yang sia-sia jika framework hanya ingin memeriksa keberadaan (*presence*) suatu atribut tanpa membaca datanya.

#### Alokasi Memori / Resource
- **Docblock Parsing (Legacy)**: Membutuhkan pembacaan string docblock dari memori, tokenisasi userland, dan alokasi array besar untuk metadata tree. Bisa mengonsumsi puluhan megabyte pada framework besar.
- **Native Attributes**: Menghemat footprint memori secara masif. Metadata disimpan dalam representasi internal C struct `zend_attribute` yang terkompresi.

#### Trade-offs
- Nilai argumen pada Atribut **harus berupa konstanta deterministik saat kompilasi** (literal nilai, konstanta kelas, operator ternary dasar, ekspresi scalar, atau array konstan). Anda tidak dapat memasukkan panggilan fungsi dinamis atau closure seperti: `#[Route(path: getenv('APP_URL'))]`.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Target Flags secara Spesifik**: Selalu batasi target atribut menggunakan kombinasi `Attribute::TARGET_CLASS`, `Attribute::TARGET_PROPERTY`, `Attribute::TARGET_METHOD`, dll., untuk mencegah kesalahan semantik kode.
- **Gunakan Readonly Properties**: Gunakan `public readonly` pada konstruktor atribut (seperti standar PHP 8.1+) agar metadata bersifat *immutable* setelah di-instansiasi.
- **Cache Hasil Parsing Reflection**: Meskipun native atribut sangat cepat, melakukan iterasi Reflection terhadap ratusan class di setiap daur hidup HTTP request tetap menimbulkan overhead CPU. Lakukan scanning sekali pada fase *build/cache generation* framework.

#### Don'ts
- **Jangan Masukkan Business Logic**: Kelas atribut murni berfungsi sebagai kontainer DTO (Data Transfer Object) untuk metadata. Jangan letakkan koneksi database, logic HTTP, atau dependency injection container di dalam kelas atribut.
- **Hindari Komputasi Berat di Konstruktor Atribut**: Karena `newInstance()` dapat dipanggil beberapa kali oleh berbagai layer tooling (misal: router resolver, OpenAPI documentation generator, profiler).

#### Edge Cases
- **Pengecekan Kelas Non-Existent**: `ReflectionAttribute::getName()` akan mengembalikan nama kelas dalam bentuk string FQCN meskipun kelas atribut tersebut belum didefinisikan atau di-autoload. Namun, pemanggilan `newInstance()` pada atribut yang kelasnya tidak ditemukan akan melempar fatal error `Error: Class "..." not found`.
- **Ekspresi Ilegal**: Mencoba mengoper objek ke dalam argumen atribut (misal: `#[Inject(new Logger())]`) baru diizinkan secara terbatas mulai PHP 8.1 (menggunakan fitur `new in initializers`), namun tetap dibatasi pada objek tanpa state dinamis eksternal.

### 5. Tantangan Eksplorasi Mandiri

1. **Membuat Validation Engine**:
   Buatlah dua buah atribut: `#[AssertLength(min: 3, max: 10)]` dan `#[AssertEmail]`. Buat sebuah class `Validator` yang menerima sembarang objek, memindai properti menggunakan Reflection, membaca atribut validasi tersebut, dan mengembalikan array berisi daftar error jika nilai properti tidak valid.
2. **Deep-dive Target Inheritance**:
   Coba buat sebuah kelas Parent dengan sebuah atribut pada method-nya, lalu buat Child class yang meng-*override* method tersebut tanpa mendeklarasikan ulang atributnya. Gunakan `ReflectionMethod` pada Child class untuk melihat apakah atribut tersebut diwariskan secara otomatis atau tidak. Analisis mengapa Zend Engine memilih perilaku tersebut!
