### 1. Konsep & Arsitektur Mendalam

OpenAPI Specification (OAS)—sebelumnya dikenal sebagai Swagger—adalah format deskripsi standar industri yang *vendor-neutral* dan berbasis mesin (JSON/YAML) untuk RESTful API. OpenAPI berfungsi sebagai **kontrak formal** antara penyedia layanan (backend) dan konsumen API (frontend, third-party, microservices lain).

Dalam ekosistem PHP modern (PHP 8.0+), terdapat dua paradigma utama dalam mengelola dokumentasi OpenAPI:
1. **Design-First (Contract-First):** OpenAPI YAML/JSON ditulis terlebih dahulu menggunakan API designer, kemudian generator kode (*scaffolding*) menghasilkan *skeleton* controller dan DTO di PHP.
2. **Code-First:** Kode PHP ditulis sebagai sumber kebenaran (*single source of truth*), di mana metadata OpenAPI disematkan langsung pada kode menggunakan **PHP Native Attributes** (`#[Attribute]`). Generator statis kemudian mengekstraksi metadata ini menjadi dokumen OpenAPI.

```
+-------------------------------------------------------------+
|                      PHP Code-First Flow                    |
+-------------------------------------------------------------+
|  Controller & DTO (PHP 8 Attributes: #[OA\Get], #[OA\Schema]|
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
|   Static Analysis Engine (e.g., zircote/swagger-php)        |
|   - Tokenizer & AST Parser                                  |
|   - PHP Reflection API (ReflectionClass::getAttributes())   |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
|           In-Memory OpenAPI Abstract Data Tree              |
|           - Validation, Inheritance, $ref Resolution       |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
|               openapi.json / openapi.yaml                   |
+-------------------------------------------------------------+
         |                                           |
         v                                           v
+------------------+                       +------------------+
| Swagger UI/Redoc |                       | Prism Mock/Tests |
+------------------+                       +------------------+
```

#### Evolusi: Dari DocBlock (Doctrine Annotations) ke PHP 8 Native Attributes
Sebelum PHP 8, dokumentasi *code-first* mengandalkan *DocBlocks* komentar teks (`/** @OA\Get(...) */`) yang diparsing menggunakan *string manipulation* atau parser *token* (Doctrine Annotations). Pendekatan ini lambat, rawan kesalahan penulisan (*silent typos*), dan tidak diverifikasi oleh PHP linter.

Dengan **PHP 8 Native Attributes**, metadata OpenAPI kini berstatus sebagai *first-class language citizen*. Engine PHP mengompilasinya langsung ke dalam *Opcode*, memungkinkan akses instan melalui Reflection API tanpa parsing teks manual, serta mendukung penulisan tipe data yang lebih ketat (*strict typing*).

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengimplementasikan OpenAPI 3.1 menggunakan pustaka standar industri `zircote/swagger-php` (v4.x) dengan pendekatan PHP 8 Attributes.

#### Instalasi Dependensi
```bash
composer require zircote/swagger-php
```

#### Definisi Server & Informasi API (`src/OpenApiSpec.php`)
```php
<?php

declare(strict_types=1);

namespace App\Documentation;

use OpenApi\Attributes as OA;

#[OA\Info(
    version: "1.0.0",
    title: "Order Management Core API",
    description: "API sistem pemrosesan transaksi dan inventaris berskala enterprise."
)]
#[OA\Server(
    url: "https://api.internal.corp/v1",
    description: "Production Server"
)]
#[OA\Server(
    url: "http://localhost:8080/v1",
    description: "Local Sandbox"
)]
final class OpenApiSpec {}
```

#### Definisi Data Transfer Object (DTO) & Schema (`src/DTO/CreateOrderRequest.php`)
```php
<?php

declare(strict_types=1);

namespace App\DTO;

use OpenApi\Attributes as OA;

#[OA\Schema(
    schema: "CreateOrderRequest",
    description: "Payload untuk registrasi pesanan baru",
    required: ["customerId", "items", "paymentMethod"]
)]
final readonly class CreateOrderRequest
{
    /**
     * @param array<int, array{productId: string, quantity: int}> $items
     */
    public function __construct(
        #[OA\Property(description: "UUID v4 Customer", example: "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d")]
        public string $customerId,

        #[OA\Property(
            description: "Daftar item produk",
            type: "array",
            items: new OA\Items(
                properties: [
                    new OA\Property(property: "productId", type: "string", format: "uuid"),
                    new OA\Property(property: "quantity", type: "integer", minimum: 1, example: 2)
                ]
            )
        )]
        public array $items,

        #[OA\Property(
            description: "Metode pembayaran",
            type: "string",
            enum: ["CREDIT_CARD", "BANK_TRANSFER", "E_WALLET"],
            example: "BANK_TRANSFER"
        )]
        public string $paymentMethod
    ) {}
}
```

#### Definisi Controller Endpoint (`src/Controller/OrderController.php`)
```php
<?php

declare(strict_types=1);

namespace App\Controller;

use App\DTO\CreateOrderRequest;
use OpenApi\Attributes as OA;

final class OrderController
{
    #[OA\Post(
        path: "/orders",
        operationId: "createOrder",
        description: "Membuat pesanan baru dan mereservasi stok inventaris secara atomik.",
        summary: "Buat Order Baru",
        tags: ["Orders"]
    )]
    #[OA\RequestBody(
        required: true,
        content: new OA\JsonContent(ref: "#/components/schemas/CreateOrderRequest")
    )]
    #[OA\Response(
        response: 201,
        description: "Order berhasil dibuat",
        content: new OA\JsonContent(
            properties: [
                new OA\Property(property: "orderId", type: "string", format: "uuid", example: "d3b07384-d113-494a-a9e8-466f87422f8d"),
                new OA\Property(property: "status", type: "string", example: "PENDING_PAYMENT"),
                new OA\Property(property: "totalAmount", type: "number", format: "float", example: 450000.00),
                new OA\Property(property: "createdAt", type: "string", format: "date-time")
            ]
        )
    )]
    #[OA\Response(
        response: 422,
        description: "Unprocessable Entity - Validasi gagal",
        content: new OA\JsonContent(
            properties: [
                new OA\Property(property: "error", type: "string", example: "Validation Error"),
                new OA\Property(
                    property: "details",
                    type: "array",
                    items: new OA\Items(type: "string", example: "Field 'items' must not be empty.")
                )
            ]
        )
    )]
    public function store(CreateOrderRequest $request): void
    {
        // Logika bisnis pembuatan order...
    }
}
```

#### Script Generator Command-Line / Pipeline (`bin/generate-docs.php`)
```php
<?php

declare(strict_types=1);

require __DIR__ . '/../vendor/autoload.php';

use OpenApi\Generator;

$sourceDir = __DIR__ . '/../src';
$outputFile = __DIR__ . '/../public/openapi.json';

echo "Memulai analisis statis pada direktori: {$sourceDir}\n";

$openapi = Generator::scan([$sourceDir]);

if ($openapi === null) {
    fwrite(STDERR, "Gagal meng-generate dokumentasi OpenAPI.\n");
    exit(1);
}

// Validasi internal swagger-php terhadap struktur OAS
$openapi->validate();

file_put_contents($outputFile, $openapi->toJson(JSON_PRETTY_PRINT | JSON_UNESCAPED_SLASHES));

echo "Spesifikasi OpenAPI berhasil dibuat di: {$outputFile}\n";
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Parsing Engine
Pustaka seperti `swagger-php` tidak mengeksekusi (*run*) controller API Anda saat proses generasi dokumentasi. Engine ini bekerja sebagai **static analyzer**:
1. **Directory Traversal & Tokenizer:** Engine memindai seluruh file `.php` menggunakan `nikic/php-parser` atau token internal PHP (`token_get_all`). Mesin mencari deklarasi `namespace`, `class`, dan method tanpa memuat dependensi logis ke memori aplikasi.
2. **Reflection Resolution:** Saat deklarasi kelas ditemukan, engine memanfaatkan PHP 8 Native Reflection:
   ```php
   $reflector = new ReflectionClass(OrderController::class);
   $attributes = $reflector->getMethod('store')->getAttributes(
       \OpenApi\Attributes\Operation::class,
       \ReflectionAttribute::IS_INSTANCEOF
   );
   ```
   PHP Engine membaca metadata atribut yang disimpan langsung di level tabel simbol C-Struct kernel Zend (`zend_attribute *`).
3. **Reference Mapping (`$ref`):** Semua kelas yang memiliki `#[OA\Schema]` diekstrak ke dalam tabel komponen global (`components/schemas`). Reference string seperti `#/components/schemas/CreateOrderRequest` diselesaikan (*resolved*) pada pass terakhir guna menyusun tree hierarkis OpenAPI yang utuh.

#### Alokasi Memori / Resource
- **Autoloading Overhead:** Menginstansiasi `ReflectionClass` memaksa Composer *autoloader* memuat (*require*) setiap file PHP target ke memori interpreter. Pada proyek besar dengan ribuan file, *memory peak* dapat melesat drastis (ratusan Megabyte) karena Zend VM harus mengalokasikan memori untuk *class entry*, *method tables*, dan *opcodes* dari seluruh file tersebut.
- **Garbage Collection (GC):** Engine parser membangun struktur Graph Object in-memory yang kompleks dengan relasi *two-way binding*. Jika tidak dioptimalkan, siklus referensi ini dapat membebani Zend Engine Cycle Collector.

#### Trade-offs: Code-First vs Design-First
| Parameter | Code-First (PHP Attributes) | Design-First (Manual YAML/JSON) |
| :--- | :--- | :--- |
| **Source of Truth** | Kode PHP aktual. Dokumentasi sinkron dengan tipe data. | File YAML. Kode harus disesuaikan secara disiplin. |
| **Polusi Kode** | **Tinggi.** Controller dan DTO menjadi padat dengan metadata non-eksekusi. | **Nol.** Kode aplikasi bersih murni dari atribut dokumentasi. |
| **Performa Runtime** | Bebas beban *jika* di-cache statis. Fatal *jika* discan pada setiap *request*. | Sama sekali tidak membebani PHP engine. |
| **Kolaborasi Tim** | Sulit diulas oleh analis/frontend non-PHP sebelum kode ditulis. | Mudah didesain dan di-*mock* bersama sebelum implementasi. |

### 4. Best Practices & Common Pitfalls

#### Do's:
1. **Kompilasi dan Cache pada Pipeline CI/CD:** Hasilkan file statis `openapi.json` saat *build phase* deployment. Sajikan dokumen tersebut melalui Web Server (Nginx/Caddy) sebagai aset statis, bukan via request PHP runtime.
2. **Pisahkan DTO dengan ORM/Entity:** Jangan pernah menaruh atribut `#[OA\Schema]` langsung pada Doctrine/Eloquent Entities. Hal ini berisiko membocorkan struktur tabel database, relasi internal, dan kolom sensitif (seperti `password_hash`). Selalu gunakan dedicated DTO.
3. **Validasi Skema Menggunakan Linter Eksternal:** Integrasikan linter seperti **Spectral** (`@stoplight/spectral-cli`) dalam pipeline CI/CD untuk memastikan penulisan OpenAPI mematuhi aturan konsistensi API governance perusahaan.

#### Don'ts:
1. **DILARANG Melakukan Dynamic Scan di Production Runtime:**
   ```php
   // ANTI-PATTERN: Jangan pernah melakukan ini di dalam Controller produksi!
   public function getSwaggerJson(): Response {
       $openapi = \OpenApi\Generator::scan(['/path/to/project']); // Memory spike & CPU throttling tinggi!
       return new JsonResponse($openapi->toJson());
   }
   ```
2. **Jangan Biarkan Generic Error Responses Tidak Terdokumentasi:** Kesalahan umum adalah hanya mendokumentasikan kode status `200/201`. Respon `400`, `401`, `403`, `422`, dan `500` harus terpetakan secara ketat agar konsumen API dapat menangani skenario kegagalan secara deterministik.

#### Edge Cases:
- **Polymorphic Responses (`oneOf` / `anyOf`):** Saat mengembalikan data dinamis (misalnya polymorphic payment: `CreditCardPayment` vs `BankTransferPayment`), gunakan atribut discriminator:
  ```php
  #[OA\Schema(
      schema: "PaymentDetails",
      oneOf: [
          new OA\Schema(ref: "#/components/schemas/CreditCard"),
          new OA\Schema(ref: "#/components/schemas/BankTransfer")
      ],
      discriminator: new OA\Discriminator(
          propertyName: "type",
          mapping: ["cc" => "#/components/schemas/CreditCard", "va" => "#/components/schemas/BankTransfer"]
      )
  )]
  ```
- **Circular References:** Model hierarki seperti Menu Kategori (`Category has many sub-Categories`) akan memicu infinite loop jika recursive schema tidak diproteksi dengan `$ref` yang benar. Pastikan relasi recursive menunjuk ke named schema reference, bukan inline schema.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Drift-Detection Pipeline:**
   Buat sebuah script PHP (misalnya: `bin/check-schema-drift.php`) yang dapat dijalankan pada CI pipeline. Script ini harus meng-generate OpenAPI JSON baru di memori, membandingkannya dengan `openapi.json` yang saat ini ter-*commit* di git repository, dan mengembalikan `exit(1)` jika ada perubahan yang belum di-*commit*. Tujuannya mencegah developer memodifikasi DTO tanpa meng-update file spesifikasi.
2. **Polymorphic Schema Engine:**
   Rancang sebuah endpoint `POST /webhooks` yang dapat menerima 3 jenis payload event yang berbeda (misalnya: `UserRegisteredEvent`, `InvoicePaidEvent`, dan `SubscriptionCancelledEvent`). Konfigurasikan skema OpenAPI menggunakan PHP 8 Native Attributes lengkap dengan `discriminator` property untuk membedakan struktur JSON masing-masing event secara presisi.
