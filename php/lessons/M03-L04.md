## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum PHP 8.1, representasi *callable* di PHP bersifat *stringly-typed* atau berbasis array struktural. Developer terbiasa menggunakan string untuk fungsi global (`'strlen'`) atau array berisi instans/nama kelas beserta nama metodenya (`[$this, 'handle']` atau `[OrderService::class, 'process']`). 

Mekanisme lama ini memiliki kelemahan mendasar:
1. **Lemahnya Validasi Statis (Static Analysis & Tooling)**: IDE dan static analyzer (seperti PHPStan atau Psalm) kesulitan melacak referensi callable berbasis string/array. Jika nama metode diubah saat *refactoring*, string tersebut berisiko terlewat dan memicu *runtime error*.
2. **Overhead Validasi Runtime**: PHP harus memverifikasi apakah string atau pasangan array tersebut benar-benar sebuah callable yang valid setiap kali eksekusi berlangsung menggunakan `is_callable()` internal.
3. **Verbose**: Solusi alternatif yang aman sebelumnya adalah `Closure::fromCallable([$this, 'method'])`, namun sintaks ini panjang dan mengurangi keterbacaan kode secara signifikan.

PHP 8.1 memperkenalkan **First-Class Callable Syntax** menggunakan operator ellipsis (`...`). Format ini memungkinkan developer membuat objek `Closure` anonim langsung dari fungsi, metode statis, atau metode instans yang sudah ada:

```php
$callable = strlen(...);
$method   = $service->processOrder(...);
$static   = Response::json(...);
```

Sintaks ini bukan sekadar pemanis (*syntactic sugar*) untuk array-callback. Secara semantik, sintaks ini setara dengan pemanggilan `Closure::fromCallable(...)`, tetapi dievaluasi langsung oleh *parser* dan *compiler* Zend Engine. Hal ini memungkinkan compiler melakukan resolusi scope secara instan dan memvalidasi eksistensi target fungsi/metode pada saat inisialisasi, bukan saat fungsi tersebut dieksekusi (*delayed invocation*).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah demonstrasi variasi First-Class Callable Syntax dalam arsitektur modern (PHP 8.2+), termasuk integrasinya dengan Higher-Order Functions dan Pipeline pattern.

```php
<?php

declare(strict_types=1);

namespace App\Pipelines;

final class SanitizePipeline
{
    public function __construct(
        private readonly string $encoding = 'UTF-8'
    ) {}

    public function trimSpaces(string $input): string
    {
        return trim($input);
    }

    public function normalizeEncoding(string $input): string
    {
        return mb_convert_encoding($input, $this->encoding);
    }

    public static function stripTags(string $input): string
    {
        return strip_tags($input);
    }
}

// -------------------------------------------------------------
// Penggunaan Kasus Nyata: Data Transformation Pipeline
// -------------------------------------------------------------

$pipeline = new SanitizePipeline();

// 1. First-class callable dari fungsi bawaan/global PHP
$nativeCallable = strtolower(...);

// 2. First-class callable dari instance method ($this atau instans objek)
$instanceCallable = $pipeline->trimSpaces(...);

// 3. First-class callable dari static method
$staticCallable = SanitizePipeline::stripTags(...);

// Dataset kotor dari input request
$payload = [
    '  <b>USER_ONE</b>  ',
    '  <i>ADMIN_ROOT</i>  ',
    '  <script>ALERT()</script>HELLO  '
];

/**
 * Menerapkan pipeline transformasi secara fungsional.
 * Objek Closure yang dihasilkan sepenuhnya bertipe \Closure.
 *
 * @param array<string> $data
 * @param array<\Closure(string): string> $transformers
 * @return array<string>
 */
function applyPipeline(array $data, array $transformers): array
{
    return array_map(
        static fn(string $item): string => array_reduce(
            $transformers,
            static fn(string $carry, \Closure $pipe): string => $pipe($carry),
            $item
        ),
        $data
    );
}

$cleanData = applyPipeline($payload, [
    $staticCallable,    // Menghapus HTML tag
    $instanceCallable,  // Menghapus leading/trailing whitespace
    $nativeCallable,    // Normalisasi ke lowercase
]);

print_r($cleanData);
/*
Output:
Array
(
    [0] => user_one
    [1] => admin_root
    [2] => hello
)
*/
```

#### Kompatibilitas dengan Invokable Objects
Sintaks ini juga dapat digunakan pada objek yang mengimplementasikan `__invoke()`:

```php
$action = new class {
    public function __invoke(int $id): string {
        return "Processed #{$id}";
    }
};

$callable = $action(...); // Mengembalikan Closure yang membungkus __invoke()
echo $callable(42);       // Output: Processed #42
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (Zend Engine)
Pada level *abstract syntax tree* (AST), ekspresi `foo(...)` dipetakan ke node khusus yang dikompilasi oleh Zend Engine ke dalam opcode `ZEND_CALLABLE_CONVERT`.

1. **Resolusi Fungsi**: Ketika opcode dieksekusi, Zend Engine mencari referensi fungsi di tabel fungsi global (`CG(function_table)`) atau *class entry* (`zend_class_entry`).
2. **Penciptaan Instans `zend_closure`**: Alih-alih menyimpan tuple `['class', 'method']`, Zend VM mengalokasikan struktur internal `zend_closure` di *Zend Heap*.
3. **Perekaman Scope dan Binding `$this`**: Jika menargetkan instance method (`$obj->method(...)`), Zend VM mengikat pointer `$this` milik objek target dan `scope` kelas saat ini ke dalam objek closure secara permanen.

#### Alokasi Memori & Resource
- **Lebih Rendah Overhead Pemanggilan**: Meskipun alokasi awalnya menginstansiasi objek `\Closure`, biaya eksekusi berulang (`$closure()`) jauh lebih cepat dibandingkan string callable (`'MyClass::myMethod'()`). Panggilan string callback menuntut Zend VM melakukan pencarian lookup tabel fungsi dan verifikasi hak akses (*visibility check*) di setiap panggilan, sedangkan `\Closure` telah mem-bypass pemeriksaan tersebut karena scope sudah di-*bind* di awal.
- **Siklus Hidup Objek (Memory Retention)**: Ketika instansiasi `$closure = $instance->method(...)` terjadi, referensi internal objek `$instance` di-increment (`refcount++`). Objek target tidak akan terkena *garbage collection* selama variabel `$closure` masih hidup di memori.

#### Trade-offs
- **Bukan Partial Function Application**: Di bahasa seperti Haskell, Scala, atau Python (via `functools.partial`), operator currying/partial dapat menerima sebagian argumen. Di PHP, sintaks `...` **harus digunakan secara utuh tanpa argumen lain**. Anda tidak dapat melakukan `str_replace('a', 'b', ...)`. Sintaks ini murni untuk resolusi referensi fungsi menjadi `\Closure`.
- **Eager Scope Capture**: Scope visibilitas (private/protected) dikunci saat pembuatan sintaks, bukan saat pemanggilan.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan untuk Functional Primitives**: Gunakan sintaks ini saat mengoper argumen ke `array_map`, `array_filter`, `usort`, atau komponen event dispatcher.
- **Manfaatkan Refactoring Otomatis**: Gunakan first-class callable agar IDE dapat melacak rename method tanpa merusak referensi callback.
- **Terapkan Type-Hinting yang Ketat**: Gunakan type-hint `\Closure` daripada union type `callable|string|array` ketika fungsi Anda memerlukan dependensi callable yang stabil.

#### Don'ts
- **Hindari untuk Dinamisme Tanpa Analisis**: Jangan gunakan first-class callable jika nama method target masih bersifat variabel dinamis yang rawan `null`, tanpa validasi sebelumnya.
- **Jangan Mengira Ada Partial Application**:
  ```php
  // FATAL COMPILE ERROR:
  // array_map(str_contains(..., 'needle'), $haystacks);
  
  // BENAR (gunakan arrow function jika butuh parameter binding):
  array_map(static fn($h) => str_contains($h, 'needle'), $haystacks);
  ```

#### Edge Cases
1. **Private Method Scope Binding**:
   First-class callable yang dibuat di dalam scope kelas dapat mengakses metode `private`. Closure tersebut tetap mempertahankan hak akses private tersebut bahkan jika dipassing ke luar kelas (*scope leakage* terkontrol).
   ```php
   class SecurityGate {
       private function internalToken(): string {
           return "SECRET_HASH";
       }

       public function getTokenExtractor(): \Closure {
           return $this->internalToken(...); // Valid: Scope ditangkap di sini
       }
   }

   $gate = new SecurityGate();
   $leak = $gate->getTokenExtractor();
   echo $leak(); // Berhasil mengeksekusi metode private dari luar!
   ```
2. **Kombinasi dengan Nullsafe Operator (`?->`)**:
   First-class callable syntax **tidak mendukung** nullsafe operator secara langsung jika targetnya berpotensi `null`.
   ```php
   $service = null;
   // FATAL ERROR: Cannot use ?-> with first-class callable syntax
   // $callable = $service?->process(...); 
   ```

### 5. Tantangan Eksplorasi Mandiri

1. **Inspeksi Reflection**: Buatlah sebuah instance method `private` pada sebuah class, ubah menjadi First-Class Callable menggunakan sintaks `...`, lalu gunakan `ReflectionFunction::from($callable)` untuk memeriksa properti Closure tersebut (periksa attributes, parameters, return type, dan scope class-nya).
2. **Profiling Performa**: Buat benchmark loop 100.000 iterasi yang membandingkan performa pemanggilan:
   - String callable: `call_user_func('trim', $str)`
   - Array callable: `call_user_func([$instance, 'method'], $str)`
   - First-Class Callable: `$fn = $instance->method(...); $fn($str)`  
   Perhatikan perbedaan alokasi memori awal vs kecepatan eksekusi di Zend Engine.
