## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Secara historis, model eksekusi PHP bersifat *synchronous*, *blocking*, dan *share-nothing*. Setiap *request* dijalankan dari atas ke bawah dalam satu *thread* sistem operasi (OS thread). Ketika operasi I/O terjadi (misal: *query* database, HTTP call, pembacaan disk), CPU berada dalam kondisi *idle* menunggu kernel menyelesaikan transfer data I/O tersebut.

Sebelum PHP 8.1, penanganan konkurensi asinkron di *userland* (seperti ReactPHP atau Amp v2) bertumpu pada **Generator** (`yield`) atau *Promise chains*. Pendekatan ini memicu masalah klasik arsitektur: **"What Color is Your Function?"**. Jika sebuah fungsi di tingkat bawah bersifat asinkron, seluruh rantai fungsi pemanggil di atasnya (*call stack*) harus diubah menjadi Generator atau mengembalikan *Promise*.

```
Pendekatan Generator/Promise (Call Stack Terkontaminasi):
[Async Handler] -> harus me-return Promise / yield
       ↓
  [Middleware]  -> harus me-return Promise / yield
       ↓
    [Router]    -> harus me-return Promise / yield
```

#### Hadirnya PHP 8.1 Fibers

**Fiber** (RFC: Fibers) diperkenalkan di PHP 8.1 sebagai primitif konkurensi berjenis *stackful coroutine* (atau *green thread* kooperatif). Fiber merepresentasikan blok eksekusi mandiri yang memiliki *call stack* C dan PHP sendiri, yang dapat dihentikan sementara (*suspend*) dan dilanjutkan kembali (*resume*) di titik mana pun secara arbitrer, tanpa mengotori penandaan *type signature* fungsi-fungsi di atasnya.

```
Pendekatan Fiber (Call Stack Transparan):
[Normal Handler] -> fungsi sinkron biasa
       ↓
  [Middleware]   -> fungsi sinkron biasa
       ↓
 [Fiber::suspend()] -> Eksekusi dijeda, kontrol dikembalikan ke Event Loop
```

Karakteristik arsitektur Fiber:
1. **Cooperative Multitasking**: Fiber tidak berjalan secara paralel via *preemptive scheduling* kernel. Pengalihan konteks (*context switch*) terjadi secara eksplisit ketika kode memanggil `Fiber::suspend()` atau saat di-*resume* via `$fiber->resume()`.
2. **Stackful**: Berbeda dengan Generator (yang merupakan *stackless coroutine* dan hanya menyimpan frame eksekusi lokal), Fiber mempertahankan seluruh rantai pemanggilan fungsi (*nested stack frames*) saat dihentikan.
3. **Bukan Pengganti Event Loop**: Fiber hanyalah *low-level execution control primitive*. Fiber tidak menyediakan I/O *multiplexing* (seperti `epoll`, `kqueue`, atau `io_uring`). Agar menjadi sistem asinkron fungsional, Fiber harus diorkestrasikan oleh sebuah **Scheduler** atau **Event Loop** (seperti Revolt PHP yang mendasari Amp v3).

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengimplementasikan sebuah *Miniature Asynchronous HTTP Fetcher & Task Scheduler* murni menggunakan PHP 8.1+ Fiber dan non-blocking stream sockets, tanpa dependensi pustaka eksternal.

```php
<?php

declare(strict_types=1);

final class MiniScheduler
{
    /** @var SplQueue<Fiber> */
    private SplQueue $readyQueue;

    /** @var array<int, array{fiber: Fiber, socket: resource}> */
    private array $readSockets = [];

    public function __construct()
    {
        $this->readyQueue = new SplQueue();
    }

    public function enqueue(Fiber $fiber): void
    {
        $this->readyQueue->enqueue($fiber);
    }

    public function waitForRead(mixed $socket, Fiber $fiber): void
    {
        $id = (int) $socket;
        $this->readSockets[$id] = ['fiber' => $fiber, 'socket' => $socket];
    }

    public function run(): void
    {
        while (!$this->readyQueue->isEmpty() || !empty($this->readSockets)) {
            // 1. Eksekusi semua Fiber yang siap berjalan
            while (!$this->readyQueue->isEmpty()) {
                $fiber = $this->readyQueue->dequeue();
                
                if ($fiber->isSuspended()) {
                    $fiber->resume();
                } elseif (!$fiber->isStarted()) {
                    $fiber->start();
                }
            }

            if (empty($this->readSockets)) {
                break;
            }

            // 2. I/O Multiplexing menggunakan stream_select
            $read = array_column($this->readSockets, 'socket');
            $write = null;
            $except = null;

            // Block CPU sebentar menunggu I/O siap (timeout 200ms)
            $changed = stream_select($read, $write, $except, 0, 200_000);

            if ($changed === false) {
                throw new RuntimeException("Stream select failed");
            }

            if ($changed > 0) {
                foreach ($read as $socket) {
                    $id = (int) $socket;
                    $fiber = $this->readSockets[$id]['fiber'];
                    unset($this->readSockets[$id]);
                    
                    // Masukkan kembali Fiber ke antrean eksekusi
                    $this->readyQueue->enqueue($fiber);
                }
            }
        }
    }
}

final class AsyncHttpClient
{
    public function __construct(private MiniScheduler $scheduler) {}

    public function get(string $host, string $path = '/'): string
    {
        $currentFiber = Fiber::getCurrent();
        if ($currentFiber === null) {
            throw new LogicException("AsyncHttpClient::get() must be called inside a Fiber.");
        }

        // Buka non-blocking socket
        $socket = @stream_socket_client(
            "tcp://{$host}:80",
            $errno,
            $errstr,
            3,
            STREAM_CLIENT_CONNECT | STREAM_CLIENT_ASYNC_CONNECT
        );

        if (!$socket) {
            throw new RuntimeException("Connection failed: {$errstr} ({$errno})");
        }

        stream_set_blocking($socket, false);

        // Daftarkan socket ke scheduler dan jeda eksekusi
        $this->scheduler->waitForRead($socket, $currentFiber);
        Fiber::suspend();

        // Kirim HTTP request mentah
        $request = "GET {$path} HTTP/1.1\r\nHost: {$host}\r\nConnection: close\r\n\r\n";
        fwrite($socket, $request);

        $response = '';
        while (!feof($socket)) {
            // Tunggu data tersedia untuk dibaca
            $this->scheduler->waitForRead($socket, $currentFiber);
            Fiber::suspend();

            $chunk = fread($socket, 8192);
            if ($chunk !== false) {
                $response .= $chunk;
            }
        }

        fclose($socket);
        return $response;
    }
}

// ==========================================
// Eksekusi Concurrency
// ==========================================

$scheduler = new MiniScheduler();
$client = new AsyncHttpClient($scheduler);

$urls = [
    ['host' => 'httpbin.org', 'path' => '/delay/1'],
    ['host' => 'httpbin.org', 'path' => '/delay/2'],
    ['host' => 'httpbin.org', 'path' => '/ip'],
];

echo "[START] Memulai request asinkron concurrent...\n";
$startTime = microtime(true);

foreach ($urls as $target) {
    $fiber = new Fiber(function () use ($client, $target): void {
        $fiberId = spl_object_id(Fiber::getCurrent());
        echo "[Fiber {$fiberId}] Fetching: {$target['host']}{$target['path']}...\n";
        
        $data = $client->get($target['host'], $target['path']);
        $statusLine = strtok($data, "\r\n");
        
        echo "[Fiber {$fiberId}] Selesai! Status: {$statusLine}\n";
    });

    $scheduler->enqueue($fiber);
}

$scheduler->run();

$totalTime = round(microtime(true) - $startTime, 2);
echo "[DONE] Seluruh task selesai dalam {$totalTime} detik (Non-blocking I/O).\n";
```

#### Penjelasan Alur Kode:
1. `MiniScheduler` bertindak sebagai *event loop* sederhana. Ia mengombinasikan *run-queue* untuk Fiber dengan `stream_select` untuk *I/O multiplexing*.
2. Pada `AsyncHttpClient::get()`, ketika soket belum siap membaca data, fungsi memanggil `Fiber::suspend()`. Ini menghentikan eksekusi kode lokal secara instan dan mengembalikan kendali ke `MiniScheduler::run()`.
3. Fungsi pemanggil `AsyncHttpClient::get()` terlihat seperti kode sinkron imperatif biasa, namun di belakang layar ia diistirahatkan hingga event loop mendeteksi ketersediaan data via `stream_select`, kemudian memicu `$fiber->resume()`.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Native C Stack Switching
* **Zend VM Context**: PHP Engine mempertahankan struktur data global internal yang disebut `zend_executor_globals` (sering disingkat `EG`). Properti ini memegang pointer ke eksekusi saat ini (`EG(current_execute_data)`), *exception handler*, dan alokasi *symbol table*.
* **Context Switching di Level Mesin**: Saat `new Fiber()` diinstansiasi, PHP tidak sekadar membuat objek di memori; PHP mengalokasikan konteks *call stack* arsitektur CPU baru. Implementasi Zend Fiber bergantung pada library platform-spesifik berkinerja tinggi:
  * Arsitektur POSIX x86_64/ARM: Menggunakan kode assembly berbasis `boost.context` untuk manipulasi register CPU secara langsung (`RSP`/`ESP`, `RBP`, program counter `RIP`).
  * Fallback: Menggunakan POSIX `makecontext`/`swapcontext` atau API Fibers bawaan Windows OS (`CreateFiberEx`).
* Ketika `Fiber::suspend()` dipanggil:
  1. Zend Engine menyimpan pointer frame instruksi saat ini ke objek PHP Fiber.
  2. Instruksi assembly memindahkan register CPU saat ini ke memori konteks Fiber yang aktif.
  3. Pointer register stack CPU dialihkan kembali ke stack pemanggil (`$fiber->resume()` atau `$fiber->start()`).
  4. Seluruh proses ini terjadi dalam orde nanodetik (tidak ada keterlibatan *kernel context switch* atau alokasi *thread* OS baru).

```
          Thread OS Utama (Satu Kernel Thread)
┌────────────────────────────────────────────────────────┐
│                      Zend VM Engine                    │
│                                                        │
│  [Event Loop / Main Stack]                             │
│          │                                             │
│     fiber->start() ──┐ [Swap Context ASM]              │
│          │           ▼                                 │
│          │    [Fiber Stack A]                          │
│          │           │                                 │
│          │    Fiber::suspend() ──┐                     │
│          │           ▲           │ [Swap Context ASM]  │
│          ▼           │           ▼                     │
│   (I/O Polling) ─────┘    [Event Loop / Main Stack]    │
└────────────────────────────────────────────────────────┘
```

#### Alokasi Memori / Resource
* **Stack Size**: Setiap Fiber mengalokasikan stack memori virtual (secara *default* berkisar 2MB memori virtual di OS, dialokasikan melalui `mmap` dengan proteksi *guard page* untuk mencegah *stack overflow* mengeksploitasi area memori lain). Alokasi fisik (RAM) hanya bertambah secara dinamis sesuai kedalaman *call stack* Fiber tersebut.
* Objek `Fiber` tetap berada di dalam memori PHP hingga siklus hidup fungsi yang di-*wrap* selesai dieksekusi atau objek Fiber di-*garbage collect* (jika tidak ada referensi siklis tertahan).

#### Trade-offs
* **Fiber vs OS Thread**: Fiber sangat ringan (memungkinkan pembuatan puluhan ribu Fiber dalam 1 proses tanpa membebani *kernel thread scheduler*). Namun, Fiber **tidak memberikan paralelisme multi-core**. Jika ada satu Fiber menjalankan kalkulasi CPU intensif (misal: enkripsi berat atau *hashing loop*), seluruh event loop dan Fiber lain dalam proses tersebut akan terhenti (*starvation*).

### 4. Best Practices & Common Pitfalls

#### Do's
* **Gunakan Event Loop Standar Industri**: Untuk kebutuhan produksi, gunakan abstraksi modern seperti **Revolt PHP** (`revolt/event-loop`) atau framework **Amp v3**. Jangan membuat scheduler berbasis `stream_select` sendiri untuk aplikasi berskala besar karena keterbatasan limit *file descriptor* (FD) hingga 1024 FD.
* **Pertahankan Isolasi State**: Pastikan status transaksional lokal diikat pada instance konteks atau Fiber ID, bukan pada variabel global atau properti *singleton* statis yang dapat terkontaminasi oleh *interleaved execution*.
* **Tangani Exception di Dalam Fiber**: Selalu gunakan blok `try-catch` di dalam *closure* Fiber jika Anda tidak ingin exception yang tidak tertangkap meledak ke frame pemanggil `resume()`.

#### Don'ts
* **Jangan Jalankan Operasi Blocking I/O**: Memanggil `PDO::query()`, `file_get_contents()`, `curl_exec()`, atau `sleep()` di dalam Fiber akan mengunci *seluruh proses PHP*. Semua Fiber lain akan terhenti hingga pemanggilan blocking tersebut selesai. Operasi I/O harus didelegasikan ke driver non-blocking atau *worker thread pool*.
* **Jangan Gunakan Fiber untuk Paralelisme CPU**: Fiber ditujukan untuk *concurrency* (mengelola banyak I/O secara bersamaan), bukan *parallelism* (memecah kalkulasi CPU ke beberapa core). Gunakan ekstensi `parallel` atau worker process (misal: Symfony Messenger worker) untuk tugas berbasis CPU.

#### Edge Cases & Gotchas
* **Pembersihan Resource Tergantung Garbage Collector**: Jika sebuah Fiber di-*suspend* dan referensinya hilang dari memori tanpa pernah di-*resume*, blok `finally` di dalam Fiber **tidak akan langsung dieksekusi** sampai garbage collector membersihkan siklus referensi tersebut.
* **Fiber Serialization**: Objek `Fiber` tidak dapat di-serialize (`serialize()` akan melempar `Exception`). State Fiber tidak bisa disimpan langsung ke Redis atau database.
* **Reentrancy State**: Memanggil `$fiber->resume()` pada Fiber yang sedang berstatus `isRunning` atau `isTerminated` akan melempar `FiberError`. Selalu periksa state dengan `$fiber->isSuspended()` sebelum memanggil `$fiber->resume()`.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Timeout Mechanism**: Modifikasi kelas `MiniScheduler` di atas agar mendukung pembatalan (atau pelontaran `TimeoutException`) pada Fiber yang operasi I/O-nya melebihi ambang batas waktu tertentu (misalnya > 3 detik).
2. **Transformasi Generator ke Fiber**: Ambil kode lama berbasis Generator (`yield` Promise) dan ubah strukturnya menjadi berbasis Fiber murni. Ukur perbedaannya dari segi kompleksitas kode dan jejak *stack trace* saat terjadi *error*.
3. **Deteksi Blocking Operation**: Buat sebuah decorator atau helper function yang dapat mengukur durasi antar *suspension point* di dalam Fiber, dan log sebuah *warning* jika ada blok kode yang menahan eksekusi CPU lebih dari 50ms tanpa melakukan suspend.
