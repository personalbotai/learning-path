## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

**PSR-15 (HTTP Server Request Handlers)** adalah standar interoperabilitas PHP yang mendefinisikan mekanisme pemrosesan HTTP *request* berbasis middleware dan *request handler*. Sebelum PSR-15 diadopsi secara luas, setiap *framework* (seperti Zend/Laminas, Slim, Symfony, dan Laravel) mengimplementasikan arsitektur middleware milik sendiri secara terisolasi. Akibatnya, komponen ekosistem seperti otentikasi, *rate-limiting*, atau *profiling* tidak dapat dipindahkan antar-framework tanpa menulis ulang lapisan adaptasi.

PSR-15 distandardisasi di atas **PSR-7 (HTTP Message Interfaces)** dan membagi peran menjadi dua antarmuka (*interface*) utama:

1. **`Psr\Http\Server\MiddlewareInterface`**:
   Komponen yang memproses *request* secara parsial atau menyeluruh. Ia menerima *request* masuk dan referensi ke *handler* berikutnya, lalu mengembalikan *response*.
2. **`Psr\Http\Server\RequestHandlerInterface`**:
   Komponen yang bertindak sebagai "terminal" atau "dispatcher". Ia menerima *request* dan bertanggung jawab mutlak mengembalikan *response* (tanpa meneruskan ke komponen lain di rantai tersebut).

#### Arsitektur: *The Onion Pattern* (Pola Lapisan Kulit Bawang)

Middleware pipeline beroperasi mengikuti pola *onion* atau rantai tanggung jawab (*Chain of Responsibility*):

```
       [ HTTP Request Masuk ]
                 │
                 ▼
┌─────────────────────────────────┐
│     Middleware 1: Routing       │
│  ┌───────────────────────────┐  │
│  │   Middleware 2: Auth      │  │
│  │  ┌─────────────────────┐  │  │
│  │  │ Terminal Handler    │  │  │
│  │  │ (Controller Logic)  │  │  │
│  │  └─────────────────────┘  │  │
│  │   [Response Dibentuk]     │  │
│  └───────────────────────────┘  │
│     [Post-Processing Response]  │
└─────────────────────────────────┘
                 │
                 ▼
       [ HTTP Response Keluar ]
```

- **Fase Masuk (*Inbound/Pre-processing*)**: Request mengalir dari lapisan terluar menuju ke lapisan paling dalam. Setiap middleware dapat menginspeksi, memvalidasi, atau mengubah request (menggunakan klon baru karena PSR-7 bersifat *immutable*).
- **Short-Circuiting**: Middleware dapat menghentikan eksekusi rantai lebih awal tanpa memanggil `$handler->handle($request)`. Contoh: middleware autentikasi langsung mengembalikan `401 Unauthorized` jika token tidak valid.
- **Terminal Execution**: Request mencapai handler target (misal: Controller Action).
- **Fase Keluar (*Outbound/Post-processing*)**: Response kembali mengalir keluar melewati middleware dalam urutan terbalik (*LIFO - Last In, First Out*). Middleware dapat memodifikasi header, membungkus payload, atau mengukur metrik eksekusi (seperti durasi pemrosesan).

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut menunjukkan implementasi pipeline PSR-15 mandiri yang mengeksekusi middleware autentikasi dan pengukuran durasi (*timing*), diakhiri oleh *terminal request handler*.

> **Catatan Dependensi**: Contoh ini mengasumsikan penggunaan implementasi PSR-7 (misalnya `nyholm/psr7` atau `laminas/laminas-diactoros`) dan antarmuka resmi `psr/http-server-middleware` serta `psr/http-server-handler`.

```php
<?php

declare(strict_types=1);

namespace App\Http;

use Psr\Http\Message\ResponseInterface;
use Psr\Http\Message\ServerRequestInterface;
use Psr\Http\Server\MiddlewareInterface;
use Psr\Http\Server\RequestHandlerInterface;

// ============================================================================
// 1. DISPATCHER / PIPELINE IMPLEMENTATION (RequestHandlerInterface)
// ============================================================================
final class MiddlewarePipeline implements RequestHandlerInterface
{
    /** @var MiddlewareInterface[] */
    private array $middlewares = [];
    private RequestHandlerInterface $fallbackHandler;
    private int $index = 0;

    public function __construct(RequestHandlerInterface $fallbackHandler)
    {
        $this->fallbackHandler = $fallbackHandler;
    }

    public function pipe(MiddlewareInterface $middleware): self
    {
        $this->middlewares[] = $middleware;
        return $this;
    }

    public function handle(ServerRequestInterface $request): ResponseInterface
    {
        // Jika seluruh middleware selesai dieksekusi, teruskan ke fallback handler
        if (!isset($this->middlewares[$this->index])) {
            return $this->fallbackHandler->handle($request);
        }

        // Ambil middleware saat ini dan majukan pointer untuk pemanggilan berikutnya
        $middleware = $this->middlewares[$this->index];
        
        // Buat salinan shallow untuk menjaga rekursi tetap terisolasi
        $next = clone $this;
        $next->index++;

        return $middleware->process($request, $next);
    }
}

// ============================================================================
// 2. MIDDLEWARES IMPLEMENTATION
// ============================================================================

/**
 * Middleware: Mengukur waktu eksekusi total dari rantai internal
 */
final class ExecutionTimerMiddleware implements MiddlewareInterface
{
    public function process(ServerRequestInterface $request, RequestHandlerInterface $handler): ResponseInterface
    {
        $startTime = hrtime(true);

        // Teruskan ke middleware / handler berikutnya
        $response = $handler->handle($request);

        $endTime = hrtime(true);
        $durationMs = ($endTime - $startTime) / 1e+6;

        // Modifikasi response sebelum diteruskan ke lapisan luar
        return $response->withHeader('X-Response-Time-Ms', sprintf('%.2f', $durationMs));
    }
}

/**
 * Middleware: Validasi API Key (Short-circuiting jika gagal)
 */
final class ApiKeyAuthMiddleware implements MiddlewareInterface
{
    public function __construct(
        private string $validApiKey,
        private \Closure $responseFactory // Factory untuk membuat Response PSR-7
    ) {}

    public function process(ServerRequestInterface $request, RequestHandlerInterface $handler): ResponseInterface
    {
        $authHeader = $request->getHeaderLine('X-API-KEY');

        if ($authHeader === '' || !hash_equals($this->validApiKey, $authHeader)) {
            // Short-circuit: Langsung buat response tanpa menyentuh $handler
            /** @var ResponseInterface $response */
            $response = ($this->responseFactory)(401);
            $response->getBody()->write(json_encode(['error' => 'Unauthorized Access']));
            
            return $response->withHeader('Content-Type', 'application/json');
        }

        // Tambahkan context identitas ke dalam request attribute secara immutable
        $mutatedRequest = $request->withAttribute('authenticated_client', 'client_internal_01');

        return $handler->handle($mutatedRequest);
    }
}

// ============================================================================
// 3. TERMINAL HANDLER (Aplikasi / Controller Logic)
// ============================================================================
final class ApiEndpointHandler implements RequestHandlerInterface
{
    public function __construct(private \Closure $responseFactory) {}

    public function handle(ServerRequestInterface $request): ResponseInterface
    {
        $client = $request->getAttribute('authenticated_client', 'unknown');

        /** @var ResponseInterface $response */
        $response = ($this->responseFactory)(200);
        $response->getBody()->write(json_encode([
            'status'  => 'success',
            'client'  => $client,
            'payload' => ['item1', 'item2', 'item3']
        ]));

        return $response->withHeader('Content-Type', 'application/json');
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Call-Stack & Zend Engine Frames**: Pipeline dieksekusi secara sinkron melalui pemanggilan metode rekursif atau delegasi berantai. Setiap kali middleware memanggil `$handler->handle($request)`, Zend Engine mengalokasikan frame eksekusi baru (`zend_execute_data`) di C-stack. 
- Jika sebuah aplikasi memiliki 50 middleware, *stack depth* akan bertambah setidaknya 50 tingkat ke dalam sebelum akhirnya unwinding (berjalan mundur) ketika response mulai dikembalikan.
- **State Preservation via Immutability**: Pola *clone $this* pada class `MiddlewarePipeline` di atas memastikan bahwa manipulasi indeks pemrosesan bersifat *idempotent* dan terisolasi dari *side-effects* cabang konkurensi (seperti sub-request).

#### Alokasi Memori / Resource
- **PSR-7 Object Churn**: Setiap kali middleware memanggil `$request->withHeader()` atau `$request->withAttribute()`, Zend Engine **tidak** memodifikasi array internal object tersebut di tempat (*in-place mutation*). Sebaliknya, *Zend Object Handler* mengeksekusi operasi `clone`, menduplikasi struktur `zend_object`, dan mengalokasikan memori baru di *Zend Memory Manager* (ZMM). 
- Meskipun mekanisme *Copy-on-Write* (COW) PHP melindungi zval skalar dan array referensial dari duplikasi instan, instansiasi klon objek berulang kali dalam pipeline panjang tetap menghasilkan lonjakan *memory churn* dan memicu aktivitas *Garbage Collection* (GC) lebih cepat.

#### Trade-offs Desain
- **Keuntungan**: *Zero coupling*. Komponen otentikasi tidak perlu tahu apakah ia berjalan di atas Laravel, Mezzio, atau implementasi kustom. Mudah diuji secara terisolasi (*unit testable*) hanya dengan memalsukan (`mock`) `RequestHandlerInterface`.
- **Kerugian**: Sedikit degradasi latensi mikro (*overhead CPU instructions*) dibandingkan pendekatan arsitektur monolitik prosedural akibat alokasi memori klon objek PSR-7 dan *nested method invocation overhead*.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Jaga Middleware Tetap Stateless**: Middleware harus berstatus *stateless* terhadap request. Jangan pernah menyimpan data spesifik request di dalam properti instansi (`$this->someData`). Middleware yang stateful akan menjadi celah keamanan fatal (*data leakage*) jika dijalankan di runtime persisten seperti **Swoole**, **RoadRunner**, atau **FrankenPHP**.
- **Teruskan Konteks via Request Attributes**: Selalu gunakan `$request->withAttribute('key', $value)` untuk meneruskan metadata (seperti ID user terotentikasi, *tenant id*, atau role) ke middleware atau controller berikutnya.
- **Posisikan Error Handling di Lapisan Terluar**: Tempatkan middleware pengurang/penangkap exception (`Throwable`) sedekat mungkin dengan lapisan terluar pipeline agar dapat menangkap kegagalan yang terjadi di middleware dalam dan tetap mengembalikan PSR-7 Response yang valid.

#### Don'ts
- **Hindari Side-Effects Langsung ke Output Buffer**: Jangan gunakan `echo`, `print`, `var_dump`, atau `header()` di dalam middleware. Hal ini melanggar arsitektur PSR-7/PSR-15 dan merusak integritas *response stream* HTTP.
- **Jangan Menggunakan `exit()` atau `die()`**: Menghentikan eksekusi secara brutal merusak fase pembersihan (*teardown*), mengabaikan middleware post-processing, dan mematikan worker pada arsitektur async PHP runtime. Selalu lakukan *short-circuit* dengan mengembalikan instansi `ResponseInterface`.

#### Edge Cases & Pitfalls
- **Streaming & Large Payload Handling**: Modifikasi payload pada response berukuran gigabita (misal: ekspor CSV) di dalam middleware post-processing berisiko menyebabkan *Out-of-Memory* (OOM). Hindari pemanggilan `$response->getBody()->getContents()` jika data tidak sepenuhnya ditampung di memori. Gunakan dekorator `StreamInterface` untuk menyaring stream secara *chunk-by-chunk*.

### 5. Tantangan Eksplorasi Mandiri

1. **Lazy Loading Middleware Resolver**:
   Implementasi pipeline di atas langsung menginstansiasi middleware di awal. Rancang dan modifikasi class `MiddlewarePipeline` agar mendukung resolusi kontainer dependensi (**PSR-11 ContainerInterface**). Middleware hanya boleh diinstansiasi dari container saat rantai eksekusi benar-benar mencapai giliran middleware tersebut (*lazy-instantiation*).
2. **Double-Pass vs Single-Pass Migration**:
   Cari tahu tentang arsitektur middleware lawas "Double-Pass" `function($request, $response, $next)` yang populer sebelum PSR-15. Buat sebuah adapter kelas PSR-15 yang mampu membungkus (*wrap*) legacy double-pass middleware agar dapat berjalan di pipeline modern tanpa mengubah kode legacy tersebut.
