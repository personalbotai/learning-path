## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum PHP 8.1, representasi data diskrit yang terbatas (enumerated types) biasanya diimplementasikan menggunakan kumpulan konstanta kelas (`class constants`), paket pihak ketiga seperti `myclabs/php-enum`, atau ekstensi lama `SplEnum`. Pendekatan ini memiliki kelemahan fundamental: tidak adanya jaminan integritas tipe (*type safety*) pada level engine, rawan terhadap mutasi nilai tak valid jika dioperasikan sebagai skalar bebas, serta ketiadaan identitas objek yang deterministik.

PHP 8.1 memperkenalkan **Enums natively** sebagai tipe data tingkat pertama (*first-class citizens*). Di PHP, Enum bukan sekadar alias sintaksis untuk integer atau string, melainkan sebuah tipe khusus dari **objek** (`class` dengan restriksi ketat) yang mengimplementasikan arsitektur *Singleton/Flyweight pattern* pada setiap *case*-nya.

Secara taksonomi, Enum di PHP terbagi menjadi dua:

1. **Pure Enums**: Enum yang kasus-kasus nilainya tidak memiliki representasi skalar eksternal. Setiap *case* berdiri sendiri murni sebagai identitas objek unik. Pure Enum mengimplementasikan interface internal `\UnitEnum`.
2. **Backed Enums**: Enum yang setiap kasusnya terikat secara ekuivalen ke satu nilai skalar primitif bertipe konsisten, yaitu `string` atau `int`. Backed Enum mengimplementasikan `\BackedEnum` (yang merupakan turunan dari `\UnitEnum`).

```
                +-------------------+
                |     UnitEnum      |
                | (Pure Enums)      |
                | - cases(): array  |
                +---------+---------+
                          ^
                          | (extends)
                +---------+---------+
                |    BackedEnum     |
                | (Backed Enums)    |
                | - from(scalar)    |
                | - tryFrom(scalar) |
                +-------------------+
```

#### Karakteristik Struktural Enum:
- **Restriksi Ketat**: Enum tidak dapat diinstansiasi secara manual via operator `new`, tidak dapat di-*clone* via keyword `clone`, tidak dapat diekstensi (*no inheritance*), dan tidak dapat memiliki *state* dinamis (tidak boleh memiliki properti instansiasi non-statis).
- **Equivalence & Identity**: Perbandingan dua *case* Enum dengan tipe yang sama dapat menggunakan operator identitas ketat (`===`) karena keduanya merujuk pada *pointer* instansiasi memori yang identik.
- **Dukungan Fitur Kelas**: Enum dapat memiliki method (statis maupun non-statis), mengimplementasikan `interface`, menggunakan `trait` (selama trait tidak mendeklarasikan *instance properties*), dan mendukung ekspresi konstanta.

### 2. Implementasi & Contoh Kasus Nyata

Berikut implementasi komprehensif sistem manajemen status transaksi pembayaran menggunakan Backed Enum, method internal, implementasi interface, serta pemanfaatan `tryFrom`:

```php
<?php

declare(strict_types=1);

namespace App\Domain\Payment;

interface Describable
{
    public function label(): string;
    public function canTransitionTo(PaymentStatus $nextStatus): bool;
}

// Mendeklarasikan Backed Enum berbasis string
enum PaymentStatus: string implements Describable
{
    case PENDING    = 'pending';
    case PROCESSING = 'processing';
    case COMPLETED  = 'completed';
    case FAILED     = 'failed';
    case REFUNDED   = 'refunded';

    // Implementasi method interface
    public function label(): string
    {
        return match ($this) {
            self::PENDING    => 'Menunggu Pembayaran',
            self::PROCESSING => 'Sedang Diproses Gateway',
            self::COMPLETED  => 'Pembayaran Berhasil Dikonfirmasi',
            self::FAILED     => 'Transaksi Gagal',
            self::REFUNDED   => 'Dana Dikembalikan',
        };
    }

    // Business rule state transition engine
    public function canTransitionTo(self $nextStatus): bool
    {
        return match ($this) {
            self::PENDING    => in_array($nextStatus, [self::PROCESSING, self::FAILED], true),
            self::PROCESSING => in_array($nextStatus, [self::COMPLETED, self::FAILED], true),
            self::COMPLETED  => $nextStatus === self::REFUNDED,
            self::FAILED, 
            self::REFUNDED   => false, // Terminal states: tidak dapat berpindah lagi
        };
    }

    // Static helper method untuk ekstraksi nilai skalar
    /**
     * @return array<string>
     */
    public static function values(): array
    {
        return array_column(self::cases(), 'value');
    }
}

// ==========================================
// Simulasi Pemrosesan Domain Payment
// ==========================================

class OrderPaymentProcessor
{
    private PaymentStatus $status;

    public function __construct(string $rawStatus)
    {
        // tryFrom mengembalikan null secara aman jika value tidak terdaftar
        $this->status = PaymentStatus::tryFrom($rawStatus) 
            ?? throw new \InvalidArgumentException("Status invalid: {$rawStatus}");
    }

    public function transition(PaymentStatus $targetStatus): void
    {
        if (!$this->status->canTransitionTo($targetStatus)) {
            throw new \DomainException(
                sprintf('Transisi ilegal dari "%s" menuju "%s"', $this->status->value, $targetStatus->value)
            );
        }

        $this->status = $targetStatus;
    }

    public function getStatus(): PaymentStatus
    {
        return $this->status;
    }
}

// Eksekusi kode
$order = new OrderPaymentProcessor('pending');
echo "Status saat ini: " . $order->getStatus()->label() . PHP_EOL;

// Coba transisi valid
$order->transition(PaymentStatus::PROCESSING);
echo "Status baru: " . $order->getStatus()->label() . PHP_EOL;

// Verifikasi Identity Check
$statusRef = PaymentStatus::PROCESSING;
var_dump($order->getStatus() === $statusRef); // bool(true) - Identitas pointer memori sama
```

#### Penjelasan Elemen Penting:
1. `PaymentStatus: string`: Mendeklarasikan bahwa Enum ini adalah Backed Enum bertipe string. Semua kasus **harus** memiliki nilai string unik.
2. `$this->name` dan `$this->value`: Properti bawaan read-only engine. Pada `PaymentStatus::PENDING`, `$this->name` bernilai `'PENDING'`, sedangkan `$this->value` bernilai `'pending'`.
3. `match ($this)`: Karena `$this` adalah instansi objek dari *case*, operator `match` mengevaluasi identitas objek tanpa memerlukan *type juggling*.
4. `self::cases()`: Mengembalikan array berisi seluruh singleton instance dari *case* enum tersebut secara berurutan.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime:
- Pada Zend Engine, definisi sebuah Enum dialokasikan sebagai sebuah `zend_class_entry` dengan flag modifikator khusus: `ZEND_ACC_ENUM`.
- Ketika PHP mengompilasi Enum, engine secara otomatis menyuntikkan implementasi internal dari `\UnitEnum` atau `\BackedEnum`.
- Setiap deklarasi *case* diterjemahkan menjadi konstanta kelas internal bernilai objek instansiasi statis:
  ```c
  // Pseudocode representasi internal Zend Engine
  zend_enum_case = zend_register_internal_class_constant(ce, case_name, sizeof(case_name)-1, ...);
  ```
- Objek dari masing-masing *case* diinisialisasi hanya sekali saat proses prapemindaian runtime (*compile-time/early binding step*) berlangsung. Akibatnya, setiap pemanggilan `PaymentStatus::PENDING` di belahan kode mana pun akan merujuk langsung ke pointer `zend_object` yang sama persis (Pattern *Flyweight*).

#### Alokasi Memori / Resource:
- **Zero Heap Allocations on Evaluation**: Karena seluruh *case* telah dialokasikan ke memori engine sebagai objek singleton abadi (*immutable static objects*) selama daur hidup *request*, pemanggilan Enum tidak menyebabkan *memory reallocation* pada heap per *call*, berbeda dengan instansiasi class biasa via `new ClassName()`.
- **Identity Evaluation Speed**: Operasi `$a === $b` di runtime dievaluasi menggunakan pembandingan pointer objek level C (`obj1 == obj2`), bukan pembandingan komputasi string atau array hashing. Ini membuat evaluasi kesetaraan Enum berjalan dalam kompleksitas waktu konstan $O(1)$ setara dengan pembandingan integer murni.

#### Trade-offs:
- **Immutability vs Metadata Extensibility**: Enum tidak dapat memiliki properti instansiasi dinamis. Data tambahan yang terikat pada *case* harus diresolusi lewat method (menggunakan `match`) atau reflection/attributes, yang sedikit mengorbankan performa dibandingkan membaca direct property.
- **Overhead Serialization**: Serialisasi Enum via `serialize()` akan menyimpan tipe kelas dan nama kasusnya (misal: `E:27:"App\Domain\PaymentStatus:7:"PENDING";`). Ini lebih besar daripada hanya menyimpan nilai primitif seperti integer flag.

### 4. Best Practices & Common Pitfalls

#### Do's:
- **Gunakan Strict Identity (`===`)**: Selalu bandingkan kasus Enum dengan operator identitas `===`, jangan gunakan `==` untuk mencegah celah *type juggling* tak disengaja.
- **Gunakan `tryFrom()` pada I/O Boundary**: Manfaatkan `tryFrom()` saat menerima payload dari luar domain (Request JSON, Query String, Database result) untuk menangani input tidak valid dengan elegan tanpa memicu fatal exception `ValueError`.
- **Gunakan Pure Enum jika tidak butuh persistensi skalar**: Jika sebuah status hanya digunakan sebagai flag alur logika memori internal domain (tidak disimpan langsung ke database atau API external), gunakan Pure Enum.

#### Don'ts:
- **Jangan Menggunakan Enums Sebagai Array Key Secara Langsung**: PHP tidak mengizinkan objek dijadikan array key.
  ```php
  // FATAL ERROR: Invalid key type
  $cache = [];
  $cache[PaymentStatus::PENDING] = 'data'; // TypeError: Cannot use object of type PaymentStatus as offset
  
  // SOLUSI: Gunakan properti value (jika Backed Enum) atau SplObjectStorage
  $cache[PaymentStatus::PENDING->value] = 'data';
  ```
- **Hindari Implementasi `__call` / Magic Methods yang Dilarang**: Engine melarang deklarasi magic method seperti `__construct`, `__destruct`, `__set`, `__get`, `__clone`, `__sleep`, `__wakeup` di dalam tubuh Enum untuk menjamin *strict immutability*.

#### Edge Cases:
- **Masalah Serialization ke JSON**: Secara bawaan, `json_encode(PaymentStatus::PENDING)` menghasilkan output kosong `{}` karena PHP Engine tidak mengekspos properti publik secara otomatis pada Pure Enum, atau hanya mengabaikannya.
  ```php
  // PENTING: Untuk mengontrol output json_encode, implementasikan JsonSerializable
  enum OrderType: string implements \JsonSerializable
  {
      case PHYSICAL = 'physical';
      case DIGITAL  = 'digital';

      public function jsonSerialize(): string
      {
          return $this->value;
      }
  }

  echo json_encode(OrderType::PHYSICAL); // Output: "physical" (bukan {})
  ```
- **Type Casting Skalar yang Tidak Cocok**: `PaymentStatus::from(1)` akan melempar `TypeError` jika enum dideklarasikan sebagai string (`PaymentStatus: string`), meskipun nilai integer tersebut bisa di-cast menjadi string `'1'`. Strict scalar types mutlak berlaku pada `from()` dan `tryFrom()`.

### 5. Tantangan Eksplorasi Mandiri

1. **Custom Attribute Lookup pada Enum Cases**:
   Buatlah sebuah *Custom Attribute* bernama `#[Color(string $hex)]`. Pasang atribut ini di setiap *case* pada sebuah Enum baru bernama `TrafficLight`. Kemudian, buat sebuah method `public function getColor(): string` di dalam Enum tersebut yang memanfaatkan `ReflectionEnumUnitCase` untuk membaca warna hex secara dinamis dari atribut *case* yang sedang aktif.

2. **Database Casting Engine**:
   Rancang sebuah *Data Mapper* sederhana yang dapat menerima data baris dari tabel database berupa *raw array* skalar (`['id' => 1, 'status' => 'refunded']`), lalu secara otomatis memvalidasi dan menginstansiasinya ke dalam sebuah objek `InvoiceEntity` menggunakan `PaymentStatus::from()`, dan tangani skenario bagaimana jika isi kolom database bernilai string yang korup/tidak terdaftar di Enum.
