### 1. Konsep & Arsitektur Mendalam

Evolusi sistem tipe dan resolusi simbol di PHP modern (PHP 8.0 hingga 8.3+) berfokus pada penghapusan ambiguitas string-based meta-programming dan peningkatan integritas tipe saat *compile-time* maupun *runtime*. Dua pilar penting dalam modernisasi ini adalah **Dynamic Class Fetching** dan **Typed Class Constants**.

```
+-------------------------------------------------------------------------------+
|                             PHP RESOLUTION PIPELINE                           |
+-------------------------------------------------------------------------------+
|                                                                               |
|   PHP 5/7: get_class($obj)               PHP 8.0+: $obj::class                |
|   [ Call Function Stack ]               [ Direct AST Opcode Lookup ]          |
|   -> zend_execute (VM Frame)            -> ZEND_FETCH_CLASS_NAME              |
|   -> C-Function get_class()             -> Direct Access: zval.value.ce->name |
|   -> Return zval string                 -> Return zval interned string        |
|                                                                               |
|-------------------------------------------------------------------------------|
|                                                                               |
|   PHP 8.3+: Typed Class Constants                                             |
|   Interface/Parent Contract             Child Inheritance                     |
|   +--------------------------+          +--------------------------+          |
|   | const string|int CODE    |  <====   | const string CODE        | (Valid)  |
|   +--------------------------+          +--------------------------+          |
|                 \                                     /                       |
|                  \====== [ Covariance Check ] =======/                        |
|                          (zend_do_inheritance)                                |
|                                                                               |
+-------------------------------------------------------------------------------+
```

#### Dynamic Class Fetching (`::class` pada Objek & Ekspresi)
Sebelum PHP 8.0, resolusi nama kelas yang aman dari namespace dilakukan menggunakan sintaks statis `ClassName::class` (diperkenalkan di PHP 5.5), yang dievaluasi saat *compile-time*. Namun, jika developer memiliki sebuah *instance* dan membutuhkan *Fully Qualified Class Name* (FQCN), mereka terpaksa menggunakan fungsi runtime `get_class($instance)`. 

PHP 8.0 menghapus diskrepansi ini dengan mengizinkan fetch dinamis melalui operator resolusi lingkup:
```php
$object::class;
(new Service())::class;
($condition ? $serviceA : $serviceB)::class;
```
Fitur ini bukan sekadar *syntactic sugar*; ia beroperasi langsung di level Abstract Syntax Tree (AST) dan Zend Virtual Machine (Zend VM) opcode, mengekstraksi metadata kelas secara langsung tanpa alokasi frame fungsi reguler.

#### Class Constant Types (PHP 8.3)
Sebelum PHP 8.3, konstanta kelas (`const`) tidak memiliki mekanisme penegakan tipe data (*type enforcement*). Konstanta kelas hanya diasumsikan bertipe data berdasarkan nilai skalar atau array yang di-assign padanya. Masalah timbul pada arsitektur berbasis antarmuka (interface) atau kelas abstrak: kelas turunan dapat menimpa (*override*) nilai konstanta dengan tipe data yang sama sekali berbeda, merusak kontrak API (misalnya antarmuka mengharapkan string representasi UUID, tetapi kelas anak mengisinya dengan integer atau array).

Mulai PHP 8.3, konstanta kelas, antarmuka, dan trait dapat dideklarasikan dengan tipe eksplisit:
```php
interface Configurable {
    public const string DRIVER = 'mysql';
    public const int TIMEOUT = 5000;
}
```
Aturan tipe pada konstanta mengikuti prinsip **Kovariansi (Covariance)**: tipe konstanta di kelas anak dapat dipersempit (*narrowed*), namun tidak boleh diperluas (*widened*) atau diubah tipenya secara bertentangan.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut menunjukkan integrasi pemrosesan *Domain Event* menggunakan Dynamic Class Fetching untuk *event-routing* otomatis, dipadukan dengan Typed Class Constants untuk menjaga integritas metadata *event*.

```php
<?php

declare(strict_types=1);

namespace App\Infrastructure\Messaging;

// 1. Antarmuka dengan Typed Constants (PHP 8.3)
interface DomainEventInterface
{
    // Mengunci bahwa semua event wajib mendefinisikan versi berupa int,
    // dan nama agregat berupa string.
    public const int SCHEMA_VERSION = 1;
    public const string|null AGGREGATE_TYPE = null;

    public function getPayload(): array;
}

// 2. Base Abstract Event
abstract readonly class AbstractEvent implements DomainEventInterface
{
    // Override dengan narrowing (kovarian): nullable string dipersempit menjadi non-empty-string
    public const string AGGREGATE_TYPE = 'core_domain';

    public function __construct(
        public array $data,
        public int $occurredOn
    ) {}

    public function getPayload(): array
    {
        return $this->data;
    }
}

// 3. Concrete Event
final readonly class UserRegisteredEvent extends AbstractEvent
{
    // Spesifikasikan konstanta tipe untuk event ini
    public const int SCHEMA_VERSION = 2; // Valid: tetap bertipe int
    public const string AGGREGATE_TYPE = 'user'; // Valid: kompatibel dengan 'string'
}

// 4. Dispatcher yang memanfaatkan Dynamic Class Fetching
final class EventDispatcher
{
    /** @var array<string, list<callable>> */
    private array $listeners = [];

    public function registerListener(string $eventFqcn, callable $handler): void
    {
        $this->listeners[$eventFqcn][] = $handler;
    }

    public function dispatch(DomainEventInterface $event): void
    {
        // Dynamic Class Fetching (PHP 8.0+)
        // Mengambil FQCN langsung dari instance tanpa overhead get_class()
        $eventClass = $event::class;

        // Dynamic Constant Resolution dari objek langsung
        $schemaVersion = $event::SCHEMA_VERSION;
        $aggregate = $event::AGGREGATE_TYPE;

        echo sprintf(
            "[LOG] Dispatching event: %s (Aggregate: %s, Schema: v%d)\n",
            $eventClass,
            $aggregate,
            $schemaVersion
        );

        if (!isset($this->listeners[$eventClass])) {
            return;
        }

        foreach ($this->listeners[$eventClass] as $listener) {
            $listener($event);
        }
    }
}

// 5. Eksekusi Runtime
$dispatcher = new EventDispatcher();

// Registrasi listener menggunakan static class resolution
$dispatcher->registerListener(
    UserRegisteredEvent::class,
    static function (UserRegisteredEvent $e): void {
        echo "Handler invoked for payload: " . json_encode($e->getPayload()) . "\n";
    }
);

// Trigger Event
$event = new UserRegisteredEvent(
    data: ['userId' => 'usr_98a7sd', 'email' => 'tech@roadmap.sh'],
    occurredOn: time()
);

$dispatcher->dispatch($event);
```

#### Variasi Ekspresi Dinamis
Anda juga dapat menggunakan ekspresi arbitrer dalam fetch dinamis:

```php
function getActivePipeline(): object {
    return new class {
        public const string STAGE = 'BUILD';
    };
}

// Evaluasi ekspresi langsung diakhiri ::class atau akses konstanta dinamis
$className = (getActivePipeline())::class;
$stage = (getActivePipeline())::STAGE;
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Zend VM
1. **Dynamic Class Fetching (`$obj::class`)**:
   - Ketika PHP mengompilasi `get_class($obj)`, Zend Compiler menghasilkan instruksi `DO_FCALL` standar. VM harus mengalokasikan stack frame (`zend_execute_data`), memeriksa konteks scope pemanggil, lalu memanggil fungsi C level internal `zif_get_class`.
   - Sebaliknya, `$obj::class` dikompilasi menjadi opcode spesifik: **`ZEND_FETCH_CLASS_NAME`**.
   - Pada tingkat mesin Zend (C-level), instruksi ini langsung mengakses pointer internal `zend_class_entry` (`ce`) dari struktur `zval` objek yang bersangkutan (`Z_OBJ_P(op1)->ce->name`) dan langsung mengembalikan pointer `zend_string*` yang sudah di-intern (*interned string*). Tidak ada alokasi call stack baru.

2. **Typed Class Constants**:
   - Selama tahap kompilasi (*compilation phase*), konstanta kelas disimpan dalam tabel `zend_class_entry.constants_table`.
   - Informasi tipe disimpan dalam struct internal `zend_type` pada elemen `zend_class_constant`.
   - Validasi nilai konstanta terhadap tipenya dilakukan pada dua fase:
     - **Compile-Time**: Jika nilainya adalah skalar statis literal (misal `public const int X = 10;`), Zend Compiler langsung memverifikasi `zend_type`.
     - **Inheritance Phase (`zend_do_inheritance`)**: Saat inheritance di-link (bisa saat file di-include atau saat inheritance cache diisi di Opcache), mesin mengeksekusi `zend_verify_const_type`. Mesin membandingkan deklarasi konstanta kelas anak terhadap antarmuka atau kelas induknya.

#### Kompatibilitas Tipe & Varian Memori
Typed class constants mematuhi aturan **Kovariansi (Covariance)**. Kelas anak diizinkan mempersempit tipe dari induk:

| Tipe Induk | Tipe Anak yang Valid | Tipe Anak yang Tidak Valid |
| :--- | :--- | :--- |
| `mixed` | `string`, `int`, `array`, dll. | *None* |
| `string\|int` | `string` atau `int` | `string\|bool` |
| `object` | `DateTime` | `string` |
| `int` | `int` | `float`, `int\|string` |

Setiap konstanta yang melanggar kontrak menghasilkan `Fatal Error: Type of Child::CONST must be compatible with Parent::CONST` saat proses linking kelas, bukan saat nilai konstanta tersebut diakses.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `$instance::class` daripada `get_class($instance)`**: `$instance::class` selalu mengembalikan FQCN murni, lebih cepat karena eliminasi function-call overhead, dan konsisten secara leksikal dengan `SelfOrParent::class`.
- **Berikan tipe pada konstanta di Interface Publik**: Gunakan PHP 8.3 typed constants untuk mencegah *accidental type mutability* pada inheritance hierarki domain core.
- **Manfaatkan Union/Intersection Types pada Konstanta**: 
  ```php
  public const string|int IDENTIFIER = 1;
  ```

#### Don'ts
- **Hindari mengandalkan fallback string loose**: Jangan abaikan strictly typed constant dengan mengandalkan implicit coercion. 
  ```php
  // BURUK: Mengharapkan int tetapi string numerik diterima tanpa type guard
  class Storage { public const TIMEOUT = '3600'; } 

  // BENAR: Tegaskan di level tipe
  class Storage { public const int TIMEOUT = 3600; }
  ```
- **Jangan mengubah tipe konstanta secara sembarangan di kelas turunan**: Melanggar invariant/covariance menghasilkan fatal error instan saat kelas dimuat oleh Autoloader.

#### Edge Cases
1. **Fetch pada Non-Object**:
   Jika variabel bernilai `null` atau non-object, memanggil `$var::class` akan melempar `TypeError` fatal:
   ```php
   $user = null;
   $name = $user::class; // Fatal error: Cannot use "::class" on null
   ```
   *Mitigasi:* Selalu validasi nullability atau gunakan ternary/nullsafe pattern jika variabel berpotensi `null`.

2. **Perbedaan Evaluasi `class_alias`**:
   - `ClassName::class` di-resolve saat **compile-time** berdasarkan namespace use-statement lokal.
   - `$obj::class` di-resolve saat **runtime**. Jika menggunakan `class_alias()`, `$obj::class` akan mengembalikan nama kelas asli (*original class name*), bukan nama aliasnya.

3. **Const Type Modifiers dan Final Constants**:
   PHP 8.1 memperkenalkan konstanta `final`. Menggabungkan `final` dengan tipe di PHP 8.3:
   ```php
   final public const string VERSION = '1.0.0';
   ```
   Urutan modifier (`final`, `public`, `type`) bersifat fleksibel, tetapi meletakkan visibility lebih dahulu (`public final const string`) adalah standar konvensi PSR-12/PER.

### 5. Tantangan Eksplorasi Mandiri

1. **Refactoring Legacy Code**:
   Cari penggunaan `get_class()` dalam framework atau proyek Anda. Lakukan refactoring ke sintaks `$obj::class`. Periksa apakah ada perbedaan perilaku ketika fungsi tersebut menerima argumen non-objek dalam kondisi runtime edge-case.
2. **Kovariansi pada Domain Pattern**:
   Buat sebuah `PaymentGatewayInterface` yang mendefinisikan `public const array|string SUPPORTED_CURRENCIES`. Turunkan ke `StripeGateway` yang mempersempit tipe konstanta tersebut menjadi `public const array SUPPORTED_CURRENCIES`. Buktikan bahwa kelas anak valid saat *linking*, kemudian ubah tipenya menjadi `int` untuk melihat bagaimana Zend Engine menolak kompilasi inheritance.
3. **Analisis Opcodes**:
   Gunakan PHP CLI dengan ekstensi VLD (Vulcan Logic Dumper) atau via online opcode viewer (misalnya 3v4l.org):
   Bandingkan bytecode yang dihasilkan antara:
   - `echo get_class($a);`
   - `echo $a::class;`
   Identifikasi opcode spesifik dan perhatikan perbedaan konsumsi `ZEND_DO_FCALL` vs `ZEND_FETCH_CLASS_NAME`.
