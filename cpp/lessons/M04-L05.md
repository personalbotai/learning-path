## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

*Compile-time programming* dalam C++ modern adalah paradigma komputasi di mana logika eksekusi dipindahkan dari fase *runtime* ke fase *compilation*. Pendekatan historis menggunakan *Template Metaprogramming* (TMP) memanfaatkan *SFINAE* dan rekursi template yang sulit di-*debug*, memperlambat kompilasi, serta menghasilkan pesan error yang rumit. Untuk mengatasi batasan ini, komite C++ memperkenalkan kata kunci evaluasi konstanta secara bertahap:

*   **`constexpr` (Diperkenalkan pada C++11, disempurnakan di C++14/17/20)**: Menandakan bahwa suatu ekspresi, variabel, atau fungsi *dapat* dievaluasi pada saat kompilasi jika argumen yang diberikan bernilai konstan (*core constant expression*). Namun, jika dipanggil dengan variabel *runtime*, fungsi `constexpr` tetap dapat berjalan sebagai fungsi reguler pada fase runtime tanpa penolakan compiler.
*   **`consteval` (C++20 - *Immediate Functions*)**: Berbeda dengan `constexpr`, `consteval` adalah jaminan mutlak. Fungsi yang dideklarasikan sebagai `consteval` **harus** menghasilkan nilai konstan pada saat kompilasi. Jika dipanggil dalam konteks yang memerlukan evaluasi runtime, kompilator akan langsung memunculkan *compile-time error*.
*   **`constinit` (C++20)**: Memastikan bahwa variabel dengan *static* atau *thread-local storage duration* diinisialisasi pada saat kompilasi untuk mencegah *Static Initialization Order Fiasco*, tanpa memaksakan variabel tersebut menjadi `const` (nilainya tetap bisa dimutasi saat runtime).

```
        +--------------------------------------------------------+
        |                 Evaluasi Compiler                      |
        +--------------------------------------------------------+
                                    |
            Apakah argumen diketahui saat kompilasi?
                   /                                \
                 YES                                 NO
                 /                                    \
      [consteval] / [constexpr]                 [constexpr]
      Eksekusi di AST/Constexpr VM             Compile ke Assembly Reguler
      Hasil diinjeksi ke Binary                 Eksekusi di CPU Runtime
```

Alasan utama arsitektur ini diterapkan adalah prinsip *Zero-Cost Abstraction*: komputasi berat, validasi skema (seperti *compile-time regex* atau verifikasi *format string* pada `std::format`), dan *lookup table generation* diselesaikan di level compiler. Runtime hanya menerima hasil evaluasi akhir yang disematkan langsung ke dalam segmen memori *read-only* atau langsung di-*inline* ke dalam instruksi register.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengilustrasikan pembuatan *Compile-Time String Hash* (menggunakan algoritma FNV-1a) dan generator *Lookup Table* (LUT) trigonometri/matematika tanpa alokasi memori runtime.

```cpp
#include <iostream>
#include <array>
#include <string_view>
#include <cstdint>

// 1. FNV-1a Hash yang diwajibkan berjalan saat kompilasi via consteval
namespace Hash {
    constexpr uint64_t FNV_PRIME = 0x100000001b3ULL;
    constexpr uint64_t FNV_OFFSET_BASIS = 0xcbf29ce484222325ULL;

    consteval uint64_t fnv1a(std::string_view str) {
        uint64_t hash = FNV_OFFSET_BASIS;
        for (char c : str) {
            hash ^= static_cast<uint64_t>(c);
            hash *= FNV_PRIME;
        }
        return hash;
    }
}

// 2. Generator Lookup Table (LUT) menggunakan constexpr (C++20 std::array compile-time context)
template <size_t N>
struct FactorialTable {
    std::array<uint64_t, N> values{};

    constexpr FactorialTable() {
        values[0] = 1;
        for (size_t i = 1; i < N; ++i) {
            values[i] = values[i - 1] * i;
        }
    }
};

// Evaluasi tabel saat kompilasi
constexpr auto FACTORIALS = FactorialTable<10>();

// 3. constinit untuk mencegah Static Initialization Order Fiasco
constinit uint64_t g_system_salt = Hash::fnv1a("GLOBAL_APP_SALT_2024");

int main() {
    // A. Penggunaan consteval: Menghasilkan nilai literal utuh di binary
    // Label "user_admin" diubah menjadi 64-bit integer sebelum masuk linker
    constexpr uint64_t admin_hash = Hash::fnv1a("user_admin");
    std::cout << "Admin Hash (Compile-Time): " << admin_hash << '\n';

    // B. Pemanfaatan compile-time hash di dalam switch-case
    // C++ biasa tidak bisa switch pada const char*, tetapi bisa pada uint64_t hash!
    auto evaluate_command = [](uint64_t cmd_hash) {
        switch (cmd_hash) {
            case Hash::fnv1a("START"):
                std::cout << "Handling START\n";
                break;
            case Hash::fnv1a("STOP"):
                std::cout << "Handling STOP\n";
                break;
            default:
                std::cout << "Unknown command\n";
                break;
        }
    };

    evaluate_command(Hash::fnv1a("START"));

    // C. Mengakses precomputed LUT tanpa runtime overhead
    constexpr uint64_t five_factorial = FACTORIALS.values[5];
    std::cout << "5! = " << five_factorial << '\n';

    // D. constinit variabel dapat dimutasi saat runtime, namun diinisialisasi secara statis
    g_system_salt ^= 0xFAFAFAFA;
    std::cout << "Mutated Global Salt: " << g_system_salt << '\n';

    // Error Kasus Nyata (Uncomment untuk menguji error kompilasi):
    // std::string dynamic_str = "user_guest";
    // uint64_t fail = Hash::fnv1a(dynamic_str); // Error: dynamic_str bukan ekspresi konstan!

    return 0;
}
```

#### Komponen Kunci:
1.  **`Hash::fnv1a`**: Fungsi `consteval` menjamin bahwa *string literal* langsung diubah menjadi *integer* saat kompilasi. Mengeliminasi overhead runtime parsing string dalam percabangan (`switch-case`).
2.  **`FactorialTable`**: Konstruktor `constexpr` mengisi `std::array` pada compile-time. Seluruh kalkulasi loop dilakukan oleh internal compiler VM.
3.  **`constinit g_system_salt`**: Menjamin inisialisasi terjadi pada *static phase*, sehingga tidak terpengaruh urutan inisialisasi lintas *Translation Units* (TU).

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Compiler Architecture
Di balik layar, kompilator modern (seperti Clang dan GCC) menyematkan *internal bytecode interpreter* atau *Constant Expression Evaluator* (sering disebut *Constexpr VM*). 
*   Ketika kompilator mem-parsing Abstract Syntax Tree (AST) dan menemukan pemanggilan fungsi `consteval` atau `constexpr` dalam *constant context* (misal: template argument, array boundary, atau penugasan variabel `constexpr`), AST node tidak diteruskan ke *intermediate representation* (IR/LLVM) generator.
*   Interpreter internal compiler mengeksekusi instruksi AST tersebut secara virtual. Evaluator ini memiliki batasan ketat: tidak boleh mengakses memori sistem riil, tidak boleh melakukan dereferensi pointer tak terdefinisi (*UB - Undefined Behavior*), dan loop dibatasi oleh *step counter* (menghindari infinite loop saat kompilasi, misal flag `-fconstexpr-steps`).

#### Alokasi Memori & Binary Layout
*   Hasil dari evaluasi `constexpr` atau `consteval` yang berwujud konstanta global/lokal akan langsung ditempatkan pada segmen **`.rodata`** (Read-Only Data) dari file *Executable and Linkable Format* (ELF/PE), atau dilebur menjadi instruksi *immediate operand* pada assembly (misalnya: `mov rax, 0x5a3f...`).
*   Tidak ada *stack allocation* runtime, tidak ada *call frame instruction* (`push rbp`, `call`, `ret`), dan memori runtime bersih dari kalkulasi loop.
*   Khusus C++20 `constexpr virtual functions` dan `constexpr dynamic allocation` (`std::allocator`, `std::vector`, `std::string`): Alokasi memori heap dapat terjadi di dalam Compiler VM, namun memori tersebut harus sudah di-*deallocate* sebelum evaluasi compile-time selesai (*transient allocation*). Memori heap kompilasi tidak bisa lolos (*leak*) ke runtime executable.

#### Trade-offs
*   **Compile Time vs Runtime Performance**: Beban komputasi dialihkan ke CPU mesin developer/CI-CD. Kompilasi bisa melonjak signifikan jika *depth* rekursi atau iterasi kalkulasi sangat dalam.
*   **Code Bloat Potential**: Generasi data berukuran besar melalui LUT dapat memperbesar ukuran file biner (*bloat* pada disk dan memori cache L1/L2 data miss saat dieksekusi).

### 4. Best Practices & Common Pitfalls

#### Do's
*   Gunakan **`consteval`** pada fungsi utilitas murni yang dirancang khusus untuk memvalidasi literal sebelum runtime (misalnya validasi *format string*, parsing skema JSON pada literal, penghitungan *compile-time hash*).
*   Gunakan **`std::is_constant_evaluated()`** (C++20: lebih disukai blok `if consteval`) pada fungsi `constexpr` jika Anda ingin mengoptimasi jalur eksekusi: gunakan algoritma ramah compiler saat compile-time, dan gunakan intrinsik CPU/SIMD saat runtime.
*   Terapkan **`constexpr`** pada konstruktor objek domain yang bersifat *immutable* untuk memaksimalkan *constant folding*.

#### Don'ts
*   JANGAN menggunakan `consteval` jika fungsi tersebut diharapkan fleksibel untuk menerima argumen variabel biasa saat runtime. Gunakan `constexpr` sebagai gantinya.
*   JANGAN menaruh I/O, pembacaan environment, atau panggilan sistem ke dalam fungsi `constexpr`/`consteval`; hal ini memicu error kompilasi karena compiler berjalan dalam *sandboxed environment*.
*   JANGAN mengabaikan *compile-time overhead*. Pembuatan Lookup Table berukuran gigabyte via `constexpr` akan membekukan compiler dan menghabiskan RAM mesin kompilasi (*Out of Memory*).

#### Edge Cases
*   **Undefined Behavior (UB)**: Di runtime, UB seperti *out-of-bounds array access* atau pembagian dengan nol mungkin tidak langsung terdeteksi (silent crash/corrupted data). Namun pada compile-time (`constexpr`/`consteval`), UB **selalu berstatus fatal** dan menyebabkan kompilasi gagal secara otomatis. Compiler bertindak sebagai verifikator kepatuhan memori yang sangat ketat.
*   **`constinit` tidak menjamin *constness***: `constinit` menjamin *compile-time initialization*, tetapi tidak melarang modifikasi saat runtime. Jika menginginkan imutabilitas mutlak, kombinasikan menjadi `constexpr` atau `constinit const`.

### 5. Tantangan Eksplorasi Mandiri

1.  **Compile-Time IP Address Validator**:
    Buatlah fungsi `consteval uint32_t parse_ipv4(std::string_view ip)` yang mem-parsing string literal IPv4 (misal `"192.168.1.1"`) menjadi representasi integer 32-bit. Fungsi harus memicu *compile-time error* (gunakan `throw` di dalam fungsi jika format string tidak valid atau terdapat oktet bernilai $> 255$).
2.  **Dual-path Execution Comparison**:
    Implementasikan fungsi `constexpr double power(double base, int exp)` yang menggunakan *loop* sederhana jika dievaluasi pada compile-time (`if consteval`), tetapi memanggil `std::pow` berakselerasi CPU jika dievaluasi pada runtime. Ujilah kedua cabang pemanggilan dan analisis kode assembly yang dihasilkan menggunakan Compiler Explorer (godbolt.org).
