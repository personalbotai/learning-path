### 1. Konsep & Arsitektur Mendalam

Class Template adalah cetak biru (*blueprint*) berbasis tipe yang diinstansiasi oleh compiler untuk menghasilkan kelas konkret pada waktu kompilasi (*compile-time*). Fitur ini merupakan fondasi dari paradigma *generic programming* di C++, yang memungkinkan penulisan kode tipe-independen tanpa mengorbankan performa *runtime* (zero-cost abstraction) jika dibandingkan dengan polimorfisme dinamis berbasis *virtual method table* (vtable).

```
+-------------------------------------------------------------+
|               Template Definition (.hpp)                    |
|          template <typename T, std::size_t N>               |
|                   class StaticArray;                        |
+-------------------------------------------------------------+
                               |
               +---------------+---------------+
               | Kompilasi: Two-Phase Lookup   |
               +---------------+---------------+
                               |
        +----------------------+----------------------+
        | Substitusi Tipe & Monomorphization          |
        v                                             v
+-----------------------+                 +-----------------------+
|  StaticArray<int, 4>  |                 | StaticArray<double, 2>|
| - Layout: 4 * 4B = 16B|                 | - Layout: 2 * 8B = 16B|
| - Mangled Symbol A    |                 | - Mangled Symbol B    |
+-----------------------+                 +-----------------------+
```

#### Mekanisme Instansiasi
Class template tidak menghasilkan kode mesin langsung saat didefinisikan. Compiler hanya memvalidasi sintaks dasar. Kode mesin baru digenerasi ketika terjadi **instansiasi**:
1. **Implicit Instantiation**: Terjadi otomatis saat objek dari tipe template dideklarasikan, dipanggil melalui *pointer/reference* (hanya jika membutuhkan *complete type*), atau ketika anggotanya diakses. Anggota fungsi (*member functions*) dari class template hanya diinstansiasi jika benar-benar dipanggil (*lazy instantiation*).
2. **Explicit Instantiation**: Pengembang secara eksplisit memerintahkan compiler untuk menginstansiasi kelas atau metode tertentu dalam satu Translation Unit (TU). Tujuannya adalah membatasi *code bloat* atau mempercepat waktu kompilasi.

#### Two-Phase Lookup
Proses parsing template berjalan dalam dua fase:
- **Fase 1 (Parsing Template Definition)**: Compiler memeriksa sintaksis yang tidak bergantung pada parameter template (*non-dependent names*). Tipe yang salah eja atau tanda baca yang hilang akan memicu error di sini.
- **Fase 2 (Instantiation Phase)**: Compiler memeriksa nama-nama yang bergantung pada parameter template (*dependent names*). Pada fase ini, tipe substitusi dipetakan, ekspresi divalidasi, dan kode assembly/biner konkret digenerasi.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern dari struktur data `StaticVector`—sebuah vektor dengan alokasi memori *inline* tetap (tanpa alokasi heap), memanfaatkan *Class Templates*, *Non-Type Template Parameters (NTTP)*, dan *C++20 Concepts*.

```cpp
#include <iostream>
#include <concepts>
#include <cstddef>
#include <new>
#include <utility>
#include <stdexcept>

// Concept untuk memastikan tipe aman dimanipulasi dalam raw storage
template <typename T>
concept TriviallyOrMoveConstructible = std::destructible<T> && 
    (std::is_trivially_copyable_v<T> || std::move_constructible<T>);

// Class Template dengan Type Parameter dan Non-Type Template Parameter (Capacity)
template <TriviallyOrMoveConstructible T, std::size_t Capacity>
class StaticVector {
    static_assert(Capacity > 0, "Kapasitas StaticVector harus lebih besar dari 0.");

public:
    using value_type      = T;
    using size_type       = std::size_t;
    using reference       = T&;
    using const_reference = const T&;

    constexpr StaticVector() noexcept : m_size(0) {}

    // Destructor: Menjalankan manual destruction pada elemen yang aktif
    ~StaticVector() {
        clear();
    }

    // Copy Constructor
    StaticVector(const StaticVector& other) {
        for (size_type i = 0; i < other.m_size; ++i) {
            push_back(other[i]);
        }
    }

    // Move Constructor
    StaticVector(StaticVector&& other) noexcept(std::is_nothrow_move_constructible_v<T>) {
        for (size_type i = 0; i < other.m_size; ++i) {
            emplace_back(std::move(other[i]));
        }
        other.clear();
    }

    template <typename... Args>
    reference emplace_back(Args&&... args) {
        if (m_size >= Capacity) {
            throw std::overflow_error("StaticVector: Melebihi kapasitas maksimum.");
        }
        
        // Penempatan memori in-place via Placement New ke buffer mentah
        T* element_addr = reinterpret_cast<T*>(&m_storage[m_size * sizeof(T)]);
        ::new (static_cast<void*>(element_addr)) T(std::forward<Args>(args)...);
        
        ++m_size;
        return *element_addr;
    }

    void push_back(const T& value) {
        emplace_back(value);
    }

    void push_back(T&& value) {
        emplace_back(std::move(value));
    }

    void clear() noexcept {
        for (size_type i = 0; i < m_size; ++i) {
            data()[i].~T();
        }
        m_size = 0;
    }

    [[nodiscard]] constexpr size_type size() const noexcept { return m_size; }
    [[nodiscard]] constexpr size_type capacity() const noexcept { return Capacity; }

    reference operator[](size_type index) noexcept {
        return data()[index];
    }

    const_reference operator[](size_type index) const noexcept {
        return data()[index];
    }

    T* data() noexcept {
        return reinterpret_cast<T*>(m_storage);
    }

    const T* data() const noexcept {
        return reinterpret_cast<const T*>(m_storage);
    }

private:
    // Alokasi memori inline yang diselaraskan (aligned) dengan representasi tipe T
    alignas(alignof(T)) std::byte m_storage[sizeof(T) * Capacity];
    size_type m_size{0};
};

// -------------------------------------------------------------
// Demonstrasi Penggunaan
// -------------------------------------------------------------
struct SensorData {
    int id;
    double reading;

    SensorData(int i, double r) : id(i), reading(r) {
        std::cout << "SensorData Construct [" << id << "]\n";
    }
    ~SensorData() {
        std::cout << "SensorData Destruct [" << id << "]\n";
    }
};

int main() {
    // Instansiasi tipe: StaticVector<SensorData, 3>
    StaticVector<SensorData, 3> sensor_buffer;

    sensor_buffer.emplace_back(101, 24.5);
    sensor_buffer.emplace_back(102, 30.1);

    std::cout << "Ukuran buffer: " << sensor_buffer.size() << "/" << sensor_buffer.capacity() << '\n';

    for (std::size_t i = 0; i < sensor_buffer.size(); ++i) {
        std::cout << "Sensor: " << sensor_buffer[i].id 
                  << " -> Nilai: " << sensor_buffer[i].reading << '\n';
    }

    // Instansiasi berbeda: Menghasilkan kelas biner baru StaticVector<int, 5>
    StaticVector<int, 5> int_buffer;
    int_buffer.push_back(42);

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Monomorphization
C++ mengadopsi pendekatan **Monomorphization**. Jika Anda menggunakan `StaticVector<int, 10>` dan `StaticVector<double, 10>`, compiler akan memancarkan (*emit*) **dua struktur biner dan set instruksi assembly yang benar-benar terpisah**.
- Simbol fungsi akan mengalami *name mangling* khusus, misalnya `_ZN12StaticVectorIiLm10EE12emplace_back...` untuk `int` dan `_ZN12StaticVectorIdLm10EE12emplace_back...` untuk `double`.
- Tidak ada *indirection overhead* runtime (seperti pointer dereference atau boxing/unboxing seperti pada Java/C# Generics). Komputasi offset memori dieksekusi secara instan menggunakan instruksi *direct displacement*.

#### Linker & One Definition Rule (ODR)
Ketika class template disertakan di beberapa Translation Unit (`.cpp`), metode yang sama dari instansiasi yang identik (misal `StaticVector<int, 5>::push_back`) dapat dikompilasi berulang kali ke dalam masing-masing *object file* (`.o`).
- Compiler menandai fungsi-fungsi instansiasi ini ke dalam seksi memori khusus ELF/PE yang disebut **COMDAT** (atau *linkonce*).
- Pada fase *linking*, linker mendeteksi duplikasi simbol COMDAT tersebut dan membuang salinan yang redundan (*folding*), menyisakan tepat satu instansiasi kode biner di *executable* final untuk memenuhi ODR.

#### Memory Alignment dan Layout
Class template menghitung alignment memori saat fase substitusi. Variabel:
```cpp
alignas(alignof(T)) std::byte m_storage[sizeof(T) * Capacity];
```
Menjamin bahwa kompilasi memetakan alamat memori array byte internal sesuai dengan kebutuhan spesifik tipe substitusi `T` (misalnya 4-byte untuk `int`, 8-byte untuk `double`, atau 64-byte untuk tipe AVX-512 SIMD).

#### Trade-offs
- **Kelebihan**: Kinerja setara dengan kode yang ditulis tangan (*hardcoded*), inlining sangat optimal, tidak ada alokasi heap dinamis.
- **Kekurangan (Template Bloat)**: Ukuran biner (*binary size*) membengkak jika template diinstansiasi dengan banyak kombinasi tipe dan nilai NTTP. Waktu kompilasi meningkat tajam seiring kompleksitas template.

### 4. Best Practices & Common Pitfalls

#### Do's
1. **Gunakan C++20 Concepts atau `static_assert`**: Lindungi template Anda dari substitusi tipe yang tidak kompatibel agar error kompilasi langsung menunjuk ke sumber masalah, bukan kegagalan mendalam di internal fungsi template.
2. **Pisahkan Deklarasi Menggunakan Explicit Instantiation jika Binary Bloat Kritis**:
   Jika Anda tahu bahwa `MyTemplate<T>` hanya akan digunakan untuk `int`, `float`, dan `double`, deklarasikan template di header dan instansiasi secara eksplisit di file `.cpp`:
   ```cpp
   // Dalam file MyTemplate.cpp
   template class MyTemplate<int>;
   template class MyTemplate<double>;
   ```
   Lalu gunakan `extern template class MyTemplate<int>;` di header lain untuk menekan durasi kompilasi.
3. **Manfaatkan *Dependent Types* dengan Tepat**: Gunakan *keyword* `typename` ketika merujuk ke tipe bersarang (*nested type*) di dalam parameter dependent:
   ```cpp
   template <typename T>
   void process() {
       typename T::iterator it; // 'typename' wajib karena 'iterator' adalah dependent name
   }
   ```

#### Don'ts
1. **Jangan Pisahkan Definisi Template ke File `.cpp` Biasa**:
   Template bukan kode konkret. Menempatkan deklarasi di `Vector.hpp` dan implementasi metode di `Vector.cpp` tanpa *explicit instantiation* akan menghasilkan **Linker Error: Unresolved External Symbol** pada TU lain yang menggunakannya.
2. **Jangan Mengasumsikan Semua Anggota Diinstansiasi**:
   Jangan bergantung pada pengecekan compiler terhadap fungsi yang tidak pernah dipanggil. Jika sebuah fungsi anggota memiliki bug sintaks dependen, bug tersebut tidak akan terdeteksi hingga ada kode yang memanggil fungsi tersebut (*lazy instantiation*).

#### Edge Cases
- **Non-Type Template Arguments (Floating Point)**: Sebelum C++20, tipe float/double tidak valid sebagai NTTP. Mulai C++20, tipe *structural class* dan literal floating-point diperbolehkan.
- **Circular Template Instantiation**: Template yang secara rekursif menginstansiasi dirinya sendiri tanpa kondisi basis (*base case*) yang jelas akan menghabiskan batas rekursi compiler (`-ftemplate-depth`).

### 5. Tantangan Eksplorasi Mandiri

1. **Inspeksi Binary via CLI**:
   Kompilasi kode `StaticVector` di atas menggunakan flag `-c` (hanya sampai tahap kompilasi/assembly):
   ```bash
   g++ -std=c++20 -c main.cpp -o main.o
   nm --demangle main.o | grep StaticVector
   ```
   Analisis simbol yang dihasilkan. Identifikasi bagaimana nama kelas dan fungsinya diubah (*mangled*) berdasarkan parameter template yang Anda berikan.

2. **Template Rekursif & Partial Specialization**:
   Buat class template `TuplePrinter<T, Args...>` yang mencetak elemen tuple ke konsol dengan memanfaatkan *parameter pack* dan teknik rekursi compile-time. Implementasikan *base specialization* untuk menghentikan rekursi saat argumen habis.

3. **Optimasi Thin Template Idiom**:
   Rancang sebuah class template penampung pointer `PointerBuffer<T*>`. Untuk mencegah *code bloat*, buat kelas dasar non-template internal berbasis `void*` yang menangani manipulasi memori mentah, lalu turunkan `PointerBuffer<T*>` dari kelas non-template tersebut dengan melakukan *type-safe casting* pada metode pembungkusnya (*wrapper*).
