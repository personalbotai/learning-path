## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sejak C++20, C++ secara resmi mengadopsi mekanisme **Stackless Coroutines**. Berbeda dengan *stackful coroutines* (seperti Boost.Fiber atau implementasi green thread di Go) yang mengalokasikan call stack independen lengkap per coroutine, *stackless coroutine* tidak memiliki runtime call stack sendiri. Eksekusinya dijalankan langsung di atas thread pemanggil, dan saat disuspensi (*suspended*), seluruh *state* eksekusi (variabel lokal, register, titik suspensi/IP) dipaketkan ke dalam sebuah struktur data heap/frame bernama **Coroutine Frame**.

C++20 tidak menyediakan coroutine siap pakai tingkat tinggi di standard library secara langsung (seperti `std::generator` baru distandarisasi di C++23). C++20 justru menyediakan **primitif tingkat rendah** yang mengharuskan kita merakit arsitektur coroutine sendiri melalui sekumpulan antarmuka (*customization points*) yang dikendalikan oleh compiler.

Sebuah fungsi otomatis dianggap sebagai coroutine oleh compiler jika di dalamnya memuat minimal salah satu dari tiga kata kunci:
1. `co_await`: Menghentikan eksekusi coroutine sementara sampai sebuah operasi selesai (*awaitable*).
2. `co_yield`: Menghentikan eksekusi dan mengembalikan nilai ke pemanggil (*generator pattern*).
3. `co_return`: Menyelesaikan coroutine dan opsional mengembalikan nilai final.

Arsitektur coroutine C++20 terdiri dari empat pilar utama:
1. **Promise Object (`promise_type`)**: Mengontrol perilaku internal coroutine dari sisi pembuat. Bertanggung jawab atas inisialisasi, suspensi awal/akhir, menangani pengecualian, dan memproduksi objek kembalian.
2. **Coroutine Handle (`std::coroutine_handle<P>`)**: Non-owning pointer/handle yang digunakan dari luar coroutine untuk melanjutkan (*resume*) atau menghancurkan (*destroy*) frame coroutine.
3. **Coroutine Return Object**: Objek RAII pembungkus coroutine handle yang dikembalikan ke pemanggil saat coroutine pertama kali dipanggil.
4. **Awaiter Interface**: Protokol yang menentukan apakah coroutine harus ditangguhkan dan bagaimana proses penangguhannya via metode `await_ready()`, `await_suspend()`, dan `await_resume()`.

```
Caller Thread                Compiler State Machine             Coroutine Frame (Heap/HALO)
     |                                  |                                   |
     |--- Memanggil Coroutine() ------->|                                   |
     |                                  |--- Alokasi Frame ---------------->| [Simpan state/args]
     |                                  |--- Instansiasi promise_type ----->|
     |                                  |<-- get_return_object() -----------|
     |<-- Return Task/Generator Object -|                                   |
     |                                  |--- co_await initial_suspend() --->|
     |                                  |    (Suspend / Resume?)            |
```

### 2. Implementasi & Contoh Kasus Nyata

Di bawah ini adalah implementasi coroutine jenis **Generator** sederhana dan idiomatik dari nol tanpa dependensi eksternal:

```cpp
#include <iostream>
#include <coroutine>
#include <exception>
#include <utility>

template <typename T>
class Generator {
public:
    // 1. Definisikan promise_type yang diwajibkan compiler
    struct promise_type {
        const T* current_value{nullptr};
        std::exception_ptr exception{nullptr};

        // Membentuk return object (Generator) dari promise
        Generator get_return_object() noexcept {
            return Generator{std::coroutine_handle<promise_type>::from_promise(*this)};
        }

        // Suspensi saat pertama kali coroutine dipanggil (Lazy evaluation)
        std::suspend_always initial_suspend() noexcept { return {}; }

        // Suspensi di akhir siklus hidup untuk membiarkan RAII Generator menghancurkan frame
        std::suspend_always final_suspend() noexcept { return {}; }

        // Handler untuk 'co_yield value'
        std::suspend_always yield_value(const T& value) noexcept {
            current_value = std::addressof(value);
            return {};
        }

        // Handler untuk 'co_return'
        void return_void() noexcept {}

        // Menangkap exception tak tertangani di dalam coroutine
        void unhandled_exception() noexcept {
            exception = std::current_exception();
        }
    };

    using Handle = std::coroutine_handle<promise_type>;

    // 2. Lifecycle Management (RAII)
    explicit Generator(Handle handle) noexcept : coroutine_handle_(handle) {}

    ~Generator() {
        if (coroutine_handle_) {
            coroutine_handle_.destroy();
        }
    }

    // Move-only semantics: cegah double-free pada frame coroutine
    Generator(const Generator&) = delete;
    Generator& operator=(const Generator&) = delete;

    Generator(Generator&& other) noexcept : coroutine_handle_(std::exchange(other.coroutine_handle_, nullptr)) {}
    
    Generator& operator=(Generator&& other) noexcept {
        if (this != &other) {
            if (coroutine_handle_) {
                coroutine_handle_.destroy();
            }
            coroutine_handle_ = std::exchange(other.coroutine_handle_, nullptr);
        }
        return *this;
    }

    // 3. API Konsumsi Data
    bool next() {
        if (!coroutine_handle_ || coroutine_handle_.done()) {
            return false;
        }

        coroutine_handle_.resume();

        if (coroutine_handle_.promise().exception) {
            std::rethrow_exception(coroutine_handle_.promise().exception);
        }

        return !coroutine_handle_.done();
    }

    const T& value() const {
        return *(coroutine_handle_.promise().current_value);
    }

private:
    Handle coroutine_handle_;
};

// Penggunaan Generator
Generator<uint64_t> fibonacci_sequence(uint64_t limit) {
    uint64_t a = 0;
    uint64_t b = 1;
    while (a <= limit) {
        co_yield a; // Eksekusi berhenti di sini, transfer kontrol ke pemanggil
        auto next = a + b;
        a = b;
        b = next;
    }
}

int main() {
    auto fib = fibonacci_sequence(50);
    while (fib.next()) {
        std::cout << fib.value() << " ";
    }
    std::cout << "\n";
    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (State Machine Transformation)
Ketika compiler menemukan fungsi coroutine, ia membongkar *body* fungsi menjadi *state machine* berbasis switch-case tersembunyi.
Setiap titik `co_await` atau `co_yield` menjadi label suspensi terpisah:
- Variabel lokal diekstrak keluar dari stack dan dimasukkan ke dalam layout memori coroutine frame.
- Nilai titik suspensi (*resume index*) diperbarui sebelum eksekusi melompat kembali ke pemanggil.
- Pemanggilan `handle.resume()` secara internal melompat langsung (*indirect jump*) ke alamat instruksi tepat setelah suspensi terakhir berdasarkan *resume index* tersebut.

#### Alokasi Memori / Resource
Coroutine Frame secara default dialokasikan via `operator new` dinamis di heap. Frame ini menampung:
1. Instansi `promise_type`.
2. Salinan parameter fungsi coroutine (diteruskan via *by-value* atau referensi).
3. Variabel lokal yang masa hidupnya melintasi batas `co_await`/`co_yield`.
4. State internal compiler (function pointers untuk resume/destroy, suspend index).

**HALO (Heap Allocation Elision Optimization)**:
Jika compiler (seperti Clang atau GCC) melalui optimasi inline mendeteksi bahwa masa hidup coroutine frame terkurung seluruhnya di dalam scope fungsi pemanggil (seperti pada generator lokal), alokasi heap akan dielidasi (*elided*) dan Coroutine Frame dialokasikan langsung pada stack frame pemanggil.

#### Trade-offs
- **Keuntungan**: Overhead memori sangat kecil per coroutine (~beberapa puluh byte) dibandingkan thread OS atau stackful fiber (biasanya minimum 4KB - 2MB per stack). Tidak ada *kernel context switch overhead*.
- **Kerugian**: Debugging call stack menjadi rumit karena stack trace terputus saat fungsi disuspensi. Optimasi compiler sangat agresif, kegagalan HALO dapat menyebabkan *hidden heap allocations* pada *hot path*.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Pola RAII**: Bungkus `std::coroutine_handle` dalam *move-only class* yang otomatis memanggil `.destroy()` pada destruktor jika handle masih valid.
- **Kembalikan `std::suspend_always` pada `final_suspend`**: Praktik ini mencegah coroutine menghancurkan dirinya sendiri saat selesai jika frame masih diakses oleh wrapper class untuk mengambil nilai akhir atau menangani exception.
- **Passing parameter dengan nilai (by-value)** jika coroutine bersifat asinkron atau masa hidupnya melampaui scope pemanggil.

#### Don'ts
- **Jangan pass referensi/pointer sementara (temporary reference)** ke parameter coroutine. Objek temporary milik pemanggil bisa terdestruksi saat suspensi pertama, menyebabkan dangling reference di dalam coroutine frame.
```cpp
// SANGAT BERBAHAYA: Dangling reference
Generator<int> bad_coroutine(const std::string& str) { 
    co_yield str.length(); // Jika str adalah temporary, memory UB terjadi di resume berikutnya!
}
```
- **Jangan memanggil `.resume()` pada coroutine yang sudah `.done()`**: Tindakan ini menghasilkan **Undefined Behavior (UB)**.
- **Jangan biarkan exception keluar dari `final_suspend`**: Standar menetapkan bahwa `final_suspend` harus `noexcept`. Jika melempar exception, program akan memanggil `std::terminate`.

#### Edge Cases
- **Self-destroying coroutines**: Untuk arsitektur *fire-and-forget task*, coroutine dapat memanggil `handle.destroy()` di dalam `final_suspend` atau via callback kustom, namun pastikan tidak ada handle lain yang mengakses frame setelah itu.

### 5. Tantangan Eksplorasi Mandiri

1. **Rancang Custom Awaiter**: Buat sebuah struct `SleepAwaiter` yang mengimplementasikan `await_ready()`, `await_suspend(std::coroutine_handle<>)`, dan `await_resume()`, yang menggunakan thread pool atau timer OS (`std::jthread` dan `sleep_for`) untuk menunda eksekusi coroutine selama interval waktu tertentu tanpa memblokir thread utama.
2. **Implementasikan Coroutine Task Sederhana**: Ubah implementasi `Generator` di atas menjadi `Task<T>` untuk operasi asinkron yang dieksekusi secara *eager* atau *lazy*, di mana nilai baliknya dikembalikan via `co_return value`, dan hasilnya dapat diambil via metode `.get()` yang memblokir hingga operasi selesai.
