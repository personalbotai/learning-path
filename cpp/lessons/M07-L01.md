## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam arsitektur *Standard Template Library* (STL) C++, algoritma dan struktur data (kontainer) sengaja dirancang terpisah secara ortogonal. Masalah fundamental yang diselesaikan oleh arsitektur ini adalah ledakan kombinatorial ($O(N \times M)$): jika kita memiliki $N$ kontainer dan $M$ algoritma, mengimplementasikan algoritma secara spesifik di dalam setiap kelas kontainer akan membutuhkan $N \times M$ implementasi. 

STL menyelesaikan persoalan ini menggunakan abstraksi **Iterator** sebagai perantara (jembatan), mereduksi kompleksitas implementasi menjadi $O(N + M)$. Algoritma ditulis sebagai fungsi generik (*function template*) yang hanya bergantung pada properti iterator, bukan tipe fisik kontainer.

```
+--------------------+        +--------------------+
|     Containers     |        |     Algorithms     |
| (vector, list, ..) |        | (sort, find, ..)   |
+---------+----------+        +---------+----------+
          |                             |
          +------> [  Iterators  ] <----+
                   (Abstraksi Memori)
```

#### Taksonomi Iterator (C++98 hingga C++20)

Hingga standar C++17, relasi kemampuan iterator diekspresikan melalui penanda tag hirarkis (*tag dispatching* via `std::iterator_traits`). Pada C++20, taksonomi ini diformalkan menggunakan *Concepts*:

1. **Input Iterator (`std::input_iterator`)**: Pembacaan sekuensial satu arah, nilai hanya dapat dibaca satu kali per posisi (*single-pass*), contoh: `std::istream_iterator`.
2. **Output Iterator (`std::output_iterator`)**: Penulisan sekuensial satu arah, nilai hanya dapat ditulis satu kali per posisi (*single-pass*), contoh: `std::ostream_iterator`, `std::back_insert_iterator`.
3. **Forward Iterator (`std::forward_iterator`)**: Pembacaan dan/atau penulisan multi-pass sekuensial ke arah depan, contoh: iterator pada `std::forward_list`.
4. **Bidirectional Iterator (`std::bidirectional_iterator`)**: Memiliki kemampuan *Forward Iterator* ditambah operasi decrement (`--`), contoh: iterator pada `std::list`, `std::set`, `std::map`.
5. **Random Access Iterator (`std::random_access_iterator`)**: Mendukung pengalamatan instan dengan kompleksitas waktu konstan $O(1)$ (`+`, `-`, `+=`, `-=`, `[]`), contoh: iterator pada `std::deque`.
6. **Contiguous Iterator (`std::contiguous_iterator`, C++20)**: Menjamin bahwa elemen yang ditunjuk secara logis berdekatan juga terletak bersebelahan secara fisik di memori riil (`*(it + n)` ekuivalen dengan `*(&*it + n)`), contoh: iterator pada `std::vector`, `std::array`, `std::string`, atau *raw pointer* (`T*`).

#### Kategori Algoritma Standar (`<algorithm>`, `<numeric>`)
Algoritma STL dibagi menjadi beberapa kelompok fungsionalitas:
- **Non-modifying sequence operations**: `std::find`, `std::count`, `std::all_of`, `std::search`.
- **Modifying sequence operations**: `std::transform`, `std::copy`, `std::replace`, `std::remove_if`.
- **Sorting & Partitioning**: `std::sort`, `std::stable_sort`, `std::partition`, `std::nth_element`.
- **Binary Search Operations**: `std::lower_bound`, `std::upper_bound`, `std::binary_search`.
- **Numeric reductions**: `std::accumulate` (C++98), `std::reduce`, `std::transform_reduce` (C++17).

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengilustrasikan pemrosesan pipeline data transaksi order di bursa/fintech: pemfilteran data, transformasi entitas, kalkulasi total numerik menggunakan algoritma paralel modern, serta implementasi *custom output iterator*.

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
#include <numeric>
#include <execution>
#include <iomanip>

struct Order {
    uint64_t id;
    std::string symbol;
    double price;
    uint32_t quantity;
    bool is_filled;

    [[nodiscard]] double get_notional() const noexcept {
        return price * quantity;
    }
};

int main() {
    std::vector<Order> order_book = {
        {101, "AAPL", 175.50, 100, true},
        {102, "GOOGL", 140.25, 50, false},
        {103, "MSFT", 420.10, 200, true},
        {104, "NVDA", 880.00, 15, true},
        {105, "AAPL", 176.00, 300, false},
        {106, "TSLA", 170.80, 80, true}
    };

    // 1. In-place Partitioning: Pisahkan order yang sudah "filled" ke depan O(N)
    // std::partition mengembalikan iterator ke partisi kedua
    auto unfulfilled_bound = std::partition(
        order_book.begin(), 
        order_book.end(), 
        [](const Order& o) { return o.is_filled; }
    );

    // 2. Sorting pada sub-range: Urutkan hanya order yang filled berdasarkan notional value secara descending
    std::sort(
        order_book.begin(), 
        unfulfilled_bound, 
        [](const Order& a, const Order& b) {
            return a.get_notional() > b.get_notional();
        }
    );

    std::cout << "--- Top Filled Orders ---\n";
    std::for_each(order_book.begin(), unfulfilled_bound, [](const Order& o) {
        std::cout << "Order ID: " << o.id 
                  << " | " << std::left << std::setw(5) << o.symbol 
                  << " | Total: $" << std::fixed << std::setprecision(2) << o.get_notional() 
                  << '\n';
    });

    // 3. Binary Search Operation (O(log N)): Menggunakan lower_bound
    // Perhatikan: Range harus diurutkan dengan predikat yang sama sebelum dibinary search!
    double threshold = 50000.0;
    auto high_value_end = std::lower_bound(
        order_book.begin(), 
        unfulfilled_bound, 
        threshold, 
        [](const Order& o, double val) {
            return o.get_notional() > val; // descending order logic
        }
    );

    size_t count_high_value = std::distance(order_book.begin(), high_value_end);
    std::cout << "\nJumlah order filled bernilai > $" << threshold << " : " << count_high_value << "\n";

    // 4. Parallel Reduction (C++17 Execution Policies): std::reduce
    // Hitung total likuiditas seluruh order menggunakan vektor baru yang diekstrak
    std::vector<double> notionals;
    notionals.reserve(order_book.size());

    // std::transform untuk mentranslasikan struct menjadi kumpulan double
    std::transform(
        order_book.begin(), 
        order_book.end(), 
        std::back_inserter(notionals),
        [](const Order& o) { return o.get_notional(); }
    );

    // std::reduce dengan parallel execution policy (std::execution::par)
    // Menghindari bottleneck sequential loop accumulation
    double total_market_volume = std::reduce(
        std::execution::par,
        notionals.begin(), 
        notionals.end(), 
        0.0, 
        std::plus<double>{}
    );

    std::cout << "Total Market Volume (All Orders): $" << total_market_volume << "\n";

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Tag Dispatching vs Concepts
Sebelum C++20, fungsi seperti `std::advance` memilih implementasi menggunakan *Tag Dispatching* lewat `std::iterator_traits`:
```cpp
template <typename InputIt, typename Distance>
void advance_impl(InputIt& it, Distance n, std::input_iterator_tag) {
    while (n--) ++it; // O(N) untuk linked list
}

template <typename RandomIt, typename Distance>
void advance_impl(RandomIt& it, Distance n, std::random_access_iterator_tag) {
    it += n;          // O(1) untuk array/vector (langsung manipulasi pointer)
}
```
Pada tahap kompilasi, compiler menginspeksi jenis *iterator tag*. Jika tipe iterator adalah `std::random_access_iterator_tag`, cabang `it += n` dipilih dan di-*inline* secara langsung tanpa overhead runtime branch (`if/else`). Di C++20, teknik ini digantikan secara lebih elegan via `requires std::random_access_iterator<It>`.

#### Compiler Optimization & Vectorization (SIMD)
Ketika kontainer memiliki *contiguous iterator* (seperti `std::vector`), pointer memori fisik bersifat contiguous (`T*`). Saat menjalankan algoritma seperti `std::find`, `std::count`, atau `std::transform`:
1. **Loop Unrolling & Vectorization**: Compiler modern (GCC/Clang/MSVC) membedah loop menjadi instruksi register SIMD (AVX2/AVX-512).
2. **Penyusutan Memori**: Komparasi atau kalkulasi nilai dapat dieksekusi 4 hingga 16 elemen per siklus CPU secara serentak.
3. Sebaliknya, pada kontainer non-kontigu (`std::list`, `std::map`), iterator dereferencing memaksa CPU mengeksekusi pointer chasing (`node = node->next`), memicu serangkaian *cache misses* (L1/L2/L3 cache misses) di level memori keras.

#### Eksekusi Paralel (C++17 Parallel Algorithms)
Algoritma seperti `std::reduce(std::execution::par, ...)` membagi rentang iterator menjadi blok-blok chunk secara otomatis (*work-stealing thread pool*, biasanya ditenagai Intel TBB atau OpenMP di balik layar). Jika digunakan bersama kontainer acak (*Random Access*), pembagian partisi rentang bernilai $O(1)$. Jika dipaksakan pada Forward Iterator, pembagian partisi berbiaya linear $O(N)$ dan menurunkan performa threading drastis.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Algoritma Anggota Spesifik Kontainer**: Selalu gunakan fungsi *member* jika tersedia, misalnya gunakan `my_map.find(k)` ($O(\log N)$) alih-alih `std::find(my_map.begin(), my_map.end(), k)` ($O(N)$). Hal serupa berlaku untuk `std::list::sort()` vs `std::sort()`.
- **Manfaatkan `std::empty()` dan `std::distance()` secara Bijak**: Gunakan `container.empty()` daripada `container.size() == 0`. Jangan gunakan `std::distance(begin, end) == 0` untuk tipe data `ForwardIterator` non-kontigu jika hanya ingin memeriksa kekosongan, karena `std::distance` berbiaya $O(N)$ pada struktur non-random access.
- **Cadangkan Ruang Target (*Reserve/Back Inserter*)**: Saat menggunakan algoritma mutasi tujuan seperti `std::copy` atau `std::transform`, pastikan rentang tujuan dialokasikan sebelumnya via `vec.resize()` atau gunakan adapter `std::back_inserter(vec)` untuk *push_back* dinamis.

#### Don'ts
- **Menghapus Elemen Menggunakan Algoritma Tanpa Modifikasi Kontainer (*The Erase-Remove Idiom*)**: Algoritma `std::remove` atau `std::remove_if` **tidak** mengubah ukuran kontainer. Algoritma ini hanya menggeser elemen valid ke depan dan mengembalikan iterator logis baru. Di C++20 ke atas, selalu gunakan `std::erase` / `std::erase_if` langsung:
  ```cpp
  // BURUK (C++98/11 Bug Klasik: Size kontainer tidak berubah, elemen belakang sisa duplikat)
  std::remove(vec.begin(), vec.end(), target); 

  // BENAR (Modern C++20)
  std::erase(vec, target);
  ```

#### Iterator Invalidation (Edge Cases & Undefined Behavior)
Memanipulasi kontainer (insert, push_back, erase, rehash) saat iterasi dapat menyebabkan dereferensi memori liar (*Undefined Behavior*):
- Pada `std::vector`: Reallokasi kapasitas internal mendestruksi seluruh iterator sebelumnya.
- Iterator rentang invalid: Memberikan rentang tak berujung seperti `std::sort(v.begin(), other_v.end())` akan menyebabkan pelanggaran segmen memori (Segmentation Fault) karena batas loop komparasi keluar dari memori alokasi kontainer asal.

   Buat benchmark performa menggunakan `std::chrono::high_resolution_clock` untuk mengukur perbandingan `std::sort` sequensial standard dengan versi paralel `std::sort(std::execution::par, ...)` pada `std::vector<int>` berisi $10^7$ bilangan acak. Analisis pada ukuran data ke berapa pendekatan paralel mulai mengungguli sequential overhead.
