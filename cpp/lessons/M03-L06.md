### 1. Konsep & Arsitektur Mendalam

Dalam arsitektur perangkat lunak C++, abstraksi sering kali diasosiasikan dengan pewarisan polimorfik dinamis (*runtime polymorphism*) berbasis *virtual table* (`vtable`). Namun, dalam sistem berkinerja tinggi (*high-performance computing*, *game engine*, *trading engine*), biaya resolusi pointer dinamis dan hilangnya peluang optimasi *inlining* oleh compiler menjadi hambatan kritis. Tiga paradigma komplementer—**Composition**, **Policy-Based Design**, dan **CRTP (Curiously Recurring Template Pattern)**—hadir sebagai solusi desain arsitektural berbasis *compile-time polymorphism* (*static polymorphism*) dan kopling longgar (*decoupling*).

```
+--------------------------------------------------------------------------------+
| Polymorphism & Reuse Paradigm in C++                                           |
+------------------------------------+-------------------------------------------+
| Dynamic (Runtime)                  | Static (Compile-time)                     |
+------------------------------------+-------------------------------------------+
| - Virtual Inheritance (vptr/vtable)| - CRTP (Static dispatch)                  |
| - Runtime Strategy Pattern         | - Policy-Based Design (Compile-time Mixin)|
| - Higher Indirection Cost          | - Composition + Template Specialization   |
| - Poor Cache Locality              | - Inlining Friendly, Zero Overhead        |
+------------------------------------+-------------------------------------------+
```

#### Composition (Komposisi)
Komposisi menganut prinsip *"favor composition over inheritance"*. Alih-alih mengekspresikan relasi *IS-A* melalui hierarki pewarisan yang kaku, objek dibangun dari komponen-komponen independen dengan relasi *HAS-A*.
*   **Keuntungan Memori**: Objek tersimpan secara *flat* di dalam memori kontigu (bergantung pada *data member*), meningkatkan *spatial cache locality*.
*   **Enkapsulasi Murni**: Perubahan internal pada komponen tidak merusak state internal *enclosing class*, memitigasi masalah *fragile base class*.

#### Policy-Based Design (Andrei Alexandrescu)
Dipopulerkan oleh Andrei Alexandrescu, *Policy-Based Design* membedah perilaku suatu kelas ke dalam domain-domain independen (*policies*). Setiap *policy* diimplementasikan sebagai template parameter.
*   Kelas utama berperan sebagai *host class* yang menyusun logika orkestrasi, sedangkan *policy classes* menyediakan strategi konkret (misal: strategi sinkronisasi *thread*, strategi alokasi memori, strategi validasi data).
*   Berbeda dengan *Strategy Pattern* pada OOP klasik yang menggunakan antarmuka virtual murni, *policies* diikat pada saat kompilasi tanpa *runtime overhead*.

#### Curiously Recurring Template Pattern (CRTP)
CRTP adalah idiom C++ di mana suatu kelas turunan mewarisi kelas basis berbentuk template yang diinstansiasi dengan kelas turunan itu sendiri:

```cpp
template <typename Derived>
class Base {
    // ...
};

class Derived : public Base<Derived> {
    // ...
};
```

*   **Static Dispatch**: Menghilangkan kebutuhan pointer fungsi virtual (`vptr`). Resolusi metode dilakukan oleh compiler melalui `static_cast<Derived*>(this)` atau `static_cast<const Derived*>(this)`.
*   **Compile-Time Interface Verification**: Memungkinkan kelas basis memanggil metode kelas turunan sebelum objek dikompilasi secara lengkap.
*   **Mixin Idiom**: Menginjeksikan fungsionalitas umum ke dalam kelas turunan tanpa overhead pewarisan berganda (*multiple inheritance*) runtime.

### 2. Implementasi & Contoh Kasus Nyata

Contoh kasus nyata: Merancang **High-Frequency Network Packet Processor**. 
Kita menggunakan:
1. **CRTP** untuk mendefinisikan antarmuka parser paket secara statis tanpa `vtable`.
2. **Policy-Based Design** untuk mengonfigurasi strategi penanganan konkurensi (*threading policy*) dan strategi pencatatan log (*logging policy*).
3. **Composition** untuk menampung metrik performa di dalam prosesor.

```cpp
#include <iostream>
#include <string_view>
#include <chrono>
#include <concepts>

// ==========================================
// 1. POLICIES (Policy-Based Design)
// ==========================================

// Threading Policies
struct SingleThreadedPolicy {
    void lock() const noexcept {}
    void unlock() const noexcept {}
};

struct MultiThreadedPolicy {
    void lock() const noexcept {
        // Simulasi locking (misal: std::mutex::lock)
        // std::cout << "[Lock acquired]\n";
    }
    void unlock() const noexcept {
        // Simulasi unlocking (misal: std::mutex::unlock)
        // std::cout << "[Lock released]\n";
    }
};

// Logging Policies
struct ConsoleLoggerPolicy {
    static void log(std::string_view msg) {
        std::cout << "[LOG]: " << msg << '\n';
    }
};

struct NullLoggerPolicy {
    static void log(std::string_view) noexcept {
        // No-op: Dioptimasi habis oleh compiler
    }
};

// ==========================================
// 2. COMPOSITION COMPONENT
// ==========================================
struct PerformanceMetrics {
    uint64_t packets_processed{0};
    uint64_t bytes_processed{0};

    void record(size_t bytes) noexcept {
        ++packets_processed;
        bytes_processed += bytes;
    }
};

// ==========================================
// 3. BASE CLASS CRTP (Static Interface & Orchestration)
// ==========================================
template <
    typename Derived, 
    typename ThreadingPolicy = SingleThreadedPolicy, 
    typename LoggerPolicy = NullLoggerPolicy
>
class PacketProcessorBase : private ThreadingPolicy {
public:
    // API Publik Non-Virtual (Template Method Pattern statis)
    void process_packet(std::string_view raw_data) {
        ThreadingPolicy::lock();

        LoggerPolicy::log("Mulai memproses paket data.");

        // Static Dispatch menuju turunan via CRTP
        auto& derived = static_cast<Derived&>(*this);
        
        if (derived.validate_header(raw_data)) {
            derived.parse_body(raw_data);
            metrics_.record(raw_data.size());
            LoggerPolicy::log("Paket berhasil diproses.");
        } else {
            LoggerPolicy::log("Validasi paket gagal!");
        }

        ThreadingPolicy::unlock();
    }

    // Mengambil state komposisi
    [[nodiscard]] const PerformanceMetrics& metrics() const noexcept {
        return metrics_;
    }

protected:
    // Mencegah instansiasi langsung base class selain melalui turunan
    PacketProcessorBase() = default;
    ~PacketProcessorBase() = default;

private:
    // Composition: Komponen metrik berada langsung di dalam memori host class
    PerformanceMetrics metrics_; 
};

// ==========================================
// 4. DERIVED IMPLEMENTATIONS (CRTP Concrete Classes)
// ==========================================

// JSON Packet Processor (Single-threaded, Console Logging)
class JsonPacketProcessor : public PacketProcessorBase<JsonPacketProcessor, SingleThreadedPolicy, ConsoleLoggerPolicy> {
public:
    // Metode yang dipanggil via static dispatch
    bool validate_header(std::string_view data) const {
        return data.starts_with('{') && data.ends_with('}');
    }

    void parse_body(std::string_view data) const {
        std::cout << "-> Parsing JSON Payload: " << data << '\n';
    }
};

// Binary Packet Processor (Multi-threaded, Null Logging untuk performa ultra-tinggi)
class BinaryPacketProcessor : public PacketProcessorBase<BinaryPacketProcessor, MultiThreadedPolicy, NullLoggerPolicy> {
public:
    bool validate_header(std::string_view data) const {
        return data.size() >= 4 && data[0] == '\xAA';
    }

    void parse_body(std::string_view data) const {
        std::cout << "-> Parsing Binary Payload: Hex Header Identik [0xAA]\n";
    }
};

// ==========================================
// MAIN EXECUTION
// ==========================================
int main() {
    JsonPacketProcessor json_proc;
    json_proc.process_packet("{\"symbol\": \"BTCUSD\", \"price\": 65000}");
    
    std::cout << "JSON Packets Count: " << json_proc.metrics().packets_processed 
              << ", Bytes: " << json_proc.metrics().bytes_processed << "\n\n";

    BinaryPacketProcessor bin_proc;
    std::string binary_data = "\xAA\x01\x02\x03";
    bin_proc.process_packet(binary_data);

    std::cout << "Binary Packets Count: " << bin_proc.metrics().packets_processed 
              << ", Bytes: " << bin_proc.metrics().bytes_processed << '\n';

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
1. **Devirtualization & Inlining Total**:
   Pada polimorfisme klasik berbasis pewarisan, pemanggilan fungsi `process_packet` ke kelas turunan harus melalui dereferensi pointer:
   `this -> vptr -> vtable[idx] -> jump to function target`. 
   Indireksi ini menyebabkan *branch misprediction* dan menghalangi compiler melakukan optimasi *inlining*. 
   Pada CRTP, compiler telah mengetahui tipe absolut `Derived` saat kompilasi. Instruksi perakitan (`call`) berubah menjadi pemanggilan alamat absolut langsung (*direct call*) atau kode fungsi diinjeksikan secara *inline* tanpa instruksi *call-ret* sama sekali.

2. **Dead Code Elimination**:
   Saat `NullLoggerPolicy` digunakan, metode `log()` tidak melakukan operasi apa pun (`no-op`). Optimizer (misal Clang `-O3` atau GCC `-O3`) membuang seluruh instruksi evaluasi string dan pemanggilan fungsi logging tersebut. Tidak ada jejak instruksi assembler untuk logging dalam file biner akhir.

#### Alokasi Memori / Resource
1. **Peniadaan Pointer Virtual (`vptr`)**:
   Setiap kelas yang memiliki fungsi virtual harus menyimpan pointer `vptr` (berukuran 8 byte pada arsitektur 64-bit). Jika membuat 10.000.000 objek turunan, penggunaan CRTP menghemat 80 MB memori hanya dari peniadaan `vptr`.
2. **Empty Base Optimization (EBO)**:
   Pewarisan privat terhadap kelas policy yang tidak memiliki state internal (seperti `SingleThreadedPolicy` atau `NullLoggerPolicy`) memicu **EBO**. Berdasarkan standar C++, kelas kosong memiliki ukuran minimal 1 byte untuk menjamin alamat yang unik. Namun, jika kelas kosong dijadikan kelas basis, compiler mengoptimalkan ukuran basis tersebut menjadi 0 byte dalam memori kelas turunan.
   *(Catatan C++20: Atribut `[[no_unique_address]]` juga dapat digunakan pada komposisi policy kosong).*

```
Memory Layout Comparison (64-bit):

Dynamic Polymorphism (Virtual Base):
+-------------------------------+
| __vptr (8 bytes)              |
+-------------------------------+
| PerformanceMetrics (16 bytes) |
+-------------------------------+
Total Size: 24 bytes

CRTP + EBO (Static Base):
+-------------------------------+
| PerformanceMetrics (16 bytes) |
+-------------------------------+
| (Policy state: 0 byte via EBO)|
+-------------------------------+
Total Size: 16 bytes
```

#### Trade-offs
*   **Heterogeneous Collection Limitation**: Objek turunan CRTP yang berbeda instansiasi template (misal `Base<DerivedA>` dan `Base<DerivedB>`) adalah tipe yang benar-benar asing satu sama lain. Kita tidak dapat menyimpannya langsung di dalam satu kontainer standar seperti `std::vector<Base*>`. Solusinya membutuhkan teknik *Type Erasure* atau *Variant* (`std::variant`).
*   **Template Bloat**: Setiap kombinasi unik dari parameter policy dan derived class akan menghasilkan instansiasi kode biner baru di segmen teks memori (*code size footprint* membesar).
*   **Compilation Time**: Waktu parsing AST (*Abstract Syntax Tree*) dan resolusi template meningkatkan durasi kompilasi secara signifikan dibandingkan hierarki kelas biasa.

### 4. Best Practices & Common Pitfalls

#### Do's
*   **Enforce Compile-Time Constraints**: Gunakan C++20 Concepts atau `static_assert` di dalam kelas basis CRTP untuk memvalidasi bahwa kelas `Derived` benar-benar mengimplementasikan metode yang dibutuhkan.
    ```cpp
    template <typename Derived>
    class Base {
    public:
        void execute() {
            static_assert(&Derived::specific_impl != &Base::execute, 
                          "Derived class must implement specific_impl()");
            static_cast<Derived*>(this)->specific_impl();
        }
    };
    ```
*   **Pass-by-Reference pada Policy Instances**: Jika policy membawa state internal (*stateful policy*), gunakan komposisi dengan atribut C++20 `[[no_unique_address]]` untuk menghemat memori jika policy tersebut kebetulan *stateless*.
*   **Make Destructor Protected and Non-Virtual**: Kelas basis CRTP tidak boleh dihapus melalui pointer ke basis secara polimorfik dinamis (`delete base_ptr;`). Lindungi destruktor basis dengan akses `protected: ~Base() = default;`.

#### Don'ts
*   **Jangan Menggunakan Public Destructor Virtual pada Base CRTP**: Menambahkan destruktor virtual langsung merusak tujuan utama CRTP karena memicu kembalinya `vptr` dan tabel vtable.
*   **Hindari "The Wrong Derived Class" Bug**: Kesalahan tipografi dapat menyebabkan `Derived2` secara tidak sengaja mewarisi `Base<Derived1>`. 
    *Solusi*: Buat konstruktor basis bersifat `private` dan jadikan kelas turunan sebagai `friend`:
    ```cpp
    template <typename Derived>
    class Base {
    private:
        Base() = default;
        friend Derived; // Hanya Derived yang ditunjuk yang dapat menginstansiasi Base
    };
    ```

#### Edge Cases
*   **Object Slicing**: Memotong objek kelas turunan saat melakukan assignment ke tipe kelas basis. Pada CRTP murni, hal ini sering kali dicegah otomatis karena kelas basis tidak memiliki tipe yang sama jika parameternya berbeda, namun assignment implisit tetap harus dicegah dengan menghapus operator assignment pada basis (`Base& operator=(const Base&) = delete;`).
*   **Name Hiding**: Jika kelas basis CRTP dan kelas turunan mendeklarasikan fungsi dengan nama persis sama dan parameter berbeda tanpa resolusi eksplisit, aturan *unqualified name lookup* dapat menyembunyikan (*hide*) fungsi basis, alih-alih melakukan overloading.

### 5. Tantangan Eksplorasi Mandiri

1. **Refactoring Dynamic ke Static**:
   Ambil implementasi *Strategy Pattern* berbasis `virtual` yang pernah Anda buat (misal: sistem validasi form atau alokator memori). Ubah rancangan tersebut sepenuhnya menjadi *Policy-Based Design*. Bandingkan ukuran file biner (`size` command di Linux atau dumpbin di Windows) dan visualisasikan instruksi perakitannya via [Compiler Explorer (godbolt.org)](https://godbolt.org).
2. **C++20 Concept CRTP Enforcement**:
   Buat C++20 `concept` bernama `PacketParserConcept` yang memvalidasi bahwa suatu tipe harus memiliki metode `bool validate_header(std::string_view)` dan `void parse_body(std::string_view)`. Terapkan *concept* ini pada kelas basis CRTP untuk menggantikan validasi manual.
3. **Penyimpanan Heterogen**:
   Implementasikan kontainer `std::vector` yang dapat menampung objek-objek pemroses paket dengan policy berbeda (`JsonPacketProcessor` dan `BinaryPacketProcessor`) tanpa menggunakan fungsi virtual. Evaluasi penggunaan `std::variant` digabung dengan `std::visit` versus pendekatan *Type Erasure* kustom. Amati perbedaan performanya.
