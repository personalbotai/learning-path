### 1. Konsep & Arsitektur Mendalam

C++20 memperkenalkan *coroutine primitives* tingkat bahasa (`co_await`, `co_yield`, `co_return`), namun secara sengaja **tidak menyediakan runtime tingkat tinggi bawaan**. Tidak seperti C# (`Task`), Go (`goroutines`), atau Rust (`Tokio/async-std`), C++ menyerahkan kendali arsitektur runtime seutuhnya kepada pengembang perangkat lunak melalui model *customizable types*.

Untuk membangun sistem asinkron tingkat produksi, tiga pilar utama harus diintegrasikan:

```
[ Coroutine: Task<T> ] 
       │ (co_await schedule)
       ▼
 [ Executor (ThreadPool) ] ── (Runs state machine via coroutine_handle::resume)
       ▲
       │ (Observes)
[ Stop Token / Cancellation ]
```

#### Coroutine State Machine & Awaiter
Ketika fungsi C++ memiliki kata kunci `co_await`, compiler membongkar fungsi tersebut menjadi *state machine*:
- Setiap titik suspensi (`co_await`) membagi fungsi menjadi segmen eksekusi yang independen.
- Semua variabel lokal, parameter, dan `promise_type` dipindahkan dari *stack* ke struktur memori heap yang disebut **Coroutine Frame**.
- Antarmuka *Awaiter* (`await_ready`, `await_suspend`, `await_resume`) menentukan apakah eksekusi harus dihentikan, ke mana kontrol diserahkan, dan apa nilai kembaliannya.

#### Executor
Executor adalah abstraksi yang bertanggung jawab atas penempatan eksekusi instruksi (*execution context*). Executor dapat berupa *single-threaded event loop*, *thread pool*, atau *hardware queue* (misalnya GPU/IO Ring). 

Dalam konteks `co_await`, executor bertindak sebagai pihak yang menerima `std::coroutine_handle<>` pada fase `await_suspend` dan menjadwalkannya untuk di-`resume()` pada thread pekerja yang dituju. Ini memisahkan logika algoritma (**apa** yang dieksekusi) dari strategi konkurensi (**di mana** dan **kapan** dieksekusi).

#### Cooperative Cancellation
Di sistem konkurensi modern, pembatalan *preemptive* (seperti `pthread_cancel` atau `TerminateThread`) dihindari karena merusak prinsip RAII (*Resource Acquisition Is Initialization*), memicu *undefined behavior*, kebocoran memori, atau *deadlock* saat *mutex* tidak dilepas secara bersih.

C++20 memperkenalkan pendekatan **Cooperative Cancellation** melalui:
- `std::stop_source`: Penghasil sinyal pembatalan.
- `std::stop_token`: Objek ringan (dapat di-copy) yang diinspeksi oleh task untuk mengecek status `stop_requested()`.
- `std::stop_callback`: Callback yang dieksekusi secara otomatis begitu `std::stop_source::request_stop()` dipanggil.

### 2. Implementasi & Contoh Kasus Nyata

Berikut implementasi lengkap sebuah runtime minimal berbasis thread pool executor, awaiter penjadwalan, dan pembatalan kooperatif berbasis C++20:

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <coroutine>
#include <functional>
#include <stop_token>
#include <chrono>

// --- 1. Executor: ThreadPool Sederhana ---
class ThreadPool {
public:
    explicit ThreadPool(size_t threads) {
        for (size_t i = 0; i < threads; ++i) {
            workers_.emplace_back([this]() {
                while (true) {
                    std::function<void()> task;
                    {
                        std::unique_lock<std::mutex> lock(queue_mutex_);
                        cv_.wait(lock, [this]() { return stop_ || !tasks_.empty(); });
                        if (stop_ && tasks_.empty()) return;
                        task = std::move(tasks_.front());
                        tasks_.pop();
                    }
                    task();
                }
            });
        }
    }

    void enqueue(std::function<void()> task) {
        {
            std::unique_lock<std::mutex> lock(queue_mutex_);
            tasks_.push(std::move(task));
        }
        cv_.notify_one();
    }

    ~ThreadPool() {
        {
            std::unique_lock<std::mutex> lock(queue_mutex_);
            stop_ = true;
        }
        cv_.notify_all();
        for (std::thread &worker : workers_) {
            if (worker.joinable()) worker.join();
        }
    }

private:
    std::vector<std::thread> workers_;
    std::queue<std::function<void()>> tasks_;
    std::mutex queue_mutex_;
    std::condition_variable cv_;
    bool stop_ = false;
};

// --- 2. Custom Awaiter: Memindahkan Eksekusi ke Executor ---
struct ResumeOn {
    ThreadPool& executor_;

    bool await_ready() const noexcept { return false; }
    
    void await_suspend(std::coroutine_handle<> handle) const noexcept {
        executor_.enqueue([handle]() {
            handle.resume();
        });
    }

    void await_resume() const noexcept {}
};

// --- 3. Coroutine Type: Task dengan Dukungan Cancellation ---
struct AsyncTask {
    struct promise_type {
        AsyncTask get_return_object() {
            return AsyncTask{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_never initial_suspend() noexcept { return {}; }
        std::suspend_always final_suspend() noexcept { return {}; }
        void return_void() noexcept {}
        void unhandled_exception() { std::terminate(); }
    };

    std::coroutine_handle<promise_type> handle_;

    explicit AsyncTask(std::coroutine_handle<promise_type> h) : handle_(h) {}
    ~AsyncTask() {
        if (handle_) handle_.destroy();
    }
    
    AsyncTask(const AsyncTask&) = delete;
    AsyncTask& operator=(const AsyncTask&) = delete;
    AsyncTask(AsyncTask&& other) noexcept : handle_(other.handle_) { other.handle_ = nullptr; }
};

// --- 4. Kasus Nyata: Pipeline Data yang Mendukung Interupsi ---
AsyncTask process_data_pipeline(int pipeline_id, ThreadPool& pool, std::stop_token stop_tok) {
    std::cout << "[Pipeline " << pipeline_id << "] Dimulai pada Thread ID: " 
              << std::this_thread::get_id() << "\n";

    // Pindahkan eksekusi coroutine ke ThreadPool
    co_await ResumeOn{pool};

    std::cout << "[Pipeline " << pipeline_id << "] Beralih ke ThreadPool Thread ID: " 
              << std::this_thread::get_id() << "\n";

    // Loop pemrosesan data bertahap
    for (int step = 1; step <= 5; ++step) {
        // Checkpoint pembatalan kooperatif
        if (stop_tok.stop_requested()) {
            std::cout << "[Pipeline " << pipeline_id << "] Dibatalkan secara kooperatif pada step " 
                      << step << "\n";
            co_return; // Bersihkan frame dan keluar dengan aman (RAII terjamin)
        }

        std::this_thread::sleep_for(std::chrono::milliseconds(200));
        std::cout << "[Pipeline " << pipeline_id << "] Menyelesaikan step " << step << "\n";
    }

    std::cout << "[Pipeline " << pipeline_id << "] Selesai sepenuhnya tanpa interupsi.\n";
}

int main() {
    ThreadPool pool(4);
    std::stop_source stop_source;

    // Menjalankan pipeline yang akan berjalan sampai selesai
    AsyncTask task1 = process_data_pipeline(1, pool, stop_source.get_token());

    // Menjalankan pipeline yang akan dihentikan paksa
    std::stop_source cancelable_source;
    AsyncTask task2 = process_data_pipeline(2, pool, cancelable_source.get_token());

    // Beri jeda lalu batalkan Task 2 di tengah jalan
    std::this_thread::sleep_for(std::chrono::milliseconds(450));
    std::cout << "\n>>> Mengirim sinyal pembatalan ke Pipeline 2 <<<\n\n";
    cancelable_source.request_stop();

    // Tunggu sisa eksekusi selesai
    std::this_thread::sleep_for(std::chrono::milliseconds(1000));
    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Transformasi Kompiler
Saat fungsi coroutine dikompilasi, fungsinya diubah menjadi bentuk kanonikal:
1. Alokasi `coroutine frame` melalui `operator new` (implisit di dalam compiler, kecuali dioptimasi).
2. Konstruksi `promise_type`.
3. Panggilan `co_await promise.initial_suspend()`. Jika mengembalikan `std::suspend_never`, fungsi langsung mengeksekusi *body*.
4. Saat bertemu `co_await ResumeOn{pool}`:
   - Evaluasi `await_ready()`. Mengembalikan `false` menandakan coroutine harus ditangguhkan.
   - Panggilan `await_suspend(handle)`. Frame dihentikan, nilai instruction pointer (IP) disimpan di dalam frame.
   - `handle.resume()` dipanggil di kemudian waktu oleh worker thread di dalam `ThreadPool`. Saat `resume()` berjalan, CPU melanjutkan eksekusi tepat setelah titik suspensi, tetapi dengan konteks *call stack* milik thread pekerja baru.

#### Alokasi Memori: Heap Allocation Elision Optimization (HALO)
Secara standar, coroutine frame dialokasikan di heap. Namun, compiler C++ modern (Clang dan GCC) menyertakan optimasi **HALO**.
- Jika masa hidup coroutine terbukti secara statis berada di dalam masa hidup pemanggil (*caller*), dan ukuran frame diketahui pada saat kompilasi, compiler dapat mengeliminasi alokasi heap dan memetakan coroutine frame langsung pada stack frame milik *caller*.
- Namun, saat coroutine diserahkan ke Executor lintas thread (seperti pada implementasi `await_suspend` di atas), pointer frame berpindah kepemilikan antar-thread, sehingga optimasi HALO biasanya gugur dan alokasi heap via `operator new` tetap terjadi.

#### Trade-offs
| Aspek | C++ Coroutines + Executor | OS Threads (1:1) | Callback Pattern |
| :--- | :--- | :--- | :--- |
| **Memory Overhead** | Rendah (~ puluhan hingga ratusan byte per frame) | Tinggi (Default stack 1MB-8MB per thread) | Rendah (Hanya lambda/closure context) |
| **Context Switch** | Sangat cepat (Resume hanya melompat ke IP, tidak ada register swap CPU kernel) | Lambat (Transisi Kernel/User space, flushing CPU cache) | Cepat (Direct function call) |
| **Maintainability** | Tinggi (Struktur sequential/imperatif) | Sedang (Perlu sinkronisasi manual) | Buruk (*Callback Hell*, inversi kontrol) |
| **Cancellation** | Terstruktur & Kooperatif | Sulit & Berisiko (*Terminated state*) | Fragmented (Callback unregistering) |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Pass By Value untuk Argumen Coroutine Asinkron:** Ketika coroutine dieksekusi lintas thread, parameter yang dilewatkan secara *reference* (`const std::string&`) berisiko tinggi menjadi *dangling reference* bila objek asal di scope pemanggil musnah saat coroutine tertahan (*suspended*).
- **Tempatkan Titik Cek Pembatalan di Operasi Berat:** Cek `stop_token.stop_requested()` sebelum melakukan I/O intensif, decoding besar, atau setiap iterasi loop pemrosesan data.
- **Rancang Custom Destructor pada Task Type:** Pastikan `handle_.destroy()` dieksekusi untuk membersihkan frame jika `final_suspend` mengembalikan `std::suspend_always`.

#### Don'ts
- **Jangan Menggunakan Blokir Primitif:** Jangan memanggil `std::this_thread::sleep_for()` atau `std::mutex::lock()` di dalam coroutine thread pool tanpa alasan khusus. Ini akan memblokir worker thread pool secara keseluruhan (*thread starvation*). Buatlah timer berbasis coroutine awaiter atau gunakan async-aware primitives.
- **Jangan Mengabaikan Thread Safety di `await_suspend`:** Jika coroutine frame diserahkan ke thread lain pada `await_suspend()`, hindari mengakses `this` atau variabel awaiter setelah penjadwalan dilakukan, karena coroutine bisa saja selesai dan dihancurkan oleh thread lain sebelum `await_suspend()` kembali.

#### Edge Cases
- **Cancellation Race Condition:** Jika `request_stop()` dipanggil tepat saat coroutine sedang me-resume eksekusinya, flag pembatalan mungkin terlewat sampai iterasi berikutnya. Jika operasi harus segera dibatalkan, manfaatkan `std::stop_callback` untuk menginterupsi I/O descriptor yang mendasarinya (misal: memanggil `shutdown(socket_fd, SHUT_RDWR)`).
- **Exception setelah Pembatalan:** Pastikan mekanisme `promise_type::unhandled_exception()` menangani eksepsi pembatalan jika Anda memilih melempar eksepsi (seperti `boost::coroutines2::detail::forced_unwind`) alih-alih keluar secara implisit via `co_return`.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi `AsyncTimer` Awaiter:** Modifikasi ThreadPool untuk mendukung antrian berbasis waktu (*delay/timer queue*). Buat struct `AsyncSleep` yang dapat di-`co_await` (contoh: `co_await AsyncSleep{500ms, pool}`) tanpa memblokir thread pekerja OS.
2. **Hierarchical Task Cancellation:** Buat mekanisme di mana sebuah `ParentTask` yang dibatalkan secara otomatis membatalkan seluruh *ChildTask* yang di-spawn olehnya menggunakan nested `std::stop_source`.
3. **Deteksi HALO:** Gunakan Compiler Explorer (godbolt.org) dengan Clang 17+ flag `-O3`. Bandingkan assembly coroutine sederhana yang dipanggil sinkron dengan coroutine yang dilempar ke `ThreadPool`. Analisis pada baris assembly mana instruksi `builtin_new` dihilangkan atau tetap dipertahankan.
