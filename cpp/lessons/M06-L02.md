## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum era C++11, transfer data dari satu objek ke objek lain selalu melibatkan semantik penyalinan (*copy semantics*). Jika sebuah objek mengelola sumber daya dinamis (seperti memori *heap*, *file descriptor*, atau *socket*), operasi penyalinan memerlukan alokasi memori baru dan duplikasi data secara mendalam (*deep copy*). Hal ini menimbulkan *overhead* performa yang masif, terutama saat memproses objek temporer (*rvalues*) yang segera dihancurkan setelah ekspresi selesai dievaluasi.

```
Copy Semantics (C++98):
[Source] ---> Heap Buffer A (100 MB)
              ^
              | Deep copy (Alokasi baru + memcpy)
[Dest]   ---> Heap Buffer B (100 MB)

Move Semantics (C++11):
[Source] ---> Heap Buffer A (100 MB)
                  ^
                  | Transfer kepemilikan pointer (O(1))
[Dest]   ---------+
[Source] ---> nullptr (Mencegah double-free)
```

Untuk mengatasi inefisiensi ini, C++11 memperkenalkan **Move Semantics** yang didukung oleh kategori nilai baru (*rvalue references*, dinotasikan dengan `T&&`). Dua pilar utama dari mekanisme ini adalah:

1. **Move Constructor (`T(T&& other) noexcept`)**: Menginisialisasi objek baru dengan cara "mencuri" (*stealing*) kepemilikan internal pointer atau *handle* sumber daya dari objek sumber (`other`), tanpa melakukan alokasi baru.
2. **Move Assignment Operator (`T& operator=(T&& other) noexcept`)**: Menggantikan sumber daya objek yang sudah ada dengan sumber daya milik `other`, membersihkan sumber daya lama objek saat ini, dan memastikan objek sumber ditinggalkan dalam status valid (*valid but unspecified state*).

#### Peran Compiler & Overload Resolution
Ketika sebuah objek diinisialisasi atau di-*assign*, *overload resolution* compiler mengevaluasi kategori nilai ekspresi sumber:
- Jika sumber berupa **lvalue** (memiliki identitas dan dapat diambil alamat memorinya), compiler memilih *Copy Constructor* / *Copy Assignment*.
- Jika sumber berupa **rvalue** (objek temporer/prvalue atau lvalue yang di-*cast* menggunakan `std::move` menjadi xvalue), compiler memilih *Move Constructor* / *Move Assignment*.

### 2. Implementasi & Contoh Kasus Nyata

Berikut implementasi kelas pengelola *buffer* dinamis yang menerapkan **Rule of Five** secara eksplisit, dengan fokus pada *Move Constructor* dan *Move Assignment*.

```cpp
#include <iostream>
#include <utility>
#include <cstddef>
#include <cstring>
#include <vector>

class DynamicBuffer {
private:
    size_t m_size;
    int* m_data;

public:
    // 1. Regular Constructor
    explicit DynamicBuffer(size_t size)
        : m_size(size), m_data(size > 0 ? new int[size]() : nullptr) {
        std::cout << "[Alloc] Buffer dibuat, kapasitas: " << m_size << " elemen.\n";
    }

    // 2. Destructor
    ~DynamicBuffer() noexcept {
        delete[] m_data;
        // std::cout aman untuk debug, hindari di destructors produksi
    }

    // 3. Copy Constructor (Deep Copy)
    DynamicBuffer(const DynamicBuffer& other)
        : m_size(other.m_size), m_data(other.m_size > 0 ? new int[other.m_size] : nullptr) {
        if (m_data && other.m_data) {
            std::memcpy(m_data, other.m_data, m_size * sizeof(int));
        }
        std::cout << "[Copy Const] Deep copy dieksekusi (" << m_size << " elemen).\n";
    }

    // 4. Copy Assignment Operator
    DynamicBuffer& operator=(const DynamicBuffer& other) {
        if (this == &other) return *this; // Self-assignment check

        int* new_data = other.m_size > 0 ? new int[other.m_size] : nullptr;
        if (new_data && other.m_data) {
            std::memcpy(new_data, other.m_data, other.m_size * sizeof(int));
        }

        delete[] m_data; // Bersihkan resource lama
        m_data = new_data;
        m_size = other.m_size;

        std::cout << "[Copy Assign] Deep copy assignment dieksekusi.\n";
        return *this;
    }

    // 5. Move Constructor (Resource Theft)
    DynamicBuffer(DynamicBuffer&& other) noexcept
        : m_size(other.m_size), m_data(other.m_data) { // Curi pointer & metadata
        
        // Netralkan objek sumber agar destruktornya tidak menghapus memori yang dicuri
        other.m_size = 0;
        other.m_data = nullptr;

        std::cout << "[Move Const] Resource berhasil ditransfer secara O(1).\n";
    }

    // 6. Move Assignment Operator
    DynamicBuffer& operator=(DynamicBuffer&& other) noexcept {
        // Proteksi self-move assignment (contoh: a = std::move(a);)
        if (this == &other) return *this;

        // Dealokasi sumber daya objek penerima saat ini
        delete[] m_data;

        // Curi resource dari sumber
        m_data = other.m_data;
        m_size = other.m_size;

        // Reset objek sumber ke valid/empty state
        other.m_data = nullptr;
        other.m_size = 0;

        std::cout << "[Move Assign] Resource ditransfer via move assignment.\n";
        return *this;
    }

    [[nodiscard]] size_t size() const noexcept { return m_size; }
    [[nodiscard]] int* data() const noexcept { return m_data; }
};

int main() {
    std::cout << "--- Inisialisasi Objek A ---\n";
    DynamicBuffer bufA(1'000'000); // Alokasi 1 juta integer (~4MB)

    std::cout << "\n--- Move Constructor (bufB mencuri bufA) ---\n";
    DynamicBuffer bufB = std::move(bufA); // bufA di-cast menjadi xvalue

    std::cout << "Ukuran bufA pasca-move: " << bufA.size() << " (ptr: " << bufA.data() << ")\n";
    std::cout << "Ukuran bufB: " << bufB.size() << " (ptr: " << bufB.data() << ")\n";

    std::cout << "\n--- Move Assignment ---\n";
    DynamicBuffer bufC(500);
    bufC = std::move(bufB); // bufC membuang 500 elemennya, mengambil alih milik bufB

    std::cout << "\n--- Vector Reallocation Test ---\n";
    std::vector<DynamicBuffer> vec;
    vec.reserve(1);
    vec.push_back(DynamicBuffer(100)); // prvalue -> Move constructor
    std::cout << "Memicu relokasi vector:\n";
    vec.push_back(DynamicBuffer(200)); // Relokasi elemen lama menggunakan Move (karena noexcept)

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **`std::move` sebenarnya tidak memindahkan apa pun.** Di level instruksi assembly, `std::move` hanya sebuah `static_cast<T&&>(var)`. Fungsinya murni di ranah kompilasi untuk mengubah lvalue menjadi rvalue referensi (xvalue) agar overload resolution memilih konstruktor move.
- Eksekusi *Move Constructor* hanya melibatkan beberapa instruksi penyalinan register (menyalin nilai alamat pointer dan integer `m_size`), lalu mengisi register sumber dengan `0` (`nullptr`). Biaya eksekusinya bersifat deterministik: $\mathcal{O}(1)$.

#### Alokasi Memori / Resource
- **Stack:** Frame stack untuk `bufB` menerima salinan pointer memori dari frame stack `bufA`.
- **Heap:** Tidak ada sistem pemanggilan `brk`, `sbrk`, atau `mmap` kernel. Tidak ada panggilan ke *memory allocator* runtime (`malloc` / `operator new`). Blok heap asli tidak disentuh maupun diduplikasi.
- **Pembersihan Sumber Daya:** Mengeset pointer `other.m_data = nullptr` adalah langkah mutlak. Ketika `other` keluar dari *scope*, destruktor mengeksekusi `delete[] nullptr`, yang sesuai standar C++ adalah operasi aman (*no-op*). Jika pointer tidak di-*null*-kan, terjadi bug fatal: **Double Free Corruption**.

#### Peran Krusial `noexcept` pada STL Container
Kompiler dan Standard Library (seperti `std::vector`) mengedepankan **Strong Exception Guarantee**. Jika operasi manipulasi data gagal, *state* kontainer harus kembali persis seperti semula.
- Jika sebuah kelas memiliki *Move Constructor* yang **tidak** ditandai `noexcept`, `std::vector` saat melakukan ekspansi kapasitas (*growth*) akan menolak menggunakan *Move Constructor* dan terpaksa melakukan fallback ke *Copy Constructor*.
- Alasan: Jika *Move Constructor* melempar eksepsi di tengah proses relokasi, objek asal telah dimodifikasi (dicuri), sehingga vector tidak dapat membatalkan mutasi (*rollback*).

### 4. Best Practices & Common Pitfalls

#### Do's
- **Selalu deklarasikan move operations dengan `noexcept`:** Ini memastikan kompatibilitas penuh dengan algoritma STL (`std::move_if_noexcept`).
- **Gunakan idiom *Copy-and-Swap* jika memungkinkan:** Alternatif bersih untuk menyatukan Copy dan Move Assignment Operator guna menghindari duplikasi logika destruksi dan alokasi.
- **Terapkan *Rule of Zero*:** Jika kelas hanya membungkus tipe yang sudah mengimplementasikan semantik pemindahan (misalnya `std::string`, `std::unique_ptr`, `std::vector`), biarkan compiler men-generate seluruh fungsi khusus secara otomatis.

#### Don'ts
- **Jangan gunakan objek setelah dipindahkan (*Use-after-move*):** Objek yang telah dipindahkan berada dalam kondisi valid secara mekanis (dapat dihancurkan tanpa *crash*), namun nilainya tidak lagi terdefinisi secara logis (*unspecified state*).
- **Hindari `return std::move(lokal);`:** Ini adalah *anti-pattern* yang menghambat optimasi kompiler **NRVO** (*Named Return Value Optimization*). Mengembalikan variabel lokal secara langsung memungkinkan kompiler mengalokasikan objek langsung di stack pemanggil tanpa *copy* maupun *move* (*zero-cost elision*).
- **Jangan buat move assignment pada tipe `const`:** Tipe `const DynamicBuffer` tidak dapat dipindahkan; memanggil `std::move` pada objek konstan akan secara diam-diam memanggil *Copy Constructor*.

#### Edge Cases
- **Self-Move Assignment (`x = std::move(x);`):** Secara standar kode seperti ini tidak dianjurkan, namun harus ditangani secara aman. Tanpa pengecekan `if (this == &other)`, memori milik `this` akan di-`delete[]`, lalu `this->m_data` akan mengambil pointer yang baru saja ia hapus (mengarah ke *dangling pointer*).

### 5. Tantangan Eksplorasi Mandiri

1. **Efek `noexcept` pada Relokasi Vector:**
   Hapus penanda `noexcept` dari *Move Constructor* kelas `DynamicBuffer` di atas. Tambahkan log ke dalam *Copy Constructor*. Jalankan program dan perhatikan apakah `std::vector` saat relokasi kapasitas memanggil *Move* atau *Copy*. Jelaskan fenomena tersebut berdasarkan analisis kode internal STL `std::move_if_noexcept`.

2. **Implementasi `std::unique_ptr` Sederhana:**
   Rancang sebuah *smart pointer* kustom bernama `MyUniquePtr<T>`. Nonaktifkan *Copy Constructor* dan *Copy Assignment* (`= delete`), lalu implementasikan *Move Constructor* dan *Move Assignment*. Pastikan objek yang dibungkus tidak bocor (*memory leak*) dan kepemilikan ditransfer secara eksklusif.
