## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

**Inheritance (Pewarisan)** dalam C++ adalah mekanisme fundamental dari *Object-Oriented Programming* (OOP) yang memungkinkan sebuah kelas (Derived Class) mewarisi state dan behavior dari kelas lain (Base Class). Tujuan utamanya adalah *code reuse* dan pemodelan relasi "IS-A" (Adalah Sebuah).

Namun, kekuatan sejati dari inheritance di C++ baru muncul ketika digabungkan dengan **Virtual Dispatch** (atau *Dynamic Binding* / *Runtime Polymorphism*). Secara default, pemanggilan fungsi di C++ diselesaikan pada saat kompilasi (*Static Binding*). Jika Anda memanggil fungsi dari pointer/referensi Base Class yang menunjuk ke objek Derived Class, C++ akan mengeksekusi fungsi milik Base Class.

Untuk mengubah perilaku ini, C++ menyediakan keyword `virtual`. Ketika sebuah fungsi ditandai sebagai `virtual`, C++ menunda resolusi pemanggilan fungsi hingga *runtime*. Mekanisme ini (Virtual Dispatch) memastikan bahwa fungsi yang dieksekusi adalah fungsi milik tipe objek asli yang ada di memori, bukan tipe pointer/referensinya. Hal ini memungkinkan arsitektur perangkat lunak yang sangat *extensible*, seperti sistem *plugin*, *dependency injection*, dan *UI frameworks*.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern menggunakan *Abstract Base Class* (Interface) untuk sistem pemrosesan pembayaran.

```cpp
#include <iostream>
#include <memory>
#include <string>
#include <vector>

// 1. Abstract Base Class (Interface)
class PaymentGateway {
public:
    // WAJIB: Virtual destructor agar derived class dihancurkan dengan benar
    virtual ~PaymentGateway() {
        std::cout << "[Base] PaymentGateway destroyed\n";
    }

    // Pure virtual function (= 0). Membuat kelas ini menjadi Abstract.
    virtual bool processPayment(double amount) = 0;

    // Fungsi virtual biasa, bisa di-override, tapi punya implementasi default
    virtual std::string getGatewayName() const {
        return "Generic Gateway";
    }
};

// 2. Derived Class 1
class StripeGateway final : public PaymentGateway {
public:
    ~StripeGateway() override {
        std::cout << "[Derived] StripeGateway destroyed\n";
    }

    // Gunakan 'override' agar compiler memvalidasi signature fungsi
    bool processPayment(double amount) override {
        std::cout << "Processing $" << amount << " via Stripe API...\n";
        return true;
    }

    std::string getGatewayName() const override {
        return "Stripe";
    }
};

// 3. Derived Class 2
class PayPalGateway final : public PaymentGateway {
public:
    ~PayPalGateway() override {
        std::cout << "[Derived] PayPalGateway destroyed\n";
    }

    bool processPayment(double amount) override {
        std::cout << "Processing $" << amount << " via PayPal API...\n";
        return true;
    }

    std::string getGatewayName() const override {
        return "PayPal";
    }
};

// Fungsi polimorfik: Menerima interface, tidak peduli implementasi spesifiknya
void checkout(PaymentGateway& gateway, double amount) {
    std::cout << "Using: " << gateway.getGatewayName() << "\n";
    if (gateway.processPayment(amount)) {
        std::cout << "Checkout successful!\n\n";
    }
}

int main() {
    // Menggunakan smart pointers untuk manajemen memori otomatis
    std::vector<std::unique_ptr<PaymentGateway>> gateways;
    
    gateways.push_back(std::make_unique<StripeGateway>());
    gateways.push_back(std::make_unique<PayPalGateway>());

    // Virtual dispatch terjadi di sini
    for (const auto& gw : gateways) {
        checkout(*gw, 150.50);
    }

    return 0;
}
```

**Penjelasan Kode:**
- `virtual ~PaymentGateway()`: Destruktor virtual memastikan saat `std::unique_ptr<PaymentGateway>` dihapus, destruktor `StripeGateway` atau `PayPalGateway` dipanggil terlebih dahulu.
- `= 0`: Menandakan *pure virtual function*. Kelas tidak bisa diinstansiasi langsung.
- `override`: Memaksa compiler mengecek apakah fungsi ini benar-benar menimpa fungsi virtual di Base Class. Mencegah bug akibat salah ketik nama fungsi atau parameter.
- `final`: Optimasi tingkat lanjut. Memberitahu compiler bahwa kelas ini tidak akan diwariskan lagi, memungkinkan compiler melakukan *devirtualization* (mengubah dynamic binding menjadi static binding untuk performa).

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (vptr dan vtable)**: 
  Ketika sebuah kelas memiliki minimal satu fungsi `virtual`, compiler secara diam-diam membuat **vtable** (Virtual Method Table) untuk kelas tersebut. Vtable adalah array statis berisi *function pointers* yang menunjuk ke implementasi fungsi virtual yang paling spesifik untuk kelas itu.
  Selain itu, compiler menyisipkan sebuah pointer tersembunyi bernama **vptr** (Virtual Pointer) ke dalam setiap *instance* (objek) dari kelas tersebut. Saat runtime, pemanggilan `gateway.processPayment()` diterjemahkan menjadi instruksi assembly yang kira-kira setara dengan: `gateway->vptr[index_of_processPayment](gateway, amount)`.
- **Alokasi Memori / Resource**: 
  - **Vtable** disimpan di area memori *read-only* (seperti `.rodata` di Linux) dan dibuat *per-class*, bukan *per-object*.
  - **Vptr** menambah ukuran setiap objek sebesar ukuran pointer arsitektur sistem (8 bytes pada sistem 64-bit). Jika Anda memiliki jutaan objek kecil, *overhead* 8 bytes per objek ini bisa menjadi masalah memori.
- **Trade-offs**: 
  Virtual dispatch memiliki *overhead* performa karena adanya *pointer indirection* (harus membaca vptr, lalu membaca vtable, baru melompat ke alamat fungsi). Selain itu, pemanggilan virtual seringkali menghalangi compiler untuk melakukan *inlining* fungsi, yang merupakan salah satu optimasi paling krusial di C++.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - **SELALU** gunakan `virtual destructor` pada Base Class jika kelas tersebut dirancang untuk diwariskan dan dimanipulasi secara polimorfik. Tanpanya, Anda akan mengalami *Memory Leak*.
  - **SELALU** gunakan keyword `override` pada Derived Class. Ini mengubah error logika saat runtime menjadi error kompilasi.
  - Gunakan `final` pada kelas atau fungsi jika hierarki pewarisan sudah selesai. Ini membantu performa (*devirtualization*).
- **Don'ts**:
  - **JANGAN PERNAH** memanggil fungsi `virtual` dari dalam *Constructor* atau *Destructor*. Saat constructor Base Class berjalan, objek tersebut *masih berupa* Base Class (vptr menunjuk ke vtable Base Class). Fungsi yang dipanggil bukanlah versi Derived Class, yang seringkali menyebabkan *undefined behavior* atau *pure virtual function call crash*.
  - Hindari hierarki inheritance yang terlalu dalam (lebih dari 3 tingkat). Gunakan prinsip *Composition over Inheritance*.
- **Edge Cases**:
  - **Object Slicing**: Terjadi jika Anda mem-passing objek polimorfik secara *by value* (misal: `void process(PaymentGateway gw)`). Bagian spesifik dari Derived Class akan "terpotong" (sliced), dan objek tersebut akan di-copy murni sebagai Base Class. Selalu gunakan *pointer* atau *reference* (`&` atau `*`).
  - **Multiple Inheritance & Diamond Problem**: Jika D mewarisi B dan C, dan B serta C mewarisi A, akan ada ambiguitas state A. Solusinya adalah `virtual inheritance` (`class B : virtual public A`), namun ini menambah kompleksitas dan *overhead* memori yang signifikan.

### 5. Tantangan Eksplorasi Mandiri

1. **Simulasi Object Slicing**: Buatlah sebuah fungsi yang menerima parameter Base Class secara *by value* (bukan reference/pointer). Passing objek Derived Class ke dalamnya, dan cetak outputnya. Amati apa yang terjadi pada data spesifik milik Derived Class.
2. **Eksplorasi Vptr Size**: Gunakan operator `sizeof()` pada sebuah kelas kosong, lalu tambahkan satu fungsi `virtual` ke dalamnya. Bandingkan hasil `sizeof()` sebelum dan sesudah penambahan fungsi virtual. Jelaskan mengapa ukurannya berubah.
