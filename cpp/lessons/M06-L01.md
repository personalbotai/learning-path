## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum C++11, C++ hanya memiliki dua kategori nilai (value category): **Lvalue** (kiri dari *assignment*) dan **Rvalue** (kanan dari *assignment*). Namun, pengenalan *Move Semantics* di C++11 memaksa komite standar C++ untuk merombak taksonomi ini menjadi lebih presisi. 

Kategori nilai di C++ modern tidak hanya bergantung pada "posisi", melainkan pada dua properti fundamental dari sebuah ekspresi (expression):
1. **Identity (Identitas):** Apakah ekspresi tersebut merujuk pada lokasi memori yang spesifik dan dapat diidentifikasi (misalnya, memiliki nama atau alamat yang bisa diambil dengan `&`)?
2. **Movability (Dapat dipindahkan):** Apakah aman untuk "mencuri" resource dari objek yang dievaluasi oleh ekspresi tersebut (biasanya karena objek tersebut akan segera hancur/expire)?

Berdasarkan dua properti ini, C++ membagi ekspresi menjadi tiga kategori utama:
*   **Lvalue (Locator Value):** Memiliki *Identity*, tetapi **TIDAK** *Movable*. Contoh: Variabel bernama, dereference pointer `*p`.
*   **Prvalue (Pure Rvalue):** **TIDAK** memiliki *Identity*, tetapi *Movable*. Contoh: Literal (`42`, `true`), hasil kembalian fungsi yang bukan referensi (`int f()`).
*   **Xvalue (eXpiring Value):** Memiliki *Identity* **DAN** *Movable*. Objek ini memiliki lokasi memori, tetapi kita secara eksplisit memberi tahu kompilator bahwa resource-nya boleh dicuri. Contoh: Hasil dari `std::move(x)`.

Untuk mempermudah aturan bahasa, C++ juga mengelompokkannya menjadi:
*   **Glvalue (Generalized Lvalue):** Ekspresi yang memiliki *Identity* (`Lvalue` + `Xvalue`).
*   **Rvalue:** Ekspresi yang *Movable* (`Prvalue` + `Xvalue`).

### 2. Implementasi & Contoh Kasus Nyata

Kategori nilai sangat krusial dalam **Overload Resolution**, terutama saat kompilator harus memilih antara *Copy Constructor/Assignment* (menerima Lvalue) dan *Move Constructor/Assignment* (menerima Rvalue).

```cpp
#include <iostream>
#include <string>
#include <utility>

// Fungsi yang menerima Lvalue (Pass by lvalue reference)
void process(std::string& str) {
    std::cout << "Lvalue diproses: " << str << "\n";
}

// Fungsi yang menerima Rvalue (Pass by rvalue reference)
// Menangkap Prvalue dan Xvalue
void process(std::string&& str) {
    std::cout << "Rvalue diproses (bisa dicuri): " << str << "\n";
    // Simulasi mencuri resource
    std::string stolen = std::move(str); 
}

std::string createString() {
    return "Hello Prvalue"; // Mengembalikan prvalue
}

int main() {
    std::string name = "C++ Modern"; // 'name' adalah lvalue

    // 1. Lvalue
    // 'name' memiliki identitas dan tidak bisa dipindahkan secara implisit.
    process(name); 

    // 2. Prvalue
    // createString() mengembalikan objek sementara tanpa nama.
    // Tidak punya identitas, tapi aman untuk dipindahkan.
    process(createString()); 

    // 3. Xvalue
    // std::move(name) mengonversi lvalue 'name' menjadi xvalue (rvalue reference).
    // Memiliki identitas (merujuk ke 'name'), tapi kita izinkan untuk dicuri.
    process(std::move(name)); 

    // PERINGATAN: 'name' sekarang dalam kondisi "valid but unspecified"
    // karena resource-nya kemungkinan besar sudah dicuri oleh fungsi process().
    
    return 0;
}
```

**Penjelasan Kode:**
- `process(name)` memanggil versi `std::string&` karena `name` adalah **lvalue**.
- `process(createString())` memanggil versi `std::string&&` karena hasil fungsi adalah **prvalue**.
- `process(std::move(name))` memanggil versi `std::string&&` karena `std::move` melakukan *cast* menjadi `std::string&&`, menjadikannya **xvalue**.

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime:** Kategori nilai adalah konsep **Compile-Time**. Di level *machine code* (runtime), CPU tidak tahu apa itu lvalue atau xvalue; CPU hanya melihat pointer dan register. Kompilator menggunakan kategori nilai murni untuk menentukan fungsi mana yang akan dipanggil (*overload resolution*) dan apakah operasi *copy* atau *move* yang harus di- *generate* ke dalam *byte-code/assembly*.
- **Alokasi Memori / Resource:** 
  - **Lvalue** selalu berada di memori (stack atau heap).
  - **Prvalue** seringkali hanya hidup di register CPU. Sejak C++17 (Guaranteed Copy Elision), *prvalue* tidak lagi dianggap sebagai objek sementara yang dikopi/dipindah, melainkan sebagai "resep" untuk menginisialisasi objek di memori tujuan secara langsung (tanpa alokasi memori sementara).
  - **Xvalue** merujuk pada memori yang sudah ada (seperti lvalue), tetapi memberi sinyal ke *Execution Engine* bahwa pointer internal dari objek tersebut (misal pointer ke array karakter dalam `std::string`) boleh dipindahkan ke objek lain, menghindari alokasi heap baru.
- **Trade-offs:** Kompleksitas aturan bahasa C++ meningkat drastis. Developer harus memahami perbedaan referensi untuk menghindari *dangling pointer* atau *use-after-move*. Namun, trade-off ini memberikan performa *Zero-Cost Abstraction* yang tidak tertandingi oleh bahasa dengan *Garbage Collector*.

### 4. Best Practices & Common Pitfalls

- **Do's:**
  - Gunakan `std::move` hanya ketika Anda benar-benar selesai menggunakan sebuah objek (menjadikannya *xvalue*).
  - Pahami bahwa `std::move` **tidak memindahkan apa-apa**. Ia hanya melakukan *type cast* ke *rvalue reference* (`T&&`), mengubah *lvalue* menjadi *xvalue*. Pemindahan sebenarnya dilakukan oleh *Move Constructor/Assignment*.
- **Don'ts:**
  - **Jangan** melakukan `return std::move(local_variable);`. Ini adalah *anti-pattern* yang mematikan optimasi kompilator bernama NRVO (Named Return Value Optimization). Cukup `return local_variable;`, kompilator sudah tahu itu akan menjadi *xvalue* atau di-elisi.
  - **Jangan** menggunakan objek setelah di-`std::move` kecuali untuk menghancurkannya atau memberinya nilai baru.
- **Edge Cases (Jebakan Batman):**
  - **Named Rvalue Reference is an Lvalue!** 
    ```cpp
    void foo(std::string&& r) {
        // 'r' tipenya adalah rvalue reference, 
        // TETAPI di dalam blok ini, 'r' memiliki nama, sehingga ia adalah LVALUE!
        // Jika ingin meneruskannya sebagai rvalue, Anda harus menggunakan std::move(r)
        process(r); // Memanggil versi Lvalue!
        process(std::move(r)); // Memanggil versi Rvalue!
    }
    ```

### 5. Tantangan Eksplorasi Mandiri

1. **Eksplorasi `decltype`:** Buatlah sebuah makro atau *template function* menggunakan `decltype` dan `std::is_lvalue_reference`, `std::is_rvalue_reference` untuk mencetak ke terminal apakah sebuah ekspresi adalah Lvalue, Xvalue, atau Prvalue. Uji dengan ekspresi seperti `++x` vs `x++`.
2. **Guaranteed Copy Elision (C++17):** Buatlah sebuah class yang *Copy Constructor* dan *Move Constructor*-nya di-`delete`. Buktikan bahwa Anda tetap bisa mengembalikan objek dari class tersebut melalui fungsi (sebagai *prvalue*) di C++17, yang mana hal ini akan error di C++14.
3. **Perfect Forwarding:** Pelajari bagaimana `std::forward<T>(arg)` bekerja. Mengapa kita membutuhkan `std::forward` di dalam *template* alih-alih menggunakan `std::move`? (Petunjuk: Hubungkan dengan *Reference Collapsing Rules*).
