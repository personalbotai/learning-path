### 1. Konsep & Arsitektur Mendalam

Capstone ini merupakan kulminasi dari penguasaan rekayasa perangkat lunak modern berbasis C++ (C++20/C++23). Fokus implementasi adalah membangun **High-Throughput Concurrent Telemetry Engine**: sistem ingestion dan pemrosesan metrik berkinerja tinggi yang menggabungkan prinsip *zero-cost abstraction*, manajemen konkurensi tingkat lanjut, pencegahan *false sharing*, serta *deterministic resource management* (RAII).

```
[Producers: Ingestion Threads]
          │
          ▼ (std::move, zero-copy)
┌────────────────────────────────────────────────────────┐
│ Lock-Free / Low-Contention Bounded RingBuffer          │
│ - alignas(hardware_destructive_interference_size)      │
│ - Circular Array pre-allocated memory                 │
└────────────────────────────────────────────────────────┘
          │
          ▼ (Event Batching / Dispatch)
┌────────────────────────────────────────────────────────┐
│ Worker Pool (std::jthread + std::stop_token)           │
│ - Cache-friendly Pipeline                              │
│ - Aggregation Engine (std::atomic, Bitset/Metrics)     │
└────────────────────────────────────────────────────────┘
          │
          ▼
[Sink: Analytical Report / Storage Emulator]
```

#### Arsitektur Inti:
1. **Bounded Ring Buffer dengan Cache-Line Padding**: Meminimalkan contention antar core CPU dengan menyelaraskan (*aligning*) pointer baca (*head*) dan tulis (*tail*) ke batas cache-line yang berbeda via `hardware_destructive_interference_size`.
2. **Compile-Time Polymorphism via C++20 Concepts**: Mengganti dynamic dispatch (`vtable`) dengan pemrosesan statis guna menghilangkan latensi *indirect branching* dan memungkinkan *inlining* penuh oleh optimizer.
3. **Cooperative Cancellation & RAII Threading**: Menggunakan `std::jthread` dan `std::stop_token` untuk eliminasi *resource leak* dan *deadlock* saat *graceful shutdown*.
4. **Move Semantics & Cache Locality**: Payload metrik dialokasikan contiguous di memori flat tanpa *scatter-gather dynamic allocation* pada heap di *hot-path*.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi *thread-safe concurrent metric dispatcher engine* siap-kompilasi menggunakan C++20.

```cpp
#include <iostream>
#include <vector>
#include <array>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <concepts>
#include <chrono>
#include <atomic>
#include <new>

#ifdef __cpp_lib_hardware_interference_size
using std::hardware_destructive_interference_size;
#else
constexpr size_t hardware_destructive_interference_size = 64;
#endif

// 1. Concept Definition: Memastikan tipe event memenuhi kriteria zero-cost transfer
template <typename T>
concept TelemetryEvent = std::is_nothrow_move_constructible_v<T> && requires(T t) {
    { t.id } -> std::convertible_to<uint64_t>;
    { t.value } -> std::convertible_to<double>;
    { t.timestamp } -> std::convertible_to<uint64_t>;
};

// Payload representasi event metrik
struct MetricRecord {
    uint64_t id;
    double value;
    uint64_t timestamp;
};

// 2. High-Performance Bounded Channel dengan Proteksi False Sharing
template <TelemetryEvent T, size_t Capacity>
class BoundedEventQueue {
private:
    std::array<T, Capacity> buffer_;
    
    // Pisahkan indeks baca dan tulis ke cache line berbeda
    alignas(hardware_destructive_interference_size) size_t head_{0};
    alignas(hardware_destructive_interference_size) size_t tail_{0};
    alignas(hardware_destructive_interference_size) size_t count_{0};
    
    std::mutex mtx_;
    std::condition_variable not_full_cv_;
    std::condition_variable not_empty_cv_;

public:
    BoundedEventQueue() = default;
    ~BoundedEventQueue() = default;

    // Non-copyable, non-movable resource owner
    BoundedEventQueue(const BoundedEventQueue&) = delete;
    BoundedEventQueue& operator=(const BoundedEventQueue&) = delete;

    bool push(T&& item, std::chrono::milliseconds timeout) {
        std::unique_lock<std::mutex> lock(mtx_);
        if (!not_full_cv_.wait_for(lock, timeout, [this]() { return count_ < Capacity; })) {
            return false; // Backpressure / drop
        }

        buffer_[tail_] = std::move(item);
        tail_ = (tail_ + 1) % Capacity;
        ++count_;

        lock.unlock();
        not_empty_cv_.notify_one();
        return true;
    }

    bool pop(T& item, std::stop_token stop_tok) {
        std::unique_lock<std::mutex> lock(mtx_);
        // Awasi predicate atau sinyal cooperative interruption
        not_empty_cv_.wait(lock, [&]() { 
            return count_ > 0 || stop_tok.stop_requested(); 
        });

        if (count_ == 0) {
            return false; // Interrupted dan buffer kosong
        }

        item = std::move(buffer_[head_]);
        head_ = (head_ + 1) % Capacity;
        --count_;

        lock.unlock();
        not_full_cv_.notify_one();
        return true;
    }
};

// 3. Engine Orchestrator
class TelemetryEngine {
public:
    static constexpr size_t QUEUE_SIZE = 4096;
    
    TelemetryEngine() : total_processed_(0), total_sum_(0.0) {}

    void start(size_t consumer_count) {
        for (size_t i = 0; i < consumer_count; ++i) {
            workers_.emplace_back([this](std::stop_token s_token) {
                this->consumer_loop(s_token);
            });
        }
    }

    bool ingest(MetricRecord&& record) {
        return queue_.push(std::move(record), std::chrono::milliseconds(5));
    }

    void shutdown() {
        // Memicu cooperative cancellation pada seluruh std::jthread
        for (auto& worker : workers_) {
            worker.request_stop();
        }
        // Workers di-join otomatis oleh destructor std::jthread
        workers_.clear();
    }

    void print_stats() const {
        std::cout << "\n=== Execution Summary ===" << std::endl;
        std::cout << "Processed Records : " << total_processed_.load() << std::endl;
        std::cout << "Accumulated Metric: " << total_sum_.load() << std::endl;
    }

private:
    void consumer_loop(std::stop_token s_token) {
        MetricRecord record;
        while (!s_token.stop_requested()) {
            if (queue_.pop(record, s_token)) {
                // Aggregation logic (Hot-path processing)
                total_sum_.fetch_add(record.value, std::memory_order_relaxed);
                total_processed_.fetch_add(1, std::memory_order_relaxed);
            }
        }
    }

    BoundedEventQueue<MetricRecord, QUEUE_SIZE> queue_;
    std::vector<std::jthread> workers_;
    alignas(hardware_destructive_interference_size) std::atomic<uint64_t> total_processed_;
    alignas(hardware_destructive_interference_size) std::atomic<double> total_sum_;
};

// 4. Execution Entry Point & Demo
int main() {
    TelemetryEngine engine;
    constexpr size_t CONSUMER_THREADS = 4;
    constexpr size_t PRODUCER_THREADS = 2;
    constexpr uint64_t ITEMS_PER_PRODUCER = 100'000;

    engine.start(CONSUMER_THREADS);

    auto start_time = std::chrono::high_resolution_clock::now();

    // Spawn producer threads
    {
        std::vector<std::jthread> producers;
        for (size_t id = 0; id < PRODUCER_THREADS; ++id) {
            producers.emplace_back([&engine, id]() {
                for (uint64_t i = 0; i < ITEMS_PER_PRODUCER; ++i) {
                    MetricRecord rec{
                        .id = (id * ITEMS_PER_PRODUCER) + i,
                        .value = 1.5,
                        .timestamp = static_cast<uint64_t>(std::chrono::system_clock::now().time_since_epoch().count())
                    };
                    while (!engine.ingest(std::move(rec))) {
                        std::this_thread::yield(); // Backpressure handling
                    }
                }
            });
        }
    } // Seluruh produsen selesai & di-join di sini via RAII

    // Graceful drain
    std::this_thread::sleep_for(std::chrono::milliseconds(200));
    engine.shutdown();

    auto end_time = std::chrono::high_resolution_clock::now();
    std::chrono::duration<double, std::milli> elapsed = end_time - start_time;

    engine.print_stats();
    std::cout << "Elapsed Time      : " << elapsed.count() << " ms" << std::endl;

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: 
  Setiap *thread* OS dimapping secara 1:1 ke core thread CPU via kernel scheduler. Saat *pipeline* bekerja, thread yang tertahan di *condition variable* dievakuasi dari core CPU menuju status *sleeping/blocked*, menghindari pemborosan siklus komputasi (*busy-wait*), berbeda dari arsitektur *spin-lock* murni. Penggunaan `std::stop_token` menyediakan registri atomik thread-safe internal yang mentransmisikan sinyal interupsi secara non-preemptive tanpa sinyal OS eksternal (seperti `SIGUSR1`).

- **Alokasi Memori / Resource**:
  Penyusunan buffer `MetricRecord` menggunakan memori kontigu (`std::array`) yang dipesan secara statis/inline saat runtime inisialisasi class. Ini mengeliminasi *heap fragmentation* dan dereferensi pointer *cache-miss*. Struktur:
  ```
  [Cache Line 0: head_ | padding] -> 64 bytes
  [Cache Line 1: tail_ | padding] -> 64 bytes
  [Cache Line 2: count_| padding] -> 64 bytes
  ```
  Ini mengisolasi protokol MESI/MOESI cache CPU, mencegah pembatalan baris cache (*cache invalidation*) antar core saat thread producer memodifikasi `tail_` bertepatan dengan thread consumer yang memodifikasi `head_`.

- **Trade-offs**:
  Penggunaan `std::mutex` dan `std::condition_variable` memperkenalkan *context-switch overhead* (~1–2 microseconds per wait/notify saat kolisi). Pendekatan alternatif berupa *Lock-Free Circular Queue* murni dengan CAS (*Compare-And-Swap*) atomic primitives akan menurunkan latensi hingga hitungan nanodetik, namun membakar 100% utilisasi core CPU (*busy spin*) saat antrean kosong dan meningkatkan kompleksitas algoritma resolusi konkurensi (seperti bahaya *ABA problem*).

### 4. Best Practices & Common Pitfalls

#### Do's:
- **Terapkan `noexcept` pada move constructors**: Type traits dan kontainer STL (misal `std::vector::resize`) akan mendegradasi operasi performa tinggi menjadi `copy` lambat jika *move constructor* tidak dijamin `noexcept`.
- **Align Data Concurrency**: Selalu pisahkan atomik/indeks yang sering ditulis oleh core berbeda menggunakan `alignas(std::hardware_destructive_interference_size)`.
- **Gunakan RAII Thread Management**: Selalu pilih `std::jthread` dibanding `std::thread` klasik untuk menjamin pemanggilan `.join()` saat eksepsi dilempar (*stack unwinding*).

#### Don'ts:
- **Jangan Menggunakan Raw Pointer untuk Ownership Transfer**: Hindari `new`/`delete` dalam *hot-path*. Gunakan *value semantics* dan `std::move`.
- **Hindari Shared Pointer Overuse**: `std::shared_ptr` memiliki overhead atomik pada *reference counter* internal. Setiap penyalinan `shared_ptr` memicu instruksi *bus locking* (`LOCK XADD` pada arsitektur x86) yang menghambat skalabilitas multi-core.
- **Jangan Mengabaikan Spurious Wakeup**: Jangan pernah memanggil `cv.wait()` tanpa predikat lambda.

#### Edge Cases:
- **Destruction Race pada Queue Shutdown**: Jika consumer thread keluar sebelum queue sepenuhnya kosong, metrik yang tertinggal dalam memori buffer akan lenyap (*dropped data*). Pola mitigasinya adalah mengeksekusi *draining phase* di dalam method shutdown sebelum `stop_requested()` mematikan thread seutuhnya.

### 5. Tantangan Eksplorasi Mandiri

1. **Lock-Free Refactoring**: Ubah `BoundedEventQueue` dari berbasis `std::mutex` menjadi *Lock-Free Single-Producer Single-Consumer (SPSC)* menggunakan `std::atomic<size_t>` dengan memory ordering terperinci (`std::memory_order_acquire` / `std::memory_order_release`). Bandingkan *throughput*-nya menggunakan Google Benchmark.
2. **SIMD Vectorization Batching**: Modifikasi pemrosesan consumer agar memproses *MetricRecord* dalam blok *batch* (misal 8 rekaman sekaligus) dan gunakan instruksi intrinsik AVX-256/AVX-512 untuk menjumlahkan metrik `value` secara terparalelisasi di tingkat hardware.
3. **Telemetry Persistence via Memory-Mapped Files**: Implementasikan komponen *Storage Sink* yang memetakan file biner ke virtual memory (`mmap` pada Linux atau `CreateFileMapping` pada Windows) untuk menulis seluruh telemetry data tanpa melibatkan *system call* IO standar (`write`), lalu validasi konsistensi datanya saat crash.
