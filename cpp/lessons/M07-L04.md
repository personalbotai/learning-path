### 1. Konsep & Arsitektur Mendalam

Pada standar C++20, library Ranges memperkenalkan paradigma pemrograman deklaratif dan fungsional untuk manipulasi sekuens data tanpa alokasi memori berlebih melalui *lazy evaluation*. Namun, fungsionalitas inti untuk manipulasi multi-range dan windowing masih terbatas. C++23 melengkapi ekosistem ini dengan memperkenalkan empat *range adaptors* krusial pada namespace `std::views`:

1. **`views::zip`**: Menggabungkan $N$ buah range secara paralel menjadi satu range berisi `std::tuple` of references. Iterasi berhenti secara deterministik saat range terpendek mencapai elemen akhirnya (*common shortest length*).
2. **`views::enumerate`**: Adaptor sintetis yang memetakan elemen range menjadi pasangan `std::tuple<Index, ValueReference>`, mengeliminasi antipattern loop berbasis indeks manual (`size_t i = 0; ... ++i`) atau ketergantungan pada variabel iterator manual.
3. **`views::chunk`**: Membagi range menjadi sub-range berurutan non-overlapping dengan ukuran tepat $N$ (kecuali partisi terakhir yang menampung sisa elemen mod $N$).
4. **`views::slide`**: Mengimplementasikan pola sliding-window berukuran $N$. Menghasilkan range of subranges yang overlapping, di mana setiap window bergeser satu elemen ke kanan.

```
Input Range: [ A, B, C, D, E ]

views::chunk(2):  [ [A, B],   [C, D],   [E] ]       (Non-overlapping)
views::slide(3):  [ [A, B, C], [B, C, D], [C, D, E] ] (Overlapping)
```

#### Komposisi & Karakteristik Arsitektural

- **Pure Composition (Pipeline Operator `|`)**: Seluruh adaptor ini mengekspresikan antarmuka *Range Adaptor Closure Object* (RACO). Objek dapat dirangkai secara linier tanpa mengevaluasi atau menduplikasi kontainer perantara (*intermediate vectors*).
- **Semantik Referensi (Non-Owning)**: Seluruh *view* tidak memiliki (*non-owning*) elemen target. View hanya menyimpan pointer, referensi, atau iterator ke kontainer dasar.
- **Iterator Categories Preservation**: Jika underlying ranges mendukung *Random Access* atau *Contiguous Iterator*, beberapa view (seperti `slide_view` atau `zip_view`) mempropagasi kapabilitas tersebut ke iterator hasil sintesisnya, menjaga kompleksitas waktu akses tetap $\mathcal{O}(1)$.

### 2. Implementasi & Contoh Kasus Nyata

Skenario: Pemrosesan telemetri finansial frekuensi tinggi (*High-Frequency Trading*). Sistem menerima data harga eksekusi (*ticks*), volume perdagangan, dan timestamp. Tugasnya adalah:
1. Menghitung rata-rata bergerak (Moving Average - window size 3).
2. Memaketkan transaksi dalam batch ukuran tetap untuk agregasi I/O.
3. Menampilkan indeks audit untuk deteksi anomali.

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <ranges>
#include <numeric>
#include <iomanip>

int main() {
    // 1. Dataset Dasar (Simulasi Data Pasar)
    const std::vector<double> prices = {100.5, 101.2, 101.8, 100.9, 102.4, 103.1, 102.8};
    const std::vector<int> volumes    = {120,   85,    310,   150,   420,   95,    210};
    const std::vector<std::string> tags = {"T1", "T2", "T3", "T4", "T5", "T6", "T7"};

    std::cout << "=== 1. std::views::zip ===" << '\n';
    // Menggabungkan prices, volumes, dan tags secara sinkron
    for (auto&& [price, vol, tag] : std::views::zip(prices, volumes, tags)) {
        std::cout << "[" << tag << "] Price: " << price << " | Volume: " << vol << '\n';
    }

    std::cout << "\n=== 2. std::views::enumerate ===" << '\n';
    // Audit Trail: Mendapatkan indeks deterministik bersama referensi elemen
    for (auto&& [idx, price] : std::views::enumerate(prices)) {
        std::cout << "Tick #" << idx << ": " << price << '\n';
    }

    std::cout << "\n=== 3. std::views::slide (Moving Average Window = 3) ===" << '\n';
    // Menghasilkan overlapping window untuk smoothing data
    auto moving_windows = prices | std::views::slide(3);
    for (auto&& window : moving_windows) {
        // window adalah subrange berukuran 3
        double sum = std::accumulate(window.begin(), window.end(), 0.0);
        double ma = sum / std::ranges::distance(window);
        std::cout << "SMA (3-ticks): " << std::fixed << std::setprecision(2) << ma << '\n';
    }

    std::cout << "\n=== 4. std::views::chunk (Batching) ===" << '\n';
    // Mengelompokkan transaksi per 3 batch untuk dikirim ke network/disk
    auto batched_prices = prices | std::views::chunk(3);
    for (auto&& [batch_id, batch] : std::views::enumerate(batched_prices)) {
        std::cout << "Batch " << batch_id << " (Size " << std::ranges::distance(batch) << "): ";
        for (double p : batch) {
            std::cout << p << " ";
        }
        std::cout << '\n';
    }

    std::cout << "\n=== 5. Pipeline Komposisi Tingkat Lanjut ===" << '\n';
    // Pipeline: Zip -> Enumerate -> Slide
    // Menghitung delta total volume berurutan dari pasangan ter-zip
    auto zipped_data = std::views::zip(prices, volumes);
    auto sliding_pairs = zipped_data | std::views::slide(2);

    for (auto&& pair_window : sliding_pairs) {
        // pair_window berisi 2 elemen zip [tick_t, tick_t+1]
        auto [price_t0, vol_t0] = pair_window[0];
        auto [price_t1, vol_t1] = pair_window[1];

        double val_delta = (price_t1 * vol_t1) - (price_t0 * vol_t0);
        std::cout << "Notional Shift: " << val_delta << '\n';
    }

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Iterator Synthetic Tuple (`zip_view`)**: Iterator dari `zip_view` membungkus `std::tuple` yang beranggotakan iterator-iterator dari masing-masing range input (`std::tuple<ranges::iterator_t<Views>...>`). Saat operator `++` dipanggil pada zip iterator, compiler menghasilkan instruksi assembly tunggal untuk meng-inkremen seluruh iterator internal secara serempak. Resolusi dereferensi (`operator*`) menghasilkan `std::tuple<Args&...>` berupa rvalue tuple yang memegang lvalue reference ke elemen asli.
- **Subrange Materialization (`chunk` vs `slide`)**:
  - `views::slide` mengevaluasi window dengan mempertahankan dua iterator internal: `current` dan `last = current + N`. Jika underlying iterator adalah *random_access*, perhitungan jarak window adalah $\mathcal{O}(1)$.
  - `views::chunk` memiliki dua strategi implementasi internal tergantung *iterator concept*: untuk *forward iterator*, chunking membutuhkan status cache (*caching iterator*) untuk menyimpan posisi akhir chunk saat ini agar iterasi chunk berikutnya tidak mengulang traversal ($\mathcal{O}(N)$ amortized).

#### Alokasi Memori / Resource
- **Zero-Allocation**: Seluruh adaptor (`zip`, `chunk`, `slide`, `enumerate`) beroperasi secara eksklusif di stack. Objek view hanya mengonsumsi memori sebesar ukuran iterator dan integer/sentinel batasnya (umumnya berkisar 16–48 byte, tergantung arsitektur dan range underlying).
- Tidak ada panggilan ke `malloc` atau *heap allocator* kecuali pengguna secara eksplisit mematerialisasi data ke kontainer lain (misalnya menggunakan `std::ranges::to<std::vector>()`).

#### Trade-offs
- **Beban Template Instantiation (Compile-time)**: Pipeline ranges yang panjang menghasilkan instansiasi template yang sangat dalam. Simbol mangling compiler membengkak, meningkatkan konsumsi RAM compiler dan memperlambat build time.
- **Optimization Barriers**: Optimasi auto-vektorisasi (SIMD) oleh compiler (seperti GCC/Clang) terkadang terhambat pada `zip_view` dibanding loop pointer raw primitif bertipe array of structures (AoS) karena kompleksitas dependency analysis pada tuple of references.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Structured Binding (`auto&& [a, b]`)**: Selalu gunakan forwarding reference (`auto&&`) saat mengekstrak elemen dari `views::enumerate` atau `views::zip` untuk menghindari penyalinan (*copy overhead*) yang tidak disengaja.
- **Kombinasikan dengan `std::ranges::to`**: Jika hasil transformasi lazy perlu di-*cache* atau dikirim ke API berbasis kontainer konvensional, gunakan materialisasi C++23:
  ```cpp
  auto materialized = prices | std::views::slide(3) | std::ranges::to<std::vector<std::vector<double>>>();
  ```

#### Don'ts
- **Hindari Mengikat Rvalue Sementara (Dangling References)**: `std::views` tidak memperpanjang masa hidup (*lifetime extension*) kontainer temporer.
  ```cpp
  // CRITICAL BUG: Undefined Behavior!
  auto bad_view = std::vector{1, 2, 3, 4} | std::views::chunk(2);
  // Vector temporer langsung hancur di akhir ekspresi titik koma!
  // Mengakses bad_view di baris ini menyebabkan dangling reference.
  ```
- **Hindari Mutasi Ukuran Kontainer Asli Saat Iterasi**: Mengubah kapasitas kontainer underlying (misal memanggil `push_back()` pada `std::vector`) saat sedang diiterasi melalui `slide` atau `zip` akan memicu *iterator invalidation*, memicu segfault atau *memory corruption*.

#### Edge Cases
- **Ukuran Asimetris pada `zip`**: `views::zip` memotong panjang sekuens mengikuti range dengan ukuran terkecil. Jika Range A berukuran 1000 dan Range B berukuran 3, loop hanya berjalan 3 kali. Jika asimetri ini tidak diinginkan, lakukan validasi assert sebelum pipeline dipanggil.
- **Underflow pada `views::slide`**: Jika input range memiliki panjang $M$ di mana $M < N$ ($N$ adalah ukuran sliding window), `views::slide` tidak melempar eksepsi runtime melainkan menghasilkan range kosong (ukuran 0).

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Expiry Window Metric**: Buat pipeline C++23 menggunakan `views::zip` dan `views::slide(2)` untuk menghitung *volatilitas logaritmik* antara tick berturut-turut:
   $$\text{return}_t = \ln\left(\frac{P_t}{P_{t-1}}\right)$$
   Pastikan kode tidak mengalokasikan vektor baru dan aman dari pembagian dengan nol.
2. **Batch Matrix Serialization**: Buat fungsi yang menerima `std::vector<uint8_t>` flat berukuran $H \times W$, kemudian gunakan `views::chunk(W)` dikombinasikan dengan `views::enumerate` untuk mencetak koordinat piksel `(Y, X)` dan representasi heksadesimal setiap byte baris demi baris secara deklaratif murni tanpa nested raw loop `for (int i...)`.
