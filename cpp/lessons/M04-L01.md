## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Function Templates adalah fondasi dari *Generic Programming* dalam C++. Fitur ini memungkinkan penulisan algoritma yang independen terhadap tipe data tanpa mengorbankan *type safety* maupun performa *runtime*. 

Berbeda dengan mekanisme polimorfisme berbasis pewarisan (*runtime polymorphism* via *virtual table* / `vptr`), template bekerja secara *compile-time polymorphism* (atau *static polymorphism*). Di C++, template bukan merupakan kode yang langsung dieksekusi, melainkan sebuah **cetak biru (blueprint)** yang digunakan oleh compiler untuk menghasilkan fungsi konkret melalui proses yang disebut **Template Instantiation**.

```
[Source Code: Function Template]
               │
               ▼ (Template Argument Deduction)
[Compiler: Evaluasi Tipe Argumen]
               │
               ▼ (Monomorphization / Instantiation)
[Generated Function: func<int>()]   [Generated Function: func<double>()]
               │                                    │
               └─────────────────┬──────────────────┘
                                 ▼
                     [Binary / Machine Code]
```

#### Two-Phase Lookup
Proses kompilasi template di C++ terjadi dalam dua fase:
1. **Phase 1 (Definition Time):** Compiler memeriksa sintaks template secara terisolasi tanpa mengetahui tipe konkretnya. Nama-nama non-dependen (*non-dependent names*) diikat dan divalidasi di sini.
2. **Phase 2 (Instantiation Time):** Saat template dipanggil dengan tipe argumen tertentu, compiler melakukan substitusi tipe parameter (*dependent names* diikat) dan menghasilkan kode mesin fungsi spesifik. Jika operasi pada tipe tidak valid (misal: memanggil operator `+` pada tipe yang tidak menyediakannya), error kompilasi akan dipicu pada fase ini.

#### Mekanisme Template Argument Deduction (TAD)
Compiler secara otomatis menyimpulkan (*deduce*) parameter tipe `T` dari argumen ekspresi yang dilewatkan ke parameter fungsi `f(expr)`. Scott Meyers mengklasifikasikan deduksi ini ke dalam tiga skenario struktural utama berdasarkan deklarasi parameter fungsi (`ParamType`):

1. **Kasus 1: `ParamType` adalah Pointer atau Reference (Bukan Universal Reference)**
   * Jika ekspresi memiliki reference, sifat reference diabaikan.
   * `const`-ness dari tipe argumen tetap dipertahankan (*preserved*).
   * Contoh: `template <typename T> void f(const T& param);`
2. **Kasus 2: `ParamType` adalah Universal / Forwarding Reference (`T&&`)**
   * Mengikuti aturan *Reference Collapsing*:
     - `&` + `&` $\to$ `&`
     - `&` + `&&` $\to$ `&`
     - `&&` + `&` $\to$ `&`
     - `&&` + `&&` $\to$ `&&`
   * Jika argumen adalah *lvalue* bertipe `X`, `T` disimpulkan sebagai `X&`, dan `ParamType` menjadi `X&`.
   * Jika argumen adalah *rvalue* bertipe `X`, `T` disimpulkan sebagai `X`, dan `ParamType` menjadi `X&&`.
3. **Kasus 3: `ParamType` adalah Pass-by-Value (`T`)**
   * Terjadi mekanisme *decay*: sifat *reference*, *top-level const*, dan *volatile* dari argumen diabaikan (*dropped*).
   * Array dan pointer fungsi berubah (*decay*) menjadi raw pointer.

C++20 memperkenalkan **Abbreviated Function Templates** menggunakan sintaks `auto` pada parameter fungsi (`void f(auto x);`), yang secara semantik identik dengan deklarasi template eksplisit berkat unifikasi aturan deduksi.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern yang mendemonstrasikan variasi deduksi tipe, *forwarding reference*, serta *abbreviated function template* (C++20).

```cpp
#include <iostream>
#include <string>
#include <type_traits>
#include <utility>

// 1. Pass-by-Value: Mengabaikan top-level const dan reference (Decay)
template <typename T>
void inspectValue(T param) {
    std::cout << "Value Type Deduced: " << typeid(param).name() << '\n';
}

// 2. Pass-by-Reference-to-Const: Menjaga const-correctness tanpa copy overhead
template <typename T>
const T& maxElement(const T& a, const T& b) {
    return (a < b) ? b : a;
}

// 3. Universal / Forwarding Reference: Menjaga Value Category (Lvalue vs Rvalue)
template <typename T>
void relayMessage(T&& msg) {
    // std::forward mempertahankan status lvalue/rvalue dari T
    if constexpr (std::is_lvalue_reference_v<T>) {
        std::cout << "Relaying Lvalue: " << msg << '\n';
    } else {
        std::cout << "Relaying Rvalue: " << std::move(msg) << '\n';
    }
}

// 4. Non-Type Template Parameter (NTTP) + Array Reference Deduction
template <typename T, std::size_t N>
constexpr std::size_t getArrayCapacity(const T (&)[N]) noexcept {
    return N; // Menangkap ukuran fixed-size array secara compile-time
}

// 5. C++20 Abbreviated Function Template (Syntactic Sugar untuk Function Template)
void printConcatenated(const auto& first, const auto& second) {
    std::cout << first << " -> " << second << '\n';
}

int main() {
    // Kasus 1: Value decay
    const int x = 42;
    inspectValue(x); // T disimpulkan sebagai 'int', bukan 'const int'

    // Kasus 2: Reference preservation & explicit argument overrides
    const double d1 = 12.34;
    const double d2 = 56.78;
    std::cout << "Max: " << maxElement(d1, d2) << '\n'; // T disimpulkan sebagai 'double'

    // Ambiguity handling: Tipe tidak cocok
    // maxElement(10, 20.5); // ERROR: Deduce conflict (int vs double)
    auto res = maxElement<double>(10, 20.5); // OK: Explicitly specified

    // Kasus 3: Perfect Forwarding Deduction
    std::string text = "Persistent Buffer";
    relayMessage(text);                     // T disimpulkan sebagai std::string& (Lvalue)
    relayMessage(std::string("Ephemeral")); // T disimpulkan sebagai std::string (Rvalue)

    // Kasus 4: Array Dediction via NTTP
    int rawArray[] = {1, 2, 3, 4, 5, 6};
    std::cout << "Array Size: " << getArrayCapacity(rawArray) << '\n'; // N = 6

    // Kasus 5: C++20 Abbreviated Template
    printConcatenated("Module", 401);

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Monomorphization dan Name Mangling
Compiler C++ mengeksekusi proses **monomorphization**. Jika fungsi template `maxElement<T>` dipanggil dengan `int`, `double`, dan `std::string`, compiler menghasilkan 3 fungsi mesin terpisah dalam binary:
- `maxElement<int>` $\to$ Target instruksi assembler aritmatika integer.
- `maxElement<double>` $\to$ Target register SSE/AVX (misal: `xmm0`).
- `maxElement<std::string>` $\to$ Target instruksi pointer heap & copy operator.

Pada level linker, setiap instansiasi template memiliki nama unik melalui mekanisme **Name Mangling**.
- Sebagai contoh, fungsi `inspectValue(int)` di bawah ABI Itanium (Linux/GCC/Clang) dapat dimangle menjadi:
  `_Z12inspectValueIiEvT_`
  - `_Z`: Prefix simbol GCC mangled.
  - `12`: Panjang nama fungsi (`inspectValue`).
  - `I`: Parameter template dimulai.
  - `i`: Tipe parameter template (`int`).
  - `E`: Penutup parameter template.
  - `v`: Tipe kembalian `void`.
  - `T_`: Argumen fungsi menggunakan parameter template pertama.

#### Alokasi Memori & Resource
- **Instruction Cache (I-Cache) Pressure:** Instansiasi template yang eksesif untuk banyak tipe yang berbeda dapat menyebabkan **code bloat**. Binary membesar secara drastis, meningkatkan kemungkinan *I-Cache miss* pada CPU pipeline.
- **Deduplikasi COMDAT:** Compiler modern menempatkan setiap instansiasi fungsi template ke dalam *section* ELF/PE tersendiri yang disebut **COMDAT section**. Jika beberapa file `.o` (translation unit) menginstansiasi template yang sama persis (misal `func<int>`), linker akan secara cerdas membuang duplikasi tersebut dan hanya menyisakan satu salinan kode biner di binary akhir.

#### Trade-offs: Static Dispatch vs Dynamic Polymorphism
| Aspek | Function Template (Static) | Virtual Function (Dynamic) |
| :--- | :--- | :--- |
| **Overhead Runtime** | **0% (Zero)**. Dapat di-inlining oleh compiler secara agresif. | Indirection cost (~2-3 clock cycles via vtable ptr lookup). Inlining sulit dilakukan. |
| **Ukuran Binary** | Berpotensi besar (*code bloat* jika banyak variasi tipe diinstansiasi). | Lebih kecil dan terprediksi; hanya ada satu fungsi biner terkompilasi. |
| **Kompilasi** | Jauh lebih lambat karena compiler menganalisis AST berulang kali. | Cepat; implementasi dipisahkan ke Translation Unit (`.cpp`). |
| **Binding Time** | Compile-time. Tipe harus sudah diketahui saat kompilasi. | Runtime. Tipe dapat diselesaikan saat runtime (misal via plugin/DLL). |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Forwarding Reference (`T&&`) + `std::forward`** saat membuat fungsi wrapper, factory pattern, atau relay function untuk menghindari penyalinan (*unnecessary copies*) objek besar.
- **Manfaatkan C++20 Concepts** untuk membatasi template argument deduction. Menghindari error kompilasi ratusan baris ketika substitusi tipe gagal.
- **Terapkan Pass-by-Value + `std::move`** jika fungsi memang berniat mengambil alih (*consume/sink*) kepemilikan data tersebut.

#### Don'ts
- **Dilarang melakukan *Template Specialization* untuk Function Templates.**
  - Standar ISO C++ menetapkan bahwa Function Template Specialization **tidak berpartisipasi dalam *overload resolution***. Ini sering menghasilkan *unintuitive bug*.
  - **Best Practice:** Gunakan *plain function overloading* daripada spesialisasi.
  ```cpp
  // BURUK: Menghasilkan prioritas overload yang membingungkan
  template <typename T> void process(T val);
  template <> void process<int*>(int* val); 

  // BENAR: Overloading standar
  template <typename T> void process(T val);
  void process(int* val); 
  ```
- **Hindari mendeklarasikan implementasi function template di file `.cpp`.** 
  Karena instansiasi terjadi pada fase kompilasi di tiap *Translation Unit*, pemisahan deklarasi di `.h` dan definisi di `.cpp` akan menghasilkan error **Unresolved External Symbol / LNK2019** di fase link, kecuali Anda melakukan *explicit template instantiation*. Simpan definisi template di dalam header file.

#### Edge Cases
- **Array-to-Pointer & Function-to-Pointer Decay:**
  ```cpp
  template <typename T> void byVal(T x);
  template <typename T> void byRef(T& x);

  int arr[5];
  byVal(arr); // T disimpulkan sebagai 'int*' (Decay)
  byRef(arr); // T disimpulkan sebagai 'int[5]' (Tipe array dan ukuran preserved)
  ```
- **Deduksi `std::initializer_list` Gagal pada Template Murni:**
  ```cpp
  template <typename T> void deduce(T x);
  // deduce({1, 2, 3}); // ERROR: Compiler tidak dapat menyimpulkan initializer_list secara implisit
  
  template <typename T> void deduceExplicit(std::initializer_list<T> x);
  deduceExplicit({1, 2, 3}); // OK: T disimpulkan sebagai int
  ```

### 5. Tantangan Eksplorasi Mandiri

1. **Analisis Dekonstruksi ASM (Compiler Explorer):**
   Buka [Compiler Explorer (godbolt.org)](https://godbolt.org). Masukkan fungsi template sederhana `template <typename T> T multiply(T a, T b) { return a * b; }`. Instansiasi fungsi tersebut dengan tipe `int`, `float`, dan tipe bentukan kustom (misal: `struct Matrix`). Amati instruksi assembly yang dihasilkan (seperti `imul` vs `vmulss`). Identifikasi bagaimana COMDAT membuang kode duplikat.
2. **Compile-Time String Literal Length Extractor:**
   Buat function template yang menggunakan *reference to array of characters* (`const char (&)[N]`) sebagai parameter untuk mengembalikan panjang string literal secara *compile-time* (`constexpr`) tanpa memanggil `strlen` di runtime.
3. **Penyelidikan Bug Spesialisasi vs Overloading:**
   Tulis program yang mendemonstrasikan kegagalan pemanggilan spesialisasi template akibat interaksinya dengan *base template overload*. Analisis mengapa C++ Core Guidelines melarang spesialisasi function templates.
