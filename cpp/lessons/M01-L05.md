## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Fungsi di dalam C++ bukan sekadar blok kode yang dapat dipanggil kembali (*callable code block*), melainkan unit fundamental abstraksi yang berinteraksi langsung dengan *Application Binary Interface* (ABI), konvensi pemanggilan (*calling convention*), dan sistem tipe (*type system*) statis yang ketat.

#### Semantik Parameter Passing
Pemilihan cara melewatkan data ke dalam fungsi menentukan alokasi register, *cache locality*, dan overhead siklus CPU:
1. **Pass-by-Value**: Objek diduplikasi menggunakan *copy constructor* (atau *move constructor* jika rvalue). Tipe primitif (seperti `int`, `double`, pointer) yang muat dalam register CPU (misalnya arsitektur x86-64 System V ABI yang menggunakan register `RDI`, `RSI`, `RDX`, `RCX`, `R8`, `R9`) sangat optimal dilewatkan via *value*.
2. **Pass-by-Reference (`Type&` dan `const Type&`)**: Mencegah proses duplikasi memori dengan melewatkan alamat memori objek yang sudah ada tanpa sintaksis pointer eksplisit. Di balik layar, compiler biasanya merepresentasikan referensi sebagai *pointer* konstan yang di-dereferensi otomatis. `const Type&` memperluas masa hidup (*lifetime extension*) dari nilai *temporary* (rvalue) hingga akhir *scope* fungsi pemanggil.
3. **Pass-by-Rvalue Reference (`Type&&`)**: Memungkinkan fungsi "mencuri" (*steal*) sumber daya dari objek sementara tanpa alokasi memori dinamis baru (*move semantics*).

#### Overload Resolution & Name Mangling
C++ mendukung polimorfisme statis melalui *Function Overloading*, di mana beberapa fungsi berbagi nama yang sama namun memiliki tanda tangan tipe (*type signature*) berbeda. 
- **Name Mangling**: Karena *linker* tradisional (seperti GNU `ld` atau LLVM `lld`) hanya memahami simbol nama unik tanpa konsep overload, compiler C++ mengodekan tipe parameter dan *namespace* ke dalam nama simbol fungsi di tabel simbol (misalnya, fungsi `void print(int)` dapat di-mangle oleh compiler GCC/Clang menjadi `_Z5printi`).
- **Overload Resolution Process**: Terjadi pada fase kompilasi dalam tiga tahap:
  1. *Candidate Functions*: Mengumpulkan semua fungsi dengan nama yang cocok dalam *scope*.
  2. *Viable Functions*: Menyaring fungsi yang jumlah argumennya sesuai dan memiliki konversi tipe yang valid.
  3. *Best Viable Function*: Menentukan pemenang berdasarkan *Standard Conversion Sequence ranking* (Exact match > Promotion > Standard conversion > User-defined conversion). Jika ada dua fungsi dengan peringkat konversi yang identik, compiler melempar kesalahan *ambiguous call*.

#### Evaluasi Waktu Kompilasi: `constexpr`
Keyword `constexpr` (diperkenalkan pada C++11, diperluas secara masif di C++14/C++17/C++20) menginstruksikan compiler bahwa fungsi atau variabel memiliki kapabilitas untuk dievaluasi sepenuhnya pada waktu kompilasi (*compile-time*), asalkan seluruh argumennya merupakan *constant expressions*.
- **C++11 vs Modern C++**: Pada C++11, fungsi `constexpr` hanya boleh berisi satu *return statement*. Sejak C++14 ke atas, batasan tersebut dihapus; fungsi `constexpr` kini dapat memiliki loop, variabel lokal, percabangan (`if`/`switch`), dan bahkan alokasi dinamis transien (C++20).
- **Dualitas Eksekusi**: Fungsi `constexpr` bersifat fleksibel: jika dipanggil dengan parameter non-konstan di runtime, fungsi tersebut akan dikompilasi dan dieksekusi sebagai instruksi assembly runtime biasa tanpa overhead tambahan.

### 2. Implementasi & Contoh Kasus Nyata

Kode berikut mendemonstrasikan kombinasi strategi parameter, *function overloading*, serta kalkulasi *compile-time* via `constexpr` untuk validasi dan komputasi metrik performa.

```cpp
#include <iostream>
#include <string_view>
#include <array>
#include <cstdint>

// 1. Compile-time CRC32 hashing menggunakan fungsi constexpr
constexpr uint32_t generate_crc32(std::string_view data) noexcept {
    uint32_t crc = 0xFFFFFFFF;
    for (char c : data) {
        crc ^= static_cast<uint8_t>(c);
        for (int i = 0; i < 8; ++i) {
            crc = (crc >> 1) ^ (0xEDB88320 & (-(crc & 1)));
        }
    }
    return ~crc;
}

// 2. Overloading & Parameter Semantics
struct HeavyPayload {
    int id;
    double metrics[100];
};

// Overload A: Menerima primitive via Value (optimal via CPU register)
void process(int code) {
    std::cout << "[Overload: int] Code: " << code << '\n';
}

// Overload B: Menerima objek besar via Const Reference (mencegah copy 808 bytes)
void process(const HeavyPayload& payload) {
    std::cout << "[Overload: const HeavyPayload&] ID: " << payload.id << '\n';
}

// Overload C: Menerima std::string_view via Value (16-byte struct: pointer + size)
// Lebih efisien daripada const std::string& untuk read-only string
void process(std::string_view text) {
    std::cout << "[Overload: string_view] Content: " << text << '\n';
}

int main() {
    // Eksekusi Compile-time: Evaluasi terjadi di AST compiler
    // Tidak ada instruksi loop generate_crc32 yang masuk ke file binary runtime!
    constexpr uint32_t compile_time_hash = generate_crc32("SYSTEM_INIT_KEY");
    
    // Eksekusi Runtime dari fungsi constexpr yang sama
    std::string runtime_input = "DYNAMIC_KEY";
    uint32_t runtime_hash = generate_crc32(runtime_input);

    std::cout << "Compile-time CRC32: 0x" << std::hex << compile_time_hash << '\n';
    std::cout << "Runtime CRC32:      0x" << std::hex << runtime_hash << std::dec << '\n';

    // Pengujian Overload Resolution
    HeavyPayload data{101, {0.0}};
    process(42);                      // Memilih Overload A
    process(data);                    // Memilih Overload B
    process("Literal String C-Style");// Memilih Overload C (implicit convert ke string_view)

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Mekanisme Stack Frame
Ketika fungsi runtime dipanggil:
1. **Prologue**: CPU memodifikasi *Stack Pointer* (`RSP`) dan *Base Pointer* (`RBP`). Register caller-saved diselamatkan ke stack jika nilainya masih diperlukan.
2. **Passing Arguments**: ABI modern (misalnya System V AMD64 untuk Linux/macOS) melewatkan hingga 6 argumen integer/pointer lewat register (`RDI`, `RSI`, dll.) dan floating point lewat register SIMD (`XMM0`-`XMM7`). Jika argumen melebihi kapasitas register atau bertipe agregat besar yang tidak muat, argumen di-*push* ke stack memory.
3. **Epilogue**: Nilai kembalian diletakkan di register `RAX`/`RDX`, stack di-*unwind* (`RSP` dikembalikan ke posisi semula), dan instruksi `RET` mengambil alamat kembali (*return address*) dari stack untuk melompat kembali ke pemanggil.

#### Alokasi Memori: `constexpr` vs Runtime
- **Runtime Execution**: Variabel dialokasikan di *Call Stack Frame* atau *Heap*. Evaluasi logika menghabiskan siklus CPU dan *power* secara berulang setiap kali fungsi dieksekusi.
- **`constexpr` Execution**: Dievaluasi oleh *Constant Evaluator* interpreter yang tertanam di dalam compiler (misal Clang AST Interpreter). Hasilnya langsung di-*embed* ke dalam *read-only data section* (`.rodata`) dari file ELF/PE atau langsung dikonversi menjadi operan literal (*immediate value*) pada instruksi assembly (contoh: `MOV EAX, 0x5F3759DF`).

#### Trade-offs & Overhead
- **`constexpr`**:
  - *Kelebihan*: Zero-cost runtime overhead, membuka peluang optimasi *Dead Code Elimination* secara agresif.
  - *Kekurangan*: Meningkatkan waktu kompilasi (*build-time*) dan konsumsi memori compiler secara signifikan jika melibatkan algoritma rekursif atau pemrosesan array besar.
- **Inlining**: Compiler dapat memilih untuk menghapus overhead pemanggilan fungsi via *inlining*, namun inlining berlebih pada fungsi besar menyebabkan *instruction-cache misses* (*code bloat*).

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `std::string_view` atau `std::span` by-value** untuk parameter read-only sekuensial dibanding `const std::string&` atau `const std::vector<T>&`, untuk mencegah alokasi memori yang tidak perlu dan meningkatkan fleksibilitas input.
- **Terapkan `constexpr` secara agresif** pada fungsi murni (*pure functions*) yang tidak memiliki *side-effects* ke sistem I/O atau global state.
- **Manfaatkan `noexcept`** pada fungsi-fungsi kecil atau operasi utilitas; ini memberi petunjuk bagi compiler untuk tidak menghasilkan tabel *exception unwinding* yang kompleks.

#### Don'ts
- **Jangan mengembalikan referensi ke variabel lokal (`dangling reference`)**:
  ```cpp
  // FATAL BUG: Undefined Behavior
  const int& get_local_ref() {
      int local = 42;
      return local; // 'local' hancur saat fungsi keluar dari stack!
  }
  ```
- **Jangan melewatkan tipe primitif menggunakan `const T&`**:
  `const int&` membutuhkan alamat memori fisik, sering kali memaksa compiler menaruh nilai ke memori lalu membaca pointer, alih-alih meletakkannya langsung di dalam register CPU (kalah performa dari `int` by-value).

#### Edge Cases & Pitfalls
- **Overload Ambiguity via Implicit Numeric Conversion**:
  ```cpp
  void log_data(int val);
  void log_data(double val);

  // Error kompilasi: Call to 'log_data' is ambiguous
  log_data(3.14f); // float bisa dikonversi sama validnya ke int maupun double
  ```
- **Default Arguments & Virtual Functions**: Default arguments diselesaikan secara *statis* pada saat kompilasi berdasarkan tipe pointer/referensi deklaratif, bukan tipe objek *polimorfik* konkret di runtime. Hindari meng-override fungsi virtual dengan default argument yang berbeda di *derived class*.

### 5. Tantangan Eksplorasi Mandiri

1. **Inspeksi Assembly Compiler Explorer (Godbolt)**:
   Buka [godbolt.org](https://godbolt.org/). Masukkan fungsi `generate_crc32` di atas. Bandingkan assembly yang dihasilkan antara pemanggilan `constexpr auto x = generate_crc32("test");` melawan pemanggilan runtime `generate_crc32(argv[1]);`. Perhatikan letak hasil kalkulasi pada baris assembly.
2. **Implementasi `consteval`**:
   Ubah fungsi kalkulasi matematika kompleks (misalnya faktorial atau bilangan Fibonacci) menjadi `consteval` (C++20). Buktikan bahwa compiler menolak kompilasi jika fungsi tersebut dipanggil menggunakan argumen variabel non-konstan dari input `std::cin`.
3. **Mengatasi Overload Resolution SFINAE/Concept**:
   Buat dua fungsi bernama `serialize`: satu menerima kontainer yang memiliki method `.size()`, dan satu lagi menerima tipe primitif angka. Gunakan teknik *overload resolution* C++20 `requires` (*Concepts*) untuk memisahkan kedua overload tersebut tanpa ambigu.
