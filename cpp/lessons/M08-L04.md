## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam C++ modern (sejak C++11), paradigma konkurensi bergeser dari *Thread-based concurrency* (`std::thread`) menuju *Task-based concurrency*. Abstraksi ini menyembunyikan manajemen thread tingkat rendah dan berfokus pada "apa yang ingin dieksekusi" (Task) dan "bagaimana mendapatkan hasilnya" (Future).

Arsitektur ini dibangun di atas konsep **Shared State** (State Bersama) yang bertindak sebagai jembatan komunikasi asinkron antara *Producer* (yang mengeksekusi tugas) dan *Consumer* (yang membutuhkan hasil).

Komponen utama dalam ekosistem ini:
1.  **`std::future<T>`**: Representasi dari nilai (atau exception) yang belum tersedia, tetapi akan ada di masa depan. Bertindak sebagai *Consumer*.
2.  **`std::promise<T>`**: Mekanisme tingkat rendah untuk secara manual menaruh nilai atau exception ke dalam *Shared State*. Bertindak sebagai *Producer*.
3.  **`std::packaged_task<T>`**: Wrapper (pembungkus) untuk *Callable* (fungsi, lambda, functor) yang secara otomatis mengikat hasil eksekusinya ke dalam *Shared State* yang bisa diakses via `std::future`.
4.  **`std::async`**: Fungsi utilitas tingkat tinggi yang menerima *Callable*, mengeksekusinya secara asinkron (atau *deferred*), dan langsung mengembalikan `std::future`.

**Launch Policies pada `std::async`:**
-   `std::launch::async`: Memaksa eksekusi di thread baru yang terpisah.
-   `std::launch::deferred`: Evaluasi malas (*lazy evaluation*). Fungsi tidak dieksekusi sampai `future.get()` atau `future.wait()` dipanggil, dan dieksekusi di thread yang memanggilnya (sinkron).
-   *Default* (jika tidak dispesifikasikan): Implementasi bebas memilih antara keduanya (biasanya bergantung pada ketersediaan resource thread).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi yang mendemonstrasikan penggunaan `std::async`, `std::promise`, dan `std::packaged_task`.

```cpp
#include <iostream>
#include <future>
#include <thread>
#include <chrono>
#include <numeric>
#include <vector>

// Simulasi komputasi berat
int heavy_computation(int start, int end) {
    std::cout << "[Task] Berjalan di thread: " << std::this_thread::get_id() << "\n";
    int sum = 0;
    for (int i = start; i <= end; ++i) {
        sum += i;
        std::this_thread::sleep_for(std::chrono::milliseconds(1)); // simulasi delay
    }
    return sum;
}

void promise_worker(std::promise<int>&& prom, int a, int b) {
    try {
        if (b == 0) throw std::runtime_error("Division by zero!");
        std::this_thread::sleep_for(std::chrono::seconds(1));
        prom.set_value(a / b); // Memasukkan hasil ke shared state
    } catch (...) {
        prom.set_exception(std::current_exception()); // Menangkap dan melempar exception ke future
    }
}

int main() {
    std::cout << "[Main] Thread utama: " << std::this_thread::get_id() << "\n\n";

    // --- 1. Menggunakan std::async ---
    std::cout << "--- std::async ---\n";
    // Praktik terbaik: Selalu gunakan std::launch::async jika ingin jaminan asinkron
    std::future<int> async_result = std::async(std::launch::async, heavy_computation, 1, 500);
    
    std::cout << "[Main] Melakukan pekerjaan lain sambil menunggu std::async...\n";
    // get() akan memblokir thread utama sampai hasil tersedia
    std::cout << "[Main] Hasil std::async: " << async_result.get() << "\n\n";

    // --- 2. Menggunakan std::promise dan std::future ---
    std::cout << "--- std::promise & std::future ---\n";
    std::promise<int> div_promise;
    std::future<int> div_future = div_promise.get_future();
    
    // std::promise tidak bisa di-copy, harus di-move
    std::thread t1(promise_worker, std::move(div_promise), 100, 5);
    
    std::cout << "[Main] Menunggu hasil std::promise...\n";
    std::cout << "[Main] Hasil pembagian: " << div_future.get() << "\n\n";
    t1.join();

    // --- 3. Menggunakan std::packaged_task ---
    std::cout << "--- std::packaged_task ---\n";
    std::packaged_task<int(int, int)> task(heavy_computation);
    std::future<int> task_future = task.get_future();
    
    // Task bisa dieksekusi di thread terpisah
    std::thread t2(std::move(task), 501, 1000);
    
    std::cout << "[Main] Hasil std::packaged_task: " << task_future.get() << "\n";
    t2.join();

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: 
  Ketika `std::async` dipanggil dengan `std::launch::async`, runtime C++ akan meminta OS untuk membuat thread baru (atau mengambil dari *internal thread pool* milik implementasi STL). Jika `future.get()` dipanggil sebelum thread selesai, thread pemanggil akan di-suspend (masuk ke *wait queue*) menggunakan mekanisme internal mirip `std::condition_variable` hingga *Shared State* ditandai sebagai *ready*.
- **Alokasi Memori / Resource**: 
  *Shared State* tidak disimpan di dalam objek `std::future` atau `std::promise`. Ia dialokasikan secara dinamis di **Heap** (menggunakan *reference counting*). `std::future` dan `std::promise` hanyalah *handle* (pointer) yang menunjuk ke *Shared State* tersebut. Ketika kedua *handle* dihancurkan, memori *Shared State* akan di-dealokasi.
- **Trade-offs**: 
  Task-based concurrency (`std::async`) memiliki *overhead* alokasi heap untuk *Shared State* dibandingkan dengan `std::thread` murni. Namun, ia memberikan keamanan tipe (*type safety*) untuk nilai kembalian dan propagasi exception antar thread yang sangat sulit dilakukan secara manual dengan `std::thread`.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Selalu spesifikasikan *launch policy* pada `std::async`. Jika Anda mengandalkan default, kode Anda mungkin berjalan secara sinkron tanpa Anda sadari jika sistem kehabisan resource thread.
  - Gunakan `std::shared_future` jika hasil dari satu task perlu dibaca oleh banyak thread (*multiple consumers*). `std::future::get()` hanya bisa dipanggil satu kali (karena ia me-move nilai dari shared state).
  - Tangkap exception saat memanggil `.get()`. Jika task melempar exception, exception tersebut disimpan di *Shared State* dan di-lempar ulang (*re-thrown*) saat `.get()` dipanggil.

- **Don'ts**:
  - **JANGAN mengabaikan nilai kembalian `std::async`**. Ini adalah *pitfall* paling mematikan di C++. Destruktor dari `std::future` yang dikembalikan oleh `std::async` (dengan policy `std::launch::async`) akan **memblokir** (block) sampai task selesai.
    ```cpp
    // SALAH: Ini akan berjalan secara sinkron (blocking)!
    std::async(std::launch::async, heavy_task); 
    // Destruktor temporary future dipanggil di baris ini, memblokir thread.
    ```
  - Jangan memanggil `.get()` lebih dari sekali pada `std::future` yang sama. Ini akan memicu *Undefined Behavior* (biasanya `std::future_error`).

- **Edge Cases**:
  - Jika `std::promise` dihancurkan sebelum `set_value()` atau `set_exception()` dipanggil, `std::future` yang terhubung akan menerima exception `std::future_error` dengan kode `broken_promise`.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Thread Pool Sederhana**: Buatlah sebuah class `ThreadPool` yang memiliki antrean (`std::queue`) berisi `std::packaged_task<void()>`. Gunakan *worker threads* untuk mengambil task dari antrean dan mengeksekusinya.
2. **Simulasi Timeout**: Gunakan `future.wait_for(std::chrono::milliseconds)` untuk menunggu hasil dari `std::async`. Jika melebihi batas waktu (timeout), batalkan operasi atau kembalikan nilai default (Catatan: C++ standar tidak bisa membatalkan thread secara paksa, pikirkan cara menggunakan *atomic flag* untuk memberi sinyal berhenti ke dalam task).
3. **Future Chaining (Monadic Operations)**: C++11/14/17 tidak memiliki `.then()` untuk future. Cobalah buat fungsi pembungkus yang menerima sebuah `std::future<T>` dan sebuah fungsi lanjutan `T -> U`, lalu kembalikan `std::future<U>` menggunakan `std::async` yang menunggu future pertama selesai sebelum menjalankan fungsi lanjutan.
