## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Pada C++20, library Ranges (`std::ranges`) merevolusi manipulasi sekuens data dengan mengabstraksi pasangan iterator `[begin, end)` ke dalam satu entitas konseptual: **Range**. Namun, untuk membangun abstraksi pipeline yang efisien tanpa overhead alokasi dinamis, C++20 memperkenalkan diferensiasi ketat antara Container biasa, `view`, dan `borrowed_range`.

```
                  +---------------------------+
                  |    std::ranges::range     |
                  +-------------+-------------+
                                |
             +------------------+------------------+
             |                                     |
+------------v------------+           +------------v------------+
|        Container        |           |    std::ranges::view    |
| (Owning, O(N) Copy/Dest)|           | (Non-owning / O(1) Copy)|
+-------------------------+           +------------+------------+
             |                                     |
             |       +-----------------------------+
             |       |
+------------v-------v----+
| std::ranges::borrowed_range |  --> Iterator validitasnya melampaui
+-------------------------+      lifetime objek temporer (Rvalue).
```

#### A. Konsep `range` vs `view`
Sebuah tipe memenuhi konsep `std::ranges::range` jika menyediakan titik awal iterasi (`begin()`) dan penanda akhir iterasi (`end()`). Namun, `std::ranges::view` memiliki semantik operasional yang jauh lebih spesifik:
- **Kompleksitas $O(1)$**: Operasi *copy construction*, *move construction*, *copy assignment*, *move assignment*, dan *destruction* harus berjalan dalam kompleksitas waktu konstan ($O(1)$).
- **Semantik Kepemilikan (Ownership)**: Secara umum, sebuah `view` tidak memiliki elemen data yang diiterasinya secara eksklusif (non-owning), atau kepemilikannya dibagikan secara referensial. Container seperti `std::vector<int>` adalah `range`, tetapi **bukan** `view` karena proses destruksi dan copy-nya bernilai $O(N)$. Sebaliknya, `std::span` dan `std::string_view` adalah `view`.

Untuk mempermudah pembuatan custom view, C++20 menyediakan basis CRTP (Curiously Recurring Template Pattern) bernama `std::ranges::view_interface<Derived>`. Kelas basis ini secara otomatis menginjeksi antarmuka seperti `empty()`, `data()`, `size()`, `front()`, `back()`, dan operator indexing `operator[]` jika tipe turunan memenuhi kapabilitas iterator yang sesuai.

#### B. Masalah Dangling Iterator dan `borrowed_range`
Secara default, jika Anda mengambil iterator dari sebuah ekspresi *rvalue* (objek temporer), iterator tersebut berisiko mengalami *dangling* (menunjuk ke memori yang telah didealokasi):

```cpp
auto it = std::ranges::find(std::vector{1, 2, 3}, 2); // Error kompilasi!
// std::ranges::find mengembalikan std::ranges::dangling karena std::vector bukan borrowed_range.
```

Di sinilah konsep `std::ranges::borrowed_range` bekerja. Sebuah tipe $T$ adalah `borrowed_range` jika iterator yang dihasilkan dari instansiasi rvalue $T$ tetap valid meskipun masa hidup objek $T$ telah berakhir.
- Contoh tipe bawaan yang memenuhi: `std::span`, `std::string_view`.
- Iterator dari `borrowed_range` tidak terikat pada *lifetime* container pembungkusnya, melainkan terikat pada buffer data di baliknya.
- Agar tipe kustom kita diakui sebagai `borrowed_range`, kita harus secara eksplisit mengesahkan trait `std::ranges::enable_borrowed_range<CustomType> = true;`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi custom view non-owning yang membaca buffer data kontinu dalam ukuran blok tetap (`chunk_view` sederhana) yang mengimplementasikan `view_interface` dan didaftarkan sebagai `borrowed_range`.

```cpp
#include <iostream>
#include <ranges>
#include <span>
#include <vector>
#include <cassert>

// 1. Definisikan Custom View menggunakan std::ranges::view_interface
template <typename T>
class FixedBlockView : public std::ranges::view_interface<FixedBlockView<T>> {
private:
    const T* m_data{nullptr};
    std::size_t m_blockSize{0};

public:
    // Iterator minimal forward traversal
    class Iterator {
    public:
        using iterator_category = std::forward_iterator_tag;
        using value_type        = std::span<const T>;
        using difference_type   = std::ptrdiff_t;
        using pointer           = void;
        using reference         = std::span<const T>;

    private:
        const T* m_ptr{nullptr};
        std::size_t m_size{0};

    public:
        Iterator() = default;
        Iterator(const T* ptr, std::size_t size) : m_ptr(ptr), m_size(size) {}

        reference operator*() const {
            return std::span<const T>(m_ptr, m_size);
        }

        Iterator& operator++() {
            m_ptr += m_size;
            return *this;
        }

        Iterator operator++(int) {
            Iterator tmp = *this;
            ++(*this);
            return tmp;
        }

        bool operator==(const Iterator& other) const {
            return m_ptr == other.m_ptr;
        }
    };

    // Constructors
    FixedBlockView() = default;
    constexpr FixedBlockView(const T* data, std::size_t totalElements, std::size_t blockSize)
        : m_data(data), m_blockSize(blockSize) {
        assert(blockSize > 0 && "Block size harus lebih besar dari 0");
        assert(totalElements % blockSize == 0 && "Total elemen harus kelipatan block size");
        m_totalBlocks = totalElements / blockSize;
    }

    constexpr auto begin() const { return Iterator(m_data, m_blockSize); }
    constexpr auto end() const { return Iterator(m_data + (m_totalBlocks * m_blockSize), m_blockSize); }

private:
    std::size_t m_totalBlocks{0};
};

// 2. Registrasi eksplisit sebagai borrowed_range
// Memberi tahu compiler: Iterator dari objek temporer FixedBlockView AMAN digunakan.
template <typename T>
inline constexpr bool std::ranges::enable_borrowed_range<FixedBlockView<T>> = true;

// Helper factory function
template <typename T>
auto make_fixed_block_view(const std::vector<T>& vec, std::size_t blockSize) {
    return FixedBlockView<T>(vec.data(), vec.size(), blockSize);
}

int main() {
    std::vector<int> numbers = {10, 20, 30, 40, 50, 60};

    // Penggunaan normal lvalue
    FixedBlockView<int> blocks(numbers.data(), numbers.size(), 2);

    std::cout << "Iterasi blocks melalui Lvalue:\n";
    for (std::span<const int> block : blocks) {
        std::cout << "[ ";
        for (int val : block) {
            std::cout << val << " ";
        }
        std::cout << "]\n";
    }

    // Kasus Rvalue + borrowed_range:
    // Kita memanggil algoritma range pada TEMPORARY FixedBlockView.
    // Jika BUKAN borrowed_range, kembalian begin() akan menghasilkan std::ranges::dangling.
    auto firstBlockIter = std::ranges::begin(make_fixed_block_view(numbers, 2));

    // firstBlockIter BUKAN std::ranges::dangling, dereferensiasi sepenuhnya valid!
    std::span<const int> firstSpan = *firstBlockIter;
    std::cout << "\nElemen pertama blok rvalue: " << firstSpan[0] << ", " << firstSpan[1] << "\n";

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Zero-Cost Abstraction**: `std::ranges::view_interface` menggunakan CRTP. Saat kompilasi, pemanggilan metode seperti `.empty()` langsung didelegasikan ke `begin() == end()`. Tidak ada tabel fungsi virtual (`vtable`), tidak ada pointer dereferencing ganda, dan compiler (seperti GCC/Clang) dapat melakukan inlining secara agresif hingga menjadi operasi perbandingan pointer primitif pada assembly.
- **Sentinel Types**: Konsep Range C++20 membedakan antara tipe *Iterator* (posisi saat ini) dan *Sentinel* (penanda batas akhir). Sentinel tidak harus memiliki tipe data yang sama dengan iterator (`S != I`). Compiler mengevaluasi kondisi berhenti hanya dengan ekspresi `it != sentinel`, menghemat komputasi saat panjang range tidak diketahui di awal (contoh: null-terminated strings).

#### Alokasi Memori / Resource
- Objek `view` dirancang sangat ramping (umumnya hanya menyimpan 1 pointer dan 1 integer/sentinel, sekitar 16–24 byte pada arsitektur 64-bit).
- Karena implementasi di atas adalah *non-owning*, tidak ada alokasi di heap (`malloc`/`new`). Destruksi objek view hanya melepaskan frame stack lokal tanpa melakukan dealokasi buffer data dasar.

#### Cara Compiler Mengevaluasi `borrowed_range`
Saat fungsi seperti `std::ranges::begin(E)` dipanggil:
1. Compiler mengecek ekspresi tipe dari $E$.
2. Jika $E$ adalah ekspresi rvalue (`T&&`), compiler mengecek trait:
   `std::ranges::borrowed_range<std::remove_cvref_t<decltype(E)>>`.
3. Trait tersebut bernilai `true` hanya jika:
   - Tipe adalah lvalue reference (`T&`), ATAU
   - `std::ranges::enable_borrowed_range<T>` bernilai `true`.
4. Jika bernilai `false`, algoritma standar C++20 mengembalikan wrapper `std::ranges::dangling`. Setiap upaya untuk mendereferensiasi objek `dangling` akan memicu kegagalan kompilasi (compile-time assertion failure), mengeliminasi *undefined behavior* memori secara dini.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `view_interface`**: Selalu turunkan custom view dari `std::ranges::view_interface` untuk mendapatkan utilitas API standar secara gratis tanpa menulis boilerplate code berulang.
- **Penuhi Syarat Kompleksitas $O(1)$**: Pastikan copy dan move konstruktor view Anda murni bernilai $O(1)$. Jangan pernah melakukan *deep-copy* elemen data di dalam view.
- **Terapkan Semantik `const` yang Benar**: Pastikan bahwa metode `begin()` dan `end()` pada view bersifat `const` hanya jika operasi iterasi tidak memutasi state internal view tersebut (seperti state caching).

#### Don'ts
- **Jangan Sembarangan Menandai `enable_borrowed_range`**: Jangan pernah mengaktifkan `enable_borrowed_range = true` pada tipe yang menyimpan/memiliki buffer internal (owning container) seperti `std::vector` versi kustom. Hal ini akan menyebabkan *use-after-free* fatal di runtime karena iterator akan menunjuk ke memori yang dihancurkan saat rvalue container mati.
- **Hindari Mengembalikan Iterator ke Member View**: Jika iterator menyimpan pointer atau referensi langsung ke variabel *member* milik view itu sendiri (bukan ke buffer eksternal), view tersebut **bukan** `borrowed_range`.

#### Edge Cases
- **Non-propagating Cache**: Beberapa view bawaan (seperti `std::ranges::filter_view`) tidak memiliki `begin() const` karena mereka men-cache posisi elemen pertama yang lolos predikat saat `begin()` pertama kali dipanggil. View semacam ini tidak thread-safe untuk dibaca secara bersamaan dan **bukan** `borrowed_range`.

### 5. Tantangan Eksplorasi Mandiri

1. **Rancang Custom Step View (Stride)**:
   Buatlah sebuah custom view `StrideView<Range>` yang menerima sembarang forward-range dan sebuah nilai bilangan bulat $N$. View ini harus melompati elemen setiap $N$ langkah. Implementasikan menggunakan `view_interface` dan pastikan bekerja dengan syntax pipeline sederhana: `vec | stride(2)`.
2. **Analisis Iterator Dangling**:
   Hapus spesialisasi template `enable_borrowed_range` dari kode pada Bab 2, lalu amati pesan compiler ketika Anda memanggil:
   ```cpp
   auto it = std::ranges::find(make_fixed_block_view(numbers, 2), ...);
   ```
   Amati bagaimana tipe `std::ranges::dangling` mencegah bug runtime secara statis pada fase kompilasi.
