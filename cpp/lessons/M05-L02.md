## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

`std::unique_ptr` adalah *smart pointer* fundamental dalam C++ modern (diperkenalkan sejak C++11) yang mengimplementasikan konsep **Exclusive Ownership** (Kepemilikan Eksklusif) dan idiom **RAII** (*Resource Acquisition Is Initialization*). 

Secara arsitektur, `std::unique_ptr` menjamin bahwa pada satu waktu, hanya ada **tepat satu** pemilik dari sebuah objek yang dialokasikan di *heap*. Karena kepemilikannya eksklusif, `std::unique_ptr` **tidak dapat disalin (copied)**, melainkan hanya dapat **dipindahkan (moved)**. 

Ketika objek `std::unique_ptr` keluar dari *scope* (ruang lingkup), destruktornya akan secara otomatis dipanggil, yang di belakang layar akan mengeksekusi `delete` pada *raw pointer* yang dikelolanya. Hal ini secara efektif mengeliminasi masalah *memory leak* (kebocoran memori) dan *dangling pointer* yang sering terjadi pada manajemen memori manual di C++ klasik.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi idiomatik penggunaan `std::unique_ptr` untuk mengelola siklus hidup sebuah *resource* (dalam hal ini, koneksi database tiruan).

```cpp
#include <iostream>
#include <memory>
#include <string>

class DBConnection {
public:
    DBConnection(const std::string& dbName) : name(dbName) {
        std::cout << "[ALLOC] Terhubung ke database: " << name << "\n";
    }
    ~DBConnection() {
        std::cout << "[DEALLOC] Memutus koneksi dari: " << name << "\n";
    }
    void query(const std::string& q) {
        std::cout << "Mengeksekusi query: " << q << " di " << name << "\n";
    }
private:
    std::string name;
};

// Fungsi yang mengambil alih kepemilikan (Transfer of Ownership)
void processAndClose(std::unique_ptr<DBConnection> conn) {
    conn->query("SELECT * FROM users");
    // conn akan dihancurkan secara otomatis di akhir fungsi ini
}

// Fungsi yang hanya meminjam resource (Borrowing)
void inspectConnection(const std::unique_ptr<DBConnection>& conn) {
    conn->query("SELECT VERSION()");
}

int main() {
    // 1. Inisialisasi idiomatik menggunakan std::make_unique (C++14)
    auto myDb = std::make_unique<DBConnection>("ProductionDB");
    
    // 2. Meminjamkan resource tanpa memindahkan kepemilikan
    inspectConnection(myDb);

    // auto dbCopy = myDb; // ERROR KOMPILASI: Copy constructor dihapus (deleted)

    // 3. Memindahkan kepemilikan menggunakan std::move
    auto newOwnerDb = std::move(myDb);
    
    if (!myDb) {
        std::cout << "myDb sekarang kosong (null).\n";
    }

    // 4. Memindahkan kepemilikan ke dalam fungsi
    processAndClose(std::move(newOwnerDb));

    std::cout << "Fungsi main selesai.\n";
    return 0;
}
```

**Penjelasan Kode:**
- `std::make_unique<T>(args...)`: Cara paling aman dan direkomendasikan untuk membuat `unique_ptr`. Ini mencegah kebocoran memori jika terjadi *exception* saat evaluasi argumen.
- `std::move(myDb)`: Mengubah *lvalue* menjadi *rvalue*, memicu *move constructor*. `myDb` akan menjadi `nullptr`, dan `newOwnerDb` mengambil alih *pointer* aslinya.
- *Pass-by-value* pada `processAndClose`: Memaksa *caller* untuk menyerahkan kepemilikan.
- *Pass-by-const-reference* pada `inspectConnection`: Fungsi hanya membaca/menggunakan tanpa mengubah siklus hidup objek.

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: Di tingkat kompilator, `std::unique_ptr` secara eksplisit menghapus *copy constructor* dan *copy assignment operator* (`= delete`). Ini membuat pelanggaran kepemilikan eksklusif tertangkap di *compile-time*, bukan *runtime*. Saat *move* terjadi, operasi yang dilakukan hanyalah menyalin alamat memori (pointer) dan meng-set pointer sumber menjadi `nullptr`.
- **Alokasi Memori / Resource**: `std::unique_ptr` adalah contoh sempurna dari **Zero-Cost Abstraction**. Ukuran `std::unique_ptr<T>` di memori sama persis dengan ukuran *raw pointer* (`T*`), yaitu 8 byte pada sistem 64-bit. Objek `unique_ptr` itu sendiri berada di *Stack*, sedangkan data yang ditunjuknya berada di *Heap*.
- **Trade-offs**: Karena tidak ada mekanisme *reference counting* (seperti pada `std::shared_ptr`), `std::unique_ptr` sangat cepat dan hemat memori. *Trade-off*-nya adalah fleksibilitas; Anda tidak bisa membagikan kepemilikan objek ini ke berbagai komponen sistem secara bersamaan.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - **Selalu gunakan `std::make_unique`** daripada `std::unique_ptr<T>(new T())`. Selain lebih bersih, ini menjamin *Exception Safety*.
  - **Kembalikan `std::unique_ptr` dari fungsi (Factory Pattern)** secara langsung (by value). Kompilator C++ akan menggunakan *Return Value Optimization* (RVO) atau *move semantics* secara otomatis.
  - Gunakan *raw pointer* (`T*`) atau referensi (`T&`) sebagai parameter fungsi jika fungsi tersebut hanya perlu "melihat" atau memanipulasi objek tanpa mengambil alih kepemilikannya (jangan gunakan `const std::unique_ptr<T>&` kecuali Anda benar-benar perlu memanipulasi *smart pointer*-nya itu sendiri).

- **Don'ts**:
  - Jangan pernah memanggil `.get()` untuk menyimpan *raw pointer* ke dalam variabel yang siklus hidupnya lebih lama dari `unique_ptr` aslinya. Ini akan menghasilkan *dangling pointer*.
  - Jangan membuat dua `std::unique_ptr` dari *raw pointer* yang sama.
    ```cpp
    int* raw = new int(10);
    std::unique_ptr<int> p1(raw);
    std::unique_ptr<int> p2(raw); // BENCANA! Double free error saat destruksi.
    ```

- **Edge Cases**:
  - **Custom Deleter**: Jika Anda mengelola *resource* non-memori (seperti `FILE*` dari C-API atau *socket*), Anda bisa memberikan *custom deleter*. Namun, perhatikan bahwa jika *deleter* berupa *function pointer*, ukuran `unique_ptr` akan membengkak (tidak lagi *zero-cost*). Gunakan *stateless functor* (struct dengan `operator()`) agar ukurannya tetap sama dengan *raw pointer*.

### 5. Tantangan Eksplorasi Mandiri

1. Buatlah sebuah implementasi struktur data *Singly Linked List* sederhana di mana setiap *Node* memiliki `std::unique_ptr<Node> next`. Amati bagaimana destruksi satu *head node* akan memicu efek domino yang membersihkan seluruh *list* secara otomatis.
2. Integrasikan C-API lama: Gunakan `std::unique_ptr` dengan *custom deleter* untuk mengelola siklus hidup `FILE*` (dari `fopen`). Pastikan `fclose` dipanggil secara otomatis ketika `unique_ptr` keluar dari *scope*, dan buktikan bahwa ukuran `unique_ptr` Anda tetap 8 byte menggunakan `sizeof()`.
