## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam C++, *Templates* memungkinkan kita menulis kode generik (berlaku untuk berbagai tipe data). Namun, seringkali implementasi generik tidak optimal atau bahkan tidak valid untuk tipe data tertentu. Di sinilah **Specialization** (Spesialisasi) dan **Traits** (Karakteristik Tipe) berperan.

*   **Primary Template**: Cetak biru dasar yang menangani tipe data secara umum.
*   **Full Specialization (Spesialisasi Penuh)**: Mengganti seluruh implementasi *template* untuk satu tipe data spesifik (misalnya, khusus untuk `std::string` atau `bool`).
*   **Partial Specialization (Spesialisasi Parsial)**: Mengganti implementasi untuk *subset* dari tipe data (misalnya, khusus untuk semua tipe *pointer* `T*`, atau `std::vector<T>`). **Catatan Arsitektural:** Spesialisasi parsial hanya berlaku untuk *Class/Struct/Variable Templates*, **tidak** untuk *Function Templates*.
*   **Type Traits**: Pola desain (*design pattern*) metaprogramming yang memanfaatkan spesialisasi *template* untuk mengekstrak informasi atau memodifikasi tipe data pada saat kompilasi (*compile-time*). Traits bertindak sebagai "fungsi" yang beroperasi pada tipe data, mengembalikan nilai statis (seperti `true`/`false`) atau tipe data baru.

Secara arsitektur, fitur ini adalah fondasi dari **Metaprogramming** di C++. Kompilator menggunakan aturan *Partial Ordering* untuk menentukan versi *template* mana yang paling spesifik dan cocok dengan argumen tipe yang diberikan saat instansiasi.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah contoh implementasi sistem *Serializer* sederhana yang menunjukkan *Primary Template*, *Full Specialization*, *Partial Specialization*, dan pembuatan *Type Trait* kustom.

```cpp
#include <iostream>
#include <string>
#include <type_traits>

// 1. TYPE TRAIT KUSTOM: Mengecek apakah suatu tipe adalah pointer
template <typename T>
struct is_custom_pointer {
    static constexpr bool value = false; // Default: bukan pointer
};

// Partial Specialization dari Type Trait untuk tipe T*
template <typename T>
struct is_custom_pointer<T*> {
    static constexpr bool value = true;  // Jika T*, maka true
};

// 2. PRIMARY TEMPLATE: Serializer generik
template <typename T>
struct Serializer {
    static void serialize(const T& value) {
        std::cout << "[Generic] Value: " << value << "\n";
    }
};

// 3. FULL SPECIALIZATION: Khusus untuk std::string
template <>
struct Serializer<std::string> {
    static void serialize(const std::string& value) {
        std::cout << "[String] Length: " << value.length() 
                  << ", Content: \"" << value << "\"\n";
    }
};

// 4. PARTIAL SPECIALIZATION: Khusus untuk semua tipe Pointer (T*)
template <typename T>
struct Serializer<T*> {
    static void serialize(T* ptr) {
        if (ptr) {
            std::cout << "[Pointer] Dereferenced: ";
            // Rekursi ke Serializer yang sesuai dengan tipe asli
            Serializer<T>::serialize(*ptr); 
        } else {
            std::cout << "[Pointer] nullptr\n";
        }
    }
};

int main() {
    int number = 42;
    std::string text = "Roadmap.sh";
    int* ptr_number = &number;

    // Menggunakan Type Trait
    std::cout << "Is int a pointer? " 
              << is_custom_pointer<int>::value << "\n"; // 0 (false)
    std::cout << "Is int* a pointer? " 
              << is_custom_pointer<int*>::value << "\n\n"; // 1 (true)

    // Instansiasi Template
    Serializer<int>::serialize(number);       // Memanggil Primary Template
    Serializer<std::string>::serialize(text); // Memanggil Full Specialization
    Serializer<int*>::serialize(ptr_number);  // Memanggil Partial Specialization

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (Monomorphization)**: C++ tidak memiliki *generics* di *runtime* seperti Java (yang menggunakan *Type Erasure*). Kompilator C++ melakukan *Monomorphization*, yaitu menghasilkan kode mesin (assembly) yang sepenuhnya terpisah untuk setiap tipe yang diinstansiasi. Jika Anda memanggil `Serializer<int>` dan `Serializer<double>`, kompilator membuat dua *class* berbeda di *binary* akhir.
- **Resolusi Kompilator (Partial Ordering)**: Saat kompilator melihat pemanggilan `Serializer<int*>`, ia mengumpulkan semua *template* yang tersedia. Ia melihat *Primary* (`T`) dan *Partial* (`T*`). Kompilator menggunakan algoritma *Partial Ordering* untuk memilih yang **paling spesifik**. Karena `T*` lebih spesifik daripada `T`, versi parsial dipilih.
- **Alokasi Memori / Resource**: *Type Traits* (seperti `is_custom_pointer::value`) dievaluasi sepenuhnya pada *compile-time*. Mereka tidak memakan memori di *runtime* (Zero-overhead abstraction). Nilai `true` atau `false` langsung di-*hardcode* ke dalam instruksi mesin.
- **Trade-offs**: Keuntungannya adalah performa *runtime* yang maksimal karena kompilator dapat melakukan *inlining* dan optimasi spesifik tipe. Kerugiannya adalah waktu kompilasi (*compile-time*) yang lebih lama dan potensi *Binary Bloat* (ukuran *executable* membengkak) jika *template* diinstansiasi dengan terlalu banyak tipe berbeda.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan pustaka standar `<type_traits>` (seperti `std::is_pointer_v`, `std::remove_reference_t`) daripada menulis ulang *traits* dasar.
  - Di C++17 ke atas, pertimbangkan menggunakan `if constexpr` di dalam *Primary Template* sebagai alternatif yang lebih mudah dibaca daripada membuat banyak *class specialization*.
  - Di C++20 ke atas, gunakan **Concepts** untuk membatasi *template* alih-alih menggunakan SFINAE (*Substitution Failure Is Not An Error*) dengan *Traits*.
- **Don'ts**:
  - **JANGAN mencoba melakukan Partial Specialization pada Function Template.** Ini ilegal di C++. Gunakan *Function Overloading* atau delegasikan ke *Class Template* statis.
  - Jangan menyembunyikan spesialisasi di file `.cpp`. Spesialisasi harus terlihat (berada di *header*) oleh kompilator saat instansiasi terjadi untuk menghindari pelanggaran *One Definition Rule* (ODR).
- **Edge Cases**:
  - Spesialisasi penuh dari *template* yang berada di dalam *namespace* `std` umumnya dilarang (Undefined Behavior), **kecuali** untuk beberapa kasus khusus yang diizinkan standar, seperti `std::hash<MyCustomType>`.
