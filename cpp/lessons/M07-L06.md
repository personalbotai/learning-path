### 1. Konsep & Arsitektur Mendalam

Evolusi standar C++20 dan C++23 memodernisasi area standard library yang selama beberapa dekade tertinggal: operasi I/O teks, representasi konstanta matematika, dan manipulasi array multidimensi.

```
       Evolusi I/O & Formatting C++
+-----------------------------------------------+
| C (printf)       : Cepat, unsafe, variadic UB |
| C++98 (iostream) : Safe, lambat, stateful I/O |
| C++20 (format)   : Safe, cepat, stateless    |
| C++23 (print)    : Native Unicode, direct OS  |
+-----------------------------------------------+
```

#### A. `std::format` (C++20) dan `std::print` (C++23)
Sebelum C++20, developer terjebak antara dua pilihan kompromistis:
1. `printf`: Sangat cepat, namun tidak *type-safe*, rentan terhadap *buffer overflow*, dan rentan memicu *Undefined Behavior* bila format specifier tidak sinkron dengan tipe data argumen.
2. `std::cout` (`<iostream>`): *Type-safe* dan *extensible*, tetapi memiliki *overhead* performa tinggi akibat virtual dispatch, sinkronisasi locale berulang, sintaks berbelit-belit, dan manipulasi format berbasis *state* (`std::setw`, `std::setprecision`) yang rentan mengotori state output global stream.

C++20 mengadopsi rancangan pustaka `{fmt}` ke dalam `std::format`. Solusi ini mengandalkan:
- **Compile-Time Parsing via `consteval`**: Format string divalidasi pada saat kompilasi menggunakan konstruktor `std::format_string<Args...>`. Kesalahan sintaks specifier menghasilkan compiler error, bukan runtime crash.
- **Stateless formatting**: Setiap formatting call berdiri sendiri tanpa memodifikasi stream context.
- **Type-erasure (`std::make_format_args`)**: Menghindari *template code bloat* dengan mengemas argumen ke dalam array internal berbasis tipe terhapus (*type-erased context*).

C++23 melengkapi ini dengan `<print>` (`std::print` dan `std::println`). Berbeda dari `std::cout << std::format(...)`, `std::print` langsung menulis byte terformat ke file stream C (`stdout`/`FILE*`) tanpa konversi ganda ke intermediate stream buffer C++. Di Windows, `std::print` secara cerdas memanggil API native `WriteConsoleW` jika output stream tersambung langsung ke konsol interaktif, menyelesaikan masalah klasik rendering karakter UTF-8 (*mojibake*) tanpa perlu mutasi code page manual.

#### B. `<numbers>` (C++20)
Sebelum C++20, konstanta matematika mengandalkan macro non-standar POSIX (`M_PI`) yang rentan tabrakan identifier atau template manual yang tidak konsisten. Header `<numbers>` menyediakan *variable templates* dalam namespace `std::numbers` (seperti `pi`, `e`, `inv_sqrt3`, `sqrt2`) dengan kualifikasi `inline constexpr`. Nilainya dihitung dengan presisi maksimum tipe floating-point yang bersangkutan (`float`, `double`, `long double`), menjamin nol *runtime cost*.

#### C. `std::mdspan` (C++23)
`std::mdspan` adalah abstraksi *non-owning multidimensional view* di atas contiguous memory buffer linear (seperti `std::vector`, `std::array`, atau pointer C). 

Konsep intinya memisahkan:
1. **Buffer data asli**: Hanya array 1D kontigu.
2. **Layout mapping policy**: Menentukan pemetaan multi-indeks $(i, j, k)$ ke indeks 1D linear $N$.
   - `std::layout_right` (default / C-style): Indeks terakhir bervariasi paling cepat (row-major).
   - `std::layout_left` (Fortran/MATLAB-style): Indeks pertama bervariasi paling cepat (column-major).
   - `std::layout_stride`: Pemetaan dengan *strides* arbitrary (krusial untuk operasi slicing matrix).
3. **Extents**: Menyimpan batas ukuran dimensi. Dimensi dapat bersifat statis (`std::integral_constant`, nol memory footprint di runtime) atau dinamis (`std::dynamic_extent`).
4. **Accessor policy**: Menentukan cara elemen diakses (misal: read-only, atomic, restricted memory).

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut menunjukkan integrasi `std::format` (termasuk kustomisasi formatter), `std::println`, `<numbers>`, dan pemrosesan matriks berbasis `std::mdspan`.

```cpp
#include <iostream>
#include <vector>
#include <format>
#include <print>
#include <numbers>
#include <mdspan>

// 1. Domain Struct untuk Kustomisasi Formatter
struct GPSCoordinate {
    double latitude;
    double longitude;
    char hemisphere_ns;
    char hemisphere_ew;
};

// 2. Kustomisasi std::formatter untuk GPSCoordinate
template <>
struct std::formatter<GPSCoordinate> {
    // Parse format specifier: mendukung {:s} untuk short, {:f} untuk full
    char presentation = 'f';

    constexpr auto parse(std::format_parse_context& ctx) {
        auto it = ctx.begin();
        auto end = ctx.end();
        if (it != end && (*it == 's' || *it == 'f')) {
            presentation = *it++;
        }
        if (it != end && *it != '}') {
            throw std::format_error("Format specifier GPS tidak valid.");
        }
        return it;
    }

    auto format(const GPSCoordinate& coord, std::format_context& ctx) const {
        if (presentation == 's') {
            return std::format_to(ctx.out(), "{:.2f}{}, {:.2f}{}", 
                                  coord.latitude, coord.hemisphere_ns, 
                                  coord.longitude, coord.hemisphere_ew);
        }
        return std::format_to(ctx.out(), "[Lat: {:.6f}° {}, Lon: {:.6f}° {}]", 
                              coord.latitude, coord.hemisphere_ns, 
                              coord.longitude, coord.hemisphere_ew);
    }
};

int main() {
    // A. Penggunaan std::print dan std::numbers
    constexpr double radius_bumi_km = 6371.0;
    constexpr double radian_per_derajat = std::numbers::pi / 180.0;

    std::println("--- Modern C++ Formatting & Constants ---");
    std::println("Konstanta Pi: {:.10f}", std::numbers::pi_v<double>);
    std::println("Konstanta e:  {:.10f}", std::numbers::e_v<double>);

    GPSCoordinate monas{6.175392, 106.827153, 'S', 'E'};
    std::println("GPS Format Default (Full): {}", monas);
    std::println("GPS Format Ringkas:        {:s}", monas);

    // B. Penggunaan std::mdspan untuk Komputasi Matriks (2D Grid Simulation)
    std::println("\n--- Modern C++23 mdspan ---");
    constexpr size_t ROWS = 3;
    constexpr size_t COLS = 4;

    // Buffer 1D dialokasikan secara kontigu di Heap
    std::vector<double> linear_buffer(ROWS * COLS);

    // Inisialisasi dynamic-extent 2D view di atas vector 1D
    // Mapping default: std::layout_right (Row-Major)
    auto grid = std::mdspan(linear_buffer.data(), ROWS, COLS);

    // Isi matriks menggunakan koordinat multi-indeks
    for (size_t r = 0; r < grid.extent(0); ++r) {
        for (size_t c = 0; c < grid.extent(1); ++c) {
            grid[r, c] = (r * 10.0) + (c * std::numbers::sqrt2);
        }
    }

    // Tampilkan data via mdspan
    for (size_t r = 0; r < grid.extent(0); ++r) {
        std::print("Row {}: ", r);
        for (size_t c = 0; c < grid.extent(1); ++c) {
            std::print("{:8.2f} ", grid[r, c]);
        }
        std::println("");
    }

    // C. Pembuktian Kontiguitas Buffer Bawah
    std::println("\nUnderlying Linear Buffer:");
    for (double val : linear_buffer) {
        std::print("{:.2f} ", val);
    }
    std::println("");

    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Type-Erasure pada `std::format`**: Compiler tidak menginstansiasi template besar untuk keseluruhan format string dan kombinasinya. Argumen diubah menjadi array representasi internal (`std::format_args`) yang berisi pointer data dan tag tipe enum. Fungsi inti runtime (`std::vformat`) adalah fungsi non-template yang menerima string view dan `format_args`. Hal ini menekan *binary size inflation* (code bloat) yang dahulu marak di pustaka berbasis template murni.
- **Direct Terminal I/O pada `std::print`**: `std::print` bypasses overhead formatting `std::locale` dari stream C++. Apabila device target adalah file, data ditulis dalam bentuk UTF-8 langsung ke file descriptor melalui runtime C standard (`fwrite`). Pada Windows, library mendeteksi apakah `stdout` mengarah ke konsol interaktif melalui `GetConsoleMode()`. Jika ya, library memformat ke UTF-8 di buffer stack, mengonversinya ke UTF-16, dan mengeksekusi `WriteConsoleW`, melewati keterbatasan codepage ANSI lokal.

#### Alokasi Memori / Resource
- **Zero Allocation pada `std::mdspan`**: `std::mdspan` memiliki ukuran objek yang sangat kecil. Jika semua dimensi didefinisikan secara statis (`std::extents<size_t, 3, 4>`), ukuran runtime `sizeof(mdspan)` setara dengan satu pointer saja (`sizeof(T*)` = 8 byte pada sistem 64-bit). Tidak ada alokasi heap saat pembuatan view ini.
- Rumus translasi indeks untuk layout default (`layout_right`):
  $$\text{Index}_{1D} = (r \times \text{COLS}) + c$$
  Translasi ini di-*inlining* oleh compiler ke dalam operasi assembly aritmetika `lea` / `imul` standar tanpa runtime overhead.

```
Layout Memory (Contiguous 1D):
[ (0,0) | (0,1) | (0,2) | (1,0) | (1,1) | (1,2) ]
 ^                       ^
 |--- Row 0 (3 elems) ---|--- Row 1 (3 elems) ---
```

#### Trade-offs
- **Compile-Time Cost vs Runtime Speed**: Validasi `consteval` pada format string memperlambat proses kompilasi awal karena compiler harus menginterpretasikan parsing string literal secara compile-time, namun menghasilkan runtime formatting yang setara kecepatannya dengan fungsi C hand-written.
- **View Safety vs Flexibility**: `std::mdspan` adalah view murni tanpa ownership. Jika buffer dasar (misal `std::vector`) mengalami realokasi atau *destruction*, `mdspan` akan mengalami *dangling reference* tanpa mekanisme proteksi runtime bawaan.

### 4. Best Practices & Common Pitfalls

#### Do's
- Gunakan `std::println` sebagai pengganti default untuk seluruh operasi output baris baru konsol. Hal ini meningkatkan performa dan menjamin konsistensi UTF-8 lintas platform.
- Manfaatkan static extents pada `std::mdspan` jika ukuran dimensi sudah diketahui saat kompilasi (`std::extents<size_t, 4, 4>`) untuk memicu optimasi vektorisasi SIMD secara agresif oleh compiler.
- Delegasikan parsing `std::formatter` ke formatter tipe primitif yang sudah ada (misal `std::formatter<std::string_view>`) jika kustomisasi kompleks tidak diperlukan.

#### Don'ts
- Jangan mencetak format string yang ditentukan dinamis dari user input secara langsung ke `std::format(user_str, args...)`. Ini memicu compiler error karena `std::format` mewajibkan format string bersifat `constexpr`. Untuk format string dinamis di C++26 gunakan `std::runtime_format`, atau gunakan `std::vformat` di C++20.
- Jangan mengembalikan `std::mdspan` yang merujuk ke kontainer lokal (stack variable) dari sebuah fungsi; ini merupakan sumber bug *dangling pointer* instan.
- Hindari pemanggilan `std::endl` bersama `std::print`. `std::println` otomatis menyisipkan newline (`\n`) dengan efisiensi flushing I/O yang optimal.

#### Edge Cases
- **Non-contiguous Strides pada Cache Memory**: Berhati-hatilah saat menggunakan `std::layout_left` pada hardware berarsitektur modern dengan data berukuran masif. Jika Anda mengiterasi baris demi baris pada matriks bertipe column-major, Anda akan memicu *cache misses* parah pada L1/L2 cache CPU. Sesuaikan urutan iterasi dengan layout policy yang digunakan.
