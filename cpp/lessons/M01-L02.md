## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

C++ adalah bahasa bertipe statis (*statically typed*) dan berkekuatan tipe kuat (*strongly typed*). Sistem tipe data dalam C++ bukan sekadar mekanisme validasi sintaksis, melainkan fondasi bagaimana kompilator memetakan representasi logis program ke instruksi mesin dan tata letak memori fisik.

#### Sistem Tipe Fundamental dan Portabilitas Arsitektur
C++ membagi tipe data fundamental ke dalam kategori: *integral* (termasuk `bool`, `char`, `int`), *floating-point* (`float`, `double`), dan `void`. Namun, standar C++ tidak menetapkan ukuran biner mutlak untuk tipe-tipe primitif ini, melainkan batas ukuran minimum (misalnya, `int` minimal 16-bit, `long` minimal 32-bit, `long long` minimal 64-bit). 

Perbedaan model data sistem operasi menimbulkan ambiguitas portabilitas:
- **LP64** (Linux/macOS 64-bit): `int` = 32-bit, `long` = 64-bit, pointer = 64-bit.
- **LLP64** (Windows 64-bit): `int` = 32-bit, `long` = 32-bit, `long long` = 64-bit, pointer = 64-bit.

Oleh karena itu, rekayasa perangkat lunak modern menuntut penggunaan tipe biner presisi dari `<cstdint>` (seperti `int32_t`, `uint64_t`, `size_t`) guna menjamin konsistensi representasi memori lintas arsitektur CPU.

```
+-----------------------------------------------------------------+
|                        Data Models (64-bit)                     |
+-------------------+---------+---------+-----------+-------------+
| Model / OS        | short   | int     | long      | pointer     |
+-------------------+---------+---------+-----------+-------------+
| LLP64 (Windows)   | 16-bit  | 32-bit  | 32-bit    | 64-bit      |
| LP64 (Unix/Linux) | 16-bit  | 32-bit  | 64-bit    | 64-bit      |
+-------------------+---------+---------+-----------+-------------+
```

#### Literal dan User-Defined Literals (UDL)
Literal adalah token nilai konstan yang langsung disematkan pada kode sumber. Mulai C++11, literal dapat dikustomisasi melalui *User-Defined Literals* (`operator""`), memungkinkan abstraksi tipe tanpa *overhead* *runtime* (misalnya: `100_ms`, `42_km`). Literal dievaluasi langsung oleh *lexer* dan *parser* kompilator, memberikan keamanan tipe pada level gramatikal bahasa.

#### Deductions: `auto` dan Aturan Penurunan Tipe
Kata kunci `auto` menginstruksikan kompilator untuk mendeduksi tipe variabel berdasarkan ekspresi inisialisasinya pada fase kompilasi. Aturan deduksi `auto` setara dengan aturan *template argument deduction*:
1. **Decay Semantics**: Ketika menggunakan `auto` murni, *constness* teratas (*top-level const*) dan referensi (*reference*) dari ekspresi inisialisasi akan dilepas (*dropped*).
2. **Explicit Qualification**: Menambahkan `const auto&` atau `auto&&` mempertahankan integritas referensi dan kualifikasi konstan.
3. **`decltype(auto)`**: Diperkenalkan pada C++14, mempertahankan tipe referensi dan kualifikator secara presisi tanpa aturan *decay*.

#### Komputasi Waktu Kompilasi: `constexpr` vs `const`
`const` merepresentasikan nilai *read-only* yang dapat ditentukan pada *runtime* (misalnya membaca input pengguna lalu menyimpannya dalam `const int`). Sebaliknya, `constexpr` (C++11/C++14/C++20) menjamin bahwa nilai atau fungsi **harus** dapat dievaluasi secara deterministik pada saat kompilasi (*compile-time evaluation*). 

Kompilator mengintegrasikan mesin penerjemah (*compile-time interpreter*) yang mengeksekusi fungsi `constexpr` dalam batas ruang memori kompilator, memproyeksikan hasil akhir langsung ke tabel konstan biner program (seksi `.rodata`), meniadakan instruksi kalkulasi di CPU saat aplikasi dijalankan.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengilustrasikan interaksi antara tipe data tetap (*fixed-width*), deduksi `auto`, *User-Defined Literals*, dan kalkulasi nilai biner menggunakan `constexpr`.

```cpp
#include <iostream>
#include <cstdint>
#include <array>
#include <string_view>

// 1. User-Defined Literal untuk konversi ukuran data biner
constexpr uint64_t operator"" _KiB(unsigned long long int val) {
    return val * 1024ULL;
}

constexpr uint64_t operator"" _MiB(unsigned long long int val) {
    return val * 1024ULL * 1024ULL;
}

// 2. Evaluasi compile-time murni via constexpr function (C++14/C++17)
constexpr uint32_t compute_crc32(std::string_view data) {
    uint32_t crc = 0xFFFFFFFF;
    for (char c : data) {
        crc ^= static_cast<uint8_t>(c);
        for (int i = 0; i < 8; ++i) {
            crc = (crc >> 1) ^ (0xEDB88320 & (-(crc & 1)));
        }
    }
    return ~crc;
}

int main() {
    // Penggunaan fixed-width types dan literal integer terformat
    constexpr uint64_t buffer_size = 64_KiB; // UDL dievaluasi saat kompilasi
    constexpr uint32_t mem_limit   = 0x7FFF'FFFF; // Digit separator (C++14)

    // Penerapan constexpr: Hasil hash masuk langsung ke .rodata
    constexpr std::string_view payload = "SYSTEM_CRITICAL_PAYLOAD";
    constexpr uint32_t compile_time_hash = compute_crc32(payload);

    // Dynamic vs Type Deduction (auto)
    const int raw_sensor_val = 4096;
    auto decayed_copy = raw_sensor_val;          // Tipe: int (const hilang)
    const auto& ref_sensor = raw_sensor_val;     // Tipe: const int& (referensi dipertahankan)
    
    // Structured binding dengan auto (C++17)
    struct HardwarePort { uint16_t address; bool is_active; };
    HardwarePort com1{0x03F8, true};
    auto [port_addr, status] = com1;             // port_addr: uint16_t, status: bool

    // Output inspeksi
    std::cout << "Buffer Size       : " << buffer_size << " bytes\n";
    std::cout << "Memory Limit      : " << mem_limit << "\n";
    std::cout << "Payload CRC32     : 0x" << std::hex << compile_time_hash << std::dec << "\n";
    std::cout << "COM1 Active       : " << std::boolalpha << status << "\n";

    return 0;
}
```

#### Penjelasan Komponen Kunci:
1. `operator"" _KiB`: Ditandai `constexpr`, kompilator mengganti token `64_KiB` secara langsung dengan bilangan `65536` bertipe `uint64_t`.
2. `compute_crc32`: Beroperasi secara dual-mode. Jika diberikan argumen `constexpr`, fungsi dieksekusi oleh kompilator tanpa menghasilkan instruksi mesin looping pada biner. Jika diberikan variabel dinamis pada *runtime*, fungsi akan dikompilasi sebagai instruksi fungsi CPU reguler.
3. `auto [port_addr, status]`: *Structured binding* mengekstrak elemen `struct` dengan deduksi tipe otomatis tanpa kehilangan keamanan tipe statis.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Constant Folding & Propagation**: Ketika variabel dideklarasikan sebagai `constexpr uint32_t val = compute_crc32(...)`, kompilator membentuk *Abstract Syntax Tree* (AST) dan mengeksekusi logika fungsi di dalam *constant expression engine*. Nilai akhir langsung disubstitusikan ke tempat-tempat di mana variabel tersebut dipanggil, mereduksi instruksi CPU menjadi operasi pemuatan nilai langsung (*immediate value load* seperti `mov eax, 0x<hash>`).
- **Zero-Cost Abstraction**: Variasi `auto` sama sekali tidak menambah beban waktu eksekusi. `auto` murni merupakan fitur bantuan analitis *parser* kompilator (*frontend compiler*) sebelum representasi perantara (*Intermediate Representation* / IR) digenerasi.

#### Alokasi Memori & Tata Letak Biner
- **Seksi `.rodata`**: Nilai literal string (seperti `"SYSTEM_CRITICAL_PAYLOAD"`) dan variabel `constexpr` global dialokasikan pada segmen memori *read-only data* (`.rodata`). Jika ada upaya menulis ulang lokasi memori ini pada waktu eksekusi, OS akan memicu *Memory Protection Fault* (*Segmentation Fault*).
- **Alignment dan Padding**: Tipe data fundamental memiliki batasan *alignment* alami. Sebagai contoh, arsitektur x86_64 mengharuskan `uint32_t` dialokasikan pada alamat kelipatan 4 bita (`alignof(uint32_t) == 4`), dan `uint64_t` pada kelipatan 8 bita. Kompilator menyisipkan *padding bytes* secara otomatis dalam tipe gabungan (*struct/class*) untuk memenuhi batasan arsitektur mikro prosesor.

```
Representasi Padding dalam Struct:
Struct: struct Misaligned { uint8_t a; uint32_t b; };
Memory: [ a (1 byte) ][ Padding (3 bytes) ][ b (4 bytes) ] = 8 bytes total
```

#### Trade-offs
- **Compile-Time Execution vs Build Speed**: Penggunaan algoritma `constexpr` yang kompleks dapat memperlambat fase kompilasi secara signifikan karena kompilator harus menginterpretasikan eksekusi kode dalam lingkungan *single-threaded* tanpa optimasi hardware langsung.
- **`auto` vs Explicit Readability**: Penggunaan `auto` yang berlebihan pada tipe fundamental (`auto x = 5;` -> ambigu apakah signed int, unsigned, atau fixed-width) menurunkan kejelasan kode (*readability*), meskipun sangat bermanfaat pada tipe panjang seperti iterator `std::unordered_map<K, V>::const_iterator`.

### 4. Best Practices & Common Pitfalls

#### Do's
- Gunakan tipe data dengan lebar pasti dari `<cstdint>` (`int32_t`, `uint64_t`) saat berhadapan dengan serialisasi jaringan, manipulasi register perangkat keras, atau data file biner.
- Gunakan `auto` bersama referensi eksplisit (`const auto&`) untuk mencegah penyalinan objek (*deep copy*) yang tidak disengaja.
- Maksimalkan deklarasi `constexpr` untuk semua fungsi murni (*pure functions*) yang parameternya dapat diketahui sebelum eksekusi program.
- Gunakan pemisah digit (`1'000'000`) dan literal berbasis UDL untuk unit fisika/waktu guna meningkatkan ekspresi logika.

#### Don'ts
- **Jangan** mengasumsikan `long` selalu 64-bit pada mesin 64-bit (ingat model LLP64 pada MSVC Windows di mana `sizeof(long) == 4`).
- **Jangan** menggunakan `auto` telanjang saat menginisialisasi dari tipe referensi jika tidak berniat menduplikasi objek:
  ```cpp
  const HeavyObject& obj = get_reference();
  auto copy = obj; // Pitfall: Tipe menjadi HeavyObject, menyalin seluruh data!
  ```
- **Jangan** mencampur operator perbandingan antara tipe signed dan unsigned:
  ```cpp
  int a = -1;
  unsigned int b = 1;
  if (a < b) { /* Secara biner dievaluasi FALSE karena implicit unsigned promotion */ }
  ```

#### Edge Cases & Perilaku Tak Terduga
- **Implicit Integral Promotion**: Tipe integral yang lebih kecil dari `int` (seperti `int8_t`, `uint8_t`, `char`, `short`) secara otomatis dinaikkan (*promoted*) ke `int` ketika operasi aritmetika dijalankan. Hal ini dapat menimbulkan kesalahan kalkulasi overflow tak terduga pada bit-shifting.
- **Narrowing Conversions**: Inisialisasi menggunakan tanda kurung kurawal `{}` (*brace initialization*) memvalidasi *narrowing conversion* pada saat kompilasi:
  ```cpp
  int x = 1000;
  char c1 = x;   // Berhasil dikompilasi, data terpotong secara silent (UB/overflow)
  char c2{x};    // Error kompilasi: narrowing conversion prevented
  ```

### 5. Tantangan Eksplorasi Mandiri

1. **Analisis Dekompilasi / Assembly**:
   Tulis fungsi faktorial sederhana menggunakan `int` biasa, lalu buat varian identik menggunakan `constexpr int`. Jalankan kode tersebut melalui Compiler Explorer (godbolt.org) dengan flag `-O2` menggunakan GCC atau Clang. Temukan di mana instruksi rekursi/perulangan dihilangkan pada output Assembly dan bagaimana nilai langsung dipasok melalui instruksi register.

2. **Deteksi Type Decay**:
   Buat sebuah *template function* pembantu (*type traits helper*) atau gunakan operator `typeid` dan `std::is_same_v` untuk menguji apakah tipe data di bawah ini menghasilkan tipe yang identik atau berbeda:
   - `const int&` dioperasikan ke `auto`
   - `const int&` dioperasikan ke `decltype(auto)`
   - Array primitif `int arr[5]` dioperasikan ke `auto` vs `auto&`. Amatilah transformasi dari *array type* menjadi *pointer type* (*array-to-pointer decay*).
