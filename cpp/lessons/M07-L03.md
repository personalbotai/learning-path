## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum C++20, Standard Template Library (STL) *algorithm* sangat bergantung pada pasangan iterator `[first, last)`. Pendekatan klasik ini memiliki sejumlah kelemahan struktural:
1. **Iterator Mismatch**: Kerentanan *human-error* akibat mencocokkan iterator dari kontainer yang berbeda (misalnya `std::sort(vecA.begin(), vecB.end())`) yang memicu *Undefined Behavior* (UB).
2. **Verbosity**: Kode berulang-ulang mengekspresikan `begin()` dan `end()`.
3. **Komposabilitas Buruk**: Sangat sulit merangkai (*chaining*) transformasi data tanpa alokasi kontainer temporer perantara.
4. **Error Template yang Kriptik**: Jika tipe iterator tidak memenuhi spesifikasi (misalnya memberikan iterator *forward* ke algoritma yang membutuhkan *random-access*), *compiler* memuntahkan ribuan baris pesan *error* template yang sulit dibaca.

C++20 merevolusi paradigma ini melalui **Ranges Library** (`namespace std::ranges`), yang dibangun di atas fondasi **Concepts**.

```
                   +------------------------+
                   |   std::ranges::range   |
                   +-----------+------------+
                               |
              +----------------+----------------+
              |                                 |
    +---------v---------+             +---------v---------+
    | input_range       |             | sized_range       |
    +---------+---------+             +-------------------+
              |
    +---------v---------+
    | forward_range     |
    +---------+---------+
              |
    +---------v---------+
    |bidirectional_range|
    +---------+---------+
              |
    +---------v---------+
    |random_access_range|
    +---------+---------+
              |
    +---------v---------+
    | contiguous_range  |
    +-------------------+
```

#### Arsitektur Inti:
- **Range Concept**: Abstraksi atas objek apa pun yang dapat diiterasi. Minimal mengimplementasikan `ranges::begin()` dan `ranges::end()`.
- **Sentinel**: Konsep pemisahan tipe antara titik awal (`Iterator`) dan titik akhir (`Sentinel`). Iterator dan Sentinel tidak harus bertipe sama asalkan keduanya dapat dikomparasikan (`it != sentinel`). Hal ini memungkinkan pemrosesan *infinite ranges* atau data berbasis terminator (misal: *null-terminated strings*) tanpa perlu mengetahui panjang kontainer di awal.
- **Projections**: Kemampuan algoritma untuk menerima fungsi transformasi unari yang dieksekusi sebelum evaluasi predikat atau komparasi. Proyeksi mengeliminasi kebutuhan menulis *boilerplate lambda* hanya untuk mengekstrak *field* tertentu dari *struct/class*.
- **Constrained Algorithms**: Algoritma di `std::ranges::*` dipagari oleh *Concepts*. Jika tipe kontainer tidak memenuhi syarat (misalnya `std::ranges::sort` pada `std::list`), *compiler* langsung menolak pada fase *concept satisfaction check* dan memberikan diagnosa presisi dalam satu baris, bukan ratusan baris instansiasi template gagal.

### 2. Implementasi & Contoh Kasus Nyata

Kode berikut menunjukkan penggunaan *range algorithms*, penggunaan *projection*, penanganan *sentinel*, serta proteksi *dangling iterator*.

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
#include <ranges>
#include <concepts>

struct Employee {
    int id;
    std::string name;
    double salary;
    std::string department;
};

// Custom Sentinel untuk Null-terminated stream reader tanpa menghitung length di awal
struct NullTerminator {
    bool operator==(const char* ptr) const {
        return *ptr == '\0';
    }
};

int main() {
    std::vector<Employee> employees = {
        {101, "Alice", 95000.0, "Engineering"},
        {102, "Bob", 62000.0, "HR"},
        {103, "Charlie", 120000.0, "Engineering"},
        {104, "David", 58000.0, "Marketing"},
        {105, "Eve", 110000.0, "Engineering"}
    };

    // 1. PENGGUNAAN RANGE ALGORITHM DENGAN PROJECTION
    // Mengurutkan employee berdasarkan salary secara descending tanpa menulis lambda komparasi manual
    std::ranges::sort(employees, std::greater<double>{}, &Employee::salary);

    std::cout << "--- Sorted by Salary (Descending via Projection) ---\n";
    for (const auto& emp : employees) {
        std::cout << emp.name << " (" << emp.department << "): $" << emp.salary << '\n';
    }

    // 2. SEARCH DENGAN PROJECTION DAN PREDIKAT TERSUBSTITUSI
    auto it = std::ranges::find(employees, "Charlie", &Employee::name);
    if (it != employees.end()) {
        std::cout << "\nFound: " << it->name << " with ID: " << it->id << '\n';
    }

    // 3. SENTINEL IMPLEMENTATION
    const char rawData[] = "C++20 Ranges Engine";
    // std::ranges::for_each menerima iterator awal dan sentinel kustom dengan tipe berbeda
    std::cout << "\nScanning stream until null terminator via Sentinel:\n";
    std::ranges::for_each(rawData, NullTerminator{}, [](char c) {
        std::cout << '[' << c << ']';
    });
    std::cout << '\n';

    // 4. DANGLING ITERATOR PROTECTION
    // std::ranges mendeteksi jika algoritma dijalankan pada rvalue temporary container
    auto getTemporaryVector = []() {
        return std::vector<int>{5, 4, 3, 2, 1};
    };

    // Kompilasi valid, namun tipenya std::ranges::dangling, BUKAN vector<int>::iterator
    auto danglingIt = std::ranges::max_element(getTemporaryVector());
    
    // static_assert membuktikan tipe yang dikembalikan aman dari bahaya *dangling pointer*
    static_assert(std::same_as<decltype(danglingIt), std::ranges::dangling>);
    
    // Baris di bawah ini akan menyebabkan COMPILE ERROR jika di-uncomment:
    // std::cout << *danglingIt << '\n'; // Error: indirection requires pointer/iterator operand

    return 0;
}
```

#### Penjelasan Komponen Penting:
1. `std::ranges::sort(employees, std::greater<>{}, &Employee::salary);`: Menggantikan sintaks klasik `std::sort(employees.begin(), employees.end(), [](auto& a, auto& b){ return a.salary > b.salary; })`. Proyeksi pointer-to-member `&Employee::salary` mengekstrak data langsung di dalam algoritma.
2. `NullTerminator{}`: Bukan sebuah iterator. Tipe ini hanya menyediakan `operator==` terhadap `const char*`. Algoritma internal `std::ranges::for_each` berjalan hingga kondisi kesetaraan bernilai `true`.
3. `std::ranges::dangling`: Solusi terhadap masalah klasik pengembalian iterator ke kontainer rvalue temporer yang langsung terdestruksi di akhir ekspresi (*lifetime termination*).

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime:
- **Zero-Cost Abstractions**: Algoritma `std::ranges` dirancang terinlinisasi penuh (*fully inlined*). Proyeksi bukanlah pemanggilan fungsi *indirect* (seperti *function pointer* atau `std::function`), melainkan ekspresi `std::invoke` teroptimasi yang di-*inline* langsung oleh compiler (level `-O2`/`-O3`) sehingga setara dengan akses anggota langsung (*direct struct member access*).
- **Sentinels Unrolling**: Ketika iterator dan sentinel memiliki tipe berbeda, loop di-*compile* menjadi evaluasi predikat sentinel. Compiler modern mampu mengoptimasi loop sentinel ini menjadi instruksi vektorisasi SIMD jika alignment dan boundary memori terbukti aman.

#### Alokasi Memori / Resource:
- **`borrowed_range` & Dangling Prevention**: 
  Konsep `std::ranges::borrowed_range` memeriksa apakah masa hidup elemen dari suatu range terikat dengan masa hidup range itu sendiri. 
  - Tipe lvalue reference (`T&`) otomatis memenuhi `borrowed_range`.
  - Tipe rvalue kontainer standar (`std::vector<int>`, `std::string`) **bukan** `borrowed_range` karena memori teralokasi di heap akan di-*deallocate* saat kontainer mati.
  - Tipe referensial seperti `std::span` dan `std::string_view` ditandai sebagai `borrowed_range` (via template specialization `std::ranges::enable_borrowed_range`), sehingga memanggil algoritma pada `std::string_view` temporer tetap mengembalikan iterator yang valid, bukan `std::ranges::dangling`.

#### Trade-offs:
- **Waktu Kompilasi (Compile Time Overhead)**: Pengecekan *Concepts constraints* yang ekstensif dan overload resolution yang kaya pada namespace `std::ranges` membutuhkan evaluasi AST lebih dalam dibanding template STL klasik. Hal ini meningkatkan konsumsi memori dan waktu kompilasi compiler.
- **Binary Size**: Pada level optimasi rendah (`-O0`), abstraksi wrapper range menghasilkan tumpukan frame fungsi yang lebih dalam dibanding loop mentah (*raw pointer loop*). Optimasi `-O2` mutlak diperlukan untuk meratakan abstraksi ini.

### 4. Best Practices & Common Pitfalls

#### Do's:
- **Gunakan Projections alih-alih Lambda Kustom**: Proyeksi jauh lebih mudah dibaca dan dieksekusi secara efisien:
  ```cpp
  // Dianjurkan
  std::ranges::find(users, 42, &User::id);
  // Hindari
  std::ranges::find_if(users, [](const User& u){ return u.id == 42; });
  ```
- **Prioritaskan `std::ranges::*` dibanding `std::*`**: Range algorithms lebih aman dari *iterator mismatch* dan mencegah *dangling pointer* secara otomatis saat berhadapan dengan ekspresi temporer.
- **Manfaatkan `std::views` untuk Transformasi Non-Mutating**: Gabungkan algoritma range dengan *lazy evaluation views* untuk manipulasi tanpa alokasi memori tambahan.

#### Don'ts:
- **Jangan Mengabaikan Compiler Error Tipe `std::ranges::dangling`**: Ketika compiler memunculkan error terkait `dangling`, itu merupakan sinyal fatal bahwa iterator mencoba mengakses kontainer rvalue yang sudah terhapus dari memori. Jangan gunakan `auto` untuk menyamarkan tipe kembalian ini tanpa memahami konsekuensinya.
- **Jangan Mengoperasikan Mutating Algorithm pada Sub-View Tanpa Memperhatikan Cache**: Hati-hati saat melakukan modifikasi in-place pada range yang diproses melalui view yang meng-cache iterator (misalnya `std::views::filter`).

#### Edge Cases:
- **Single-Pass Input Ranges**: Range yang berbasis stream (seperti `std::ranges::subrange(std::istream_iterator<int>(...), ...)` hanya memenuhi `std::ranges::input_range`. Algoritma yang membutuhkan traversal multipas seperti `std::ranges::sort` atau `std::ranges::reverse` akan ditolak secara statis saat kompilasi.

### 5. Tantangan Eksplorasi Mandiri

1. **Custom Sentinel Parser**: Implementasikan sebuah Sentinel kustom bernama `DelimiterSentinel` yang menghentikan iterasi pada `std::string` atau buffer karakter ketika menemukan karakter koma (`,`) atau baris baru (`\n`). Gunakan sentinel ini bersama `std::ranges::for_each` untuk mem-parsing token sederhana tanpa melakukan fungsi split atau alokasi substring temporer.
2. **Constrained Algorithm Construction**: Buat template fungsi algoritma kustom bernama `find_median` yang dibatasi (*constrained*) menggunakan C++20 `requires`:
   - Algoritma hanya boleh menerima range yang memenuhi `std::ranges::random_access_range` dan `std::ranges::sized_range`.
   - Gunakan `std::ranges::nth_element` di dalam implementasinya dengan proyeksi kustom untuk mencari nilai tengah elemen tanpa perlu mengurutkan seluruh rentang kontainer secara penuh.
