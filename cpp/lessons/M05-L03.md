## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam arsitektur memori C++, kepemilikan objek (*object ownership*) harus didefinisikan secara eksplisit. Berbeda dengan `std::unique_ptr` yang menerapkan model *exclusive ownership* (tanpa overhead runtime), sistem perangkat lunak skala besar sering kali memerlukan model *shared ownership* (kepemilikan bersama). Objek yang sama mungkin direferensikan secara konkuren oleh subsistem logging, thread pool worker, dan graph node. Objek tersebut hanya boleh dihancurkan ketika **tidak ada lagi** komponen yang membutuhkannya.

Untuk mengatasi problem ini secara deterministik tanpa bantuan garbage collector runtime seperti pada JVM atau CLR, C++11 memperkenalkan `std::shared_ptr` dan `std::weak_ptr`.

```
                    +---------------------------------------+
                    |             Control Block             |
                    |---------------------------------------|
                    | Strong Ref Count : 2 (atomic)         |
                    | Weak Ref Count   : 1 (atomic)         |
                    | Custom Deleter / Allocator (optional) |
                    +---------------------------------------+
                                   ^        ^
                     Control Ptr   |        | Control Ptr
               +-------------------+        +--------------------+
               |                                                 |
+------------------------------+                 +------------------------------+
|       std::shared_ptr        |                 |        std::weak_ptr         |
|------------------------------|                 |------------------------------|
| T* ptr (Stored Pointer) ------> [ Managed  ]   | T* ptr (Observer Pointer)    |
| ControlBlock* ctrl_block ----+  [ Object T ]   | ControlBlock* ctrl_block ----+
+------------------------------+                 +------------------------------+
```

#### Komponen Utama
1. **`std::shared_ptr`**: Smart pointer yang memegang kepemilikan kuat (*strong ownership*). Ia mempertahankan referensi ke objek target dan menambah **Strong Reference Count** pada *Control Block*. Saat pointer ini musnah (*out of scope*), Strong Count didekremen. Jika Strong Count mencapai nilai `0`, destruktor objek target langsung dieksekusi.
2. **`std::weak_ptr`**: Smart pointer pengamat (*observer*) yang memegang kepemilikan lemah (*weak ownership*). Pointer ini **tidak** mencegah penghancuran objek target, melainkan hanya mengamati *Control Block* dan menambah **Weak Reference Count**. Objek ini tidak memiliki `operator->` atau `operator*` secara langsung; untuk mengakses objek target, `std::weak_ptr` harus dipromosikan sementara menjadi `std::shared_ptr` via method `.lock()`.
3. **Control Block**: Struktur data terpisah yang dialokasikan di heap untuk mengelola metadata:
   - **Strong Count**: Jumlah `shared_ptr` aktif.
   - **Weak Count**: Jumlah `weak_ptr` aktif + (1 jika Strong Count > 0).
   - **Deleter & Allocator**: Penghapus kustom (*custom deleter*) dan *allocator* (jika didefinisikan).

#### Solusi Siklus Sirkular (*Circular Reference Problem*)
Jika dua objek memiliki `std::shared_ptr` yang saling mereferensikan satu sama lain (Node A -> Node B dan Node B -> Node A), Strong Count masing-masing tidak akan pernah menyentuh angka `0`. Hasilnya adalah kebocoran memori (*memory leak*) permanen. Mengubah salah satu relasi (misalnya pointer anak-ke-induk) menjadi `std::weak_ptr` memutus siklus kepemilikan tersebut.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi sistem pemrosesan tugas berbasis *Publisher-Subscriber* (Pub/Sub) event-listener, di mana *Subscriber* tidak boleh menahan *Publisher* tetap hidup, dan siklus referensi dicegah menggunakan `std::weak_ptr` serta `std::enable_shared_from_this`.

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <string>
#include <algorithm>

// Forward declaration
class EventListener;

class EventBus : public std::enable_shared_from_this<EventBus> {
public:
    void register_listener(const std::weak_ptr<EventListener>& listener) {
        listeners_.push_back(listener);
    }

    void dispatch(const std::string& event) {
        std::cout << "[EventBus] Dispatching event: " << event << "\n";
        
        // Bersihkan dangling weak_ptr saat iterasi (compacting)
        auto it = listeners_.begin();
        while (it != listeners_.end()) {
            // Promosikan std::weak_ptr ke std::shared_ptr secara thread-safe
            if (auto strong_listener = it->lock()) {
                // Objek masih hidup, aman diakses
                strong_listener->on_event(event);
                ++it;
            } else {
                // Objek target telah dihancurkan, buang observer mati
                std::cout << "[EventBus] Menemukan listener kadaluarsa. Menghapus...\n";
                it = listeners_.erase(it);
            }
        }
    }

    ~EventBus() {
        std::cout << "[EventBus] Destruktor: EventBus dihancurkan.\n";
    }

private:
    std::vector<std::weak_ptr<EventListener>> listeners_;
};

class EventListener : public std::enable_shared_from_this<EventListener> {
public:
    explicit EventListener(std::string name) : name_(std::move(name)) {}

    void attach_to(const std::shared_ptr<EventBus>& bus) {
        // PERINGATAN: Memanggil shared_from_this() hanya legal
        // JIKA instance ini sudah dikelola oleh setidaknya satu std::shared_ptr.
        bus->register_listener(weak_from_this());
    }

    void on_event(const std::string& event) {
        std::cout << "  -> [" << name_ << "] Menerima: " << event << "\n";
    }

    ~EventListener() {
        std::cout << "[EventListener] Destruktor: " << name_ << " dihancurkan.\n";
    }

private:
    std::string name_;
};

int main() {
    // Alokasi efisien: Menggunakan std::make_shared (satu blok alokasi)
    auto bus = std::make_shared<EventBus>();

    auto sub1 = std::make_shared<EventListener>("Subscriber_Alpha");
    sub1->attach_to(bus);

    {
        // Scope lokal untuk mendemonstrasikan penghancuran objek
        auto sub2 = std::make_shared<EventListener>("Subscriber_Beta (Scoped)");
        sub2->attach_to(bus);

        bus->dispatch("EVENT_INITIALIZE");
        // sub2 keluar dari scope di sini dan langsung dihancurkan
    }

    std::cout << "\n--- Memulai dispatch kedua setelah Subscriber_Beta mati ---\n";
    bus->dispatch("EVENT_UPDATE");

    std::cout << "\nProgram selesai, membersihkan memori tersisa...\n";
    return 0;
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
1. **Atomic Reference Counting**:
   - Operasi `copy constructor` dan `destructor` dari `std::shared_ptr` mengeksekusi operasi inkremen dan dekremen atomik pada Strong Count di control block:
     ```cpp
     // Pseudocode instruksi CPU
     LOCK XADD [ctrl_block->strong_count], 1  // Copy
     LOCK XADD [ctrl_block->strong_count], -1 // Destruction
     ```
   - Operasi ini menjamin konsistensi pada *multithreading environment* saat pointer di-copy atau di-destroy. Namun, **objek yang ditunjuk tidak secara otomatis thread-safe**. Jika dua thread mengakses *managed object* yang sama via dua `shared_ptr` yang berbeda, mutasi data tetap membutuhkan sinkronisasi manual (`std::mutex`).

2. **Dua Fase Deallokasi Memori**:
   - **Fase 1 (Strong Count == 0)**:
     Destruktor objek target `T::~T()` dipanggil. Memori objek target dilepaskan jika control block dialokasikan secara terpisah. Jika `std::make_shared` digunakan, destruktor tetap dipanggil, tetapi raw memory objek belum dikembalikan ke OS.
   - **Fase 2 (Strong Count == 0 && Weak Count == 0)**:
     Memori *Control Block* akhirnya di-*free* ke heap manager/allocator.

#### Alokasi Memori: `std::make_shared` vs `new`
| Metrik | `std::shared_ptr<T>(new T())` | `std::make_shared<T>()` |
| :--- | :--- | :--- |
| **Alokasi Heap** | **2 Kali**: 1x untuk `T`, 1x untuk *Control Block*. | **1 Kali**: Memory chunk terpadu menampung `T` dan *Control Block*. |
| **Cache Locality** | Rendah (objek dan metadata terpisah di heap). | Tinggi (data objek dan metadata contiguous). |
| **Ukuran Objek Pointer** | 2 Word (16 bytes di 64-bit): Pointer ke `T*` + Pointer ke `ControlBlock*`. | 2 Word (16 bytes di 64-bit): Pointer ke `T*` + Pointer ke `ControlBlock*`. |
| **Pembersihan Memori** | Memori `T` langsung dibebaskan saat Strong Count = 0. | Memori `sizeof(T) + sizeof(ControlBlock)` baru bebas total saat Strong Count **DAN** Weak Count = 0. |

#### Trade-offs
- **Ukuran Memory Footprint**: Double size pointer biasa (pointer aliasing + pointer control block).
- **Instruction Latency**: Operasi atomic (`LOCK` prefix di x86) menyebabkan register spill dan pipeline stall pada CPU cache line dibanding manipulasi integer biasa.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Prioritaskan `std::make_shared`**: Mengurangi overhead alokasi ganda dan mencegah kebocoran memori jika terjadi pelemparan exception pada evaluasi argumen fungsi (C++11/C++14).
- **Gunakan `weak_ptr` untuk Caching/Flyweight**: Cache in-memory harus menyimpan `std::weak_ptr` agar objek yang tidak lagi dipakai oleh sistem dapat langsung di-destruct dari RAM tanpa terhalang entri cache.
- **Pass by `const std::shared_ptr<T>&`** jika fungsi hanya membaca/mengamati kepemilikan dan tidak berpartisipasi dalam transfer atau modifikasi ownership count (menghindari atomic increment/decrement yang redundant).

#### Don'ts
- **DILARANG membuat beberapa `shared_ptr` independen dari raw pointer yang sama**:
  ```cpp
  // CRITICAL BUG: Double Free Corrupt!
  T* raw = new T();
  std::shared_ptr<T> sp1(raw);
  std::shared_ptr<T> sp2(raw); // Fatal: sp2 membuat Control Block kedua!
  // sp1 dan sp2 akan sama-sama memanggil delete raw!
  ```
- **DILARANG memanggil `shared_from_this()` di dalam konstruktor**:
  Pada saat konstruktor `T::T()` dieksekusi, kepemilikan `std::shared_ptr` belum selesai diinisialisasi. Memanggil `shared_from_this()` di fase ini akan melempar exception `std::bad_weak_ptr`.
- **HINDARI default ke `shared_ptr`**: Jika suatu objek memiliki siklus hidup hierarkis yang jelas, selalu pilih `std::unique_ptr` terlebih dahulu. `std::unique_ptr` dapat dinaikkan kastanya (*converted*) ke `std::shared_ptr` via `std::move`, tetapi tidak sebaliknya.

#### Edge Cases
- **Lag Deallokasi Memori dengan `std::make_shared`**:
  Jika objek target `T` berukuran masif (misal: buffer 100 MB), dan terdapat satu saja `std::weak_ptr` berumur panjang yang masih menunjuk ke instance tersebut, maka seluruh alokasi 100 MB tersebut **tidak akan pernah dikembalikan ke OS** sampai `std::weak_ptr` terakhir mati, meskipun destruktor `~T()` sudah lama dieksekusi. Gunakan `std::shared_ptr<T>(new T())` jika objek target sangat besar dan `weak_ptr` berumur jauh lebih panjang.

### 5. Tantangan Eksplorasi Mandiri

1. **Investigasi Aliasing Constructor**:
   Pelajari dan buat implementasi fungsi yang memanfaatkan *aliasing constructor* `std::shared_ptr`:
   ```cpp
   std::shared_ptr<MemberType>(parent_shared_ptr, &(parent_shared_ptr->member));
   ```
   Buktikan bahwa Strong Count dari parent bertambah saat Anda hanya mereferensikan sub-anggota (*member variable*) dari parent tersebut. Apa konsekuensinya terhadap lifetime parent struct?
2. **Implementasi In-Memory Cache Sederhana**:
   Rancang sebuah class `ImageCache` yang memiliki method `std::shared_ptr<Image> get_image(const std::string& path)`.
   - Simpan objek image dalam `std::unordered_map<std::string, std::weak_ptr<Image>>`.
   - Jika image masih valid di memori, return instance yang ada (promosikan via `.lock()`).
   - Jika tidak ada atau sudah expired, alokasikan image baru, simpan ke map via `weak_ptr`, dan return `std::shared_ptr`-nya. Uji apakah memori langsung berkurang saat consumer di luar cache menghancurkan image tersebut.
