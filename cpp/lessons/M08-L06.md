## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Secara tradisional, fungsi dalam C++ adalah *subroutine*. Subroutine memiliki model eksekusi *single-entry / single-exit*: ketika dipanggil (`call`), alokasi aktivasi ditempatkan pada *call stack*, dieksekusi secara linear hingga selesai, dan mengembalikan kontrol ke pemanggilnya (`ret`) seraya membersihkan *stack frame*-nya.

**Coroutine** mendobrak batasan ini dengan memperkenalkan semantik *cooperative multitasking*. Coroutine adalah fungsi yang eksekusinya dapat **ditangguhkan (suspended)** di titik tertentu tanpa menghancurkan konteks lokalnya, mengembalikan kontrol ke pemanggil (atau *resumer*), dan kemudian **dilanjutkan kembali (resumed)** tepat dari titik suspensi tersebut dengan *state* (variabel lokal, nilai register sementara) yang tetap utuh.

```
Subroutine:  [Call] ---------------> [Execute] ---------------> [Return/Destroy]

Coroutine:   [Call] -> [Execute] -> [Suspend]
                                        | (Control returns to caller)
                       [Resume]  <------+
                          |
                       [Execute] -> [Suspend / Return / Destroy]
```

#### Mengapa C++20 Memilih *Stackless Coroutines*?
C++20 mengadopsi model **Stackless Coroutine**, berbeda dengan model *Stackful Coroutine* (seperti Go goroutines atau Boost.Fiber).
- **Stackful**: Setiap coroutine memiliki *call stack* independen yang dialokasikan di heap (biasanya berukuran tetap, misal 2KB–8KB). Eksekusi dapat disuspensi dari dalam fungsi bersarang (*nested calls*). Biayanya: overhead memori signifikan saat mengelola jutaan coroutine dan biaya switching konteks CPU.
- **Stackless**: Coroutine **tidak memiliki stack tersendiri**. Suspensi hanya dapat dilakukan di tingkat atas fungsi coroutine itu sendiri melalui kata kunci khusus (`co_await`, `co_yield`, `co_return`). Jika coroutine memanggil fungsi biasa, fungsi biasa tersebut dieksekusi di *native thread stack*.

#### Anatomi Komponen C++20 Coroutine
Untuk memfasilitasi suspensi dan resumpsi tanpa runtime khusus, C++20 membagi tanggung jawab ke dalam 4 pilar:
1. **Promise Object (`promise_type`)**: Mengontrol perilaku internal coroutine dari sisi pembuat coroutine (cara menangani return value, exception, dan konfigurasi penangguhan awal/akhir).
2. **Coroutine Handle (`std::coroutine_handle<P>`)**: Non-owning pointer/handle yang digunakan dari luar coroutine untuk melanjutkan (`resume()`) atau menghancurkan (`destroy()`) *coroutine state*.
3. **Coroutine State (Frame)**: Struktur data internal compiler yang dialokasikan di heap (atau dioptimasi via HALO) untuk menyimpan variabel lokal, promise object, parameter fungsi, dan titik suspensi saat ini (*state index*).
4. **Awaiter / Awaitable**: Objek yang mengatur mekanisme penangguhan melalui tiga metode: `await_ready()`, `await_suspend()`, dan `await_resume()`.

Sebuah fungsi otomatis dianggap sebagai coroutine oleh compiler jika di dalam tubuhnya terdapat minimal satu dari tiga kata kunci: `co_await`, `co_yield`, atau `co_return`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi dasar task yang dapat disuspensi dan dilanjutkan secara manual (*step-by-step execution*) untuk memahami siklus hidup `suspend` dan `resume`.

```cpp
#include <iostream>
#include <coroutine>
#include <utility>

// Tipe return coroutine yang membungkus siklus hidup handle
struct ManualTask {
    struct promise_type {
        // Objek yang dikembalikan ke pemanggil saat pertama kali coroutine dipanggil
        ManualTask get_return_object() {
            return ManualTask{
                std::coroutine_handle<promise_type>::from_promise(*this)
            };
        }

        // Tunda eksekusi segera setelah dipanggil (lazy start)
        std::suspend_always initial_suspend() noexcept { return {}; }

        // Tunda eksekusi sebelum frame dihancurkan
        std::suspend_always final_suspend() noexcept { return {}; }

        void return_void() noexcept {}

        void unhandled_exception() {
            std::terminate(); // Menghentikan program jika ada unhandled exception
        }
    };

    std::coroutine_handle<promise_type> handle;

    explicit ManualTask(std::coroutine_handle<promise_type> h) : handle(h) {}

    // RAII: Pastikan coroutine frame dihancurkan jika objek keluar dari scope
    ~ManualTask() {
        if (handle) {
            handle.destroy();
        }
    }

    // Move-only semantics (mencegah double-free pada coroutine frame)
    ManualTask(const ManualTask&) = delete;
    ManualTask& operator=(const ManualTask&) = delete;

    ManualTask(ManualTask&& other) noexcept : handle(std::exchange(other.handle, nullptr)) {}
    ManualTask& operator=(ManualTask&& other) noexcept {
        if (this != &other) {
            if (handle) handle.destroy();
            handle = std::exchange(other.handle, nullptr);
        }
        return *this;
    }

    // Antarmuka untuk melanjutkan eksekusi
    bool resume() {
        if (!handle || handle.done()) {
            return false;
        }
        handle.resume();
        return !handle.done();
    }
};

// Implementasi Coroutine
ManualTask proses_sekuensial() {
    std::cout << "[Coroutine] Memulai tahap 1...\n";
    
    // Titik suspensi pertama
    co_await std::suspend_always{}; 

    std::cout << "[Coroutine] Melanjutkan ke tahap 2...\n";

    // Titik suspensi kedua
    co_await std::suspend_always{}; 

    std::cout << "[Coroutine] Menyelesaikan tahap 3. Selesai.\n";
    co_return;
}

int main() {
    std::cout << "[Main] Memanggil fungsi coroutine...\n";
    ManualTask task = proses_sekuensial(); // Coroutine dibuat, langsung suspend karena initial_suspend

    std::cout << "[Main] Coroutine diinisialisasi (belum berjalan).\n";

    std::cout << "[Main] Resuming tahap 1:\n";
    task.resume();

    std::cout << "[Main] Berada kembali di main thread. Resuming tahap 2:\n";
    task.resume();

    std::cout << "[Main] Melakukan pekerjaan lain di main...\n";

    std::cout << "[Main] Resuming tahap akhir:\n";
    task.resume();

    std::cout << "[Main] Status selesai. Mencoba resume kembali:\n";
    bool status = task.resume();
    std::cout << "[Main] Apakah coroutine masih berjalan? " << (status ? "Ya" : "Tidak") << "\n";

    return 0;
}
```

#### Pembahasan Kode:
1. `initial_suspend()`: Mengembalikan `std::suspend_always`. Hal ini membuat eksekusi fungsi langsung berhenti sebelum baris pertama fungsi dijalankan, menyerahkan kontrol ke pemanggil `main()`.
2. `co_await std::suspend_always{}`: Berfungsi sebagai *checkpoint* eksplisit tempat instruksi berhenti, state disimpan, dan kontrol kembali ke fungsi yang memanggil `task.resume()`.
3. `handle.resume()`: Memanggil fungsi internal runtime compiler untuk melanjutkan eksekusi program tepat dari titik `co_await` terakhir.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Transformasi State Machine oleh Compiler
Ketika compiler menemukan fungsi coroutine, compiler memecah fungsi tersebut menjadi mesin status (*finite state machine/FSM*).

Secara konseptual, compiler mentransformasi fungsi coroutine menjadi struktur mirip berikut:
```cpp
// Pseudo-code hasil transformasi compiler
struct __proses_sekuensial_state_frame {
    int __state = 0;
    ManualTask::promise_type __promise;
    // Parameter fungsi yang di-copy/move
    // Variabel lokal coroutine
};

void __proses_sekuensial_resume(__proses_sekuensial_state_frame* frame) {
    switch (frame->__state) {
        case 0:
            // Dari awal sampai suspend point pertama
            std::cout << "[Coroutine] Memulai tahap 1...\n";
            frame->__state = 1;
            return; // Suspensi: kembali ke pemanggil handle.resume()
        case 1:
            // Dari suspend point pertama ke kedua
            std::cout << "[Coroutine] Melanjutkan ke tahap 2...\n";
            frame->__state = 2;
            return; // Suspensi
        case 2:
            // Menuju co_return
            std::cout << "[Coroutine] Menyelesaikan tahap 3. Selesai.\n";
            frame->__state = 3;
            frame->__promise.return_void();
            // final_suspend handling...
            return;
    }
}
```

#### Mekanika `co_await expr`
Saat compiler mengevaluasi `co_await expr`, compiler mengeksekusi protokol Awaiter:
1. Evaluasi apakah `expr` menghasilkan Awaiter via `operator co_await` atau menggunakan objek tersebut secara langsung.
2. Memanggil `awaiter.await_ready()`.
   - Jika bernilai `true`: Penangguhan **dilewati**, langsung menuju langkah 4. Ini adalah jalur optimasi performa tinggi jika data sudah tersedia tanpa perlu konteks switching.
   - Jika bernilai `false`: Coroutine disuspensi.
3. Memanggil `awaiter.await_suspend(handle)`.
   - Di sini *coroutine state* telah dipersiapkan sepenuhnya.
   - Handle coroutine dapat diserahkan ke *event loop*, *thread pool*, atau disimpan untuk nanti.
   - Mengembalikan `void` (kontrol kembali ke pemanggil saat ini), `bool` (`false` membatalkan suspensi), atau `std::coroutine_handle<>` lain (*symmetric transfer*).
4. Saat di-resume, runtime memanggil `awaiter.await_resume()`, yang hasilnya menjadi nilai ekspresi `co_await`.

#### Alokasi Memori / Resource (Coroutine Frame)
- **Heap Allocation**: Secara default, *coroutine frame* dialokasikan via `operator new` berukuran dinamis sesuai total size state + promise + variabel lokal.
- **HALO (Heap Allocation Elision Optimization)**: Jika compiler (seperti Clang atau GCC) dapat membuktikan secara statis bahwa *lifetime* coroutine berada dalam *scope* pemanggil (tidak bocor ke thread lain atau objek global), compiler dapat mengeliminasi alokasi heap dan menempatkan coroutine frame langsung pada stack pemanggil (*stack frame elision*).

### 4. Best Practices & Common Pitfalls

#### Do's
- **Terapkan Prinsip RAII pada `std::coroutine_handle`**: Selalu bungkus raw `std::coroutine_handle` di dalam kelas *wrapper* bertipe *move-only* yang memanggil `handle.destroy()` pada destructor-nya, kecuali jika siklus hidupnya ditangani oleh runtime/scheduler eksternal.
- **Gunakan `final_suspend() noexcept { return std::suspend_always{}; }`**: Ini mencegah coroutine frame dihancurkan secara otomatis di akhir coroutine sebelum pemanggil sempat memeriksa status `handle.done()` atau mengambil return value dari promise. Destruksi kemudian dilakukan via RAII wrapper.
- **Tandai fungsi awaiter dan promise methods sebagai `noexcept`**: Melempar exception di dalam metode suspensi internal seperti `initial_suspend` atau `await_suspend` dapat menyebabkan resource leak atau terminasi program yang sulit dilacak.

#### Don'ts
- **Jangan Mengoper Argumen Berupa Reference (`&`) ke Coroutine**:
  ```cpp
  // SANGAT BERBAHAYA
  ManualTask bahaya(const std::string& input) {
      co_await std::suspend_always{};
      std::cout << input; // CRASH / UB! Jika pemanggil temporary string sudah hancur.
  }
  ```
  Karena coroutine dapat disuspensi dan dilanjutkan setelah fungsi pemanggil selesai dieksekusi, referensi akan menunjuk ke stack frame pemanggil yang sudah tidak valid (*dangling reference*). Selalu gunakan *pass-by-value* untuk parameter coroutine asinkron.
- **Jangan Memanggil `handle.resume()` pada Coroutine yang Sudah Selesai (`handle.done() == true`)**:
  Melanjutkan coroutine yang telah berada di status selesai memicu **Undefined Behavior** (UB) yang biasanya berujung pada *segmentation fault*.

#### Edge Cases
- **Self-Destruction dalam `await_suspend`**: Jika Anda menyerahkan `coroutine_handle` ke thread lain di dalam `await_suspend`, thread tersebut dapat me-resume dan menghancurkan coroutine *sebelum* `await_suspend` selesai dieksekusi di thread pemanggil. Jangan pernah mengakses state objek setelah handle diserahkan ke thread lain.

### 5. Tantangan Eksplorasi Mandiri

1. **Custom Yielding Step Counter**: Modifikasi implementasi `ManualTask` di atas agar dapat menerima `int` melalui kata kunci `co_yield` (Petunjuk: implementasikan `yield_value(int val)` pada `promise_type` dan simpan nilainya ke member variabel promise untuk dibaca oleh pemanggil).
2. **Observasi Memory Elision (HALO)**: Kompilasi kode di atas menggunakan Compiler Explorer (godbolt.org) dengan compiler Clang (`-O3 -std=c++20`). Periksa kode assembly yang dihasilkan untuk melihat apakah panggilan `operator new` dihilangkan oleh compiler ketika coroutine dipanggil dan di-resume secara lokal di dalam `main()`.
3. **Deteksi Dangling Pointer**: Buat skenario di mana sebuah lambda menangkap variabel lokal secara referensi dan menjadi coroutine. Analisis alur eksekusi saat dereferensi liar terjadi akibat suspensi.
