### 1. Konsep & Arsitektur Mendalam

Persistensi data lokal dalam Kotlin Multiplatform (KMP) menghadapi tantangan fundamental: perbedaan drastis pada runtime eksekusi dan ketersediaan API SQLite antar-target:
- **Android**: Menggunakan ART/Dalvik dengan binding SQLite internal bawaan framework OS (`android.database.sqlite`) atau bundled binaries.
- **iOS / macOS**: Berjalan langsung di atas Kotlin/Native yang harus berkomunikasi dengan runtime Darwin menggunakan SQLite C-APIs melalui Kotlin/Native `cinterop`.
- **JVM / Desktop**: Memerlukan JDBC driver (seperti Xerial SQLite) yang berkomunikasi lewat JNI.
- **Web (Wasm / JS)**: Memerlukan SQLite yang dikompilasi ke WebAssembly (Wasm) dengan virtual filesystem (VFS) berbasis IndexedDB.

Untuk mengatasi fragmentasi ini, ekosistem KMP memiliki dua paradigma utama:

```
+--------------------------------------------------------------------------+
|                        Common Code / Repository                          |
|             (Business Logic, Flow / Coroutines, Domain Models)           |
+--------------------------------------------------------------------------+
                                     |
         +---------------------------+---------------------------+
         |                                                       |
         v                                                       v
+-------------------------------+               +-------------------------------+
|     SQLDelight (SQL-First)    |               |    Room KMP (Code-First)      |
| .sq Files -> ANTLR Compiler   |               | @Entity, @Dao -> KSP          |
| -> Type-Safe Kotlin API       |               | -> Generated Impl Classes     |
+-------------------------------+               +-------------------------------+
                 |                                               |
                 +-----------------------+-----------------------+
                                         |
                                         v
               +---------------------------------------------------+
               |             Driver / Engine Abstraction           |
               | (SqlDriver [SQLDelight] / SQLiteDriver [Room])    |
               +---------------------------------------------------+
                   |                     |                      |
                   v                     v                      v
         +------------------+  +-------------------+  +-------------------+
         | Android Driver   |  | iOS Native Driver |  | JVM Driver (JDBC) |
         | (Framework/NDK)  |  | (C-Interop SQLite)|  | (Xerial SQLite)   |
         +------------------+  +-------------------+  +-------------------+
```

#### SQL-First (SQLDelight) vs Code-First (Room Multiplatform)
1. **SQLDelight (SQL-First)**:
   - *Prinsip*: File mentah `.sq` bertindak sebagai *single source of truth*.
   - *Mekanisme*: Plugin Gradle SQLDelight menggunakan parser ANTLR untuk memvalidasi sintaks SQL langsung terhadap dialek database yang dipilih saat kompilasi. ANTLR mengabstraksi AST (Abstract Syntax Tree), memverifikasi tipe kolom, lalu men-generate interface Kotlin murni dan *row-mapper* tanpa refleksi.
   
2. **Room KMP (Code-First / Annotation-Driven)**:
   - *Prinsip*: Entity dan DAO ditulis dalam Kotlin dengan anotasi (`@Entity`, `@Dao`, `@Database`).
   - *Mekanisme*: KSP (Kotlin Symbol Processing) mem-parse metadata kode Kotlin, menghasilkan implementasi DAO, skema SQLite, serta validasi query SQL saat kompilasi. Memanfaatkan `androidx.sqlite:sqlite` sebagai abstraksi driver tingkat rendah.

Kedua pendekatan memisahkan **logika eksekusi query (Common)** dari **implementasi engine koneksi database (Platform-Specific Drivers)**.

### 2. Implementasi & Contoh Kasus Nyata

Contoh implementasi berikut menggunakan **SQLDelight** sebagai representasi murni abstraksi database multiplatform berkinerja tinggi.

#### Struktur File SQL (`src/commonMain/sqldelight/com/example/db/AppDatabase.sq`)
```sql
CREATE TABLE UserProfile (
    id TEXT NOT NULL PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE,
    updatedAt INTEGER NOT NULL
);

-- Queries di bawah akan digenerate menjadi fungsi Kotlin dengan tipe data terikat
selectAllUsers:
SELECT *
FROM UserProfile
ORDER BY updatedAt DESC;

getUserById:
SELECT *
FROM UserProfile
WHERE id = ?;

insertUser:
INSERT OR REPLACE INTO UserProfile(id, name, email, updatedAt)
VALUES (?, ?, ?, ?);

deleteUserById:
DELETE FROM UserProfile
WHERE id = ?;
```

#### Abstraksi Factory Driver (`src/commonMain/kotlin/DatabaseDriverFactory.kt`)
```kotlin
package com.example.db

import app.cash.sqldelight.db.SqlDriver

// Driver Factory diakses via dependency injection (Koin) atau expect/actual
expect class DatabaseDriverFactory {
    fun createDriver(): SqlDriver
}
```

#### Implementasi Android Platform (`src/androidMain/kotlin/DatabaseDriverFactory.kt`)
```kotlin
package com.example.db

import android.content.Context
import app.cash.sqldelight.db.SqlDriver
import app.cash.sqldelight.driver.android.AndroidSqliteDriver

actual class DatabaseDriverFactory(private val context: Context) {
    actual fun createDriver(): SqlDriver {
        return AndroidSqliteDriver(
            schema = AppDatabase.Schema,
            context = context,
            name = "production.db"
        )
    }
}
```

#### Implementasi iOS Native Platform (`src/iosMain/kotlin/DatabaseDriverFactory.kt`)
```kotlin
package com.example.db

import app.cash.sqldelight.db.SqlDriver
import app.cash.sqldelight.driver.native.NativeSqliteDriver
import co.touchlab.sqliter.DatabaseConfiguration

actual class DatabaseDriverFactory {
    actual fun createDriver(): SqlDriver {
        return NativeSqliteDriver(
            schema = AppDatabase.Schema,
            name = "production.db",
            onConfiguration = { config: DatabaseConfiguration ->
                // Mengaktifkan Write-Ahead Logging (WAL) untuk performa concurrency native
                config.copy(
                    extendedConfig = DatabaseConfiguration.Extended(
                        foreignKeyConstraints = true
                    )
                )
            }
        )
    }
}
```

#### Shared Repository Layer (`src/commonMain/kotlin/UserRepository.kt`)
```kotlin
package com.example.db

import app.cash.sqldelight.coroutines.asFlow
import app.cash.sqldelight.coroutines.mapToList
import app.cash.sqldelight.coroutines.mapToOneOrNull
import kotlinx.coroutines.CoroutineDispatcher
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.withContext

class UserRepository(
    driverFactory: DatabaseDriverFactory,
    private val ioDispatcher: CoroutineDispatcher
) {
    // Inisialisasi engine database hasil kompilasi SQLDelight
    private val database = AppDatabase(driverFactory.createDriver())
    private val dbQueries = database.appDatabaseQueries

    // Mengamati perubahan data secara reaktif menggunakan Flow
    fun observeAllUsers(): Flow<List<UserProfile>> {
        return dbQueries.selectAllUsers()
            .asFlow()
            .mapToList(ioDispatcher)
    }

    suspend fun getUser(id: String): UserProfile? = withContext(ioDispatcher) {
        dbQueries.getUserById(id).executeAsOneOrNull()
    }

    suspend fun saveUser(id: String, name: String, email: String, timestamp: Long) =
        withContext(ioDispatcher) {
            // Operasi mutasi dibungkus dalam transaksi untuk menjamin integritas atomik
            database.transaction {
                dbQueries.insertUser(
                    id = id,
                    name = name,
                    email = email,
                    updatedAt = timestamp
                )
            }
        }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Kompilasi & Code Generation
1. **SQLDelight**:
   - Compiler membedah syntax tree file `.sq`.
   - Untuk setiap query bertipe `SELECT`, compiler menginferensikan *nullability* dan tipe kolom berdasarkan skema.
   - Hasil generasi: Interface `AppDatabase`, turunan `SqlDriver`, serta kelas *query executable* yang membungkus *prepared statement*. Tidak ada kode yang di-parse pada saat runtime aplikasi berjalan; query SQL telah dioptimasi menjadi string statis.
2. **Room KMP**:
   - KSP menganalisis metadata Kotlin saat kompilasi target berlangsung.
   - Room memvalidasi kecocokan antara struktur tabel di SQLite dengan properti Kotlin `@Entity`.
   - Kode yang digenerasi mengekstrak data dari kursor `SQLiteStatement` secara prosedural langsung tanpa menggunakan *reflection* (seperti `java.lang.reflect.*`).

#### Eksekusi & Memory Lifecycle di Tingkat Native (iOS/Darwin)
- Pada target iOS, driver seperti `NativeSqliteDriver` bergantung pada library C-interop (misal `SQLiter`).
- Setiap koneksi ke database membuka instance pointer C murni `sqlite3*`.
- Pengeksekusian query memanggil `sqlite3_prepare_v2`, `sqlite3_bind_*`, dan iterasi via `sqlite3_step`.
- **Manajemen Memori Kotlin/Native**: Objek Kotlin membungkus pointer C. Ketika objek `Cursor` ditutup (`close()`), statement C harus segera melepaskan pointer melalui `sqlite3_finalize()`. Jika terlewat, memory leak terjadi di luar jangkauan Kotlin/Native Garbage Collector (GC), karena memori native C dialokasikan di luar Garbage Collected Heap.

#### Trade-offs: SQL-First vs Code-First KMP

| Aspek | SQLDelight (SQL-First) | Room KMP (Code-First) |
| :--- | :--- | :--- |
| **Source of Truth** | File SQL murni (`.sq`) | Kelas Kotlin & Anotasi |
| **Tooling & IDE** | Membutuhkan plugin IDE SQLDelight | Terintegrasi langsung dengan Android Studio |
| **Adopsi Developer** | Sangat disukai oleh engineer yang mahir SQL | Mudah dipelajari developer Android/Room kawakan |
| **Fleksibilitas Database**| Mendukung dialek fleksibel (SQLite, MySQL, Postgres) | Terfokus eksklusif pada SQLite |
| **Schema Migration** | File `.sqm` diverifikasi ketat saat compile | Schema export JSON, rentan mismatch jika manual |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Aktifkan Foreign Key Constraints**: Secara default, engine SQLite mematikan *Foreign Key*. Selalu aktifkan via hook konfigurasi driver (`PRAGMA foreign_keys = ON;`).
- **Gunakan Write-Ahead Logging (WAL)**: Mode default SQLite menggunakan *rollback journal* yang mengunci seluruh database saat operasi tulis. Konfigurasikan driver untuk menggunakan WAL (`PRAGMA journal_mode=WAL;`), yang memungkinkan banyak pembaca (*concurrent readers*) tetap berjalan saat ada satu proses penulisan (*single writer*).
- **Gunakan Transaksi Batch**: Jangan pernah memanggil operasi insert individual berulang-ulang di dalam loop. Bungkus ke dalam `database.transaction { ... }` untuk mencegah disk I/O flush berulang untuk setiap baris data.

#### Don'ts
- **Menjalankan Blocking Query di Main Thread**: Walaupun Kotlin/Native dan ART mengizinkan pemanggilan database di thread mana pun, query berat di Main Thread akan langsung menyebabkan freeze pada UI. Selalu sertakan `CoroutineDispatcher` (misal `Dispatchers.IO`) saat mengeksekusi query.
- **Menggunakan Driver Instance Ganda**: Jangan menginstansiasi `SqlDriver` baru setiap kali repository membutuhkan koneksi. SQLite driver harus berstatus *Singleton* per file database sepanjang siklus hidup proses aplikasi. Driver ganda yang mengakses file yang sama memicu error `SQLITE_BUSY` atau kegagalan concurrency lock.

#### Edge Cases & Platform Quirks
- **Database Thread Concurrency di Kotlin/Native**: Model concurrency baru Kotlin/Native (K/N GC) mendukung pembagian objek antar thread tanpa *freezing*. Namun, koneksi SQLite native berbasis pointer thread-confined jika tidak dikonfigurasi dengan flag `SQLITE_OPEN_FULLMUTEX`. SQLDelight mengatasinya dengan mendesain pool koneksi thread-safe internal; jangan override connection pool ini sembarangan.
- **Perbedaan Versi SQLite Bawaan OS**: iOS versi lama dan Android versi lama menyertakan engine SQLite OS yang versinya berbeda. Query yang memanfaatkan fitur baru (seperti *Window Functions* atau *JSON functions*) bisa gagal pada OS versi lawas jika tidak menggunakan *bundled SQLite library*.
