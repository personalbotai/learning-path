### 1. Konsep & Arsitektur Mendalam

Kotlin tidak mengizinkan pembuatan operator baru secara bebas (seperti simbol kustom `*|*` di Scala atau Haskell) untuk mencegah timbulnya *syntactic noise* dan kode yang sulit dibaca. Sebagai gantinya, Kotlin menerapkan **Convention-Based Operator Overloading**. 

Desain ini menetapkan bahwa sekumpulan operator simbolik (misal: `+`, `-`, `*`, `[]`, `()`) dipetakan secara kaku oleh compiler ke nama fungsi tertentu (`plus`, `minus`, `times`, `get`, `invoke`).

```
+--------------------+           +------------------------+
|   Sintaks Sumber   |           |   Nama Fungsi Konvensi |
|       a + b        |  ======>  |        a.plus(b)       |
|       a[i]         |  ======>  |        a.get(i)        |
|       a(x)         |  ======>  |        a.invoke(x)     |
+--------------------+           +------------------------+
              Resolusi Tingkat Kompilasi
```

#### Modifier `operator`
Sebuah fungsi tidak dapat sembarangan merespons simbol operator hanya karena memiliki nama yang cocok. Compiler mewajibkan penambahan modifier `operator`. Modifier ini menginstruksikan frontend compiler Kotlin (`kotlinc`) untuk memvalidasi tanda tangan metode (*method signature*) terhadap aturan konvensi:
- Arity parameter harus sesuai (misalnya, `unaryMinus` tanpa parameter, `plus` tepat 1 parameter).
- Operator tertentu memiliki batas tipe kembalian (misalnya, `compareTo` harus mengembalikan `Int`, `contains` harus mengembalikan `Boolean`).

#### Infix Functions
Fitur `infix` memungkinkan pemanggilan fungsi member atau *extension function* dengan parameter tunggal tanpa tanda titik (`.`) dan tanda kurung `()`. 

Secara arsitektural, infix tidak mengubah cara fungsi dieksekusi di runtime, melainkan memengaruhi *lexical parsing* dan *abstract syntax tree* (AST). Presedensi fungsi infix berada di posisi khusus:
- Lebih rendah daripada operator aritmatika, pergeseran bitwise, dan *range* (`..`).
- Lebih tinggi daripada operator perbandingan (`<`, `>`, `<=`, `>=`), kesetaraan (`==`, `!=`), serta operator logika (`&&`, `||`).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah contoh implementasi domain finansial: manipulasi nilai moneter berbasis vektor mata uang, penggunaan operator indexed access (`[]`), invokasi fungsional, dan fungsi infix untuk transaksi pertukaran mata uang.

```kotlin
import java.math.BigDecimal
import java.math.RoundingMode
import java.util.Currency

// Value class untuk menghindari overhead alokasi memori berlebih
@JvmInline
value class CurrencyCode(val code: String) {
    init {
        require(code.length == 3) { "Kode mata uang harus 3 karakter ISO-4217" }
    }
}

data class Money(
    val amount: BigDecimal,
    val currency: CurrencyCode
) : Comparable<Money> {

    // 1. Operator Overloading: Penjumlahan (+)
    operator fun plus(other: Money): Money {
        require(this.currency == other.currency) {
            "Tidak dapat menjumlahkan ${this.currency.code} dengan ${other.currency.code}"
        }
        return Money(this.amount.add(other.amount), this.currency)
    }

    // 2. Operator Overloading: Perkalian Skalar (*)
    operator fun times(scalar: BigDecimal): Money {
        return Money(this.amount.multiply(scalar), this.currency)
    }

    // 3. Operator Overloading: Negasi Unary (-a)
    operator fun unaryMinus(): Money = Money(this.amount.negate(), this.currency)

    // 4. Implementasi Comparable memetakan operator: <, <=, >, >=
    override operator fun compareTo(other: Money): Int {
        require(this.currency == other.currency) { "Perbandingan mata uang silang tidak valid" }
        return this.amount.compareTo(other.amount)
    }
}

// Koleksi Portofolio yang mengimplementasikan operator invoke () dan index access []
class Portfolio(private val holdings: MutableMap<CurrencyCode, BigDecimal> = mutableMapOf()) {

    // Operator get: portofolio[currency]
    operator fun get(currency: CurrencyCode): BigDecimal =
        holdings.getOrDefault(currency, BigDecimal.ZERO)

    // Operator set: portofolio[currency] = amount
    operator fun set(currency: CurrencyCode, amount: BigDecimal) {
        holdings[currency] = amount
    }

    // Operator invoke: memungkinkan instance dipanggil seperti fungsi -> portfolio()
    operator fun invoke(action: (CurrencyCode, BigDecimal) -> Unit) {
        holdings.forEach { (currency, amount) -> action(currency, amount) }
    }
}

// Infix Function untuk Domain Specific Language (DSL) Transfer
infix fun Money.convertTo(rate: BigDecimal): Money {
    val newAmount = this.amount.multiply(rate).setScale(2, RoundingMode.HALF_EVEN)
    return Money(newAmount, this.currency)
}

// Infix Function: Validasi alokasi
infix fun Money.allocateTo(portfolio: Portfolio) {
    val current = portfolio[this.currency]
    portfolio[this.currency] = current.add(this.amount)
}

fun main() {
    val usd = CurrencyCode("USD")
    val salary = Money(BigDecimal("5000.00"), usd)
    val bonus = Money(BigDecimal("1250.50"), usd)

    // Penggunaan Operator Overloading (+)
    val totalIncome = salary + bonus 
    println("Total Pendapatan: ${totalIncome.amount} ${totalIncome.currency.code}")

    // Penggunaan Operator Comparison (>) via Comparable
    if (totalIncome > salary) {
        println("Bonus berhasil diterapkan.")
    }

    // Infix call: ekuivalen dengan salary.convertTo(BigDecimal("1.05"))
    val adjustedSalary = salary convertTo BigDecimal("1.05")

    val myPortfolio = Portfolio()
    
    // Infix call untuk alokasi domain
    adjustedSalary allocateTo myPortfolio

    // Operator set ([])
    myPortfolio[CurrencyCode("EUR")] = BigDecimal("300.00")

    // Operator get ([])
    val usdHolding = myPortfolio[usd]
    println("USD di Portfolio: $usdHolding")

    // Operator invoke (())
    println("Rincian Portofolio:")
    myPortfolio { curr, amt ->
        println("- ${curr.code}: $amt")
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Desugaring Bytecode
Kotlin tidak memerlukan modifikasi pada JVM Runtime untuk menjalankan operator overloading atau infix functions. JVM tidak memiliki konsep `operator +` untuk tipe objek kustom. Kompiler melakukan teknik **syntactic desugaring**:

Jika kode didekompilasi ke Java Bytecode:
1. `val total = a + b` diterjemahkan secara identik menjadi:
   ```text
   INVOKEVIRTUAL Money.plus (LMoney;)LMoney;
   ```
2. Pemanggilan infix `salary convertTo rate` didekompilasi menjadi:
   ```text
   INVOKESTATIC MoneyKt.convertTo (LMoney;Ljava/math/BigDecimal;)LMoney;
   ```
   (Bila dideklarasikan sebagai *top-level extension function*).

Fungsi `infix` hanyalah *syntactic sugar*. Pada tingkat *bytecode*, ia identik 100% dengan pemanggilan metode normal `a.convertTo(rate)` tanpa ada overhead eksekusi tambahan.

#### Alokasi Memori & Object Creation
Operasi overloading matematis pada tipe *immutable* (seperti `Money` atau `Vector`) menghasilkan instansiasi objek baru pada heap di setiap operasinya (`return Money(...)`). 

Jika dilakukan dalam loop berulang (*high-frequency calculation*):
```kotlin
var total = Money(BigDecimal.ZERO, usd)
for (item in hugeList) {
    total = total + item // Menghasilkan ribuan alokasi objek sementara di Young Generation Heap!
}
```
Ini memicu tekanan signifikan pada Garbage Collector (GC). Untuk operasi intensif, sediakan varian mutabel internal atau gunakan *inline value class* jika tipe data dapat direpresentasikan oleh satu nilai primitif.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Patuhi *Principle of Least Astonishment* (POLA)**: Operator `+` harus selalu berarti penambahan, penggabungan, atau agregasi. Jangan gunakan `+` untuk mutasi yang menghapus data atau memicu operasi *asynchronous network call*.
- **Pertahankan Karakteristik Aljabar**: Jika mengimplementasikan `plus`, pastikan operasi bersifat komutatif ($a + b == b + a$) jika domain memungkinkannya.
- **Gunakan Infix untuk Membaca Kalimat Logis**: Infix sangat ideal untuk assertion testing (`actual shouldEqual expected`) atau mapping konfigurasi (`key to value`).

#### Don'ts
- **Hindari Membuat DSL Kriptik**: Menggunakan operator seperti `/` untuk membagi path direktori atau `*` untuk filter database dapat membingungkan pengembang lain jika tidak dirancang sesuai konsensus tim.
- **Jangan Mengabaikan Immutabilitas pada Arithmetic Operator**: Fungsi konvensi `plus` idealnya tidak memutasi penerima (*receiver*), melainkan mengembalikan *instance* baru. Untuk memutasi objek secara internal, gunakan konvensi `plusAssign` (`+=`).

#### Edge Cases & Trap Presedensi Infix
Presedensi operator infix berada di bawah operator aritmatika. Perhatikan jebakan evaluasi ekspresi berikut:

```kotlin
// EKSPEKTASI: (x add y) * z
// REALITAS:   x add (y * z)
val result = x add y * z 
```
Karena perkalian (`*`) memiliki presedensi lebih tinggi daripada infix `add`, ekspresi `y * z` dievaluasi terlebih dahulu sebelum dijadikan argumen ke dalam fungsi `add`. Selalu gunakan tanda kurung eksplisit jika menggabungkan operator matematika dengan fungsi infix.
