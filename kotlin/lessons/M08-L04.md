## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Jetpack Compose dan Compose Multiplatform (CMP) fundamentally mengubah paradigma pembangunan antarmuka grafis dari **Imperative View System** (seperti Android `View` hierarchy berbasis mutasi objek `android.view.View` secara langsung atau UIKit `UIView`) menjadi **Declarative Reactive System**.

Secara arsitektural, Compose dipecah menjadi beberapa layer decoupled yang memungkinkan portabilitas ke berbagai platform (Android, iOS via Skiko/Metal, Desktop via Skiko/DirectX/Vulkan/OpenGL, dan Web via Wasm/Canvas):

```text
+-----------------------------------------------------------+
| Compose Material 3 / Foundation (Multiplatform UI)        |
+-----------------------------------------------------------+
| Compose UI (Layout, Modifier, Input Events, Pointer, Text)|
+-----------------------------------------------------------+
| Compose Runtime (State, Slot Table, Recomposition Engine) |
+-----------------------------------------------------------+
| Kotlin Compiler Plugin (IR Transform, Stability, $composer)|
+-----------------------------------------------------------+
| Platform Host / Graphics Engine (Android HWUI / Skiko)    |
+-----------------------------------------------------------+
```

#### Arsitektur Tiga Fase Compose
Ketika sebuah frame dirender, Compose mengeksekusi tiga fase berbeda secara berurutan:
1. **Composition (What to show)**: Runtime mengeksekusi fungsi `@Composable`, mengevaluasi percabangan logika, membaca `State`, dan membangun/memperbarui pohon data internal yang disebut **Slot Table** serta pohon representasi antarmuka (`LayoutNode`).
2. **Layout (Where to place it)**: Pohon `LayoutNode` diukur (*measurement*) dan diposisikan (*placement*). Compose menerapkan batasan ukuran hierarki *single-pass measurement* dengan kompleksitas $O(N)$, menyelesaikan masalah performa *multi-pass measurement* yang kerap terjadi pada nested layout imperatif seperti `RelativeLayout`.
3. **Drawing (How to render it)**: Setiap `LayoutNode` memproyeksikan visualnya ke canvas grafis platform (misalnya, `Canvas` Android yang terhubung ke `RenderNode`, atau `Skia Canvas` di Compose Multiplatform melalui library Skiko).

#### Recomposition dan Smart Recomposition
Compose tidak menggambar ulang seluruh layar ketika data berubah. Compose menerapkan **Smart Recomposition**, yaitu kemampuan untuk melewati (*skip*) pemanggilan fungsi composable yang parameter-parameternya tidak mengalami perubahan mutasi nilai berdasarkan analisis stabilitas memori.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengimplementasikan skenario performa-kritis: feed transaksi keuangan yang menerima pembaruan nilai secara real-time. Kode mendemonstrasikan stabilitas tipe data, penghindaran alokasi memori yang tidak perlu, dan penundaan pembacaan state (*deferred state read*) ke fase Layout/Draw.

```kotlin
package com.architecture.compose.feed

import androidx.compose.animation.AnimatedVisibility
import androidx.compose.foundation.background
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.lazy.LazyColumn
import androidx.compose.foundation.lazy.items
import androidx.compose.foundation.shape.RoundedCornerShape
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Alignment
import androidx.compose.ui.Modifier
import androidx.compose.ui.draw.drawBehind
import androidx.compose.ui.geometry.Offset
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.unit.IntOffset
import androidx.compose.ui.unit.dp
import kotlinx.collections.immutable.ImmutableList
import kotlinx.collections.immutable.toImmutableList
import kotlin.math.roundToInt

// 1. Tipe data domain diberi anotasi @Immutable untuk menjamin stabilitas 
// jika kelas berada pada modul terpisah atau berisi tipe generik.
@Immutable
data class TransactionItem(
    val id: String,
    val title: String,
    val amount: Double,
    val isCredit: Boolean
)

@Composable
fun TransactionDashboard(
    transactions: ImmutableList<TransactionItem>,
    modifier: Modifier = Modifier
) {
    // Hoisting state untuk scroll offset atau dynamic calculation
    var scrollOffsetMultiplier by remember { mutableFloatStateOf(0f) }

    Column(modifier = modifier.fillMaxSize()) {
        DashboardHeader(
            transactionCount = transactions.size,
            // Mengirim lambda alih-alih nilai langsung mencegah Recomposition 
            // pada DashboardHeader saat scrollOffsetMultiplier berubah
            offsetProvider = { scrollOffsetMultiplier }
        )

        LazyColumn(
            modifier = Modifier.fillMaxSize(),
            contentPadding = PaddingValues(16.dp),
            verticalArrangement = Arrangement.spacedBy(8.dp)
        ) {
            items(
                items = transactions,
                key = { item -> item.id } // Wajib: Menjaga identitas node di Slot Table
            ) { tx ->
                TransactionCard(transaction = tx)
            }
        }
    }
}

@Composable
private fun DashboardHeader(
    transactionCount: Int,
    offsetProvider: () -> Float,
    modifier: Modifier = Modifier
) {
    Box(
        modifier = modifier
            .fillMaxWidth()
            .height(120.dp)
            .background(MaterialTheme.colorScheme.primaryContainer)
            // DEFERRED STATE READ: Baca offsetProvider() hanya pada Phase Layout/Draw.
            // Box ini TIDAK akan recompose saat lambda offsetProvider memancarkan perubahan.
            .offset {
                IntOffset(x = 0, y = (offsetProvider() * 10).roundToInt())
            }
            .padding(16.dp)
    ) {
        Text(
            text = "Total Transaksi: $transactionCount",
            style = MaterialTheme.typography.titleMedium,
            modifier = Modifier.align(Alignment.CenterStart)
        )
    }
}

@Composable
private fun TransactionCard(
    transaction: TransactionItem,
    modifier: Modifier = Modifier
) {
    Surface(
        modifier = modifier
            .fillMaxWidth()
            // Menggunakan drawBehind menghindari instansiasi Composable Canvas ekstra
            .drawBehind {
                val strokeWidth = 2.dp.toPx()
                val color = if (transaction.isCredit) Color.Green else Color.Red
                drawLine(
                    color = color,
                    start = Offset(0f, 0f),
                    end = Offset(0f, size.height),
                    strokeWidth = strokeWidth
                )
            },
        shape = RoundedCornerShape(8.dp),
        tonalElevation = 2.dp
    ) {
        Row(
            modifier = Modifier
                .padding(16.dp)
                .fillMaxWidth(),
            horizontalArrangement = Arrangement.SpaceBetween,
            verticalAlignment = Alignment.CenterVertically
        ) {
            Text(text = transaction.title, style = MaterialTheme.typography.bodyLarge)
            Text(
                text = "${if (transaction.isCredit) "+" else "-"} Rp ${transaction.amount}",
                style = MaterialTheme.typography.bodyMedium,
                color = if (transaction.isCredit) Color(0xFF1B5E20) else Color(0xFFB71C1C)
            )
        }
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Compose Compiler Plugin & Kode Sintesis IR
Ketika fungsi dianotasi `@Composable`, compiler Kotlin mengubah signature fungsi melalui transformasi Kotlin Intermediate Representation (IR).

Fungsi asli:
```kotlin
@Composable
fun Counter(count: Int) {
    Text(text = "$count")
}
```
Ditransformasikan menjadi:
```kotlin
fun Counter(count: Int, $composer: Composer, $changed: Int) {
    $composer.startRestartGroup(123456) // Hash unik dari fungsi
    
    // Evaluasi Bitmask untuk stabilitas
    var $dirty = $changed
    if (($changed and 0b110) == 0) {
        $dirty = $dirty or if ($composer.changed(count)) 0b100 else 0b010
    }
    
    // SKIP CHECK: Jika argumen tidak berubah dan slot memori valid, lompat!
    if (($dirty and 0b11) != 0b10 || !$composer.skipping) {
        Text(text = "$count", $composer, 0)
    } else {
        $composer.skipToGroupEnd()
    }
    
    $composer.endRestartGroup()?.updateScope { nextComposer ->
        Counter(count, nextComposer, $changed or 0b001)
    }
}
```
Variabel `$changed` adalah integer bitmask 32-bit:
- Setiap parameter dialokasikan 3 bit data stabilitas: `SAME` (0b001), `DIFFERENT` (0b010), atau `STATIC` (0b100).
- Jika bit menyatakan `SAME`, `$composer.skipToGroupEnd()` dipanggil. CPU langsung memindahkan pointer tanpa mengeksekusi body fungsi.

#### Slot Table Data Structure
Compose Runtime mengelola *cache* deklarasi UI menggunakan **Gap Buffer** yang disebut **Slot Table**.
- Slot Table adalah array 1-dimensi bertipe `Array<Any?>`.
- Array ini memiliki ruang kosong berpindah (*gap*) di tengah-tengahnya, yang memungkinkan operasi penyisipan (*insert*) dan penghapusan (*delete*) bernilai $O(1)$ pada titik kursor render saat ini.
- Semua pemanggilan `remember`, state snapshot, referensi Modifier, dan child layout nodes ditulis secara serial ke dalam array ini.

```text
[GroupHeader][Slot: StateX][Slot: ModifierA] <--- GAP (Empty Area) ---> [GroupHeader][Slot: Text]
```
Jika struktur tree berubah (misalnya akibat percabangan `if-else`), gap dipindahkan (*relocated*) ke indeks operasi melalui `System.arraycopy()`, memvalidasi atau membuang data lama.

#### Snapshot State System (MVCC)
Sistem state Compose mengadopsi prinsip **Multiversion Concurrency Control (MVCC)** yang lazim digunakan dalam arsitektur database:
1. Ketika membaca `mutableStateOf()`, Compose mendaftarkan dependency antara `StateObject` dan `Snapshot` yang sedang aktif di thread tersebut.
2. Setiap thread membaca versi (*snapshot record*) yang terisolasi. Penulisan ke state menghasilkan record baru.
3. Saat operasi penulisan selesai, perubahan di-*commit* ke `GlobalSnapshot`. Compose mengirimkan notifikasi invalidasi ke Recomposition Engine hanya untuk scope-scope yang membaca state tersebut.

#### Compose Multiplatform (CMP) Execution Pipeline
Berbeda dengan Android yang menggunakan Android HWUI/View tree hosting melalui `ComposeView`, Compose Multiplatform memanfaatkan abstraksi Skiko (Skia for Kotlin):
- **iOS**: Skiko mengeksekusi render grafis langsung di atas Metal layer (`CAMetalLayer`). Event input ditangkap dari UIKit (`UIViewController`) lalu dinormalisasi menjadi Compose `PointerInputEvent`.
- **Desktop (JVM)**: Menggunakan engine Skia yang di-render di atas layer OS asli (DirectX di Windows, Metal di macOS, OpenGL di Linux).
- Runtime Compose bersifat multiplatform murni (`commonMain`), sehingga seluruh lifecycle state dan slot table berjalan identik di semua target OS.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Tipe Koleksi Immutable**: Tipe bawaan Java/Kotlin seperti `List<T>` dianggap *unstable* oleh Compose Compiler karena tidak ada jaminan bahwa implementasinya bukan `ArrayList` yang termutasi. Gunakan `kotlinx.collections.immutable` (`ImmutableList`, `ImmutableSet`) untuk memungkinkan fungsi di-*skip*.
- **Tunda Pembacaan State (*Defer Reads*)**: Gunakan lambda modifier seperti `Modifier.offset { ... }`, `Modifier.drawWithContent { ... }`, atau `Modifier.graphicsLayer { ... }` jika state berubah dengan frekuensi tinggi (misal: scroll position, animasi timer). Ini melewati fase Recomposition dan langsung mengeksekusi fase Layout atau Draw.
- **Kunci Identitas Item di Lazy Layout**: Selalu tentukan `key = { it.id }` pada `items()` di `LazyColumn` / `LazyRow` agar Slot Table tidak mengalokasikan ulang state ketika susunan list bergeser atau berotasi.

#### Don'ts
- **Menghindari Perhitungan Berat Tanpa `remember`**:
  ```kotlin
  // SALAH: Dihitung ulang pada setiap kali Recomposition terjadi
  val sortedList = items.sortedBy { it.timestamp }
  
  // BENAR: Dicache dan hanya dihitung ulang jika items berubah referensi
  val sortedList = remember(items) { items.sortedBy { it.timestamp } }
  ```
- **Melakukan Mutasi Objek Di Luar Snapshot Engine**:
  ```kotlin
  // SALAH: Mutasi instance tidak memicu rekomposisi
  val list = remember { mutableListOf<String>() }
  list.add("New") 
  
  // BENAR: Menggunakan SnapshotStateList
  val list = remember { mutableStateListOf<String>() }
  list.add("New")
  ```
- **Jangan Membaca State Frekuensi Tinggi di Root Node**: Membaca scroll offset integer di parent composable utama akan memicu Recomposition untuk parent beserta seluruh child yang tidak stabil pada setiap piksel perubahan layar.

#### Edge Cases
- **Interoperabilitas iOS UIKitView**: Pada Compose Multiplatform iOS, menaruh komponen native iOS (`UIKitView`) di dalam kontainer yang mengalami scrolling cepat dapat memicu *frame desynchronization* antara thread grafis Skiko (Metal) dan main runloop Apple UIKit. Atasi dengan membatasi clipping kompleks pada layer interop tersebut.

### 5. Tantangan Eksplorasi Mandiri

1. **Analisis Kompiler Menggunakan Compiler Metrics**:
   - Pasang flag compiler Compose Metrics (`-Pplugin:androidx.compose.compiler.plugins.kotlin:reportsDestination=...`) pada script Gradle Anda.
   - Periksa file output `.txt` yang dihasilkan. Temukan composable mana yang berstatus `restartable` namun **bukan** `skippable`. Ubah parameter fungsi tersebut hingga statusnya berubah menjadi `skippable`.
2. **Reverse Engineering Slot Table**:
   - Letakkan breakpoint pada sebuah composable sederhana. Masuk ke stack trace internal `androidx.compose.runtime.ComposerImpl`.
   - Amati isi properti `slots` (`SlotTable`) sebelum dan sesudah cabang `if-else` dievaluasi untuk melihat pergeseran fisik *gap buffer* di memori runtime.
