## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

**Delegation Pattern** adalah pola desain struktural di mana sebuah objek menangani *request* dengan mendelegasikannya ke objek pembantu (delegate). Kotlin memberikan dukungan *first-class* (bawaan bahasa) untuk pola ini melalui *keyword* `by`, yang secara drastis mengurangi *boilerplate code* dibandingkan implementasi manual di Java.

Terdapat dua jenis delegasi utama di Kotlin:
1.  **Class Delegation (Delegasi Kelas):** Implementasi prinsip *Composition over Inheritance*. Sebuah kelas dapat mengimplementasikan sebuah *interface* dengan mendelegasikan semua *member* publiknya ke objek spesifik yang diberikan.
2.  **Delegated Properties (Delegasi Properti):** Mengekstrak logika *getter* dan *setter* dari sebuah properti ke dalam kelas terpisah. Ini memungkinkan penggunaan ulang logika umum seperti inisialisasi lambat (*lazy*), observasi perubahan (*observable*), validasi (*vetoable*), atau penyimpanan di *Map*/*Database*.

**Mengapa fitur ini ada?**
Dalam arsitektur perangkat lunak modern, pewarisan (*inheritance*) sering kali menyebabkan hierarki yang kaku dan *fragile base class problem*. Delegasi memungkinkan komposisi perilaku secara dinamis saat *runtime* tanpa mengorbankan keamanan tipe (*type safety*). Untuk properti, delegasi memisahkan *concern* (pemisahan tanggung jawab) antara penyimpanan data dan logika akses data.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi komprehensif yang mencakup *Class Delegation*, *Standard Property Delegates* (`lazy`, `observable`), dan *Custom Delegate*.

```kotlin
import kotlin.properties.Delegates
import kotlin.reflect.KProperty

// --- 1. CLASS DELEGATION ---
interface AnalyticsLogger {
    fun logEvent(eventName: String)
}

class FirebaseAnalytics : AnalyticsLogger {
    override fun logEvent(eventName: String) {
        println("[Firebase] Event logged: $eventName")
    }
}

// UserManager mendelegasikan implementasi AnalyticsLogger ke instance yang di-pass via constructor
class UserManager(
    analytics: AnalyticsLogger
) : AnalyticsLogger by analytics {
    
    fun createUser(name: String) {
        println("User $name created.")
        logEvent("user_created") // Memanggil fungsi dari delegate
    }
}

// --- 2. DELEGATED PROPERTIES ---
class AppConfiguration {
    
    // a. by lazy: Diinisialisasi hanya saat pertama kali dipanggil.
    // Thread-safe secara default (LazyThreadSafetyMode.SYNCHRONIZED)
    val heavyDatabaseConnection: String by lazy {
        println("--> Initializing Database Connection...")
        "jdbc:postgresql://localhost:5432/mydb"
    }

    // b. observable: Menjalankan lambda setiap kali nilai properti berubah
    var themeMode: String by Delegates.observable("Light") { property, oldValue, newValue ->
        println("Property '${property.name}' changed from $oldValue to $newValue")
        // Trigger UI Update logic here
    }

    // c. vetoable: Memvalidasi perubahan. Jika lambda return false, nilai tidak diubah.
    var maxUsers: Int by Delegates.vetoable(10) { _, _, newValue ->
        newValue > 0 // Hanya izinkan nilai positif
    }

    // d. Custom Delegate
    var secureToken: String by EncryptedDelegate()
}

// --- 3. CUSTOM DELEGATE IMPLEMENTATION ---
class EncryptedDelegate {
    private var encryptedValue: String = ""

    // Operator wajib untuk Getter
    operator fun getValue(thisRef: Any?, property: KProperty<*>): String {
        println("Decrypting property '${property.name}'...")
        return encryptedValue.removePrefix("ENC_")
    }

    // Operator wajib untuk Setter
    operator fun setValue(thisRef: Any?, property: KProperty<*>, value: String) {
        println("Encrypting property '${property.name}'...")
        encryptedValue = "ENC_$value"
    }
}

fun main() {
    // Test Class Delegation
    val manager = UserManager(FirebaseAnalytics())
    manager.createUser("Budi")

    // Test Delegated Properties
    val config = AppConfiguration()
    
    println("\n-- Testing Lazy --")
    println(config.heavyDatabaseConnection) // Memicu inisialisasi
    println(config.heavyDatabaseConnection) // Menggunakan nilai cache

    println("\n-- Testing Observable & Vetoable --")
    config.themeMode = "Dark"
    
    config.maxUsers = -5 // Ditolak oleh vetoable
    println("Max Users after invalid set: ${config.maxUsers}") // Tetap 10

    println("\n-- Testing Custom Delegate --")
    config.secureToken = "my_secret_token"
    println("Retrieved Token: ${config.secureToken}")
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (Bytecode Generation):**
  - **Class Delegation:** Kompiler Kotlin secara otomatis menghasilkan *wrapper methods* di kelas utama. Untuk `UserManager` di atas, kompiler membuat *hidden field* untuk menyimpan referensi `AnalyticsLogger`, lalu membuat fungsi `logEvent` yang isinya hanya meneruskan panggilan ke *hidden field* tersebut (`this.delegate.logEvent()`).
  - **Property Delegation:** Kompiler tidak membuat *backing field* standar untuk properti tersebut. Alih-alih, ia membuat instance dari kelas *delegate* (misal `Lazy` atau `EncryptedDelegate`) sebagai *hidden private field* (contoh: `appConfig$heavyDatabaseConnection$delegate`). Pemanggilan *getter*/*setter* diubah di level *bytecode* menjadi pemanggilan `getValue()` dan `setValue()` pada objek *delegate* tersebut.
  
- **Alokasi Memori / Resource:**
  - Setiap properti yang didelegasikan menghasilkan **alokasi objek tambahan** (objek *delegate* itu sendiri).
  - Objek `KProperty` yang di-*pass* ke `getValue`/`setValue` di-*cache* oleh kompiler sebagai *static array* di dalam kelas, sehingga tidak ada alokasi `KProperty` berulang saat *runtime*.

- **Trade-offs:**
  - **Kelebihan:** Abstraksi yang sangat bersih, *reusability* tinggi, dan pemisahan *concern* yang sempurna.
  - **Kekurangan:** Sedikit *overhead* memori (karena objek *delegate* tambahan) dan *method dispatch* (pemanggilan fungsi ekstra). Dalam *hot path* (kode yang dieksekusi ribuan kali per detik), *overhead* ini mungkin terlihat, meski JIT compiler JVM sering kali mampu melakukan *inlining*.

### 4. Best Practices & Common Pitfalls

- **Do's:**
  - Gunakan `by lazy` untuk objek yang berat (seperti koneksi DB, inisialisasi *View* di Android, atau *parsing* file) yang mungkin tidak selalu digunakan dalam siklus hidup aplikasi.
  - Gunakan `LazyThreadSafetyMode.NONE` jika Anda yakin properti `lazy` hanya akan diakses dari satu *thread* (misal: Main Thread di Android/UI). Ini menghilangkan *overhead* dari *synchronization lock*.
    ```kotlin
    val formatter by lazy(LazyThreadSafetyMode.NONE) { SimpleDateFormat("yyyy-MM-dd") }
    ```
  - Gunakan *Class Delegation* untuk menghindari *God Objects* dan menerapkan pola *Decorator* dengan mudah.

- **Don'ts:**
  - Jangan gunakan delegasi untuk properti primitif sederhana yang tidak memerlukan logika khusus. *Overhead* alokasi objek *delegate* tidak sepadan.
  - Jangan menyimpan referensi berat (seperti `Context` atau `Activity` di Android) di dalam *Custom Delegate* tanpa penanganan siklus hidup yang tepat, karena dapat menyebabkan **Memory Leak**.

- **Edge Cases:**
  - **Deadlock pada `lazy`:** Jika dua properti `lazy` saling memanggil satu sama lain saat inisialisasi dalam mode `SYNCHRONIZED`, ini akan menyebabkan *deadlock* pada level JVM.
  - **Vetoable State:** Hati-hati saat menggunakan `vetoable` yang bergantung pada *state* eksternal yang *volatile*. Validasi harus bersifat deterministik.

### 5. Tantangan Eksplorasi Mandiri

1. **Buat Custom Delegate untuk SharedPreferences/DataStore:** Buatlah delegasi properti `by SharedPrefsDelegate(key, defaultValue)` yang secara otomatis membaca dari dan menulis ke penyimpanan lokal (Android/Multiplatform) setiap kali properti diakses atau diubah.
2. **Eksplorasi Map Delegation:** Pelajari bagaimana Kotlin memungkinkan delegasi ke sebuah `Map` (contoh: `val name: String by map`). Cobalah implementasikan ini untuk melakukan *parsing* respons JSON dinamis ke dalam *Data Class* tanpa menggunakan *library* refleksi pihak ketiga.
3. **Analisis Bytecode:** Tulis kode sederhana dengan `by lazy`, lalu gunakan fitur *Show Kotlin Bytecode* di IntelliJ IDEA / Android Studio. Lakukan *Decompile* ke Java dan perhatikan *hidden field* `SynchronizedLazyImpl` yang dihasilkan oleh kompiler.
