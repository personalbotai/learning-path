## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

*Dependency Injection* (DI) adalah teknik implementasi *Inversion of Control* (IoC) di mana objek tidak membuat dependensinya sendiri, melainkan menerimanya dari luar. Tujuannya adalah memisahkan konstruksi objek dari penggunaannya, meningkatkan *testability* (mudah melakukan *mocking*), serta mereduksi *coupling*.

Dalam ekosistem Kotlin, terdapat dua paradigma dominan yang sering disandingkan:

```
+-------------------------------------------------------------------------+
|                              PARADIGMA DI                               |
+------------------------------------+------------------------------------+
|            COMPILE-TIME            |              RUNTIME               |
|            (Dagger/Hilt)           |               (Koin)               |
+------------------------------------+------------------------------------+
| - Tipe: True Dependency Injection  | - Tipe: Service Locator via DSL    |
| - Validasi: Saat kompilasi (KSP)   | - Validasi: Saat runtime           |
| - Overhead: Build-time tinggi      | - Overhead: Sedikit alokasi memori |
| - Kecepatan Runtime: Maksimal      | - Kecepatan Runtime: Lookup hashmap|
+------------------------------------+------------------------------------+
```

#### Dagger / Hilt (Compile-Time DI)
Dagger adalah *framework* DI berbasis *code generation* yang memanfaatkan pemrosesan anotasi (KSP atau Kapt). Hilt adalah lapisan opini (*opinionated wrapper*) di atas Dagger khusus untuk ekosistem Android/Kotlin yang menyederhanakan arsitektur *Component* dan *Subcomponent*.
- **Mekanisme**: Membaca anotasi (`@Inject`, `@Module`, `@Provides`, `@Binds`), memvalidasi grafik dependensi (*Directed Acyclic Graph* / DAG) saat kompilasi. Jika ada dependensi siklik atau tipe data yang tidak terdaftar, proses kompilasi gagal (*fail-fast*).
- **Hasil**: Kode Java murni dihasilkan (*generated code*) yang menginstansiasi objek secara langsung tanpa refleksi.

#### Koin (Runtime Pragmatic Service Locator / DI)
Koin adalah pustaka injeksi dependensi pragmatis yang ditulis murni dalam Kotlin. Secara teknis, Koin beroperasi lebih mendekati pola *Service Locator* yang dibungkus dengan Kotlin DSL yang elegan.
- **Mekanisme**: Tidak melakukan *code generation*. Semua dependensi didaftarkan ke dalam *instance registry* internal menggunakan DSL (`module`, `single`, `factory`).
- **Hasil**: Dependensi di-*resolve* secara dinamis saat aplikasi berjalan melalui pemanggilan fungsi atau delegasi properti (`by inject()`).

### 2. Implementasi & Contoh Kasus Nyata

Skenario: Membangun sistem pembayaran (`PaymentProcessor`) yang membutuhkan `PaymentGateway` dan `AuditLogger`.

#### A. Implementasi Menggunakan Koin

```kotlin
import org.koin.core.context.startKoin
import org.koin.core.module.dsl.bind
import org.koin.core.module.dsl.singleOf
import org.koin.dsl.module
import org.koin.core.component.KoinComponent
import org.koin.core.component.inject

// 1. Abstraksi dan Implementasi
interface AuditLogger { fun log(msg: String) }
class ConsoleAuditLogger : AuditLogger {
    override fun log(msg: String) = println("[AUDIT] $msg")
}

interface PaymentGateway { fun charge(amount: Double) }
class StripeGateway(private val logger: AuditLogger) : PaymentGateway {
    override fun charge(amount: Double) {
        logger.log("Memproses pembayaran stripe: $$amount")
    }
}

class PaymentProcessor(private val gateway: PaymentGateway) {
    fun process(amount: Double) = gateway.charge(amount)
}

// 2. Deklarasi Modul Koin DSL
val paymentModule = module {
    // single: Singleton scope
    single<AuditLogger> { ConsoleAuditLogger() }
    
    // factory: Membuat instance baru setiap kali di-resolve
    single<PaymentGateway> { StripeGateway(get()) } // get() meresolve AuditLogger
    
    // Konstruktor injection otomatis via koin core-dsl
    singleOf(::PaymentProcessor)
}

// 3. Eksekusi Runtime
class CheckoutController : KoinComponent {
    // Injeksi dengan lazy evaluation (Delegated Property)
    private val processor: PaymentProcessor by inject()

    fun executeCheckout() {
        processor.process(150.0)
    }
}

fun main() {
    startKoin {
        modules(paymentModule)
    }

    val controller = CheckoutController()
    controller.executeCheckout()
}
```

#### B. Implementasi Menggunakan Dagger / Hilt

```kotlin
import javax.inject.Inject
import javax.inject.Singleton
import dagger.Module
import dagger.Provides
import dagger.Binds
import dagger.Component

// 1. Domain Class dengan Constructor Injection
class HiltAuditLogger @Inject constructor() : AuditLogger {
    override fun log(msg: String) = println("[HILT-AUDIT] $msg")
}

class HiltStripeGateway @Inject constructor(
    private val logger: AuditLogger
) : PaymentGateway {
    override fun charge(amount: Double) {
        logger.log("Memproses via Hilt: $$amount")
    }
}

class HiltPaymentProcessor @Inject constructor(
    private val gateway: PaymentGateway
) {
    fun process(amount: Double) = gateway.charge(amount)
}

// 2. Definisi Modul Dagger
@Module
abstract class PaymentBindingModule {
    // @Binds lebih efisien dari @Provides karena tidak menghasilkan instruksi metode baru di bytecode
    @Binds
    @Singleton
    abstract fun bindAuditLogger(impl: HiltAuditLogger): AuditLogger

    @Binds
    @Singleton
    abstract fun bindPaymentGateway(impl: HiltStripeGateway): PaymentGateway
}

// 3. Graph Container (Component)
@Singleton
@Component(modules = [PaymentBindingModule::class])
interface ApplicationComponent {
    fun getPaymentProcessor(): HiltPaymentProcessor
}

fun main() {
    // DaggerApplicationComponent dibuat otomatis oleh KSP/Annotation Processor
    val component: ApplicationComponent = DaggerApplicationComponent.create()
    val processor = component.getPaymentProcessor()
    processor.process(250.0)
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Dagger / Hilt

```
[Sumber Kode] 
      │ 
      ▼
(KSP / Kapt Annotation Processor)
      │
      ├──> Validasi Directed Acyclic Graph (DAG)
      │    (Deteksi siklus/missing binding secara statis)
      │
      └──> Generate Bytecode Java:
           ├── HiltPaymentProcessor_Factory.java
           └── DaggerApplicationComponent.java
                 │
                 ▼
[Runtime]: Instansiasi objek langsung (Direct Instantiation)
```

- **Eksekusi & Runtime**: Saat Anda menambahkan `@Inject constructor(...)`, Dagger membuat kelas pendamping bernama `[NamaKelas]_Factory.java`. Kelas ini mengimplementasikan antarmuka `Provider<T>` yang memiliki metode `get()`. Pada runtime, pemanggilan `component.getPaymentProcessor()` diterjemahkan menjadi panggilan langsung:
  `new HiltPaymentProcessor(new HiltStripeGateway(new HiltAuditLogger()))`. Tidak ada *reflection*, tidak ada *dictionary lookup*.
- **Alokasi Memori**: Sangat optimal. Memori hanya dialokasikan untuk referensi objek yang dibuat dan kelas `Factory` stateless.
- **Trade-offs**: Beban dialihkan ke waktu kompilasi (*build time impact*). Jika grafik dependensi berskala ribuan kelas, *build time* akan bertambah signifikan.

#### Koin

```
[Sumber Kode]
      │
      ▼
(Kotlin Compiler Biasa - Tanpa Code Generation)
      │
[Runtime Startup (startKoin)]:
      │
      ▼
Inisialisasi InstanceRegistry
(Menyimpan Map<IndexKey, BeanDefinition<*>>)
      │
[Saat Resolusi (by inject() / get())]:
      │
      ▼
Lookup HashMap berdasarkan KClass + Qualifier -> Jalankan Lambda Provider
```

- **Eksekusi & Runtime**: Saat `startKoin` dipanggil, modul dievaluasi dan dependensi didaftarkan ke dalam `BeanRegistry` yang pada dasarnya membungkus struktur data `Map<String, BeanDefinition<*>>`. Ketika memanggil `get<T>()`, Koin mencari definisi berdasarkan `KClass` (menggunakan nama *qualified class* sebagai *key*). Lambda factory dieksekusi secara dinamis untuk mengembalikan instance.
- **Alokasi Memori**: Koin menyimpan *graph registry* berupa *HashMap*, objek `BeanDefinition`, dan closure lambda di dalam heap memory selama masa hidup aplikasi.
- **Trade-offs**: Waktu kompilasi sangat cepat (*zero annotation processing overhead*), namun terdapat potensi *runtime crash* jika dependensi lupa didaftarkan (`NoDefinitionFoundException`), serta adanya sedikit degradasi performa (*lookup latency*) saat *cold-start* dependensi dalam jumlah masif.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Constructor Injection secara Eksklusif**: Hindari melakukan *field injection* atau *property injection* kecuali terpaksa (seperti pada `Activity` di Android sebelum Hilt ada). Constructor injection memastikan kelas dapat diuji secara independen tanpa *framework* DI.
- **Optimasi Dagger dengan `@Binds`**: Gunakan `@Binds` (metode abstrak) daripada `@Provides` saat Anda hanya memetakan kelas konkret ke antarmuka (*interface*). `@Binds` tidak menghasilkan kode delegasi baru di bytecode, mengurangi *binary size*.
- **Gunakan Koin Verification API di Unit Test**: Jalankan `verify()` dari modul Koin pada unit test untuk menangkap *missing dependency* sebelum kode masuk ke produksi:
  ```kotlin
  @Test
  fun verifyKoinGraph() {
      paymentModule.verify() // Memvalidasi grafik tanpa menjalankan aplikasi
  }
  ```

#### Don'ts
- **Menjadikan Koin sebagai Service Locator Murni**: Hindari menyuntikkan objek `KoinComponent` langsung ke dalam *domain layer* (misal: *use cases* atau *business logic* memanggil `get()` di dalam fungsinya). Ini merusak prinsip *clean architecture* karena mencemari *domain* dengan ketergantungan pada *framework* eksternal.
- **Scoping Memory Leaks**: Jangan memberikan *scope* `@Singleton` atau `single` pada kelas yang memegang referensi ke objek dengan siklus hidup pendek (*short-lived context*). Ini akan menahan objek tersebut di memori dan memicu *memory leak*.

#### Edge Cases
- **Cyclic Dependency**:
  - Pada **Dagger/Hilt**, siklus `A -> B -> A` akan memicu kegagalan kompilasi eksplisit: `[Dagger/DependencyCycle] Found a dependency cycle`. Penanganannya memerlukan pembungkusan salah satu dependensi dengan `Lazy<T>` atau `Provider<T>`.
  - Pada **Koin**, siklus dependensi akan menyebabkan `StackOverflowError` saat runtime karena rekursi tak terbatas pada fungsi `get()`.

### 5. Tantangan Eksplorasi Mandiri

1. **Analisis Dekompilasi Bytecode Dagger**: 
   Buat kelas sederhana dengan Dagger `@Inject constructor`. Lakukan *build* dan buka direktori `build/generated/ksp/` (atau `kapt`). Analisis file `_Factory.java` yang dihasilkan. Perhatikan bagaimana metode `.get()` bekerja menginstansiasi objek tanpa bantuan mekanisme Java Reflection.
2. **Uji Validasi Statis Koin (Koin Check)**: 
   Sengaja buat sebuah *dependency graph* yang tidak lengkap di modul Koin (misal: sebuah kelas membutuhkan `Repository`, tapi `Repository` tidak didaftarkan di modul). Tulis satu unit test menggunakan `koin-test` dengan ekstensi `.verify()`. Amati bagaimana Koin mendeteksi dependensi yang hilang tanpa harus menjalankan seluruh aplikasi Android/Desktop.
