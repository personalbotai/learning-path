## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Reflection adalah kemampuan sebuah program untuk melakukan inspeksi, modifikasi, dan interaksi dengan struktur kodenya sendiri (seperti kelas, fungsi, properti, dan anotasi) pada saat *runtime*. Di ekosistem Kotlin, Reflection memiliki arsitektur yang unik dan terpisah dari Java Reflection, meskipun keduanya berjalan di atas JVM.

**Mengapa Kotlin Membutuhkan Reflection Sendiri?**
Java Reflection (`java.lang.reflect`) tidak memahami semantik khusus Kotlin. Jika Anda menggunakan Java Reflection pada kode Kotlin, Anda hanya akan melihat *bytecode* hasil kompilasi: properti Kotlin menjadi *getter/setter* Java, *nullability* (`String?` vs `String`) menghilang, dan fitur seperti *extension functions* atau *default parameters* tidak dapat diidentifikasi.

Untuk mengatasi ini, Kotlin menggunakan arsitektur berbasis **Metadata**. Saat kompilator Kotlin (`kotlinc`) menghasilkan file `.class`, ia menyisipkan anotasi `@kotlin.Metadata`. Anotasi ini berisi representasi *protobuf-encoded* dari struktur asli Kotlin. Library `kotlin-reflect.jar` kemudian membaca dan mendekode metadata ini saat *runtime* untuk merekonstruksi objek seperti `KClass`, `KProperty`, dan `KFunction`.

Fitur ini menjadi tulang punggung bagi *framework* modern seperti Spring Boot (dengan modul Kotlin), Koin (Dependency Injection), Moshi/Jackson (Serialization), dan Room (ORM).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi pembuatan *mini-validation framework* menggunakan Kotlin Reflection. Kasus ini mendemonstrasikan cara membaca anotasi, menginspeksi properti, dan memanggil *getter* secara dinamis.

```kotlin
import kotlin.reflect.full.declaredMemberProperties
import kotlin.reflect.full.findAnnotation
import kotlin.reflect.full.hasAnnotation

// 1. Definisi Custom Annotation untuk validasi
@Target(AnnotationTarget.PROPERTY)
@Retention(AnnotationRetention.RUNTIME)
annotation class MinLength(val value: Int)

@Target(AnnotationTarget.PROPERTY)
@Retention(AnnotationRetention.RUNTIME)
annotation class Required

// 2. Data Class target dengan anotasi
data class UserDTO(
    @Required
    val username: String?,
    
    @MinLength(6)
    val password: String,
    
    val age: Int
)

// 3. Engine Validasi menggunakan Reflection
class Validator {
    fun validate(obj: Any): List<String> {
        val errors = mutableListOf<String>()
        val kClass = obj::class // Mendapatkan KClass dari objek

        // Iterasi semua properti yang dideklarasikan dalam kelas
        for (prop in kClass.declaredMemberProperties) {
            // Memanggil getter secara dinamis
            val value = prop.getter.call(obj)

            // Cek anotasi @Required
            if (prop.hasAnnotation<Required>() && value == null) {
                errors.add("Property '${prop.name}' is required but was null.")
            }

            // Cek anotasi @MinLength
            val minLengthAnnotation = prop.findAnnotation<MinLength>()
            if (minLengthAnnotation != null && value is String) {
                if (value.length < minLengthAnnotation.value) {
                    errors.add("Property '${prop.name}' must be at least ${minLengthAnnotation.value} characters.")
                }
            }
        }
        return errors
    }
}

fun main() {
    val invalidUser = UserDTO(username = null, password = "123", age = 25)
    val validator = Validator()
    
    val validationErrors = validator.validate(invalidUser)
    validationErrors.forEach { println("Error: $it") }
    // Output:
    // Error: Property 'username' is required but was null.
    // Error: Property 'password' must be at least 6 characters.
}
```

**Penjelasan Kode:**
- `obj::class`: Mengembalikan instance `KClass<out Any>`. Ini adalah titik masuk utama (entry point) untuk Kotlin Reflection.
- `declaredMemberProperties`: Mengambil semua properti yang dideklarasikan langsung di dalam kelas (mengabaikan properti dari *superclass*).
- `prop.getter.call(obj)`: Mengeksekusi fungsi *getter* dari properti tersebut terhadap *instance* `obj`.
- `findAnnotation<T>()`: Fungsi ekstensi dari `kotlin.reflect.full` untuk mencari anotasi spesifik dan membaca nilainya (misal: `minLengthAnnotation.value`).

*Catatan: Untuk menjalankan kode di atas, Anda wajib menambahkan dependensi `org.jetbrains.kotlin:kotlin-reflect` di `build.gradle` Anda.*

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: 
  Saat `obj::class` dipanggil, Kotlin tidak langsung membuat objek `KClass` yang berat. Kotlin menggunakan mekanisme *lazy initialization*. `kotlin-reflect` akan mencari anotasi `@Metadata` pada `java.lang.Class` yang bersesuaian, mem-parsing *protobuf array* di dalamnya, dan membangun representasi *Abstract Syntax Tree* (AST) di memori. Pemanggilan `call()` pada `KFunction` atau `KProperty` pada akhirnya akan di-rutekan (di- *dispatch*) ke Java Reflection API (`Method.invoke`) di level JVM.
- **Alokasi Memori / Resource**: 
  Reflection sangat mahal (*expensive*). Mem-parsing `@Metadata` membutuhkan alokasi memori untuk string dan objek deskriptor. Selain itu, pemanggilan dinamis via `call()` melibatkan *Boxing/Unboxing* tipe primitif (misal `Int` menjadi `java.lang.Integer`) dan pembuatan array objek untuk argumen parameter.
- **Trade-offs**: 
  Anda menukar performa (CPU & Memori) dan keamanan *compile-time* demi fleksibilitas *runtime*. JIT (Just-In-Time) Compiler pada JVM sangat kesulitan melakukan optimasi (seperti *method inlining*) pada kode yang dieksekusi melalui reflection.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - **Caching**: Selalu *cache* hasil reflection. Jika Anda membuat *serializer*, simpan daftar `KProperty` di dalam `ConcurrentHashMap<KClass<*>, List<KProperty<*>>>` saat pertama kali kelas diinspeksi. Jangan memanggil `declaredMemberProperties` berulang kali.
  - **Gunakan Reified Type Parameters**: Jika Anda hanya butuh mengecek tipe kelas, gunakan `inline fun <reified T> doSomething()` daripada melewatkan `KClass` sebagai parameter. Ini diselesaikan saat *compile-time* tanpa *overhead* reflection.
- **Don'ts**:
  - **Jangan gunakan di Hot Path**: Hindari penggunaan reflection di dalam *loop* yang dieksekusi ribuan kali per detik (misal: di dalam fungsi `onDraw` pada UI, atau *game loop*).
  - **Mencampur Java dan Kotlin Reflection sembarangan**: Hindari memanggil `.javaClass` jika Anda membutuhkan semantik Kotlin. Gunakan `::class.java` hanya jika berinteraksi dengan *library* Java murni.
- **Edge Cases**:
  - **Obfuscation (ProGuard/R8)**: Saat merilis aplikasi (terutama Android), *minifier* akan mengubah nama kelas/properti dan seringkali menghapus anotasi `@Metadata`. Ini akan membuat Kotlin Reflection *crash* di *production*. Anda wajib menambahkan aturan `-keep class kotlin.Metadata { *; }` dan aturan `@Keep` untuk kelas target Anda.

### 5. Tantangan Eksplorasi Mandiri

1. **Bangun Mini Dependency Injector**: Buatlah sebuah fungsi `inline fun <reified T : Any> inject(): T` yang dapat menginisialisasi sebuah kelas secara otomatis dengan mencari konstruktor utamanya (`primaryConstructor`) dan menginisialisasi parameter-parameternya secara rekursif menggunakan Reflection.
2. **Eksplorasi Nullability**: Buatlah sebuah fungsi yang menerima sembarang objek data class, lalu iterasi semua propertinya. Jika properti tersebut bertipe *non-nullable* (cek via `prop.returnType.isMarkedNullable`) namun nilainya di- *bypass* menjadi null (misal dari deserialisasi JSON Java yang buruk), lemparkan *custom exception*.
3. **Inspeksi Bytecode**: Tulis kelas Kotlin sederhana, kompilasi, lalu gunakan *tool* `javap -c -v` atau *Kotlin Bytecode Viewer* di IntelliJ/Android Studio. Temukan anotasi `@kotlin.Metadata` dan perhatikan bagaimana struktur datanya disimpan dalam bentuk *array of strings* (d1, d2).
