## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam Kotlin, kelas tidak memiliki *fields* (variabel instance) yang diekspos secara langsung seperti di Java. Kotlin menggunakan konsep **Properties**. Secara arsitektur, sebuah *property* di Kotlin adalah abstraksi tingkat tinggi yang mengimplementasikan **Uniform Access Principle**. Artinya, sintaks untuk mengakses atau memodifikasi data terlihat seperti akses variabel biasa, namun di balik layar, ia memanggil fungsi *getter* dan *setter*.

- **`val` (Read-only):** Secara otomatis menghasilkan *backing field* (jika diperlukan) dan sebuah fungsi *getter*.
- **`var` (Mutable):** Menghasilkan *backing field*, fungsi *getter*, dan fungsi *setter*.

**Mengapa konsep ini ada?**
Untuk menegakkan enkapsulasi secara *default*. Anda tidak perlu menulis boilerplate `get()` dan `set()` seperti di Java. Jika di masa depan Anda perlu menambahkan logika validasi saat variabel diubah, Anda cukup menambahkan *custom setter* tanpa merusak API publik (kode pemanggil tidak perlu diubah).

**Backing Field (`field`)**
Jika sebuah *property* membutuhkan tempat di memori untuk menyimpan nilainya, Kotlin compiler akan secara otomatis membuatkan **backing field**. Anda tidak bisa mendeklarasikan *field* secara eksplisit. Di dalam *custom getter/setter*, Anda mengakses *backing field* ini menggunakan *identifier* khusus yaitu `field`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi sistem akun bank yang mendemonstrasikan *custom getter*, *custom setter* dengan validasi, *computed property*, dan *backing property pattern*.

```kotlin
class BankAccount(val accountHolder: String) {

    // 1. Property standar dengan Custom Setter & Backing Field
    var balance: Double = 0.0
        set(value) {
            require(value >= 0) { "Balance tidak boleh negatif!" }
            // Menggunakan 'field' untuk menyimpan nilai ke memori.
            // JANGAN gunakan 'balance = value' di sini (akan memicu StackOverflow)
            field = value 
        }

    // 2. Computed Property (Tanpa Backing Field)
    // Tidak memakan alokasi memori tambahan, nilainya dihitung on-the-fly
    val isBankrupt: Boolean
        get() = balance == 0.0

    // 3. Backing Property Pattern (Sangat umum di Android/State Management)
    // _transactionHistory adalah state internal yang bisa dimutasi (Mutable)
    private val _transactionHistory = mutableListOf<String>()
    
    // transactionHistory adalah API publik yang read-only (Immutable)
    val transactionHistory: List<String>
        get() = _transactionHistory.toList()

    fun deposit(amount: Double) {
        if (amount > 0) {
            balance += amount // Memanggil getter, lalu setter dari 'balance'
            _transactionHistory.add("Deposit: $$amount")
        }
    }
}

fun main() {
    val account = BankAccount("Budi")
    
    account.deposit(150.0)
    println(account.balance) // Output: 150.0 (Memanggil getter)
    
    // account.balance = -50.0 // Akan melempar IllegalArgumentException
    
    println("Is Bankrupt? ${account.isBankrupt}") // Output: false
    println(account.transactionHistory) // Output: [Deposit: $150.0]
}
```

**Penjelasan Kode:**
- `balance`: Memiliki *custom setter* untuk mencegah saldo negatif. Kata kunci `field` merujuk pada lokasi memori asli dari `balance`.
- `isBankrupt`: Ini adalah *computed property*. Karena ia tidak memiliki nilai awal dan *getter*-nya tidak memanggil `field`, Kotlin **tidak** akan mengalokasikan memori (*backing field*) untuknya.
- `_transactionHistory` & `transactionHistory`: Pola ini memisahkan state internal yang *mutable* dari eksposur eksternal yang *immutable*, mencegah modifikasi list dari luar kelas.

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (JVM Bytecode):**
  Ketika kode Kotlin di atas dikompilasi ke JVM bytecode, Kotlin compiler akan mengubah *property* menjadi *private field* dan *public methods*.
  Misalnya, `var balance: Double` akan dikompilasi menjadi ekuivalen Java berikut:
  ```java
  private double balance = 0.0;
  public final double getBalance() { return this.balance; }
  public final void setBalance(double value) { 
      if (!(value >= 0)) throw new IllegalArgumentException("...");
      this.balance = value; 
  }
  ```
- **Alokasi Memori / Resource:**
  *Property* yang hanya memiliki *custom getter* dan tidak merujuk pada `field` (seperti `isBankrupt`) tidak akan menghasilkan *private field* di bytecode. Ini murni menjadi sebuah *method* `public final boolean isBankrupt()`. Ini sangat efisien dari segi memori.
- **Trade-offs:**
  Menggunakan *property* berarti setiap akses variabel adalah pemanggilan fungsi (method call). Meskipun JVM JIT Compiler sangat agresif dalam melakukan *inlining* pada *getter/setter* sederhana, menambahkan logika berat di dalam *custom getter/setter* dapat menyebabkan *bottleneck* performa yang tidak disadari oleh pemanggil (karena sintaksnya terlihat seperti akses variabel O(1)).

### 4. Best Practices & Common Pitfalls

- **Do's:**
  - Gunakan **Backing Property Pattern** (`_state` dan `state`) untuk mengenkapsulasi koleksi *mutable* (seperti `MutableList`, `MutableStateFlow`, `MutableLiveData`).
  - Gunakan *visibility modifier* pada *setter* jika Anda ingin *property* bisa dibaca dari luar tapi hanya bisa diubah dari dalam kelas: `var status: String = "Active"; private set`.
- **Don'ts:**
  - **JANGAN** menaruh operasi I/O, *network call*, atau komputasi berat (O(N) atau lebih) di dalam *getter/setter*. Pemanggil berekspektasi bahwa akses *property* itu instan. Jika butuh komputasi berat, gunakan fungsi eksplisit (misal: `fun calculateTotal(): Double`).
- **Edge Cases & Pitfalls (StackOverflowError):**
  Kesalahan paling umum developer pemula adalah memanggil *property* itu sendiri di dalam *custom accessor*-nya:
  ```kotlin
  var name: String = ""
      set(value) {
          name = value // SALAH! Ini akan memanggil setter ini lagi secara rekursif tak terbatas.
          // Gunakan: field = value
      }
  ```

### 5. Tantangan Eksplorasi Mandiri

1. **Konversi Suhu:** Buatlah kelas `Temperature` yang menyimpan suhu dalam Celcius (sebagai *backing field*). Buat *property* `fahrenheit` dan `kelvin` yang merupakan *computed properties* (keduanya memiliki *custom getter* dan *setter* yang secara otomatis mengonversi dan menyimpan nilainya kembali ke Celcius).
2. **Lazy Caching:** Implementasikan sebuah *property* dengan *custom getter* yang melakukan simulasi komputasi berat (misal: `Thread.sleep(1000)`), namun komputasi tersebut hanya dilakukan satu kali saat *property* pertama kali diakses. Simpan hasilnya di *backing property* (Hint: Jangan gunakan `by lazy` bawaan Kotlin, buat logikanya sendiri menggunakan *custom getter* dan *backing field* nullable).
3. **Bytecode Analysis:** Tulis sebuah kelas Kotlin sederhana dengan berbagai jenis *properties*. Gunakan fitur *Show Kotlin Bytecode* di IntelliJ IDEA / Android Studio, lalu klik *Decompile* untuk melihat representasi Java-nya. Amati kapan `field` dibuat dan kapan tidak.
