### 1. Konsep & Arsitektur Mendalam

Di Kotlin, fungsi adalah *first-class citizen*; fungsi dapat berdiri sendiri di tingkat berkas (*top-level functions*) tanpa harus dibungkus di dalam kelas utilitas statis seperti pada Java klasik. Dua fitur krusial yang menyederhanakan API design di Kotlin adalah **Default Arguments** dan **Single-Expression Functions**.

#### Mengapa Fitur Ini Ada?
1. **Mengeliminasi *Telescoping Arguments/Overload Explosion*:**
   Pada Java, untuk menyediakan fleksibilitas pemanggilan metode dengan parameter opsional, developer terpaksa membuat banyak *overload*:
   ```java
   // Anti-pattern telescoping di Java
   void connect(String host) { connect(host, 8080); }
   void connect(String host, int port) { connect(host, port, 3000); }
   void connect(String host, int port, int timeout) { ... }
   ```
   Kotlin menyelesaikan masalah kombinatorial ini di tingkat bahasa menggunakan **Default Arguments**, yang dipadukan dengan **Named Arguments** saat pemanggilan.
2. **Ekspresifitas Deklaratif (Single-Expression Functions):**
   Fungsi yang hanya mengembalikan sebuah nilai atau mendelegasikan panggilan sering kali terbebani oleh *boilerplate* kurung kurawal `{}` dan kata kunci `return`. Single-expression functions (`fun f() = ...`) memanfaatkan *Local Type Inference* dari compiler untuk menyajikan alur komputasi secara ringkas dan fungsional.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah contoh modul konfigurasi koneksi basis data/layanan backend yang memanfaatkan fitur-fitur ini secara idiomatik.

```kotlin
package com.architect.engine.network

import java.time.Duration

// Domain model
data class ConnectionConfig(
    val host: String,
    val port: Int,
    val timeout: Duration,
    val ssl: Boolean,
    val maxRetries: Int
)

class DatabaseClient {

    /**
     * Fungsi dengan Default Arguments.
     * Nilai default dievaluasi saat runtime pada call-site, bukan saat definisi fungsi.
     * Perhatikan parameter 'maxRetries' yang bergantung pada parameter sebelumnya ('ssl').
     */
    @JvmOverloads // Opsional: Membantu interoperabilitas dengan Java
    fun createConnection(
        host: String,
        port: Int = 5432,
        timeout: Duration = Duration.ofSeconds(30),
        ssl: Boolean = true,
        maxRetries: Int = if (ssl) 3 else 1 // Dynamic default value
    ): ConnectionConfig {
        require(host.isNotBlank()) { "Host tidak boleh kosong!" }
        require(port in 1..65535) { "Port harus valid (1-65535)" }
        
        return ConnectionConfig(host, port, timeout, ssl, maxRetries)
    }

    /**
     * Single-Expression Function: Tipe kembalian (Boolean) diinferensi oleh compiler.
     * Mengeliminasi block body dan explicit return untuk komputasi sederhana.
     */
    fun isProductionReady(config: ConnectionConfig): Boolean =
        config.ssl && config.timeout.seconds <= 10 && config.maxRetries >= 3

    /**
     * Single-Expression Function dengan branching `when`.
     */
    fun resolveEnvironment(port: Int): String = when (port) {
        5432 -> "POSTGRES_PROD"
        5433 -> "POSTGRES_STAGING"
        else -> "UNKNOWN_DEV"
    }
}

fun main() {
    val client = DatabaseClient()

    // 1. Memanfaatkan Default Arguments secara natural
    val devConfig = client.createConnection("localhost")

    // 2. Memanfaatkan Named Arguments: Menukar urutan argumen & meningkatkan readibility
    val customConfig = client.createConnection(
        host = "db.internal.infra",
        ssl = false, // maxRetries otomatis bernilai 1 berdasarkan dynamic default logic
        timeout = Duration.ofSeconds(5)
        // 'port' menggunakan nilai default 5432
    )

    println("Dev Config: $devConfig")
    println("Custom Config: $customConfig")
    println("Is Dev Prod-Ready? = ${client.isProductionReady(devConfig)}")
    println("Custom Env = ${client.resolveEnvironment(customConfig.port)}")
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Mekanisme Synthetic Bitmask
JVM tidak memiliki konsep bawaan (*native support*) untuk default parameter hingga saat ini. Kotlin menyelesaikan abstraksi ini di tingkat compiler dengan membuat **synthetic method** tersembunyi.

Ketika Anda mendeklarasikan fungsi:
```kotlin
fun connect(host: String, port: Int = 8080, ssl: Boolean = true)
```

Kotlin Compiler menghasilkan *dua* metode pada bytecode:
1. Metode asli:
   `public final void connect(String host, int port, boolean ssl)`
2. Metode sintetis (synthetic delegate):
   `public static void connect$default(DatabaseClient instance, String host, int port, boolean ssl, int mask, Object handler)`

**Mekanisme Bitmasking:**
Compiler memetakan setiap parameter opsional ke bit integer tunggal (dimulai dari $2^0, 2^1, dst.$):
- `port` (indeks 1) -> bit ke-1 ($2^1 = 2$)
- `ssl` (indeks 2) -> bit ke-2 ($2^2 = 4$)

Ketika pemanggil mengeksekusi `connect("localhost")`, pemanggil akan mengeksekusi metode `$default` dengan nilai mask `0b0110` (desimal: 6). Di dalam method `$default`, bytecode melakukan evaluasi bitwise AND:
```java
// Representasi ekuivalen dekompilasi Java dari bytecode
if ((mask & 2) != 0) {
    port = 8080; // Nilai default dieksekusi jika bit aktif
}
if ((mask & 4) != 0) {
    ssl = true;  // Nilai default dieksekusi jika bit aktif
}
instance.connect(host, port, ssl);
```
Jika jumlah parameter melebihi 32, compiler akan menyuntikkan mask kedua (`int mask1`), dan seterusnya.

#### Evaluasi Dynamic Default Argument
Parameter default di Kotlin dievaluasi secara dinamis secara sekuensial dari kiri ke kanan saat *call-site*. Oleh karena itu, argumen default di kanan valid mengonsumsi argumen di kirinya (seperti contoh: `maxRetries: Int = if (ssl) 3 else 1`).

#### Alokasi Memori / Resource
- **Single-Expression Functions:** Tidak ada *overhead* performa sama sekali. Bytecode yang dihasilkan identik dengan fungsi blok biasa dengan instruksi pengembalian eksplisit (`ARETURN`, `IRETURN`, dll.).
- **Default Arguments:** Menghasilkan sedikit overhead ukuran metadata class (*method footprint*) akibat adanya synthetic method dan instruksi percabangan bitmask, tetapi overhead komputasi CPU-nya bernilai $O(1)$ dan nyaris nol (hanya operasi logika bitwise).

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Named Arguments untuk Parameter Primitif/Boolean Beruntun:** Memanggil `createUser("John", true, false, true)` sangat rawan *human error*. Gunakan `createUser("John", isActive = true, isAdmin = false, sendEmail = true)` untuk mencegah ambiguitas data.
- **Manfaatkan `@JvmOverloads` Jika Membuat Library Multiplatform/Java-Interop:** Tanpa anotasi ini, kode Java yang memanggil fungsi Kotlin harus menyediakan seluruh parameter secara manual tanpa ada fallback ke nilai default.
- **Tuliskan Tipe Return Eksplisit untuk Public API pada Single-Expression:**
  ```kotlin
  // Dianjurkan untuk Public API (mencegah breaking changes tak sengaja)
  fun calculateDiscount(order: Order): BigDecimal = ...
  
  // Internal/Private functions cukup mengandalkan type inference
  private fun getBaseRate() = 0.05
  ```

#### Don'ts
- **Hindari Side-Effect di Parameter Default:**
  Jangan gunakan pemanggilan fungsi yang memodifikasi state eksternal sebagai default argument, seperti `id: String = generateAndSaveId()`. Evaluasi dinamis call-site dapat memicu side-effect berulang atau tidak terprediksi.
- **Jangan Memaksakan Single-Expression untuk Logika Kompleks:**
  Jika sebuah ekspresi membutuhkan nesting yang dalam atau banyak chaining logika bisnis, membungkusnya dalam satu baris ekspresi merusak keterbacaan (*readability*). Gunakan block-body biasa.

#### Edge Cases
- **Overriding Fungsi dengan Default Arguments:**
  Saat meng-override fungsi turunan (inheritance), fungsi override **dilarang keras** mendefinisikan ulang nilai default argumen.
  ```kotlin
  open class Base {
      open fun execute(timeout: Int = 1000) {}
  }
  class Derived : Base() {
      // COMPILE ERROR: An overriding function is not allowed to specify default values for its parameters
      override fun execute(timeout: Int = 2000) {} 
  }
  ```
  Nilai default diwarisi langsung dari implementasi dasar (*Base*) dan ditentukan secara virtual saat runtime.

### 5. Tantangan Eksplorasi Mandiri

1. **Investigasi Bytecode (Javap/Decompiler):**
   Buat sebuah fungsi top-level Kotlin yang memiliki 33 parameter dengan nilai default. Lakukan kompilasi, lalu buka bytecode-nya menggunakan IntelliJ IDEA (`Tools -> Kotlin -> Show Kotlin Bytecode -> Decompile`). Amati berapa banyak parameter `mask` (misal: `mask0`, `mask1`) yang diinjeksikan oleh compiler untuk menangani batasan 32-bit integer.
2. **Ketergantungan Forward-Reference:**
   Coba buat fungsi di mana parameter pertama mereferensikan parameter kedua:
   `fun compute(a: Int = b * 2, b: Int = 10)`.
   Amati mengapa compiler Kotlin menolak kode tersebut (*compile error: cannot access 'b' before its declaration*), dan pahami bagaimana urutan evaluasi parameter stack JVM memengaruhi aturan ini.
