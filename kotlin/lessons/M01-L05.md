### 1. Konsep & Arsitektur Mendalam

Kotlin secara sengaja menghilangkan perulangan gaya C klasik (`for (int i = 0; i < n; i++)`). Pendekatan ini digantikan oleh konsep iterasi berbasis **Operator Conventions** dan **Range/Progression Abstractions**.

#### Paradigma Iterasi Kotlin: Operator `iterator()`
Dalam Kotlin, ekspresi `for (item in container)` valid jika dan hanya jika `container` menyediakan fungsi anggota (atau fungsi ekstensi) bertanda `operator fun iterator()`. Fungsi ini harus mengembalikan sebuah objek yang mengimplementasikan metode:
- `operator fun next(): T`
- `operator fun hasNext(): Boolean`

Artinya, perulangan `for` di Kotlin adalah *syntactic sugar* tingkat tinggi yang bekerja secara polimorfik pada koleksi, array, string, maupun rentang angka, selama mematuhi kontrak antarmuka tersebut.

```
       for (x in collection)
                │
                ▼ (Diterjemahkan oleh Compiler)
       val it = collection.iterator()
       while (it.hasNext()) {
           val x = it.next()
           // body
       }
```

#### Taksonomi Ranges & Progressions
Rentang nilai dalam Kotlin dibagi menjadi dua konsep utama dalam hierarki standar pustaka (`kotlin.ranges`):
1. **`ClosedRange<T>`**: Merepresentasikan interval matematika tertutup $[a, b]$. Memerlukan tipe data yang mengimplementasikan `Comparable<T>`. Digunakan utamanya untuk evaluasi keanggotaan (`contains` atau operator `in`).
2. **`*Progression` (`IntProgression`, `LongProgression`, `CharProgression`)**: Merepresentasikan barisan aritmetika berhingga: $a, a + step, a + 2 \cdot step, \dots \le b$. Progression memiliki tiga komponen inti: `first`, `last`, dan `step`.
3. **`*Range` (`IntRange`, `LongRange`, `CharRange`)**: Subkelas dari *progression* dengan nilai `step` konstan $= 1$. `IntRange` mengimplementasikan `ClosedRange<Int>` dan `Iterable<Int>`.

Rentang instan dibuat menggunakan operator:
- `..` (fungsi `rangeTo`): Inklusif terhadap kedua batas ($[start, end]$).
- `..<` (sejak Kotlin 1.9) atau `until`: Rentang setengah terbuka ($[start, end)$).
- `downTo`: Progression mundur dari batas atas ke batas bawah dengan step bernilai negatif.
- `step`: Fungsi ekstensi yang mengembalikan *progression* baru dengan selisih antar-elemen yang dimodifikasi.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi idiomatik mencakup berbagai variasi perulangan, penggunaan range/step, serta integrasi custom iterator dan labeled jumps pada kasus pengolahan data batch.

```kotlin
package com.alvint.loops

data class BatchChunk(val id: Int, val payload: String)

class BatchQueue(private val items: List<BatchChunk>) {
    // Memenuhi konvensi operator iterator
    operator fun iterator(): Iterator<BatchChunk> = items.iterator()
}

fun main() {
    // -------------------------------------------------------------
    // 1. Variasi Ranges & Progressions
    // -------------------------------------------------------------
    println("=== 1. Progression & Step ===")
    
    // Inklusif 0..10 dengan lompatan 2
    for (i in 0..10 step 2) {
        print("$i ") // 0 2 4 6 8 10
    }
    println()

    // Half-open interval: [0, 5)
    for (i in 0 until 5) {
        print("$i ") // 0 1 2 3 4
    }
    println()

    // Mundur (downTo) dengan step
    for (i in 10 downTo 2 step 3) {
        print("$i ") // 10 7 4
    }
    println()

    // -------------------------------------------------------------
    // 2. Custom Type Iteration Menggunakan Operator Convention
    // -------------------------------------------------------------
    println("\n=== 2. Custom Object Iteration ===")
    val queue = BatchQueue(
        listOf(
            BatchChunk(1, "AUTH_EVENT"),
            BatchChunk(2, "PAYMENT_INIT"),
            BatchChunk(3, "POISON_PILL"),
            BatchChunk(4, "ORDER_COMPLETED")
        )
    )

    for (chunk in queue) {
        println("Memproses Chunk: [${chunk.id}] -> ${chunk.payload}")
    }

    // -------------------------------------------------------------
    // 3. Nested Loop dengan Labeled Jump (break/continue@label)
    // -------------------------------------------------------------
    println("\n=== 3. Labeled Breaks & While ===")
    val matrix = arrayOf(
        intArrayOf(1, 2, 3),
        intArrayOf(4, -99, 6), // -99 menandakan corrupt data
        intArrayOf(7, 8, 9)
    )

    // Mencari elemen dan melompat keluar dari perulangan bertingkat
    outerLoop@ for (row in matrix.indices) {
        for (col in matrix[row].indices) {
            val value = matrix[row][col]
            if (value == -99) {
                println("Data korup terdeteksi pada [$row, $col]! Batalkan seluruh pemrosesan matriks.")
                break@outerLoop
            }
            print("$value ")
        }
        println()
    }

    // -------------------------------------------------------------
    // 4. While & Do-While: Pola Exponential Backoff
    // -------------------------------------------------------------
    println("\n=== 4. While Loop: Retry Pattern ===")
    var attempt = 1
    val maxAttempts = 3
    var isSuccess = false

    while (attempt <= maxAttempts && !isSuccess) {
        println("Mencoba koneksi database, percobaan ke-$attempt...")
        if (attempt == 3) {
            isSuccess = true
            println("Koneksi berhasil!")
        } else {
            attempt++
        }
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Eliminasi Overhead Alokasi
Salah satu kekhawatiran terbesar dalam pemrograman berbasis objek adalah biaya alokasi objek `Iterator` dan *boxing* tipe data primitif pada setiap perulangan. 

Compiler Kotlin (`kotlinc`) menerapkan optimasi lowering agresif:
Jika Anda menulis:
```kotlin
for (i in 0..10 step 2) {
    println(i)
}
```
`kotlinc` **tidak** menginstansiasi objek `IntRange` maupun `IntIterator` di JVM heap jika rentang tersebut dideklarasikan secara eksplisit dalam ekspresi `for`. Melalui bytecode decompilation ke Java, kode di atas ditranslasikan menjadi loop `for` berbasis variabel primitif flat:

```java
// Bytecode Decompiled Output (Representasi Java Setara)
int i = 0;
int limit = 10;
int step = 2;
if (step > 0) {
    if (i <= limit) {
        while (true) {
            System.out.println(i);
            if (i == limit) break;
            i += step;
        }
    }
}
```
Hasilnya adalah instruksi byte code `iloop` standar yang berjalan dengan alokasi memori **0 byte (zero-allocation)** dan dieksekusi secara instan di register CPU.

#### Kapan Optimasi Gagal (Optimization De-optimization)?
Optimasi zero-allocation akan gugur jika *range* disimpan ke dalam variabel polimorfik atau diteruskan ke fungsi generic:
```kotlin
val myRange: Iterable<Int> = 0..10 // Compiler terpaksa melakukan boxing
for (i in myRange) { ... }          // Memanggil Iterable.iterator() -> alokasi objek Iterator
```
Pada kondisi ini:
1. Instansi objek `IntRange` dialokasikan di heap.
2. Panggilan `iterator()` mengalokasikan objek baru bertipe `IntProgressionIterator`.
3. Tipe data primitif `int` berpotensi mengalami mekanisme *boxing* menjadi `java.lang.Integer` jika dioperasikan di level generic `Iterable<T>`.

#### Trade-offs: `indices` vs `withIndex()`
- `for (i in array.indices)`: Menggunakan ekspresi `0 until array.size`, yang dioptimasi langsung menjadi loop primitif berindeks tanpa alokasi objek tambahan.
- `for ((index, value) in array.withIndex())`: Menghasilkan wrapper struct `IndexedValue<T>`, yang dapat memicu alokasi heap iterator kecil secara konstan kecuali di-inline secara tepat oleh JIT compiler.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `indices` untuk iterasi berbasis indeks array/list**:
  ```kotlin
  // Benar dan dioptimasi compiler menjadi size-check biasa
  for (i in list.indices) { ... }
  ```
- **Gunakan `until` atau `..<` untuk menghindari *Off-by-One Error***:
  Jika bekerja dengan array ukuran $N$, gunakan `0 until size` bukan `0..size - 1` untuk kejelasan semantik.
- **Pilih `repeat(n)` untuk pengulangan instruksi murni**:
  ```kotlin
  repeat(5) { attempt ->
      println("Menjalankan tugas: $attempt")
  }
  ```
  Fungsi `repeat` ditandai dengan keyword `inline`, sehingga blok lambda dieksekusi sebagai perulangan dasar tanpa overhead alokasi fungsi objek.

#### Don'ts
- **Hindari penggunaan operator `step` bernilai negatif**:
  `step` hanya menerima argumen positif ($> 0$). Jika membutuhkan hitungan mundur, gunakan `downTo`, bukan mengubah step menjadi negatif:
  ```kotlin
  // SALAH: IllegalArgumentException: Step must be positive, was: -1.
  for (i in 10..1 step -1) { ... }

  // BENAR
  for (i in 10 downTo 1 step 1) { ... }
  ```
- **Jangan gunakan `..` untuk rentang terbalik secara langsung**:
  `for (i in 5..1)` tidak akan mengeksekusi body loop sama sekali karena secara default `first > last` pada rentang bertambah menghasilkan himpunan kosong.

#### Edge Cases
- **Overhead Loop `forEach` vs `for` Tradisional**:
  Pada koleksi standar (`List`, `Set`), `collection.forEach { }` menggunakan lambda inline, efisiensinya setara. Namun, pada koleksi pihak ketiga non-inlined atau tipe data primitif, loop `for (item in ...)` bawaan bahasa lebih aman dari alokasi lambda tak terduga.
- **Perubahan State Koleksi saat Iterasi (`ConcurrentModificationException`)**:
  Jika Anda memodifikasi (menambah/menghapus) elemen dari sebuah `MutableList` langsung di dalam loop `for`, JVM akan melempar exception:
  ```kotlin
  // Menyebabkan ConcurrentModificationException
  for (item in mutableList) {
      if (item.isInvalid) mutableList.remove(item)
  }
  
  // Solusi: Gunakan iterator eksplisit atau filter inplace
  mutableList.removeAll { it.isInvalid }
  ```
