## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Kotlin Multiplatform (KMP) memungkinkan developer untuk membagikan kode logika bisnis (domain, data, network) melintasi berbagai platform sambil tetap mempertahankan akses penuh ke API native masing-masing platform. Berbeda dengan framework *cross-platform* lain yang menggunakan *bridge* saat runtime (seperti React Native) atau me-render UI sendiri di atas kanvas (seperti Flutter), KMP beroperasi di level **kompilator (compiler)**.

Arsitektur KMP didasarkan pada konsep **Source Sets** dan **Compiler Toolchains**:
1. **`commonMain`**: Berisi kode murni Kotlin. Tidak memiliki dependensi ke JVM, Android SDK, atau iOS Foundation.
2. **Platform Targets**:
   - **Kotlin/JVM**: Mengkompilasi kode menjadi Java Bytecode (untuk Android dan Desktop/Java).
   - **Kotlin/Native**: Menggunakan LLVM backend untuk mengkompilasi kode langsung menjadi *machine code* (binari native) untuk iOS, macOS, Linux, dan Windows. Tidak ada JVM yang berjalan di iOS.
   - **Kotlin/JS & Kotlin/Wasm**: Mengkompilasi kode menjadi JavaScript atau WebAssembly untuk target Web.

Untuk menjembatani kode *common* dengan API spesifik platform, Kotlin menggunakan mekanisme **`expect` / `actual`**. Anda mendeklarasikan kontrak (`expect`) di `commonMain`, dan kompilator akan memaksa Anda menyediakan implementasinya (`actual`) di setiap target platform.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah konfigurasi Gradle modern dan implementasi `expect`/`actual` untuk mengambil informasi perangkat keras di Android, iOS, dan Desktop.

**1. Konfigurasi Target di `build.gradle.kts`**
```kotlin
plugins {
    kotlin("multiplatform")
    id("com.android.library")
}

kotlin {
    // 1. Target Android (Kompilasi ke JVM Bytecode / DEX)
    androidTarget {
        compilations.all {
            kotlinOptions { jvmTarget = "17" }
        }
    }
    
    // 2. Target Desktop (Kompilasi ke JVM Bytecode)
    jvm("desktop")
    
    // 3. Target iOS (Kompilasi ke Native Binary via LLVM)
    listOf(
        iosX64(),
        iosArm64(),
        iosSimulatorArm64()
    ).forEach { iosTarget ->
        iosTarget.binaries.framework {
            baseName = "SharedLogic"
            isStatic = true
        }
    }

    // Konfigurasi Source Sets
    sourceSets {
        val commonMain by getting {
            dependencies {
                // Dependensi KMP murni (contoh: Ktor, Coroutines, Serialization)
                implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.7.3")
            }
        }
        val androidMain by getting
        val desktopMain by getting
        val iosMain by creating {
            dependsOn(commonMain)
            iosX64Main.get().dependsOn(this)
            iosArm64Main.get().dependsOn(this)
            iosSimulatorArm64Main.get().dependsOn(this)
        }
    }
}
```

**2. Implementasi `expect` / `actual`**

```kotlin
// --- File: src/commonMain/kotlin/Platform.kt ---
// Deklarasi kontrak di Common
expect class Platform() {
    val osName: String
    val osVersion: String
    fun logSystemInfo()
}

// --- File: src/androidMain/kotlin/Platform.kt ---
// Implementasi untuk Android (Bisa akses android.os.*)
import android.os.Build
import android.util.Log

actual class Platform actual constructor() {
    actual val osName: String = "Android"
    actual val osVersion: String = "${Build.VERSION.SDK_INT}"
    
    actual fun logSystemInfo() {
        Log.d("KMP_LOG", "Running on $osName $osVersion")
    }
}

// --- File: src/iosMain/kotlin/Platform.kt ---
// Implementasi untuk iOS (Bisa akses platform.UIKit.* via C-Interop)
import platform.UIKit.UIDevice
import platform.Foundation.NSLog

actual class Platform actual constructor() {
    actual val osName: String = UIDevice.currentDevice.systemName()
    actual val osVersion: String = UIDevice.currentDevice.systemVersion
    
    actual fun logSystemInfo() {
        // NSLog di-binding langsung dari Objective-C/C
        NSLog("Running on %s %s", osName, osVersion)
    }
}

// --- File: src/desktopMain/kotlin/Platform.kt ---
// Implementasi untuk Desktop JVM (Bisa akses java.lang.System)
actual class Platform actual constructor() {
    actual val osName: String = System.getProperty("os.name") ?: "Desktop"
    actual val osVersion: String = System.getProperty("os.version") ?: "Unknown"
    
    actual fun logSystemInfo() {
        println("Running on $osName $osVersion")
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**:
  - **Android/Desktop**: Kode Kotlin dikompilasi oleh `kotlinc-jvm` menjadi `.class` (bytecode). Di Android, bytecode ini diubah lagi menjadi `.dex` oleh D8/R8 dan dieksekusi oleh Android Runtime (ART).
  - **iOS**: Kode Kotlin dikompilasi oleh `kotlinc-native`. Kompilator ini memiliki *frontend* yang menghasilkan Intermediate Representation (IR), yang kemudian diumpankan ke **LLVM backend**. LLVM mengoptimasi dan menghasilkan *machine code* spesifik arsitektur (ARM64 untuk iPhone fisik, x86_64/ARM64 untuk Simulator). Hasil akhirnya adalah `.framework` (Objective-C framework) yang bisa langsung di-import di Xcode.
- **Alokasi Memori / Resource**:
  - **JVM**: Menggunakan Garbage Collector (GC) standar dari JVM atau ART.
  - **Kotlin/Native**: Menggunakan *New Memory Manager* (sejak Kotlin 1.7.20). Ini adalah *tracing garbage collector* yang berjalan secara native. Berbeda dengan model memori K/N lama yang sangat ketat terhadap *thread confinement* (objek beku/frozen), model baru ini memungkinkan objek Kotlin dibagikan antar *thread* secara bebas, mirip dengan JVM, namun tetap beroperasi tanpa *Virtual Machine*.
- **Trade-offs**:
  - Waktu kompilasi Kotlin/Native (iOS) jauh lebih lambat dibandingkan Kotlin/JVM karena proses LLVM *optimization* dan *linking* yang berat.
  - Ukuran binari iOS akan sedikit membengkak karena Kotlin/Native harus menyertakan *runtime* ringan (untuk GC, exception handling, dan coroutines) di dalam `.framework`.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - **Gunakan Dependency Injection (DI) daripada `expect`/`actual` jika memungkinkan.** Mendefinisikan `interface` di `commonMain` dan meng-inject implementasi spesifik platform dari sisi native (Swift/Kotlin Android) seringkali lebih fleksibel dan mudah di-test daripada menggunakan `expect`/`actual`.
  - **Gunakan Koin atau Kodein** untuk DI di KMP, karena Dagger/Hilt sangat terikat dengan JVM/Android.
  - **Pahami Objective-C Interop.** Kotlin/Native saat ini mengekspor API ke iOS melalui header Objective-C, bukan Swift murni (meskipun Swift interop sedang dikembangkan). Gunakan anotasi `@ObjCName` untuk mempercantik nama fungsi/kelas saat dipanggil dari Swift.
- **Don'ts**:
  - **Jangan bocorkan tipe spesifik platform ke `commonMain`.** Misalnya, jangan mencoba me-return `Context` Android atau `UIViewController` iOS di fungsi `commonMain`.
  - **Jangan abaikan penanganan Exception di iOS.** Exception di Kotlin (Unchecked) yang tidak ditangkap dan menembus batas Swift/Objective-C akan menyebabkan aplikasi iOS *crash* (SIGABRT). Gunakan `@Throws` atau bungkus hasil dalam tipe `Result<T>`.
- **Edge Cases**:
  - **Coroutines & Swift**: Fungsi `suspend` Kotlin diterjemahkan menjadi fungsi dengan *completion handler* atau `async/await` di Swift. Namun, `Flow` Kotlin tidak otomatis menjadi `Publisher` (Combine) atau `AsyncSequence` di Swift tanpa *wrapper* tambahan (seperti library `SKIE` atau *custom wrapper*).

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Key-Value Storage**: Buatlah modul KMP yang menggunakan `expect`/`actual` untuk menyimpan token sesi. Gunakan `SharedPreferences` / `DataStore` di `androidMain` dan `NSUserDefaults` di `iosMain`.
2. **Swift Interop dengan Flow**: Buatlah sebuah `StateFlow<String>` di `commonMain`. Tulis *wrapper* agar `StateFlow` tersebut dapat diobservasi secara reaktif di dalam `View` SwiftUI di proyek iOS Anda.
3. **C-Interop (Advanced)**: Buat target Kotlin/Native murni (misal: `linuxX64` atau `macosX64`). Gunakan file `.def` (C-Interop) untuk mengimpor library C standar (seperti `curl` atau `sqlite3`) dan panggil fungsi C tersebut langsung dari kode Kotlin Anda.
