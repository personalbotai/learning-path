## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam Kotlin, segala sesuatu direpresentasikan sebagai objek di level sintaksis. Tidak ada tipe primitif eksplisit seperti `int` atau `double` di Java. Namun, di bawah kap (pada level JVM), tipe primitif sangat krusial untuk performa dan efisiensi memori. 

Untuk menjembatani filosofi "semuanya adalah objek" dengan kebutuhan performa JVM, Kotlin membedakan antara **Object Arrays** (`Array<T>`) dan **Primitive Arrays** (`IntArray`, `DoubleArray`, `BooleanArray`, dll).

- **Object Array (`Array<Int>`)**: Merupakan array generik. Pada JVM, ini dikompilasi menjadi array dari tipe *wrapper* (misalnya `java.lang.Integer[]`). Setiap elemen dalam array ini adalah referensi (pointer) yang menunjuk ke objek di dalam *Heap memory*.
- **Primitive Array (`IntArray`)**: Merupakan kelas khusus yang merepresentasikan array primitif. Pada JVM, ini dikompilasi langsung menjadi array primitif Java (misalnya `int[]`). Elemen-elemennya disimpan secara berurutan (*contiguous*) di dalam memori tanpa *overhead* objek.

Keberadaan *Primitive Arrays* sangat vital untuk menghindari proses **Autoboxing/Unboxing** (konversi otomatis antara tipe primitif dan tipe *wrapper* objeknya) yang memakan banyak siklus CPU dan memicu *Garbage Collection* (GC) secara berlebihan pada operasi komputasi intensif.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah cara inisialisasi, penggunaan, dan konversi antara kedua jenis array ini dalam skenario pemrosesan data.

```kotlin
// 1. Inisialisasi Object Array (Array<Int>)
// Menggunakan arrayOf() - Tipe inferensinya adalah Array<Int>
val objectArray: Array<Int> = arrayOf(1, 2, 3, 4, 5)

// Inisialisasi dengan lambda (misal: array berisi kuadrat indeks)
val dynamicObjectArray = Array(5) { index -> index * index }

// 2. Inisialisasi Primitive Array (IntArray)
// Menggunakan intArrayOf() - Jauh lebih efisien
val primitiveArray: IntArray = intArrayOf(1, 2, 3, 4, 5)

// Inisialisasi dengan lambda
val dynamicPrimitiveArray = IntArray(5) { index -> index * index }

// 3. Kasus Nyata: Perbedaan Performa pada Komputasi
fun processAudioSamples(samples: DoubleArray): Double {
    var sum = 0.0
    // Iterasi pada DoubleArray sangat cepat karena cache locality
    for (sample in samples) {
        sum += sample * 1.5
    }
    return sum
}

fun main() {
    // 4. Konversi antar tipe (Gunakan hanya jika terpaksa, karena memakan O(N) waktu)
    val boxedArray: Array<Int> = primitiveArray.toTypedArray()
    val unboxedArray: IntArray = objectArray.toIntArray()
    
    println("Boxed class: ${boxedArray::class.java}")     // class [Ljava.lang.Integer;
    println("Unboxed class: ${unboxedArray::class.java}") // class [I
}
```

**Penjelasan Kode:**
- `Array(size) { ... }` dan `IntArray(size) { ... }` menggunakan *factory function* untuk inisialisasi dinamis.
- Fungsi ekstensi `.toTypedArray()` digunakan untuk mengubah primitive array menjadi object array (Boxing).
- Fungsi ekstensi `.toIntArray()` digunakan untuk mengubah object array menjadi primitive array (Unboxing).

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (Bytecode Mapping)**:
  - `Array<Int>` dipetakan ke bytecode JVM sebagai `[Ljava/lang/Integer;`.
  - `IntArray` dipetakan ke bytecode JVM sebagai `[I`.
  - Saat Anda melakukan operasi matematika pada `Array<Int>`, JVM harus melakukan *unboxing* (memanggil `intValue()`) pada setiap elemen sebelum operasi dilakukan, lalu melakukan *boxing* (memanggil `Integer.valueOf()`) jika hasilnya disimpan kembali ke array objek.

- **Alokasi Memori / Resource**:
  - **`IntArray` (Primitive)**: Memori dialokasikan secara *contiguous* (bersebelahan). Array dengan 1000 elemen `int` hanya membutuhkan memori sekitar `16 bytes (Array Header) + (1000 * 4 bytes) = ~4016 bytes`. CPU dapat memuat blok memori ini ke L1/L2 Cache dengan sangat efisien (*Cache Locality* tinggi).
  - **`Array<Int>` (Object)**: Memori terfragmentasi. Array menyimpan 1000 referensi. Ukurannya: `16 bytes (Array Header) + (1000 * 4/8 bytes untuk referensi) + (1000 * 16 bytes untuk setiap objek Integer di Heap) = ~20.000+ bytes`. Selain boros memori sebesar 5x lipat, hal ini menyebabkan *Cache Misses* pada CPU karena harus melompat ke berbagai lokasi di Heap untuk membaca nilai sebenarnya.

- **Trade-offs**:
  - *Primitive Arrays* sangat cepat dan hemat memori, tetapi tidak bisa menyimpan nilai `null` dan tidak bisa digunakan langsung sebagai argumen tipe generik (misal: `List<T>`).
  - *Object Arrays* mendukung *nullability* (`Array<Int?>`) dan kompatibel dengan sistem generik, namun mengorbankan performa dan memori.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - **Selalu gunakan Primitive Arrays** (`IntArray`, `DoubleArray`, `ByteArray`, dll) ketika berurusan dengan data numerik mentah, pemrosesan gambar/audio, atau algoritma kriptografi.
  - Gunakan `ByteArray` untuk operasi I/O (seperti membaca file atau *network socket*).
  - Gunakan `List<Int>` daripada `Array<Int>` jika Anda membutuhkan koleksi objek numerik. Di Kotlin, `List` lebih idiomatik dan memiliki API yang lebih kaya daripada `Array`.

- **Don'ts**:
  - Jangan gunakan `Array<Int>`, `Array<Double>`, dll., kecuali Anda berinteraksi dengan API Java lama yang secara eksplisit meminta `Integer[]` atau `Double[]`.
  - Jangan melakukan konversi bolak-balik (`toTypedArray()` dan `toIntArray()`) di dalam *loop* atau jalur eksekusi kritis (*hot path*), karena ini akan memicu alokasi objek masif dan *Garbage Collection* (GC pause).

- **Edge Cases**:
  - **Varargs**: Jika Anda memanggil fungsi Java yang menerima `int...`, Anda harus mengirimkan `IntArray`, bukan `Array<Int>`. Anda bisa menggunakan *spread operator* (`*`) seperti ini: `javaMethod(*myIntArray)`.
  - **Nullability**: Jika Anda benar-benar membutuhkan array numerik yang elemennya bisa bernilai `null`, Anda terpaksa menggunakan `Array<Int?>`. Tidak ada representasi primitif untuk ini di JVM.
