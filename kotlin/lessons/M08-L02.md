### 1. Konsep & Arsitektur Mendalam

Ktor Client adalah pustaka *networking asynchronous* multiplatform yang dibangun di atas fondasi Kotlin Coroutines. Berbeda dengan HTTP *client* tradisional pada JVM (seperti Apache HttpClient atau OkHttp) yang sering kali dirancang monolitik dan terikat erat pada Java NIO/Threads, Ktor Client menggunakan pendekatan arsitektur modular berbasis **Pipeline** dan **Pluggable Engines**.

```
+----------------------------------------------------------------+
|                       Application Layer                        |
+----------------------------------------------------------------+
                               |
+----------------------------------------------------------------+
|                Ktor Client Core (Pipeline Engine)              |
|  [Setup] -> [Monitoring] -> [Send] -> [Transform] -> [Receive] |
+----------------------------------------------------------------+
                               |
       +-----------------------+-----------------------+
       | Plugins (ContentNegotiation, Auth, Logging)   |
       +-----------------------+-----------------------+
                               |
+----------------------------------------------------------------+
|                     Engine Abstraction                         |
|  +---------+   +---------+   +----------+   +---------------+  |
|  | CIO     |   | OkHttp  |   | Darwin   |   | JS / WinHttp  |  |
|  | (Pure-K)|   | (JVM/And)   | (iOS/Mac)|   | (Web/Windows) |  |
+----------------------------------------------------------------+
```

#### Arsitektur Inti Ktor Client:
1. **Engine Abstraction Layer**: Ktor memisahkan antarmuka API publik dari *runtime network driver*. Kode logika aplikasi berinteraksi dengan API seragam (`HttpClient`), sementara transport layer didelegasikan ke engine:
   - **CIO (Coroutine I/O)**: Engine murni Kotlin multiplatform berbasis non-blocking socket via coroutines.
   - **OkHttp / Apache**: Memanfaatkan pool koneksi dan HTTP/2 stack mature pada ekosistem JVM/Android.
   - **Darwin**: Membungkus `NSURLSession` bawaan Apple untuk integrasi native di iOS/macOS.
   - **JS / Fetch**: Menggunakan Web Fetch API di lingkungan JavaScript runtime.
2. **Pipelines & Phases**: Setiap *request* dan *response* melewati *pipeline machine*. Pipeline terdiri dari fase-fase terurut (*phases*). Interceptor dapat didaftarkan pada fase tertentu untuk memanipulasi header, serialisasi payload, atau mengalihkan *control flow*.
3. **Plugin Architecture**: Di Ktor, fitur-fitur seperti *JSON Serialization*, *Authentication*, *Logging*, dan *WebSockets* tidak terkompilasi langsung di dalam inti klien, melainkan sebagai plugin independen yang mengaitkan (*hook*) fungsionalitasnya ke fase pipeline yang relevan.

### 2. Implementasi & Contoh Kasus Nyata

Contoh implementasi Ktor Client multiplatform dengan engine CIO, *bearer authentication*, *content negotiation*, serta penanganan *error*:

```kotlin
import io.ktor.client.*
import io.ktor.client.call.*
import io.ktor.client.engine.cio.*
import io.ktor.client.plugins.*
import io.ktor.client.plugins.auth.*
import io.ktor.client.plugins.auth.providers.*
import io.ktor.client.plugins.contentnegotiation.*
import io.ktor.client.plugins.logging.*
import io.ktor.client.request.*
import io.ktor.client.statement.*
import io.ktor.http.*
import io.ktor.serialization.kotlinx.json.*
import kotlinx.coroutines.runBlocking
import kotlinx.serialization.Serializable
import kotlinx.serialization.json.Json

// 1. Data Transfer Object (DTO)
@Serializable
data class UserProfile(
    val id: Long,
    val username: String,
    val email: String,
    val role: String
)

@Serializable
data class ErrorResponse(
    val message: String,
    val code: Int
)

// 2. Network Client Factory & Configuration
object NetworkClientFactory {
    fun createClient(): HttpClient {
        return HttpClient(CIO) {
            // Nonaktifkan exception default untuk handling manual response status
            expectSuccess = false

            // Konfigurasi Serialization (kotlinx.serialization)
            install(ContentNegotiation) {
                json(Json {
                    ignoreUnknownKeys = true
                    isLenient = true
                    prettyPrint = false
                })
            }

            // Konfigurasi Timeout
            install(HttpTimeout) {
                requestTimeoutMillis = 15_000
                connectTimeoutMillis = 10_000
                socketTimeoutMillis = 15_000
            }

            // Auto-Injection Token & Refresh Handling
            install(Auth) {
                bearer {
                    loadTokens {
                        BearerTokens(
                            accessToken = "initial_access_token_xyz",
                            refreshToken = "refresh_token_abc"
                        )
                    }
                    refreshTokens {
                        // Dipanggil otomatis saat menerima respons 401 Unauthorized
                        // Di industri: panggil endpoint refresh token di sini
                        BearerTokens("refreshed_access_token_123", "refresh_token_abc")
                    }
                }
            }

            // Logging Pipeline
            install(Logging) {
                logger = Logger.DEFAULT
                level = LogLevel.INFO
            }

            // Engine-specific tuning
            engine {
                maxConnectionsCount = 1000
                endpoint {
                    maxConnectionsPerRoute = 100
                    pipelineMaxSize = 20
                    keepAliveTime = 5000
                    connectAttempts = 3
                }
            }
        }
    }
}

// 3. Service Layer Implementation
class UserService(private val client: HttpClient) {
    private val baseUrl = "https://api.internal.infra/v1"

    suspend fun fetchUserProfile(userId: Long): Result<UserProfile> {
        return try {
            val response: HttpResponse = client.get("$baseUrl/users/$userId") {
                contentType(ContentType.Application.Json)
                header("X-Client-Version", "2.4.0")
            }

            when (response.status) {
                HttpStatusCode.OK -> {
                    val profile = response.body<UserProfile>()
                    Result.success(profile)
                }
                HttpStatusCode.NotFound -> {
                    Result.failure(NoSuchElementException("User ID $userId tidak ditemukan."))
                }
                HttpStatusCode.Unauthorized -> {
                    Result.failure(IllegalAccessException("Akses ditolak: Token tidak valid."))
                }
                else -> {
                    val err = response.body<ErrorResponse>()
                    Result.failure(RuntimeException("API Error [${err.code}]: ${err.message}"))
                }
            }
        } catch (e: ClientRequestException) {
            Result.failure(e)
        } catch (e: HttpRequestTimeoutException) {
            Result.failure(e)
        } catch (e: Exception) {
            Result.failure(e)
        }
    }
}

fun main() = runBlocking {
    val client = NetworkClientFactory.createClient()
    val userService = UserService(client)

    val result = userService.fetchUserProfile(42)
    result.fold(
        onSuccess = { println("Profile loaded: ${it.username} (${it.email})") },
        onFailure = { println("Failed to load profile: ${it.message}") }
    )

    // Selalu tutup client saat aplikasi shutdown untuk merilis resources
    client.close()
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Pipeline Machine
Saat eksekusi `client.get(...)`, Ktor tidak langsung mengeksekusi I/O:
1. Sebuah objek `HttpRequestBuilder` dibuat dan dimasukkan ke dalam `HttpRequestPipeline`.
2. Pipeline memproses serangkaian interceptor pada fase:
   - **`Before`**: Inisialisasi awal context.
   - **`State`**: Modifikasi konfigurasi (e.g., query params).
   - **`Transform`**: Payload Kotlin diubah menjadi `OutgoingContent` oleh serializer.
   - **`Render`**: Headers dan metadata dienkapsulasi.
   - **`Send`**: Engine menerima request dan menginisiasi transmisi byte.
3. Setelah transmisi selesai, data balik masuk ke `HttpResponsePipeline`, di mana `ByteReadChannel` dibaca secara streaming atau di-*parse* ke tipe objek target via fase `Receive` -> `Transform`.

#### Alokasi Memori & Zero-Copy I/O
Ktor Client memanfaatkan abstractions `ByteReadChannel` dan `ByteWriteChannel` dari pustaka I/O Kotlin.
- **Buffer Pooling**: Ktor menggunakan memori *object pools* (seperti `DirectByteBufferPool` pada JVM). Payload jaringan tidak dialokasikan sebagai array byte (`ByteArray`) baru secara terus-menerus. Sebaliknya, buffer memori digunakan ulang (*recycled*) untuk meminimalkan beban Garbage Collector (GC Pressure).
- **Suspension over Thread Blocking**: Engine CIO tidak menduduki *OS-thread* saat menunggu latensi jaringan. CIO menggunakan satu atau sedikit thread untuk mengelola *OS selector multiplexer* (misalnya `epoll` di Linux, `kqueue` di macOS, `select` di Windows), memarkir coroutine pada suspension point (`Continuation`), dan membangunkannya kembali ketika kernel memberi tahu bahwa socket memiliki byte yang siap dibaca.

#### Trade-offs: CIO vs Platform-Native Engines
| Metrik / Aspek | Ktor CIO Engine | Platform Native (OkHttp / Darwin) |
| :--- | :--- | :--- |
| **Portabilitas** | Murni Kotlin, seragam di JVM & Multiplatform. | Terikat platform (JVM/Android untuk OkHttp, Apple OS untuk Darwin). |
| **HTTP/2 & HTTP/3** | Terbatas (fokus utama HTTP/1.x, implementasi H2 eksperimental). | Sangat stabil dan teruji di level enterprise. |
| **Memory Footprint** | Rendah karena tidak ada wrapper bridging C/Java layer. | Lebih tinggi, membawa dependency stack bawaan platform. |
| **Fitur Tingkat Lanjut** | Terbatas pada konfigurasi socket mentah. | Penuh (OS-level proxy auto-discovery, platform certificate stores, HTTP/3 QUIC). |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Lifecycle Singleton**: Instansiasi `HttpClient` adalah operasi komputasi yang mahal karena mengalokasikan connection pool, SSL context, thread pools, dan pipeline interceptors. Bagikan *single instance* `HttpClient` ke seluruh dependensi aplikasi via Dependency Injection (Koin, Dagger/Hilt, dsb.).
- **Konsumsi Body Respons**: Saat menggunakan `HttpStatement` atau streaming, selalu konsumsi seluruh channel atau panggil `.cancel()` jika pembacaan dihentikan di tengah jalan. Meninggalkan stream terbuka menyebabkan *socket leak* pada pool.
- **Konfigurasi Timeout Eksplisit**: Jangan pernah menggunakan default timeout tak terbatas di *production*. Selalu atur kombinasi: `requestTimeout`, `connectTimeout`, dan `socketTimeout`.

#### Don'ts
- **Membuat Client Baru per Request**: Pola anti-pattern fatal:
  ```kotlin
  // JANGAN LAKUKAN INI: Connection pool bocor, thread pool exhaust, OS port starvation
  suspend fun getData(): Data = HttpClient(CIO).get("...").body()
  ```
- **Mengabaikan Engine-Specific Certificate Handling**: Jangan berasumsi konfigurasi SSL otomatis bekerja sama di seluruh platform KMP. Native engine seperti Darwin bergantung pada iOS Keychain, sedangkan CIO pada JVM membutuhkan Java TrustStore (`KeyStore`).
- **Memblokir Coroutine Context**: Jangan menjalankan pemrosesan CPU-heavy langsung di dalam transform pipeline response tanpa memindahkannya ke `Dispatchers.Default`.

#### Edge Cases
- **Handling Payload Besar (OOM Mitigation)**: Memanggil `response.body<ByteArray>()` atau `response.body<String>()` pada berkas berukuran gigabyte akan memicu `OutOfMemoryError`. Gunakan pola streaming:
  ```kotlin
  client.prepareGet("https://large.download/file.iso").execute { httpResponse ->
      val channel: ByteReadChannel = httpResponse.body()
      while (!channel.isClosedForRead) {
          val packet = channel.readRemaining(DEFAULT_BUFFER_SIZE.toLong())
          // Tulis ke persistent storage / file secara streaming
      }
  }
  ```

### 5. Tantangan Eksplorasi Mandiri

1. **Custom Pipeline Interceptor**:
   Buat Ktor Client plugin kustom (`createClientPlugin`) yang menghitung *round-trip latency* (dalam milidetik) dari setiap HTTP request dan menginjeksi header metrik tracing `X-Response-Time-Ms` ke *context response* sebelum dikonsumsi oleh service layer.

2. **Cross-Platform Resilience Pattern**:
   Gunakan plugin `HttpRequestRetry` pada Ktor Client. Rancang skenario pengujian di mana client melakukan *exponential backoff* dengan jitter ketika server mengembalikan status code `503 Service Unavailable` atau terjadi `SocketTimeoutException`, namun langsung *fail-fast* (tanpa retry) jika menerima status `400 Bad Request` atau `422 Unprocessable Entity`.
