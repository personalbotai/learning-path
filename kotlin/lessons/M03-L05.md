### 1. Konsep & Arsitektur Mendalam

Operasi `Set` dalam Kotlin Standard Library memodelkan teori himpunan matematika (*set theory*) yang menjamin keunikan elemen tanpa duplikasi. Kotlin membagi hierarki koleksi menjadi dua antarmuka mendasar: `Set<out E>` (*read-only*, kovarian) dan `MutableSet<E>` (*read-write*, invarian). Di balik layar runtime JVM, kedua antarmuka ini dipetakan langsung ke tipe bawaan Java (`java.util.Set`), menghasilkan abstraksi dengan *zero-cost overhead* tanpa *wrapper penalty*.

```
   Set<out E> (Kotlin read-only)       MutableSet<E> (Kotlin read-write)
           \                                /
            v                              v
           Mapped at compile time to: java.util.Set<E>
                           |
        +------------------+------------------+
        |                  |                  |
        v                  v                  v
  LinkedHashSet         HashSet            TreeSet
  (Insertion Order)   (Hash Table)     (Red-Black Tree)
```

Keunikan dan integritas elemen dalam sebuah `Set` bergantung sepenuhnya pada mekanisme identifikasi kesetaraan:
1. **Hash-based Collections (`HashSet`, `LinkedHashSet`)**: Bergantung pada kontrak `equals()` dan `hashCode()`. Objek dianggap duplikat jika dan hanya jika `a.hashCode() == b.hashCode()` dan `a.equals(b) == true`.
2. **Tree-based Collections (`TreeSet`)**: Tidak menggunakan `equals()` untuk menentukan keunikan elemen, melainkan bergantung pada **total ordering** yang didefinisikan oleh `Comparable<T>` atau `Comparator<T>`. Dua elemen dianggap sama jika `comparator.compare(a, b) == 0`.

#### Comparable vs Comparator
* **`Comparable<T>`**: Merepresentasikan *natural ordering* dari sebuah kelas domain. Didefinisikan secara internal di dalam kelas tersebut dengan mengimplementasikan fungsi `compareTo(other: T): Int`.
* **`Comparator<T>`**: Merepresentasikan *ad-hoc* atau strategi pengurutan eksternal. Digunakan ketika kelas domain tidak memiliki akses modifikasi, membutuhkan multipel kriteria pengurutan konteks tertentu, atau ketika logika pengurutan dinamis dibutuhkan pada saat *runtime*.

Perbedaan arsitektural ini memunculkan **Inconsistency Bug**: jika implementasi `compareTo()` menghasilkan nilai `0` untuk dua objek yang memiliki `equals() == false`, `TreeSet` akan menganggap salah satu objek sebagai duplikat dan menolaknya, sedangkan `HashSet` akan menyimpan keduanya.

### 2. Implementasi & Contoh Kasus Nyata

Skenario nyata di bawah mengimplementasikan sistem Role-Based Access Control (RBAC) dan Audit Engine yang mengombinasikan kalkulasi himpunan izin (*permissions set operations*) serta audit log berbasis `TreeSet` dengan *chained comparators*.

```kotlin
import java.time.Instant

// Domain model yang mengimplementasikan Comparable untuk Natural Ordering
data class Permission(
    val code: String,
    val module: String
) : Comparable<Permission> {
    override fun compareTo(other: Permission): Int {
        // Natural order: modul terlebih dahulu, kemudian kode permission
        return compareValuesBy(this, other, { it.module }, { it.code })
    }
}

data class UserSession(
    val userId: String,
    val basePermissions: Set<Permission>,
    val explicitDeniedPermissions: Set<Permission>
)

data class AuditLog(
    val eventId: String,
    val timestamp: Instant,
    val priority: Int,
    val message: String
)

fun main() {
    // 1. Operasi Himpunan (Set Operations)
    val readAudit = Permission("AUDIT_READ", "SECURITY")
    val writeAudit = Permission("AUDIT_WRITE", "SECURITY")
    val readUser = Permission("USER_READ", "IAM")
    val deleteUser = Permission("USER_DELETE", "IAM")

    val roleAdminPermissions = setOf(readAudit, writeAudit, readUser, deleteUser)
    val roleAuditorPermissions = setOf(readAudit, readUser)
    val revokedPermissions = setOf(deleteUser)

    // Intersect (Irisan A ∩ B): Hak akses yang dimiliki oleh kedua peran
    val sharedPermissions = roleAdminPermissions intersect roleAuditorPermissions
    println("Shared Permissions: ${sharedPermissions.map { it.code }}")

    // Subtract / Minus (Selisih A - B): Hak admin dikurangi hak yang dicabut
    val effectiveAdminPermissions = roleAdminPermissions - revokedPermissions
    println("Effective Admin: ${effectiveAdminPermissions.map { it.code }}")

    // Union (Gabungan A ∪ B): Gabungan unik dari seluruh hak akses
    val systemPool = roleAdminPermissions union roleAuditorPermissions
    println("Total System Pool: ${systemPool.size} items")

    // 2. Custom Comparator & Chaining pada Collections Terurut (TreeSet)
    // Kriteria: Priority tertinggi dulu (DESC), jika sama urutkan Timestamp tertua dulu (ASC)
    val auditComparator = compareByDescending<AuditLog> { it.priority }
        .thenBy { it.timestamp }
        .thenBy { it.eventId } // Tie-breaker penting agar set tidak menolak log dengan waktu & prioritas sama

    val now = Instant.now()
    val auditQueue = java.util.TreeSet(auditComparator).apply {
        add(AuditLog("EVT-001", now.minusSeconds(30), 2, "User Login Success"))
        add(AuditLog("EVT-002", now.minusSeconds(10), 5, "Database Outage"))
        add(AuditLog("EVT-003", now.minusSeconds(20), 5, "Network Interface Down"))
        add(AuditLog("EVT-004", now, 1, "Cache Eviction Triggered"))
    }

    println("\n--- Prioritized Audit Logs ---")
    auditQueue.forEach { log ->
        println("[P${log.priority}] ${log.timestamp} -> ${log.message} (${log.eventId})")
    }
}
```

#### Penjelasan Komponen Kunci:
1. `compareValuesBy`: Helper idiomatik Kotlin untuk membandingkan multi-properti secara berurutan (*short-circuiting* saat nilai pembanding != 0).
2. `intersect`, `union`, `subtract`: Ekstensi Kotlin yang memanfaatkan alokasi efisien untuk menghasilkan `Set` baru yang *immutable/read-only*.
3. **Tie-Breaker (`thenBy { it.eventId }`)**: Pada `TreeSet`, jika dua objek berbeda menghasilkan evaluasi `compare() == 0`, objek kedua akan dibuang sebagai duplikat. `eventId` bertindak sebagai *tie-breaker* untuk menjaga integritas data log.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime:
* **Kotlin Set Infix Extension Functions**:
  Fungsi seperti `setA intersect setB` diimplementasikan di level stdlib dengan logika dinamis:
  ```kotlin
  // Konsep penyederhanaan implementasi internal Kotlin Stdlib
  public infix fun <T> Iterable<T>.intersect(other: Iterable<T>): Set<T> {
      val set = this.toMutableSet()
      set.retainAll(other)
      return set
  }
  ```
  Pada pemanggilan `retainAll`, JVM mengeksekusi operasi $O(N)$ jika `other` berupa `Set` (karena *lookup* $O(1)$). Namun jika salah satu adalah `List`, kompleksitas memburuk menjadi $O(N \times M)$ karena pencarian linear.

* **HashSet vs TreeSet Internals**:
  * `HashSet<T>` membungkus `HashMap<T, DummyObject>`. Saat `hashCode()` mengalami tabrakan (*hash collision*), Java 8+ mengubah bucket dari *singly-linked list* menjadi *Red-Black Tree* jika ukuran bucket melebihi ambang batas 8 (`TREEIFY_THRESHOLD`).
  * `TreeSet<T>` membungkus `TreeMap<T, DummyObject>`. Penambahan elemen memicu penyeimbangan ulang pohon (*tree rebalancing via rotations*) dengan kompleksitas waktu strictly $O(\log N)$.

#### Alokasi Memori / Resource:
* **Overhead Struktur Data**:
  * `HashSet`: Membutuhkan array bucket (`Node<K, V>[]`) ditambah instance `Node` per elemen. Konsumsi memori sekitar 32-48 byte per entri pada 64-bit JVM dengan Compressed OOPs.
  * `TreeSet`: Mengalokasikan objek `Entry<K, V>` untuk setiap elemen yang memuat 4 referensi pointer (`left`, `right`, `parent`, `color`) dan satu nilai Boolean, menghasilkan jejak memori yang lebih besar secara seragam dan hilangnya *cache locality* CPU akibat alokasi *node-pointer* di heap.

#### Trade-offs:
| Tipe | Pencarian | Penyisipan | Penjamin Urutan | Syarat Kontrak |
| :--- | :--- | :--- | :--- | :--- |
| **HashSet** | Amortized $O(1)$ | Amortized $O(1)$ | Tidak Ada | `equals()` & `hashCode()` |
| **LinkedHashSet** | Amortized $O(1)$ | Amortized $O(1)$ | Sesuai Urutan Sisip | `equals()` & `hashCode()` |
| **TreeSet** | $O(\log N)$ | $O(\log N)$ | Terurut (Sorted) | `Comparable` / `Comparator` |

### 4. Best Practices & Common Pitfalls

#### Do's:
* **Jaga Konsistensi `compareTo` dan `equals`**: Pastikan aturan `(a.compareTo(b) == 0) == (a.equals(b))` terpenuhi. Ini mencegah perilaku inkonsisten saat struktur data beralih antara `HashSet` dan `TreeSet`.
* **Gunakan Tie-Breaker yang Unik**: Pada `Comparator` kustom untuk `TreeSet`, selalu sertakan properti pengidentifikasi unik (misal `id`, `UUID`) sebagai rantai evaluasi terakhir.
* **Gunakan `data class` untuk Set Element**: Kotlin otomatis meng-*generate* `equals()` dan `hashCode()` yang simetris dan transparan berdasarkan semua *primary constructor properties*.

#### Don'ts:
* **Jangan Gunakan Properti Mutable di Hashing/Sorting**:
  ```kotlin
  // SANGAT BERBAHAYA
  data class BrokenUser(var id: Long, var name: String)
  val user = BrokenUser(1L, "Alice")
  val set = hashSetOf(user)
  user.name = "Bob" // HashCode berubah saat objek sudah berada di dalam Set!
  println(set.contains(user)) // Mengembalikan FALSE: Memory leak & Ghost element
  ```
* **Hindari Operasi Set Berantai pada Koleksi Besar**: Hindari `setA union setB intersect setC` secara beruntun tanpa buffer penampung, karena setiap operasi mengalokasikan instance koleksi intermediate baru.

#### Edge Cases:
* **Prinsip Subtraksi Tipe Nullable**: Saat melakukan operasi `setA - setB`, jika `setB` memiliki elemen `null` dan `setA` mengizinkan `null`, elemen `null` pada `setA` akan dihapus.
* **Primitive Boxed Types Overhead**: Menyimpan `Set<Int>` menyebabkan setiap angka primitif di-*boxing* menjadi `java.lang.Integer`. Untuk beban performa kritis pada JVM, pertimbangkan library khusus tipe primitif (seperti Koloboke atau FastUtil).

### 5. Tantangan Eksplorasi Mandiri

1. **Bug Forensik TreeSet**: 
   Buat sebuah `data class Product(val id: String, val price: Double)`. Definisikan `Comparator` yang hanya membandingkan `price`. Masukkan 3 produk dengan `id` berbeda tetapi memiliki `price` identik ke dalam `TreeSet`. Analisis berapa banyak elemen yang tersisa di dalam `TreeSet`, jelaskan mengapa itu terjadi, dan perbaiki kodenya tanpa mengubah `data class`.
2. **Kalkulator Symmetric Difference**:
   Kotlin tidak menyediakan operator `symmetricDifference` secara *built-in* (himpunan elemen yang ada di A atau B, tetapi tidak ada di keduanya: $(A \setminus B) \cup (B \setminus A)$). Tulis sebuah *generic extension function* `infix fun <T> Set<T>.symmetricDifference(other: Set<T>): Set<T>` yang mengimplementasikan ini dengan alokasi memori seringkas mungkin.
