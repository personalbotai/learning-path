## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Kotlin mendesain ulang paradigma kontrol alur (*control flow*) dari bahasa-bahasa berbasis C/Java terdahulu. Pada kebanyakan bahasa imperatif, struktur percabangan diperlakukan murni sebagai **statement** (instruksi yang mengeksekusi aksi tanpa mengembalikan nilai). Kotlin mengubah paradigma ini dengan memperlakukan percabangan secara fleksibel: baik sebagai *statement* maupun sebagai **expression** (menghasilkan nilai kembalian yang dapat dimasukkan ke dalam variabel atau di-pass sebagai argumen fungsi).

#### A. `if` as an Expression
Kotlin meniadakan operator ternary (`condition ? then : else`) yang ada pada Java atau C. Sebagai gantinya, konstruksi `if` dapat langsung bertindak sebagai ekspresi. 
- Ketika digunakan sebagai ekspresi, cabang `else` menjadi **wajib** (*mandatory*) demi menjamin keselamatan sistem tipe (*type safety*).
- Compiler akan mengevaluasi cabang yang terpenuhi dan tipe data dari variabel penampung ditentukan dari *Least Upper Bound* (LUB) atau supertype terdekat dari nilai kembalian setiap blok.

#### B. `when`: Pattern Matching Tingkat Lanjut
Struktur `when` merupakan evolusi radikal dari `switch-case` tradisional:
- `when` dapat beroperasi secara *argument-based* (mencocokkan nilai/kondisi terhadap satu target) atau *argument-less* (berfungsi sebagai pengganti rantai panjang `if-else if-else`).
- **Exhaustiveness Guarantee**: Jika `when` digunakan sebagai ekspresi terhadap tipe tertutup seperti `enum` atau `sealed class/interface`, compiler memvalidasi bahwa seluruh kemungkinan cabang telah ditangani. Jika ada cabang yang terlewat, kompilasi akan gagal (*compile-time error*), meminimalkan *runtime bug*.

#### C. Smart Casts & Flow-Sensitive Typing
Pada bahasa seperti Java, developer harus mengecek tipe data (`instanceof`) lalu melakukan casting manual secara eksplisit (`(TargetType) obj`). Kotlin mengimplementasikan **Flow-Sensitive Typing** melalui fitur **Smart Casts**:
- Kotlin compiler (`kotlinc`) melakukan analisis alur kontrol (*control flow analysis*). Jika compiler dapat membuktikan secara matematis bahwa suatu variabel tidak mungkin bertipe lain atau tidak bernilai `null` pada titik eksekusi tertentu, compiler akan menyisipkan instruksi casting secara otomatis.
- **Batasan Keamanan**: Smart cast hanya bekerja jika compiler dapat menjamin nilai variabel tersebut tidak berubah (*immutable*) antara waktu pengecekan dan waktu pemakaian. Hal ini berdampak langsung pada variabel `val` lokal versus `var` atau properti kelas.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah contoh sistem evaluasi transaksi finansial modern yang menggabungkan `if` as expression, `when` komprehensif, dan `Smart Casts`.

```kotlin
package com.payment.engine

import java.math.BigDecimal

// Domain Model menggunakan Sealed Interface
sealed interface TransactionStatus {
    data class Success(val transactionId: String, val amount: BigDecimal) : TransactionStatus
    data class Pending(val retryCount: Int) : TransactionStatus
    data class Failed(val errorCode: String, val message: String, val isTransient: Boolean) : TransactionStatus
    data object Blocked : TransactionStatus
}

data class TransactionContext(
    val id: String,
    val status: TransactionStatus,
    val userRiskScore: Int // Skala 0 - 100
)

class TransactionProcessor {

    fun evaluateTransaction(context: TransactionContext): String {
        // 1. 'if' sebagai expression untuk kalkulasi diskon risiko
        val riskMultiplier: Double = if (context.userRiskScore > 75) {
            1.5
        } else if (context.userRiskScore in 40..75) {
            1.0
        } else {
            0.8
        }

        // 2. 'when' sebagai expression dengan exhaustiveness check & Smart Casts
        val auditLog: String = when (val currentStatus = context.status) {
            is TransactionStatus.Success -> {
                // SMART CAST otomatis: currentStatus langsung dikenali sebagai TransactionStatus.Success
                val adjustedAmount = currentStatus.amount.toDouble() * riskMultiplier
                "TX SUCCESS [ID: ${currentStatus.transactionId}] - Final Adjusted Amount: $$adjustedAmount"
            }
            is TransactionStatus.Pending -> {
                // SMART CAST otomatis: currentStatus dikenali sebagai TransactionStatus.Pending
                if (currentStatus.retryCount >= 3) {
                    "TX PENDING - Escalating to manual review due to ${currentStatus.retryCount} retries."
                } else {
                    "TX PENDING - Retry queued. Current attempts: ${currentStatus.retryCount}"
                }
            }
            is TransactionStatus.Failed -> {
                // SMART CAST otomatis: currentStatus dikenali sebagai TransactionStatus.Failed
                // 'when' tanpa argumen untuk evaluasi kondisi kustom
                when {
                    currentStatus.isTransient -> "TX FAILED - Temporary error (${currentStatus.errorCode}). Retrying..."
                    else -> "TX ABORTED - Critical failure: ${currentStatus.message} (Code: ${currentStatus.errorCode})"
                }
            }
            TransactionStatus.Blocked -> {
                // Objek singleton, tidak butuh smart cast field
                "TX BLOCKED - Compliance violation detected."
            }
            // Tidak membutuhkan 'else' branch karena seluruh hierarki Sealed Interface telah tercakup!
        }

        return auditLog
    }

    // Contoh Smart Cast dengan Nullability
    fun processPayload(payload: Any?) {
        when (payload) {
            null -> println("Payload is null, skipping.")
            is String -> println("Processing text data: ${payload.uppercase()}") // Smart cast ke String
            is List<*> -> println("Processing list data of size: ${payload.size}") // Smart cast ke List
            else -> println("Unknown payload type: ${payload::class.simpleName}")
        }
    }
}

fun main() {
    val processor = TransactionProcessor()

    val successfulTx = TransactionContext(
        id = "TX-9901",
        status = TransactionStatus.Success("TX-9901", BigDecimal("250.00")),
        userRiskScore = 80
    )

    println(processor.evaluateTransaction(successfulTx))

    val failedTx = TransactionContext(
        id = "TX-9902",
        status = TransactionStatus.Failed("ERR_GATEWAY_TIMEOUT", "Payment provider unreachable", true),
        userRiskScore = 20
    )

    println(processor.evaluateTransaction(failedTx))
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### A. Eksekusi & Runtime: Bytecode Decompilation
1. **`if` as Expression**:
   JVM tidak memiliki konsep ekspresi `if`. Pada tingkat *bytecode*, Kotlin compiler memetakan ekspresi `if` menggunakan instruksi percabangan standar Java (`IFNE`, `IF_ICMPLE`, dsb.) bersama dengan manipulasi operand stack:
   - Hasil akhir dari branch yang terpilih di-`push` ke atas *operand stack*.
   - Nilai tersebut kemudian di-`store` ke sebuah register variabel lokal (mirip dengan inisialisasi ternary di Java bytecode).

2. **Optimasi `when` ke Bytecode**:
   Tergantung pada pola percabangan, compiler menghasilkan bytecode yang berbeda untuk efisiensi CPU:
   - **Integer/Constants Branch**: Dikompilasi menjadi instruksi JVM `TABLESWITCH` ($O(1)$ jump table berbasis indeks) atau `LOOKUPSWITCH` ($O(\log N)$ binary search).
   - **String Matching**: Menggunakan `hashCode()` dari string untuk `LOOKUPSWITCH`, lalu mengeksekusi `String.equals()` untuk menangani potensi *hash collision*.
   - **Type Checking (`is Type`)**: Diterjemahkan menjadi instruksi `INSTANCEOF` berantai yang diikuti instruksi *conditional jump* (`IFEQ`).

3. **Smart Casts**:
   Secara bytecode, Kotlin menginjeksi instruksi `CHECKCAST` tepat sebelum nilai diakses sebagai subtipe, **hanya jika** mesin JVM membutuhkan verifikasi verifier. Namun, dalam banyak kasus di tingkat stack frame lokal, compiler langsung memperlakukan referensi tersebut sebagai subtipe yang valid tanpa penalti alokasi baru.

#### B. Alokasi Memori & Resource
- **Zero-Allocation**: Smart Cast tidak membuat objek wrapper baru di memori heap. Objek referensi yang sama di stack frame langsung dibaca dengan batasan tipe baru.
- **Sealed Type Elimination**: Exhaustive `when` tidak menghasilkan cabang *fallback* yang tidak perlu di runtime, mengurangi *dead code* dan menjaga *instruction cache* CPU tetap optimal.

#### C. Trade-offs
- Struktur `when` berbasis kondisi ekspresi (`when { ... }`) akan dikompilasi menjadi rantai `if-else` linier. Jika terdapat ratusan kondisi acak non-konstanta, performanya adalah $O(N)$, bukan $O(1)$. Gunakan map lookup jika cabang kondisi non-tipe berjumlah sangat masif.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Exhaustive `when` tanpa `else` pada Sealed Hierarchies / Enums**: Hindari menambahkan blok `else` jika sedang mencocokkan `sealed class` atau `enum`. Jika kelak ada varian baru ditambahkan ke sealed class, compiler akan memunculkan error, memaksa developer menangani varian baru tersebut secara eksplisit.
- **Terapkan Scope Variables pada `when`**: Deklarasikan variabel langsung di dalam argumen `when (val x = calculate())` untuk mempersempit masa hidup (*lifespan*) variabel dan mencegah polusi scope fungsi.

#### Don'ts
- **Jangan Menggunakan `when` untuk Kondisi Boolean Biner**: Jangan gunakan `when (boolValue)` untuk operasi benar/salah sederhana. Gunakan `if-else` ekspresi standar yang lebih idiomatik dan bersih dibaca.
- **Jangan Memanggil Logika Berat di dalam Branch**: Pecah logika yang memiliki lebih dari 3-5 baris dalam satu cabang menjadi fungsi privat tersendiri agar struktur `when` tetap menjadi deklarasi alur data, bukan implementasi komputasi.

#### Edge Cases & Pitfalls
- **Gagalnya Smart Cast pada `var`**:
  ```kotlin
  class DeviceManager {
      var status: String? = "CONNECTED"

      fun check() {
          if (status != null) {
              // ERROR: Smart cast to 'String' is impossible, because 'status' is a mutable property
              // that could be mutated by another thread concurrently.
              println(status.length) 
          }
      }
  }
  ```
  *Solusi*: Gunakan teknik local capture:
  ```kotlin
  val currentStatus = status
  if (currentStatus != null) {
      println(currentStatus.length) // Sukses! Local val immutable.
  }
  ```
- **Gagalnya Smart Cast pada Properti Terbuka (`open val`)**:
  `open val` pada sebuah kelas tidak bisa di-smart-cast karena properti tersebut dapat di-override oleh kelas turunan menggunakan custom getter yang mengembalikan nilai berbeda pada setiap pemanggilan.

### 5. Tantangan Eksplorasi Mandiri

1. **Analisis Dekompilasi Bytecode**:
   Buat sebuah file Kotlin kecil yang memuat satu `when` berbasis `String` dan satu `when` berbasis `is Type`. Kompilasi file tersebut menggunakan `kotlinc`, lalu jalankan `javap -c NamaFileKt.class` (atau gunakan menu *Show Kotlin Bytecode -> Decompile to Java* di IntelliJ IDEA). Analisis perbedaan instruksi bytecode antara pencocokan String (`hashCode` & `equals`) dan evaluasi polimorfik (`instanceof` & `checkcast`).

2. **Refactoring Legacy State Machine**:
   Ambil struktur percabangan berbasis `switch-case` gaya Java lama yang menggunakan representasi *integer error codes* dan ubah menjadi idiomatik Kotlin menggunakan `sealed interface`, `when` exhaustiveness, dan `Smart Casts`. Pastikan tidak ada satupun pemanggilan cast manual (`as` / `as?`) dan tidak ada cabang `else` pada evaluasi status akhir.
