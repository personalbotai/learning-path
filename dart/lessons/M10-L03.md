### 1. Konsep & Arsitektur Mendalam

Pengujian asynchronous pada Dart berakar pada arsitektur **Event Loop**, yang memisahkan eksekusi ke dalam dua antrean utama: **Microtask Queue** (prioritas tinggi, internal core operations) dan **Event Queue** (I/O, gesture, timer, dan stream events).

```
                      +-------------------+
                      |   Main Isolate    |
                      +-------------------+
                                |
                                v
                   +---> [ Microtask Queue ] (Diproses hingga kosong)
                   |            |
             Loop  |            v
                   +---- [  Event Queue  ] (Timer, I/O, Stream events)
```

Ketika menguji `Stream`, tantangan terbesar muncul saat stream tersebut terikat dengan dimensi waktu—misalnya operasi *debounce*, *throttle*, *heartbeat/ping*, atau *polling* berkala. Menggunakan `await Future.delayed()` dalam automated test adalah antipattern fatal:
1. **Flaky Tests:** Latensi CPU pada runner CI/CD yang padat dapat memicu *race condition* jika toleransi delay terlalu ketat.
2. **Slow Test Suite:** Akumulasi delay beberapa ratus milidetik pada ratusan test case dapat memperpanjang waktu build secara signifikan.

Untuk mengatasi ini, Dart menyediakan simulasi waktu deterministik melalui package `fake_async`. 

#### Arsitektur `fakeAsync` dan Zone Injection
`fakeAsync` tidak mempercepat jam pada level Operating System (OS clock). Sebaliknya, ia mengeksploitasi arsitektur **Zone** pada Dart (`dart:async`). `Zone` bertindak sebagai *asynchronous dynamic scope* yang membungkus pemanggilan kode.

Saat blok `fakeAsync((async) { ... })` dieksekusi:
1. Runtime memanggil `Zone.current.fork()`.
2. Handler inti untuk waktu dialihkan melalui `ZoneSpecification`:
   - `createTimer` dan `createPeriodicTimer` dibajak (intercepted). Alih-alih mendaftarkan handler ke OS timer loop melalui C++ runtime Dart, timer disimpan dalam struktur data internal (antrean berbasis prioritas/min-heap) milik `FakeAsync`.
   - `scheduleMicrotask` dipantau untuk memastikan eksekusi microtask tetap terkontrol.
3. Fungsi `async.elapse(Duration duration)` menggeser *virtual clock* secara sinkron. Jam virtual dimajukan, dan callback timer yang waktu jatuh temponya telah terlewati akan langsung dipindahkan ke antrean eksekusi dan diproses secara deterministik tanpa jeda waktu nyata di dunia fisik.

### 2. Implementasi & Contoh Kasus Nyata

Skenario: Membangun sistem `ConnectivityMonitor` yang menerima stream status koneksi mentah, menerapkan *debounce* 300ms untuk menyaring flapping (kondisi sinyal tidak stabil yang menyala-mati dengan cepat), lalu memancarkan status yang sudah stabil.

#### Implementasi Bisnis (`lib/connectivity_monitor.dart`)

```dart
import 'dart:async';

enum NetworkStatus { online, offline }

class ConnectivityMonitor {
  final Stream<NetworkStatus> _rawInput;
  final Duration debounceDuration;

  ConnectivityMonitor(
    this._rawInput, {
    this.debounceDuration = const Duration(milliseconds: 300),
  });

  /// Mengembalikan stream status jaringan yang telah distabilkan.
  Stream<NetworkStatus> get stabilizedStream {
    StreamController<NetworkStatus>? controller;
    StreamSubscription<NetworkStatus>? subscription;
    Timer? debounceTimer;

    controller = StreamController<NetworkStatus>(
      onListen: () {
        subscription = _rawInput.listen(
          (status) {
            debounceTimer?.cancel();
            debounceTimer = Timer(debounceDuration, () {
              if (!controller!.isClosed) {
                controller.add(status);
              }
            });
          },
          onError: (Object error, StackTrace stackTrace) {
            controller?.addError(error, stackTrace);
          },
          onDone: () {
            debounceTimer?.cancel();
            controller?.close();
          },
        );
      },
      onCancel: () async {
        debounceTimer?.cancel();
        await subscription?.cancel();
      },
    );

    return controller.stream;
  }
}
```

#### Pengujian Menggunakan `test` & `fake_async` (`test/connectivity_monitor_test.dart`)

```dart
import 'dart:async';
import 'package:fake_async/fake_async.dart';
import 'package:test/test.dart';

// Asumsikan class ConnectivityMonitor berada dalam scope yang sama
void main() {
  group('ConnectivityMonitor - Stream & FakeAsync Suite', () {
    late StreamController<NetworkStatus> rawInputController;
    late ConnectivityMonitor monitor;

    setUp(() {
      rawInputController = StreamController<NetworkStatus>();
      monitor = ConnectivityMonitor(
        rawInputController.stream,
        debounceDuration: const Duration(milliseconds: 300),
      );
    });

    tearDown(() async {
      await rawInputController.close();
    });

    test('Harus mendebounce fluktuasi sinyal yang cepat secara deterministik', () {
      fakeAsync((async) {
        final emittedEvents = <NetworkStatus>[];
        final subscription = monitor.stabilizedStream.listen(emittedEvents.add);

        // T = 0ms: Emisi fluktuasi
        rawInputController.add(NetworkStatus.offline);
        async.elapse(const Duration(milliseconds: 100)); // T = 100ms
        expect(emittedEvents, isEmpty, reason: 'Event tertahan debounce');

        // T = 100ms: Perubahan cepat sebelum 300ms tercapai
        rawInputController.add(NetworkStatus.online);
        async.elapse(const Duration(milliseconds: 150)); // T = 250ms
        expect(emittedEvents, isEmpty, reason: 'Timer debounce di-reset');

        // T = 250ms: Lompati sisa waktu 150ms melewati batas debounce (Total 250ms + 150ms = 400ms)
        async.elapse(const Duration(milliseconds: 150));

        // Verifikasi event
        expect(emittedEvents, equals([NetworkStatus.online]));
        expect(emittedEvents.length, 1);

        subscription.cancel();
      });
    });

    test('Validasi sinkronisasi completion menggunakan matchers async Stream', () {
      fakeAsync((async) {
        final stream = monitor.stabilizedStream;

        // Registrasi ekspektasi deklaratif sebelum trigger dilakukan
        expectLater(
          stream,
          emitsInOrder([
            NetworkStatus.online,
            emitsDone,
          ]),
        );

        rawInputController.add(NetworkStatus.online);
        
        // Majukan waktu virtual melebihi debounce agar event terdorong ke stream
        async.elapse(const Duration(milliseconds: 300));

        rawInputController.close();
        
        // Memproses microtask yang tersisa dari penutupan stream
        async.flushMicrotasks();
      });
    });
  });
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Manipulasi Priority Queue
Di dalam `FakeAsync`, waktu adalah integer skalar:
```dart
// Konseptual pseudocode runtime fake_async
class FakeAsync {
  Duration _elapsed = Duration.zero;
  final PriorityQueue<_FakeTimer> _timerQueue = PriorityQueue();

  void elapse(Duration duration) {
    final targetTime = _elapsed + duration;
    while (_timerQueue.isNotEmpty && _timerQueue.first.nextCall <= targetTime) {
      final timer = _timerQueue.removeFirst();
      _elapsed = timer.nextCall;
      timer.callback(); // Menjalankan callback synchronous di thread test runner
      runMicrotasks();  // Menguras microtask yang tercipta oleh callback
    }
    _elapsed = targetTime;
  }
}
```
Ketika `async.elapse(Duration(milliseconds: 300))` dipanggil, loop runtime tidak menggunakan sleep tingkat CPU (seperti `nanosleep` atau `usleep`). Sebaliknya, ia mengeksekusi operasi penelusuran queue berbasis CPU secara instan.

#### Alokasi Memori & Resource
- `FakeTimer` menyimpan referensi kuat (*strong reference*) ke *closure* callback yang dilekatkan padanya.
- Jika sebuah stream controller atau timer berkala (`Timer.periodic`) tidak dihentikan (`cancel()`) sebelum blok `fakeAsync` berakhir, instance closure tersebut beserta seluruh referensi variabel di dalam leksikal scope-nya akan menggantung di heap memory. Dart test framework akan melempar assertion error: `"FakeAsync has pending timers"` untuk mencegah *silent resource leakage*.

#### Trade-offs: Lingkup Zona vs Batasan Eksternal
- **Zone Containment:** `fakeAsync` hanya memegang kontrol penuh atas objek yang mengalokasikan timer melalui Dart Zone APIs.
- **I/O & FFI Boundary:** Apabila stream bergantung pada I/O thread native (misalnya: operasi `dart:io` membaca disk riil, native C plugins melalui `dart:ffi`), waktu pada subsystem eksternal tersebut tidak tunduk pada jam virtual `fakeAsync`. Pemanggilan asynchronous native akan menyebabkan *uncontrolled wait* yang dapat menggagalkan eksekusi `fakeAsync`.

### 4. Best Practices & Common Pitfalls

#### Do's
1. **Pasang `expectLater` Sebelum Mentransmisikan Event:**
   Selalu pasang matcher asinkron (`expectLater`, `emitsInOrder`) *sebelum* memanggil metode yang men-trigger stream. Jika tidak, stream broadcast akan membuang event sebelum listener pengujian terpasang.
2. **Kuras Microtasks Secara Eksplisit:**
   Gunakan `async.flushMicrotasks()` saat memvalidasi status transisi instan pasca stream ditutup (`close()`), karena pemanggilan `close()` pada `StreamController` mendaftarkan penyelesaiannya ke Microtask Queue.
3. **Pastikan Idempotensi Pembatalan Timer:**
   Selalu bersihkan listener dan timer dalam lifecycle callback `onCancel` milik `StreamController`.

#### Don'ts
1. **Mencampur Real Time dengan Fake Time:**
   Jangan pernah menulis `await Future.delayed()` nyata di dalam blok callback `fakeAsync`. Tindakan ini akan mengunci (*deadlock*) runner karena Event Loop OS tidak akan pernah menerima tick untuk memajukan clock tersebut saat runner berada di eksekusi sinkron `fakeAsync`.
2. **Mengabaikan "Pending Timers" Assertion:**
   Jangan abaikan error `FakeAsync has uncompleted timers`. Ini adalah peringatan valid bahwa implementasi kode produksi Anda gagal membersihkan timer saat stream di-cancel/dispose.

#### Edge Cases
- **Timer Berkelanjutan (Periodic Timers) Tak Berujung:**
  Saat menguji `Timer.periodic`, pemanggilan `async.flushTimers()` akan memicu **infinite loop** karena timer periodik akan terus menjadwalkan ulang dirinya sendiri ke masa depan tanpa henti. Selalu gunakan `async.elapse(finiteDuration)` untuk timer periodik, bukan `flushTimers()`.
- **Eksekusi Microtask Mengunci Waktu Virtual:**
  Jika ada infinite recursion pada Microtask Queue (misalnya, fungsi microtask yang menjadwalkan microtask lain tanpa basis kondisi berhenti), `async.elapse` akan mengalami infinite loop sebelum sempat mengeksekusi satu pun event timer.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Retry dengan Exponential Backoff Stream:**
   Bangun sebuah fungsi `Stream<T> retryWithBackoff<T>(Stream<T> Function() streamFactory, {int maxRetries})` di mana durasi tunggu berlipat ganda secara eksponensial (1 detik, 2 detik, 4 detik) tiap kali stream melempar exception. Buat test suite menggunakan `fakeAsync` yang menguji:
   - Verifikasi bahwa percobaan retry ke-2 benar-benar menunggu 2 detik setelah kegagalan retry ke-1.
   - Verifikasi bahwa stream memancarkan error terminal setelah batas `maxRetries` tercapai, seluruhnya diverifikasi dalam waktu virtual kurang dari 1 detik waktu nyata.

2. **Deteksi Deadlock pada Windowed Stream:**
   Rancang transformer stream kustom yang mengelompokkan event ke dalam batch per 5 detik, ATAU maksimal 10 event (mana saja yang tercapai lebih dulu). Gunakan `fakeAsync` untuk membuktikan skenario di mana 9 event masuk, sistem menunggu 5 detik, dan batch berhasil dipancarkan tepat pada tick virtual `4999ms` vs `5000ms`.
