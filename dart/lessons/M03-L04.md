## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam rekayasa perangkat lunak, kita sering dihadapkan pada situasi di mana kita perlu menambahkan fungsionalitas pada kelas yang sudah ada, namun kita tidak memiliki akses ke *source code* kelas tersebut (misalnya kelas bawaan bahasa seperti `String`, `DateTime`, atau kelas dari *package* pihak ketiga). Pendekatan tradisional biasanya menggunakan *Utility Classes* (contoh: `StringUtils.capitalize(text)`) atau *Wrapper Classes*. 

Dart memperkenalkan **Extension Methods** (sejak versi 2.7) sebagai solusi elegan untuk masalah ini. Extension methods memungkinkan Anda "menambahkan" metode, *getter*, *setter*, dan *operator* ke tipe yang sudah ada tanpa melakukan *subclassing* (pewarisan) atau mengubah kode aslinya.

Secara arsitektur, extension methods di Dart adalah **syntactic sugar** untuk pemanggilan *static method*. Mereka di-resolve secara **statis pada saat kompilasi (compile-time)**, bukan secara dinamis pada saat *runtime*. Ini berarti extension methods tidak mengubah struktur internal atau *blueprint* dari kelas asli sama sekali.

**Mengapa fitur ini ada?**
1. **Fluent Interfaces:** Memungkinkan *chaining* metode yang lebih natural (contoh: `text.capitalize().trim()` lebih mudah dibaca daripada `trim(capitalize(text))`).
2. **Domain-Specific Language (DSL):** Sangat berguna dalam ekosistem Flutter untuk membangun UI yang deklaratif.
3. **Null Safety Ergonomics:** Memungkinkan pembuatan metode yang aman terhadap nilai *null* dengan melakukan ekstensi pada *nullable types* (contoh: `String?`).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern dan idiomatik dari berbagai skenario penggunaan Extension Methods di Dart.

```dart
// 1. Ekstensi Dasar pada Tipe Bawaan (String)
// Memberikan nama pada ekstensi (StringCasingExtension) memungkinkan ekstensi ini 
// di-import dan digunakan di file lain.
extension StringCasingExtension on String {
  // Menggunakan getter untuk komputasi tanpa argumen
  String get capitalized {
    if (this.isEmpty) return this;
    return '${this[0].toUpperCase()}${this.substring(1).toLowerCase()}';
  }
}

// 2. Ekstensi pada Nullable Types (Sangat berguna untuk Null Safety)
extension NullableStringExtension on String? {
  // Mengembalikan true jika string null atau kosong
  bool get isNullOrEmpty => this == null || this!.isEmpty;
}

// 3. Ekstensi Generic (Berlaku untuk semua tipe dalam Iterable)
extension IterableExtensions<T> on Iterable<T> {
  // Menambahkan fungsionalitas pencarian yang aman (mengembalikan null jika tidak ada)
  T? firstWhereOrNull(bool Function(T) test) {
    for (var element in this) {
      if (test(element)) return element;
    }
    return null;
  }
}

// 4. Ekstensi dengan Operator Overloading
extension IntDuration on int {
  // Memungkinkan sintaks deklaratif seperti: 5.days
  Duration get days => Duration(days: this);
  Duration get hours => Duration(hours: this);
}

void main() {
  // Penggunaan Ekstensi Dasar
  String name = "dArT";
  print(name.capitalized); // Output: Dart

  // Penggunaan Nullable Extension
  String? nullString;
  print(nullString.isNullOrEmpty); // Output: true

  // Penggunaan Generic Extension
  List<int> numbers = [1, 2, 3, 4, 5];
  int? found = numbers.firstWhereOrNull((n) => n > 10);
  print(found); // Output: null

  // Penggunaan Operator/Property Extension
  DateTime futureDate = DateTime.now().add(5.days);
  print('5 hari dari sekarang: $futureDate');
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (Static Dispatch):** 
  Karena di-resolve saat *compile-time*, *compiler* Dart menerjemahkan pemanggilan `name.capitalized` menjadi sesuatu yang secara konseptual mirip dengan `StringCasingExtension.capitalized(name)`. Tidak ada *Dynamic Dispatch* atau pencarian *vtable* (Virtual Method Table) saat *runtime*. Akibatnya, jika Anda menggunakan tipe `dynamic`, Anda **tidak bisa** memanggil extension methods, karena *compiler* tidak tahu tipe pastinya saat kompilasi.
  
- **Alokasi Memori / Resource:** 
  Extension methods memiliki **zero memory overhead** pada instansiasi objek. Karena mereka tidak benar-benar ditambahkan ke dalam kelas, Anda **tidak dapat mendeklarasikan *instance variables* (state)** di dalam sebuah ekstensi. Ukuran objek di memori (heap) tetap sama persis seperti sebelum ekstensi dibuat.

- **Trade-offs (Shadowing & Polymorphism):** 
  Extension methods tidak mendukung polimorfisme. Jika kelas asli (atau *subclass*-nya) memiliki metode dengan nama yang sama dengan metode di ekstensi, **metode instans dari kelas asli akan selalu menang (Shadowing)**. Ekstensi hanya akan dipanggil jika kelas asli tidak memiliki metode tersebut.

### 4. Best Practices & Common Pitfalls

- **Do's:**
  - Gunakan *Getter* daripada metode `()` jika ekstensi tersebut hanya melakukan transformasi data tanpa memerlukan parameter tambahan (contoh: `list.lastIndex` bukan `list.getLastIndex()`).
  - Beri nama ekstensi secara eksplisit (contoh: `extension DateFormatting on DateTime`) agar mudah di-resolve jika terjadi konflik antar-package.
  - Manfaatkan ekstensi pada tipe *nullable* (`T?`) untuk menyederhanakan pengecekan *null* di seluruh *codebase*.

- **Don'ts:**
  - **Jangan** menggunakan ekstensi untuk menyembunyikan *business logic* yang kompleks. Ekstensi idealnya murni, fungsional, dan bertindak sebagai *utility*.
  - **Jangan** membuat ekstensi tanpa nama (`extension on String`) kecuali ekstensi tersebut benar-benar hanya digunakan secara privat di dalam satu file tersebut.

- **Edge Cases (Resolusi Konflik):**
  Jika dua *package* berbeda menyediakan ekstensi dengan nama metode yang sama untuk tipe yang sama, *compiler* akan bingung. Anda harus menyelesaikannya dengan:
  1. Menyembunyikan salah satu ekstensi saat import: `import 'package:a/a.dart' hide ConflictingExtension;`
  2. Pemanggilan eksplisit (Explicit Extension Application): `ConflictingExtension(myObject).methodName();`

### 5. Tantangan Eksplorasi Mandiri

1. Buatlah sebuah *generic extension* pada `List<T>` yang menambahkan metode `swap(int indexA, int indexB)` untuk menukar posisi dua elemen di dalam list secara *in-place*.
2. Rancang sebuah ekstensi pada `DateTime` yang memiliki *getter* `isWeekend` (mengembalikan `true` jika hari Sabtu atau Minggu) dan metode `next(int weekday)` untuk mencari tanggal terdekat dari hari tertentu (misal: mencari hari Senin minggu depan).
3. Eksplorasi perilaku *compiler*: Buat sebuah kelas `User` dengan metode `printName()`. Buat juga ekstensi pada `User` dengan metode `printName()`. Panggil metode tersebut dan amati mana yang dieksekusi, lalu coba panggil metode ekstensi secara eksplisit menggunakan sintaks *Explicit Extension Application*.
