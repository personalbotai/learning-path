## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam Dart, *collections* (`List`, `Set`, dan `Map`) adalah objek inti pada runtime `dart:core` yang digunakan untuk mengelola sekumpulan data. Berbeda dengan bahasa yang membedakan array primitif dan objek penampung (*wrapper collections*), seluruh *collection* di Dart merupakan turunan langsung atau tidak langsung dari kelas objek murni, dan mayoritas mengimplementasikan kontrak `Iterable<E>`.

```
          +------------------+
          |   Iterable<E>    |
          +--------+---------+
                   |
         +---------+---------+
         |                   |
+--------v-------+  +--------v-------+  +-------------------+
|    List<E>     |  |     Set<E>     |  |   Map<K, V> (*)   |
| (Index-based)  |  | (Unique Hash)  |  |  (Key-Value Pair) |
+----------------+  +----------------+  +-------------------+
(*) Map bukan turunan Iterable, tetapi mengekspos iterable keys/values/entries.
```

#### Reified Generics
Dart menggunakan sistem **Reified Generics** (tipe generik yang tetap dipertahankan saat runtime). Berbeda dengan *Type Erasure* pada Java di mana tipe generik dihapus setelah fase kompilasi bytecode, runtime Dart VM maupun JavaScript output (via `dart2js` / `dart2wasm`) menyimpan metadata tipe generik tersebut. Konsekuensinya:
- Pengecekan tipe seperti `list is List<String>` bernilai valid dan dievaluasi secara dinamis saat runtime.
- Pelanggaran tipe data pada struktur generik akan melempar `TypeError` di runtime saat operasi mutasi dilakukan, bukan sekadar peringatan statis saat kompilasi.

#### Literal Syntax & Type Inference
Dart menyediakan sintaksis literal deklaratif untuk mempermudah instansiasi:
- `[...]` untuk `List`
- `{...}` dengan elemen tunggal untuk `Set`
- `{...}` dengan pasangan `key: value` untuk `Map`

Compiler Dart (CFE / *Common Front End*) melakukan inferensi tipe lokal (*type argument inference*) berdasarkan konteks deklarasi dan tipe elemen literal. Jika ambiguitas muncul—seperti literal kosong `{}` tanpa konteks—kompiler secara default akan menyimpulkan tipe tersebut sebagai `Map<dynamic, dynamic>`, bukan `Set<dynamic>`. Oleh karena itu, *explicit type arguments* (`<E>` atau `<K, V>`) krusial untuk menjamin *sound type safety*.

### 2. Implementasi & Contoh Kasus Nyata

Berikut implementasi idiomatik modern yang mendemonstrasikan generic typing, ambiguitas literal, dynamic type promotion, serta fitur *collection-if* dan *collection-for*.

```dart
// Model domain untuk simulasi payload backend
class UserSession {
  final String id;
  final Set<String> roles;

  const UserSession(this.id, this.roles);
  
  @override
  String toString() => 'UserSession(id: $id, roles: $roles)';
}

void main() {
  // 1. Inisialisasi Eksplisit vs Inferensi Type Argument
  // Disarankan: Mengunci tipe secara statis menggunakan generic parameter pada literal
  final primaryColors = <String>['red', 'green', 'blue']; // List<String>
  final uniqueTags = <String>{'dart', 'backend', 'dart'};   // Set<String>, duplikat otomatis dieliminasi
  
  // 2. Ambiguitas Literal Kosong: Map vs Set
  final ambiguousLiteral = {}; // Terinferensi sebagai Map<dynamic, dynamic>
  final emptySet = <String>{}; // Eksplisit Set<String>
  final emptyMap = <String, int>{}; // Eksplisit Map<String, int>

  assert(ambiguousLiteral is Map, 'Literal {} tanpa elemen selalu berupa Map');

  // 3. Collection-if & Collection-for (Control Flow Elements)
  const bool isAdmin = true;
  final List<String> additionalRoles = ['auditor', 'maintainer'];

  final resolvedRoles = <String>{
    'user',
    if (isAdmin) 'admin',
    for (final role in additionalRoles) role.toLowerCase(),
  };

  // 4. Transformasi Struktur Relasional (Lookup Map)
  final sessions = <UserSession>[
    const UserSession('usr_01', {'user'}),
    UserSession('usr_02', resolvedRoles),
  ];

  // Mengubah List menjadi Map terindeks (O(1) access lookup table)
  final sessionLookup = <String, UserSession>{
    for (final session in sessions) session.id: session,
  };

  // Akses O(1) aman
  final targetSession = sessionLookup['usr_02'];
  print('Target Roles: ${targetSession?.roles}');

  // 5. Pembuktian Reified Generic & Type Safety Runtime
  List<Object> polymorphicList = <String>['engine', 'compiler'];
  
  try {
    // Statis valid (karena Object menerima int), tapi Runtime melemparkan TypeError
    // karena instansi aslinya adalah List<String>
    (polymorphicList as dynamic).add(404);
  } on TypeError catch (e) {
    print('Type safety terjamin oleh VM: ${e.runtimeType}');
  }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **List Implementation**: Saat Anda mendeklarasikan list literal `[1, 2, 3]`, Dart VM mengalokasikan instansi internal `_GrowableList<E>` (pada mode *growable*) atau `_List<E>` (jika *fixed-length* via `List.filled(n, val, growable: false)`). Elemen disimpan di dalam array memori sekuensial (*contiguous array buffer*).
- **Set & Map Implementation**: Sintaksis literal `{}` secara internal menggunakan `_CompactLinkedHashSet<E>` dan `_CompactLinkedHashMap<K, V>`. Struktur data ini menggunakan skema *flat hash table*: bukan memakai *linked-nodes* terpisah seperti Java `LinkedHashMap`, Dart menggunakan dua array internal:
  1. Array *hash table* (indeks *bucket*).
  2. Array data kontigu yang menyimpan kunci (*keys*), nilai (*values*), dan tautan (*links*) untuk menjaga urutan insersi (*insertion-order traversal*). Pendekatan ini menghasilkan *cache locality* yang jauh lebih superior pada arsitektur CPU modern.

#### Alokasi Memori / Resource
- **Resizing Policy**: Pada `_GrowableList`, ketika kapasitas (*capacity*) buffer penuh saat pemanggilan `.add()`, Dart VM menggandakan kapasitas buffer (`new_capacity = old_capacity + (old_capacity >> 1) + 1` atau doubling strategy tergantung target architecture). Ini memberikan amortized time complexity $O(1)$ untuk insersi, namun menghasilkan relokasi memori dan garbage collection pada buffer lama.
- **Generic Metadata**: Setiap instance `List<E>`, `Set<E>`, dan `Map<K, V>` membawa pointer ke struktur metadata tipe (*type arguments descriptor*) di header objeknya pada heap. Pointer ini menambah overhead sebesar 8 byte (pada 64-bit architecture) per collection instance, yang diperiksa setiap kali instruksi tipe (`check-cast` / *subtyping check*) dipanggil oleh Dart AOT/JIT engine.

#### Trade-offs
| Collection Type | Kompleksitas Waktu Rata-rata | Memory Overhead | Karakteristik Ruang Cache |
| :--- | :--- | :--- | :--- |
| `List<E>` | Read: $O(1)$, Append: Amortized $O(1)$, Insert/Remove: $O(N)$ | Minimal (Contiguous Pointer Array) | Sangat Tinggi (L1/L2 Cache hit optimal) |
| `Set<E>` | Search: $O(1)$, Insert: $O(1)$, Delete: $O(1)$ | Sedang-Tinggi (Hash table + Index array) | Moderat (Flat Linked Array Hash Table) |
| `Map<K, V>` | Lookup: $O(1)$, Insert: $O(1)$, Delete: $O(1)$ | Tinggi (Dua array paralel untuk Keys & Values) | Moderat |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan generic parameter pada sisi literal**: Tuliskan `<String>['a', 'b']` daripada `List<String> list = ['a', 'b']`. Pendekatan ini mencegah komputasi inferensi ganda dan langsung mengikat tipe sejak alokasi ekspresi literal.
- **Konversikan List ke Set untuk operasi pencarian masif**: Jika data membutuhkan validasi keberadaan (`.contains()`) di dalam loop atau dataset besar, alihkan dari $O(N)$ milik `List` ke $O(1)$ milik `Set`.
- **Manfaatkan `const` collection literal**: Jika elemen bersifat konstan pada fase kompilasi (`const <String>['prod', 'staging']`), Dart akan melakukan *canonicalization*—hanya satu instance memori tunggal yang dialokasikan di segmen *read-only* memory untuk seluruh siklus hidup aplikasi.

#### Don'ts
- **Hindari *raw types* / dynamic types implisit**: Menulis `final list = [];` menghasilkan `List<dynamic>`. Ini mematikan optimasi compiler AOT (*devirtualization*) dan memperlambat pemrosesan karena engine harus melakukan boxing/unboxing dan runtime checks pada setiap akses elemen.
- **Jangan gunakan `{}` untuk inisialisasi Set kosong**: Menulis `Set<int> mySet = {};` valid karena konteks variabel, namun menulis `final mySet = {};` akan diam-diam menghasilkan `Map<dynamic, dynamic>`, memicu error di baris kode selanjutnya. Gunakan selalu `final mySet = <int>{};`.

#### Edge Cases
- **Identity Hash vs Equality Contract**: Objek yang dimasukkan ke dalam `Set` atau dijadikan kunci pada `Map` **wajib** meng-override operator `==` dan getter `hashCode` secara konsisten. Jika tidak, dua instance objek yang memiliki data identik akan dianggap sebagai entitas berbeda karena Dart runtime menggunakan identitas referensi memori (*identity hash*) secara default.
- **Mutasi Objek Kunci Map**: Jangan pernah memutasi nilai internal sebuah objek yang telah digunakan sebagai *Key* pada `Map` jika nilai tersebut mempengaruhi hasil `hashCode`. Perubahan hash saat objek berada di dalam bucket akan merusak integritas tabel pencarian, membuat objek tersebut tidak lagi dapat ditemukan (*lost key memory leak*).

### 5. Tantangan Eksplorasi Mandiri

1. **Investigasi Type Covariance**: Ujilah skenario *runtime covariance* berikut: buat variabel `List<num> numList = <int>[1, 2, 3];`. Analisis apa yang terjadi pada runtime ketika Anda memanggil `numList.add(3.14);`. Mengapa kompiler meloloskan kode tersebut saat statis, namun runtime melempar exception? Jelaskan kaitannya dengan *reified generics*.
2. **Benchmark Cache Locality**: Buat pengujian performa perbandingan eksekusi iterasi menggunakan `Stopwatch`: iterasi membaca 1.000.000 data pada `List<int>` versus pencarian 1.000.000 data menggunakan `Set<int>.contains()`. Analisis konsumsi memori dan kecepatan transfer data berdasarkan arsitektur heap Dart.
