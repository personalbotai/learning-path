## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Diperkenalkan secara masif pada Dart 3.0, **Patterns** adalah kategori sintaksis baru yang merepresentasikan "bentuk" (shape) dari sekumpulan nilai. Pattern memungkinkan Anda melakukan tiga hal sekaligus secara deklaratif:
1. **Matching (Pencocokan):** Memeriksa apakah suatu nilai memiliki bentuk atau tipe tertentu.
2. **Destructuring (Pembongkaran):** Mengekstrak bagian-bagian dari nilai komposit (seperti Record, List, Map, atau Object) menjadi variabel terpisah.
3. **Variable Assignment (Penugasan Variabel):** Mengikat (bind) nilai yang diekstrak ke dalam variabel baru dalam satu langkah.

Secara arsitektur, Pattern mengubah paradigma Dart dari ekstraksi data imperatif (menggunakan banyak `if-else`, `is`, dan *getter* manual) menjadi deklaratif. Fitur ini sangat terintegrasi dengan *Flow Analysis* pada Dart Compiler. Ketika sebuah pattern berhasil dicocokkan, compiler secara otomatis melakukan *type promotion* pada variabel yang diekstrak, memastikan *type safety* tanpa *casting* manual.

Pattern sangat bersinergi dengan **Algebraic Data Types (ADT)** melalui penggunaan `sealed classes` dan `switch expressions`, memungkinkan *exhaustiveness checking* (pengecekan kelengkapan) di tingkat kompilasi.

### 2. Implementasi & Contoh Kasus Nyata

```dart
// 1. Destructuring & Variable Assignment pada Records
void recordDestructuring() {
  var (a, b) = ('Dart', 3.0);
  print('$a version $b'); // Output: Dart version 3.0

  // Swapping variabel tanpa variabel temporary (Under the hood: menggunakan stack)
  (a, b) = (b.toString(), double.tryParse(a) ?? 0.0); 
}

// 2. Pattern Matching pada JSON (Map Destructuring)
void parseJson(Map<String, dynamic> json) {
  // if-case pattern: Memvalidasi struktur dan mengekstrak data sekaligus
  if (json case {'user': {'name': String name, 'age': int age}} when age >= 18) {
    print('User dewasa: $name');
  } else {
    print('JSON tidak valid atau user di bawah umur.');
  }
}

// 3. Switch Expression dengan Object Destructuring & Relational Patterns
sealed class Shape {}
class Circle extends Shape { final double radius; Circle(this.radius); }
class Rectangle extends Shape { final double width, height; Rectangle(this.width, this.height); }

String calculateArea(Shape shape) {
  // Switch expression mewajibkan exhaustiveness (semua kemungkinan harus ditangani)
  return switch (shape) {
    // Object destructuring: mengekstrak properti 'radius'
    Circle(radius: final r) when r > 0 => 'Luas Lingkaran: ${3.14 * r * r}',
    Circle() => 'Radius tidak valid', // Menangkap radius <= 0
    
    // Mengekstrak width dan height, menggunakan wildcard (_) jika tidak butuh nama variabel spesifik
    Rectangle(width: final w, height: final h) => 'Luas Persegi Panjang: ${w * h}',
  };
}

// 4. List Pattern & Rest Element (...)
void processList(List<int> numbers) {
  switch (numbers) {
    case [1, 2]:
      print('List berisi tepat 1 dan 2');
    case [1, 2, ...var rest]:
      print('Dimulai dengan 1, 2. Sisanya: $rest');
    case [_, _, final third, ...]:
      print('Elemen ketiga adalah $third');
    default:
      print('Bentuk list tidak dikenali');
  }
}

void main() {
  recordDestructuring();
  parseJson({'user': {'name': 'Budi', 'age': 25}});
  print(calculateArea(Circle(10)));
  processList([1, 2, 3, 4, 5]);
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: Pattern matching tidak dieksekusi menggunakan *reflection* (mirrors) yang lambat. Dart compiler menerjemahkan pattern menjadi serangkaian instruksi `is` (type checks), `==` (equality checks), dan pemanggilan *getter* yang sangat dioptimalkan. Pada *switch expressions*, compiler menggunakan *jump tables* atau *binary search* jika memungkinkan, membuatnya lebih cepat daripada rantai `if-else`.
- **Alokasi Memori / Resource**: Destructuring (terutama pada Records) sangat efisien. Dart tidak membuat objek baru di *heap* hanya untuk membongkar nilai. Variabel yang diikat (bound variables) langsung dialokasikan di *stack* atau register CPU. Penggunaan *rest element* (`...`) pada List akan mengalokasikan List baru di memori untuk menampung sisa elemen, sehingga perlu digunakan dengan bijak pada List berukuran masif.
- **Trade-offs**: Pattern matching meningkatkan *readability* dan *safety*, namun pattern yang terlalu dalam (deeply nested) dapat meningkatkan beban kognitif developer dan sedikit memperlambat waktu kompilasi karena *Flow Analysis* harus menghitung semua kemungkinan *branching* dan *type promotion*.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan `if case` untuk memvalidasi dan mengekstrak data dari JSON/Map dinamis. Ini menghilangkan kebutuhan akan *null-checking* dan *type-casting* manual yang rawan error.
  - Gunakan `switch expressions` dikombinasikan dengan `sealed classes` untuk *state management* (misal: BLoC/Riverpod states) agar compiler memaksa Anda menangani semua *state* (Exhaustive).
  - Gunakan *wildcard* (`_`) untuk nilai yang diekstrak namun tidak digunakan agar linter tidak mengeluh tentang *unused variables*.
- **Don'ts**:
  - Jangan membuat *nested patterns* yang terlalu kompleks dalam satu baris. Jika pattern melebihi 3 tingkat kedalaman, pecah menjadi beberapa fungsi atau evaluasi terpisah demi keterbacaan.
  - Jangan gunakan pattern matching untuk logika perbandingan sederhana yang bisa diselesaikan dengan `if (a == b)`. Pattern memiliki sedikit *overhead* sintaksis.
- **Edge Cases**:
  - **Map Keys**: Pada Map pattern (`{'key': var value}`), Dart hanya mengecek keberadaan *key* tersebut. Jika Map memiliki *key* lain, pattern tetap *match* (tidak *strict*).
  - **Nullability**: Hati-hati dengan tipe *nullable*. Pattern `String x` tidak akan *match* dengan nilai `null`. Gunakan `String? x` atau tangani `null` secara eksplisit.

### 5. Tantangan Eksplorasi Mandiri

1. **JSON Parser Kompleks**: Buat sebuah fungsi yang menerima respons API berupa `List<dynamic>`. Gunakan List dan Map destructuring secara bersamaan untuk mengekstrak hanya objek yang memiliki status `"active"` dan memiliki properti `"metadata"` yang berisi `"role": "admin"`.
2. **State Machine dengan Sealed Classes**: Implementasikan sistem *Routing* sederhana. Buat `sealed class RouteState`. Buat subclass `Home`, `Profile(String userId)`, dan `Error(int code)`. Gunakan *switch expression* untuk me-return *String* URL berdasarkan state tersebut, manfaatkan *guard clause* (`when`) untuk memvalidasi `userId` tidak boleh kosong.
3. **Custom Object Pattern**: Buat class `Vector3(double x, double y, double z)`. Implementasikan logika untuk mendeteksi apakah vektor tersebut berada di sumbu X, Y, atau Z murni (dua nilai lainnya 0) menggunakan *Object Destructuring* di dalam *switch statement*.
