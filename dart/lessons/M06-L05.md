## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam Dart, `Future` merepresentasikan komputasi asinkron tunggal yang akan selesai di masa depan, sedangkan `Stream` merepresentasikan sekuens data asinkron yang tiba secara bertahap. Ketika membangun pipeline data yang reaktif, pengelolaan stream manual menggunakan `StreamController` sering kali memicu *boilerplate* kode yang repetitif serta rentan terhadap *memory leak* akibat kegagalan penanganan *lifecycle* langganan (`StreamSubscription`).

Untuk mengatasi masalah ini, Dart menyediakan:
1. **`async*` (Asynchronous Generators)**: Modifikasi fungsi yang secara otomatis mengembalikan objek `Stream<T>`. Compiler memetakan fungsi ini menjadi sebuah *state machine* asinkron.
2. **`yield` & `yield*`**: Pernyataan kendali untuk memancarkan (*emit*) nilai ke dalam stream. 
   - `yield e`: Mengirimkan satu nilai `e` ke stream dan menunda (*suspend*) eksekusi fungsi sampai event loop dan konsumen siap memproses nilai berikutnya (*backpressure aware*).
   - `yield* s`: Mendelegasikan pemancaran seluruh urutan nilai dari stream lain (atau `Iterable`) `s` secara langsung ke output stream tanpa overhead ekstraksi manual per elemen.
3. **`StreamTransformer<S, T>`**: Abstraksi kelas middleware yang memproses elemen input bertipe `S` dan mentransformasikannya menjadi elemen bertipe `T`. Ini menerapkan pola arsitektur *Pipes and Filters*, memungkinkan pemisahan tegas antara produsen data, logika transformasi, dan konsumen akhir.

```
[Producer: async* + yield] 
       │ (Events: Type S)
       ▼
┌──────────────────────────────┐
│ StreamTransformer<S, T>       │  <-- Interseptasi, Filter, Mutasi, Buffer
└──────────────────────────────┘
       │ (Events: Type T)
       ▼
[Consumer: listen / await for]
```

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengimplementasikan sistem ingest log metrik server. Produsen menggunakan `async*` dan `yield*`, yang kemudian diproses melalui *custom* `StreamTransformer` untuk memvalidasi dan mem-parsing data mentah menjadi structured model.

```dart
import 'dart:async';
import 'dart:convert';

// Model data metrik
class MetricLog {
  final DateTime timestamp;
  final String level;
  final String message;

  MetricLog({required this.timestamp, required this.level, required this.message});

  @override
  String toString() => '[$level] ${timestamp.toIso8601String()} -> $message';
}

// 1. Stream Generator menggunakan async* dan yield / yield*
Stream<String> fetchRawLogBatches(int batchCount) async* {
  for (int i = 1; i <= batchCount; i++) {
    // Simulasi latency jaringan
    await Future.delayed(Duration(milliseconds: 100));

    // Memancarkan satu batch log mentah sebagai sub-stream menggunakan yield*
    yield* _generateBatch(i);
  }
}

Stream<String> _generateBatch(int batchId) async* {
  yield '{"level": "INFO", "msg": "Worker $batchId online"}';
  yield 'INVALID_PAYLOAD'; // Simulasi data korup
  yield '{"level": "WARN", "msg": "Worker $batchId high memory usage"}';
}

// 2. Custom StreamTransformer untuk Sanitasi dan Parsing
class MetricLogTransformer extends StreamTransformerBase<String, MetricLog> {
  @override
  Stream<MetricLog> bind(Stream<String> stream) {
    return Stream<MetricLog>.eventTransformed(stream, (sink) => _MetricLogSink(sink));
  }
}

class _MetricLogSink implements EventSink<String> {
  final EventSink<MetricLog> _outputSink;

  _MetricLogSink(this._outputSink);

  @override
  void add(String data) {
    try {
      final Map<String, dynamic> json = jsonDecode(data);
      final log = MetricLog(
        timestamp: DateTime.now(),
        level: json['level'] as String? ?? 'UNKNOWN',
        message: json['msg'] as String? ?? '',
      );
      _outputSink.add(log); // Teruskan data valid
    } catch (_) {
      // Abaikan payload corrupt secara silent atau kirim via addError
      // Di sini kita memilih membuang data corrupt (filter behavior)
    }
  }

  @override
  void addError(Object error, [StackTrace? stackTrace]) {
    _outputSink.addError(error, stackTrace);
  }

  @override
  void close() {
    _outputSink.close();
  }
}

// 3. Execution Pipeline
void main() async {
  final rawLogStream = fetchRawLogBatches(2);

  // Menerapkan transformer ke dalam stream pipeline
  final processedStream = rawLogStream.transform(MetricLogTransformer());

  // Konsumsi data stream
  await for (final MetricLog log in processedStream) {
    print(log);
  }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (State Machine Compilation)
- Saat compiler Dart (`dart2js`, `dart2wasm`, atau AOT Dart VM) menemukan fungsi `async*`, compiler membongkar fungsi imperatif tersebut menjadi sebuah objek `_AsyncStarStreamController`.
- Setiap pernyataan `yield` diterjemahkan menjadi *suspension point*. Runtime menghentikan eksekusi kode lokal pada frame fungsi tersebut dan mengembalikan eksekusi ke Dart Event Loop.
- Eksekusi fungsi tidak akan berlanjut ke baris setelah `yield` sampai event yang baru saja dipancarkan selesai dialirkan ke *listener*, atau listener memberi sinyal siap (*backpressure pull*).
- `yield*` tidak melakukan iterasi manual sederhana seperti `await for (var x in s) yield x;`. Secara internal, Dart Runtime menghubungkan sink stream tujuan langsung ke sub-stream sumber via delegasi subscription level-C++/C-runtime. Ini mereduksi *frame allocation* dan mencegah eksploitasi call-stack berlebih.

#### Alokasi Memori / Resource
- **State Preservation**: Variabel lokal dalam fungsi `async*` dipindahkan (*hoisted*) dari *stack frame* ke *heap-allocated context*. Ini wajib karena fungsi harus dapat di-*suspend* dan di-*resume* lintas iterasi event loop.
- **Microtask Queue Interaction**: Emisi data dari `yield` biasanya dijadwalkan melalui Microtask Queue agar transmisi data tetap asinkron namun diprioritaskan sebelum event I/O berikutnya diproses oleh Dart Event Loop.

#### Trade-offs
- **`async*` vs `StreamController`**: `async*` jauh lebih aman dari kebocoran memori karena siklus hidupnya terikat langsung dengan status pembatalan listener (`cancel()`). Namun, ada sedikit overhead performa alokasi objek heap state-machine dibandingkan memancarkan data secara langsung via `StreamController.add()` sinkron murni.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Manfaatkan Blok `try...finally`**: Kode dalam blok `finally` pada fungsi `async*` dijamin **pasti dieksekusi** ketika konsumen membatalkan subscription (`subscription.cancel()`). Gunakan ini untuk *resource disposal* (misal: menutup koneksi socket atau file handle).
  ```dart
  Stream<int> readFileChunks(File file) async* {
    final handle = await file.open();
    try {
      while (true) {
        final chunk = await handle.read(1024);
        if (chunk.isEmpty) break;
        yield chunk;
      }
    } finally {
      await handle.close(); // Selalu dipanggil saat cancel() dipicu
    }
  }
  ```
- **Gunakan `yield*` untuk Delegasi**: Selalu gunakan `yield* subStream` alih-alih `await for (var item in subStream) { yield item; }`. `yield*` menghindari overhead pembuatan frame task berulang.

#### Don'ts
- **Menghindari `yield` dalam Loop Sinkron Tanpa Asinkronisitas Nyata**: Menggunakan `async*` untuk menghasilkan data yang sudah ada di memori (misalnya mem-parsing `List` lokal) adalah anti-pattern. Gunakan `sync*` dengan `Iterable` untuk komputasi sekuensial sinkron.
- **Mengabaikan Backpressure**: Jangan memodifikasi variabel state bersama (*shared mutable state*) di luar `async*` yang bergantung pada timing konsumsi downstream.

#### Edge Cases
- **Unconsumed `yield` Execution Halt**: Jika konsumen stream berhenti mendengarkan atau melakukan `break` di dalam loop `await for`, fungsi `async*` akan dihentikan secara permanen tepat di titik `yield` terakhir. Kode imperatif apa pun setelah titik `yield` tersebut (di luar blok `finally`) **tidak akan pernah dieksekusi**.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi `DebounceTransformer`**: Tanpa menggunakan pustaka pihak ketiga (seperti RxDart), buatlah sebuah `StreamTransformer<T, T>` yang menunda pemancaran data selama durasi waktu tertentu (`Duration`), dan membatalkan pemancaran data sebelumnya jika ada data baru yang masuk sebelum durasi berakhir.
2. **Memory Profile `yield*` vs `await for + yield`**: Buat fungsi rekursif pembuat pohon folder direktori (`Directory`). Uji traversal direktori yang sangat dalam (misal: 10.000 level hierarki buatan) menggunakan `await for + yield` vs `yield*`. Amati perbandingan alokasi heap memori dan stack trace menggunakan *Dart DevTools Memory Profiler*.
