### 1. Konsep & Arsitektur Mendalam

Di ekosistem Dart, komunikasi HTTP tidak berjalan di atas thread terpisah yang memblokir eksekusi, melainkan terintegrasi langsung dengan model non-blocking event-driven runtime Dart VM. Inti dari networking Dart bertumpu pada pustaka level rendah `dart:io` (khususnya class `HttpClient`) untuk platform native (VM, Desktop, Mobile) dan API browser (`fetch`/`XMLHttpRequest`) untuk Dart Web.

Dua package utama yang mendominasi ekosistem Dart adalah `http` dan `dio`. Keduanya memecahkan masalah abstraksi level rendah `dart:io`, namun dengan filosofi arsitektural yang berbeda:

```
+-----------------------------------------------------------+
|                    Aplikasi Dart                          |
+-----------------------------------------------------------+
         |                                         |
         v                                         v
+------------------+                    +--------------------+
|  package:http    |                    |    package:dio     |
| (Composable,     |                    | (Interceptor Chain,|
|  Minimalist)     |                    |  CancelToken, etc) |
+------------------+                    +--------------------+
         |                                         |
         +--------------------+--------------------+
                              |
                              v
             +----------------------------------+
             |      Engine: dart:io / Web       |
             |  (Socket Pool, TLS, Event Loop)  |
             +----------------------------------+
```

#### Package `http` (Filosofi Composable)
Package resmi dari tim Dart (`package:http`) dirancang dengan prinsip modularitas minimalis. Ia membungkus request dan response dalam kelas immutable (`Request`, `Response`, `StreamedResponse`). 
- **Arsitektur Client**: Menggunakan `BaseClient` yang memungkinkan pembuatan *pipeline* middleware melalui komposisi (misal: wrapping client untuk logging atau autentikasi).
- **Target Penggunaan**: Aplikasi dengan kebutuhan networking standar, CLI tools, atau microservice yang membutuhkan binary size ramping dan ketergantungan minimal.

#### Package `dio` (Filosofi Enterprise-Ready)
`dio` adalah HTTP client kaya fitur yang mengadopsi pola arsitektur *Interceptors*, terinspirasi dari Axios di ekosistem JavaScript.
- **Interceptors Pipeline**: Request, response, dan error melewati antrean interceptor tersinkronisasi. Ini memungkinkan operasi atomik seperti penyisipan token, *refresh token queuing*, dan logging global tanpa merusak abstraksi caller.
- **Fitur Lanjutan Bawaan**: Mendukung pembatalan request (`CancelToken`), pelacakan progres download/upload berbasis stream, konfigurasi *transformer*, dan adapter jaringan kustom (`HttpClientAdapter`).
- **Target Penggunaan**: Aplikasi skala produksi enterprise yang membutuhkan manajemen siklus hidup request kompleks, penanganan refresh token otomatis, dan kontrol transfer data besar.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah contoh implementasi modern (Dart 3.x) yang membandingkan penggunaan `http.Client` dengan arsitektur produksi menggunakan `Dio`, lengkap dengan Interceptor untuk refresh token dan error handling yang terstruktur.

```dart
import 'dart:async';
import 'dart:convert';
import 'package:dio/dio.dart';
import 'package:http/http.dart' as http;

// =======================================================================
// 1. PENDEKATAN package:http (Lightweight & Composable)
// =======================================================================

class SimpleApiClient {
  final http.Client _client;
  final String _baseUrl;

  SimpleApiClient({required String baseUrl, http.Client? client})
      : _baseUrl = baseUrl,
        _client = client ?? http.Client();

  Future<Map<String, dynamic>> fetchPost(int id) async {
    final uri = Uri.parse('$_baseUrl/posts/$id');

    // Menghindari socket exhaustion: gunakan kembali instance _client yang sama
    final response = await _client.get(
      uri,
      headers: {'Accept': 'application/json'},
    );

    if (response.statusCode == 200) {
      return jsonDecode(response.body) as Map<String, dynamic>;
    } else {
      throw HttpException('Gagal memuat post: ${response.statusCode}');
    }
  }

  void dispose() {
    _client.close(); // Menutup persistent connections (TCP sockets)
  }
}

class HttpException implements Exception {
  final String message;
  HttpException(this.message);
  @override
  String toString() => 'HttpException: $message';
}

// =======================================================================
// 2. PENDEKATAN package:dio (Production-Grade Architecture)
// =======================================================================

class TokenManager {
  static String? accessToken = "expired_dummy_token";
  
  static Future<String> refreshAccessToken() async {
    // Simulasi delay pemanggilan auth server
    await Future.delayed(const Duration(milliseconds: 500));
    accessToken = "valid_new_token_${DateTime.now().millisecondsSinceEpoch}";
    return accessToken!;
  }
}

class ApiService {
  late final Dio _dio;

  ApiService(String baseUrl) {
    _dio = Dio(
      BaseOptions(
        baseUrl: baseUrl,
        connectTimeout: const Duration(seconds: 5),
        receiveTimeout: const Duration(seconds: 3),
        headers: {'Accept': 'application/json'},
      ),
    );

    // Menambahkan Interceptor untuk Logging & Refresh Token Queue
    _dio.interceptors.add(
      QueuedInterceptorsWrapper(
        onRequest: (options, handler) {
          // Inject token pada setiap request
          if (TokenManager.accessToken != null) {
            options.headers['Authorization'] = 'Bearer ${TokenManager.accessToken}';
          }
          return handler.next(options);
        },
        onError: (DioException error, handler) async {
          // Tangkap 401 dan lakukan auto-retry setelah refresh token
          if (error.response?.statusCode == 401) {
            try {
              final newToken = await TokenManager.refreshAccessToken();
              
              // Kloning request sebelumnya dengan token baru
              final requestOptions = error.requestOptions;
              requestOptions.headers['Authorization'] = 'Bearer $newToken';
              
              // Retry request secara transparan
              final response = await _dio.fetch(requestOptions);
              return handler.resolve(response);
            } catch (refreshError) {
              return handler.reject(error);
            }
          }
          return handler.next(error);
        },
      ),
    );
  }

  // Penggunaan CancelToken untuk mencegah memory leak saat proses dibatalkan
  Future<Response<T>> getData<T>(String endpoint, {CancelToken? cancelToken}) async {
    try {
      return await _dio.get<T>(endpoint, cancelToken: cancelToken);
    } on DioException catch (e) {
      throw _handleDioError(e);
    }
  }

  String _handleDioError(DioException error) {
    switch (error.type) {
      case DioExceptionType.connectionTimeout:
      case DioExceptionType.receiveTimeout:
        return "Batas waktu koneksi habis.";
      case DioExceptionType.badResponse:
        return "Server error: ${error.response?.statusCode}";
      case DioExceptionType.cancel:
        return "Permintaan dibatalkan.";
      default:
        return "Kesalahan jaringan tidak terduga: ${error.message}";
    }
  }
}

void main() async {
  // Simulasi penggunaan Dio
  final api = ApiService('https://jsonplaceholder.typicode.com');
  final cancelToken = CancelToken();

  try {
    final response = await api.getData('/posts/1', cancelToken: cancelToken);
    print("Dio Response: ${response.data['title']}");
  } catch (e) {
    print("Terjadi Error: $e");
  }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime Dart
Dart menggunakan single-threaded concurrency berbasis **Event Loop**. Ketika operasi HTTP dipanggil:
1. Permintaan I/O didelegasikan keluar dari Isolate utama ke **Dart Native OS Thread Pool** melalui asynchronous primitives `dart:io`.
2. Native engine membuat OS-level system calls (`epoll` di Linux/Android, `kqueue` di macOS/iOS, atau `IOCP` di Windows) untuk mendengarkan state perubahan socket.
3. Selama soket menunggu *handshake* TLS atau respons server, thread utama Dart bebas memproses task lain di Event Loop (rendering UI atau komputasi lokal).
4. Ketika data byte pertama tiba, sistem operasi membangunkan native thread, menyuntikkan I/O event ke dalam **Event Queue** Dart Isolate pemanggil, dan memproses parsing data chunk demi chunk via microtasks.

#### Alokasi Memori & Resource
- **Persistent Connection (Keep-Alive)**: Ketika menggunakan instance `Client()` atau `Dio()` yang persisten, Dart mempertahankan TCP connection pool aktif. Jika instance dibuat ulang pada setiap request (misal: `http.get()` level fungsi), sistem akan terus-menerus melakukan alokasi 3-way TCP handshake dan TLS negotiation, memicu **Socket/File Descriptor Exhaustion** di tingkat OS.
- **Chunked Transfer vs In-Memory Buffering**: 
  - `http.Response` mengumpulkan seluruh body respons ke dalam bentuk byte array di RAM sebelum mengubahnya menjadi `String` via `utf8.decode()`. Untuk file berukuran ratusan megabyte, ini memicu GC (*Garbage Collector*) pressure secara drastis hingga Out-Of-Memory (OOM).
  - `dio` dan `http.StreamedResponse` membaca data langsung dari network socket sebagai `Stream<List<int>>`. Data dapat di-pipe langsung ke sistem file (disk) tanpa mendiami RAM secara penuh.

#### Trade-offs
| Parameter | `package:http` | `package:dio` |
| :--- | :--- | :--- |
| **Footprint Dependency** | Sangat ringan, core maintenance oleh tim Dart. | Lebih besar, banyak modul internal (adapter, form-data, dll). |
| **Control Cancellation** | Terbatas (harus membatalkan stream secara manual). | Native & Elegan via `CancelToken`. |
| **Customization Curve** | Rendah (butuh manual boilerplate wrapping). | Tinggi (Interceptors, QueuedInterceptors, Transformer). |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Single Instance**: Deklarasikan `Dio` atau `http.Client` sebagai singleton atau dependency jangka panjang (menggunakan Service Locator seperti `get_it` atau DI pattern) agar TCP connection pool dapat di-reuse.
- **Gunakan `QueuedInterceptorsWrapper` untuk Auth**: Pada `dio`, jika token kedaluwarsa, gunakan antrean (`QueuedInterceptorsWrapper`) agar ketika ada 5 request paralel yang terkena `401 Unauthorized`, proses refresh token hanya dieksekusi **satu kali**, dan 4 request sisanya ditangguhkan sampai token baru siap.
- **Offload Parsing JSON Besar ke Isolate**: Parsing payload JSON ribuan baris dengan `jsonDecode` dapat menyebabkan *frame drop* (jank) pada UI Flutter. Gunakan `compute` atau `Isolate.run()`:
  ```dart
  final rawData = response.data;
  final parsed = await Isolate.run(() => parseHeavyJson(rawData));
  ```

#### Don'ts
- **Hindari Top-Level Functions `http.get()` di Siklus Berulang**: Top-level function pada package `http` membuat instance client baru lalu langsung menutupnya (`close()`) setiap kali selesai, mematikan kemampuan HTTP Keep-Alive.
- **Jangan Mengabaikan Timeouts**: Nilai default timeout pada koneksi socket native bisa tak terbatas atau sangat lama (hingga hitungan menit). Selalu konfigurasikan `connectTimeout`, `sendTimeout`, dan `receiveTimeout`.
- **Jangan Mematikan Validasi SSL di Produksi**: Menulis `badCertificateCallback = (cert, host, port) => true;` untuk mengatasi masalah sertifikat pada masa dev adalah lubang keamanan fatal terhadap serangan *Man-in-the-Middle* (MITM).

#### Edge Cases
- **Mutasi Payload Bersamaan (Race Conditions)**: Berhati-hatilah saat mengubah instance request option di interceptor. Jika menggunakan instance mutable yang diakses secara concurrent, gunakan kloning deep-copy sebelum melakukan retry request.
- **Stream Interruption**: Saat download data besar dibatalkan menggunakan `CancelToken`, pastikan file partial yang belum selesai ditulis dihapus dari disk penyimpanan agar tidak menyisakan *dangling temporary files*.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Refresh Token Queue dengan Exponential Backoff**:
   Bangun sebuah instance `Dio` yang menggunakan `QueuedInterceptorsWrapper`. Uji kasus di mana ketika refresh token gagal (misal server auth down), sistem melakukan *exponential retry* sebanyak 3 kali (1 detik, 2 detik, 4 detik) sebelum akhirnya menyerah dan melempar error `SessionExpiredException`.

2. **Large File Downloader dengan Backpressure**:
   Buat downloader file menggunakan `dio` dengan konfigurasi respons berupa stream data (`ResponseType.stream`). Tuliskan chunk data tersebut ke file menggunakan `IOSink` dari `dart:io`. Pantau progress unduhan dalam persentase tanpa membiarkan alokasi memori RAM aplikasi naik lebih dari 15MB selama proses unduhan file berukuran >500MB berlangsung.
