## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dart mengadopsi model konkurensi berbasis **Single-Threaded Execution** yang berjalan di dalam sebuah unit eksekusi terisolasi yang disebut **Isolate**. Berbeda dengan runtime multi-thread konvensional (seperti Java atau C#) di mana thread berbagi memori (*shared memory*) dan memerlukan sinkronisasi berbasis *mutex/lock*, setiap Isolate pada Dart memiliki heap memori dan tumpukan eksekusi (*call stack*) miliknya sendiri. Ketiadaan *shared memory* mengeliminasi potensi *race condition*, *deadlock*, dan overhead sinkronisasi thread di tingkat bahasa.

Untuk menangani operasi asinkron (I/O, network, timer, user interaction) tanpa memblokir thread utama, Dart Runtime mengimplementasikan **Event Loop**. Arsitektur ini terdiri dari dua komponen inti:

1. **Call Stack**: Struktur data LIFO (*Last In, First Out*) tempat *frame* fungsi dieksekusi secara sinkron hingga selesai (*run-to-completion*).
2. **Event Loop Queues**: Struktur FIFO (*First In, First Out*) yang menampung task asinkron. Terdapat dua antrean dengan prioritas berbeda:
   - **Microtask Queue**: Antrean internal berprioritas tinggi. Digunakan untuk tindakan komputasi internal yang sangat singkat dan harus diselesaikan sebelum menyerahkan kendali kembali ke sistem operasi atau event berikutnya.
   - **Event Queue**: Antrean umum untuk event eksternal, seperti interaksi UI, operasi I/O (file, network), timer (`Timer`, `Future.delayed`), dan pesan antar-isolate (*port messaging*).

```
+-----------------------------------------------------------+
|                        DART ISOLATE                       |
|                                                           |
|   +-------------------+                                   |
|   |    Call Stack     | <--- Menjalankan kode sinkron     |
|   +-------------------+                                   |
|             ^                                             |
|             |                                             |
|   +-------------------+                                   |
|   |    Event Loop     |                                   |
|   +-------------------+                                   |
|        /         \                                        |
|   [Prioritas 1]  [Prioritas 2]                            |
|       v             v                                     |
|  +-----------+  +------------+                            |
|  | Microtask |  |   Event    |                            |
|  |   Queue   |  |   Queue    |                            |
|  +-----------+  +------------+                            |
+-----------------------------------------------------------+
```

#### Aturan Eksekusi Event Loop
Dart memproses eksekusi dengan determinisme tinggi:
1. Selesaikan semua eksekusi sinkron pada *Call Stack* hingga kosong.
2. Periksa **Microtask Queue**. Jika ada task, ambil satu per satu dan eksekusi pada Call Stack sampai Microtask Queue **benar-benar kosong**.
3. Jika Microtask Queue kosong, ambil **satu** event terdepan dari **Event Queue**, lalu eksekusi di Call Stack.
4. Ulangi siklus: setelah *satu* event dari Event Queue selesai, Dart akan selalu memeriksa Microtask Queue kembali sebelum mengambil event berikutnya dari Event Queue.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengilustrasikan determinisme urutan eksekusi antara eksekusi sinkron, Microtask Queue, dan Event Queue.

```dart
import 'dart:async';

void main() {
  print('1. [Sync] Main execution started');

  // Menambahkan task ke Event Queue
  Future(() {
    print('7. [Event Queue] Normal Future executed');
  });

  // Future dengan delay (Event Queue)
  Future.delayed(Duration.zero, () {
    print('8. [Event Queue] Zero-delay Future executed');
  });

  // Menambahkan task ke Microtask Queue secara eksplisit
  scheduleMicrotask(() {
    print('4. [Microtask] scheduleMicrotask executed');
  });

  // Future.microtask secara otomatis masuk ke Microtask Queue
  Future.microtask(() {
    print('5. [Microtask] Future.microtask executed');
  });

  // Chain asynchronous: Then akan dieksekusi segera setelah Future selesai
  Future(() {
    print('9. [Event Queue] Chained Future - Base');
  }).then((_) {
    print('10. [Microtask via Then] Chained Future - Callback');
  });

  // Menjadwalkan microtask bersarang di dalam microtask lain
  scheduleMicrotask(() {
    print('6. [Microtask] Outer microtask');
    scheduleMicrotask(() {
      // Ini akan dieksekusi sebelum Event Queue berikutnya diproses!
      print('6b. [Microtask] Nested microtask');
    });
  });

  // Eksekusi sinkron langsung di call stack
  print('2. [Sync] Processing inline logic...');

  // Task microtask yang dijadwalkan tepat sebelum sinkron selesai
  scheduleMicrotask(() => print('3. [Microtask] Final sync-scheduled microtask'));

  print('2b. [Sync] Main execution finished');
}
```

#### Analisis Output:
```text
1. [Sync] Main execution started
2. [Sync] Processing inline logic...
2b. [Sync] Main execution finished
4. [Microtask] scheduleMicrotask executed
5. [Microtask] Future.microtask executed
6. [Microtask] Outer microtask
3. [Microtask] Final sync-scheduled microtask
6b. [Microtask] Nested microtask
7. [Event Queue] Normal Future executed
8. [Event Queue] Zero-delay Future executed
9. [Event Queue] Chained Future - Base
10. [Microtask via Then] Chained Future - Callback
```

**Penjelasan Tahapan:**
1. Baris sinkron (`1`, `2`, `2b`) dieksekusi langsung pada *Call Stack*.
2. Call stack kosong. Dart memeriksa *Microtask Queue*: mengeksekusi `4`, `5`, `6`, `3`. Microtask `6` mendaftarkan `6b`. Karena loop memprioritaskan Microtask Queue hingga benar-benar habis, `6b` langsung dieksekusi sebelum beralih ke Event Queue.
3. Microtask Queue kosong. Dart mengambil satu event dari *Event Queue*: `7`.
4. Dart memeriksa kembali Microtask Queue (kosong), lalu mengambil event berikutnya: `8`.
5. Event `9` dieksekusi. Callback `.then()` pada Dart dieksekusi secara sinkron jika Future sudah selesai, atau dijadwalkan sebagai microtask/callback langsung, menghasilkan eksekusi `10` sebelum event lain berjalan.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Loop Abstraction**: Di tingkat runtime C++ (Dart VM), event loop diimplementasikan di atas native I/O multiplexer seperti `epoll` (Linux/Android), `kqueue` (macOS/iOS), atau `IOCP` (Windows).
- **Non-blocking Native Worker**: Operasi asinkron (misalnya pembacaan file via `dart:io`) tidak memblokir Isolate. Dart VM mendelegasikan tugas I/O ke thread pool native sistem operasi (C++ worker thread). Ketika OS menyelesaikan pembacaan data, interrupt/sinyal dikirimkan kembali ke Dart VM, dan runtime menyuntikkan callback ke dalam **Event Queue** Isolate tersebut.

```
+--------------------------------------------------------+
|                      DART VM                           |
|                                                        |
|  +--------------------+           +-----------------+  |
|  |    Dart Isolate    |           |  Native Thread  |  |
|  |  (Single Threaded) |           |      Pool       |  |
|  |                    |           +-----------------+  |
|  |  Meminta Read File |                   |            |
|  |  ----------------> | Delegasi Native   |            |
|  |                    | ----------------> | (Blocking  |
|  |  Tetap berjalan /  |                   |  I/O call  |
|  |  handle event lain |                   |  ke OS)    |
|  |                    | Callback selesai  |            |
|  |  Event Queue <---- | <---------------- |            |
|  +--------------------+                                |
+--------------------------------------------------------+
```

#### Alokasi Memori / Resource
- Objek `Future` dan closure callback yang menyertainya adalah alokasi heap biasa yang tunduk pada garbage collection (Dart Generational GC: *Scavenge* untuk new space, *Mark-Sweep* untuk old space).
- Setiap closure menahan referensi konteks leksikal (*lexical scope*). Jika closure yang diantrekan memegang objek besar (seperti payload byte atau referensi UI state), memori tersebut tidak akan dapat dibersihkan GC hingga event callback selesai dieksekusi.

#### Trade-offs
- **Keuntungan**:
  - Nol biaya sinkronisasi (tidak ada deadlock, mutex starvation, memory barrier penalty).
  - Jejak memori isolate kecil, memungkinkan inisialisasi cepat.
- **Konsekuensi**:
  - Komputasi intensif CPU (seperti parsing JSON 50MB, enkripsi kriptografi, manipulasi gambar) yang berjalan di Call Stack akan memblokir siklus Event Loop. Akibatnya, I/O terhenti, UI frame rate anjlok (*jank*), dan timer mengalami deviasi (*latency drift*).

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Isolate Mandiri untuk Operasi CPU-Bound**: Gunakan `Isolate.run()` untuk memindahkan operasi komputasi berat keluar dari event loop utama UI.
  ```dart
  // Mengomputasi data besar tanpa memblokir Event Loop Isolate utama
  final processedData = await Isolate.run(() => heavyCpuTask(largePayload));
  ```
- **Pahami Kapan Menggunakan Microtask**: Batasi `scheduleMicrotask` hanya untuk menyelesaikan komputasi internal sebelum event berikutnya dirender (misalnya, menyelesaikan status internal state manager sebelum UI re-paint).
- **Manfaatkan Async/Await Secara Bertanggung Jawab**: Ingat bahwa `await` memecah fungsi menjadi dua bagian: kode sebelum `await` berjalan sinkron, dan kode setelah `await` diantrekan sebagai kelanjutan (*continuation*) task.

#### Don'ts
- **Menyebabkan Microtask Starvation**: Mengantrekan microtask secara rekursif atau berkepanjangan akan membuat Event Queue mati kelaparan (*event starvation*). Event interaksi user, rendering frame (pada Flutter), dan I/O tidak akan pernah diproses.
  ```dart
  // CONTOH KELIRU: Loop microtask yang memblokir Event Loop selamanya
  void starveEventLoop() {
    scheduleMicrotask(() {
      starveEventLoop(); // Event Queue tidak akan pernah dieksekusi!
    });
  }
  ```
- **Melakukan Operasi Sinkron I/O**: Hindari API pemblokir seperti `File.readAsStringSync()` pada Isolate utama jika aplikasi memiliki antarmuka interaktif atau menangani koneksi concurrent tinggi.

#### Edge Cases
- **Timer Resolution**: `Future.delayed(Duration(milliseconds: 10))` tidak menjamin callback dieksekusi tepat pada milidetik ke-10. Callback hanya akan masuk ke Event Queue setelah 10 milidetik; eksekusinya tetap harus menunggu Call Stack kosong dan Microtask Queue tuntas.
