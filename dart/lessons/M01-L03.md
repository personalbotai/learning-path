## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Null reference sering disebut oleh penemunya, Sir Tony Hoare, sebagai *"The Billion Dollar Mistake"*. Dalam runtime konvensional tanpa null safety, referensi apa pun dapat menunjuk ke alamat memori yang valid atau ke pointer `null`. Ketika program mencoba mengakses member dari pointer `null`, runtime melempar pengecualian fatal (seperti `NullPointerException` di Java atau `NoSuchMethodError: The getter 'x' was called on null` di Dart era legacy).

Dart mengatasi masalah ini secara radikal melalui **Sound Null Safety** yang diperkenalkan secara penuh pada Dart 2.12. Kata kuncinya adalah **"Sound"** (Kuat/Pasti). Sistem tipe Dart menjamin bahwa jika sebuah variabel dideklarasikan bertipe non-nullable (misalnya `int`), maka variabel tersebut **tidak akan pernah** bernilai `null` baik pada tahap static analysis (compile-time) maupun pada saat eksekusi (runtime).

```
                  [ Object? ]  <-- Top type nullable
                 /     |     \
            [Object] [Null]  ...
             /    \
        [String]  [int]        <-- Non-nullable types
             \    /
            [Never]            <-- Bottom type (unreachable / throws)
```

#### Re-arsitektur Type Hierarchy Dart
Sebelum null safety, `Null` adalah subtipe dari semua tipe data. Sekarang, Dart memecah hierarki tipe menjadi dua cabang terpisah:
1. **Non-nullable types (`T`)**: `Object`, `String`, `int`, custom classes. Tipe ini tidak memuat nilai `null`.
2. **Nullable types (`T?`)**: Union implisit antara `T` dan `Null`. `Object?` berada di puncak hierarki (Top Type), sedangkan `Never` berada di dasar terdalam hierarki (Bottom Type) yang merepresentasikan komputasi yang tidak pernah menghasilkan nilai (misalnya fungsi yang selalu melempar exception atau loop tak terbatas).

#### Flow Analysis
Compiler Dart dilengkapi dengan *Flow Analysis engine*. Engine ini melacak status setiap variabel lokal di sepanjang Control Flow Graph (CFG). Fitur utamanya meliputi:
- **Definite Assignment**: Mengetahui dengan pasti apakah suatu variabel telah diinisialisasi sebelum dibaca, terlepas dari branch code mana yang dieksekusi.
- **Type Promotion**: Mempromosikan tipe variabel lokal dari `T?` menjadi `T` secara otomatis setelah melewati guard clause (misalnya `if (x != null)`).

### 2. Implementasi & Contoh Kasus Nyata

Berikut implementasi idiomatik yang memperlihatkan interaksi antara non-nullable types, promotion, operator null-aware, dan keyword `late`.

```dart
// Model domain dengan null safety ketat
class UserProfile {
  final String id;
  final String username;
  final String? bio; // Nullable: bio bersifat opsional

  UserProfile({
    required this.id,
    required this.username,
    this.bio,
  });
}

class UserRepository {
  // 1. Lazy Initialization dengan 'late'
  // Variabel ini tidak dialokasikan/dihitung sampai pertama kali diakses.
  late final HeavyCacheEngine _cache = _initializeCache();

  HeavyCacheEngine _initializeCache() {
    print('Membuat instance HeavyCacheEngine yang memakan memori...');
    return HeavyCacheEngine();
  }

  // 2. Type Promotion & Definite Assignment
  String resolveUserBio(UserProfile user) {
    // Variable declaration tanpa inisialisasi awal
    String displayBio;

    if (user.bio != null) {
      // Flow Analysis melakukan Type Promotion: user.bio dipromosikan dari 'String?' ke 'String'
      displayBio = 'Bio: ${user.bio!.toUpperCase()}'; // '!' redundant di sini karena promotion
      displayBio = 'Bio: ${user.bio.toUpperCase()}';  // Idiomatik
    } else {
      displayBio = 'Bio tidak tersedia.';
    }

    // Compiler tahu pasti 'displayBio' terisi di semua branch (Definite Assignment)
    return displayBio;
  }

  // 3. Null-aware Operators & Short-circuiting
  int calculateBioLength(UserProfile? maybeUser) {
    // ?. (null-aware access) dan ?? (null-coalescing)
    return maybeUser?.bio?.trim().length ?? 0;
  }
}

class HeavyCacheEngine {
  final Map<String, dynamic> store = {};
}

void main() {
  final repo = UserRepository();

  final user1 = UserProfile(id: 'usr_01', username: 'alex', bio: 'Software Architect');
  final user2 = UserProfile(id: 'usr_02', username: 'bob');

  print(repo.resolveUserBio(user1)); // Output: Bio: SOFTWARE ARCHITECT
  print(repo.resolveUserBio(user2)); // Output: Bio tidak tersedia.

  // Cache Engine belum diinisialisasi hingga baris ini dipanggil
  print('Sebelum akses _cache');
  repo._cache.store['active'] = true; // _initializeCache() terpicu di sini
  print('Setelah akses _cache');
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
1. **Penghapusan Null Checks di AOT Compiler**:
   Dalam bahasa tanpa sound null safety, setiap invokasi method (misal `obj.doSomething()`) membutuhkan instruksi CPU tambahan untuk mengecek apakah `obj == 0x0` sebelum melakukan jump instruksi, guna mencegah crash level OS (Segmentation Fault). Dalam Dart AOT, jika compiler melihat parameter `T` (non-nullable), compiler **sama sekali tidak meng-generate instruksi pengecekan null** di tingkat assembly. Hasilnya: binary lebih kecil dan throughput eksekusi melonjak signifikan.
2. **Devirtualization**:
   Ketika compiler yakin bahwa sebuah target pemanggilan metode tidak mungkin `null`, compiler dapat melakukan direct jump atau bahkan inline kode tersebut tanpa harus melalui Virtual Method Table (vtable) lookup untuk fallback pengecekan `Null.noSuchMethod`.

#### Mekanisme `late` Keyword
Keyword `late` memiliki dua implementasi internal berbeda tergantung konteksnya:
- **`late` tanpa initializer (`late T x;`)**:
  Compiler membuat field backing store dan sebuah flag/sentinel implisit. Saat variabel diakses, runtime melakukan micro-check:
  ```c++
  // Pseudocode implementasi C++ Dart VM
  if (this->field_x == kLateInitializationSentinel) {
    ThrowLateInitializationError("Field 'x' has not been initialized.");
  }
  return this->field_x;
  ```
- **`late` dengan initializer (`late T x = expr;`)**:
  Compiler mentransformasi field ini menjadi getter dengan pola caching/singleton implisit. Ekspresi `expr` hanya dievaluasi sekali, disimpan, dan untuk panggilan berikutnya sentinel menandakan bahwa value sudah siap.

#### Trade-offs
- **Memori Overhead pada `late`**: Variabel `late` non-nullable di Dart VM membutuhkan alokasi memori implisit untuk tracking sentinel state guna memastikan variabel tidak dibaca sebelum diisi.
- **Compile-time Cost**: Flow analysis mengharuskan compiler melakukan traversal graph yang lebih lambat selama fase parsing AST (Abstract Syntax Tree), meningkatkan waktu kompilasi demi efisiensi runtime.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan guard clause sedini mungkin**:
  ```dart
  void handleEvent(String? payload) {
    if (payload == null) return;
    // 'payload' otomatis terpromosi menjadi 'String' di bawah baris ini
    print(payload.length);
  }
  ```
- **Manfaatkan local variable copy untuk field class**:
  Flow analysis Dart **tidak bisa** mempromosikan getter class publik secara otomatis, karena getter bisa saja di-override oleh subclass atau dimutasi oleh thread/event loop lain. Solusinya, salin ke variabel lokal:
  ```dart
  class Manager {
    String? token;

    void execute() {
      final localToken = token; // Copy reference
      if (localToken != null) {
        // localToken terpromosi, sedangkan 'token' tidak
        sendRequest(localToken);
      }
    }
    void sendRequest(String t) {}
  }
  ```

#### Don'ts
- **Hindari overuse Assertion Operator (`!`)**:
  Operator `!` (bang operator) mematikan proteksi static analysis dan memaksa runtime check. Menggunakan `!` menandakan developer berasumsi nilai tidak null, yang jika meleset akan melempar unhandled exception `Null check operator used on a null value`.
- **Jangan gunakan `late` hanya untuk menghindari constructor**:
  Menggunakan `late` untuk menunda inisialisasi class member yang seharusnya bisa dioper via constructor adalah anti-pattern. Hal ini memindahkan potensi compile-time error menjadi runtime crash.

#### Edge Cases & Pitfalls
- **Race Condition pada `late` Async Initialization**:
  Jika mengakses lazy `late` variable dalam method asynchronous secara konkuren sebelum inisialisasi pertama selesai, inisialisasi ganda dapat terjadi secara tak terduga jika proses tersebut melibatkan side-effect.
- **Nullable Generic Constraints**:
  Perhatikan bahwa parameter generik `<T>` secara default adalah `<T extends Object?>` (nullable). Jika Anda ingin parameter generik wajib non-nullable, Anda harus mengekspresikannya secara eksplisit: `<T extends Object>`.

### 5. Tantangan Eksplorasi Mandiri

1. **Analisis Dekompilasi Flow Analysis**:
   Buat class dengan getter publik `String? get name`. Buat method yang melakukan check `if (name != null)`. Perhatikan compiler error ketika Anda mencoba memanggil `name.length`. Ubah kode menggunakan teknik local variable caching atau `late final`, dan jelaskan mengapa compiler Dart menolak mempromosikan property accessor (getter) publik secara default.
2. **Eksperimen Boundary Error pada `late`**:
   Tulis program yang mendeklarasikan `late int counter;`. Coba buat sebuah control flow di mana counter dibaca di dalam blok `try-catch` sebelum diinisialisasi. Tangkap exception-nya, cetak tipe error spesifiknya (`LateInitializationError`), lalu cari tahu bagaimana Dart VM merepresentasikan state "belum terinisialisasi" secara internal.
