## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Di dalam ekosistem asinkron Dart, `Stream` adalah urutan data asinkron (*asynchronous sequence of data*). Jika `Future` merepresentasikan komputasi yang menghasilkan nilai tunggal di masa depan, maka `Stream` merepresentasikan pipa data kontinu yang dapat memancarkan nol, satu, atau banyak nilai secara berurutan, hingga akhirnya ditutup (*done*) atau gagal (*error*).

Dart membagi `Stream` ke dalam dua kategori arsitektural fundamental berdasarkan model konsumsi datanya:

```
                      +-------------------+
                      |    Stream<T>      |
                      +---------+---------+
                                |
        +-----------------------+-----------------------+
        |                                               |
        v                                               v
+-------------------------------+       +-------------------------------+
|  Single-Subscription Stream   |       |       Broadcast Stream        |
+-------------------------------+       +-------------------------------+
| - Tepat 1 listener seumur hidup|      | - 0, 1, atau banyak listener  |
| - Buffer otomatis jika belum  |       | - Event hilang jika tidak ada |
|   ada listener aktif          |       |   listener (Fire-and-Forget)  |
| - Menjaga integritas urutan   |       | - Listener bebas masuk/keluar |
| - Cocok untuk I/O, File, HTTP |       | - Cocok untuk UI Events, Bus  |
+-------------------------------+       +-------------------------------+
```

#### A. Single-Subscription Streams
Secara *default*, stream di Dart bersifat *single-subscription*. Karakteristik utamanya:
- **Strict Point-to-Point**: Hanya memperbolehkan **satu** `StreamSubscription` sepanjang siklus hidupnya. Jika Anda mencoba memanggil `.listen()` untuk kedua kalinya—bahkan setelah subscription pertama dibatalkan—runtime akan melempar `StateError: Bad state: Stream has already been listened to`.
- **Integrity & Buffering**: Dirancang untuk skenario di mana integritas data dan urutan (*ordering*) sangat krusial. Jika event dipancarkan sebelum ada listener yang terdaftar, controller akan menahan (*buffer*) event tersebut sampai listener aktif mendengarkan.
- **Use Cases**: Membaca file (`File.openRead()`), streaming respons HTTP, parsing dokumen JSON/CSV berukuran gigabyte.

#### B. Broadcast Streams
Karakteristik utamanya:
- **Publish-Subscribe (Pub/Sub)**: Mengizinkan sejumlah listener independen untuk mendengarkan event yang sama secara bersamaan.
- **No Inherent Buffering**: Mengadopsi mekanisme *fire-and-forget*. Jika sebuah event dipancarkan saat tidak ada listener yang aktif, event tersebut langsung dibuang (*discarded*). Listener baru hanya menerima event yang dipancarkan **setelah** mereka berlangganan.
- **Independent Lifecycle**: Masing-masing listener dapat melakukan `pause`, `resume`, atau `cancel` tanpa memengaruhi aliran data ke listener lainnya.
- **Use Cases**: Event klik tombol di UI, koneksi WebSocket multi-consumer, Event Bus sistem, notifikasi perubahan status sensor (GPS, accelerometer).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah perbandingan konkret antara *Single-Subscription Stream*, *Broadcast Stream*, dan konversi menggunakan `.asBroadcastStream()`.

```dart
import 'dart:async';

void main() async {
  print('=== 1. DEMO: SINGLE-SUBSCRIPTION STREAM ===');
  await singleSubscriptionDemo();

  print('\n=== 2. DEMO: BROADCAST STREAM ===');
  await broadcastDemo();

  print('\n=== 3. DEMO: CONVERSION (.asBroadcastStream) ===');
  await conversionDemo();
}

/// Mensimulasikan pembacaan file I/O (Single-Subscription)
Future<void> singleSubscriptionDemo() async {
  final controller = StreamController<String>();

  // Memancarkan data
  controller.add('Chunk 1: Metadata');
  controller.add('Chunk 2: Payload');
  controller.close();

  // Listener Pertama: Mengonsumsi data
  final subscription1 = controller.stream.listen(
    (chunk) => print('[Single] Listener 1 menerima: $chunk'),
    onDone: () => print('[Single] Listener 1 selesai.'),
  );

  await subscription1.asFuture();

  // Mencoba mendaftarkan listener kedua pada Stream yang sama
  try {
    controller.stream.listen((chunk) => print('[Single] Listener 2: $chunk'));
  } catch (e) {
    print('[Single] Error tertangkap: $e'); // Menghasilkan StateError
  }
}

/// Mensimulasikan Event Bus / UI Click Bus (Broadcast)
Future<void> broadcastDemo() async {
  // Membuat controller broadcast secara eksplisit
  final broadcastController = StreamController<String>.broadcast();

  // Event ini akan hilang karena belum ada listener
  broadcastController.add('Event 0: Dibuang (Tanpa Listener)');

  // Listener Pertama bergabung
  final sub1 = broadcastController.stream.listen(
    (event) => print('[Broadcast] Sub 1 menerima: $event'),
  );

  broadcastController.add('Event 1: Notifikasi User Login');

  // Listener Kedua bergabung belakangan
  final sub2 = broadcastController.stream.listen(
    (event) => print('[Broadcast] Sub 2 menerima: $event'),
  );

  broadcastController.add('Event 2: Data Sinkronisasi Selesai');

  // Batalkan subscription secara individual
  await sub1.cancel();
  print('[Broadcast] Sub 1 berhenti mendengarkan.');

  // Sub 2 masih menerima data
  broadcastController.add('Event 3: Ping UI');

  await sub2.cancel();
  await broadcastController.close();
}

/// Mengubah Single-Subscription menjadi Broadcast Stream
Future<void> conversionDemo() async {
  // Stream single-subscription berbasis interval
  final singleStream = Stream<int>.periodic(
    const Duration(milliseconds: 100),
    (count) => count,
  ).take(4);

  // Dikonversi ke broadcast stream
  // onListen dan onCancel dapat digunakan untuk mengontrol sumber data asli
  final broadcastStream = singleStream.asBroadcastStream(
    onListen: (subscription) => print('[Transform] Pipa upstream dibuka'),
    onCancel: (subscription) => print('[Transform] Pipa upstream ditutup'),
  );

  final subA = broadcastStream.listen((val) => print('[Transform] Sub A: $val'));
  
  // Beri delay sebelum Sub B bergabung
  await Future.delayed(const Duration(milliseconds: 150));
  final subB = broadcastStream.listen((val) => print('[Transform] Sub B: $val'));

  // Tunggu stream selesai
  await Future.delayed(const Duration(milliseconds: 350));
  await subA.cancel();
  await subB.cancel();
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### A. Eksekusi & Runtime Dispatch
Di Dart VM, controller stream diimplementasikan melalui class internal seperti `_AsyncStreamController` dan `_SyncStreamController`.

1. **Microtask Queue Scheduling**:
   Secara default, pemanggilan `controller.add(data)` tidak mengeksekusi handler listener secara sinkron (*synchronous*). Runtime Dart memasukkan pemanggilan callback listener ke dalam **Microtask Queue**. Ini mencegah *re-entrancy bugs* dan memastikan eksekusi kode sinkron saat ini selesai sebelum event berikutnya diproses:
   ```
   [Event Loop] -> [Microtask Queue: execute listener(event)] -> [Call Stack]
   ```
2. **Subscription Ring vs Single Pointer**:
   - Pada **Single-Subscription**, controller menyimpan referensi langsung ke satu instans internal `_BufferingStreamSubscription`. State stream dilindungi oleh *flag bitwise* internal (`_STATE_SUBSCRIBED`). Jika bit ini sudah aktif saat `listen()` dipanggil, runtime langsung melempar `StateError`.
   - Pada **Broadcast Stream**, controller mengelola *doubly-linked list* atau array internal yang berisi banyak pointer listener (`_BroadcastSubscription`). Saat `.add()` dipanggil, runtime mengiterasi pointer-pointer tersebut dan menjadwalkan notifikasi ke masing-masing listener.

#### B. Alokasi Memori & Buffering Trade-offs
- **Single-Subscription Buffer Risk**:
  Jika data ditambahkan terus-menerus ke `StreamController` sebelum ada yang mendengarkan, atau listener memanggil `subscription.pause()`, data akan ditumpuk di dalam antrean memori internal (`_PendingEvents`). Jika produser menghasilkan data lebih cepat daripada yang dikonsumsi (tanpa mekanisme *backpressure* manual), alokasi memori heap akan melonjak secara eksponensial hingga terjadi *Out Of Memory* (OOM).
- **Broadcast Zero-Retention**:
  Broadcast stream tidak mengalokasikan buffer retensi untuk event yang terlewat. Jika list subscriber kosong (`subscriptions.isEmpty`), payload langsung diabaikan dan dibiarkan untuk dibersihkan oleh Garbage Collector (GC).

#### C. Lifecycle Mapping `.asBroadcastStream()`
Metode `.asBroadcastStream()` membungkus Single-Subscription stream asli di dalam perantara broadcast. Penting untuk dipahami: **Stream dasarnya tetap bersifat single-subscription**.
- Wrapper ini mendengarkan stream asli hanya ketika ada *setidaknya satu* listener broadcast aktif.
- Jika semua listener broadcast membatalkan subscription (`onCancel`), wrapper dapat membatalkan subscription ke stream asli. Jika ada listener baru masuk setelahnya, stream asli tidak dapat di-*listen* kembali kecuali wrapper dikonfigurasi secara eksplisit untuk tidak membatalkan upstream subscription.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Selalu Simpan dan Cancel `StreamSubscription`**: Dalam aplikasi Flutter atau Dart server, langganan stream yang tidak dibatalkan ketika objek mati (misal: widget di-*dispose*) akan menahan referensi objek tersebut di memori (*memory leak*).
  ```dart
  // Simpan referensi dan batalkan
  final subscription = stream.listen(handler);
  // ... saat teardown:
  await subscription.cancel();
  ```
- **Gunakan Broadcast untuk Event, Single untuk Data Pipeling**: Gunakan Broadcast Stream untuk UI gesture atau status koneksi socket. Gunakan Single-Subscription untuk transmisi berkas, dekompresi data, atau request-response network pipeline.
- **Tutup StreamController**: Selalu panggil `await controller.close()` ketika produser data sudah selesai memancarkan nilai untuk memicu event `onDone` pada semua listener.

#### Don'ts
- **Jangan Mengasumsikan Broadcast Menyimpan Nilai Terakhir (Replay)**: Broadcast stream murni tidak menyimpan *state* saat ini. Jika Anda butuh nilai terakhir saat subscriber baru masuk, gunakan implementasi `ValueNotifier`, `BehaviorSubject` (dari package `rxdart`), atau buat cache manual.
- **Jangan Menjadikan Controller `sync: true` Kecuali Terpaksa**:
  ```dart
  // HATI-HATI
  final controller = StreamController<T>(sync: true);
  ```
  `sync: true` memotong antrean Microtask dan langsung memanggil callback listener saat `add()` dieksekusi. Ini melanggar isolasi konkurensi Dart dan dapat memicu *race condition* atau *infinite recursive loops*.

#### Edge Cases & Pitfalls
- **Membaca Stream Menggunakan `await for`**:
  Looping `await for (final data in stream)` membuat single-subscription listener di balik layar. Jika loop tersebut diinterupsi oleh `break` atau `return`, subscription akan dibatalkan secara otomatis (`cancel()`). Mencoba mengakses stream itu lagi setelahnya akan gagal.
- **Error Propagation**: Pada Broadcast stream, jika sebuah error dimasukkan melalui `addError()`, **semua** listener harus memiliki handler `onError`. Jika salah satu listener tidak menangani error tersebut, runtime akan melempar *uncaught exception* ke level zone/isolate global.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi BehaviorSubject Sederhana**:
   Buatlah sebuah class wrapper di atas `StreamController.broadcast()` bernama `CurrentValueSubject<T>` yang menyimpan nilai terakhir (`latestValue`). Setiap kali listener baru mendaftar melalui method kustom atau ekstensi, subscriber tersebut harus langsung menerima `latestValue` secara sinkron/mikrotask sebelum menerima update event berikutnya.
2. **Deteksi Memory Leak pada Pause Backpressure**:
   Buat sebuah `StreamController` single-subscription, panggil `controller.pause()` pada subscription-nya, lalu gunakan `Timer.periodic` untuk memompa objek berukuran besar (`Uint8List(1024 * 1024)`) ke controller tersebut. Amati konsumsi memori Dart VM via Dart DevTools Memory Profiler untuk membuktikan penumpukan buffer pada antrean internal subscription. Modifikasi kodenya agar produser berhenti memompa saat controller sedang di-*pause*.
