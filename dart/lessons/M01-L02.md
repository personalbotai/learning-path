## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dart adalah bahasa pemrograman dengan sistem pengetikan statis (*statically typed*) yang didukung oleh **Sound Null Safety** dan **Type Inference** (inferensi tipe) yang kuat. Meskipun Anda tidak menuliskan tipe data secara eksplisit, *analyzer* Dart dapat menyimpulkan tipe data pada saat kompilasi (*compile-time*). 

Secara arsitektur, **semua hal di Dart adalah Object**, termasuk angka (`int`, `double`), fungsi, dan `null`. Semuanya mewarisi dari kelas dasar `Object?`. Tidak ada tipe primitif murni seperti di Java (`int` vs `Integer`); namun, Dart VM (Virtual Machine) dan kompilator AOT (Ahead-of-Time) sangat pintar dalam mengoptimalkan objek-objek ini di level memori agar secepat tipe primitif.

Tiga pilar utama dalam deklarasi variabel di Dart:
1.  **`var`**: Membiarkan kompilator menyimpulkan tipe data. Sekali disimpulkan, tipenya terkunci (tidak bisa diubah seperti di JavaScript).
2.  **`final`**: Variabel yang nilainya hanya bisa diinisialisasi **satu kali**. Nilainya dapat dievaluasi pada saat *runtime* (saat program berjalan).
3.  **`const`**: Variabel yang nilainya harus diketahui secara pasti pada saat **waktu kompilasi (*compile-time*)**. `const` bersifat *deeply immutable* (sepenuhnya tidak bisa diubah).

### 2. Implementasi & Contoh Kasus Nyata

```dart
void main() {
  // 1. Type Inference dengan 'var'
  // Dart tahu ini adalah String. Tipe terkunci, tidak bisa diisi angka setelahnya.
  var username = 'engineer_01'; 
  
  // 2. Explicit Typing (Built-in Types)
  // Digunakan jika tipe data tidak langsung terlihat jelas atau untuk properti kelas.
  int maxRetries = 3;
  double cpuTemperature = 45.5;
  bool isConnected = true;
  
  // 3. final vs const
  // 'final' dievaluasi saat runtime. DateTime.now() tidak diketahui saat kompilasi.
  final DateTime sessionStart = DateTime.now();
  
  // 'const' dievaluasi saat compile-time. Nilainya harus absolut.
  const double pi = 3.14159;
  
  // 4. Koleksi (Built-in Types: List, Set, Map)
  // Menggunakan type inference untuk koleksi
  var endpoints = ['/api/v1/users', '/api/v1/posts']; // Disimpulkan sebagai List<String>
  
  // Perbedaan krusial final vs const pada koleksi:
  final List<String> mutableList = ['A', 'B'];
  mutableList.add('C'); // BERHASIL: Referensi 'mutableList' final, tapi isinya bisa diubah.
  
  const List<String> immutableList = ['X', 'Y'];
  // immutableList.add('Z'); // ERROR RUNTIME: Cannot add to an unmodifiable list.

  // 5. Runes & Symbol (Advanced Built-in Types)
  // Runes digunakan untuk merepresentasikan Unicode code points (misal: Emoji)
  var heart = '\u2665'; 
  
  print('User $username connected at $sessionStart');
}
```

**Penjelasan:**
- Penggunaan `var` sangat dianjurkan untuk variabel lokal (di dalam fungsi) sesuai dengan panduan *Effective Dart*, karena mengurangi *boilerplate* tanpa mengorbankan *type safety*.
- `final` digunakan untuk state yang tidak berubah setelah diinisialisasi, sangat umum digunakan dalam pembuatan *Widget* di Flutter.
- `const` digunakan untuk nilai statis, konfigurasi, atau *Widget* yang tidak pernah berubah, menghemat memori secara signifikan.

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: 
  - Saat Anda menggunakan `const`, Dart menggunakan pola *Flyweight*. Jika Anda membuat beberapa variabel `const` dengan nilai yang sama persis, Dart VM tidak akan membuat objek baru di memori. Ia akan melakukan **Kanonikalisasi (*Canonicalization*)**, menunjuk semua variabel tersebut ke satu instans memori yang sama.
  - Variabel `final` diimplementasikan sebagai *single-assignment variable*. Di level *bytecode*, instruksi *setter* untuk variabel ini dihilangkan setelah inisialisasi pertama.
- **Alokasi Memori / Resource**: 
  - Objek `const` dialokasikan di area memori khusus yang bersifat *read-only* saat aplikasi dimuat. Ini membuat *garbage collector* (GC) tidak perlu memindai objek `const`, sehingga performa aplikasi (terutama Flutter) meningkat drastis.
  - Tipe bawaan seperti `int` dan `double` (keduanya turunan dari `num`) secara konseptual dialokasikan di *heap*. Namun, kompilator Dart (baik JIT maupun AOT) melakukan *unboxing* di balik layar pada arsitektur 64-bit, menyimpannya di dalam register CPU langsung untuk operasi matematika berkinerja tinggi.
- **Trade-offs**: 
  - Menggunakan `dynamic` (menonaktifkan *type checking*) akan memaksa Dart VM menggunakan *dynamic dispatch* (mencari method/properti saat runtime). Ini sangat lambat dan memakan lebih banyak memori dibandingkan pemanggilan statis.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan `var` untuk variabel lokal jika tipe datanya sudah jelas dari nilai inisialisasinya (contoh: `var name = 'Budi';`).
  - Jadikan variabel `final` sebagai *default mindset* Anda. Jika sebuah variabel tidak perlu diubah nilainya, jadikan `final`. Ini mencegah *bug* mutasi state yang tidak disengaja.
  - Gunakan `const` sebanyak mungkin, terutama untuk konstruktor kelas dan koleksi data statis.
- **Don'ts**:
  - Jangan gunakan `dynamic` kecuali Anda benar-benar berurusan dengan data yang strukturnya tidak diketahui (seperti *parsing* JSON mentah). Gunakan `Object?` jika Anda hanya butuh tipe yang bisa menampung apa saja tapi tetap aman (*type-safe*).
  - Jangan menuliskan tipe data secara eksplisit jika Anda sudah menggunakan `var` atau jika tipe sudah sangat jelas (contoh buruk: `String name = 'Budi';` di dalam fungsi lokal).
- **Edge Cases**:
  - **Late Initialization**: Jika Anda memiliki variabel `final` yang nilainya baru diketahui nanti (misal dari hasil *fetch* API), tetapi Anda tidak ingin membuatnya *nullable* (`?`), gunakan *keyword* `late final`. Namun hati-hati, mengakses variabel `late` sebelum diinisialisasi akan memicu *runtime exception* (LateInitializationError).

### 5. Tantangan Eksplorasi Mandiri

1. Buatlah sebuah program Dart yang menerima data JSON (simulasikan dengan `Map<String, dynamic>`). Ekstrak nilai-nilai di dalamnya ke dalam variabel-variabel bertipe statis yang kuat (Strongly Typed) menggunakan `final`. Tangani kasus di mana tipe data dari JSON mungkin tidak sesuai ekspektasi.
2. Buatlah sebuah kelas dengan konstruktor `const`. Instansiasi kelas tersebut dua kali dengan nilai parameter yang sama persis menggunakan *keyword* `const`. Gunakan fungsi `identical(obj1, obj2)` untuk membuktikan bahwa keduanya menunjuk ke alamat memori yang sama persis (Kanonikalisasi).
3. Eksplorasi tipe data `Runes`. Cobalah memanipulasi sebuah *String* yang berisi kombinasi huruf latin dan emoji kompleks (seperti emoji keluarga 👨‍👩‍👧‍👦), lalu hitung panjang karakternya menggunakan `.length` biasa versus `.runes.length`. Analisis mengapa hasilnya berbeda.
