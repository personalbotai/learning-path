## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam ekosistem Dart dan Flutter, persistensi data lokal sangat krusial untuk membangun aplikasi *offline-first*, *caching* respons API, dan menyimpan preferensi pengguna. Memilih solusi penyimpanan yang tepat bergantung pada kompleksitas data dan kebutuhan performa.

*   **SharedPreferences**: Merupakan *wrapper* asinkron untuk penyimpanan *key-value* bawaan platform (`NSUserDefaults` di iOS/macOS, `SharedPreferences` di Android). Arsitekturnya sangat sederhana, menyimpan data primitif (int, double, bool, string, List<String>) dalam format XML atau JSON di level OS. Tidak dirancang untuk menyimpan data terstruktur yang besar atau melakukan *query*.
*   **Hive**: Database NoSQL *key-value* murni berbasis Dart. Hive sangat cepat karena menggunakan arsitektur *memory-mapped files* dan menyimpan data dalam format biner (menggunakan *TypeAdapters*). Secara *default*, Hive memuat seluruh data ke dalam RAM (kecuali menggunakan `LazyBox`), membuatnya sangat cepat untuk operasi *read*, namun memakan memori jika dataset terlalu besar.
*   **Isar Database**: Evolusi dari Hive (dibuat oleh kreator yang sama), Isar adalah database NoSQL yang sangat dioptimalkan, mendukung relasi, indeks, dan *full-text search*. Arsitekturnya menggunakan **Rust** di *backend* dan berkomunikasi dengan Dart melalui **FFI (Foreign Function Interface)**. Isar sepenuhnya *ACID compliant*, *thread-safe* (mendukung multi-isolate), dan menggunakan arsitektur *zero-copy serialization* yang meminimalisir beban *Garbage Collector* (GC) di Dart.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern untuk ketiga teknologi tersebut, disesuaikan dengan *use-case* idealnya.

```dart
import 'package:shared_preferences/shared_preferences.pering.dart';
import 'package:hive/hive.dart';
import 'package:isar/isar.dart';

// ==========================================
// 1. SharedPreferences: Untuk Preferensi UI
// ==========================================
class ThemePreference {
  static const _key = 'isDarkMode';

  Future<void> setDarkMode(bool value) async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.setBool(_key, value);
  }

  Future<bool> getDarkMode() async {
    final prefs = await SharedPreferences.getInstance();
    return prefs.getBool(_key) ?? false; // Default false
  }
}

// ==========================================
// 2. Hive: Untuk Caching Sederhana (Key-Value)
// ==========================================
// Membutuhkan hive_generator untuk TypeAdapter
@HiveType(typeId: 0)
class UserCache extends HiveObject {
  @HiveField(0)
  late String id;

  @HiveField(1)
  late String token;
}

class HiveService {
  static Future<void> initAndSaveToken(String id, String token) async {
    // Asumsi Hive.init() sudah dipanggil di main()
    Hive.registerAdapter(UserCacheAdapter()); // Hasil generate
    
    final box = await Hive.openBox<UserCache>('userBox');
    
    final user = UserCache()
      ..id = id
      ..token = token;
      
    await box.put('currentUser', user); // Upsert data
  }
}

// ==========================================
// 3. Isar: Untuk Data Relasional & Query Kompleks
// ==========================================
// Membutuhkan isar_generator
@collection
class Product {
  Id id = Isar.autoIncrement; // ID otomatis (64-bit integer)

  @Index(type: IndexType.value) // Indeks untuk pencarian cepat
  late String name;

  late double price;

  @Index(type: IndexType.words) // Indeks untuk Full-Text Search
  late String description;
}

class IsarService {
  late Isar isar;

  Future<void> init() async {
    // Membuka instance Isar, schema di-generate oleh build_runner
    isar = await Isar.open([ProductSchema]);
  }

  Future<void> addProducts(List<Product> products) async {
    // Operasi write harus berada di dalam transaksi (writeTxn)
    await isar.writeTxn(() async {
      await isar.products.putAll(products);
    });
  }

  Future<List<Product>> searchProducts(String keyword) async {
    // Query kompleks: Full-text search dan filter harga
    return await isar.products.filter()
        .descriptionWordsAnyStartsWith(keyword)
        .and()
        .priceGreaterThan(10.0)
        .sortByPriceDesc()
        .limit(20)
        .findAll();
  }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**:
  - **SharedPreferences**: Memanggil API *native* melalui *MethodChannel* (sebelum versi terbaru yang mulai menggunakan FFI). Operasi I/O terjadi di *native thread*, namun proses serialisasi/deserialisasi JSON/XML terjadi di Dart *thread*, yang dapat menyebabkan *UI jank* jika datanya besar.
  - **Hive**: Menggunakan *append-only log*. Setiap operasi `put` akan menambahkan baris baru di akhir file biner. Jika sebuah *key* di-update berkali-kali, file akan membengkak. Hive menangani ini dengan proses *compaction* otomatis di *background* untuk membersihkan data usang.
  - **Isar**: Berjalan di atas *Rust core*. Saat Dart memanggil *query* Isar, ia mengirimkan pointer memori via FFI. Rust mengeksekusi *query* menggunakan struktur data B-Tree yang sangat efisien, lalu mengembalikan pointer ke Dart.
- **Alokasi Memori / Resource**:
  - **Hive**: Box standar memuat semua *key* dan *value* ke dalam RAM Dart. Ini membuat pembacaan O(1) secara instan, namun berisiko *Out of Memory* (OOM) pada dataset masif.
  - **Isar**: Menggunakan *Zero-copy serialization*. Data tidak diduplikasi antara Rust dan Dart. Objek Dart hanya dibuat (dialokasikan di *heap*) saat data benar-benar diakses dari hasil *query*, sangat menghemat beban *Garbage Collector*.
- **Trade-offs**:
  - SharedPreferences: Mudah digunakan, tapi lambat dan tidak terstruktur.
  - Hive: Sangat cepat untuk *read/write* sederhana, tapi tidak mendukung *query* kompleks dan relasi.
  - Isar: Fitur sangat kaya dan performa tinggi, namun menambah ukuran *binary* aplikasi (karena *library* Rust yang di-compile) dan membutuhkan *code generation*.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan **SharedPreferences** *hanya* untuk data primitif yang sangat kecil (misal: status *onboarding*, tema aplikasi).
  - Gunakan **Isar** jika aplikasi Anda membutuhkan fitur *offline-first*, pencarian data, filter kompleks, atau memiliki lebih dari 10.000 *records*.
  - Selalu bungkus operasi *write* Isar dalam `writeTxn` (transaksi) untuk memastikan integritas data (ACID) dan performa *batch insert*.
- **Don'ts**:
  - **Jangan** menyimpan JSON *string* berukuran besar (misal: *response* API 5MB) ke dalam SharedPreferences. Ini akan memblokir *thread* saat proses *parsing*.
  - **Jangan** menggunakan Hive standar untuk menyimpan ratusan ribu data. Gunakan `LazyBox` di Hive atau beralih ke Isar untuk menghindari lonjakan penggunaan RAM.
- **Edge Cases**:
  - **Migrasi Skema**: Saat struktur model berubah (misal menambah kolom baru), Isar menangani penambahan kolom secara otomatis, namun perubahan tipe data memerlukan migrasi manual.
  - **Multi-Isolate**: Jika Anda melakukan *background processing* (misal via `compute`), Hive standar bisa mengalami *race condition*. Isar secara *native* mendukung akses dari berbagai *isolate* secara bersamaan.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Isar Full-Text Search**: Buat aplikasi pencatatan (*Notes App*) sederhana menggunakan Isar. Implementasikan fitur pencarian *real-time* yang mencari kata spesifik di dalam judul dan isi catatan menggunakan indeks `IndexType.words`.
2. **Hive Custom TypeAdapter**: Cobalah menyimpan objek Dart yang kompleks (misalnya objek yang memiliki properti `DateTime` dan `Enum`) ke dalam Hive dengan menulis `TypeAdapter` secara manual tanpa menggunakan `hive_generator`.
3. **Benchmarking**: Buat *script* Dart sederhana yang melakukan *insert* 100.000 data *dummy* secara *batch*. Bandingkan waktu eksekusi dan penggunaan memori antara Hive (`putAll`) dan Isar (`putAll` di dalam `writeTxn`).
