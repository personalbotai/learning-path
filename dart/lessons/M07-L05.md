## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Secara default, Dart mengeksekusi kode dalam model *single-threaded* yang dikelola oleh sebuah **Event Loop**. Model ini sangat efisien untuk operasi I/O (seperti *network request* atau *file reading*) karena menggunakan *asynchronous non-blocking*. Namun, ketika aplikasi dihadapkan pada komputasi berat (CPU-bound) seperti *parsing* JSON berukuran masif, enkripsi, atau pemrosesan gambar, Event Loop akan terblokir. Hal ini menyebabkan *frame drop* (jank) pada UI atau *latency* tinggi pada server.

Untuk mengatasi ini, Dart menggunakan konsep **Isolate**. Berbeda dengan *Thread* pada Java atau C++, Isolate mengimplementasikan **Actor Model**. 
*   **Tidak ada Shared Memory:** Setiap Isolate memiliki *memory heap*, *garbage collector*, dan *event loop* sendiri.
*   **Message Passing:** Isolates berkomunikasi secara eksklusif dengan mengirim pesan melalui `SendPort` dan `ReceivePort`.
*   **Thread-Safe by Design:** Karena memori tidak dibagikan, Dart terhindar dari masalah konkurensi klasik seperti *race conditions*, *deadlocks*, dan kebutuhan akan *mutex/locks*.

### 2. Implementasi & Contoh Kasus Nyata

Sejak Dart 2.19, pendekatan modern untuk *compute offloading* sangat disederhanakan dengan `Isolate.run()`. Untuk *background task* yang berjalan terus-menerus (long-lived), kita menggunakan `Isolate.spawn()`.

```dart
import 'dart:async';
import 'dart:convert';
import 'dart:isolate';

// ---------------------------------------------------------
// Kasus 1: One-off Heavy Compute (Pendekatan Modern)
// ---------------------------------------------------------

// Fungsi komputasi berat (harus top-level atau static)
Map<String, dynamic> _parseMassiveJson(String jsonString) {
  // Simulasi komputasi berat (misal parsing JSON 50MB)
  return jsonDecode(jsonString);
}

Future<void> runOneOffTask() async {
  String massiveJson = '{"data": "very large payload...", "id": 1}';
  
  // Isolate.run akan membuat isolate baru, menjalankan fungsi, 
  // mengembalikan hasil, dan langsung mematikan isolate tersebut.
  final result = await Isolate.run(() => _parseMassiveJson(massiveJson));
  print('One-off Task Selesai: ${result['id']}');
}

// ---------------------------------------------------------
// Kasus 2: Long-lived Background Worker (Pendekatan Tradisional)
// ---------------------------------------------------------

// Entry point untuk Isolate pekerja
void _workerIsolate(SendPort mainSendPort) {
  // Port untuk menerima pesan dari Main Isolate
  final workerReceivePort = ReceivePort();
  
  // Kirim SendPort milik worker ke Main Isolate agar bisa saling komunikasi
  mainSendPort.send(workerReceivePort.sendPort);

  // Dengarkan tugas yang masuk
  workerReceivePort.listen((message) {
    if (message is String) {
      // Proses komputasi berat
      final reversed = message.split('').reversed.join('');
      mainSendPort.send(reversed); // Kirim hasil kembali
    } else if (message == 'KILL') {
      workerReceivePort.close();
    }
  });
}

Future<void> runLongLivedWorker() async {
  final mainReceivePort = ReceivePort();
  
  // Spawn isolate baru
  final isolate = await Isolate.spawn(_workerIsolate, mainReceivePort.sendPort);
  
  SendPort? workerSendPort;
  final completer = Completer<void>();

  mainReceivePort.listen((message) {
    if (message is SendPort) {
      // Menerima SendPort dari worker
      workerSendPort = message;
      workerSendPort?.send("Hello Dart Isolates"); // Kirim tugas
    } else if (message is String) {
      print('Hasil dari Worker: $message');
      workerSendPort?.send('KILL'); // Hentikan worker
      mainReceivePort.close();
      isolate.kill();
      completer.complete();
    }
  });

  await completer.future;
}

void main() async {
  print('--- Memulai One-off Task ---');
  await runOneOffTask();
  
  print('\n--- Memulai Long-lived Worker ---');
  await runLongLivedWorker();
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: Saat `Isolate.spawn` dipanggil, Dart VM meminta OS untuk mengalokasikan *thread* baru (atau mengambil dari *thread pool* internal VM). VM kemudian menginisialisasi *Isolate structure* baru yang berisi Event Loop dan Call Stack yang sepenuhnya terisolasi dari *main thread*.
- **Alokasi Memori / Resource**: Karena tidak ada *shared memory*, pesan yang dikirim melalui `SendPort` secara default akan di-**copy** (disalin) ke *heap* milik Isolate penerima. Proses *copying* ini memakan waktu $O(n)$. Jika Anda mengirim list berisi 1 juta integer, Dart akan menyalin 1 juta integer tersebut.
- **Trade-offs**: 
  - *Startup Latency*: Membuat Isolate baru membutuhkan waktu (sekitar beberapa milidetik) dan memori dasar (sekitar 2-3 MB per Isolate).
  - *Zero-Copy Transfer*: Untuk menghindari biaya *copying* pada data biner besar (seperti pemrosesan gambar), Dart menyediakan `TransferableTypedData`. Data ini tidak disalin, melainkan kepemilikan memorinya (pointer) dipindahkan dari satu Isolate ke Isolate lain.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan `Isolate.run()` untuk tugas CPU-bound yang hanya berjalan sekali (seperti *parsing* JSON, kompresi file).
  - Gunakan `TransferableTypedData` jika Anda perlu memindahkan data biner berukuran besar (misal: `Uint8List` dari file gambar) antar Isolate.
  - Pertahankan jumlah Isolate yang hidup (long-lived) seminimal mungkin, idealnya tidak melebihi jumlah *core* CPU fisik perangkat.
- **Don'ts**:
  - **JANGAN** menggunakan Isolate untuk operasi I/O (Network HTTP calls, File Read/Write). Operasi I/O sudah *non-blocking* di Dart. Menggunakan Isolate untuk I/O hanya akan membuang memori tanpa memberikan keuntungan performa.
  - Jangan mengirim objek kompleks yang berisi *closures* (fungsi) atau *native resources* (seperti *file handles* atau *sockets*) melalui `SendPort`. Dart tidak bisa men-serialisasi fungsi.
- **Edge Cases**:
  - *Closure Capture*: Saat menggunakan `Isolate.run()`, pastikan *closure* yang Anda berikan tidak secara tidak sengaja menangkap (capture) variabel dari *scope* luar yang tidak bisa dikirim lintas Isolate (misalnya objek `BuildContext` di Flutter atau koneksi database).

### 5. Tantangan Eksplorasi Mandiri

1. **Benchmarking Overhead**: Buatlah skrip yang membandingkan waktu eksekusi *parsing* JSON berukuran 10MB menggunakan tiga metode: di *Main Thread*, menggunakan `Isolate.run()`, dan menggunakan *Long-lived Isolate*. Amati *overhead* waktu pembuatan Isolate pada `Isolate.run()`.
2. **Zero-Copy Implementation**: Modifikasi contoh kode di atas untuk membaca file gambar menjadi `Uint8List`, lalu ubah menjadi `TransferableTypedData`, kirim ke Isolate pekerja untuk dimanipulasi (misal: invert warna), dan kembalikan ke *Main Isolate* tanpa proses *copying*.
3. **Isolate Pool**: Rancang sebuah class `IsolatePool` sederhana yang melakukan *spawn* pada 3 Isolate saat aplikasi berjalan, dan mendistribusikan tugas-tugas komputasi berat secara *round-robin* ke ketiga Isolate tersebut menggunakan `SendPort`.
