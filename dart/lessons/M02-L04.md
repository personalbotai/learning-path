## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam paradigma OOP pada Dart, **Inheritance** (pewarisan) memungkinkan sebuah *class* (subclass/derived class) mengadopsi struktur state (field) dan behavior (method/getter/setter) dari *class* lain (superclass/base class) menggunakan *keyword* `extends`. Dart menganut model **Single Inheritance**—sebuah class hanya dapat mewarisi langsung dari satu superclass. Semua class di Dart (kecuali `Null`) secara implisit merupakan turunan dari class `Object`.

```
        [ Object ]
            ▲
            │ extends
      [ BaseEntity ]
            ▲
            │ extends
      [ UserEntity ]
```

#### Alasan Keberadaan & Mekanisme Compiler
Inheritance memfasilitasi prinsip polimorfisme subtipikal (*subtyping polymorphism*), yang menyatakan bahwa instansi dari subclass dapat digunakan di mana pun tipe superclass diharapkan (Liskov Substitution Principle).

Ketika subclass mendefinisikan ulang implementasi method yang sudah ada di superclass, proses ini disebut **Method Overriding**. Anotasi `@override` adalah metadata deklaratif tingkat compiler (disediakan oleh `dart:core`). 

Secara teknis compiler:
1. **Verifikasi Statis:** Compiler memeriksa apakah signature (nama method, return type, jumlah, dan tipe parameter) pada method bertanda `@override` benar-benar cocok dengan member yang ada di rantai prototipe superclass. Jika tidak ditemukan (misal ada *typo* pada nama method), kompilasi akan langsung gagal (*compile-time error*).
2. **Subtype Covariance & Contravariance:** Dart menerapkan aturan *sound typing*. Return type pada method override boleh bersifat *covariant* (spesialisasi turunan dari return type superclass), sedangkan tipe parameter tidak boleh dipersempit sembarangan tanpa deklarasi eksplisit (*contravariance/covariance* rules).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah contoh sistem gateway notifikasi backend/service yang memanfaatkan inheritance dan method overriding secara terstruktur.

```dart
// base_notification_service.dart
abstract class NotificationPayload {
  final String recipient;
  final String content;

  const NotificationPayload({
    required this.recipient,
    required this.content,
  });
}

class EmailPayload extends NotificationPayload {
  final String subject;

  const EmailPayload({
    required super.recipient,
    required super.content,
    required this.subject,
  });
}

/// Base Service: Mendefinisikan kontrak dan alur template eksekusi
abstract class NotificationService {
  final bool isSandbox;

  const NotificationService({this.isSandbox = false});

  // Base behavior yang diharapkan dapat dioverride atau dipanggil via super
  Future<bool> send(NotificationPayload payload) async {
    _logAudit(payload);
    if (isSandbox) {
      print('[SANDBOX] Suppressing real dispatch to ${payload.recipient}');
      return true;
    }
    return false; // Menandakan pengiriman nyata harus ditangani subclass
  }

  void _logAudit(NotificationPayload payload) {
    print('[AUDIT] Dispatch initialized for: ${payload.recipient}');
  }
}

/// Specialized Subclass: Email Dispatcher
class EmailNotificationService extends NotificationService {
  final String smtpServer;

  // Inisialisasi constructor superclass melalui constructor initializer list
  EmailNotificationService({
    required this.smtpServer,
    super.isSandbox,
  });

  // Method overriding eksplisit dengan anotasi @override
  @override
  Future<bool> send(covariant EmailPayload payload) async {
    // 1. Menjalankan logika dasar superclass menggunakan keyword 'super'
    final wasHandledByBase = await super.send(payload);
    if (wasHandledByBase) {
      return true;
    }

    // 2. Eksekusi logika spesifik milik subclass
    print('Connecting to SMTP Server: $smtpServer');
    print('Sending Email Subject: "${payload.subject}" to ${payload.recipient}');
    
    // Simulasi network I/O
    await Future<void>.delayed(const Duration(milliseconds: 100));
    print('Email successfully dispatched.');
    return true;
  }
}

void main() async {
  final NotificationService mailer = EmailNotificationService(
    smtpServer: 'smtp.mailgun.org',
    isSandbox: false,
  );

  final emailData = EmailPayload(
    recipient: 'engineer@company.internal',
    subject: 'Production Deployment Notice',
    content: 'Release v2.4.0 is live.',
  );

  // Dynamic dispatch dieksekusi di runtime
  final success = await mailer.send(emailData);
  print('Result status: $success');
}
```

#### Analisis Kode Kunci:
- `super.isSandbox`: *Super parameter syntax* (mulai Dart 2.17) menyederhanakan *forwarding argument* langsung ke konstruktor superclass tanpa boiler-plate initializer.
- `await super.send(payload)`: Subclass mempertahankan perilaku penting dari superclass (seperti logging dan audit) sebelum memperluas fungsionalitasnya sendiri.
- `covariant EmailPayload payload`: Mengizinkan *narrowing type* (penyempitan tipe) dari `NotificationPayload` menjadi `EmailPayload` secara eksplisit, divalidasi oleh compiler dan runtime.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Virtual Method Table (vtable) & Inline Caching
- **VTable (Virtual Table):** Di lingkungan AOT (Ahead-of-Time) compiler Dart, tiap class memiliki representasi struktur data internal berupa tabel pointer fungsi (*vtable*). Ketika subclass meng-override method, slot pointer untuk method tersebut pada vtable milik subclass diarahkan ke alamat memori instruksi baru, bukan lagi ke instruksi milik superclass.
- **Dynamic Dispatch:** Pemanggilan `mailer.send()` tidak dikompilasi menjadi lompatan memori langsung (*direct jump/call*) ke alamat fungsi statis. Sebaliknya, Dart runtime memeriksa *type tag* dari instansi `mailer`, membuka vtable instansi tersebut, lalu melompat ke alamat fungsi yang sesuai.
- **Inline Caching (IC):** Untuk meminimalkan *overhead* resolusi vtable, Dart VM menggunakan teknik *Monomorphic* dan *Polymorphic Inline Caching*. Jika suatu call-site selalu memanggil tipe konkret yang sama (misal selalu `EmailNotificationService`), instruksi call langsung di-*patch* di CPU cache untuk melompati pembacaan vtable secara penuh.

#### Alokasi Memori / Resource
- Di level Heap, instansi subclass dialokasikan sebagai satu blok memori contiguous (berurutan).
- Blok ini diawali oleh **Object Header** (berisi informasi Garbage Collector, tag tipe, dan pointer ke informasi class), diikuti oleh variabel instansi milik superclass, dan diakhiri oleh variabel instansi milik subclass.
- Instance variables dari superclass tidak disimpan di tempat terpisah; subclass adalah satu objek utuh yang mencakup ukuran memori akumulatif dari semua rantai inheritance-nya.

#### Trade-offs
- **Abstraksi vs Call Overhead:** Dynamic dispatch membawa penalti performa mikro dibanding pemanggilan statis/inlined (meskipun Inline Caching memitigasinya hingga mendekati performa direct call).
- **Fragile Base Class Problem:** Modifikasi internal pada superclass berisiko merusak invariansi perilaku di subclass secara tidak terduga tanpa memicu compile-time error jika kontraknya tidak dirancang secara ketat.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Selalu Pasang `@override`:** Jadikan anotasi `@override` kewajiban mutlak. Ini mencegah bug laten ketika nama method superclass direfaktor tetapi subclass tertinggal (tanpa `@override`, method di subclass akan dianggap sebagai method baru, bukan override).
- **Patuhi Liskov Substitution Principle (LSP):** Subclass tidak boleh memperketat prakondisi (misalnya melempar Exception tak terduga pada argumen yang valid di superclass) atau melemahkan pascakondisi.
- **Gunakan Composition di atas Deep Inheritance:** Jika hubungan antar entitas adalah *"has-a"* bukan *"is-a"*, hindari `extends`. Batasi kedalaman inheritance tree maksimal 2-3 tingkat untuk menjaga *maintainability*.

#### Don'ts
- **Jangan Mengabaikan Kontrak Signature:** Mengubah parameter opsional menjadi parameter wajib saat meng-override method akan merusak polimorfisme kode pemanggil dan memicu compile error.
- **Hindari Memanggil Method Virtual di dalam Constructor:**
  ```dart
  class Base {
    Base() {
      init(); // BAHAYA: Jika subclass meng-override init(), state subclass belum siap!
    }
    void init() {}
  }
  ```
  Di Dart, konstruktor superclass dieksekusi sebelum body konstruktor subclass selesai. Memanggil method virtual di base constructor dapat menyebabkan akses state subclass yang masih bernilai `null` atau belum terinisialisasi.

#### Edge Cases
- **Field Overriding:** Di Dart, sebuah *field* implisit menghasilkan getter dan setter. Maka dari itu, Anda dapat meng-override field dengan getter/setter atau sebaliknya:
  ```dart
  class Parent {
    final String id = 'DEFAULT';
  }
  class Child extends Parent {
    @override
    String get id => fetchDynamicId(); // Sah secara sintaks Dart
  }
  ```
- **Covariant Keyword Edge-case:** Menggunakan `covariant` pada parameter memindahkan pengecekan tipe dari static compile-time checking ke dynamic type check di runtime. Jika tipe yang dikirim tidak kompatibel di runtime, aplikasi akan crash dengan `TypeError`.

### 5. Tantangan Eksplorasi Mandiri

1. **Investigasi Urutan Eksekusi Inisialisasi:**
   Buat class `Parent` dan `Child`. Definisikan *Initializer List*, *Field Initializer inline*, dan *Constructor Body* pada kedua class dengan instruksi `print`. Petakan urutan eksekusi presisi dari instansiasi `Child` hingga selesai. Di fase mana variabel milik superclass dialokasikan dibanding milik subclass?
2. **Eksplorasi Runtime Type Safety:**
   Buat superclass `Storage` dengan method `void save(Object data)`. Buat subclass `SecureStorage` yang meng-override method menjadi `void save(covariant String data)`. Upcast instance `SecureStorage` ke variabel bertipe `Storage`, lalu teruskan parameter bernilai integer (`12345`). Amati bagaimana runtime VM bereaksi dan analisis mengapa compiler meloloskan kode tersebut.
