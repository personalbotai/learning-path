## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam paradigma berorientasi objek Dart, proses instansiasi bukan sekadar memanggil fungsi dan mengalokasikan memori acak. Dart memiliki sistem *sound null-safety* dan aturan imutabilitas ketat yang mengharuskan variabel bertipe `final` dan *non-nullable* terinisialisasi sepenuhnya **sebelum** konstruktor objek dianggap selesai dan referensi `this` terekspos. Di sinilah **Initializer Lists** dan **Redirecting Constructors** memainkan peran arsitektural krusial.

#### Siklus Hidup Konstruksi Objek (Phase Lifecycle)
Ketika konstruktor generatif dipanggil, Dart mengeksekusi tahapan berikut secara berurutan:
1. **Binding Parameter Formal**: Argumen dimasukkan ke dalam parameter (termasuk *initializing formals* seperti `this.field`).
2. **Initializer List**: Dieksekusi dari kiri ke kanan. Tahap ini mengevaluasi ekspresi inisialisasi *field*, validasi berbasis `assert`, atau kalkulasi nilai turunan.
3. **Superclass Constructor Initialization**: Pemanggilan konstruktor *super-class* (baik implisit `super()` tanpa argumen maupun eksplisit `: super(...)`).
4. **Constructor Body (`{ ... }`)**: Kode di dalam kurung kurawal dieksekusi. Hanya pada fase ini referensi `this` aman diakses secara penuh.

```
[ Parameter Binding ]
         │
         ▼
[ Initializer List (Field Assignment & Asserts) ]  <-- `this` BELUM VALID
         │
         ▼
[ Superclass Constructor Execution ]
         │
         ▼
[ Constructor Body Execution { ... } ]             <-- `this` VALID & AMAN
```

#### Initializer Lists
Initializer list adalah blok ekspresi yang diletakkan di antara tanda titik dua (`:`) dan kurung kurawal pembuka (`{`) pada konstruktor. Initializer list menyelesaikan tiga masalah fundamental:
* Menginisialisasi *field* `final` yang nilainya membutuhkan komputasi dari parameter, tanpa mengorbankan status `final`.
* Menjalankan `assert` sebelum objek dialokasikan sepenuhnya untuk menghentikan instansiasi *invalid* sedini mungkin (*fail-fast*).
* Menjaga keamanan kompilasi (*compile-time safety*): Dart melarang akses ke `this` di dalam initializer list agar state objek yang "setengah jadi" tidak bocor ke fungsi luar (*anti-leakage guarantee*).

#### Redirecting Constructors
Sering kali suatu kelas memiliki beberapa konstruktor dengan variasi parameter, namun memproses logika akhir yang identik. Alih-alih menduplikasi logika inisialisasi, sebuah konstruktor dapat mengalihkan (*redirect*) panggilannya ke konstruktor lain di kelas yang sama menggunakan sintaks `: this(...)` atau `: this.named(...)`.
Konstruktor yang dialihkan ini **tidak boleh memiliki body (`{}`)**, menjadikannya murni sebuah gerbang delegasi parameter.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi entitas `NetworkEndpoint` yang memvalidasi URL, mem-parsing skema/port, dan menggunakan *redirecting constructors* untuk menyediakan berbagai pintu masuk API yang aman dan teruji.

```dart
class NetworkEndpoint {
  final String host;
  final int port;
  final String scheme;
  final String rawUri;
  final bool isSecure;

  // 1. Primary Constructor dengan Initializer List
  // Mengkalkulasi nilai dependensi dan memvalidasi invarian sebelum field final dikunci.
  NetworkEndpoint({
    required this.host,
    this.port = 443,
    String? scheme,
  })  : assert(host.isNotEmpty, 'Host tidak boleh kosong'),
        assert(port > 0 && port <= 65535, 'Port harus berada di rentang 1-65535'),
        scheme = scheme ?? (port == 443 ? 'https' : 'http'),
        isSecure = (scheme == 'https' || (scheme == null && port == 443)),
        rawUri = '${scheme ?? (port == 443 ? 'https' : 'http')}://$host:$port' {
    // Body dijalankan setelah seluruh final fields terinisialisasi
    // Pada titik ini, 'this' sudah aman digunakan sepenuhnya.
  }

  // 2. Redirecting Constructor: Delegasi dari String mentah
  // Meneruskan parsing awal ke static helper, lalu me-redirect ke konstruktor utama.
  NetworkEndpoint.fromString(String uriString)
      : this._fromParsedUri(Uri.parse(uriString));

  // 3. Private Redirecting Constructor: Jembatan perantara
  // Mencegah duplikasi mapping dari instance Uri ke field individual.
  NetworkEndpoint._fromParsedUri(Uri uri)
      : this(
          host: uri.host,
          port: uri.hasPort ? uri.port : (uri.scheme == 'https' ? 443 : 80),
          scheme: uri.scheme.isEmpty ? null : uri.scheme,
        );

  // 4. Redirecting Named Constructor untuk Kasus Khusus (Localhost Development)
  NetworkEndpoint.localhost([int port = 8080])
      : this(
          host: '127.0.0.1',
          port: port,
          scheme: 'http',
        );

  @override
  String toString() => 'Endpoint($rawUri, Secure: $isSecure)';
}

void main() {
  // Menggunakan konstruktor utama
  final apiProduction = NetworkEndpoint(host: 'api.enterprise.com');
  print(apiProduction); // Endpoint(https://api.enterprise.com:443, Secure: true)

  // Menggunakan redirecting constructor dari string
  final apiStaging = NetworkEndpoint.fromString('https://staging.internal:8443');
  print(apiStaging); // Endpoint(https://staging.internal:8443, Secure: true)

  // Menggunakan redirecting constructor localhost
  final apiDev = NetworkEndpoint.localhost();
  print(apiDev); // Endpoint(http://127.0.0.1:8080, Secure: false)
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (Desugaring & Inlining)
- **Common Front End (CFE) Compiling**: Saat kode Dart dikompilasi ke Kernel AST (representasi perantara Dart), *redirecting generative constructors* tidak membuat *stack frame* baru di runtime. Kompiler melakukan *desugaring* dan me-redirect pemanggilan langsung ke instruksi konstruktor target.
- **Inisialisasi Field**: *Field initializers* dan *initializer list* diubah oleh CFE menjadi serangkaian operasi *store* ke dalam memori *heap* sebelum memanggil instruksi `super()`.
- **Eksekusi Assert**: Statement `assert(...)` di dalam initializer list dikompilasi secara kondisional. Pada mode *Release* (AOT Compilation), seluruh ekspresi assert di-strip dari *binary*, mengeliminasi *overhead* performa runtime tanpa sisa instruksi mesin.

#### Alokasi Memori & Mutabilitas
- Objek dialokasikan dalam *new generation heap* (Dart GC berbasis *generational scraping*).
- Karena *field* bertipe `final`, lokasi memori untuk field-field tersebut langsung diisi nilainya pada alokasi awal. Begitu konstruktor selesai, pointer objek ditandai sebagai referensi valid. 
- Larangan akses `this` pada Initializer List mencegah **Object Escape Analysis Failure**: jika `this` diizinkan lewat fungsi callback sebelum *field final* diinisialisasi, thread/fungsi lain dapat membaca *uninitialized/garbage pointer*, merusak jaminan *sound null-safety*.

#### Trade-offs
- **Keterbatasan Kontrol Alur**: Initializer list adalah kumpulan ekspresi (*expressions*), bukan pernyataan (*statements*). Anda tidak bisa menyisipkan blok `if-else`, `try-catch`, atau perulangan `for`. Jika kalkulasi kompleks dibutuhkan, Anda terpaksa mengekstraknya ke fungsi `static` terpisah.
- **Overhead Static Helpers**: Mengekstrak kalkulasi ke static helper untuk initializer list dapat menghasilkan pemanggilan fungsi berulang jika satu nilai bergantung pada hasil kalkulasi nilai lainnya, kecuali dikelola via konstruktor privat perantara.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Validasi Segera dengan Assert**: Letakkan `assert` di posisi teratas initializer list. Jika input korup, eksekusi gagal sebelum superclass mengalokasikan resource turunan.
- **Gunakan Private Constructors sebagai Perantara Delegasi**: Saat mengurai objek kompleks (seperti JSON atau Uri), gunakan kombinasi `factory` atau redirecting constructor privat (misal: `ClassName._(...)`) agar pemrosesan tidak bercampur dengan penetapan field.
- **Manfaatkan Inisialisasi Berantai**: Tetapkan nilai default konseptual hanya pada SATU konstruktor utama (biasanya *generative default constructor*), dan arahkan semua variasi konstruktor lain ke sana menggunakan *redirecting constructor*.

#### Don'ts
- **Jangan Memanggil Instance Method di Initializer List**: Anda tidak bisa memanggil `this.hitungNilai()` di initializer list. Jadikan fungsi tersebut `static` jika perlu dipanggil saat fase inisialisasi.
- **Jangan Menduplikasi Inisialisasi**: Hindari membuat dua konstruktor berbeda yang masing-masing menetapkan 10 *field* identik secara manual. Gunakan redirection.
- **Jangan Menyematkan Body pada Redirecting Constructor**: Konstruktor yang memiliki sintaks `: this(...)` dilarang memiliki body kurung kurawal `{ ... }`. Penambahan body akan memicu *compile-time error*.

#### Edge Cases
- **Super vs Redirection Incompatibility**: Sebuah konstruktor tidak bisa memanggil `super(...)` dan `this(...)` secara bersamaan. Redirection hanya mendelegasikan ke konstruktor sekelas; pemanggilan `super(...)` didelegasikan ke konstruktor target akhir.
- **Circular Redirection**: Jika Constructor A mengarah ke Constructor B, dan Constructor B mengarah ke Constructor A, CFE akan mendeteksi *compile-time cycle error* (`Redirecting constructors can't form a cycle`).
