### 1. Konsep & Arsitektur Mendalam

Di dalam Dart, manipulasi state koleksi (*collection*) yang tidak terkontrol merupakan salah satu sumber utama *state corruption*, terutama saat data dibagi ke berbagai lapisan arsitektur (misalnya: domain model yang diakses oleh UI layer atau service layer). Dart menyediakan mekanisme immutability dan traversal data menggunakan dua pilar utama: **Unmodifiable Collections** dan **Iterable/Iterator Pattern**.

```
[ In-Memory Collection Strategy ]
├── Compile-time Const : Canonicalized, Read-Only Data Segment (rodata)
├── List.unmodifiable  : Heap Copy (O(N)), Fixed-length, Mutator Throws UnsupportedError
└── UnmodifiableListView: Heap Wrapper (O(1)), View to Backing List, Zero-Copy
```

#### A. Spektrum Immutability pada Koleksi Dart
Dart tidak memiliki tipe statis terpisah seperti `ImmutableList<E>` pada level type system inti; interface yang diekspos tetap berupa `List<E>`, `Set<E>`, atau `Map<K, V>`. Namun, perilaku mutasi diatur secara dinamis pada saat runtime:

1. **`const [...]` (Compile-time Canonicalized Collection)**:
   Objek dialokasikan sekali oleh compiler pada memory snapshot/rodata segment. Objek dengan identitas dan data yang sama persis akan menggunakan pointer yang identik (*canonicalized*). Setiap upaya mutasi (seperti `.add()`) akan melempar `UnsupportedError`.
2. **`List.unmodifiable(Iterable elements)`**:
   Melakukan *shallow copy* dari elemen-elemen iterable ke dalam *fixed-length array* baru di heap, lalu mengunci seluruh API mutator (`add`, `[]=`, `clear`, dll.) agar melempar `UnsupportedError`.
3. **`UnmodifiableListView<E>` (Proxy / View Pattern via `dart:collection`)**:
   Tidak melakukan alokasi array baru. Class ini membungkus (*wrap*) koleksi target yang sudah ada secara *zero-copy*. Semua operasi baca didelegasikan langsung ke koleksi target, sedangkan semua mutasi diintersepsi dan dibatalkan dengan melempar `UnsupportedError`. Namun, jika koleksi internal yang dibungkus berubah, perubahan tersebut akan terefleksi di view ini.

#### B. Anatomi Built-in Iterator & Iterable
Dart mengadopsi model **Pull-Based Iteration**:
- **`Iterable<E>`**: Abstraksi tingkat tinggi yang merepresentasikan sekumpulan elemen berurutan yang dapat diakses secara sekuensial. `Iterable` bersifat deklaratif dan mendukung *lazy evaluation* (evaluasi lambat).
- **`Iterator<E>`**: Kursor imperatif level rendah yang mempertahankan pointer/state traversing saat ini. Kontrak kerjanya bertumpu pada getter `current` dan method `moveNext()`.

Saat Anda menulis rantai transformasi seperti `.where().map()`, Dart **tidak** mengalokasikan array penampung sementara. Sebaliknya, Dart menyusun rantai wrapper objek (misalnya `WhereIterable` membungkus `MappedIterable`) yang hanya akan menarik (*pull*) data satu per satu ketika consumer meminta elemen (misalnya saat loop `for-in` dipanggil atau dieksekusi via `.toList()`).

### 2. Implementasi & Contoh Kasus Nyata

Kode di bawah menunjukkan implementasi enkapsulasi state pada entitas domain menggunakan variasi unmodifiable collections, serta eksplorasi internal dari `Iterable` dan `Iterator`.

```dart
import 'dart:collection';

class OrderItem {
  final String id;
  final double price;

  OrderItem(this.id, this.price);

  @override
  String toString() => 'OrderItem($id, \$$price)';
}

class OrderState {
  // 1. Private mutable state di dalam class
  final List<OrderItem> _items = [];

  // 2. Ekspos via UnmodifiableListView: Zero-copy, mencegah modifikasi dari luar
  // Perubahan internal pada _items akan langsung terefleksi di getter ini.
  UnmodifiableListView<OrderItem> get items => UnmodifiableListView(_items);

  // 3. Ekspos via List.unmodifiable: Snapshot independen (Shallow copy)
  // Perubahan internal pada _items TIDAK akan mempengaruhi snapshot ini.
  List<OrderItem> get itemsSnapshot => List.unmodifiable(_items);

  void addItem(OrderItem item) {
    _items.add(item);
  }
}

void main() {
  final order = OrderState();
  order.addItem(OrderItem('item-1', 150.0));
  order.addItem(OrderItem('item-2', 50.0));

  final viewList = order.items;
  final snapshotList = order.itemsSnapshot;

  print('Initial View Size: ${viewList.length}'); // 2
  print('Initial Snapshot Size: ${snapshotList.length}'); // 2

  // Menambah item baru ke dalam aggregate root
  order.addItem(OrderItem('item-3', 200.0));

  print('Updated View Size: ${viewList.length}'); // 3 (Mengikuti perubahan target)
  print('Updated Snapshot Size: ${snapshotList.length}'); // 2 (Tetap pada state lama)

  // Mencoba mutasi ilegal pada UnmodifiableListView
  try {
    viewList.add(OrderItem('item-hacker', 0.0));
  } on UnsupportedError catch (e) {
    print('Safety Triggered: $e'); // Cannot add to an unmodifiable list
  }

  // --- DEMO BUILT-IN ITERABLE & ITERATOR UNDER THE HOOD ---
  print('\n=== Evaluasi Lazy Iterable vs Iterator ===');

  final prices = [100.0, 250.0, 50.0, 400.0, 30.0];

  // Pipeline pemrosesan lazily-evaluated (Belum dieksekusi di memori)
  final highValuePricedTaxes = prices
      .where((price) {
        print('Filtering: $price');
        return price > 80.0;
      })
      .map((price) {
        print('Mapping Tax: $price');
        return price * 1.11;
      });

  print('Pipeline didefinisikan. Pemrosesan belum berjalan.');

  // Traversal manual menggunakan kontrak dasar Iterator<E>
  final Iterator<double> iterator = highValuePricedTaxes.iterator;

  print('Mulai mengonsumsi via iterator manual:');
  while (iterator.moveNext()) {
    // Pipeline dieksekusi per-elemen on-demand
    print('Consuming Current Value: ${iterator.current.toStringAsFixed(2)}');
    break; // Hanya mengonsumsi 1 item pertama; sisa pipeline tidak diproses!
  }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Absennya Immutable Interface Statis**: Compiler Dart (AOT maupun JIT) mengizinkan invokasi method `add()`, `remove()`, atau `operator[]=` pada referensi bertipe `List<E>`, meskipun instansiasi aktual di heap adalah `UnmodifiableListView` atau fixed-length copy. Validasi dilakukan via *dynamic runtime check* di dalam method implementasi koleksi tersebut yang secara eksplisit mengeksekusi:
  ```dart
  void add(E value) {
    throw UnsupportedError("Cannot add to an unmodifiable list");
  }
  ```
- **State Machine pada Iterator**: Rantai `.where().map()` menghasilkan objek internal seperti `WhereIterable` dan `MappedIterable`. Ketika `iterator` dipanggil, rantai ini menghasilkan `WhereIterator` yang membungkus `MappedIterator`. `moveNext()` bekerja seperti pipeline coroutine: ia memanggil `moveNext()` milik parent, mengevaluasi predikat boolean, dan menghentikan traversing tepat saat elemen berikutnya valid ditemukan.

#### Alokasi Memori / Resource
- **`UnmodifiableListView` vs `List.unmodifiable`**:
  - `UnmodifiableListView`: Memori yang dialokasikan hanyalah satu instance wrapper object kecil yang memegang pointer referensi ke backing list asli. Kompleksitas memori: $\mathcal{O}(1)$.
  - `List.unmodifiable`: Mengalokasikan array baru di memori dan menyalin setiap referensi pointer elemen dari iterable sumber. Kompleksitas memori dan waktu: $\mathcal{O}(N)$.
- **Const Canonicalization**: Koleksi `const` disimpan di read-only data segment pada snapshot VM. Alokasi memori adalah $\mathcal{O}(1)$ terlepas dari berapa kali instansiasi literal tersebut dieksekusi di runtime.

#### Trade-offs
| Pendekatan | Kecepatan Alokasi | Keamanan State Internal | Memory Footprint |
| :--- | :--- | :--- | :--- |
| `UnmodifiableListView` | $\mathcal{O}(1)$ | Rentan jika internal list bermutasi saat dibaca | Sangat Rendah |
| `List.unmodifiable` | $\mathcal{O}(N)$ | Sangat Aman (Deep snapshot isolatif) | Tinggi (Duplikasi pointer) |
| `const [...]` | Instant (Compile time) | Mutlak (Immutable fisik) | Nol di Runtime Heap |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `UnmodifiableListView` untuk Encapsulation**: Selalu gunakan `UnmodifiableListView` saat mengekspos internal koleksi privat dari sebuah class/service demi mencegah caller memodifikasi state secara diam-diam.
- **Rantai Operasi Iterable secara Lazy**: Manfaatkan sifat *lazy* dari `where`, `map`, `take`, dan `skip` untuk pemrosesan dataset besar bertingkat.
- **Materialisasi Tepat Waktu**: Panggil `.toList()` atau `.toSet()` hanya saat Anda membutuhkan *caching* hasil eksekusi, operasi pengurutan (`sort`), atau pengindeksan acak (`list[index]`).

#### Don'ts
- **Jangan Mengira `Unmodifiable` adalah Deeply Immutable**: `UnmodifiableListView` dan `List.unmodifiable` hanya mengunci referensi array (*shallow unmodifiable*). Jika elemen di dalamnya adalah objek mutable (misal: objek `User`), atribut di dalam `User` tersebut masih dapat diubah:
  ```dart
  unmodifiableUsers[0].name = "Changed"; // Berhasil, objek di dalamnya tetap mutable!
  ```
- **Hindari Re-evaluasi Berulang pada Lazy Iterables**: Jangan memanggil properti berulang pada iterable lazy tanpa mematerialisasikannya:
  ```dart
  final filtered = rawData.where((e) => expensiveCompute(e));
  if (filtered.isNotEmpty) { // expensiveCompute dieksekusi
    print(filtered.first);   // expensiveCompute dieksekusi ULANG
  }
  ```
- **Hindari Mutasi Koleksi Asli Selama Iterasi View**: Mengubah target list asli ketika sebuah loop sedang berjalan di atas `UnmodifiableListView` akan memicu runtime crash: `ConcurrentModificationError`.

#### Edge Cases
- **Akses `iterator.current` Ilegal**:
  Mengakses `iterator.current` sebelum pemanggilan `moveNext()` pertama kali bernilai `true`, atau setelah `moveNext()` mengembalikan `false`, menghasilkan perilaku *undefined* (bergantung pada implementasi iterator spesifik, bisa mengembalikan elemen stale terakhir atau melempar runtime exception).

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Custom `Iterable` & `Iterator`**:
   Buat class bernama `FibonacciIterable` yang mengimplementasikan `Iterable<int>` tanpa batas (*infinite stream*) menggunakan implementasi `Iterator<int>` manual dengan state machine internal. Gunakan operator `.take(10)` untuk mengonsumsi 10 bilangan pertama.
2. **Memory Overhead Benchmark**:
   Gunakan profil memori atau jalankan profiling sederhana pada list berisi 1.000.000 integer: bandingkan konsumsi memori dan kecepatan eksekusi antara `List.unmodifiable(source)` vs `UnmodifiableListView(source)`.
3. **Deep Immutability Layer**:
   Rancang sebuah wrapper generic `DeepImmutableList<T>` yang mencegah mutasi terhadap koleksi itu sendiri serta memastikan method pemutasi pada elemen individual tidak dapat dipanggil dari luar (gunakan abstraksi readonly interface).
