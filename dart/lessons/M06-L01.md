## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dart adalah bahasa pemrograman *single-threaded* secara default. Setiap program Dart berjalan di dalam sebuah **Isolate** (ruang memori terisolasi dengan *thread* tunggal). Karena hanya memiliki satu *thread*, Dart tidak dapat mengeksekusi dua baris kode secara bersamaan. Untuk menangani operasi asinkron (seperti I/O, *network request*, atau *timer*) tanpa memblokir eksekusi utama, Dart menggunakan arsitektur **Event Loop**.

Event Loop di Dart mengelola dua antrean (*queues*) utama:
1. **Microtask Queue**: Digunakan untuk tugas-tugas asinkron internal yang sangat singkat dan harus dieksekusi sesegera mungkin setelah kode sinkron selesai, tetapi sebelum *event* eksternal diproses.
2. **Event Queue**: Digunakan untuk *event* eksternal seperti I/O, *timer*, *drawing events* (di Flutter), dan eksekusi `Future` standar.

**Aturan Emas Eksekusi Event Loop Dart:**
1. Eksekusi semua kode sinkron (fungsi `main`).
2. Periksa **Microtask Queue**. Jika ada, eksekusi *semua* microtask sampai antrean kosong. (Jika sebuah microtask menjadwalkan microtask baru, ia akan dieksekusi di fase ini juga).
3. Periksa **Event Queue**. Ambil **satu** *event*, lalu eksekusi.
4. Kembali ke langkah 2 (Periksa Microtask Queue lagi).

Arsitektur ini memastikan bahwa operasi UI atau I/O (Event Queue) tidak akan diproses jika masih ada status internal yang perlu diselesaikan segera (Microtask Queue).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah kode yang mendemonstrasikan urutan eksekusi antara kode sinkron, Microtask, dan Event Queue.

```dart
import 'dart:async';

void main() {
  print('1. Kode Sinkron: Mulai main()');

  // Menjadwalkan ke Event Queue
  Timer.run(() {
    print('2. Event Queue: Timer.run dieksekusi');
  });

  // Menjadwalkan ke Event Queue
  Future(() {
    print('3. Event Queue: Future standar dieksekusi');
  }).then((_) {
    // Callback 'then' dari Future standar dieksekusi sebagai Microtask 
    // SETELAH Future tersebut selesai.
    print('4. Microtask Queue: Callback .then() dari Future standar');
  });

  // Menjadwalkan ke Microtask Queue
  scheduleMicrotask(() {
    print('5. Microtask Queue: scheduleMicrotask dieksekusi');
  });

  // Future.value() menjadwalkan resolusinya ke Microtask Queue
  Future.value('6. Microtask Queue: Future.value dieksekusi').then((val) {
    print(val);
  });

  print('7. Kode Sinkron: Akhir main()');
}
```

**Output yang Dihasilkan:**
```text
1. Kode Sinkron: Mulai main()
7. Kode Sinkron: Akhir main()
5. Microtask Queue: scheduleMicrotask dieksekusi
6. Microtask Queue: Future.value dieksekusi
2. Event Queue: Timer.run dieksekusi
3. Event Queue: Future standar dieksekusi
4. Microtask Queue: Callback .then() dari Future standar
```

**Penjelasan Eksekusi:**
1. Baris `1` dan `7` dieksekusi pertama karena bersifat sinkron.
2. Event Loop memeriksa Microtask Queue. Ia menemukan `scheduleMicrotask` (5) dan `Future.value` (6). Keduanya dieksekusi hingga antrean microtask kosong.
3. Event Loop mengambil *satu* item dari Event Queue: `Timer.run` (2).
4. Event Loop memeriksa Microtask (kosong).
5. Event Loop mengambil item berikutnya dari Event Queue: `Future` (3).
6. Setelah `Future` (3) selesai, ia mendaftarkan `.then()` ke Microtask Queue. Event loop langsung mengeksekusi microtask tersebut (4) sebelum mengambil *event* lain dari Event Queue.

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: Di dalam Dart VM, Event Loop pada dasarnya adalah sebuah *infinite loop* (`while(true)`). Ketika `main()` selesai, VM tidak langsung mematikan program. Ia akan terus berputar memeriksa `microtask_queue` dan `event_queue`. Jika kedua antrean kosong dan tidak ada *port* yang terbuka (menunggu I/O), barulah Isolate dimatikan (program *exit*).
- **Alokasi Memori / Resource**: Setiap *callback* yang didaftarkan ke dalam antrean (baik `Future` maupun `Timer`) adalah sebuah *Closure*. *Closure* ini menangkap (*capture*) variabel dari *lexical scope* sekitarnya. Objek-objek ini dialokasikan di **Heap Memory**. Jika Anda mendaftarkan terlalu banyak *event* yang tidak pernah selesai, Anda akan mengalami *Memory Leak* karena *Garbage Collector* tidak bisa membersihkan *closure* yang masih direferensikan oleh Event Loop.
- **Trade-offs**: Prioritas absolut Microtask Queue membawa risiko **Microtask Starvation**. Jika Anda membuat rekursi tak terbatas menggunakan `scheduleMicrotask`, Event Queue tidak akan pernah dieksekusi. Di Flutter, ini berarti UI akan *freeze* (membeku) karena *drawing events* dan *user input* berada di Event Queue.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan `Future` standar untuk operasi asinkron biasa (I/O, *network*).
  - Gunakan `Isolate` (seperti `Isolate.run()` atau `compute` di Flutter) untuk komputasi berat (misal: *parsing* JSON berukuran besar, manipulasi gambar). Event Loop tidak dirancang untuk komputasi CPU-bound.
- **Don'ts**:
  - **Jangan memblokir Event Loop.** Melakukan iterasi sinkron yang sangat besar (misal: `for` loop 1 miliar kali) di *main thread* akan menghentikan Event Loop, membuat aplikasi tidak responsif.
  - **Jangan menyalahgunakan Microtask.** Hindari penggunaan `scheduleMicrotask` kecuali Anda benar-benar sedang menulis *framework* atau *library* internal yang membutuhkan resolusi *state* instan sebelum *frame* UI berikutnya digambar.
- **Edge Cases**:
  - Memahami perbedaan inisialisasi `Future`:
    - `Future(() => ...)`: Menjadwalkan eksekusi ke **Event Queue**.
    - `Future.microtask(() => ...)`: Menjadwalkan eksekusi ke **Microtask Queue**.
    - `Future.sync(() => ...)`: Mengeksekusi fungsi secara **Sinkron** saat itu juga, tetapi mengembalikan hasilnya sebagai `Future`.
    - `Future.value(...)`: Menjadwalkan penyelesaian (resolusi) ke **Microtask Queue**.

### 5. Tantangan Eksplorasi Mandiri

1. **Simulasi Starvation:** Buatlah sebuah program Dart dengan fungsi rekursif yang memanggil `scheduleMicrotask` secara terus-menerus. Tambahkan sebuah `Timer` berdurasi 1 detik. Amati apakah `Timer` tersebut pernah dieksekusi.
2. **Analisis Nested Futures:** Tulis sebuah kode di mana sebuah `Future` di dalam Event Queue menghasilkan `Future.microtask`, dan di dalam microtask tersebut menghasilkan `Future` baru. Prediksi urutan *print* di konsol sebelum Anda menjalankannya.
3. **Refactoring CPU-Bound:** Buatlah sebuah fungsi sinkron yang menghitung bilangan prima hingga 100.000 (yang akan memblokir Event Loop). Refaktor kode tersebut menggunakan `Isolate.run()` agar Event Loop tetap bisa mencetak pesan dari `Timer.periodic` setiap 100 milidetik tanpa terputus.
