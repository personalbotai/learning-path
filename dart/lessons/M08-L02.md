## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Di ekosistem Dart, serialisasi dan deserialisasi data (khususnya JSON) merupakan jembatan antara representasi data berbasis teks/skema dinamis (`Map<String, dynamic>`) dengan sistem tipe statis Dart yang kuat (*sound type system*). 

Secara mendasar, proses deserialisasi terbagi menjadi dua tahap:
1. **Parsing Primitif**: Mengubah format string JSON menjadi struktur data primitif in-memory Dart (`Map`, `List`, `num`, `bool`, `String`) menggunakan pustaka bawaan `dart:convert` (`jsonDecode()`).
2. **Object Hydration / Mapping**: Mengonversi `Map<String, dynamic>` tersebut ke dalam objek kelas (*Data Transfer Object* atau *Domain Model*) agar memiliki validasi tipe waktu-kompilasi (*compile-time type safety*).

```
                      +-------------------+
                      |    JSON String    |
                      +-------------------+
                                |
                                | dart:convert (jsonDecode)
                                v
                   +-------------------------+
                   |  Map<String, dynamic>   |
                   +-------------------------+
                                |
          +---------------------+---------------------+
          | (Manual Parsing)                          | (Code Generation)
          v                                           v
+--------------------+                      +--------------------+
| Model.fromJson()   |                      | _$ModelFromJson()  |
| - Casting manual   |                      | - Static Analyzer  |
| - Rentan human err |                      | - AST Inspection   |
+--------------------+                      +--------------------+
          |                                           |
          +---------------------+---------------------+
                                v
                      +-------------------+
                      |   Typed Object    |
                      +-------------------+
```

#### Mengapa Tidak Menggunakan Refleksi Waktu-Jalan (*Runtime Reflection*)?
Di bahasa seperti Java (Jackson/Gson) atau C# (System.Text.Json), parsing JSON umumnya memanfaatkan *runtime reflection*. Namun, arsitektur Dart dirancang khusus untuk kompilasi *Ahead-of-Time* (AOT) guna menghasilkan performa tinggi pada aplikasi klien (seperti Flutter). Fitur refleksi Dart (`dart:mirrors`):
- Mematikan kemampuan *tree-shaking* (kompiler tidak dapat mendeteksi kode mati karena metode dapat dipanggil secara dinamis lewat string).
- Menyebabkan ukuran biner aplikasi membengkak secara drastis (*bloat*).
- Menurunkan performa secara signifikan karena JIT/AOT compiler tidak bisa melakukan inlining atau optimasi register.

Oleh sebab itu, Dart memisahkan penanganan JSON menjadi dua pendekatan:
- **Manual Parsing**: Developer menulis logika konversi secara eksplisit pada *factory constructor* `fromJson` dan metode `toJson`.
- **Compile-time Code Generation (`json_serializable` + `build_runner`)**: Menggunakan inspeksi AST (*Abstract Syntax Tree*) pada fase *build* untuk menghasilkan kode serialisasi berbasis fungsi statis murni tanpa overhead refleksi waktu-jalan.

### 2. Implementasi & Contoh Kasus Nyata

Berikut perbandingan implementasi: Model `User` yang memiliki *nested object* `Address` serta penanganan tipe khusus seperti `DateTime` dan `enum`.

#### Pendekatan 1: Manual Parsing
Metode ini tidak memerlukan dependensi eksternal, namun mengharuskan casting tipe secara manual dan rentan terhadap kesalahan ketik (*typo*).

```dart
// user_manual.dart
enum UserRole { admin, member, guest }

class Address {
  final String street;
  final String city;

  Address({required this.street, required this.city});

  factory Address.fromJson(Map<String, dynamic> json) {
    return Address(
      street: json['street'] as String,
      city: json['city'] as String,
    );
  }

  Map<String, dynamic> toJson() => {
    'street': street,
    'city': city,
  };
}

class User {
  final String id;
  final String name;
  final UserRole role;
  final DateTime createdAt;
  final Address address;
  final List<String> tags;

  User({
    required this.id,
    required this.name,
    required this.role,
    required this.createdAt,
    required this.address,
    required this.tags,
  });

  factory User.fromJson(Map<String, dynamic> json) {
    return User(
      id: json['id'] as String,
      name: json['name'] as String,
      role: UserRole.values.byName(json['role'] as String),
      createdAt: DateTime.parse(json['created_at'] as String),
      address: Address.fromJson(json['address'] as Map<String, dynamic>),
      // List parsing memerlukan casting eksplisit pada setiap elemen
      tags: (json['tags'] as List<dynamic>).map((e) => e as String).toList(),
    );
  }

  Map<String, dynamic> toJson() => {
    'id': id,
    'name': name,
    'role': role.name,
    'created_at': createdAt.toIso8601String(),
    'address': address.toJson(),
    'tags': tags,
  };
}
```

#### Pendekatan 2: Code Generation (`json_serializable`)

Tambahkan dependensi pada `pubspec.yaml`:
```yaml
dependencies:
  json_annotation: ^4.9.0

dev_dependencies:
  build_runner: ^2.4.9
  json_serializable: ^6.8.0
```

Implementasi file model:

```dart
// user_generated.dart
import 'package:json_annotation/json_annotation.dart';

part 'user_generated.g.dart';

enum UserRole {
  @JsonValue('admin')
  admin,
  @JsonValue('member')
  member,
  @JsonValue('guest')
  guest,
}

@JsonSerializable(explicitToJson: true)
class Address {
  final String street;
  final String city;

  Address({required this.street, required this.city});

  factory Address.fromJson(Map<String, dynamic> json) => _$AddressFromJson(json);
  Map<String, dynamic> toJson() => _$AddressToJson(this);
}

@JsonSerializable(
  explicitToJson: true, 
  fieldRename: FieldRename.snake, // Otomatis mengonversi camelCase ke snake_case
)
class User {
  final String id;
  final String name;
  final UserRole role;
  final DateTime createdAt;
  final Address address;
  
  @JsonKey(defaultValue: <String>[])
  final List<String> tags;

  User({
    required this.id,
    required this.name,
    required this.role,
    required this.createdAt,
    required this.address,
    required this.tags,
  });

  factory User.fromJson(Map<String, dynamic> json) => _$UserFromJson(json);
  Map<String, dynamic> toJson() => _$UserToJson(this);
}
```

Jalankan perintah generator via terminal:
```bash
dart run build_runner build --delete-conflicting-outputs
```

Output file yang digenerate oleh `build_runner` (`user_generated.g.dart`):
```dart
// user_generated.g.dart (Auto-generated)
part of 'user_generated.dart';

Address _$AddressFromJson(Map<String, dynamic> json) => Address(
      street: json['street'] as String,
      city: json['city'] as String,
    );

Map<String, dynamic> _$AddressToJson(Address instance) => <String, dynamic>{
      'street': instance.street,
      'city': instance.city,
    };

User _$UserFromJson(Map<String, dynamic> json) => User(
      id: json['id'] as String,
      name: json['name'] as String,
      role: $enumDecode(_$UserRoleEnumMap, json['role']),
      createdAt: DateTime.parse(json['created_at'] as String),
      address: Address.fromJson(json['address'] as Map<String, dynamic>),
      tags: (json['tags'] as List<dynamic>?)?.map((e) => e as String).toList() ??
          const <String>[],
    );

Map<String, dynamic> _$UserToJson(User instance) => <String, dynamic>{
      'id': instance.id,
      'name': instance.name,
      'role': _$UserRoleEnumMap[instance.role]!,
      'created_at': instance.createdAt.toIso8601String(),
      'address': instance.address.toJson(),
      'tags': instance.tags,
    };

const _$UserRoleEnumMap = {
  UserRole.admin: 'admin',
  UserRole.member: 'member',
  UserRole.guest: 'guest',
};
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Pipeline Kompilasi
Generator tidak mengeksekusi kode Dart runtime. Sebaliknya, pipeline `build_runner` bekerja dengan alur berikut:
1. **Source Parsing**: Paket `analyzer` mem-parsing source code Dart menjadi **Abstract Syntax Tree (AST)** dan model semantik (*Element Model*).
2. **Annotation Scanning**: Generator memindai metadata (misal: `@JsonSerializable()`).
3. **Type Resolution**: Kompiler memetakan metadata tipe data dari setiap field (misal: memeriksa apakah tipe field mengimplementasikan `fromJson`, apakah bertipe primitif, atau berupa `enum`).
4. **Code Emission**: Generator menyusun kode Dart murni ke dalam buffer string, memvalidasi sintaksisnya, dan menulisnya ke file ekstensi `.g.dart` sebagai bagian (`part of`) dari file utama.

Karena file hasil akhirnya adalah Dart murni, kode tersebut dioptimasi secara penuh oleh Dart AOT compiler saat build produksi:
- Mendukung *Function Inlining*.
- *Zero-overhead abstraction* (tidak ada dispatch dinamis berbasis string seperti pada `dart:mirrors`).

#### Alokasi Memori & Karakteristik Runtime
- Ketika `jsonDecode(source)` dijalankan, runtime Dart mengalokasikan memori untuk seluruh struktur JSON sebagai instans internal `_InternalLinkedHashMap<dynamic, dynamic>`.
- **Parsing Manual**: Rentan menciptakan overhead memori ganda apabila parsing dilakukan secara lambat (*lazy*) atau menahan referensi ke map primitif original terlalu lama.
- **Garbage Collection (GC)**: Konversi map ke kelas DTO menciptakan objek baru di *Young Generation* (nursery) memori Dart Heap. Setelah DTO selesai dibangun, referensi Map awal langsung memenuhi syarat untuk di-*sweep* oleh Scavenger (minor GC).

#### Perbandingan Karakteristik Arsitektur

| Karakteristik | Manual Parsing | json_serializable |
| :--- | :--- | :--- |
| **Kecepatan Build** | Instan (tidak ada code-gen step) | Lambat (ada fase eksekusi `build_runner`) |
| **Kecepatan Runtime** | Sangat Cepat (bergantung efisiensi penulisan manual) | Optimal (dihasilkan oleh template standar AOT) |
| **Ukuran Binary** | Minimal | Terkendali (hanya kode yang dipanggil yang masuk tree-shaking) |
| **Biaya Pemeliharaan** | Tinggi (rawan *human error*, refactoring manual) | Rendah (cukup update class dan trigger build) |
| **Dependensi Eksternal** | Tidak ada | Membutuhkan dependensi package & tools |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `explicitToJson: true`**: Secara *default*, `json_serializable` hanya memanggil `toJson()` pada level pertama. Untuk objek bertingkat (*nested objects*), opsi `explicitToJson: true` wajib diaktifkan agar method `.toJson()` milik objek di dalamnya ikut dipanggil, bukan sekadar menyematkan instans objek mentah ke dalam map.
- **Konfigurasi `build.yaml` Global**: Alih-alih menambahkan parameter berulang di setiap anotasi `@JsonSerializable()`, definisikan konfigurasi global pada root proyek untuk standardisasi *naming convention* (`field_rename: snake`):
  ```yaml
  # build.yaml
  targets:
    $default:
      builders:
        json_serializable:
          options:
            field_rename: snake
            explicit_to_json: true
  ```
- **Kombinasikan dengan Immutability**: Integrasikan `json_serializable` dengan pustaka seperti `freezed` untuk memastikan seluruh DTO bersifat *immutable* dan memiliki implementasi `copyWith()`, `==`, serta `hashCode` otomatis.

#### Don'ts
- **Menghindari `as num` atau Casting Implisit untuk Angka Desimal**: Jangan lakukan `json['amount'] as double`. Pada parser JSON Dart, jika payload bernilai `10`, ia akan di-parse sebagai `int`. Casting langsung `10 as double` akan melempar `TypeError` di runtime. Gunakan `(json['amount'] as num).toDouble()`.
- **Jangan Mengabaikan Null Safety pada Dynamic Map**: Jangan berasumsi data API selalu mematuhi kontrak. Field non-nullable di Dart akan langsung melempar exception saat inisialisasi constructor jika API mengembalikan `null`.

#### Edge Cases & Penanganannya
**Kustomisasi Tipe (Custom Type Converter)**:
Jika format JSON tidak dapat dipetakan langsung oleh konverter bawaan (misal: string numerik dari backend warisan seperti `"12345"` yang harus menjadi `int`), gunakan `JsonConverter`:

```dart
class StringToIntConverter implements JsonConverter<int, dynamic> {
  const StringToIntConverter();

  @override
  int fromJson(dynamic json) {
    if (json is int) return json;
    if (json is String) return int.parse(json);
    throw FormatException('Gagal mem-parsing $json ke int');
  }

  @override
  dynamic toJson(int object) => object.toString();
}

// Penggunaan pada field:
@JsonSerializable()
class Account {
  @StringToIntConverter()
  final int balance;

  Account(this.balance);
  
  factory Account.fromJson(Map<String, dynamic> json) => _$AccountFromJson(json);
  Map<String, dynamic> toJson() => _$AccountToJson(this);
}
```

### 5. Tantangan Eksplorasi Mandiri

1. **Rancang Custom Converter untuk Epoch Milliseconds**:
   Backend mengirimkan data timestamp dalam format integer Unix Epoch Milliseconds (contoh: `1700000000000`), tetapi domain model Anda membutuhkan tipe `DateTime`. Buatlah kelas `EpochDateTimeConverter` yang mengimplementasikan `JsonConverter<DateTime, int>`, kemudian pasang pada properti model menggunakan `@JsonSerializable()`.
2. **Benchmarking & Profiling Parsing Payload Besar**:
   Buat file JSON berukuran ~10MB (berisi list yang memuat 50.000 user). Ukur durasi waktu eksekusi dan amati konsumsi alokasi heap Dart VM menggunakan `dart:developer` (`Timeline` atau `Stopwatch`) antara:
   - Pemanggilan deserialisasi langsung pada *main isolate*.
   - Pemanggilan deserialisasi yang didelegasikan ke *background worker isolate* menggunakan `Isolate.run()`. Analisis mengapa payload besar dapat menyebabkan *jank* (frame drop) pada thread utama.
