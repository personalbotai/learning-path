## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Di dalam runtime Dart, fungsi adalah **first-class citizens**—artinya fungsi merupakan objek instan dari tipe `Function`, dapat disimpan dalam variabel, diteruskan sebagai argumen, atau dikembalikan dari fungsi lain. Dart mengimplementasikan sistem penanganan parameter yang ketat dan fleksibel melalui kombinasi *Positional Parameters* dan *Named Parameters*, didukung penuh oleh arsitektur *Sound Null Safety*.

```
Fungsi di Dart
├── Positional
│   ├── Required Positional   : fn(int a, String b)
│   └── Optional Positional   : fn(int a, [String? b, int c = 0])
└── Named
    ├── Optional Named        : fn({String? key, int retries = 3})
    └── Required Named        : fn({required String id, int timeout = 10})
```

#### Arsitektur Parameter
1. **Positional Parameters**: Dipetakan berdasarkan urutan deklarasi indeks pada call-site. Nilai pertama dialokasikan ke parameter pertama, nilai kedua ke parameter kedua, dan seterusnya.
   - **Required Positional**: Wajib dipasok saat pemanggilan, urutan mutlak.
   - **Optional Positional** (`[ ]`): Parameter opsional berbasis indeks. Jika tidak dipasok, nilainya akan fallback ke nilai default konstan atau `null`. Parameter ini harus selalu diletakkan setelah parameter *required positional*.
2. **Named Parameters** (`{ }`): Dipetakan berdasarkan label/nama parameter pada call-site, bukan urutan posisinya.
   - Secara default, named parameter bersifat opsional.
   - Karena Dart menerapkan *Sound Null Safety*, parameter yang tidak memiliki nilai default harus dideklarasikan sebagai nullable (`Type?`) ATAU ditandai dengan kata kunci `required`.
   - Sebuah fungsi di Dart tidak dapat menggabungkan *Optional Positional* dan *Named Parameters* secara bersamaan dalam satu tanda tangan fungsi.
3. **Arrow Syntax (`=>`)**: Merupakan gula sintaksis (*syntactic sugar*) untuk blok fungsi yang hanya terdiri dari satu *expression*. Bentuk `=> expr;` ekuivalen secara semantik dengan `{ return expr; }`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern yang memodelkan subsistem pengiriman notifikasi transaksi:

```dart
// Model data sederhana
class NotificationPayload {
  final String userId;
  final String title;
  final String body;

  const NotificationPayload({
    required this.userId,
    required this.title,
    required this.body,
  });
}

// 1. Required Positional + Optional Positional Parameter
// Parameter [format] opsional dengan default value 'TEXT'
String formatLog(DateTime timestamp, String message, [String format = 'TEXT']) {
  final timeStr = timestamp.toIso8601String();
  return format == 'JSON' 
      ? '{"timestamp": "$timeStr", "message": "$message"}'
      : '[$timeStr] $message';
}

// 2. Named Parameters: Kombinasi required dan default values
void sendPushNotification({
  required NotificationPayload payload,
  int retryAttempts = 3,
  Duration timeout = const Duration(seconds: 5),
  bool silent = false,
}) {
  print('Mengirim push ke: ${payload.userId}');
  print('Config: MaxRetries=$retryAttempts, Timeout=${timeout.inSeconds}s, Silent=$silent');
  // Logika HTTP client disimulasikan di sini
}

// 3. Higher-order function & Arrow Syntax (Expression Body)
// Menggunakan arrow syntax untuk transformasi data stream/list
List<String> extractUserIds(List<NotificationPayload> queue) =>
    queue.map((item) => item.userId).toList();

// Arrow syntax dengan operasi kondisional murni
bool shouldThrottle(int requestCount, {int threshold = 100}) => 
    requestCount > threshold;

void main() {
  // Pemanggilan Positional & Optional Positional
  final now = DateTime.now();
  print(formatLog(now, 'Sistem diinisialisasi')); // Pakai default format
  print(formatLog(now, 'Metrik dimuat', 'JSON')); // Override optional positional

  // Pemanggilan Named Parameters (urutan argument bebas)
  final payload = NotificationPayload(
    userId: 'USR-8902',
    title: 'Pembayaran Sukses',
    body: 'Transaksi #TRX-101 telah diverifikasi.',
  );

  sendPushNotification(
    silent: true,
    payload: payload,
    // retryAttempts menggunakan default (3)
    timeout: const Duration(seconds: 10),
  );

  // Arrow syntax execution
  final queue = [payload];
  final userIds = extractUserIds(queue);
  print('User ID antrean: $userIds');
  print('Status throttle: ${shouldThrottle(150)}');
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (Dart AOT / JIT)
- **Call Stubs & Name Mangling**: Pada runtime berbasis AOT (seperti Flutter/Dart native compile via LLVM backend), nama parameter tidak disimpan sebagai string dinamis di memory table untuk pencarian *runtime dictionary*. Pemanggilan *named parameters* diterjemahkan pada level kompilator menjadi argumen berindeks register tertentu atau *entry-point stubs* yang dimodifikasi (*mangled symbols*). Hal ini membuat pemanggilan named parameter sama efisiennya dengan positional parameter tanpa overhead hashing string saat runtime.
- **Constant Propagation pada Default Values**: Nilai default untuk optional dan named parameters dievaluasi secara statis pada fase *compile-time* dan wajib berupa nilai `const`. Kompilator menyisipkan pointer nilai default tersebut langsung ke *preamble* instruksi fungsi pemanggil atau melalui epilog fungsi target jika argumen tidak dipasok pada *call-stack*.

#### Alokasi Memori
- Parameter di Dart diteruskan secara **pass-by-value-of-reference** (call-by-sharing).
- Baik positional maupun named parameters menyimpan referensi 64-bit (pada arsitektur modern) menuju objek di memori heap (atau nilai *Small Integer / Smi* langsung di register/stack).
- Stack frame sebuah fungsi hanya mengalokasikan slot sejumlah parameter yang didefinisikan; jika nilai argumen tidak dipasok, register/slot stack diisi nilai referensi default atau `null`.

#### Trade-offs
- **Positional**: Keuntungan performa mikro (sedikit instruksi register allocation), namun menurunkan *readability* dan rentan bug inversi tipe identik saat pemanggilan (misal: `createUser(String firstName, String lastName)` tertukar `createUser(lastName, firstName)`).
- **Named Parameters**: Sangat tinggi dari segi *readability* dan fleksibilitas evolusi API (menambah parameter baru tidak merusak call-site lama), tetapi membutuhkan sedikit overhead metadata biner di level AOT untuk menangani berbagai signature stubs.
- **Arrow Syntax**: Hanya gula sintaksis AST (*Abstract Syntax Tree*). Tidak ada perbedaan performa atau *bytecode* instruksi antara `{ return expr; }` dan `=> expr;`.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Named Parameters jika fungsi menerima > 2 parameter**: Ini mencegah kesalahan *human-error* terkait urutan argumen dan membuat kode menjadi *self-documenting*.
- **Manfaatkan kata kunci `required` daripada mendiamkannya menjadi `Type?` tanpa alasan**: Jika parameter tersebut mutlak dibutuhkan untuk eksekusi fungsi, jangan biarkan nullable jika Anda akhirnya hanya melakukan `argument!`.
- **Gunakan Arrow Syntax hanya untuk kalkulasi ekspresi tunggal**: Ideal untuk getter, mapper, filter, atau fungsi matematika ringkas.

#### Don'ts
- **Jangan memaksakan *side-effects* kompleks ke dalam Arrow Syntax**: 
  ```dart
  // BURUK: Sulit dibaca, menyembunyikan mutasi kompleks dalam single expression
  void updateState() => repository.fetch().then((v) => state = v).catchError((e) => log(e));

  // BAIK: Gunakan block body dengan async/await
  Future<void> updateState() async {
    try {
      final v = await repository.fetch();
      state = v;
    } catch (e) {
      log(e);
    }
  }
  ```
- **Hindari mengganti nama parameter pada implementasi turunan (Subtyping rule)**:
  Jika sebuah interface mendeklarasikan named parameter `{required String id}`, kelas implementasi tidak boleh mengubahnya menjadi `{required String userId}`, karena dynamic dispatch atau polymorphism call via interface type akan crash pada runtime / gagal kompilasi.

#### Edge Cases
- **Konflik Sintaksis**: Dart secara leksikal melarang deklarasi fungsi yang mencampur `[ ]` dan `{ }`. Anda harus memilih salah satu:
  ```dart
  // ILEGAL: Compile Error
  void invalidFn(int a, [int b = 0], {int c = 1}) {}
  ```
- **Evaluasi Laziness**: Default value parameter tidak dievaluasi ulang setiap fungsi dipanggil jika bernilai mutable instance. Oleh karena itu Dart mewajibkan default value bertipe compile-time `const`, mencegah *shared mutated state* antar pemanggilan fungsi.

### 5. Tantangan Eksplorasi Mandiri

1. **Refactoring Legacy API**: Diberikan sebuah fungsi `void configureServer(String host, int port, bool useSsl, int timeout, int maxConnections)`. Ubah rancangan fungsi ini menggunakan kombinasi *Required Positional* untuk koneksi fundamental (`host`, `port`) dan *Named Parameters* dengan nilai default yang aman untuk konfigurasi sisanya.
2. **Behavioral Test Subtyping**: Buat sebuah `abstract class Filter` yang memiliki method `bool match({required String query})`. Buat subclass `PrefixFilter` yang mengoverride method tersebut. Ujilah apa yang terjadi pada Dart analyzer jika Anda mengubah nama parameter `query` menjadi `searchQuery` pada subclass saat diakses via tipe parent-nya (`Filter f = PrefixFilter()`).
3. **Analisis Dekompilasi AST**: Gunakan terminal dan jalankan `dart compile kernel --dump-kernel` pada file Dart sederhana yang memiliki fungsi *block body* dan *arrow syntax*. Bandingkan representasi Kernel AST dari kedua fungsi tersebut untuk memvalidasi bahwa keduanya menghasilkan struktur ekuivalen.
