## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum Dart 3.0, representasi *Sum Types* atau *Algebraic Data Types* (ADT) biasanya disimulasikan menggunakan abstract class biasa, paket pihak ketiga (seperti `freezed`), atau implementasi manual *Visitor Pattern*. Masalah utama dari pendekatan ini adalah ketidakmampuan compiler untuk memverifikasi apakah seluruh variasi *subtipe* telah ditangani secara lengkap (*exhaustiveness*) pada saat kompilasi.

Modifier `sealed` diperkenalkan di Dart 3 untuk memecahkan masalah ini pada level arsitektur compiler.

```
                  ┌──────────────────────┐
                  │ sealed class Result  │  (Tidak bisa diinstansiasi langsung)
                  └──────────┬───────────┘
                             │
         ┌───────────────────┼───────────────────┐
         ▼                   ▼                   ▼
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
│  class Success  │ │  class Failure  │ │  class Loading  │ (Harus di-declare
└─────────────────┘ └─────────────────┘ └─────────────────┘  di library yg sama)
```

#### Karakteristik Utama `sealed`:
1. **Implicitly Abstract**: Kelas dengan modifier `sealed` tidak dapat diinstansiasi secara langsung (`sealed class Result` otomatis bersifat `abstract`).
2. **Library-Confined Hierarchy**: Subtipe langsung (*direct subtypes*) dari sebuah `sealed class` **wajib** dideklarasikan di dalam *library* (file atau kumpulan file yang disatukan via direktif `part/part of`) yang sama. Kode di luar library tersebut dilarang melakukan `extend`, `implement`, atau `with` terhadap kelas tersebut.
3. **Exhaustiveness Checking**: Karena compiler mengetahui secara deterministik seluruh hierarki turunan dari kelas tersebut di level kompilasi, compiler dapat melakukan *Static Flow Analysis* untuk memastikan ekspresi `switch` menangani semua kemungkinan cabang tanpa memerlukan fallback klausa `default`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi *State Management* operasi I/O jaringan menggunakan `sealed class` yang dipadukan dengan *pattern matching* dan *destructuring*.

```dart
// File: network_state.dart
import 'dart:math';

// 1. Deklarasi hierarki sealed class
sealed class NetworkState<T> {
  const NetworkState();
}

final class StateInitial<T> extends NetworkState<T> {
  const StateInitial();
}

final class StateLoading<T> extends NetworkState<T> {
  final double? progress;
  const StateLoading({this.progress});
}

final class StateSuccess<T> extends NetworkState<T> {
  final T data;
  final DateTime timestamp;
  const StateSuccess(this.data, {required this.timestamp});
}

final class StateFailure<T> extends NetworkState<T> {
  final String message;
  final int? statusCode;
  const StateFailure(this.message, {this.statusCode});
}

// 2. Business Logic menggunakan Switch Expression & Exhaustive Matching
String renderUI<T>(NetworkState<T> state) {
  // Switch expression mewajibkan penanganan seluruh cabang.
  // Jika salah satu subclass dihapus dari switch, kode TIDAK AKAN BISA DI-COMPILE.
  return switch (state) {
    StateInitial() => 'Status: Siap memuat data.',
    
    // Pattern matching dengan Guard Clause (when)
    StateLoading(:final progress?) when progress > 0.0 => 
      'Status: Mengunduh ${(progress * 100).toStringAsFixed(1)}%...',
    StateLoading() => 
      'Status: Memulai koneksi...',
      
    // Object destructuring langsung pada pattern
    StateSuccess(:final data, :final timestamp) => 
      'Sukses: $data (Diterima pada: ${timestamp.toIso8601String()})',
      
    // Matching nilai spesifik menggunakan Relational Patterns & Destructuring
    StateFailure(:final message, statusCode: 404) => 
      'Error 404: Endpoint tidak ditemukan - $message',
    StateFailure(:final message, statusCode: >= 500 && <= 599) => 
      'Error Server: Terjadi kendala internal ($message)',
    StateFailure(:final message, :final statusCode) => 
      'Error $statusCode: $message',
  };
}

void main() {
  final List<NetworkState<String>> simulationStates = [
    const StateInitial(),
    const StateLoading(progress: 0.45),
    const StateLoading(),
    StateSuccess('Payload Data JSON', timestamp: DateTime.now()),
    const StateFailure('Resource hilang', statusCode: 404),
    const StateFailure('Database down', statusCode: 503),
    const StateFailure('Akses ditolak', statusCode: 403),
  ];

  for (final state in simulationStates) {
    print(renderUI(state));
  }
}
```

#### Penjelasan Komponen Penting:
- **`switch (state)` sebagai *Expression***: Mengembalikan nilai secara langsung, mereduksi *boilerplate* fungsi dan menghilangkan mutasi variabel sementara.
- **Destructuring Pattern (`:final data`)**: Mengambil properti `state.data` dan mengikatnya ke variabel lokal baru bernama `data` dalam satu operasi deklaratif.
- **Guard Clause (`when`)**: Mengevaluasi kondisi boolean runtime tambahan setelah tipe objek cocok dengan pattern.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime:
- Pada tahap kompilasi, **Front-End Compiler (cfe)** Dart menganalisis Abstract Syntax Tree (AST) dan membangun grafik himpunan tertutup (*finite set*) dari semua subtipe `NetworkState`.
- Kompilator menggunakan algoritma pengujian exhaustiveness berbasis ruang vektor ruang keadaan (state-space exhaustiveness checking). Jika gabungan seluruh cabang pola dalam `switch` tidak mencakup 100% himpunan subtipe, CFE mengeluarkan kompilasi galat: *The type 'NetworkState' is not exhaustively matched*.
- Di level AOT (*Ahead-Of-Time*) atau JIT (*Just-In-Time*), cabang dievaluasi menggunakan instruksi *Type Check* (`is`) yang sangat teroptimasi atau diubah menjadi *Jump Table* berbasis Class ID (*CID*) internal VM, bukan perbandingan string atau dynamic dispatch yang lambat.

#### Alokasi Memori:
- Setiap instance subtipe `NetworkState` dialokasikan secara standar pada Dart Heap Memory.
- Objek membawa header yang menyimpan referensi ke `Class` tabel internal objek (*vtable* pointer) dan GC metadata. Modifiers `sealed` tidak menambah overhead memori runtime sama sekali; seluruh mekanisme validasi terjadi murni pada **tahap analisis statis (compile-time)**.

#### Trade-offs:
- **Modularitas vs Keamanan Sistem**: Tipe tertutup mengorbankan fleksibilitas *Open-Closed Principle*. Anda tidak dapat mengizinkan paket konsumen pihak ketiga menambahkan state baru ke dalam `sealed class` yang Anda sediakan. Penambahan satu subtipe baru di library asal akan memaksa *breaking change* di seluruh `switch` expression di mana pun class tersebut dikonsumsi.

### 4. Best Practices & Common Pitfalls

#### Do's:
- **Gunakan `switch` expression**: Prioritaskan bentuk expression (`final result = switch(...)`) daripada statement konvensional (`switch(...) { case ...: break; }`), karena compiler memvalidasi exhaustiveness secara mutlak pada bentuk ekspresi.
- **Gunakan modifier lanjutan pada Subclass**: Kombinasikan dengan modifier seperti `final`, `base`, atau `sealed` pada subclass langsung dari sealed class untuk secara eksplisit mendefinisikan kontrak pewarisan tingkat lanjut.
- **Kombinasikan dengan Records**: Gunakan records untuk mengembalikan tuple error/data dari state tanpa perlu membuat sub-objek berlebih.

#### Don'ts:
- **Menghindari `default` atau Wildcard (`_`) sembarangan**:
  ```dart
  // ANTI-PATTERN: Menggagalkan fungsi exhaustive checking
  return switch (state) {
    StateSuccess(:final data) => data,
    _ => 'Bukan sukses', // Jangan lakukan ini jika ingin aman saat refactoring!
  };
  ```
  Jika di kemudian hari ditambahkan `StateCancelled`, compiler tidak akan memberi tahu Anda bahwa state baru tersebut belum di-handle secara spesifik.

- **Menyebarkan subclass di file terpisah tanpa `part`**: Mendeklarasikan turunan `sealed class` di file yang di-`import` biasa (bukan file yang sama atau library yang sama via `part of`) akan menghasilkan compile error.

#### Edge Cases:
- **Hierarki Multi-level**: Jika subclass dari sebuah `sealed class` dideklarasikan sebagai `sealed class` lagi, kompilator akan melacak rekursi hierarki tersebut. Seluruh daun terbawah (*leaf nodes*) dari pohon tipe wajib ter-cover dalam switch pattern.
- **Nullable Generic Arguments**: Jika menggunakan `NetworkState<T?>`, pastikan berhati-hati dalam membedakan pattern antara matching terhadap status sukses dengan data bernilai `null` vs data yang tidak nullable.

### 5. Tantangan Eksplorasi Mandiri

1. **Rancang Abstract Syntax Tree (AST) Evaluator**:
   Buat sebuah `sealed class Expr` yang memiliki varian: `Number(double value)`, `Add(Expr left, Expr right)`, `Multiply(Expr left, Expr right)`, dan `Divide(Expr left, Expr right)`. Buat fungsi evaluasi rekursif menggunakan `switch expression` untuk menghitung hasil kalkulasinya dengan penanganan pembagian dengan nol (`ZeroDivisionError`).

2. **Refactoring Legacy State**:
   Ambil satu controller/bloc/notifier yang masih membedakan state menggunakan kombinasi banyak flag boolean primitif (misal: `isLoading`, `hasError`, `isSuccess`, `data`), ubah struktur tersebut menjadi arsitektur satu `sealed class` dan bandingkan keamanan aliran kodenya (*flow safety*) saat merender komponen logika bisnis.
