## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dart adalah bahasa pemrograman berorientasi objek murni (Pure OOP). Di Dart, setiap nilai yang Anda simpan dalam variabel adalah sebuah *object*, dan setiap *object* adalah *instance* dari sebuah *class* (bahkan tipe primitif seperti `int` dan `Function` adalah objek yang diturunkan dari `Object`).

**Generative Constructors**
Generative constructor adalah mekanisme standar untuk mengalokasikan memori dan menginisialisasi *state* dari sebuah objek baru. Berbeda dengan *factory constructor* yang dapat mengembalikan *instance* yang sudah ada (cache), generative constructor **selalu** menghasilkan *instance* baru di memori. Dart menyediakan *syntactic sugar* (`this.fieldName`) untuk menghindari *boilerplate* saat inisialisasi.

**Named Constructors**
Banyak bahasa pemrograman (seperti Java atau C++) mendukung *Method/Constructor Overloading* (memiliki beberapa konstruktor dengan nama yang sama tetapi parameter berbeda). **Dart tidak mendukung overloading.** 
Sebagai solusinya, Dart memperkenalkan **Named Constructors**. Fitur ini memungkinkan Anda mendefinisikan beberapa konstruktor dalam satu kelas dengan nama yang eksplisit. Hal ini secara drastis meningkatkan *readability* (keterbacaan) kode, karena intensi pembuatan objek menjadi sangat jelas (misal: `User.fromJson()` vs `User.guest()`).

**Initializer List (`:`)**
Ini adalah fase kritis dalam arsitektur konstruktor Dart. *Initializer list* dieksekusi **sebelum** *body* konstruktor dijalankan. Ini adalah satu-satunya tempat di mana Anda dapat menginisialisasi variabel `final` yang nilainya tidak berasal langsung dari parameter, atau memanggil konstruktor dari *superclass* (`super()`).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi kelas `NetworkRequest` yang mendemonstrasikan penggunaan *generative* dan *named constructors* dalam skenario nyata.

```dart
class NetworkRequest {
  final String url;
  final String method;
  final Map<String, String> headers;
  final DateTime timestamp;

  // 1. Standard Generative Constructor
  // Menggunakan 'initializing formals' (this.url) untuk inisialisasi langsung.
  // Menggunakan Initializer List (:) untuk menginisialisasi field 'timestamp' 
  // sebelum body konstruktor dieksekusi.
  NetworkRequest(this.url, {this.method = 'GET', Map<String, String>? headers}) 
      : headers = headers ?? {'Content-Type': 'application/json'},
        timestamp = DateTime.now() {
    // Body konstruktor (opsional). Dijalankan SETELAH initializer list.
    print('Request created for $url at $timestamp');
  }

  // 2. Named Constructor: Intensi yang jelas untuk request POST
  NetworkRequest.post(this.url, {required Map<String, String> bodyHeaders})
      : method = 'POST',
        headers = {...bodyHeaders, 'Content-Type': 'application/json'},
        timestamp = DateTime.now();

  // 3. Named Constructor: Parsing dari format eksternal (JSON)
  NetworkRequest.fromJson(Map<String, dynamic> json)
      : url = json['url'] as String,
        method = json['method'] as String? ?? 'GET',
        headers = Map<String, String>.from(json['headers'] ?? {}),
        timestamp = DateTime.now();
        
  void send() {
    print('Sending $method request to $url...');
  }
}

void main() {
  // Menggunakan Standard Generative Constructor
  final req1 = NetworkRequest('https://api.example.com/users');
  
  // Menggunakan Named Constructor (.post)
  final req2 = NetworkRequest.post(
    'https://api.example.com/users', 
    bodyHeaders: {'Authorization': 'Bearer token123'}
  );

  // Menggunakan Named Constructor (.fromJson)
  final req3 = NetworkRequest.fromJson({
    'url': 'https://api.example.com/status',
    'method': 'GET'
  });
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: Saat sebuah generative/named constructor dipanggil, Dart VM / eksekusi runtime melakukan urutan berikut:
  1. Mengalokasikan memori di *Heap* untuk objek baru.
  2. Menginisialisasi semua *instance variables* dengan nilai *default* (biasanya `null` jika tidak ada nilai awal).
  3. Mengeksekusi **Initializer List** dari kelas saat ini.
  4. Memanggil konstruktor dari *superclass* (jika ada, defaultnya `super()`).
  5. Mengeksekusi **Body** dari konstruktor kelas saat ini.
- **Alokasi Memori / Resource**: Objek yang dibuat oleh generative constructor selalu dialokasikan di *Heap*. Referensi (pointer) ke objek tersebut disimpan di *Stack* (dalam scope fungsi pemanggil). Variabel `final` dijamin hanya ditulis satu kali di memori selama fase *initializer list*, membuatnya sangat aman untuk *concurrency* (thread-safe di Isolate Dart).
- **Trade-offs**: Generative constructor sangat cepat dan *straightforward*, namun kurang fleksibel jika Anda ingin mengembalikan *instance* dari *cache* atau mengembalikan *subtype* dari kelas tersebut. Untuk kasus tersebut, *Factory Constructor* lebih cocok.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan *initializing formals* (`this.fieldName`) sebanyak mungkin untuk menghindari *boilerplate*.
  - Gunakan *Named Constructors* untuk memberikan semantik yang jelas pada cara instansiasi (contoh: `DateTime.now()`, `Vector.polar()`).
  - Gunakan *Initializer List* untuk memvalidasi input sebelum objek benar-benar selesai dibuat (contoh: `assert(url.isNotEmpty)`).
- **Don'ts**:
  - Jangan meletakkan logika komputasi yang berat atau *I/O operations* di dalam *body* konstruktor. Konstruktor harus cepat dan hanya bertugas menyiapkan *state*.
  - Hindari penggunaan `late` modifier jika variabel sebenarnya bisa diinisialisasi melalui *initializer list*.
- **Edge Cases**: 
  - Saat berhadapan dengan *Inheritance* (pewarisan), jika *superclass* tidak memiliki konstruktor default tanpa argumen (unnamed, no-argument), Anda **wajib** memanggil konstruktor *superclass* secara manual di akhir *initializer list* kelas turunan menggunakan `super(...)`.
