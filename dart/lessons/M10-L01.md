### 1. Konsep & Arsitektur Mendalam

Dalam ekosistem Dart, *unit testing* bukan sekadar eksekusi fungsi dengan pengecekan `assert(condition)`. Pengujian unit skala produksi bersandar pada paket resmi `package:test` (dan fondasinya `test_core`), yang menyediakan *test runner*, *assertion framework*, serta *execution harness* yang terisolasi.

#### Mengapa Tidak Menggunakan `assert` Bawaan Bahasa?
Keyword `assert` bawaan Dart dievaluasi hanya pada *debug mode* (dengan flag `--enable-asserts`) dan diabaikan sepenuhnya di *production mode* (AOT/JIT release). Selain itu, jika `assert` gagal, ia hanya melempar `AssertionError` generik tanpa informasi diagnostik mendalam mengenai objek yang dibandingkan (misalnya: *diffing* struktur data kompleks, representasi tipe runtime, atau inspeksi tumpukan asinkron).

#### Arsitektur Matcher & Declarative Assertions
`package:test` menggunakan pola desain **Matcher** yang memisahkan:
1. **Target yang diuji (`actual`)**: Nilai nyata hasil eksekusi unit kode.
2. **Kriteria validasi (`matcher`)**: Objek turunan dari kelas abstrak `Matcher` yang mendefinisikan logika perbandingan dan mekanisme serialisasi pesan kegagalan.

Sintaks dasarnya adalah:
```dart
void expect(dynamic actual, dynamic matcher, {String? reason});
```

Di balik layar, `expect()` tidak langsung membandingkan kesetaraan referensial (`identical`) atau operator `==` saja. Jika argumen `matcher` bukan merupakan instansi `Matcher`, Dart secara implisit membungkusnya dengan `equals(matcher)`. Ketika kecocokan gagal, `Matcher` membangun representasi teks terstruktur (*failure description*) yang membedah letak ketidaksesuaian secara presisi (seperti indeks array yang salah, field spesifik pada *nested object*, atau perbedaan tipe data).

#### Zone-based Isolation
Setiap fungsi `test()` dieksekusi di dalam `Zone` Dart yang dikustomisasi oleh internal `package:test` (via kelas `Invoker`). `Zone` bertindak sebagai *asynchronous dynamic extent* yang:
- Mencegat (*intercept*) unhandled asynchronous exceptions sehingga tidak merusak proses utama *test runner*.
- Mengisolasi dan mengukur eksekusi waktu (*timeout tracking*).
- Menangkap keluaran I/O (seperti `print`) dan mengasosiasikannya secara eksklusif ke unit tes yang bersangkutan.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi sistem manajemen dompet digital (`WalletService`) beserta rangkaian pengujian komprehensif menggunakan `package:test` modern (Dart 3.x).

```dart
// ==========================================
// KODE PRODUKSI: lib/wallet_service.dart
// ==========================================

sealed class WalletException implements Exception {
  final String message;
  const WalletException(this.message);

  @override
  String toString() => '$runtimeType: $message';
}

final class InsufficientFundsException extends WalletException {
  final double currentBalance;
  final double attemptedAmount;

  const InsufficientFundsException(this.currentBalance, this.attemptedAmount)
      : super('Saldo tidak mencukupi untuk penarikan.');
}

final class InvalidAmountException extends WalletException {
  const InvalidAmountException(super.message);
}

final class WalletService {
  double _balance;
  final List<String> _transactionLogs = [];

  WalletService({double initialBalance = 0.0}) : _balance = initialBalance {
    if (initialBalance < 0) {
      throw const InvalidAmountException('Saldo awal tidak boleh negatif.');
    }
  }

  double get balance => _balance;
  List<String> get logs => List.unmodifiable(_transactionLogs);

  void deposit(double amount) {
    if (amount <= 0) {
      throw const InvalidAmountException('Jumlah deposit harus lebih dari 0.');
    }
    _balance += amount;
    _transactionLogs.add('DEPOSIT: +$amount');
  }

  Future<void> withdrawAsync(double amount) async {
    // Simulasi latensi verifikasi I/O atau jaringan
    await Future<void>.delayed(const Duration(milliseconds: 10));

    if (amount <= 0) {
      throw const InvalidAmountException('Jumlah penarikan harus lebih dari 0.');
    }
    if (amount > _balance) {
      throw InsufficientFundsException(_balance, amount);
    }
    _balance -= amount;
    _transactionLogs.add('WITHDRAW: -$amount');
  }
}

// ==========================================
// KODE TESTING: test/wallet_service_test.dart
// ==========================================

import 'package:test/test.dart';
// import 'package:my_app/wallet_service.dart';

void main() {
  group('WalletService Unit Tests', () {
    late WalletService wallet;

    // Eksekusi sebelum SETIAP unit tes di dalam group ini
    setUp(() {
      wallet = WalletService(initialBalance: 100.0);
    });

    // Eksekusi setelah SETIAP unit tes di dalam group ini
    tearDown(() {
      // Pembersihan state / mocking jika diperlukan
    });

    group('Inisialisasi', () {
      test('harus menginisialisasi saldo awal dengan benar', () {
        expect(wallet.balance, equals(100.0));
        expect(wallet.logs, isEmpty);
      });

      test('harus melempar InvalidAmountException jika saldo awal negatif', () {
        expect(
          () => WalletService(initialBalance: -50.0),
          throwsA(
            isA<InvalidAmountException>().having(
              (e) => e.message,
              'pesan kesalahan',
              contains('tidak boleh negatif'),
            ),
          ),
        );
      });
    });

    group('Operasi Deposit (Sinkron)', () {
      test('harus menambah saldo dan mencatat log transaksi secara valid', () {
        wallet.deposit(50.0);

        expect(wallet.balance, equals(150.0));
        expect(
          wallet.logs,
          allOf([
            hasLength(1),
            contains('DEPOSIT: +50.0'),
          ]),
        );
      });

      test('harus gagal saat deposit bernilai nol atau negatif', () {
        expect(
          () => wallet.deposit(0.0),
          throwsA(isA<InvalidAmountException>()),
        );
        expect(
          () => wallet.deposit(-10.0),
          throwsA(isA<InvalidAmountException>()),
        );
        // Memastikan state tidak termutasi saat terjadi eksepsi
        expect(wallet.balance, equals(100.0));
      });
    });

    group('Operasi Penarikan / Withdraw (Asinkron)', () {
      test('harus mengurangi saldo ketika nominal penarikan valid', () async {
        await expectLater(wallet.withdrawAsync(40.0), completes);
        expect(wallet.balance, equals(60.0));
        expect(wallet.logs, contains('WITHDRAW: -$40.0'));
      });

      test('harus melempar InsufficientFundsException beserta detail konteks yang valid', () async {
        final withdrawFuture = wallet.withdrawAsync(150.0);

        await expectLater(
          withdrawFuture,
          throwsA(
            isA<InsufficientFundsException>()
                .having((e) => e.currentBalance, 'currentBalance', 100.0)
                .having((e) => e.attemptedAmount, 'attemptedAmount', 150.0),
          ),
        );

        // Memastikan saldo tidak berkurang
        expect(wallet.balance, equals(100.0));
      });
    });
  });
}
```

#### Bedah Komponen Krusial:
1. `throwsA()`: Menangkap eksepsi dari closure sinkron (`() => ...`) atau langsung dari objek `Future`.
2. `isA<T>()`: Memverifikasi tipe polimorfis secara *type-safe* tanpa perlu melakukan *casting manual*.
3. `.having(closure, description, matcher)`: Teknik deep inspection pada atribut objek target untuk memastikan bukan hanya tipenya yang tepat, melainkan isi field internalnya valid.
4. `expectLater()`: Varian `expect()` yang mengembalikan `Future<void>`, wajib digunakan dengan `await` pada assertions asinkron agar test runner menunggu resolusi assertion sebelum menutup siklus pengujian.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime Test Runner
Ketika Anda menjalankan perintah `dart test`:
1. **Compilation Phase**: Dart Test CLI mengompilasi file pengujian ke dalam format kernel binary (`.dill`) secara inkremental.
2. **Isolate Spawning**: Runner mengeksekusi suite pengujian di dalam **Isolate baru** (bukan di isolate utama CLI runner). Hal ini mencegah leaking memori antar suite file tes yang berbeda.
3. **Declarative Discovery**: Saat method `main()` pada file tes dijalankan, deklarasi `test()` dan `group()` sebenarnya tidak langsung mengeksekusi logika tes. Fungsi-fungsi tersebut mendaftarkan fungsi callback dan metadata ke dalam singleton `Declarer`. Setelah pohon hierarki selesai dideklarasikan, `RemoteListener` mulai menjadwalkan eksekusi tes secara berurutan.

#### Alokasi Memori & Lifecycle Hooks
- Variabel yang diinstansiasi di luar blok `setUp()` atau pada tingkat file (global scope) akan menetap (*retained*) selama seluruh suite dalam file tersebut berjalan.
- Pola `late WalletService wallet;` di dalam cakupan `group` yang diinisialisasi ulang di dalam `setUp()` memastikan referensi objek lama dilepaskan ke Garbage Collector (GC) setiap kali tes baru dimulai, mencegah **cross-test state contamination**.

#### Event Loop & Asynchronous Pumping
Ketika menguji `Future` atau `Stream`:
- Dart tidak melakukan pemblokiran thread (*thread blocking*).
- Assertion `completes` mendaftarkan callback listener ke `Future` yang diuji. Kontrol runtime diserahkan kembali ke **Dart Event Loop**.
- Jika pengujian selesai tanpa `await` pada assertion asinkron, `Invoker` Zone mungkin menganggap tes sukses secara prematur padahal ada microtask atau event yang melempar `Exception` setelah tes berakhir. Kasus ini memicu *Uncaught Asynchronous Error* yang merusak integritas runner.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Matcher `isA<T>().having()`**: Selalu validasi data internal eksepsi, jangan hanya memeriksa tipenya saja.
- **Terapkan Prinsip AAA (Arrange, Act, Assert)**: Buat pemisahan visual yang jelas antara persiapan data, eksekusi unit, dan verifikasi assertion.
- **Hermetic Testing**: Setiap blok `test()` harus independen dan *idempotent*. Hasil `test('A')` tidak boleh menjadi prasyarat bagi suksesnya `test('B')`.

#### Don'ts
- **Menghindari `expect` Mengambang (Floating Futures)**:
  ```dart
  // SALAH (Race condition: test selesai sebelum assertion dievaluasi)
  test('unawaited async', () {
    wallet.withdrawAsync(200.0);
    expect(wallet.withdrawAsync(200.0), throwsA(anything));
  });

  // BENAR
  test('properly awaited async', () async {
    await expectLater(wallet.withdrawAsync(200.0), throwsA(isA<InsufficientFundsException>()));
  });
  ```
- **Jangan Menggunakan Assertion `expect` di dalam `catch` block manual**:
  ```dart
  // SALAH
  try {
    wallet.deposit(-1);
  } catch (e) {
    expect(e, isA<InvalidAmountException>()); // Jika deposit TIDAK melempar exception, tes tetap PASSED!
  }

  // BENAR
  expect(() => wallet.deposit(-1), throwsA(isA<InvalidAmountException>()));
  ```

#### Edge Cases
- **Custom Equality (`==`)**: Jika membandingkan objek komposit buatan sendiri tanpa `package:equatable` atau tanpa override `operator ==` dan `hashCode`, Matcher `equals(objek)` akan jatuh ke perbandingan identitas referensial (`identical`), menyebabkan assertion gagal meskipun nilai seluruh atributnya identik.

### 5. Tantangan Eksplorasi Mandiri

1. **Rancang Custom Matcher**: Buat sebuah kelas yang meng-extend `Matcher` bernama `IsValidIndonesianPhoneNumber` yang memvalidasi apakah sebuah string diawali dengan `+62` atau `08`, memiliki panjang antara 10–13 digit, dan menghasilkan pesan kegagalan yang deskriptif melalui method `describe()` dan `describeMismatch()`.
2. **Asynchronous Stream Testing**: Implementasikan class `EventTracker` yang memancarkan `Stream<int>`. Tulis unit test untuk memvalidasi pancaran data berkala menggunakan Matcher `emitsInOrder()`, `emitsError()`, dan `emitsDone`. Pastikan tidak terjadi *resource leak* dengan menutup controller menggunakan `tearDown()`.
