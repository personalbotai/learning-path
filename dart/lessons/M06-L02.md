## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dart mengadopsi model konkurensi berbasis *single-threaded execution per isolate*. Berbeda dengan runtime multi-threaded berbasis shared-memory (seperti Java atau C#), Dart mengeksekusi seluruh instruksi kode di dalam satu thread utama yang dikendalikan oleh **Event Loop**. Konsekuensinya, tidak ada *race condition* berbasis shared-memory di dalam satu isolate, dan locking primitives (seperti mutex/semaphore) tidak diperlukan.

#### Anatomi Event Loop Dart
Runtime Dart memproses instruksi melalui dua antrean utama:
1. **Microtask Queue**: Menyimpan tugas-tugas internal berdurasi sangat singkat yang harus dieksekusi secara sinkron sebelum kontrol dikembalikan ke siklus event berikutnya.
2. **Event Queue**: Menyimpan event eksternal seperti I/O operasi (disk, network), timer tick, user input (pada Flutter), serta event pesan antar-isolate.

```
       [Start]
          │
          ▼
┌──────────────────┐
│ Microtask Queue? ├─(Ya)──> [Eksekusi Microtask] ──┐
└─────────┬────────┘                                │
         (Tidak)                                    │
          ▼                                         │
┌──────────────────┐                                │
│   Event Queue?   ├─(Ya)──> [Eksekusi 1 Event]     │
└─────────┬────────┘                │               │
         (Tidak)                    └───────────────┤
          ▼                                         │
       [Exit] <─────────────────────────────────────┘
```

Setiap putaran (*tick*) dari Event Loop akan menguras habis isi **Microtask Queue** terlebih dahulu sebelum mengambil **satu** event dari **Event Queue**. Pola ini diulang terus-menerus hingga kedua antrean kosong.

#### Arsitektur `Future<T>`
`Future<T>` adalah representasi objek dari sebuah komputasi yang nilainya belum tersedia saat eksekusi dimulai. Objek ini beroperasi melalui tiga state:
- **Uncompleted**: Operasi sedang berjalan; `Future` belum menghasilkan data atau error.
- **Completed with Value**: Komputasi berhasil dan menghasilkan nilai bertipe `T`.
- **Completed with Error**: Komputasi gagal dan mengembalikan exception/error bertipe `Object`.

Di balik layar, instansiasi `Future` default (misalnya via konstruktor `Future(...)`) akan mendaftarkan sebuah event ke dalam **Event Queue**. Sebaliknya, `Future.microtask(...)` mendaftarkan callback langsung ke **Microtask Queue**.

#### Transformasi `async` dan `await`
Sintaks `async`/`await` adalah *syntactic sugar* tingkat compiler yang mengeliminasi *callback hell* dari rantai `Future.then()`. Ketika compiler Dart (baik AOT maupun JIT/dart2js) menemukan fungsi bertanda `async`, ia mengubah bodi fungsi tersebut menjadi sebuah **State Machine** (berbasis Continuation-Passing Style).

Ketika eksekusi menemui keyword `await`:
1. Ekspresi yang di-`await` dievaluasi dan dipastikan dibungkus menjadi `Future`.
2. State machine menyimpan variabel lokal dan *instruction pointer* saat ini.
3. Fungsi segera menangguhkan (*suspend*) eksekusinya dan mengembalikan `Future` yang belum selesai (*uncompleted*) ke pemanggil (*caller*).
4. Runtime mendaftarkan kelanjutan (*continuation callback*) dari state machine tersebut sebagai listener pada `Future` yang ditunggu. Callback ini akan dimasukkan ke dalam **Microtask Queue** saat `Future` tersebut selesai.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut menunjukkan orkestrasi pemanggilan API terdistribusi: mengambil metadata profil pengguna dan daftar order secara paralel, serta menangani error menggunakan arsitektur `Future` modern.

```dart
import 'dart:async';

// Domain Models
final class UserProfile {
  final String id;
  final String name;
  const UserProfile(this.id, this.name);

  @override
  String toString() => 'UserProfile(id: $id, name: $name)';
}

final class OrderSummary {
  final String orderId;
  final double totalAmount;
  const OrderSummary(this.orderId, this.totalAmount);

  @override
  String toString() => 'OrderSummary(orderId: $orderId, amount: $totalAmount)';
}

final class DashboardData {
  final UserProfile profile;
  final List<OrderSummary> recentOrders;
  const DashboardData(this.profile, this.recentOrders);
}

// Service Simulation
class DashboardService {
  Future<UserProfile> _fetchUserProfile(String userId) async {
    // Simulasi network I/O via Event Queue
    await Future.delayed(const Duration(milliseconds: 150));
    if (userId.isEmpty) {
      throw ArgumentError('User ID tidak boleh kosong.');
    }
    return UserProfile(userId, 'Alex River');
  }

  Future<List<OrderSummary>> _fetchRecentOrders(String userId) async {
    await Future.delayed(const Duration(milliseconds: 200));
    return const [
      OrderSummary('ORD-001', 250000.0),
      OrderSummary('ORD-002', 120000.0),
    ];
  }

  /// Mengambil data dashboard secara konkuren untuk meminimalkan latency.
  Future<DashboardData> getDashboard(String userId) async {
    try {
      // Menjalankan kedua operasi paralel (bukan sequential)
      // Future.wait mendaftarkan listener ke kedua future secara konkuren.
      final results = await Future.wait([
        _fetchUserProfile(userId),
        _fetchRecentOrders(userId),
      ], eagerError: true); // eagerError langsung membatalkan jika ada salah satu yang fail

      final profile = results[0] as UserProfile;
      final orders = results[1] as List<OrderSummary>;

      return DashboardData(profile, orders);
    } on ArgumentError catch (e, stackTrace) {
      // Handle domain-specific validation error
      Zone.current.handleUncaughtError(e, stackTrace);
      rethrow;
    } catch (e) {
      // Fallback atau error remapping
      throw Exception('Gagal memuat data dashboard: $e');
    }
  }
}

void main() async {
  print('--- 1. Eksekusi Sinkron Dimulai ---');

  // Menunjukkan prioritas Event vs Microtask Queue
  scheduleMicrotask(() {
    print('--- 3. Microtask Queue Dieksekusi ---');
  });

  Future(() {
    print('--- 4. Event Queue Biasa Dieksekusi ---');
  });

  final service = DashboardService();

  print('--- 2. Memanggil getDashboard (Non-blocking) ---');
  try {
    final dashboard = await service.getDashboard('USR-108');
    print('--- 5. Hasil Diterima: ${dashboard.profile} ---');
    print('       Jumlah Order: ${dashboard.recentOrders.length}');
  } catch (error) {
    print('Error tertangkap: $error');
  }

  print('--- 6. Eksekusi Selesai ---');
}
```

#### Penjelasan Alur Eksekusi:
1. `main()` berjalan secara sinkron, mencetak log nomor 1 dan 2.
2. `scheduleMicrotask` memasukkan closure ke Microtask Queue.
3. `Future()` memasukkan closure ke Event Queue.
4. Ketika `await service.getDashboard(...)` dipanggil, `main()` menangguhkan eksekusi dirinya sendiri. Kontrol kembali ke Event Loop.
5. Event Loop menyelesaikan semua antrean Microtask terlebih dahulu (Mencetak log nomor 3), kemudian beralih ke Event Queue (Mencetak log nomor 4).
6. Begitu `Future.wait` selesai di dalam service, kelanjutan dari `main()` di-jadwalkan ulang ke Microtask Queue, mengeksekusi log nomor 5 dan 6.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Desugaring State Machine
Ketika sebuah fungsi ditandai dengan `async`, compiler Dart membungkusnya dalam kelas internal bertipe `_AsyncAwaitCompleter` dan membagi bodi fungsi ke dalam blok-blok *state switch*.

```dart
// Kode Konseptual Internal Compiler
void _stateMachine(int state, dynamic result, dynamic error) {
  switch (state) {
    case 0:
      // Kode sebelum await pertama
      var future = expression();
      future.then(
        (val) => _stateMachine(1, val, null),
        onError: (err) => _stateMachine(1, null, err)
      );
      return;
    case 1:
      // Lanjutan setelah await pertama
      if (error != null) throw error;
      // Gunakan result...
  }
}
```
Ketika eksekusi fungsi di-suspend, frame eksekusi dilepaskan dari Call Stack native thread C++. Variabel lokal disimpan di dalam heap (sebagai properti dari context objek state machine). Inilah yang memungkinkan thread utama Dart bebas memproses event UI/I/O lain selagi menunggu I/O selesai tanpa memblokir CPU.

#### Alokasi Memori & Resource
- **Closure Allocation**: Setiap pemanggilan `await` atau `.then()` mengalokasikan objek callback closure di memori heap isolate.
- **Context Preservation**: Variabel yang hidup melintasi titik `await` (*cross-await variables*) tidak dapat dialokasikan pada CPU stack register; variabel ini dialokasikan ke objek konteks berbasis heap, yang meningkatkan beban Garbage Collection (GC) jika dibuat berulang kali di dalam loop ketat (*hot paths*).
- **`_Future<T>` Node**: Sebuah instance `_Future` internal mengalokasikan linked-list node untuk setiap listener yang terdaftar (`_FutureListener`).

#### Trade-offs: Concurrency vs CPU-bound Task
- **Kelebihan**: Sangat efisien untuk I/O-bound operations. Memory footprint per operasi asinkron jauh lebih kecil dibanding alokasi thread native OS (yang membutuhkan default stack memory ~1-2 MB per thread).
- **Kekurangan**: Karena tetap berjalan di satu thread OS, operasi komputasi berat (misalnya hashing data besar, parsing JSON berukuran puluhan megabyte, manipulasi matriks gambar) akan **memblokir seluruh Event Loop**. Solusi untuk CPU-bound task bukanlah `Future`, melainkan komputasi paralel menggunakan **Isolate terpisah**.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `Future.wait` untuk operasi independen**: Jika Anda perlu memanggil dua endpoint yang tidak saling bergantung, jangan lakukan `await` secara sekuensial. Jalankan keduanya secara konkuren.
  ```dart
  // BENAR: Menghemat waktu (Total waktu = max(T1, T2))
  final userFuture = api.getUser();
  final configFuture = api.getConfig();
  final (user, config) = await (userFuture, configFuture).wait; // Record wait syntax (Dart 3+)
  ```
- **Tandai Fire-and-Forget dengan `unawaited`**: Jika Anda mengeksekusi asynchronous operation tanpa `await`, gunakan fungsi `unawaited` dari `dart:async` untuk memberi sinyal pada linter bahwa Anda sengaja tidak menunggu hasilnya.
  ```dart
  unawaited(analyticsService.logEvent('page_view'));
  ```

#### Don'ts
- **Hindari Sequential Await yang Tidak Perlu**:
  ```dart
  // SALAH: Latensi bertambah secara linear (Total waktu = T1 + T2)
  final user = await api.getUser();
  final config = await api.getConfig(); // Menunggu user selesai padahal tidak bergantung
  ```
- **Jangan Menggunakan `async` Jika Tidak Ada `await`**:
  ```dart
  // SALAH: Overhead pembuatan State Machine dan Future instance yang tidak perlu
  Future<int> getConstant() async {
    return 42;
  }

  // BENAR: Langsung kembalikan Future tersinkronisasi
  Future<int> getConstant() => Future.value(42);
  ```

#### Edge Cases & Pitfalls
- **Microtask Queue Starvation**: Jika Anda menjadwalkan `scheduleMicrotask` secara rekursif atau berlebihan, runtime tidak akan pernah memiliki kesempatan untuk mengambil event dari Event Queue. Akibatnya: I/O berhenti, rendering UI Flutter akan *freeze* total (ANR).
- **Unhandled Async Errors**: Error yang dilempar di dalam `Future` tanpa blok `try/catch` atau tanpa didaftarkan `.catchError()` dapat lolos keluar isolate jika tidak dilindungi oleh root `Zone`. Error ini menyebabkan aplikasi crash secara diam-diam (*silent crash*) atau terminasi runtime.

### 5. Tantangan Eksplorasi Mandiri

1. **Analisis Execution Order**: Prediksi urutan keluaran console dari kode berikut sebelum menjalankannya, lalu jelaskan mengapa urutannya terbentuk demikian berdasarkan siklus Microtask vs Event Queue:
   ```dart
   import 'dart:async';

   void main() {
     print('1');
     scheduleMicrotask(() => print('2'));
     Future.delayed(Duration.zero, () => print('3'));
     Future(() => print('4')).then((_) => scheduleMicrotask(() => print('5')));
     Future.microtask(() => print('6'));
     print('7');
   }
   ```
2. **Implementasi Retry Mechanism dengan Exponential Backoff**:
   Bangun fungsi `Future<T> retry<T>(Future<T> Function() operation, {int maxAttempts, Duration delay})` yang akan mengeksekusi ulang operasi jika menemui error jaringan, menggandakan delay di setiap kegagalan, dan melempar error final jika mencapai batas maksimum percobaan. Pastikan mekanisme tidak memblokir Event Loop.
3. **Async Batch Processor (Rate Limiting)**:
   Buat sebuah class `AsyncQueuePool` yang membatasi konkurensi pemanggilan `Future` (misalnya: maksimal 3 operasi I/O berjalan bersamaan). Jika ada 10 task yang didaftarkan sekaligus, hanya 3 yang dieksekusi pertama kali, dan task ke-4 baru dijalankan segera setelah salah satu dari 3 task awal selesai. Lakukan ini tanpa dependency eksternal.
