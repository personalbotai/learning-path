## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Paket (*package*) di ekosistem Dart adalah unit modular terkecil yang dapat didistribusikan, memuat kode, aset, dependensi, hingga perkakas eksekusi (*tools*). Memahami arsitektur paket tidak hanya sebatas mengisi `pubspec.yaml`, melainkan memahami mekanisme isolasi batas pustaka (*library boundary isolation*), resolusi AST (*Abstract Syntax Tree*) oleh Dart Analyzer, dan standarisasi skor kualitas pada registry `pub.dev`.

```
my_package/
├── .dart_tool/           # Metadata kompilasi & package_config.json
├── lib/
│   ├── my_package.dart   # Public API (Barrel file)
│   └── src/              # Private implementation details
│       ├── core.dart
│       └── utils.dart
├── test/
├── doc/
├── pubspec.yaml          # Manifest paket & constraint dependensi
├── CHANGELOG.md          # History rilis (Wajib untuk pub.dev)
├── LICENSE               # Lisensi open-source (OSI approved)
└── README.md             # Landing page dokumentasi utama
```

#### Enkapsulasi: Konvensi `lib/` dan `lib/src/`
Kompiler dan penganalisis statis (*analyzer*) Dart menerapkan aturan privasi pustaka berbasis tata letak direktori:
- Kode di bawah `lib/` yang berada di luar subdirektori `src/` dianggap sebagai **Public API**. Kode ini dapat diimpor langsung oleh konsumen paket (`import 'package:my_package/my_package.dart';`).
- Kode di dalam `lib/src/` adalah **Private Implementation**. Meskipun Dart tidak memblokir impor `package:my_package/src/...` di tingkat *runtime*, Dart Analyzer akan menandainya sebagai lint violation (`implementation_imports`). Arsitektur yang baik menggunakan pola *Barrel File* di `lib/my_package.dart` yang mengekspos representasi publik menggunakan statement `export ... show ...;`.

#### Dokumentasi Teknis via `dartdoc`
Tool bawaan `dart doc` membedah komentar dokumentasi (`///`) secara statis melalui representasi AST dari kode Dart. Ia menyelesaikan relasi tipe, tautan silang (*intra-doc cross-linking* seperti `[MyClass]`), dan markdown internal. Fitur tingkat lanjut seperti macro template (`{@template}`) dan penyembunyian API internal dari dokumentasi (`@nodoc`) dieksekusi pada fase kompilasi AST sebelum keluaran HTML/JSON dihasilkan.

#### Ekosistem Publikasi dan `pana`
Ketika sebuah paket dipublikasikan ke `pub.dev`, paket tersebut tidak hanya di-hosting. Mesin backend `pub.dev` memicu **pana** (*Package Analysis*). Pana mengevaluasi:
1. Kesesuaian kaidah konvensi struktur repositori.
2. Analisis statis tanpa peringatan (*zero warnings*).
3. Kelengkapan dokumentasi (*dartdoc coverage* minimal 20% untuk bobot penuh).
4. Kompatibilitas multi-platform (apakah ada impor `dart:io` yang membatasi paket tidak bisa berjalan di Web).
5. Kepatuhan Semantic Versioning (SemVer 2.0.0).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi pustaka enkripsi token tiruan (`token_vault`) yang menerapkan enkapsulasi ketat, dokumentasi tingkat lanjut (`dartdoc`), dan konfigurasi publikasi yang siap lolos uji `pana`.

#### 1. File Konfigurasi: `pubspec.yaml`
```yaml
name: token_vault
version: 1.0.0
description: A high-performance, deterministic token generation and verification vault for Dart services.
repository: https://github.com/example/token_vault
issue_tracker: https://github.com/example/token_vault/issues
topics:
  - cryptography
  - security
  - tokens

environment:
  sdk: '^3.3.0'

dependencies:
  crypto: ^3.0.3

dev_dependencies:
  lints: ^3.0.0
  test: ^1.24.0
```

#### 2. Implementasi Internal: `lib/src/vault_engine.dart`
```dart
import 'dart:convert';
import 'package:crypto/crypto.dart';

/// Mesin kriptografi dasar yang diisolasi dari konsumsi publik.
/// 
/// Menggunakan {@template hashing_algo}HMAC-SHA256{@endtemplate}
/// untuk kalkulasi integritas token.
class VaultEngine {
  final List<int> _secretBytes;

  /// Inisialisasi engine dengan secret key.
  VaultEngine(String secret) : _secretBytes = utf8.encode(secret);

  /// Menghasilkan hash berbasis {@macro hashing_algo}.
  String computeSignature(String payload) {
    final hmac = Hmac(sha256, _secretBytes);
    final digest = hmac.convert(utf8.encode(payload));
    return digest.toString();
  }
}
```

#### 3. Public API / Barrel File: `lib/token_vault.dart`
```dart
/// Pustaka utama untuk penanganan token aman.
///
/// Untuk memulai, inisialisasi instance [TokenVault] dan panggil [TokenVault.sign]:
/// ```dart
/// final vault = TokenVault(secret: 'my-super-secret-key');
/// final token = vault.sign('user_id_42');
/// print('Generated Token: $token');
/// ```
library token_vault;

import 'src/vault_engine.dart';

export 'src/vault_engine.dart' show VaultEngine; // Hanya jika VaultEngine ingin diekspos sebagian

/// {@template token_vault}
/// Layanan tingkat tinggi untuk enkapsulasi penandatanganan dan validasi token.
/// {@endtemplate}
class TokenVault {
  final VaultEngine _engine;

  /// Membuat instance baru dari [TokenVault].
  ///
  /// Parameter [secret] harus memiliki entropi tinggi dan tidak boleh kosong.
  /// Melempar [ArgumentError] jika [secret] kosong.
  TokenVault({required String secret}) {
    if (secret.trim().isEmpty) {
      throw ArgumentError.value(secret, 'secret', 'Secret tidak boleh kosong.');
    }
    _engine = VaultEngine(secret);
  }

  /// Menandatangani string [payload] dan mengembalikan token gabungan.
  ///
  /// Format keluaran adalah `base64(payload).signature`.
  /// Lihat juga metode verifikasi internal untuk validasi balikan.
  String sign(String payload) {
    final encodedPayload = base64Url.encode(utf8.encode(payload));
    final signature = _engine.computeSignature(encodedPayload);
    return '$encodedPayload.$signature';
  }

  /// Memverifikasi keabsahan [token].
  ///
  /// Mengembalikan payload asli berformat UTF-8 jika valid, atau `null` jika signature
  /// tidak cocok atau struktur token rusak.
  String? verify(String token) {
    final parts = token.split('.');
    if (parts.length != 2) return null;

    final encodedPayload = parts[0];
    final signature = parts[1];

    final expectedSignature = _engine.computeSignature(encodedPayload);
    if (signature != expectedSignature) {
      return null;
    }

    try {
      return utf8.decode(base64Url.decode(encodedPayload));
    } catch (_) {
      return null;
    }
  }
}
```

#### 4. Validasi dan Rilis Menggunakan CLI
```bash
# 1. Pastikan analisis statis 100% bersih tanpa warning/hint
dart analyze --fatal-infos

# 2. Uji fungsionalitas paket
dart test

# 3. Generate dan verifikasi dokumentasi HTML secara lokal
dart doc .

# 4. Validasi kondisi pra-publikasi (Dry Run)
dart pub publish --dry-run

# 5. Publikasikan ke pub.dev (Hanya dilakukan setelah dry-run sukses)
dart pub publish
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Resolusi Runtime (`package_config.json`)
Ketika runtime atau kompilator Dart (`dart compile exe/aot`) memproses import `package:token_vault/...`, ia tidak mencari direktori fisik secara heuristik. Dart memeriksa berkas `.dart_tool/package_config.json`. Berkas ini memetakan identifier namespace paket ke path absolut atau relatif pada filesystem lokal (`rootUri`). Jika struktur `package_config.json` inkonsisten atau paket belum diunduh (`dart pub get`), *Virtual File System (VFS)* pada kompilator gagal mengurai modul dan menghentikan fase kompilasi di tahap parse pipeline frontend (`kernel_service`).

```json
{
  "configVersion": 2,
  "packages": [
    {
      "name": "token_vault",
      "rootUri": "../",
      "packageUri": "lib/",
      "languageVersion": "3.3"
    },
    {
      "name": "crypto",
      "rootUri": "file:///Users/dev/.pub-cache/hosted/pub.dev/crypto-3.0.3",
      "packageUri": "lib/",
      "languageVersion": "3.0"
    }
  ]
}
```

#### Alokasi Memori, AST, & Tree-Shaking
- **Fase Analisis Dokumen (`dartdoc`)**: `dartdoc` tidak mengeksekusi program. Kompiler memuat seluruh target berkas ke dalam AST memori melalui pustaka internal `analyzer`. Semua macro `{@template}` disubstitusi di tingkat parser AST sebelum serialisasi HTML, membutuhkan konsumsi RAM proporsional terhadap jumlah *symbol declaration* pada project besar.
- **Tree-Shaking di Client**: Jika konsumen paket hanya menggunakan satu fungsi dari file barrel yang mengekspor 20 class, kompilator AOT (AOT backend) akan membangun call graph hierarkis (*TFA - Type Flow Analysis*). Kelas atau pustaka di dalam `lib/src/` yang tidak memiliki jangkauan eksekusi (*unreachable code*) akan dieliminasi total dari binary image akhir.

#### Mekanisme Publikasi Tarball & Immutability
Saat Anda menjalankan `dart pub publish`:
1. Tool pub membuat arsip gzipped tarball (`.tar.gz`) dari direktori paket Anda, mengecualikan berkas yang tertera pada `.gitignore` dan aturan default (seperti `.dart_tool/`, `build/`).
2. Tarball diunggah ke Google Cloud Storage bucket milik `pub.dev`.
3. Setelah berhasil diverifikasi melalui token OAuth/OIDC, paket bersifat **Immutable**. Anda tidak bisa memperbarui kode pada versi yang sama (`1.0.0`). Setiap perbaikan bug atau perubahan dokumentasi *harus* memicu kenaikan versi SemVer baru untuk menjamin reproduktibilitas build dependensi downstream.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Semantic Versioning Secara Disiplin**:
  - `PATCH` (1.0.1): Bug fix internal, tidak ada perubahan antarmuka publik.
  - `MINOR` (1.1.0): Penambahan fungsionalitas baru yang *backward-compatible*.
  - `MAJOR` (2.0.0): Perubahan tanda tangan fungsi, penghapusan API lama, atau perubahan perilaku fatal.
- **Terapkan OIDC (OpenID Connect) untuk CI/CD Publishing**: Jangan simpan API credential jangka panjang pada GitHub Actions. Gunakan integrasi native OIDC antara GitHub Actions dan `pub.dev` via tag `permissions: id-token: write`.
- **Gunakan `[TipeData]` pada Dokumentasi**: Selalu gunakan tanda kurung siku agar `dartdoc` meresolusi tipe data tersebut menjadi tautan hidup ke kelas atau metode terkait.

#### Don'ts
- **Dilarang Mengekspor File `src/` Sembarangan**: Jangan mengekspos model internal ke API publik tanpa alasan arsitektural. Sekali kelas diekspor dari barrel file, mengubah konstruktor kelas tersebut berpotensi menjadi *breaking change* bagi pengguna paket Anda.
- **Hindari Impor Platfrom-Specific Tanpa Abstraksi**: Mengimpor `dart:io` secara langsung di kelas inti akan menggugurkan tag platform **Web** pada skor pana `pub.dev`. Gunakan conditional import jika paket ditujukan cross-platform:
  ```dart
  import 'src/stub_io.dart'
      if (dart.library.io) 'src/native_io.dart'
      if (dart.library.js_interop) 'src/web_io.dart';
  ```

#### Edge Cases
- **Leak Interface via Inheritance**: Jika Anda mengekspos abstract class yang ditujukan hanya untuk diimplementasi oleh internal paket, tandai kelas tersebut sebagai `interface class` atau `final class` (fitur Dart 3 Class Modifiers). Tanpa ini, pengguna eksternal dapat melakukan `extend` atau `implement`, dan ketika Anda menambahkan method baru di versi `MINOR`, aplikasi pengguna akan rusak (*compile error*), melanggar aturan SemVer.

### 5. Tantangan Eksplorasi Mandiri

1. **Simulasi Audit Kualitas Pana**:
   Pasang global CLI pana (`dart pub global activate pana`) dan jalankan `pana .` pada proyek paket lokal Anda. Analisis output JSON/laporannya, lalu modifikasi kode Anda hingga mendapatkan skor maksimal: **140/140 Pub Points**.
2. **Dokumentasi Macro Bersarang**:
   Buat dua kelas terpisah di `lib/src/`. Gunakan `{@template base_desc}` di kelas pertama, dan panggil `{@macro base_desc}` di kelas kedua. Eksekusi `dart doc .` dan buka file HTML di direktori `doc/api/` untuk memverifikasi apakah parsing teks berhasil disalin dengan presisi oleh AST resolver.
