### 1. Konsep & Arsitektur Mendalam

Dart Foreign Function Interface (FFI) adalah mekanisme tingkat rendah yang memungkinkan Dart VM mengeksekusi kode mesin yang dikompilasi dari bahasa berlandaskan C ABI (seperti C, C++, Rust, atau Zig) secara langsung di dalam ruang alamat memori (*address space*) proses yang sama.

```
+-----------------------------------------------------------------+
|                       Dart Isolate Process                      |
|                                                                 |
|  +--------------------+             +------------------------+  |
|  |   Dart GC Heap     |             |   Native Memory        |  |
|  |  (Managed Memory)  |             |  (Off-Heap / Malloc)   |  |
|  +---------+----------+             +-----------+------------+  |
|            |                                    ^               |
|            | Pointer<T> wrapping address        |               |
|            +------------------------------------+               |
|                                                                 |
|  +--------------------+   ABI Call (cdecl, SysV) +-----------+  |
|  | Dart Machine Code  | -----------------------> | Shared Lib|  |
|  | (JIT / AOT Engine) | <----------------------- | (.so/.dylib) |
|  +--------------------+       Zero-Copy Data     +-----------+  |
+-----------------------------------------------------------------+
```

#### Perbedaan Fundamental: Dart FFI vs Platform Channels
Pada Flutter/Dart multi-platform, integrasi native sering diasosiasikan dengan *Platform Channels*. Namun secara arsitektur:
- **Platform Channels** mengandalkan asynchronous Inter-Process/Thread Communication (IPC) via `BinaryMessenger`. Data harus diserialisasi menjadi biner (menggunakan codec standar), dikirim melintasi thread engine ke Android (JVM/ART via JNI) atau iOS (Obj-C/Swift Runtime), lalu dideserialisasi kembali. Latensinya tinggi dan memicu alokasi memori berlebih (*serialization overhead*).
- **Dart FFI** beroperasi via *Dynamic Linking*. Dart AOT/JIT compiler menghasilkan instruksi mesin pemanggilan fungsi (*call instruction*) langsung ke library biner (`.so`, `.dylib`, atau `.dll`) yang dimuat ke memori. Menggunakan prinsip **Zero-Copy**, Dart dapat membaca dan memodifikasi *raw byte* di off-heap memory tanpa konversi ke managed object.

#### Representasi Tipe Data Native
C dan Dart memiliki sistem tipe yang berbeda:
1. **Representasi Statis vs Instansiasi**: Tipe `dart:ffi` seperti `Int32`, `Double`, `Pointer`, atau `Struct` bukanlah class biasa yang dapat diinstansiasi secara bebas di Dart. Tipe-tipe ini adalah *marker types* untuk compiler agar mengetahui ukuran *byte* (*alignment* & *padding*) serta layout register mesin target.
2. **Type Mapping**:
   - `NativeFunction<T>`: Representasi tipe signature fungsi di sisi C ABI.
   - `asFunction<T>()`: Metode Dart extension yang mengubah representasi `NativeFunction` menjadi First-Class Dart Function closure.
   - Pointer type (`Pointer<T>`): Menampung alamat memori 64-bit (atau 32-bit pada arsitektur tertentu) ke lokasi memori off-heap.

### 2. Implementasi & Contoh Kasus Nyata

Kita akan membuat library C native untuk memproses komputasi vektor 2D dan manipulasi teks, lalu mengintegrasikannya ke Dart menggunakan `dart:ffi` dan `package:ffi`.

#### 1. Implementasi C (`native_math.c`)
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// Definisi Struct C
typedef struct {
    double x;
    double y;
} Vector2D;

// Ekspor simbol secara eksplisit
#if defined(_WIN32)
#define EXPORT __declspec(dllexport)
#else
#define EXPORT __attribute__((visibility("default")))
#endif

EXPORT double calculate_magnitude(const Vector2D* vec) {
    if (vec == NULL) return 0.0;
    return (vec->x * vec->x) + (vec->y * vec->y); // Mengembalikan squared magnitude demi efisiensi
}

EXPORT char* transform_string(const char* input) {
    if (input == NULL) return NULL;
    
    size_t len = strlen(input);
    char* result = (char*)malloc(len + 1);
    
    for (size_t i = 0; i < len; i++) {
        // Simple Caesar cipher shift +1
        result[i] = input[i] + 1;
    }
    result[len] = '\0';
    return result;
}

EXPORT void free_native_string(char* ptr) {
    if (ptr != NULL) {
        free(ptr);
    }
}
```

*Kompilasi C menjadi shared library:*
```bash
# Linux/macOS
gcc -shared -fPIC -O3 native_math.c -o libnative_math.so # .dylib untuk macOS
```

#### 2. Implementasi Dart FFI (`main.dart`)
```dart
import 'dart:ffi' as ffi;
import 'dart:io' show Platform;
import 'package:ffi/ffi.dart';

// 1. Representasikan C Struct ke Dart
final class Vector2D extends ffi.Struct {
  @ffi.Double()
  external double x;

  @ffi.Double()
  external double y;
}

// 2. Definisi Native Signatures & Dart Signatures
// C: double calculate_magnitude(const Vector2D* vec);
typedef NativeCalculateMagnitude = ffi.Double Function(ffi.Pointer<Vector2D>);
typedef DartCalculateMagnitude = double Function(ffi.Pointer<Vector2D>);

// C: char* transform_string(const char* input);
typedef NativeTransformString = ffi.Pointer<Utf8> Function(ffi.Pointer<Utf8>);
typedef DartTransformString = ffi.Pointer<Utf8> Function(ffi.Pointer<Utf8>);

// C: void free_native_string(char* ptr);
typedef NativeFreeString = ffi.Void Function(ffi.Pointer<Utf8>);
typedef DartFreeString = void Function(ffi.Pointer<Utf8>);

void main() {
  // 3. Resolusi Path Dynamic Library
  final libraryPath = Platform.isLinux
      ? './libnative_math.so'
      : Platform.isMacOS
          ? './libnative_math.dylib'
          : 'native_math.dll';

  final dylib = ffi.DynamicLibrary.open(libraryPath);

  // 4. Look-up function pointers
  final DartCalculateMagnitude calculateMagnitude = dylib
      .lookup<ffi.NativeFunction<NativeCalculateMagnitude>>('calculate_magnitude')
      .asFunction();

  final DartTransformString transformString = dylib
      .lookup<ffi.NativeFunction<NativeTransformString>>('transform_string')
      .asFunction();

  final DartFreeString freeNativeString = dylib
      .lookup<ffi.NativeFunction<NativeFreeString>>('free_native_string')
      .asFunction();

  // 5. Kasus A: Menggunakan Struct & Manual Allocator
  // Gunakan 'using' dan Arena agar alokasi dijamin di-free setelah eksekusi blok
  using((Arena arena) {
    // Mengalokasikan memori struct di native heap
    final ffi.Pointer<Vector2D> vecPtr = arena<Vector2D>();
    vecPtr.ref.x = 3.0;
    vecPtr.ref.y = 4.0;

    final magnitude = calculateMagnitude(vecPtr);
    print('Vector Squared Magnitude: $magnitude'); // 25.0
  });

  // 6. Kasus B: String Interop & Native Heap Management
  using((Arena arena) {
    final rawInput = 'Dart FFI Engine';
    // Mengonversi UTF-16 Dart String ke UTF-8 C string di native memory
    final ffi.Pointer<Utf8> nativeInput = rawInput.toNativeUtf8(allocator: arena);

    // Memanggil native function
    final ffi.Pointer<Utf8> resultPtr = transformString(nativeInput);

    if (resultPtr != ffi.nullptr) {
      try {
        // Konversi C Pointer byte kembali ke Dart String
        final dartStringResult = resultPtr.toDartString();
        print('Transformed Native String: $dartStringResult');
      } finally {
        // PENTING: Memori 'resultPtr' dialokasikan oleh malloc di native_math.c,
        // sehingga harus dibebaskan menggunakan native free dari library yang sama.
        freeNativeString(resultPtr);
      }
    }
  });
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Calling Convention Bridge**: Ketika `dylib.lookup(...).asFunction()` dieksekusi, Dart VM menghasilkan potongan kode dinamis (*trampoline stub*). Stub ini bertanggung jawab menyalin argumen dari stack/register Dart VM ke register arsitektur CPU target sesuai standar ABI host (contoh: System V AMD64 ABI menggunakan register `RDI`, `RSI`, `RDX`, `RCX`, `R8`, `R9` untuk argumen integer/pointer, serta register `XMM0-XMM7` untuk floating point).
- **Zero-Copy Memory**: Objek `Pointer` hanya menyimpan alamat virtual 64-bit (*unsigned int address*). Saat `pointer.ref` diakses, Dart langsung memetakan operasi pembacaan ke instruksi *memory dereference* CPU (seperti `MOV [RAX]`) tanpa adanya instansiasi managed heap object intermediate.

#### Alokasi Memori / Resource
- **Off-Heap Allocation**: Native memory yang dialokasikan lewat `calloc()`, `malloc()`, atau `arena()` berada sepenuhnya di luar jangkauan Dart Garbage Collector (GC). GC tidak memiliki visibility terhadap ukuran native memory ini.
- **Fragmentasi & Memory Leaks**: Jika `free()` gagal dipanggil pada sebuah pointer, memori native tersebut akan terus tersita (*leak*) sampai proses OS ditutup secara total, meskipun Dart isolate yang mereferensikannya telah hancur.

#### Trade-offs
- **Segfaults Are Fatal**: Berbeda dengan exception runtime Dart yang dapat ditangani dengan `try-catch`, pembacaan pointer yang *out-of-bounds*, *nullptr dereference*, atau *use-after-free* pada C native library akan langsung memicu signal `SIGSEGV` / `Access Violation` dan mematikan seluruh OS Process tanpa stack trace Dart yang bersih.
- **Thread Blocking**: Invokasi native function via Dart FFI berjalan secara sinkron pada thread isolate pemanggil. Jika fungsi native C melakukan komputasi berat selama 3 detik, UI loop atau event loop Dart akan terblokir (*freeze*) selama 3 detik.

### 4. Best Practices & Common Pitfalls

#### Do's
1. **Gunakan `using(Arena)` untuk alokasi transien**: Mengurangi risiko lupa memanggil `malloc.free()`.
2. **Gunakan `NativeFinalizer` untuk Native Resources jangka panjang**: Jika mengikat native handle (misal: file descriptor C / pointer C struct) ke Dart wrapper object, kaitkan dengan `NativeFinalizer` agar saat instance Dart dikumpulkan oleh GC, native destructor otomatis dipanggil.
3. **Eksekusi FFI Berat di Worker Isolate**: Gunakan `Isolate.run()` atau `compute()` untuk komputasi native intensif agar event loop utama (termasuk UI pipeline Flutter) tetap responsif.
4. **Validasi `nullptr`**: Selalu pastikan `pointer != nullptr` sebelum membaca properti `.ref` atau `.value`.

#### Don'ts
1. **Jangan gunakan allocator yang salah**: Jangan pernah membebaskan memori yang dialokasikan oleh C `malloc` menggunakan Dart `calloc.free()`, atau sebaliknya jika di-link dengan compiler toolchain runtime C yang berbeda (terutama di Windows di mana CRT runtime bisa berbeda antar DLL). Gunakan fungsi free yang diekspor langsung oleh library bersangkutan.
2. **Jangan asumsikan Dart String adalah Utf8**: String di Dart secara internal adalah UTF-16. Konversi ke `Pointer<Utf8>` melibatkan alokasi byte array baru dan iterasi. Selalu bersihkan hasil konversi tersebut.
3. **Hindari Passing Raw Pointer antar Isolate tanpa sinkronisasi**: Memori off-heap dapat diakses lintas Isolate, tetapi Anda harus mengelola concurrency synchronization (race condition) secara mandiri karena Dart GC tidak mengawasi native memory tersebut.

#### Edge Cases
- **Struct Packing & Alignment**: Kompiler C sering melakukan *padding* byte pada struct demi data alignment CPU register. Jika struct C didefinisikan dengan `#pragma pack(push, 1)`, Dart Struct juga harus ditandai dengan `@Packed(1)`. Jika tidak cocok, parsing field struct akan korup atau bergeser secara offset.
