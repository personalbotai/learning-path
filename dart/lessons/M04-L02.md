## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum Dart 3.0, pengembang Dart menghadapi dilema klasik saat membutuhkan fungsi yang mengembalikan lebih dari satu nilai (*multiple returns*):
1. Membuat class boilerplate baru (sering kali memerlukan package seperti `freezed` atau `equatable`).
2. Menggunakan package pihak ketiga seperti `tuple`.
3. Menggunakan struktur data generik seperti `List<dynamic>` atau `Map<String, dynamic>`, yang mengorbankan *type safety* dan performa runtime.

Dart 3.0 memperkenalkan **Records** dan **Destructuring/Pattern Matching** untuk menyelesaikan masalah ini secara mendasar pada level arsitektur bahasa.

```
       +-------------------------------------------------------+
       |                     Dart Source                       |
       |  final (status, :message) = fetchResponse();          |
       +-------------------------------------------------------+
                                  |
                           Frontend Compiler (CFE)
                                  |
              +-------------------+-------------------+
              | Validasi Shape & Tipe                |
              | Synthesize Structural Equality        |
              +---------------------------------------+
                                  |
       +-------------------------------------------------------+
       |               Kernel AST Representation               |
       |  - Instansiasi RecordShape (_Record2, dsb.)           |
       |  - Pattern dimatangkan menjadi ekstraksi properti      |
       +-------------------------------------------------------+
              |                                       |
              v                                       v
      [ AOT/JIT Compilation ]                   [ Dart2JS / DDC ]
  Record flat struct + Tagged Pointer    JS Plain Object / Array Array-like
```

#### Karakteristik Arsitektur Record:
- **Anonymous & Aggregate**: Record adalah kumpulan data heterogen tanpa nama kelas formal, tetapi memiliki skema struktural (*structural shape*).
- **First-Class Citizens**: Record dapat disimpan dalam variabel, diteruskan sebagai argumen, disimpan dalam koleksi, dan dikembalikan dari fungsi.
- **Value-type Equality**: Dua record dianggap identik (`==`) jika memiliki *shape* yang sama (jumlah, posisi, dan nama *field* identik) serta nilai setiap *field*-nya sama secara struktural.
- **Immutable**: Nilai di dalam record tidak dapat diubah setelah diinstansiasi.

#### Pola Destrukturisasi (Pattern Matching):
Destrukturisasi adalah proses membongkar (*unpacking*) struktur data gabungan (Record, List, Map, atau Object) menjadi variabel-variabel individual. Pada level sintaksis, pemanggilan destrukturisasi mencerminkan bentuk (*shape*) dari data yang dibongkar.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah contoh implementasi idiomatik pengolahan data geospasial dan respons API menggunakan Record dan Pattern Destructuring:

```dart
// 1. Deklarasi Type Alias untuk Record (Opsional, untuk keterbacaan domain)
typedef Coordinates = (double latitude, double longitude);
typedef ApiResponse<T> = ({int statusCode, T? data, String? error});

// 2. Fungsi yang mengembalikan Multiple Returns via Record
ApiResponse<Coordinates> resolveUserLocation(Map<String, dynamic> rawPayload) {
  try {
    // Validasi payload menggunakan pattern matching pada Map
    if (rawPayload case {
      'geo': {'lat': num lat, 'lng': num lng}
    }) {
      return (
        statusCode: 200,
        data: (lat.toDouble(), lng.toDouble()),
        error: null,
      );
    }
    
    return (
      statusCode: 400,
      data: null,
      error: 'Format payload tidak valid: lat/lng hilang',
    );
  } catch (e) {
    return (statusCode: 500, data: null, error: e.toString());
  }
}

void main() {
  final payload = {
    'user': 'alice',
    'geo': {'lat': -6.2088, 'lng': 106.8456}
  };

  // 3. Destructuring Named Record & Positional Record secara Bersarang (Nested)
  final (:statusCode, :data, :error) = resolveUserLocation(payload);

  // 4. Pattern Matching dengan Switch Expression
  final statusMessage = switch (statusCode) {
    200 when data != null => () {
      // Destrukturisasi positional record
      final (lat, lng) = data;
      return 'Lokasi ditemukan: Lat $lat, Lng $lng';
    }(),
    400 => 'Bad Request: $error',
    500 => 'Internal Error: $error',
    _ => 'Status code tidak dikenal: $statusCode',
  };

  print(statusMessage);

  // 5. Destructuring pada Deklarasi Variabel & Swapping Nilai
  var a = 'Alpha';
  var b = 'Beta';
  (b, a) = (a, b); // Swap in-place tanpa variabel temporal manual
  print('a: $a, b: $b'); // Output: a: Beta, b: Alpha

  // 6. Identifier-Only Destructuring Shorthand (:fieldName)
  final userRecord = (id: 101, username: 'johndoe', role: 'admin');
  final (:id, :username, :role) = userRecord;
  print('User $username (ID: $id) memiliki hak akses: $role');
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime:
Di balik layar, Dart Kernel tidak membuat class terpisah di level kode sumber untuk setiap deklarasi Record. Sebaliknya, compiler mengelompokkan Record berdasarkan **Record Shape**. 
- Record Shape didefinisikan oleh:
  1. Jumlah positional fields (*arity*).
  2. Kumpulan nama field (*named fields*), yang selalu diurutkan secara leksikografis oleh compiler untuk memastikan konsistensi kanonikal.
- Pemanggilan getter seperti `$1` atau `$name` tidak melalui *dynamic invocation*. Pada AOT (Ahead-of-Time), ini dikompilasi menjadi *direct offset access* pada memori struktur record, setara kecepatannya dengan mengakses *final field* dari kelas biasa.

#### Alokasi Memori / Resource:
- **Dart VM / AOT**: Record direpresentasikan sebagai instansiasi kelas internal VM (misalnya `_Record2`, `_Record3` untuk optimasi arity kecil, atau instansiasi kelas record generik untuk arity besar).
- **Structural Equality**: Compiler secara otomatis menginjeksi implementasi `operator ==` dan `hashCode` deterministik:
  $$\text{Record.hashCode} = \text{combine}(\text{shapeId}, \text{hash}(f_1), \text{hash}(f_2), \dots)$$
- Objek Record dialokasikan di *Heap* (khususnya *Nursery Space* pada Generational Garbage Collector Dart). Namun, karena Record bersifat *immutable* dan sering kali memiliki *lifespan* pendek (misalnya hanya untuk membongkar return value), alokasi ini sangat murah dan cepat dibersihkan oleh Scavenger GC. Pada beberapa skenario optimasi AOT tingkat lanjut (*escape analysis*), VM berpotensi melakukan *scalar replacement* untuk mengeliminasi alokasi heap sepenuhnya.

#### Trade-offs:
- **Record vs Class**: Record tidak mendukung pewarisan (*inheritance*), tidak dapat memiliki metode privat/publik sendiri, dan tidak memiliki identitas memori unik (`identical()` tidak dapat diandalkan secara konsisten antar platform karena compiler dapat menyatukan record yang identik/canonicalization).
- **Overhead**: Record dengan banyak field (terutama > 5) menurunkan performa pembacaan kode (*readability*) dan menghasilkan kode inspeksi `hashCode` yang semakin panjang secara runtime.

### 4. Best Practices & Common Pitfalls

#### Do's:
- **Gunakan Named Fields jika field > 2**: Record `(String, String, int)` ambigu saat dibaca. Gunakan `({String firstName, String lastName, int age})` untuk menjaga kejelasan makna data.
- **Manfaatkan Destructuring Shorthand**: Gunakan sintaks `final (:name, :age) = personRecord;` daripada `final name = personRecord.name; final age = personRecord.age;`.
- **Gunakan Exhaustiveness Check**: Kombinasikan Pattern Matching dengan `switch` expression untuk memastikan compiler memvalidasi semua kemungkinan kondisi skema data.

#### Don'ts:
- **Jangan Gantikan Domain Entity Inti**: Jangan mengganti kelas model/entitas domain yang kompleks menggunakan Record. Jika data memiliki *lifecycle*, invariant bisnis yang harus divalidasi, atau membutuhkan method, gunakan Class.
- **Jangan Mengabaikan Positional Typo**: Hindari menukar posisi tipe data yang sama pada positional records, misalnya `(double latitude, double longitude)`. Jika tertukar di *call-site* `(lng, lat)`, compiler tidak akan mengeluarkan error type.

#### Edge Cases & Trap:
- **Single-element Positional Record**: Sintaks `(int)` dievaluasi oleh Dart parser sebagai ekspresi pengelompokan matematika bertipe `int`. Untuk membuat single-element positional record, wajib menyertakan tanda koma: `(int,)`.
  ```dart
  var notARecord = (42);    // Tipe: int
  var isARecord  = (42,);   // Tipe: (int,)
  ```
- **Mutable Object di Dalam Record**: Record itu sendiri bersifat *immutable* (strukturnya tidak dapat ditambah/dikurang/diubah), tetapi jika Record menyimpan objek *mutable* (misalnya `List`), mutasi pada elemen list akan merusak konsistensi `hashCode`:
  ```dart
  final record = ([1, 2], 'metadata');
  record.$1.add(3); // Legal secara runtime, tetapi merusak keandalan Record sebagai Map Key!
  ```
