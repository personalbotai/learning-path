## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam paradigma *Reactive Programming* di Dart, `StreamController` adalah jantung dari pembuatan dan manajemen *Stream* kustom. Jika `Stream` adalah pipa tempat data mengalir (hanya bisa dibaca/didengarkan), maka `StreamController` adalah mesin pompa sekaligus katup inputnya. 

Secara arsitektur, `StreamController` mengimplementasikan pola **Producer-Consumer**:
- **Producer (Input)**: Menggunakan `EventSink` (biasanya diakses via `controller.sink`), developer secara imperatif memasukkan data, error, atau sinyal selesai (`close`) ke dalam pipeline.
- **Consumer (Output)**: Menggunakan `Stream` (diakses via `controller.stream`), komponen lain bereaksi terhadap perubahan state secara asinkron.

**Mengapa ini penting?**
`StreamController` adalah fondasi dari hampir semua arsitektur *State Management* reaktif di ekosistem Dart/Flutter (seperti BLoC atau Redux-Epics). Ia memungkinkan pemisahan yang tegas antara *business logic* (yang memompa data) dan *UI/Presentation layer* (yang mendengarkan data), menciptakan **Reactive State Pipeline** yang *unidirectional* (satu arah).

Terdapat dua jenis arsitektur Controller:
1. **Single-Subscription (Default)**: Hanya mengizinkan satu *listener*. Jika belum ada yang mendengarkan, event akan di-*buffer* (disimpan di memori).
2. **Broadcast**: Mengizinkan banyak *listener*. Event yang dipancarkan saat tidak ada *listener* akan dibuang (*dropped*), tidak di-*buffer*.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi *Reactive State Pipeline* untuk sistem *Shopping Cart* sederhana. Kita akan menyembunyikan `StreamController` agar state tidak bisa dimanipulasi dari luar secara sembarangan.

```dart
import 'dart:async';

// 1. Representasi State (Immutable)
class CartState {
  final List<String> items;
  final bool isLoading;
  final String? error;

  CartState({this.items = const [], this.isLoading = false, this.error});
}

// 2. Reactive Pipeline Class
class CartPipeline {
  // Controller dienkapsulasi (private). Menggunakan broadcast agar bisa didengar banyak UI widget.
  final StreamController<CartState> _controller = StreamController<CartState>.broadcast();
  
  // Cache state terakhir (mirip konsep BehaviorSubject di RxDart)
  CartState _currentState = CartState();

  // Expose HANYA stream-nya ke publik
  Stream<CartState> get stateStream => _controller.stream;
  
  // Getter untuk state sinkron saat ini
  CartState get currentState => _currentState;

  // 3. Mutator Methods (Input Pipeline)
  void addItem(String item) {
    _emit(CartState(items: _currentState.items, isLoading: true));
    
    // Simulasi network delay
    Future.delayed(Duration(milliseconds: 500), () {
      if (item.isEmpty) {
        _emit(CartState(items: _currentState.items, error: "Item tidak valid!"));
        return;
      }
      
      final updatedItems = List<String>.from(_currentState.items)..add(item);
      _emit(CartState(items: updatedItems, isLoading: false));
    });
  }

  // Internal method untuk memancarkan state baru
  void _emit(CartState newState) {
    if (_controller.isClosed) return;
    _currentState = newState;
    _controller.sink.add(newState); // Memompa data ke pipeline
  }

  // Wajib dipanggil untuk mencegah memory leak
  void dispose() {
    _controller.close();
  }
}

void main() async {
  final cart = CartPipeline();

  // Consumer 1: UI Logger
  final sub1 = cart.stateStream.listen(
    (state) => print('[UI 1] Items: ${state.items} | Loading: ${state.isLoading} | Error: ${state.error}'),
    onError: (err) => print('Terjadi kesalahan fatal: $err'),
  );

  // Consumer 2: Analytics Pipeline (Transformasi Stream)
  final sub2 = cart.stateStream
      .where((state) => !state.isLoading && state.error == null)
      .map((state) => state.items.length)
      .listen((count) => print('[Analytics] Total item di keranjang: $count'));

  // Producer memicu perubahan state
  cart.addItem("Laptop");
  await Future.delayed(Duration(seconds: 1));
  
  cart.addItem(""); // Memicu error state
  await Future.delayed(Duration(seconds: 1));

  // Cleanup
  await sub1.cancel();
  await sub2.cancel();
  cart.dispose();
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (Event Loop)**: 
  Secara default, `StreamController` beroperasi secara asinkron (`sync: false`). Ketika Anda memanggil `sink.add()`, event tersebut tidak langsung dieksekusi oleh *listener*. Dart akan membungkus event tersebut dan menaruhnya di **Event Queue**. *Listener* baru akan bereaksi pada siklus *Event Loop* berikutnya. Jika Anda menggunakan `StreamController(sync: true)`, event akan dieksekusi secara sinkron (langsung memanggil *callback listener* di *call stack* yang sama), yang lebih cepat namun berisiko memblokir eksekusi jika prosesnya berat.
- **Alokasi Memori / Resource**: 
  Setiap `StreamController` mengalokasikan memori untuk *buffer queue* (terutama pada *single-subscription*). Jika *listener* lambat memproses data (backpressure) atau tidak ada *listener* sama sekali, *buffer* ini akan terus membesar dan menyebabkan *Out of Memory* (OOM).
- **Trade-offs**: 
  Menggunakan *Broadcast Stream* mengorbankan *buffering* demi *multiple subscribers*. Jika sebuah event dipancarkan sebelum *listener* melakukan `listen()`, event tersebut hilang selamanya. Oleh karena itu, pola caching state (seperti variabel `_currentState` pada contoh di atas) sering diperlukan.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - **Selalu panggil `close()`** pada `StreamController` saat instance kelas induknya dihancurkan (misal di metode `dispose()` pada Flutter).
  - **Enkapsulasi Controller**: Jadikan `StreamController` sebagai variabel `private` (`_controller`) dan hanya ekspos `Stream`-nya. Ini mencegah komponen luar menyuntikkan data kotor ke dalam pipeline.
  - Gunakan `StreamTransformer` (seperti `map`, `where`, `asyncMap`) untuk memanipulasi data di dalam pipeline sebelum sampai ke UI.

- **Don'ts**:
  - **Jangan memanggil `sink.add()` setelah `close()`**. Ini akan melempar `StateError` dan membuat aplikasi *crash*. Selalu cek `if (!_controller.isClosed)`.
  - **Jangan gunakan `sync: true`** kecuali Anda benar-benar memahami dampaknya terhadap *Event Loop*. Penggunaan yang salah dapat merusak urutan eksekusi asinkron aplikasi Anda.

- **Edge Cases**:
  - **Unhandled Stream Errors**: Jika Anda memanggil `sink.addError()` dan *Stream* tersebut tidak memiliki blok `onError` pada `listen()`, error tersebut akan lolos ke *global error handler* dan berpotensi menghentikan aplikasi. Selalu tangani error di ujung pipeline.

### 5. Tantangan Eksplorasi Mandiri

1. **Buat Custom BehaviorSubject**: Dart standar tidak memiliki `BehaviorSubject` (Stream yang mengingat nilai terakhirnya dan langsung memberikannya ke *listener* baru) seperti di RxDart. Cobalah buat kelas `BehaviorController<T>` menggunakan `StreamController.broadcast()` yang mengimplementasikan fitur ini dari nol.
2. **Implementasi Debouncer Pipeline**: Buat sebuah pipeline menggunakan `StreamController` dan `Timer` di mana jika `sink.add()` dipanggil berkali-kali dalam waktu cepat (misal input pencarian), *Stream* hanya akan memancarkan data setelah tidak ada input baru selama 500ms.
