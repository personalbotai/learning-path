### 1. Konsep & Arsitektur Mendalam

Protokol WebSocket (RFC 6455) menyediakan kanal komunikasi *bi-directional* (dua arah) dan *full-duplex* yang berjalan di atas satu koneksi TCP persisten. Berbeda dengan model *stateless request-response* pada HTTP/1.1 yang membutuhkan inisiasi koneksi baru (atau negosiasi `Keep-Alive`) dan membawa beban *overhead* HTTP *header* di setiap pertukaran data, WebSocket meminimalkan latensi secara ekstrem melalui arsitektur *framing* ringan.

```
Client                                                  Server
  |                                                       |
  | -------- 1. HTTP GET (Upgrade: websocket) ----------> |
  | <------- 2. HTTP 101 Switching Protocols ------------ | [Handshake Fase]
  |                                                       |
  | <================ 3. TCP Socket Persisten ==========> | [Bi-directional Data]
  |      [Frame: Text/Binary/Ping/Pong, Overhead 2-14B]   |
  |                                                       |
```

#### Siklus Hidup dan Handshake
1. **HTTP Upgrade Request:** Klien menginisiasi koneksi TCP standar dan mengirimkan HTTP GET dengan *header* khusus:
   * `Upgrade: websocket`
   * `Connection: Upgrade`
   * `Sec-WebSocket-Key`: Token Base64 acak 16-byte untuk verifikasi.
   * `Sec-WebSocket-Version: 13`
2. **Protocol Switching:** Server merespons dengan HTTP Status Code `101 Switching Protocols` dan *header* `Sec-WebSocket-Accept` (SHA-1 hash dari `Sec-WebSocket-Key` + UUID khusus RFC 6455 yang di-encode ke Base64).
3. **Framing Layer:** Setelah *handshake* sukses, lapisan aplikasi berpindah dari parser HTTP ke parser *frame* WebSocket. Komunikasi dipecah menjadi *data frame* (Text/Binary) dan *control frame* (Ping, Pong, Close) dengan beban *header* hanya berkisar antara 2 hingga 14 byte, jauh lebih efisien dibandingkan *header* HTTP yang berukuran ratusan hingga ribuan byte.

#### Abstraksi WebSocket dalam Dart
Di ekosistem Dart, arsitektur WebSocket berakar pada konsep reaktif primitif: **`Stream`** untuk konsumsi data masuk (*inbound*) dan **`StreamSink`** untuk pengiriman data keluar (*outbound*).
* **`dart:io` (`WebSocket`)**: Menyediakan implementasi native langsung yang memanfaatkan asynchronous socket binding dari sistem operasi melalui C++ layer Dart VM.
* **`package:web_socket_channel` (`WebSocketChannel`)**: Abstraksi tingkat tinggi lintas platform yang menyatukan perilaku `dart:io` (VM/Flutter Mobile/Desktop) dan `dart:html` / `package:web` (Flutter Web / Browser environment) di bawah interface `StreamChannel`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi *production-ready* dari `WebSocketClient` menggunakan Dart murni (memanfaatkan `dart:io`). Kode ini dirancang dengan isolasi status koneksi, mekanisme *exponential backoff reconnect*, integrasi *heartbeat* (Ping/Pong), dan *thread-safe event dispatching* melalui `StreamController.broadcast()`.

```dart
import 'dart:async';
import 'dart:convert';
import 'dart:io';
import 'dart:math';

enum ConnectionStatus { disconnected, connecting, connected }

class RealtimeMessage {
  final String topic;
  final dynamic payload;
  final DateTime timestamp;

  RealtimeMessage({
    required this.topic,
    required this.payload,
    DateTime? timestamp,
  }) : timestamp = timestamp ?? DateTime.now();

  factory RealtimeMessage.fromJson(Map<String, dynamic> json) {
    return RealtimeMessage(
      topic: json['topic'] as String,
      payload: json['payload'],
      timestamp: json['timestamp'] != null 
          ? DateTime.parse(json['timestamp'] as String) 
          : null,
    );
  }

  Map<String, dynamic> toJson() => {
        'topic': topic,
        'payload': payload,
        'timestamp': timestamp.toIso8601String(),
      };
}

class RobustWebSocketClient {
  final Uri uri;
  final Duration pingInterval;
  
  WebSocket? _socket;
  StreamSubscription? _socketSubscription;
  Timer? _reconnectTimer;
  
  int _reconnectAttempts = 0;
  static const int _maxReconnectAttempts = 5;
  static const Duration _baseDelay = Duration(seconds: 1);

  final _statusController = StreamController<ConnectionStatus>.broadcast();
  final _messageController = StreamController<RealtimeMessage>.broadcast();

  Stream<ConnectionStatus> get statusStream => _statusController.stream;
  Stream<RealtimeMessage> get messageStream => _messageController.stream;
  ConnectionStatus _currentStatus = ConnectionStatus.disconnected;

  RobustWebSocketClient({
    required this.uri,
    this.pingInterval = const Duration(seconds: 30),
  });

  Future<void> connect() async {
    if (_currentStatus == ConnectionStatus.connected || 
        _currentStatus == ConnectionStatus.connecting) {
      return;
    }

    _updateStatus(ConnectionStatus.connecting);

    try {
      // Menginisiasi koneksi socket melalui Dart VM I/O runtime
      _socket = await WebSocket.connect(
        uri.toString(),
      ).timeout(const Duration(seconds: 10));

      // Native ping interval untuk keep-alive TCP & deteksi dead-socket
      _socket!.pingInterval = pingInterval;

      _updateStatus(ConnectionStatus.connected);
      _reconnectAttempts = 0;

      // Berlangganan ke Stream incoming frame
      _socketSubscription = _socket!.listen(
        _onDataReceived,
        onError: _handleError,
        onDone: _handleDone,
        cancelOnError: false,
      );
    } catch (e) {
      _handleError(e);
    }
  }

  void _onDataReceived(dynamic rawData) {
    try {
      if (rawData is String) {
        final decoded = jsonDecode(rawData) as Map<String, dynamic>;
        final message = RealtimeMessage.fromJson(decoded);
        _messageController.add(message);
      } else if (rawData is List<int>) {
        // Fallback decoder jika binary frame diterima (UTF-8 binary payload)
        final stringPayload = utf8.decode(rawData);
        final decoded = jsonDecode(stringPayload) as Map<String, dynamic>;
        _messageController.add(RealtimeMessage.fromJson(decoded));
      }
    } catch (err, stack) {
      // Mengabaikan frame parsing error agar stream pipeline tidak terputus
      stderr.writeln('[WebSocket] Malformed Frame Error: $err\n$stack');
    }
  }

  void send(String topic, dynamic payload) {
    if (_currentStatus != ConnectionStatus.connected || _socket == null) {
      throw StateError('Cannot send frame: WebSocket is not connected.');
    }

    final message = RealtimeMessage(topic: topic, payload: payload);
    final serialized = jsonEncode(message.toJson());
    
    // Mengirim payload sebagai Text Frame
    _socket!.add(serialized);
  }

  void _handleError(dynamic error) {
    stderr.writeln('[WebSocket] Transport Error: $error');
    _teardownSocket();
    _scheduleReconnect();
  }

  void _handleDone() {
    stdout.writeln('[WebSocket] Connection closed by host or socket terminated.');
    _teardownSocket();
    _scheduleReconnect();
  }

  void _scheduleReconnect() {
    if (_reconnectAttempts >= _maxReconnectAttempts) {
      _updateStatus(ConnectionStatus.disconnected);
      stderr.writeln('[WebSocket] Max reconnect attempts reached. Halting pipeline.');
      return;
    }

    _updateStatus(ConnectionStatus.disconnected);

    // Exponential Backoff dengan penambahan Random Jitter: Base * 2^attempt + Jitter
    final backoffSeconds = _baseDelay.inSeconds * pow(2, _reconnectAttempts);
    final jitter = Random().nextDouble();
    final delay = Duration(milliseconds: ((backoffSeconds + jitter) * 1000).toInt());

    _reconnectAttempts++;
    stdout.writeln('[WebSocket] Reconnecting in ${delay.inMilliseconds}ms (Attempt $_reconnectAttempts)...');

    _reconnectTimer?.cancel();
    _reconnectTimer = Timer(delay, () => connect());
  }

  void _teardownSocket() {
    _socketSubscription?.cancel();
    _socketSubscription = null;
    _socket?.close(WebSocketStatus.goingAway);
    _socket = null;
  }

  void _updateStatus(ConnectionStatus newStatus) {
    _currentStatus = newStatus;
    _statusController.add(newStatus);
  }

  Future<void> dispose() async {
    _reconnectTimer?.cancel();
    _reconnectAttempts = _maxReconnectAttempts; // Cegah reconnect otomatis
    _teardownSocket();
    await _statusController.close();
    await _messageController.close();
  }
}

void main() async {
  // Menggunakan public mock echo server (misal: postman-echo)
  final client = RobustWebSocketClient(
    uri: Uri.parse('wss://ws.postman-echo.com/raw'),
    pingInterval: const Duration(seconds: 15),
  );

  client.statusStream.listen((status) {
    stdout.writeln('>>> Connection State Shift: $status');
  });

  client.messageStream.listen((msg) {
    stdout.writeln('<<< Inbound Message: [${msg.topic}] ${msg.payload}');
  });

  await client.connect();

  // Test kirim payload real-time
  Timer.periodic(const Duration(seconds: 3), (timer) {
    if (timer.tick > 2) {
      timer.cancel();
      client.dispose();
      return;
    }
    client.send('telemetry/sensor', {'cpu_load': 42.5 + timer.tick});
  });
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Event Loop dan Native Poller
WebSocket di Dart tidak membuat *thread OS* tersendiri untuk menangani *polling* data. Sebaliknya, Dart mengeksekusinya di dalam **Single Isolate Event Loop**:
1. Saat `WebSocket.connect()` dipanggil, Dart VM mendelegasikan inisiasi TCP Socket ke subsistem I/O C++ runtime.
2. Runtime mendaftarkan file descriptor (socket descriptor) ke *system event demultiplexer* milik OS:
   * **Linux/Android**: `epoll`
   * **macOS/iOS**: `kqueue`
   * **Windows**: `IOCP` (I/O Completion Ports)
3. Ketika paket data TCP tiba di kartu jaringan (NIC), kernel OS membangkitkan interupsi, memperbarui status *socket descriptor*, dan membangunkan Dart VM internal thread.
4. Dart VM mengambil *raw bytes*, menyusunnya ke dalam *WebSocket Frame*, lalu menaruh event baru ke dalam **Dart Event Queue**. Event Loop kemudian memproses callback `onData` pada micro-tick berikutnya.

#### Alokasi Memori / Resource
* **Frame Masking (RFC 6455)**: Sesuai regulasi keamanan protokol, setiap *frame* dari klien ke server **wajib** di-*masking* menggunakan 4-byte *masking key* acak. Dart VM mengeksekusi operasi XOR bitwise untuk mengacak isi payload sebelum dikirim ke socket TCP guna mencegah serangan *cache poisoning* pada intermediate proxy.
* **Buffer Allocation**: Dart VM mengalokasikan memori native di luar *Garbage Collector Managed Heap* (C-heap) untuk menampung *raw stream TCP chunk*. Data ini baru disalin (*copied*) ke Dart Heap saat dikonversi menjadi instansi `Uint8List` atau `String`.
* **Backpressure Management**: Jika WebSocket menerima *burst* puluhan ribu pesan per detik dan pemrosesan komputasi di `onData` lambat, `StreamController` akan menampung pesan tersebut di dalam antrean memori internal (*unbounded memory buffer*). Tanpa kontrol aliran data, situasi ini dapat memicu **Out-Of-Memory (OOM)** crash.

#### Trade-offs: WebSocket vs SSE vs WebTransport
| Metrik / Fitur | WebSockets (RFC 6455) | Server-Sent Events (SSE) | WebTransport (HTTP/3) |
| :--- | :--- | :--- | :--- |
| **Arah Komunikasi** | Full-Duplex (Dua arah) | Simplex (Server ke Klien) | Multiplexed Bi-directional |
| **Protokol Transport**| TCP (rentan Head-of-Line Blocking) | TCP (HTTP/1.1 atau HTTP/2) | UDP via QUIC (Bebas HoL Blocking) |
| **Tipe Data** | Binary & Text Frame murni | UTF-8 Text saja | Streams & Datagrams (Unreliable/Reliable) |
| **Overhead Koneksi** | Sangat rendah pasca-handshake | Menengah (bergantung HTTP overhead) | Sangat rendah pasca-0-RTT Handshake |
| **Kematangan di Dart** | **Sangat Matang** (`dart:io` & package) | Standar (via `dart:io` HttpClient) | Masih eksperimental di ekosistem Dart |

### 4. Best Practices & Common Pitfalls

#### Do's
* **Implementasikan Exponential Backoff dengan Jitter**: Jangan pernah mencoba melakukan rekoneksi berulang kali secara instan tanpa jeda progresif. Jitter (deviasi acak waktu) mencegah terjadinya fenomena **Thundering Herd Problem** pada server ketika jaringan pulih serentak.
* **Kombinasikan Native Ping dan Application Heartbeat**: Gunakan `WebSocket.pingInterval` dari `dart:io` untuk level TCP/Control frame, tetapi sediakan juga payload level aplikasi (seperti `{ "type": "ping" }`) jika target backend Anda (misal AWS API Gateway WebSocket) hanya mengevaluasi *idle timeout* berbasis data frame.
* **Gunakan Broadcast StreamController**: Selalu proteksi akses parsing event dengan *broadcasting* jika berbagai bagian aplikasi memerlukan aliran data stream WebSocket yang sama secara modular.

#### Don'ts
* **Jangan Mengabaikan TCP Half-Open State (Zombie Connection)**: Sering kali perangkat *mobile* beralih dari Wi-Fi ke data seluler secara tiba-tiba tanpa mengirimkan paket `TCP FIN` atau `RST`. Dalam skenario ini, OS mengira socket masih terbuka padahal komunikasi terputus. Tanpa mekanisme *heartbeat ping/pong*, klien akan membeku menunggu respon server selamanya.
* **Hindari Parse JSON Berat di Isolate Utama**: Jika klien WebSocket menerima throughput data finansial atau sensor yang sangat masif, memanggil `jsonDecode` berulang kali di Event Loop utama akan menyebabkan *UI jank* (frame drop) pada Flutter. Delegasikan proses parsing payload besar ke worker isolate via `compute` atau `Isolate.run()`.

#### Edge Cases
* **Handshake Authentication**: Menghindari pengiriman token autentikasi (JWT) pada URL query string (`wss://example.com?token=xyz`) karena query string tercatat di log intermediate proxy/server. Kirimkan token melalui HTTP Custom Header saat *handshake* berlangsung (`WebSocket.connect(..., headers: {'Authorization': 'Bearer ...'})`) atau kirimkan pesan autentikasi khusus pada *frame* pertama setelah soket terbuka.

### 5. Tantangan Eksplorasi Mandiri

1. **Backpressure Stream Transformer**: Modifikasi kelas `RobustWebSocketClient` di atas untuk mengimplementasikan *drop-oldest* atau *buffer-sliding-window* stream transformer menggunakan `asyncMap` / `StreamController`. Uji ketahanannya saat server membanjiri klien dengan 10.000 frame per detik sementara proses *handling* klien Anda beri `await Future.delayed(Duration(milliseconds: 10))`.
2. **Offline Outbox Queue via SQLite/In-Memory**: Rancang sistem *outbox queue*. Jika fungsi `send()` dipanggil saat status koneksi berada di posisi `ConnectionStatus.disconnected`, masukkan pesan tersebut ke dalam antrean (queue) terurut, lalu eksekusi pengiriman otomatis secara berurutan (*FIFO*) saat status beralih kembali ke `ConnectionStatus.connected`.
