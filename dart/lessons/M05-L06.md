## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam bahasa Dart, fungsi diperlakukan sebagai **first-class citizens**. Artinya, fungsi adalah objek instan dari tipe data `Function`. Karena fungsi berstatus sebagai objek kelas satu, Anda dapat:
1. Menyimpan fungsi ke dalam variabel atau struktur data.
2. Mengirimkan fungsi sebagai argumen ke fungsi lain (*higher-order functions*).
3. Mengembalikan fungsi dari fungsi lain (*function factories*).

```
+--------------------------------------------------------+
| Lexical Scope (Compile-time Boundary)                  |
|                                                        |
|  String prefix = "AUTH_";                              |
|                                                        |
|  +--------------------------------------------------+  |
|  | Closure: (String token)                          |  |
|  | Captures reference to [prefix] in heap context   |  |
|  +--------------------------------------------------+  |
+--------------------------------------------------------+
```

#### Lexical Scope (Static Scoping)
Dart mengadopsi **lexical scoping**, di mana resolusi variabel ditentukan secara statis berdasarkan lokasi penulisan blok kode pada *source code* (compile-time), bukan dari mana fungsi tersebut dieksekusi (*dynamic scope*). Aturan dasarnya: blok kode bagian dalam memiliki akses ke semua variabel yang dideklarasikan di scope luarnya hingga tingkat *top-level/global scope*.

#### Closures
**Closure** adalah objek fungsi yang mempertahankan referensi ke variabel-variabel dalam lexical scope tempat fungsi tersebut dibuat, meskipun eksekusi kode telah meninggalkan scope tersebut. Ketika fungsi dalam menangkap (*capture*) variabel dari scope luar, Dart tidak lagi mengizinkan variabel tersebut dihancurkan saat stack frame fungsi luar selesai dieksekusi. Variabel tersebut "dibungkus" dan dipindahkan ke heap bersama objek fungsi tersebut.

### 2. Implementasi & Contoh Kasus Nyata

Berikut implementasi idiomatik penerapan *higher-order function*, *lexical closures*, dan tipe `Function` menggunakan syntax Dart modern:

```dart
// Definisi custom function signature menggunakan typedef
typedef RetryEvaluator = bool Function(Exception error, int attempt);
typedef AsyncAction<T> = Future<T> Function();

/// Higher-order function generator (Function Factory)
/// Mengembalikan closure yang membungkus konfigurasi internal.
AsyncAction<T> createRetryRunner<T>({
  required AsyncAction<T> action,
  required int maxRetries,
  required RetryEvaluator retryWhen,
}) {
  // Variabel 'attempt' berada di luar closure yang dikembalikan,
  // tetapi akan di-capture oleh state lexical closure.
  int attempt = 0;

  return () async {
    while (true) {
      try {
        attempt++;
        return await action();
      } on Exception catch (e) {
        final shouldRetry = retryWhen(e, attempt);
        if (attempt >= maxRetries || !shouldRetry) {
          rethrow;
        }
        // Exponential backoff berbasis attempt
        await Future.delayed(Duration(milliseconds: 100 * attempt));
      }
    }
  };
}

/// Implementasi stateful closure: Rate limiter / Token Bucket sederhana
Function() createRateLimiter(int maxCalls, Duration resetWindow) {
  int callCount = 0;
  DateTime windowStart = DateTime.now();

  // Closure anonim meng-capture `callCount` dan `windowStart`
  return () {
    final now = DateTime.now();
    if (now.difference(windowStart) > resetWindow) {
      callCount = 0;
      windowStart = now;
    }

    if (callCount < maxCalls) {
      callCount++;
      print('Aksi diizinkan. Pemanggilan ke-$callCount');
    } else {
      print('Rate limit terlampaui. Tunggu hingga window di-reset.');
    }
  };
}

void main() async {
  // 1. Penggunaan Stateful Closure
  print('--- Test Rate Limiter Closure ---');
  final limiter = createRateLimiter(2, const Duration(seconds: 1));
  limiter(); // Pemanggilan ke-1
  limiter(); // Pemanggilan ke-2
  limiter(); // Ditolak

  // 2. Penggunaan Function Factory & Retry Runner
  print('\n--- Test Retry Runner ---');
  int networkHits = 0;

  Future<String> unstableNetworkCall() async {
    networkHits++;
    if (networkHits < 3) {
      throw FormatException('Koneksi terputus tiba-tiba (Hits: $networkHits)');
    }
    return 'Data berhasil diunduh pada percobaan ke-$networkHits';
  }

  // Membuat instance closure
  final resilientTask = createRetryRunner<String>(
    action: unstableNetworkCall,
    maxRetries: 3,
    retryWhen: (err, attempt) => err is FormatException,
  );

  final result = await resilientTask();
  print(result);
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Dari Stack Frame ke Heap Context
1. **Activation Record (Stack Frame)**: Pada eksekusi fungsi normal, variabel lokal dialokasikan di dalam *call stack frame*. Ketika fungsi selesai (`return`), pointer stack kembali ke pemanggil, menghapus seluruh variabel lokal dalam hitungan siklus CPU (tanpa membebani Garbage Collector).
2. **Context Promotion (Captured Variables)**: Saat Dart CFE (Common Front-End) mendeteksi ada fungsi bersarang yang membaca atau memodifikasi variabel dari outer scope, variabel tersebut **tidak dialokasikan pada stack frame**.
3. **Synthetic Context Object**: Dart compiler membuat struktur data tersembunyi berupa objek kelas sintetis (`Context`) di **Heap Memory**. Variabel yang tertangkap menjadi field dari objek `Context` tersebut.
4. Fungsi closure memegang referensi langsung ke instance objek `Context` ini. Oleh sebab itu, variabel tetap hidup selama closure tersebut masih dapat diakses (direferensikan).

#### Representasi Objek Fungsi
Setiap fungsi di Dart sebenarnya adalah turunan dari `_Closure` internal class yang mengimplementasikan antarmuka `Function`:
- Memiliki entry point pointer ke kode instruksi mesin (atau AOT bytecode).
- Memiliki pointer `context` yang menunjuk ke heap context tempat variabel-variabel yang ditangkap disimpan.

#### Trade-offs & Performance Impact
- **Alokasi Heap vs Stack**: Pembuatan closure yang meng-capture variabel memicu alokasi heap dan penambahan beban GC (Garbage Collector), berbeda dengan fungsi biasa (*tear-off* statis/top-level) yang tidak meng-capture variabel lokal.
- **Tear-offs**: Dart mendukung sintaks tear-off (misal: `items.forEach(print)` alih-alih `items.forEach((e) => print(e))`). Sejak Dart 2.15, constructor tear-offs dan static method tear-offs di-cache atau dialokasikan secara kanonikal (*canonicalized*) saat konstan, mengurangi footprint memori secara signifikan dibanding anonim closure lambda.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Tear-Offs**: Gunakan tear-off untuk passing fungsi langsung daripada membungkusnya lagi dalam lambda:
  ```dart
  // Dianjurkan:
  users.map(serializeUser);
  // Hindari redundansi:
  users.map((u) => serializeUser(u));
  ```
- **Spesifikasikan Signature via Typedef**: Buat kode eksplisit menggunakan `typedef` modern untuk mempermudah analisa statis analyzer dan pemeliharaan kode tim.
- **Batasi Lifetime Closure**: Pastikan closure yang menangkap objek besar (seperti controller, context UI/BuildContext) tidak disimpan dalam variabel global/statis yang berumur panjang.

#### Don'ts
- **Hindari Meng-capture Seluruh Objek Bila Hanya Butuh Propertinya**:
  ```dart
  // Buruk: Meng-capture seluruh instance class besar
  void setup() {
    HeavyClass heavy = HeavyClass();
    button.onClick = () => print(heavy.id); // Seluruh instance 'heavy' tidak bisa di-GC
  }

  // Benar: Capture nilai primitifnya saja
  void setup() {
    HeavyClass heavy = HeavyClass();
    final id = heavy.id;
    button.onClick = () => print(id); // Hanya 'id' yang tertahan
  }
  ```

#### Common Pitfalls: Capture Variables dalam Loop
Sebelum perbaikan semantic scope, bahasa pemrograman sering mengalami masalah *variable capture* pada perulangan. Di Dart, perulangan `for` membuat variabel baru (*new binding*) pada setiap iterasi:

```dart
// Dart menjamin binding baru untuk setiap iterasi 'i':
var closures = <Function>[];
for (var i = 0; i < 3; i++) {
  closures.add(() => i);
}

for (var fn in closures) {
  print(fn()); // Mencetak: 0, 1, 2 (Bukan 3, 3, 3 seperti pada JS lama)
}
```

*Edge Case Perhatian*: Jika Anda meng-capture variabel yang dideklarasikan di **luar** `for`, referensi yang sama akan dibagi bersama:

```dart
var closures = <Function>[];
int sharedIndex = 0;
for (; sharedIndex < 3; sharedIndex++) {
  closures.add(() => sharedIndex);
}

for (var fn in closures) {
  print(fn()); // Mencetak: 3, 3, 3! (Karena membagikan reference yang sama)
}
```

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Memoization Generic**: Buat higher-order function `T Function(R) memoize<T, R>(T Function(R) original)` yang menyimpan cache hasil komputasi fungsi murni ke dalam lexical scope berbasis hash-map closure. Uji performanya menggunakan fungsi kalkulasi Fibonacci rekursif.
2. **Investigasi Memory Leak Closure**: Buat skenario di mana dua closure saling mereferensikan context lexical masing-masing secara sirkular (*retain cycle*), simulasikan menggunakan Dart VM Service Protocol atau amati perilakunya di DevTools Memory Profiler untuk melihat kapan GC berhasil melakukan sweep pada objek context tersebut.
