## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Evolusi eksekusi Dart di web telah melalui transformasi signifikan:
1. **Dartium Era (Historis)**: Upaya menyematkan Dart VM langsung ke Chromium (dihentikan untuk menghindari fragmentasi web).
2. **JavaScript Target**: Kompilasi source-to-source melalui dua compiler:
   - **dartdevc (DDC)**: Compiler modular berorientasi developer untuk *fast incremental rebuild* dan debugging berbasis source map di development runtime.
   - **dart2js**: Compiler Ahead-Of-Time (AOT) untuk produksi dengan optimasi agresif (Global Type Analysis, Tree-shaking, Minification).
3. **WebAssembly Target (`dart2wasm`)**: Kompilasi langsung ke bytecode Wasm menggunakan ekstensi **WasmGC (WebAssembly Garbage Collection)**.

```
                  ┌───────────────┐
                  │   Dart Core   │
                  │  Source Code  │
                  └───────┬───────┘
                          │
          ┌───────────────┴───────────────┐
          ▼                               ▼
  [ dart2js Compiler ]           [ dart2wasm Compiler ]
          │                               │
   Type Flow Analysis               WasmGC Lowering
   Tree Shaking & Polyfills         Direct Heap Mapping
          │                               │
          ▼                               ▼
  ┌───────────────┐               ┌───────────────┐
  │ JavaScript    │               │ WebAssembly   │
  │ (.dart.js)    │               │ (.wasm + GC)  │
  └───────┬───────┘               └───────┬───────┘
          │                               │
          ▼                               ▼
  ┌───────────────────────────────────────────────┐
  │         Host Browser Engine (V8, etc.)        │
  │  JS Runtime Event Loop / Unified Engine GC    │
  └───────────────────────────────────────────────┘
```

#### Masalah Linear Memory vs. Terobosan WasmGC
WebAssembly MVP (Minimum Viable Product) hanya menyediakan *Linear Memory* (vektor byte primitif berukuran dinamis). Bahasa dengan Garbage Collector (seperti Go, Java, Dart) yang menargetkan Wasm MVP terpaksa menyertakan seluruh runtime GC mereka sendiri ke dalam modul Wasm. Ini memicu:
- Ukuran biner membengkak (*payload size bloat*).
- Masalah performa karena GC internal Dart mengelola byte array mentah di dalam linear memory tanpa sinkronisasi langsung dengan GC milik browser host (V8/SpiderMonkey/JSC).
- Siklus referensi yang sulit diselesaikan antara Dart Heap dan DOM/JS Heap.

**WasmGC** mengatasi masalah ini dengan memperkenalkan tipe referensi terkelola (*managed types* seperti `structref`, `arrayref`, `i31ref`) langsung ke dalam instruksi Wasm standar. Compiler `dart2wasm` memetakan class, hierarki inheritance, dan instance Dart langsung ke tipe-tipe WasmGC tersebut. Dengan demikian, objek Dart dialokasikan langsung di managed heap milik engine browser dan dibersihkan oleh Garbage Collector bawaan browser secara optimal tanpa overhead runtime GC tambahan.

#### Transisi API: Menuju `dart:js_interop` dan `package:web`
Untuk mendukung `dart2wasm`, Dart menghentikan pustaka legacy seperti `dart:html` dan `package:js`. Model baru menggunakan:
- **`dart:js_interop`**: Abstraksi level-rendah berbasis *static extension types* (`JSObject`, `JSString`, `JSAny?`).
- **`package:web`**: Binding resmi berbasis Web IDL untuk standard Web API (DOM, Canvas, Fetch) yang dapat dikompilasi secara *zero-cost* baik ke JS maupun WasmGC.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengimplementasikan kalkulator benchmark array dan manipulasi DOM menggunakan interoperabilitas modern yang kompatibel ganda (dapat dikompilasi ke `dart2js` maupun `dart2wasm`).

#### `pubspec.yaml`
```yaml
name: dart_web_targets
environment:
  sdk: '>=3.4.0 <4.0.0'

dependencies:
  web: ^1.0.0
```

#### `web/main.dart`
```dart
import 'dart:js_interop';
import 'package:web/web.dart' as web;

// Ekstensi Interop ke fungsi JS global (misal: console.time)
@JS('console.time')
external void consoleTime(JSString label);

@JS('console.timeEnd')
external void consoleTimeEnd(JSString label);

// Export fungsi Dart agar bisa dipanggil langsung oleh JS runtime
@JSExport()
class BenchmarkRunner {
  // Komputasi matematis intensif untuk menguji performa eksekusi
  double computePi(int iterations) {
    double pi = 0.0;
    for (int i = 0; i < iterations; i++) {
      double term = 1.0 / (2 * i + 1);
      if (i % 2 == 1) {
        pi -= term;
      } else {
        pi += term;
      }
    }
    return pi * 4;
  }
}

void main() {
  // 1. Manipulasi DOM via package:web
  final root = web.document.querySelector('#app') as web.HTMLDivElement?;
  if (root == null) return;

  final title = web.document.createElement('h1') as web.HTMLHeadingElement;
  title.textContent = 'Dart Web Targets: JS vs WasmGC';
  root.appendChild(title);

  final button = web.document.createElement('button') as web.HTMLButtonElement;
  button.textContent = 'Run Pi Benchmark';
  root.appendChild(button);

  final resultDisplay = web.document.createElement('p') as web.HTMLParagraphElement;
  root.appendChild(resultDisplay);

  // 2. Registrasi Export Object ke Window
  final runner = BenchmarkRunner();
  final exported = createJSInteropWrapper(runner);
  (web.window as JSObject)['benchmarkRunner'] = exported;

  // 3. Event Handling
  button.onClick.listen((web.MouseEvent _) {
    final label = 'pi-calculation'.toJS;
    consoleTime(label);

    const iterations = 50000000;
    final piValue = runner.computePi(iterations);

    consoleTimeEnd(label);

    resultDisplay.textContent = 'Hasil Pi (${iterations} iterasi): $piValue';
  });
}
```

#### Perintah Kompilasi

1. **Kompilasi ke JavaScript (Optimized Production via `dart2js`):**
   ```bash
   dart compile js -O4 -o web/main.dart.js web/main.dart
   ```
   *Flags:* `-O4` menerapkan optimasi level tertinggi (type flow analysis penuh, agresif inlining, dan minifikasi).

2. **Kompilasi ke WebAssembly (via `dart2wasm`):**
   ```bash
   dart compile wasm -O4 -o web/main.wasm web/main.dart
   ```
   Perintah ini menghasilkan dua file utama:
   - `web/main.wasm`: Bytecode WasmGC.
   - `web/main.mjs`: JavaScript bootstrap loader yang menginisialisasi modul Wasm dan mengikat host imports/exports.

#### HTML Loader (`web/index.html`)
```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Dart JS vs Wasm</title>
</head>
<body>
  <div id="app"></div>

  <!-- Skenario 1: Menjalankan Versi Wasm (Dart 3.4+) -->
  <script type="module">
    import { instantiate } from './main.mjs';
    try {
      // Inisialisasi modul WebAssembly dengan integrasi host GC
      await instantiate(fetch('./main.wasm'));
    } catch (e) {
      console.warn("WasmGC tidak didukung atau gagal dimuat, fallback ke JS:", e);
      const fallbackScript = document.createElement('script');
      fallbackScript.src = 'main.dart.js';
      document.body.appendChild(fallbackScript);
    }
  </script>
</body>
</html>
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Perbandingan Arsitektur Eksekusi

| Parameter | `dart2js` | `dart2wasm` |
| :--- | :--- | :--- |
| **Intermediate Representation** | Dart Kernel AST $\to$ SSA (Static Single Assignment) form | Dart Kernel AST $\to$ WasmGC Structural Types |
| **Output** | Single JavaScript file + Source Maps | Modul `.wasm` + Bootstrap JS glue code (`.mjs`) |
| **Number Semantics** | `int` & `double` dipetakan ke JS `Number` (IEEE 754 float), kecuali 64-bit int dipaksa emulasi via objek internal | `int` dipetakan ke native `i64` Wasm, `double` ke `f64` Wasm |
| **Type Flow Analysis (TFA)** | Closed-world analysis untuk eliminasi cabang *polymorphic dispatch* | Closed-world analysis untuk memangkas *vtable* Wasm structural types |

#### Eksekusi & Runtime
- **`dart2js` Pipeline**:
  Compiler menganalisis seluruh dependensi aplikasi secara tertutup (*closed-world assumption*). Jika class `Dog` dan `Cat` mengimplementasikan `Animal`, tetapi compiler melihat `Cat` tidak pernah diinstansiasi di kode mana pun, tipe `Cat` dihilangkan. Selanjutnya, pemanggilan virtual method di-inline atau dialihkan langsung (*monomorphic call-site devirtualization*).
- **`dart2wasm` Pipeline**:
  Dart class direpresentasikan sebagai WasmGC `struct`. Method dispatch menggunakan `call_indirect` atau *direct call* bila TFA membuktikan implementor-nya unik. Pemanggilan JS Interop di-lower melalui fungsi adapter eksternal yang dihubungkan lewat runtime host (`wasm:js-string` dan JS API bindings).

#### Alokasi Memori
- **dart2js**:
  Semua objek Dart adalah JavaScript Object biasa (`{}`). Properti dipetakan ke *hidden classes* (V8 Map/Shape). Pembersihan objek sepenuhnya diserahkan pada generational collector bawaan browser.
- **dart2wasm**:
  Objek dialokasikan sebagai Wasm internal GC types (`structref`). Hal ini menghilangkan lapisan overhead representasi JS Object, menurunkan penggunaan memory footprint secara drastis dibanding `dart2js`. 
  *Catatan Penting*: Data primitif 64-bit (`int` Dart) dieksekusi secara native via instruksi register CPU tanpa alokasi heap, sedangkan di `dart2js`, operasi 64-bit berpotensi membutuhkan boxing class tambahan jika melampaui batasan rentang aman integer JS ($2^{53} - 1$).

#### Trade-offs
- **Ukuran File**: Untuk aplikasi skala kecil/menengah, payload `dart2wasm` seringkali lebih besar dari `dart2js` akibat overhead metadata modul Wasm. Namun, pada aplikasi skala besar (seperti Flutter Web), payload WasmGC stabil dan eksekusinya jauh lebih cepat.
- **Friction Boundary (DOM Access Overhead)**: Komputasi matematis/logika di `dart2wasm` berjalan mendekati native speed. Namun, jika aplikasi sering melakukan pemanggilan DOM per frame secara berlebihan, akan ada *boundary-crossing cost* (konversi tipe WasmGC $\leftrightarrow$ WebIDL/JS Engine).

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `dart:js_interop` dan `package:web`**: Hindari seluruh dependensi berbasis `dart:html` atau `package:js`. Format baru ini memastikan kode bersifat *forward-compatible* untuk kedua compiler target.
- **Terapkan `extension type` untuk Typed Interop**:
  ```dart
  extension type HTMLElementExtension(web.HTMLElement elem) {
    void makeRed() {
      elem.style.backgroundColor = 'red';
    }
  }
  ```
  Ini adalah abstraksi *zero-runtime overhead* yang hilang saat kompilasi.
- **Gunakan Header HTTP yang Tepat**: Pastikan server web menyajikan file `.wasm` dengan Content-Type: `application/wasm` agar browser dapat melakukan *streaming compilation*.

#### Don'ts
- **Jangan Mengasumsikan Bit-Width Semantics Selalu Identik**:
  Pada `dart2js`:
  ```dart
  int x = 1 << 40; // Aman di JS Number (di bawah 2^53 - 1)
  int y = 1 << 62; // BAHAYA: Presisi hilang / overflow terpotong di JS
  ```
  Pada `dart2wasm`, `int` adalah 64-bit integer signed murni (`i64`), sehingga perilakunya persis seperti di native Dart VM (x64/ARM64). Jangan menulis kode yang mengandalkan keanehan bitwise truncation JS pada platform web Dart.
- **Hindari Refleksi (`dart:mirrors`)**: Refleksi dilarang keras di web dan secara otomatis mematikan kemampuan Tree-shaking.

#### Edge Cases
- **Handling JS Promises di Dart**:
  Gunakan `.toDart` untuk mengubah `JSPromise` menjadi Dart `Future`:
  ```dart
  Future<void> fetchExample() async {
    final response = await web.window.fetch('https://api.example.com/data'.toJS).toDart;
    // Lakukan konversi hasil
  }
  ```
- **Keterbatasan Dukungan Browser WasmGC**:
  WasmGC membutuhkan Chromium $\ge$ 119 atau Firefox $\ge$ 120. Safari baru mendukungnya di iOS/macOS Safari 17.4+. Selalu sediakan skema fallback berbasis deteksi fitur di entry point HTML loader untuk mengunduh `.dart.js` jika WasmGC belum aktif di browser klien.

### 5. Tantangan Eksplorasi Mandiri

1. **Benchmark Throughput & Payload Analysis**:
   - Ambil contoh kode `computePi` di atas, lalu kompilasi dengan kedua target:
     ```bash
     dart compile js -O4 -o benchmark.dart.js web/main.dart
     dart compile wasm -O4 -o benchmark.wasm web/main.dart
     ```
   - Bandingkan total ukuran byte yang harus diunduh (termasuk loader) dan ukur waktu eksekusi $100.000.000$ iterasi melalui `performance.now()` di browser.

2. **Analisis Structural Types WasmGC**:
   - Install WebAssembly Binary Toolkit (`wabt`).
   - Ekstrak representasi teks dari biner hasil kompilasi:
     ```bash
     wasm2wat web/main.wasm -o web/main.wat
     ```
   - Telusuri file `.wat` tersebut dan identifikasi bagaimana compiler mendefinisikan tipe `BenchmarkRunner` ke dalam konstruksi `(type ... (sub (struct ...)))`. Perhatikan bagaimana field dan virtual method table (vtable) dipetakan.
