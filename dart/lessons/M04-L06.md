### 1. Konsep & Arsitektur Mendalam

Sejak Dart 3.0, sistem *pattern matching* diperkenalkan sebagai fitur inti tingkat bahasa (*first-class language feature*). Di antara berbagai jenis pola yang ada, **Relational Patterns** dan **Logical Patterns** menyediakan abstraksi deklaratif untuk mengevaluasi nilai berdasarkan perbandingan matematis dan logika proposisional tanpa boilerplate `if-else` bertingkat.

```
                  [ Matched Value: X ]
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
   [ Relational Pattern ]      [ Logical Pattern ]
      (op <constant>)            (P1 && P2) | (P1 || P2)
             │                           │
  Evaluasi: X.operator(C)      Short-circuit evaluation
```

#### Relational Patterns
Pola relasional membandingkan nilai target dengan sebuah nilai konstan menggunakan salah satu operator perbandingan standar: `<`, `<=`, `>`, `>=`, `==`, dan `!=`. 
- Pola ini tidak melakukan *binding* variabel baru.
- Di balik layar, compiler memetakan ekspresi `case > 100` menjadi pemanggilan metode operator relasional pada nilai target: `target > 100`.
- Konstanta di sisi kanan harus bertipe kompatibel dengan nilai target dan harus merupakan ekspresi konstan pada saat kompilasi (*compile-time constant*).

#### Logical Patterns
Logical patterns memungkinkan komposisi beberapa sub-pola menggunakan operator logika:
1. **Logical-AND (`p1 && p2`)**: Mencocokkan nilai jika **kedua** sub-pola cocok. Pola ini mengevaluasi dari kiri ke kanan. Jika `p1` gagal, `p2` tidak dievaluasi (*short-circuit*). Pola ini sering dikombinasikan dengan *type test* atau perbandingan rentang (*range check*).
2. **Logical-OR (`p1 || p2`)**: Mencocokkan nilai jika **salah satu** sub-pola cocok. Evaluasi berhenti seketika saat `p1` berhasil (*short-circuit*).

##### Aturan Binding Variabel pada Logical Patterns:
- Pada **Logical-AND (`&&`)**, variabel yang di-binding di `p1` dan `p2` akan digabungkan ke dalam *scope* eksekusi.
- Pada **Logical-OR (`||`)**, jika ada variabel yang di-*bind*, variabel tersebut **harus dideklarasikan di kedua sisi** dengan nama dan tipe yang sama persis. Hal ini menjamin bahwa cabang eksekusi downstream selalu menerima variabel dengan kondisi state yang valid terlepas dari sisi mana yang cocok.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi sistem klasifikasi respon jaringan dan validasi kuota API menggunakan kombinasi *Relational* dan *Logical Patterns* dalam ekspresi modern Dart.

```dart
sealed class NetworkResponse {
  final int statusCode;
  final int payloadSizeBytes;

  const NetworkResponse(this.statusCode, this.payloadSizeBytes);
}

class HttpResponse extends NetworkResponse {
  final String body;
  const HttpResponse(super.statusCode, super.payloadSizeBytes, this.body);
}

enum ProcessingStrategy {
  cachedFastTrack,
  standard,
  payloadTooLarge,
  clientFault,
  serverFaultRetry,
  unhandled,
}

ProcessingStrategy resolveStrategy(NetworkResponse response) {
  // Switch expression yang memanfaatkan Logical (&&, ||) dan Relational Patterns
  return switch (response) {
    // Relational + Logical-AND: Status 200 OK DAN ukuran payload < 10 KB
    HttpResponse(statusCode: 200, payloadSizeBytes: < 10240) =>
      ProcessingStrategy.cachedFastTrack,

    // Logical-OR: Status 200 dengan payload normal ATAU status 201 Created
    HttpResponse(statusCode: 200, payloadSizeBytes: >= 10240 && <= 1048576) ||
    HttpResponse(statusCode: 201) =>
      ProcessingStrategy.standard,

    // Relational Pattern untuk mendeteksi oversized payload (> 1MB)
    HttpResponse(payloadSizeBytes: > 1048576) =>
      ProcessingStrategy.payloadTooLarge,

    // Relational Range Check: Client errors (400 - 499)
    HttpResponse(statusCode: >= 400 && <= 499) =>
      ProcessingStrategy.clientFault,

    // Logical-OR untuk spesifik transient server errors
    HttpResponse(statusCode: 502 || 503 || 504) =>
      ProcessingStrategy.serverFaultRetry,

    _ => ProcessingStrategy.unhandled,
  };
}

// Contoh Binding Variabel dengan Logical-OR
String extractDiagnosticData((int, dynamic) errorContext) {
  return switch (errorContext) {
    // Variabel 'code' harus memiliki tipe dan identifier yang identik di kedua sisi '||'
    (final int code && (401 || 403), _) ||
    (final int code && (500 || 503), _) =>
      'Critical Interruption: Code $code',
    _ => 'Normal Operation / Non-critical',
  };
}

void main() {
  final response1 = HttpResponse(200, 4096, '{"status": "ok"}');
  final response2 = HttpResponse(503, 128, 'Service Unavailable');
  final response3 = HttpResponse(404, 512, 'Not Found');

  print(resolveStrategy(response1)); // Output: ProcessingStrategy.cachedFastTrack
  print(resolveStrategy(response2)); // Output: ProcessingStrategy.serverFaultRetry
  print(resolveStrategy(response3)); // Output: ProcessingStrategy.clientFault

  print(extractDiagnosticData((401, 'Unauthorized'))); // Output: Critical Interruption: Code 401
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Desugaring CFE (Common Front End)
Dart Kernel Compiler (CFE) menerjemahkan pola logika dan relasional menjadi *Control Flow Graph* (CFG) primitif. Pola relasional `case >= 200 && <= 299` tidak memiliki instruksi mesin khusus; compiler melakukan *desugaring* menjadi rangkaian *conditional jumps* bersarang (nested `if` conditions):

```
[Target: X]
  │
  ├─> Evaluasi: X >= 200 ?
  │      ├─ False ─> Lanjut ke Case Berikutnya (Fail)
  │      └─ True  ─> Evaluasi: X <= 299 ?
  │                    ├─ True  ─> Eksekusi Cabang Cocok (Success)
  │                    └─ False ─> Lanjut ke Case Berikutnya (Fail)
```

#### Short-Circuit Semantics
Pada level byte-code/Dart Kernel:
- Evaluasi **`&&`** menghentikan rantai evaluasi seketika cabang kiri mengembalikan nilai *false* (atau *pattern mismatch*). Cabang kanan tidak dieksekusi, mencegah potensi overhead dari pemanggilan metode relasional `target.operator>()`.
- Evaluasi **`||`** langsung melompat (*jump instruction*) ke *body* switch saat kecocokan pertama ditemukan.

#### Alokasi Memori
Pola relasional dan logis beroperasi pada *stack register* tanpa alokasi memori heap tambahan:
- Tidak ada alokasi objek sementara (*no intermediate wrappers*).
- Konstanta yang dibandingkan di-*resolve* saat fase *canonicalization* pada compile-time. Nilai konstanta tersebut berada di segmen read-only memory runtime VM.

#### Trade-offs & Overhead
- **Pros**: Readability mendekati notasi matematika ($x \in [a, b]$ ditulis `x && >= a && <= b`). Exhaustiveness checker dapat memvalidasi cakupan jika dikombinasikan dengan enum atau sealed class.
- **Cons**: Kompilator Dart saat ini belum menerapkan *interval arithmetic solver* penuh untuk memeriksa exhaustiveness tipe numerik. Contoh: `switch(x)` dengan kasus `< 0`, `== 0`, dan `> 0` pada tipe `int` tetap mewajibkan wildcard `_` karena kompilator tidak menyimpulkan bahwa seluruh himpunan $\mathbb{Z}$ telah terpenuhi.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Logical-AND untuk Membatasi Rentang (*Range Bounding*)**:
  Format idiomatis untuk pengujian rentang adalah:
  ```dart
  case >= min && <= max
  ```
- **Kombinasikan dengan Object Patterns**:
  Gunakan pemetaan properti langsung pada objek daripada mengakses getter secara manual:
  ```dart
  // Rekomendasi
  case Order(totalAmount: > 1000 && <= 5000)
  ```

#### Don'ts
- **Jangan Mengabaikan Prioritas Operator (*Precedence Rules*)**:
  Operator `&&` memiliki presedensi lebih tinggi daripada `||`.
  ```dart
  // Ambigu dan berisiko bug logika:
  case 1 || 2 && 3 // Terbaca sebagai: 1 || (2 && 3), BUKAN: (1 || 2) && 3
  ```
  Gunakan tanda kurung eksplisit untuk menghindari ambiguitas logika kognitif.

#### Common Pitfalls
1. **Asimetri Binding pada Logical-OR**:
   Mencoba mengikat variabel di satu sisi `||` tanpa mendefinisikannya di sisi lain akan memicu *compile-time error*:
   ```dart
   // ERROR: The variable 'data' must be bound on both sides of a logical-or pattern.
   case String data || int _
   ```
2. **Evaluasi Relasional pada Nullable Value**:
   Jika target bernilai `null`, operator relasional (`>`, `<`, `>=`, `<=`) akan melempar runtime exception (`NoSuchMethodError` atau `TypeError`) jika tipe data tidak menangani `null` secara aman sebelum dievaluasi.
   ```dart
   int? val;
   // RUNTIME ERROR jika val == null dan pola dieksekusi tanpa null-check
   // Solusi aman:
   case int v && > 0 => 'Positive non-null'
   case null => 'Null'
   ```
