## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam rekayasa perangkat lunak, terdapat dilema klasik antara *type-safety* dan *runtime performance*. Pola seperti *Domain-Driven Design* (DDD) menyarankan penggunaan *Value Objects* untuk mencegah masalah *Primitive Obsession* (misalnya membungkus `int` ke dalam `UserId` dan `OrderId` agar tidak saling tertukar). Namun, membuat *class wrapper* konvensional memicu penalti performa:
1. **Alokasi Heap Tambahan:** Setiap instansiasi wrapper mengalokasikan objek baru di heap.
2. **Pointer Indirection & Memory Overhead:** Objek wrapper memiliki *object header* (biasanya 8–16 byte tergantung arsitektur dan runtime) serta referensi pointer tambahan yang memperlambat *CPU cache access*.
3. **Tekanan pada Garbage Collector (GC):** Volume alokasi objek sementara yang tinggi memicu GC cycle lebih sering.

Diperkenalkan pada Dart 3.3, **Extension Types** (sebelumnya dikenal sebagai *Inline Classes*) hadir untuk menyelesaikan dilema ini. Fitur ini menyediakan abstraksi *compile-time-only wrapper* yang membungkus tipe data yang ada (*underlying/representation type*) dengan antarmuka (*interface*) yang sepenuhnya baru dan aman secara statis, **tanpa alokasi memori tambahan di runtime (zero-cost abstraction)**.

```
+-------------------------------------------------------------+
|                        COMPILE-TIME                         |
|  UserId (Extension Type)  !==  OrderId (Extension Type)     |
|              \                     /                        |
|               +---------> <-------+                         |
|                         int                                 |
+-------------------------------------------------------------+
                              |
                     Dart Compiler (AOT/JIT)
                      Type Erasure Process
                              |
                              v
+-------------------------------------------------------------+
|                         RUNTIME                             |
|          Hanya terdapat nilai primitif: 'int'               |
|            (Tanpa wrapper object di memory heap)            |
+-------------------------------------------------------------+
```

#### Perbedaan Utama: Extension Types vs Wrapper Class vs Extension Methods

| Karakteristik | Regular Wrapper Class | Extension Methods (`extension on T`) | Extension Types (`extension type ET(T)`) |
| :--- | :--- | :--- | :--- |
| **Alokasi Heap Runtime** | Ya (Ada overhead object) | Tidak (Hanya static dispatch) | **Tidak (Zero-cost)** |
| **Identitas Tipe Baru** | Ya (Tipe unik di runtime) | Tidak (Tetap tipe aslinya) | **Ya (Unik di compile-time)** |
| **Enkapsulasi Interface** | Ya (Dapat menyembunyikan field) | Tidak (Member tipe asli tetap terlihat) | **Ya (Default: menyembunyikan API tipe asli)**|
| **Implements Interface**| Ya | Tidak | **Ya (Hanya sesama extension type/supertypes)** |
| **Runtime Type Preservation**| Ya (`is Wrapper` valid) | N/A | **Tidak (Terhapus menjadi underlying type)** |

### 2. Implementasi & Contoh Kasus Nyata

Extension types dideklarasikan dengan sintaks `extension type` diikuti nama, konstruktor representasi (*representation declaration*), serta blok method/getter opsional.

Berikut adalah implementasi sistem e-commerce yang mencegah *ID mismatch* dan menangani validasi mata uang tanpa beban alokasi objek:

```dart
// 1. Primitive Obsession Prevention via Zero-Cost Wrappers
extension type const UserId(int id) {
  // Constructor validation logika compile/runtime
  UserId {
    assert(id > 0, 'UserId harus bilangan bulat positif');
  }

  // Operator overloading khusus untuk UserId
  bool operator >(UserId other) => id > other.id;
}

extension type const OrderId(int id) {
  OrderId {
    assert(id > 0, 'OrderId harus bernilai positif');
  }
}

// 2. Mengekspos sebagian interface representation type menggunakan 'implements'
// Centimeter hanya mengekspos fungsionalitas Comparable bawaan num, bukan seluruh method double
extension type const Centimeter(double value) implements Comparable<Centimeter> {
  // Named constructor
  Centimeter.fromMeters(double meters) : this(meters * 100);

  // Custom getters & methods
  Centimeter operator +(Centimeter other) => Centimeter(value + other.value);
  Centimeter operator -(Centimeter other) => Centimeter(value - other.value);

  @override
  int compareTo(Centimeter other) => value.compareTo(other.value);
}

// 3. Database / Repository Simulation
class OrderService {
  void assignOrderToUser({required OrderId orderId, required UserId userId}) {
    print('Memproses Order #$orderId untuk User #$userId');
  }
}

void main() {
  const userId = UserId(101);
  const orderId = OrderId(5502);

  final service = OrderService();

  // Type-Safe: Tidak bisa tertukar!
  service.assignOrderToUser(orderId: orderId, userId: userId);

  // COMPILE ERROR:
  // service.assignOrderToUser(orderId: userId, userId: orderId);
  // Error: The argument type 'UserId' can't be assigned to the parameter type 'OrderId'.

  // Demonstrasi Centimeter
  const lengthA = Centimeter(150.0);
  final lengthB = Centimeter.fromMeters(2.5); // 250 cm
  final total = lengthA + lengthB;

  print('Total panjang: ${total.value} cm'); // 400.0 cm
  print('Perbandingan: ${lengthA.compareTo(lengthB)}'); // -1
}
```

#### Menghindari Bocornya Underlying Interface
Secara *default*, seluruh API bawaan dari *representation type* disembunyikan. Jika Anda memiliki `extension type UnixTimestamp(int millis)`, Anda tidak bisa memanggil `millis.isEven` secara langsung, kecuali:
1. Anda membuat getter eksplit: `bool get isEven => millis.isEven;`
2. Anda mengekspos tipe dasarnya melalui klausa `implements`:
   ```dart
   // Mengekspos seluruh fungsionalitas int pada UnixTimestamp
   extension type UnixTimestamp(int millis) implements int {}
   ```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Type Erasure
Eksekutor Dart (AOT compiler atau Dart VM JIT) memperlakukan *extension type* murni sebagai mekanisme pengecekan statis.
- Saat proses kompilasi mencapai tahap pembuatan *Intermediate Representation* (Kernel AST pada Dart SDK), tipe `UserId` **dihapus (*type erasure*)** dan digantikan langsung oleh representasi aslinya (`int`).
- Semua pemanggilan method/getter pada extension type ditranslasikan menjadi fungsi statis (*static dispatch*), serupa dengan *extension methods*:
  ```dart
  // Kode Sumber:
  final sum = lengthA + lengthB;

  // Representasi Kompilasi Internal (Lowering):
  final double sum = Centimeter$BinaryOp$Add(lengthA, lengthB);
  ```
  Tidak ada *vtable lookup* atau *dynamic dispatch*, sehingga instruksi mesin yang dihasilkan setara dengan memanggil fungsi biasa secara langsung (*direct function call* atau bahkan *inlined* ke register CPU).

#### Alokasi Memori / Resource
Jika Anda membuat `List<UserId>` dengan 1.000.000 elemen:
- **Class Wrapper Tradisional:** Memerlukan alokasi array pointer + 1.000.000 header objek heap + 1.000.000 payload `int` boxed/unboxed. Ini dapat menghabiskan sekitar 24–32 MB memori di lingkungan 64-bit.
- **Extension Type:** Array dialokasikan langsung sebagai `List<int>`. Total alokasi murni sebesar ukuran array integer (sekitar 8 MB untuk platform 64-bit unboxed integers). **Overhead memori = 0 byte.**

#### Trade-offs & Keterbatasan Arsitektural
1. **Kehilangan Dynamic Type Safety:** Karena tipe dihapus di runtime, pemeriksaan tipe dinamis (`is`, `as`) dapat menyebabkan *leakage*:
   ```dart
   dynamic val = UserId(10);
   print(val is UserId); // Runtime Warning/Check: Dievaluasi sebagai `val is int` -> TRUE!
   print(val is OrderId); // Juga dievaluasi sebagai `val is int` -> TRUE!
   ```
2. **Ketiadaan Instance Variables Tambahan:** Extension type tidak dapat memiliki *backing field* selain *representation field*-nya. Menyimpan metadata tambahan di luar *representation type* tidak dimungkinkan.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan untuk Type-Safe Identifiers:** Hindari kesalahan passing ID database/entitas dengan membungkus `int`, `String`, atau `UUID`.
- **Gunakan untuk Zero-Cost FFI & JS Interop:** `dart:js_interop` memanfaatkan extension types untuk membungkus tipe native JavaScript DOM secara efisien saat kompilasi ke Web/WASM.
- **Gunakan Pattern Subtyping Khusus Domain:** Gunakan klausa `implements` hanya jika hubungan semantik objek benar-benar mencerminkan hubungan *is-a* terhadap tipe dasar atau extension type lain.

#### Don'ts
- **Jangan gunakan untuk Validasi Runtime Polimorfik:** Hindari penggunaan pattern matching runtime menggunakan `switch (obj)` di mana cabangnya mengevaluasi runtime type yang representasinya sama:
  ```dart
  // ANTI-PATTERN: Keduanya terhapus menjadi 'int' di runtime!
  void process(dynamic obj) {
    switch (obj) {
      case UserId():  // Dievaluasi sebagai: case int():
        print('User');
      case OrderId(): // Unreachable / ambiguous branch!
        print('Order');
    }
  }
  ```
- **Jangan gunakan jika Membutuhkan State Tambahan:** Jangan memaksakan extension types jika struktur data Anda membutuhkan dua field atau lebih; gunakan `class` reguler.

#### Edge Cases
- **Generic Invariance & Covariance:**
  `List<UserId>` **bukan** subtipe dari `List<int>` secara statis, meskipun di runtime mereka adalah objek yang sama. Anda tidak bisa mengoper `List<UserId>` ke parameter yang mengharapkan `List<int>` tanpa melakukan *cast* eksplisit atau mapping, untuk menjamin keamanan tipe statis.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Domain Uang Multi-Currency:**
   Buat dua extension type `Idr(int amount)` dan `Usd(double amount)`.
   - Pastikan kedua tipe ini **tidak bisa** dijumlahkan secara langsung (`idr + usd` harus memicu *compile error*).
   - Buat extension method atau fungsi konversi eksplisit pada `Usd` bernama `toIdr({required double exchangeRate})` yang menghasilkan instans `Idr`.
   - Buktikan bahwa di runtime, objek tersebut murni berupa `int` dan `double`.

2. **Zero-Cost JSON Data Access Object (DAO):**
   Buat sebuah `extension type JsonView(Map<String, dynamic> raw)` yang:
   - Menyediakan typed-getter: `String get name`, `int get age`, dan `bool get isValid`.
   - Mengimplementasikan getter `email` opsional yang mengembalikan null jika format regex tidak terpenuhi.
   - Analisis apa perbedaan alokasi memori antara pola ini dibandingkan melakukan deserialisasi JSON penuh menggunakan class tradisional (`User.fromJson(raw)`).
