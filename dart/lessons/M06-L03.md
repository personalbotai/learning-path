## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Di dalam Dart runtime, error handling beroperasi melintasi dua paradigma: **sinkron (imperatif)** dan **asinkron (event-driven/Future-based)**. Dart membedakan kegagalan menjadi dua hierarki inti di bawah `Object`:
1. **`Exception`**: Kondisi kegagalan yang *terduga* dan *dapat dipulihkan* (recoverable) pada saat runtime, misalnya `SocketException` atau `FormatException`.
2. **`Error`**: Kesalahan logika program yang *fatal* atau kegagalan sistem yang umumnya *tidak boleh ditangkap* untuk pemulihan, melainkan harus diperbaiki di kode sumber (unrecoverable), seperti `RangeError`, `ArgumentError`, atau `OutOfMemoryError`.

```
        Object
       /      \
  Exception   Error
     |          |
  (Recoverable) (Bugs/Fatal)
```

#### Dualitas Error Handling Asinkron: `try-catch` vs `Future API`

Ketika kode dieksekusi secara asinkron di atas Dart Event Loop, penanganan error terpecah menjadi dua pendekatan:

1. **Imperatif (`try-catch-finally` dengan `async`/`await`)**:
   Syntactic sugar yang mentranslasikan alur eksekusi asinkron menjadi state machine linier. Ketika sebuah `Future` menghasilkan error (`Future.error`), compiler menyuntikkan logika untuk mengekstrak error tersebut dan melemparkannya kembali ke call-stack lokal dalam frame fungsi `async`.

2. **Deklaratif (`catchError` & `whenComplete` pada `Future`)**:
   Bagian dari callback chaining murni Dart. 
   - `catchError`: Mendaftarkan error handler ke internal listener array milik `Future`. Jika `Future` selesai dengan status rejected/error, handler ini dipanggil.
   - `whenComplete`: Ekivalen dengan blok `finally`. Callback ini dieksekusi terlepas dari apakah `Future` berhasil (`value`) atau gagal (`error`), tanpa mengubah nilai return atau status error kecuali callback itu sendiri melempar error baru.

#### Hubungan dengan Dart Zone
Di level arsitektur Dart VM, jika sebuah error asinkron tidak ditangkap oleh `try-catch` atau `catchError`, error tersebut akan merembes (bubble up) ke **Zone** saat ini (`Zone.current`). Jika Zone tersebut tidak memiliki uncaught error handler khusus (misal via `runZonedGuarded`), error akan dianggap fatal dan mencetak trace ke `stderr`, berpotensi menghentikan Isolate.

### 2. Implementasi & Contoh Kasus Nyata

Berikut implementasi komprehensif yang membandingkan gaya modern (`async`/`await` + `try-catch`) dengan chaining (`Future` API), termasuk penanganan tipe spesifik (`on Exception`) dan rethrowing.

```dart
import 'dart:async';
import 'dart:io';

// Domain Custom Exception
class NetworkTimeoutException implements Exception {
  final String message;
  final Duration elapsed;
  const NetworkTimeoutException(this.message, this.elapsed);

  @override
  String toString() => 'NetworkTimeoutException: $message ($elapsed)';
}

class UserRepository {
  // Simulasi pemanggilan HTTP client asinkron
  Future<String> fetchUserData({required bool simulateFailure}) async {
    await Future.delayed(const Duration(milliseconds: 100));
    
    if (simulateFailure) {
      throw const NetworkTimeoutException(
        'Koneksi ke gateway upstream timeout.',
        Duration(milliseconds: 100),
      );
    }
    return '{"id": "usr_99", "name": "Ahmad"}';
  }
}

// ---------------------------------------------------------------------------
// Pendekatan 1: Modern & Idiomatik (async/await + try-catch-finally)
// ---------------------------------------------------------------------------
Future<void> executeWithAsyncAwait(UserRepository repo) async {
  print('--- Memulai executeWithAsyncAwait ---');
  
  // Resource yang harus dibersihkan (misal: koneksi DB / file handle)
  var isResourceLocked = true;
  
  try {
    final payload = await repo.fetchUserData(simulateFailure: true);
    print('Data diterima: $payload');
  } on NetworkTimeoutException catch (e, stackTrace) {
    // Menangkap tipe error spesifik dengan StackTrace utuh
    print('[HANDLED] Tangkapan Timeout spesifik: $e');
    print('[STACKTRACE DAERAH RAW]:\n${stackTrace.toString().split('\n').first}');
  } on Exception catch (e) {
    // Tangkapan fallback untuk semua Exception lain
    print('[HANDLED] General Exception: $e');
  } catch (unknown, stackTrace) {
    // Menangkap Error atau objek non-Exception
    print('[CRITICAL] Tipe tak terduga lolos: $unknown');
    // Selalu gunakan 'rethrow' untuk menjaga origin stack trace
    rethrow;
  } finally {
    // Selalu dieksekusi (clean-up phase)
    isResourceLocked = false;
    print('[FINALLY] Resource dirilis. Locked status: $isResourceLocked');
  }
}

// ---------------------------------------------------------------------------
// Pendekatan 2: Functional / Stream-like Chaining (catchError + whenComplete)
// ---------------------------------------------------------------------------
Future<void> executeWithFutureChaining(UserRepository repo) {
  print('\n--- Memulai executeWithFutureChaining ---');
  var isResourceLocked = true;

  return repo
      .fetchUserData(simulateFailure: true)
      .then((payload) {
        print('Data diterima: $payload');
      })
      .catchError(
        (error, stackTrace) {
          print('[HANDLED via catchError] Error: $error');
          // Kembalikan nilai fallback bila perlu memulihkan pipeline
          return '';
        },
        // Filter predikat: hanya tangkap jika turunan Exception
        test: (error) => error is Exception,
      )
      .whenComplete(() {
        isResourceLocked = false;
        print('[WHEN_COMPLETE] Pipeline selesai. Locked status: $isResourceLocked');
      });
}

void main() async {
  final repo = UserRepository();
  
  await executeWithAsyncAwait(repo);
  await executeWithFutureChaining(repo);
}
```

#### Komponen Kunci Kode:
1. **`on NetworkTimeoutException catch (e, stackTrace)`**: Mengisolasi pemulihan kesalahan berdasarkan kontrak tipe kelas. Objek `stackTrace` memberikan jejak frame eksekusi tanpa alokasi manual.
2. **`rethrow`**: Menginstruksikan VM untuk meneruskan error yang sama ke caller tanpa menghapus atau menimpa (`reset`) call site asli pada `StackTrace`.
3. **`catchError(..., test: predicate)`**: Parameter opsional `test` mengevaluasi kondisi boolean runtime sebelum memutuskan handler mana yang berhak mengonsumsi error.
4. **`whenComplete`**: Menjamin pelepasan resource (mirip `finally`), namun tetap mempertahankan status error aslinya ke subscriber berikutnya jika `catchError` tidak dipasang sebelumnya.

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Desugaring `async`/`await`
Saat fungsi ditandai dengan `async`, Dart CFE (Common Front-End) mengompilasi fungsi tersebut menjadi sebuah **State Machine** berbasis closure internal.
- Setiap operator `await` memecah fungsi menjadi fase *resumption*.
- Jika `Future` yang di-await memanggil status `completeError(error, stackTrace)`, State Machine memanggil cabang internal penanganan exception yang melompat ke blok `catch` lokal yang sesuai.
- Di level microtask, runtime mendaftarkan callback `_thenAwait` di balik layar. Jika terjadi uncaught error, ia dikemas sebagai event microtask yang dilemparkan ke `ZoneSpecification.handleUncaughtError`.

#### Alokasi Memori / Resource
- **StackTrace Construction**: Pembentukan `StackTrace.current` adalah operasi yang mahal karena Dart VM harus melakukan *stack unwinding* dan membaca tabel metadata debug Isolate untuk memetakan pointer program (PC) ke baris kode.
- Menggunakan `rethrow` jauh lebih efisien dalam hal alokasi memori dibandingkan `throw e;` karena `throw e` membuat instance stack trace baru dari frame saat ini, sedangkan `rethrow` menggunakan kembali referensi metadata pointer yang sudah ada.

#### Perbedaan Semantik: `then(onError)` vs `catchError`
Perhatikan struktur chaining berikut:
```dart
// Pola A
future.then(handleSuccess, onError: handleError);

// Pola B
future.then(handleSuccess).catchError(handleError);
```
- **Pola A (`then` dengan `onError`)**: Jika `handleSuccess` melempar exception baru, `onError` **tidak akan** menangkapnya, karena `onError` hanya memantau kegagalan dari `future` awal.
- **Pola B (`then().catchError()`)**: `catchError` memantau seluruh rantai sebelumnya. Jika `future` gagal **atau** `handleSuccess` melempar exception, `catchError` akan menangkapnya.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `rethrow`**: Saat Anda menangkap error hanya untuk melakukan *logging* atau *side-effect*, selalu akhiri dengan `rethrow`.
  ```dart
  try {
    await service.connect();
  } catch (e) {
    logger.error('Log connection failure: $e');
    rethrow; // BENAR: Stack trace asli tetap utuh
  }
  ```
- **Spesifikasikan Tipe Exception**: Selalu prioritaskan `on SpecificException catch (e)` daripada sekadar `catch (e)`. Membiarkan tangkapan terlalu umum dapat menyembunyikan fatal runtime bugs seperti `TypeError` atau `NoSuchMethodError`.
- **Gunakan `async/await` secara konsisten**: Hindari mencampur chaining (`.catchError()`) di dalam method yang sudah dideklarasikan sebagai `async`. Gunakan `try-catch-finally` standar untuk konsistensi readability.

#### Don'ts
- **DILARANG melempar ulang via `throw e;`**:
  ```dart
  // SALAH
  try {
    await api.call();
  } catch (e) {
    throw e; // Menghilangkan stack trace asli asal mula error!
  }
  ```
- **DILARANG mengabaikan Future di dalam blok `catch`**:
  Memanggil method asinkron di dalam `catch` tanpa `await` dapat membuat error baru yang lolos ke global zone jika pemanggilan kedua tersebut gagal.

#### Edge Cases
- **Unawaited Futures di dalam `whenComplete`**:
  Jika callback di dalam `whenComplete` mengembalikan `Future`, Dart VM akan menunda penyelesaian downstream future sampai future dari `whenComplete` tersebut selesai. Namun, jika terjadi error di dalam `whenComplete`, error tersebut akan menimpa (overwrite) error atau value yang dihasilkan rantai sebelumnya.
- **Zone Boundaries**:
  Error yang dilempar dari `Timer` callback tidak dapat ditangkap oleh blok `try-catch` yang membungkus inisialisasi timer tersebut. Kesalahan ini hanya dapat ditangkap oleh `runZonedGuarded`.

### 5. Tantangan Eksplorasi Mandiri

1. **Investigasi Stack Trace Truncation**:
   Tulis program kecil yang memanggil fungsi bersarang (3 lapis: `funcA` -> `funcB` -> `funcC`). Lakukan error simulation di `funcC`. Bandingkan output `stackTrace` saat Anda menangkapnya di `funcB` menggunakan `throw e;` versus `rethrow`. Amati bagaimana perbedaan line number yang dilaporkan Dart VM.
2. **Zone Error Interception**:
   Gunakan fungsi `runZonedGuarded` untuk membungkus sebuah pemanggilan asinkron yang melempar error di dalam callback `Timer(Duration.zero, ...)`. Buktikan bahwa blok `try-catch` biasa gagal menangkap exception tersebut, tetapi `runZonedGuarded` mampu mengamankannya.
