## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sejak rilis Dart 3.0, *control flow* di Dart mengalami pergeseran paradigma dari model imperatif tradisional berbasis evaluasi skalar (`==`, boolean logic) menjadi sistem berbasis **Pattern Matching** dan **Algebraic Data Types (ADT)**. Perubahan ini mendekatkan Dart dengan bahasa fungsional modern seperti Rust dan Swift.

#### `if-case` dan Pattern Matching
Secara historis, percabangan kondisional memerlukan pemisahan antara pengujian tipe (`is`), pengecekan null (`!= null`), dan ekstraksi nilai (*casting* atau pemanggilan properti). Sintaks `if-case` menyatukan ketiga operasi ini ke dalam satu operasi atomik:
1. **Matching**: Memvalidasi apakah bentuk struktur data runtime sesuai dengan pola (*pattern*) yang didefinisikan.
2. **Destructuring**: Mengekstrak komponen internal dari objek/koleksi jika pola cocok.
3. **Binding**: Mengikat (*binding*) data yang diekstrak ke variabel lokal ber-cakupan (*scoped*) baru dengan jaminan *type safety*.

#### `switch`: Statement vs Expression
Dart membedakan `switch` menjadi dua bentuk:
- **Switch Statement**: Blok imperatif untuk mengeksekusi efek samping (*side effects*). Pada Dart 3+, *fall-through* implisit telah dihapus seluruhnya; eksekusi berhenti otomatis di akhir klausa `case` tanpa memerlukan instruksi `break`.
- **Switch Expression**: Memproduksi nilai secara langsung (`var result = switch (x) { ... };`). Mengharuskan **Exhaustiveness Checking** (pemeriksaan kelengkapan kasus). Jika tipe target adalah `sealed class`, `enum`, atau boolean, kompilator menjamin di fase kompilasi bahwa seluruh permutasi cabang telah ditangani tanpa memerlukan klausa `default` atau `_`.

#### Loops & Iteration Protocol
Loop imperatif (`for`, `while`, `do-while`) beroperasi pada level register/counter dan instruksi *conditional jump*. Sebaliknya, `for-in` mengimplementasikan protokol iterasi berbasis antarmuka:
- Target harus mengimplementasikan `Iterable<E>`.
- Runtime mengekstraksi `Iterator<E>` via getter `iterator`.
- Siklus berlanjut selama pemanggilan `moveNext()` mengembalikan `true`, mengakses elemen melalui getter `current`.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut menunjukkan integrasi modern antara *sealed classes*, `switch expressions`, `if-case` dengan *guard clause*, serta teknik *looping* tingkat lanjut.

```dart
import 'dart:math' as math;

// 1. Domain Model menggunakan Sealed Class Hierarchy
sealed class NetworkState<T> {}

class StateIdle<T> extends NetworkState<T> {}
class StateLoading<T> extends NetworkState<T> {}
class StateSuccess<T> extends NetworkState<T> {
  final T data;
  final int statusCode;
  StateSuccess(this.data, {this.statusCode = 200});
}
class StateFailure<T> extends NetworkState<T> {
  final String error;
  final int? errorCode;
  StateFailure(this.error, [this.errorCode]);
}

void main() {
  final NetworkState<Map<String, dynamic>> currentState = StateSuccess(
    {'userId': 42, 'role': 'admin', 'metrics': [10.5, 20.2, 30.8]},
    statusCode: 200,
  );

  // -------------------------------------------------------------
  // A. SWITCH EXPRESSION: Exhaustive Matching & Pattern Destructuring
  // -------------------------------------------------------------
  final uiMessage = switch (currentState) {
    StateIdle() => 'Menunggu inisialisasi...',
    StateLoading() => 'Memuat data dari server...',
    // Ekstraksi nilai bertingkat (Object Pattern + Map Pattern)
    StateSuccess(data: {'role': 'admin', 'userId': final id}) =>
      'Autentikasi Admin berhasil. User ID: $id',
    StateSuccess(data: final payload) =>
      'Autentikasi User berhasil. Payload size: ${payload.length}',
    // Relational Pattern & Logical Pattern
    StateFailure(errorCode: final code) when code != null && code >= 500 =>
      'Internal Server Error: Kode $code',
    StateFailure(error: final msg) => 'Kesalahan Klien: $msg',
  };

  print(uiMessage);

  // -------------------------------------------------------------
  // B. IF-CASE: Guard Clauses, Records, dan Null-Check Pattern
  // -------------------------------------------------------------
  final dynamic arbitraryPayload = (
    timestamp: DateTime.now().millisecondsSinceEpoch,
    metadata: {'source': 'gateway', 'priority': 1},
  );

  // Validasi bentuk Record sekaligus ekstraksi dengan guard 'when'
  if (arbitraryPayload case (
    timestamp: int ts,
    metadata: {'priority': int p}
  ) when p > 0) {
    print('Payload valid: Priority $p, Timestamp: $ts');
  } else {
    print('Payload korup atau tidak memenuhi prioritas.');
  }

  // -------------------------------------------------------------
  // C. ADVANCED LOOPS: Pattern Matching in For-In & Labeled Breaks
  // -------------------------------------------------------------
  final matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9],
  ];

  // Labeled loop untuk deep traversal control
  outerLoop:
  for (final (rowIndex, row) in matrix.indexed) {
    for (final (colIndex, val) in row.indexed) {
      if (val == 5) {
        print('Target 5 ditemukan pada koordinat: [$rowIndex, $colIndex]');
        break outerLoop; // Keluar langsung dari kedua layer loop
      }
    }
  }

  // Collection-for dengan destructuring langsung
  final coordinatePairs = [(0, 0), (10, 20), (-5, 15)];
  final normalizedPoints = [
    for (final (x, y) in coordinatePairs)
      if (x >= 0 && y >= 0) math.Point(x.toDouble(), y.toDouble()),
  ];

  print('Titik ternormalisasi: $normalizedPoints');
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Decision Tree vs Jump Table
- **Dart Common Front End (CFE)**: Saat mem-parsing `switch` statements, `switch` expressions, atau rantai `if-case`, CFE menyusun sebuah *Decision Tree* (Pohon Keputusan).
- **Primitive Matching**: Jika ekspresi mengevaluasi tipe diskrit sederhana (seperti `int` atau `enum`) dengan pola konstan yang rapat, CFE dan LLVM/AOT backend mengompilasinya menjadi **Jump Table** (instruksi percabangan terindeks $O(1)$) atau *Binary Search Tree Branching* ($O(\log N)$).
- **Complex Pattern Matching**: Untuk *Object Pattern* dan *Destructuring*, CFE mentranslasikan pola ke serangkaian instruksi imperatif berurutan: pengecekan tipe runtime (`type_check`), pengecekan slot memori, dan dereferensi pointer properti. Guard clause (`when`) dievaluasi terakhir setelah pattern structural match bernilai `true`.

#### Alokasi Memori & Resource
- **Variable Capture di Loop**: Pada loop `for (var i = 0; i < n; i++)`, jika ada closure/fungsi anonim yang meng-capture `i` di dalam tubuh loop, Dart tidak membagikan referensi memori yang sama. Kompilator mengalokasikan **konteks baru per iterasi** (*box allocation* di heap) untuk memastikan setiap closure memegang salinan nilai `i` independen.
- **Destructuring Spilling**: Variabel baru hasil binding pola (misal: `StateSuccess(data: final d)`) disimpan langsung pada *stack frame* lokal. Jika jumlah variabel melebihi register CPU yang tersedia, terjadi *stack spilling*, namun tidak ada alokasi heap baru yang dibuat hanya untuk proses *destructuring* itu sendiri.

#### Trade-offs
- **Switch Expression vs Polimorfisme Murni**: Menggunakan `switch` expression di atas `sealed class` memusatkan logika manipulasi data di satu tempat (paradigma fungsional). Trade-off-nya adalah pelanggaran prinsip *Open-Closed Principle* (OCP) jika ditinjau dari kacamata OOP murni: menambah sub-tipe baru pada `sealed class` memaksa pembaruan di semua `switch` expression yang terkait di seluruh codebase.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Manfaatkan Exhaustiveness**: Hindari menambahkan `default:` atau wildcard `_:` pada `switch` yang memeriksa `sealed class` atau `enum`, kecuali jika memang ada fallback generik yang valid. Membiarkan kompilator melempar galat kompilasi saat ada varian sub-tipe baru adalah strategi defensif terbaik.
- **Gunakan Switch Expression untuk Transformasi Nilai**: Pilih `switch` expression daripada `if-else if` bertingkat ketika memetakan input ke suatu output untuk mengeliminasi mutable state (`late` variable initialization).
- **Deklarasikan Pola dengan Spesifik**: Gunakan bentuk destructuring bertingkat untuk mengurangi dependensi rantai navigasi `obj?.prop?.subProp`.

#### Don'ts
- **Hindari Mutasi Koleksi Saat Looping**: Mengubah ukuran koleksi (`add`, `remove`) saat sedang diiterasi via `for-in` akan memicu `ConcurrentModificationError` saat runtime karena state internal `Iterator._version` tidak lagi sinkron.
- **Jangan Gunakan Break Bertingkat Manual**: Hindari penggunaan boolean flag (`bool found = false;`) untuk memutus iterasi bersarang (*nested loop*). Gunakan *labeled statements* (`break myLabel;`).

#### Edge Cases
- **Null-Check vs Null-Assert Pattern**:
  - `case int? x`: Mencocokkan nilai jika bertipe `int` atau `null`.
  - `case final x?`: Null-check pattern. Hanya cocok jika nilai **tidak null** dan melakukan unwrap tipe menjadi non-nullable.
  - `case final x!`: Null-assert pattern. Memaksa runtime unwrap; melempar runtime exception jika nilainya null.

```dart
// PERINGATAN: Null-check vs Null-assert
final int? nullableScore = null;

// Pattern Matching Aman (Null-check)
if (nullableScore case final score?) {
  print('Skor ada: $score');
} else {
  print('Skor null, cabang ini dieksekusi secara aman.');
}

// Berbahaya (Null-assert) -> Melempar TypeError / CastError saat runtime
// if (nullableScore case final score!) { ... }
```

### 5. Tantangan Eksplorasi Mandiri

1. **Parser AST (Abstract Syntax Tree)**: Definisikan sebuah `sealed class Expression` dengan varian `Number(double val)`, `Add(Expression left, Expression right)`, dan `Multiply(Expression left, Expression right)`. Tulis sebuah fungsi evaluator menggunakan `switch expression` yang menyelesaikan perhitungan aritmatika tersebut secara rekursif.
2. **Exhaustive JSON Validation**: Buat fungsi verifikasi respon API yang menerima `dynamic` JSON. Gunakan `if-case` dengan integrasi *Map Pattern*, *List Pattern*, dan *Relational Pattern* untuk memverifikasi bahwa JSON memiliki format:
   `{"code": 200, "items": [{"id": String, "score": int >= 50}]}` secara sepenuhnya type-safe tanpa bantuan library eksternal.
