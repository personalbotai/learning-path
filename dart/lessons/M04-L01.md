## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum Dart 3.0, pengembang menghadapi dilema ketika sebuah fungsi perlu mengembalikan lebih dari satu nilai:
1. Membuat *class* baru khusus untuk menampung data (menghasilkan *boilerplate* kode yang besar).
2. Menggunakan koleksi seperti `List` atau `Map` (mengorbankan *type-safety* dan performa).
3. Menggunakan *third-party package* seperti `tuple` (kurang terintegrasi secara ergonomis di level bahasa).

**Records** hadir di Dart 3.0 sebagai tipe data agregat anonim, *immutable*, dan berukuran tetap (*fixed-sized*). Berbeda dengan *class* yang berbasis **Nominal Typing** (dua kelas dengan struktur identik dianggap berbeda jika namanya berbeda), Record mengadopsi **Structural Typing**. Artinya, bentuk (*shape*) dari Record menentukan kesetaraan tipenya. Dua Record dengan tipe field dan label yang sama pada posisi yang sama dianggap memiliki tipe yang identik.

```
       Nominal Typing (Class)                Structural Typing (Record)
   ┌─────────────────────────────┐        ┌──────────────────────────────┐
   │ class PointA { int x, y; }  │        │ (int, int) a = (10, 20);     │
   │ class PointB { int x, y; }  │   ≠    │ (int, int) b = (10, 20);     │   =
   │ PointA != PointB            │        │ a.runtimeType == b.runtimeType│
   └─────────────────────────────┘        └──────────────────────────────┘
```

Secara arsitektural, Record memungkinkan dekomposisi data secara efisien melalui integrasi mendalam dengan sistem *pattern matching* dan *destructuring* Dart. Record mendukung dua jenis *field*:
- **Positional Fields**: Diakses menggunakan sintaks `.$1`, `.$2`, dst.
- **Named Fields**: Diberi anotasi label eksplisit dan diakses langsung melalui nama field-nya.

Karakteristik penting Record:
- **Immutable**: Nilai field tidak dapat diubah setelah diinstansiasi.
- **Value Equality**: Implementasi `operator ==` dan `hashCode` diturunkan secara otomatis dari nilai seluruh field di dalamnya, bukan berdasarkan *identity/reference memory address*.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengilustrasikan fungsi parser HTTP response yang mengembalikan status code, payload JSON terurai, dan metadata latency menggunakan Record campuran (*positional* & *named*), lengkap dengan proses *destructuring*.

```dart
import 'dart:convert';

// Definisi type alias untuk Record agar signature fungsi tetap bersih dan ekspresif
typedef HttpResponseResult = (int statusCode, {Map<String, dynamic> data, Duration latency});

// Simulasi network client yang mengembalikan multiple values secara anonim
HttpResponseResult executeHttpRequest(String rawResponse, DateTime requestStartTime) {
  final stopwatch = DateTime.now().difference(requestStartTime);
  
  try {
    final Map<String, dynamic> decoded = jsonDecode(rawResponse);
    final status = decoded['status'] as int? ?? 200;
    
    // Mengembalikan Record literal: kombinasi 1 positional field dan 2 named fields
    return (
      status, 
      data: decoded['payload'] as Map<String, dynamic>? ?? {}, 
      latency: stopwatch
    );
  } catch (e) {
    // Return status error jika deserialisasi gagal
    return (
      500, 
      data: {'error': e.toString()}, 
      latency: stopwatch
    );
  }
}

void main() {
  final simulatedJson = '{"status": 200, "payload": {"userId": "usr_99X", "role": "admin"}}';
  final startTime = DateTime.now();

  // 1. Pemanggilan fungsi dan penampungan hasil ke variabel Record
  final HttpResponseResult response = executeHttpRequest(simulatedJson, startTime);

  // Akses manual via positional ($1) dan named field
  print('Status: ${response.$1}');
  print('Latency: ${response.latency.inMicroseconds}µs');

  // 2. Destructuring menggunakan Pattern Matching modern
  final (statusCode, data: payload, latency: _) = response;
  
  if (statusCode == 200) {
    print('User ID: ${payload['userId']}');
  }

  // 3. Demonstrasi Structural Equality
  final (int, {String label}) recordA = (1, label: 'alpha');
  final (int, {String label}) recordB = (1, label: 'alpha');
  
  // Bernilai true karena struktur dan isi field identik
  print('Structural Equality: ${recordA == recordB}'); 
  print('Hash Identical: ${recordA.hashCode == recordB.hashCode}');

  // 4. Edge Case: Single-element positional record
  // Butuh tanda koma ',' untuk membedakannya dari tanda kurung pengelompokan ekspresi biasa
  final (int,) singleElement = (42,);
  print('Single-element value: ${singleElement.$1}');
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Kompilasi & Representasi AST (Abstract Syntax Tree)
Di tingkat *front-end compiler* Dart (CFE / Common Front End), ekspresi Record diubah menjadi representasi tipe internal `RecordType`. CFE secara otomatis mengurutkan nama-nama *named fields* secara leksikografis (alfabetis). 
Sebagai contoh, tipe `({int b, String a})` dan `({String a, int b})` akan dinormalisasi ke struktur kanonikal yang sama: `({String a, int b})`. Hal ini menjaga konsistensi resolusi *vtable* dan pengecekan tipe pada saat *compile-time*.

#### Eksekusi & Runtime Dart VM / AOT
- **Class Synthesis**: Berbeda dengan bahasa tingkat rendah seperti C++ di mana `std::tuple` bisa sepenuhnya di-*unroll* pada *stack*, Dart VM memperlakukan Record sebagai *heap-allocated objects*. Dart VM menghasilkan kelas-kelas representasi internal (misalnya `_Record`, `_Record2`, `_Record3` untuk ariti kecil guna menghindari alokasi array internal).
- **Inlining & Escape Analysis**: Pada kompilasi AOT (*Ahead-Of-Time*), jika Record hanya digunakan secara lokal dalam satu *stack frame* (misalnya untuk mengembalikan dua nilai yang langsung di-*destructure*), *escape analysis* pada compiler VM dapat mengeliminasi alokasi heap sama sekali melalui teknik **scalar replacement**. Field-field dalam Record akan dipecah langsung ke register CPU atau stack frame lokal.
- **Structural Equality CodeGen**: Compiler secara otomatis menghasilkan fungsi hash gabungan:
  ```dart
  // Pseudocode implementasi operator== pada Record di level runtime
  bool operator==(Object other) {
    if (identical(this, other)) return true;
    if (other is! ShapeOfRecord) return false;
    return this.$1 == other.$1 && this.namedField == other.namedField;
  }
  ```

#### Trade-offs Performa
- **Record vs Class**: Record menghemat memori *metadata* kelas karena tidak memerlukan deklarasi *class descriptor* terpisah per instansiasi ad-hoc. Namun, pemanggilan field melalui abstraksi Record polimorfik non-monomorfik dapat kehilangan optimasi *inline caching* jika bentuk Record terlalu dinamis.
- **Pass-by-Reference**: Record tetap dilewatkan sebagai pointer referensi (kecuali terjadi optimasi register unboxing oleh AOT), sehingga melempar Record dengan banyak elemen tidak menduplikasi nilai data di memori secara redundan.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan untuk Multiple Return Values internal**: Record sangat ideal untuk fungsi *private* atau metode internal modul yang perlu mengembalikan tuple data tanpa mengekspos representasi kelas keluar.
- **Manfaatkan Typedef**: Jika sebuah Record dipakai lebih dari dua kali dalam satu berkas, gunakan `typedef` untuk menyederhanakan deklarasi tipe yang panjang:
  ```dart
  typedef GeoPoint = (double latitude, double longitude);
  ```
- **Prioritaskan Named Fields bila > 2 Field**: Menggunakan `(int, String, bool, double)` sangat rawan salah baca (*ambiguous*). Ubah menjadi `(int id, {String name, bool isActive, double score})`.

#### Don'ts
- **Jangan gunakan Record sebagai Domain Model Utama**: Hindari mengekspos Record di boundary arsitektur aplikasi (seperti Entity layer pada Clean Architecture). Record tidak dapat memiliki *encapsulation*, *validation invariants* (tidak ada *constructor body* untuk melempar error), atau *private state*.
- **Jangan gunakan untuk State yang membutuhkan Mutasi**: Record bersifat *deeply immutable* pada tingkat referensi field-nya. Mengubah nilai membutuhkan pembuatan Record baru.

#### Common Pitfalls
- **Single Positional Record Syntax**:
  ```dart
  var x = (42);   // BUKAN Record! Ini adalah integer 42 dalam tanda kurung prioritas operasi.
  var x = (42,);  // RECORD dengan 1 elemen positional (tipe: (int,)).
  ```
- **Ketidaksengajaan Melanggar Named Parameter Equality**:
  Urutan penulisan *named argument* saat instansiasi tidak mempengaruhi equality, tetapi *nama* label adalah bagian permanen dari tipe:
  ```dart
  ({int a, int b}) r1 = (a: 1, b: 2);
  ({int x, int y}) r2 = (x: 1, y: 2);
  // r1 = r2; // COMPILE ERROR: Berbeda tipe secara struktural karena nama field berbeda.
  ```

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Priority Queue Batch Return**:
   Rancang sebuah fungsi antrean tugas (`TaskQueue`) yang memproses daftar objek dan mengembalikan sebuah Record berisikan:
   - Positional `$1`: `int` (jumlah task berhasil).
   - Positional `$2`: `int` (jumlah task gagal).
   - Named `unprocessed`: `List<Task>` (daftar task yang tertunda).
   Gunakan teknik *pattern destructuring* untuk menangani *tuple* hasil kembalian tersebut.

2. **Benchmarking Alokasi Memori**:
   Tulis program Dart kecil yang membandingkan alokasi dan eksekusi antara membuat 1.000.000 instansiasi `class Coordinate { final double x, y; Coordinate(this.x, this.y); }` versus Record `(double, double)`. Jalankan menggunakan command `dart compile exe` dan amati penggunaan memori serta waktu pemrosesan menggunakan Dart DevTools / profiler. Analisis apakah terjadi scalar replacement saat Record langsung didekomposisi dalam sebuah loop.
