## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Secara fundamental, Dart mengadopsi model konkurensi berbasis **Actor Model**, bukan model *shared-memory multithreading* konvensional seperti Java atau C++. Dalam runtime Dart, semua kode dieksekusi di dalam **Isolate**. 

Sesuai namanya, sebuah *Isolate* mengisolasi:
1. **Memory Heap**: Tidak ada *shared state* antar-Isolate. Tidak ada variabel global bersama, sehingga kondisi *race condition* pada memori dan kebutuhan primitif sinkronisasi tingkat rendah (seperti *mutex*, *semaphore*, atau *synchronized blocks*) tereliminasi secara desain.
2. **Event Loop**: Setiap Isolate memiliki *event queue*, *microtask queue*, dan *thread executor* independen.

```
+------------------------------------+      +------------------------------------+
|            Main Isolate            |      |           Worker Isolate           |
|  +--------------+  +------------+  |      |  +--------------+  +------------+  |
|  |  Event Loop  |  |  Heap Mem  |  |      |  |  Event Loop  |  |  Heap Mem  |  |
|  +-------+------+  +------------+  |      |  +-------^------+  +------------+  |
|          |                         |      |          |                         |
|     [SendPort B] ------------------+------+----------+                         |
|          ^                         |      |                                    |
|          |                         |      |                                    |
|   (ReceivePort A) <----------------+------+-- [SendPort A]                     |
+------------------------------------+      +------------------------------------+
                   Message Passing (Copy / Pointer Swap)
```

Untuk mendistribusikan beban kerja komputasi berat (CPU-bound) ke core CPU lain, Dart menyediakan API `Isolate.spawn()`. Karena memori terisolasi, komunikasi antar-Isolate dilakukan secara eksklusif melalui **Message Passing** menggunakan pasangan:
- **`ReceivePort`**: Sebuah *stream-like listener* yang berada di Isolate penerima. Bertindak sebagai *endpoint* untuk menerima pesan dan mengumpankannya ke *event loop* lokal.
- **`SendPort`**: Objek referensi pesan yang dapat dikirimkan lintas Isolate. Isolate pengirim menulis data ke `SendPort` untuk diteruskan ke `ReceivePort` pasangannya.

Komunikasi dua arah (*bidirectional communication*) memerlukan proses *handshake*: Isolate pemanggil mengirimkan `SendPort`-nya sendiri saat inisialisasi, dan Isolate pekerja membalas dengan `SendPort` miliknya.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengimplementasikan **Bidirectional Worker Isolate** yang bertugas memproses data intensif CPU (komputasi hash/transformasi data numerik) secara kontinu tanpa memblokir Main Thread / UI Isolate.

```dart
import 'dart:async';
import 'dart:isolate';

/// Protokol pesan untuk request ke Worker
sealed class WorkerCommand {}

final class ComputeTask extends WorkerCommand {
  final int id;
  final List<int> payload;
  ComputeTask(this.id, this.payload);
}

final class ShutdownCommand extends WorkerCommand {}

/// Protokol pesan untuk response dari Worker
final class TaskResult {
  final int id;
  final int computedValue;
  TaskResult(this.id, this.computedValue);
}

/// Entry-point function untuk Isolate baru.
/// HARUS berupa top-level function atau static method.
void _workerEntryPoint(SendPort initialReplyTo) {
  // 1. Buat ReceivePort untuk mendengarkan perintah masuk di worker ini
  final workerReceivePort = ReceivePort();

  // 2. Handshake: Kirim SendPort milik worker kembali ke main isolate
  initialReplyTo.send(workerReceivePort.sendPort);

  // 3. Dengarkan stream pesan yang masuk ke worker
  workerReceivePort.listen((message) {
    if (message is ComputeTask) {
      // Simulasi komputasi CPU-bound berat
      var sum = 0;
      for (final n in message.payload) {
        sum += (n * n);
      }

      // Kirim hasil kembali ke main isolate via port yang tersimpan
      initialReplyTo.send(TaskResult(message.id, sum));
    } else if (message is ShutdownCommand) {
      workerReceivePort.close();
      Isolate.current.kill(priority: Isolate.immediate);
    }
  });
}

/// Abstraksi Controller untuk mengelola lifecycle Worker dari Main Isolate
class HeavyComputeWorker {
  late Isolate _isolate;
  late ReceivePort _mainReceivePort;
  late SendPort _workerSendPort;
  final Completer<void> _readyCompleter = Completer<void>();
  final Map<int, Completer<int>> _pendingTasks = {};

  Future<void> init() async {
    _mainReceivePort = ReceivePort();

    // Spawn Isolate baru
    _isolate = await Isolate.spawn<SendPort>(
      _workerEntryPoint,
      _mainReceivePort.sendPort,
      debugName: 'HeavyComputeWorker',
    );

    // Event listener pada Main Isolate
    _mainReceivePort.listen((message) {
      if (message is SendPort) {
        // Handshake selesai: Worker mengirim SendPort miliknya
        _workerSendPort = message;
        _readyCompleter.complete();
      } else if (message is TaskResult) {
        // Selesaikan completer task yang cocok berdasarkan id
        final completer = _pendingTasks.remove(message.id);
        completer?.complete(message.computedValue);
      }
    });

    await _readyCompleter.future;
  }

  Future<int> execute(int taskId, List<int> data) async {
    final completer = Completer<int>();
    _pendingTasks[taskId] = completer;

    _workerSendPort.send(ComputeTask(taskId, data));
    return completer.future;
  }

  void dispose() {
    _workerSendPort.send(ShutdownCommand());
    _mainReceivePort.close();
    _isolate.kill(priority: Isolate.beforeNextEvent);
  }
}

void main() async {
  print('[Main] Menginisialisasi worker isolate...');
  final worker = HeavyComputeWorker();
  await worker.init();
  print('[Main] Worker siap menerima tugas.');

  // Eksekusi task secara asinkron tanpa memblokir Main Isolate
  final futures = List.generate(3, (index) {
    final dataset = List.generate(5000000, (i) => i + index);
    return worker.execute(index, dataset).then((result) {
      print('[Main] Task $index selesai. Hasil: $result');
    });
  });

  await Future.wait(futures);

  print('[Main] Membersihkan resource isolate...');
  worker.dispose();
  print('[Main] Program selesai.');
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- Ketika `Isolate.spawn()` dipanggil, Dart VM mengalokasikan konteks eksekusi baru. Dart VM memanfaatkan **OS Thread Pool** native (misal: *pthreads* di Linux/macOS). 
- Isolate tidak terikat statis 1:1 pada OS thread permanen. Dart VM scheduler dapat memindahkan Isolate yang sedang aktif ke thread yang tersedia dalam pool saat mengeksekusi microtask/event queue-nya.

#### Alokasi Memori & Transmisi Data
- Objek primitif (`int`, `double`, `bool`, `null`, `String`) serta *Object Graphs* yang dikirim melalui `SendPort.send()` secara default mengalami **Deep-Copy Serialization**. Dart VM menyalin grafik objek dari heap Isolate pengirim ke heap Isolate penerima.
- **Optimasi Dart VM Modern**: Untuk data yang tidak dapat dimutasi (*immutable*) atau *unmodifiable views*, runtime Dart mengoptimalkan pesan dengan mekanisme **Pointer Swap** (transfer kepemilikan memori) daripada penyalinan byte per byte.
- Jika mengirimkan *byte buffer* biner berukuran besar (misalnya: *frame* kamera atau file video), gunakan `TransferableTypedData`. Objek ini mentransfer kepemilikan pointer memori native C secara instan ($O(1)$) antar-heap, lalu membuat buffer di Isolate asal menjadi tidak valid (*detached/cleared*).

#### Trade-offs
- **Overhead Inisialisasi**: Melakukan `Isolate.spawn()` memiliki penalti latensi (beberapa milidetik) dan memori (sekitar 30KB - 2MB untuk alokasi heap awal dan struktur data VM). Hindari *spawn-and-kill* secara berulang dalam interval cepat; gunakan pola *Long-lived Worker Isolate* atau `Isolate.run()` untuk operasi *one-off*.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Tutup Port Secara Eksplisit**: Selalu panggil `ReceivePort.close()`. Jika port tetap terbuka, *event loop* Isolate tidak akan pernah kosong, mencegah Isolate dan Garbage Collector membebaskan memori Isolate tersebut.
- **Tangani Error Lintas Isolate**: Daftarkan port penanganan kesalahan menggunakan `Isolate.addErrorListener()` atau argumen `onError` pada `Isolate.spawn()`. Unhandled exception di spawned isolate tidak akan memicu `catch` block di main isolate.
- **Manfaatkan `Isolate.run()` untuk Kasus Ringkas**: Untuk tugas komputasi sekali jalan (*fire-and-forget*), gunakan helper `Isolate.run(() => heavyWork())` (tersedia sejak Dart 2.19+) yang secara internal menangani lifecycle `spawn`, `SendPort`, `ReceivePort`, dan `kill`.

#### Don'ts
- **Jangan Mengirim Objek Non-Transferable**: `SendPort.send()` akan melempar runtime exception jika mencoba mengirim:
  - Objek dengan *native resource* terbuka (misal: `RandomAccessFile`, `Socket`).
  - *Closures* yang meng-*capture* state lokal konteks Isolate lain.
- **Jangan Gunakan Isolate untuk I/O-Bound Task**: Operasi seperti `File.readAsString()` atau `http.get()` sudah beroperasi secara *asynchronous* non-blocking di tingkat I/O thread Dart VM. Menjalankan I/O task di Isolate baru hanya menambah *overhead serialization* tanpa keuntungan konkurensi CPU.

#### Edge Cases
- **Silent Crash**: Jika worker Isolate mengalami *crash* karena unhandled exception (misalnya: `OutOfMemoryError`), main isolate akan menggantung (*hang*) selamanya pada `Completer` jika Anda tidak mendaftarkan `onError` port atau *timeout strategy*.

```dart
// Pola mitigasi penanganan error Isolate yang robust:
final errorPort = ReceivePort();
errorPort.listen((errorData) {
  final stackTrace = (errorData as List)[1];
  print('Isolate Error terdeteksi: $errorData');
  // Gagalkan completer atau restart worker di sini
});

await Isolate.spawn(
  _workerEntryPoint,
  mainReceivePort.sendPort,
  onError: errorPort.sendPort,
  onExit: exitPort.sendPort, // Notifikasi jika isolate mati
);
```
