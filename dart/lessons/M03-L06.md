### 1. Konsep & Arsitektur Mendalam

Dalam sistem tipe Dart (khususnya sejak Dart 2.12 dengan *sound null safety* dan Dart 2.13 dengan *generalized typedefs*), sistem kompilasi mengandalkan verifikasi statis yang ketat (*static sound type system*) yang didukung oleh representasi tipe saat eksekusi (*reified types*). Dua pilar penting dalam arsitektur tipe modern ini adalah **Typedefs (Type Aliases)** dan **Generic Constraints (Bounded Polymorphism)**.

#### Typedefs (Generalized Type Aliases)
Secara historis di Dart 1.x hingga awal Dart 2.x, `typedef` hanya dapat digunakan untuk mendefinisikan signature fungsi (*function signatures*). Namun, sejak Dart 2.13, Dart mengadopsi *generalized typedefs*. Sintaks ini memungkinkan pembuatan alias struktural untuk tipe apa pun: primitives, classes, function types, generic collections, hingga Records.

```dart
// Modern Generalized Typedef
typedef JsonMap = Map<String, dynamic>;
typedef Predicate<T> = bool Function(T value);
typedef Pair<T> = (T first, T second);
```

Secara arsitektural, `typedef` **bukanlah deklarasi tipe nominal baru (*nominal subtyping*)**, melainkan **alias identik (*structural synonym*)**. Compiler tidak membedakan alias dari tipe aslinya:
- `JsonMap` dan `Map<String, dynamic>` berbagi type identifier yang sama secara internal.
- `typedef UserId = String;` dan `typedef OrderId = String;` tetap saling substitutif (*interchangeable*). Compiler tidak menganggap keduanya sebagai tipe terisolasi. Jika menginginkan isolasi total, kita membutuhkan *wrapper class* atau *extension types* (Dart 3.0+).

#### Generic Constraints (Bounded Polymorphism)
Secara default, parameter generik `<T>` di Dart memiliki *implicit upper bound* berupa `Object?`, yang berarti `T` dapat diisi oleh tipe apa pun, baik nullable maupun non-nullable.

*Generic Constraint* menggunakan kata kunci `extends` untuk menetapkan batas atas (*upper bound*) dari hierarki pewarisan tipe yang valid:

$$\mathcal{T} \subseteq \text{Upper Bound}$$

Tujuan arsitekturalnya adalah:
1. **Memperluas Kapabilitas Anggota (Member Access)**: Tanpa batasan, variabel berjenis `T` hanya dapat mengakses metode dari `Object?` (`toString()`, `hashCode`, `==`). Dengan `T extends BaseEntity`, compiler mengizinkan akses langsung ke semua properti dan metode `BaseEntity` secara *type-safe*.
2. **Menegakkan Sound Nullability**: Batasan `<T extends Object>` secara eksplisit melarang passing `null` atau tipe nullable (`String?`) ke generic parameter tersebut.
3. **F-Bounded Polymorphism**: Batasan rekursif di mana tipe parameter merujuk kembali pada dirinya sendiri, misalnya `<T extends Comparable<T>>`. Konsep ini memastikan bahwa sebuah entitas hanya dapat dibandingkan dengan tipenya sendiri, bukan sembarang turunan `Comparable`.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengilustrasikan implementasi *type-safe data pipeline* dengan generalized typedefs, recursive generic constraints (*F-bounded*), dan non-null bounds.

```dart
// 1. Generalized Typedefs untuk abstraksi struktur data kompleks
typedef EntityId = String;
typedef Serializer<T> = Map<String, dynamic> Function(T entity);
typedef ValidationResult = ({bool isValid, List<String> errors}); // Record Typedef

// 2. Kontrak Abstrak menggunakan F-Bounded Polymorphism
abstract class SerializableEntity<T extends SerializableEntity<T>> {
  EntityId get id;
  
  /// Memastikan operasi kloning atau penggabungan mengembalikan tipe konkret T,
  /// bukan sekadar instance dari SerializableEntity.
  T copyWith();
  
  Map<String, dynamic> toJson();
}

// 3. Subclass konkret
class UserProfile extends SerializableEntity<UserProfile> {
  @override
  final EntityId id;
  final String username;
  final int reputation;

  UserProfile({
    required this.id,
    required this.username,
    required this.reputation,
  });

  @override
  UserProfile copyWith({String? username, int? reputation}) {
    return UserProfile(
      id: id,
      username: username ?? this.username,
      reputation: reputation ?? this.reputation,
    );
  }

  @override
  Map<String, dynamic> toJson() => {
        'id': id,
        'username': username,
        'reputation': reputation,
      };
}

// 4. Service generic dengan Bounded Polymorphism
// Membatasi T hanya untuk SerializableEntity, dan membatasi U hanya untuk Comparable
class EntityRepository<T extends SerializableEntity<T>> {
  final Map<EntityId, T> _storage = {};

  void save(T entity) {
    _storage[entity.id] = entity;
  }

  T? findById(EntityId id) => _storage[id];

  /// Mengurutkan entitas berdasarkan properti tertentu yang mengimplementasikan Comparable.
  /// Nullability dihindari secara presisi dengan generic constraint `K extends Comparable<Object>`.
  List<T> getSortedBy<K extends Comparable<Object>>(K Function(T entity) keyExtractor) {
    final list = _storage.values.toList();
    list.sort((a, b) => keyExtractor(a).compareTo(keyExtractor(b)));
    return list;
  }

  /// Bulk processor menggunakan fungsi callback tipe alias
  void processBatch(void Function(T item) processor) {
    for (final entity in _storage.values) {
      processor(entity);
    }
  }
}

void main() {
  final userRepo = EntityRepository<UserProfile>();

  final user1 = UserProfile(id: 'u-001', username: 'alice', reputation: 450);
  final user2 = UserProfile(id: 'u-002', username: 'bob', reputation: 820);

  userRepo.save(user1);
  userRepo.save(user2);

  // Sorting strictly type-safe berdasarkan integer (int mengimplementasikan Comparable<num>)
  final sortedUsers = userRepo.getSortedBy((user) => user.reputation);
  
  for (final user in sortedUsers) {
    print('${user.username} - Rep: ${user.reputation}');
  }

  // Penggunaan Record Typedef
  final ValidationResult validation = (
    isValid: user1.reputation >= 0,
    errors: user1.reputation < 0 ? ['Reputation cannot be negative'] : const []
  );

  print('Validation state: ${validation.isValid}');
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Reified Generics vs. Type Erasure
Berbeda dari Java yang melakukan *type erasure* (menghapus metadata tipe generic saat kompilasi ke bytecode), **Dart menggunakan *reified generic types***.
- Saat program dikompilasi oleh CFE (*Common Front End*) ke format AST (*Kernel binary/Dill*), informasi tipe parameter tetap dipertahankan.
- Di runtime (AOT compiled machine code atau JIT runtime di VM), instance `EntityRepository<UserProfile>` membawa referensi pointer ke deskriptor metadata tipe `UserProfile`.
- Operasi runtime seperti `entity is T` atau `List<T> is List<UserProfile>` benar-benar divalidasi oleh VM menggunakan lookup table hierarki kelas tipe runtime.

```
+-----------------------------------------------------------+
|                   Common Front End (CFE)                  |
|  - Desugaring: Typedef diganti dengan tipe aslinya        |
|  - Verifikasi Subtyping: Validasi batasan Upper Bound     |
+-----------------------------+-----------------------------+
                              | Menghasilkan Kernel AST (.dill)
                              v
+-----------------------------------------------------------+
|                      Dart Runtime / AOT                   |
|  - Menyimpan Type Arguments sebagai Type Objects          |
|  - Mengeksekusi Dynamic Subtype Checks (is / as)          |
+-----------------------------------------------------------+
```

#### Typedef Resolution
- `typedef` dievaluasi murni pada tahap kompilasi (*AST canonicalization*).
- Kompiler mengganti setiap kemunculan `JsonMap` langsung dengan struktur kanonikal `Map<String, dynamic>`.
- Akibatnya, `typedef` memiliki **zero runtime memory overhead** dan **zero indirection penalty**. Menggunakan 10 layer nested typedefs tidak akan menambah overhead pemanggilan fungsi atau alokasi heap baru.

#### Alokasi Memori & Resource
- Parameter generik yang di-reify (`<T>`) disimpan sebagai bagian dari header objek instance kelas bersangkutan. Ini menambah ukuran memori setiap instansiasi sebesar 1 pointer word (biasanya 8 byte pada arsitektur 64-bit) untuk menampung *type argument vector*.
- Jika batas generik kompleks digunakan (misal F-Bounds), compiler membuat representasi closure tipe yang di-cache di runtime untuk memvalidasi subtype relationship tanpa perlu merekonstruksi type tree berulang kali.

#### Trade-offs: Generics Covariance
Secara default, parameter tipe generic pada class di Dart bersifat **covariant**. Artinya, jika `Dog extends Animal`, maka `List<Dog>` dianggap sebagai subtype dari `List<Animal>`.
- **Kelebihan**: Fleksibilitas tinggi dalam koleksi dan arsitektur polymorphic (mudah dipassing ke function yang menerima `List<Animal>`).
- **Kekurangan**: Membuka potensi runtime failure. Kode berikut lolos kompilasi statis namun melempar *runtime exception*:
  ```dart
  List<Animal> animals = <Dog>[]; // Legal karena covariance
  animals.add(Cat()); // Compile lolos! Tapi Runtime melempar TypeError: Cat is not a subtype of Dog
  ```

### 4. Best Practices & Common Pitfalls

#### Do's
1. **Gunakan Typedef untuk Mendokumentasikan Kontrak Kompleks**: Buat alias untuk *Higher-Order Functions* kompleks atau Record structures berukuran besar untuk menjaga kebersihan signature function.
2. **Gunakan Non-nullable Bounds `<T extends Object>`**: Jika sebuah parameter generik tidak boleh menerima nilai `null`, definisikan batas atasnya secara eksplisit ke `Object`. Parameter `<T>` tanpa batasan mengasumsikan `<T extends Object?>`.
   ```dart
   // T dilarang bernilai null
   class Cache<T extends Object> { ... }
   ```
3. **Manfaatkan Recursive Bounds untuk Operasi Sejenis**: Terapkan `<T extends Comparable<T>>` ketika mendesain algoritma komparasi, pencarian binary, atau sorting buatan sendiri.

#### Don'ts
1. **Jangan Mengira Typedef Menciptakan Primitive Type Safety Baru**:
   ```dart
   typedef Meters = double;
   typedef Inches = double;

   Meters distance = 100.0;
   Inches height = distance; // BUKAN compile error! Ini valid di Dart.
   ```
   *Solusi*: Jika membutuhkan pembatasan domain type yang ketat, gunakan `extension type` (Dart 3.0+) alih-alih `typedef`.
2. **Hindari Constraint yang Terlalu Spesifik jika Tidak Perlu**: Jangan membatasi generic class ke subclass konkret jika abstraksi hanya membutuhkan sebuah *Interface*. Batasi ke interface terkecil yang mencukupi (*Interface Segregation Principle*).

#### Edge Cases & Runtime Traps
- **Instansiasi Dynamic Generic**: Ketika instansiasi class generik tidak menyertakan tipe argumen, runtime akan otomatis menerapkan batas atasnya (*upper bound*). Jika batasnya tidak didefinisikan, ia menjadi `dynamic`.
  ```dart
  class Container<T extends num> {
    final T value;
    Container(this.value);
  }
  
  var c = Container(10); // Inferensi: Container<int>
  // Namun jika raw type dipaksa:
  Container raw = Container(10); // Container<num> (fallback ke upper bound)
  ```
- **Type Checking pada Typedef Generik**: Evaluasi tipe runtime (`is`) terhadap typedef generik harus mempertimbangkan parameter tipe yang di-reify:
  ```dart
  typedef Action<T> = void Function(T data);
  void execute(dynamic fn) {
    if (fn is Action<String>) {
      // Hanya match jika fn benar-benar menerima String, 
      // fn berjenis Action<int> akan menghasilkan false.
    }
  }
  ```

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Priority Queue Berbasis Min-Heap**:
   Buat class `PriorityQueue<T extends Comparable<T>>`. Terapkan metode `insert(T element)` dan `extractMin() -> T`. Pastikan class tersebut menolak instansiasi class yang tidak mengimplementasikan fungsi perbandingan hierarkis secara native. Uji perilakunya dengan objek kustom.
   
2. **Arsitektur Type-Safe Event Bus dengan Generalized Typedefs**:
   Rancang arsitektur event bus di mana setiap tipe payload di-mapping secara terstruktur. Definisikan `typedef EventHandler<T extends EventPayload> = Future<void> Function(T event);`. Buat mekanisme registrasi handler yang menolak type payload yang tidak sesuai saat waktu kompilasi tanpa memerlukan `dynamic type casting` saat runtime.
