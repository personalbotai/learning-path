## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam model relasional formal yang digagas oleh Edgar F. Codd, `NULL` bukan sebuah nilai (*value*), bukan tipe data, dan bukan alokasi memori kosong (seperti string kosong `''` atau angka `0`). `NULL` adalah sebuah penanda (*marker*) atau status logis yang merepresentasikan **ketiadaan nilai** (*absence of value*), data yang tidak diketahui (*unknown*), atau data yang tidak dapat diterapkan (*inapplicable*).

#### Three-Valued Logic (3VL)
Hampir seluruh bahasa pemrograman umum (seperti Java, C++, atau Go) mengadopsi logika Boolean dua nilai (Two-Valued Logic: `TRUE` dan `FALSE`). Sebaliknya, SQL mengimplementasikan *Three-Valued Logic* (3VL):
1. `TRUE`
2. `FALSE`
3. `UNKNOWN`

Karena `NULL` melambangkan ketidaktahuan (*unknown*), setiap operasi perbandingan skalar yang melibatkan `NULL` secara inheren akan menghasilkan status `UNKNOWN`:

$$\text{NULL} = \text{NULL} \implies \text{UNKNOWN}$$
$$\text{NULL} \neq \text{NULL} \implies \text{UNKNOWN}$$
$$5 > \text{NULL} \implies \text{UNKNOWN}$$

Klausa `WHERE` atau `HAVING` hanya mengizinkan *tuple* (baris data) lolos ke tahap eksekusi berikutnya jika predikat menghasilkan `TRUE`. Hasil `FALSE` maupun `UNKNOWN` akan ditolak (*filtered out*). Akibatnya, operator kesetaraan standar (`=`, `<>`) tidak pernah bisa digunakan untuk mengevaluasi `NULL`. Operator khusus `IS NULL` dan `IS NOT NULL` dirancang khusus dalam standar ANSI SQL untuk memeriksa status eksistensial ini, menghasilkan output pasti `TRUE` atau `FALSE`.

#### Evaluasi Logika 3VL
Berikut adalah tabel kebenaran untuk operasi logika 3VL dalam SQL:

| A | B | A AND B | A OR B | NOT A |
| :--- | :--- | :--- | :--- | :--- |
| `TRUE` | `UNKNOWN` | `UNKNOWN` | `TRUE` | `FALSE` |
| `FALSE` | `UNKNOWN` | `FALSE` | `UNKNOWN` | `TRUE` |
| `UNKNOWN` | `UNKNOWN` | `UNKNOWN` | `UNKNOWN` | `UNKNOWN` |

#### COALESCE: Penanganan Standar ANSI
Fungsi `COALESCE(val1, val2, ..., valN)` adalah fungsi standar ANSI SQL serbaguna yang mengevaluasi argumen secara berurutan dari kiri ke kanan dan mengembalikan nilai *non-NULL* pertama yang ditemui. Jika seluruh argumen bernilai `NULL`, fungsi ini mengembalikan `NULL`.

Secara semantik di level *parser engine*, `COALESCE` direduksi menjadi ekspresi `CASE`:

```sql
-- COALESCE(a, b, c) diinterpretasikan setara dengan:
CASE 
    WHEN a IS NOT NULL THEN a 
    WHEN b IS NOT NULL THEN b 
    ELSE c 
END
```

Engine database melakukan *short-circuit evaluation*: argumen setelah ekspresi non-NULL pertama tidak akan dieksekusi atau dievaluasi ke memory.

### 2. Implementasi & Contoh Kasus Nyata

Contoh skenario: Sistem *e-commerce billing* yang menangani alamat penagihan dinamis, kalkulasi diskon opsional, dan laporan analitik performa penjualan.

```sql
-- 1. Setup Skema Database (Dialek PostgreSQL / Modern ANSI SQL)
CREATE TABLE customers (
    customer_id SERIAL PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50),
    company_name VARCHAR(100),
    mobile_phone VARCHAR(20),
    home_phone VARCHAR(20)
);

CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    customer_id INT REFERENCES customers(customer_id),
    base_amount NUMERIC(10, 2) NOT NULL,
    discount_amount NUMERIC(10, 2), -- Bisa bernilai NULL jika tidak ada promo
    tax_amount NUMERIC(10, 2) DEFAULT 0.00
);

INSERT INTO customers (first_name, last_name, company_name, mobile_phone, home_phone) VALUES
('Budi', 'Santoso', 'PT Maju Mundur', '08123456789', NULL),
('Siti', NULL, NULL, NULL, '0215554321'),
('Agus', 'Pratama', NULL, NULL, NULL);

INSERT INTO orders (customer_id, base_amount, discount_amount, tax_amount) VALUES
(1, 1000000.00, 50000.00, 100000.00),
(2, 500000.00, NULL, 50000.00),     -- Discount NULL
(3, 250000.00, NULL, NULL);         -- Discount dan Tax NULL

-- 2. Implementasi Fallback Chaining dengan COALESCE
-- Menentukan identitas tampilan: Nama Lengkap -> Nama Perusahaan -> Nama Depan Saja
SELECT 
    customer_id,
    COALESCE(
        first_name || ' ' || last_name, 
        company_name, 
        first_name
    ) AS display_name,
    -- Menentukan nomor kontak yang tersedia: Mobile -> Home -> Placeholder
    COALESCE(mobile_phone, home_phone, 'No Contact Available') AS primary_contact
FROM customers;

-- 3. Kalkulasi Matematika Aman dari Kegagalan NULL (NULL Propagation)
-- Tanpa COALESCE, operasi matematika yang menyentuh NULL akan menghasilkan NULL
SELECT 
    order_id,
    base_amount,
    COALESCE(discount_amount, 0.00) AS discount,
    -- Total = base - discount + tax (Aman dari racun NULL)
    (base_amount - COALESCE(discount_amount, 0.00) + COALESCE(tax_amount, 0.00)) AS net_total
FROM orders;

-- 4. Pencarian Dinamis (Search Filter Pattern)
-- Mengambil order dengan batasan diskon opsional via parameter (@param_discount)
-- Jika @param bernilai NULL, kondisi diabaikan tanpa memfilter data
SELECT 
    order_id, 
    base_amount, 
    discount_amount
FROM orders
WHERE discount_amount = COALESCE(NULL, discount_amount) 
   OR (discount_amount IS NULL AND NULL IS NULL);
```

#### Komparasi: COALESCE vs Vendor-Specific Alternatives
- **`COALESCE` (ANSI SQL)**: Kompatibel lintas database (PostgreSQL, MySQL, SQL Server, Oracle, SQLite), mendukung *n* parameter, menggunakan evaluasi *short-circuit*.
- **`IFNULL(expr1, expr2)` (MySQL/SQLite)**: Hanya menerima 2 parameter.
- **`ISNULL(check_expr, repl_value)` (SQL Server)**: Hanya 2 parameter, tipe data return ditentukan oleh parameter pertama (risiko *truncation*).
- **`NVL(expr1, expr2)` (Oracle)**: Hanya 2 parameter, tidak melakukan *short-circuit* (kedua argumen selalu dievaluasi ke memory).

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime Storage: Null Bitmap
Di tingkat *storage engine* (misalnya PostgreSQL *Heap Tuple* atau MySQL *InnoDB Record*), nilai `NULL` tidak disimpan sebagai string karakter atau padding nol sebesar ukuran tipe data kolom. Mengalokasikan nilai fisik untuk data kosong akan menghabiskan ruang disk secara sia-sia.

Sebagai gantinya, storage engine menggunakan struktur data **Null Bitmap** di dalam *Header* setiap baris record (*Tuple Header*):

```text
+--------------------------------------------------------------+
|                    TUPLE HEADER                              |
| ... | Flags | Number of Attributes | NULL BITMAP [ 00000101 ]|
+--------------------------------------------------------------+
| DATA AREA (Hanya menyimpan kolom bernilai nyata)             |
| [Col 2 Data] [Col 4 Data] [Col 5 Data] ...                   |
+--------------------------------------------------------------+
```

- Pada PostgreSQL, header record mengandung bitmask `t_bits[]`. Jika tabel memiliki 8 kolom, satu byte null bitmap dialokasikan.
- Jika bit ke-*n* bernilai `1` (atau `0` tergantung implementasi engine; di Postgres: `0` = NULL, `1` = NOT NULL), *record deserializer* membaca data dari array byte berikutnya.
- Jika bit bernilai NULL, engine tidak membaca byte apapun dari *data area* dan langsung beralih ke kolom berikutnya, mengembalikan referensi internal `SQL_NULL`.

#### B-Tree Indexing dengan Nilai NULL
Perilaku indeks terhadap `NULL` berbeda drastis antar database engine:
- **PostgreSQL**: Mengindeks `NULL` secara default pada B-Tree. `NULL` ditempatkan di posisi paling akhir (`NULLS LAST`) atau paling awal (`NULLS FIRST`). Query `SELECT * FROM tbl WHERE col IS NULL` dapat menggunakan *Index Scan*.
- **Oracle**: B-Tree biasa **tidak** mengindeks baris di mana *seluruh* kolom indeks bernilai `NULL`. Jika Anda mencari `col IS NULL`, Oracle terpaksa melakukan *Full Table Scan* (FTS), kecuali jika Anda menggunakan *Bitmap Index* atau indeks komposit dengan kolom bernilai konstan.
- **MySQL (InnoDB)**: Mengizinkan indeks B-Tree menyimpan `NULL`. Semua nilai `NULL` diperlakukan sama dalam satu partisi simpul paling kiri di B-Tree.

#### Aggregate Engine Optimization
Fungsi agregasi (`SUM`, `AVG`, `MIN`, `MAX`) mengabaikan `NULL` saat evaluasi baris:
$$\text{AVG}(X) = \frac{\sum (X \text{ WHERE } X \text{ IS NOT NULL})}{\text{COUNT}(X \text{ WHERE } X \text{ IS NOT NULL})}$$
Ini berbeda dengan:
$$\text{AVG}(X) \neq \frac{\sum (X \text{ WHERE } X \text{ IS NOT NULL})}{\text{COUNT}(*)}$$
Jika seluruh baris bernilai `NULL`, fungsi `SUM()`, `AVG()`, `MIN()`, dan `MAX()` akan mengembalikan `NULL`, **bukan `0`**. Satu-satunya agregat yang menghitung baris `NULL` adalah `COUNT(*)`, karena `COUNT(*)` mengevaluasi eksistensi tuple baris secara fisik, bukan ekspresi nilainya.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `COALESCE` secara defensif pada agregasi bersarang**:
  ```sql
  -- Menghindari output NULL pada klien API jika data kosong
  SELECT COALESCE(SUM(base_amount), 0.00) FROM orders WHERE customer_id = 99999;
  ```
- **Gunakan `IS DISTINCT FROM` (atau `<=>` di MySQL)**: Jika perlu membandingkan dua nilai yang mungkin mengandung `NULL` tanpa terjebak pada Three-Valued Logic:
  ```sql
  -- Bernilai TRUE jika salah satunya NULL dan yang lain bernilai nyata, 
  -- atau jika keduanya memiliki nilai berbeda. Mengembalikan FALSE jika keduanya NULL.
  WHERE col_a IS DISTINCT FROM col_b
  ```

#### Don'ts
- **JANGAN PERNAH gunakan `= NULL` atau `!= NULL`**: Sintaks ini selalu mengembalikan `UNKNOWN`. Di sebagian besar DBMS, query tidak melempar error sintaksis, namun secara senyap (*silent failure*) mengembalikan 0 baris.
- **HINDARI argumen fungsi non-deterministik/berat di dalam variasi non-short-circuit**: Hindari `NVL` di Oracle jika argumen kedua memanggil fungsi berat (seperti UDF atau subquery kompleks), karena argumen kedua tetap dieksekusi meskipun argumen pertama bernilai valid. Gunakan `COALESCE`.

#### Common Pitfalls: Jebakan Subquery `NOT IN` dengan `NULL`
Ini adalah salah satu bug produksi paling fatal dalam SQL:

```sql
-- Diberikan tabel customer dan order
-- Asumsikan salah satu order memiliki customer_id = NULL
SELECT customer_id FROM customers 
WHERE customer_id NOT IN (SELECT customer_id FROM orders);
```
**Mengapa ini mengembalikan 0 baris (*empty set*)?**
Jika subquery menghasilkan kumpulan nilai `{1, 2, NULL}`, ekspresi diterjemahkan menjadi:
```sql
customer_id != 1 AND customer_id != 2 AND customer_id != NULL
```
Karena `customer_id != NULL` menghasilkan `UNKNOWN`, maka:
$$\text{TRUE} \text{ AND } \text{TRUE} \text{ AND } \text{UNKNOWN} \implies \text{UNKNOWN}$$
Seluruh klausa `WHERE` terevaluasi menjadi `UNKNOWN` untuk setiap baris di tabel `customers`. **Solusi wajib**: Gunakan `NOT EXISTS`:

```sql
SELECT c.customer_id 
FROM customers c
WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id
);
```

### 5. Tantangan Eksplorasi Mandiri

1. **Investigasi Performa `NOT IN` vs `NOT EXISTS`**: 
   Buat tabel dengan 100.000 baris. Masukkan 1 baris yang memiliki nilai `NULL` pada kolom yang diindeks. Buktikan perbedaan *execution plan* antara penggunaan `NOT IN (SELECT ...)` dan `NOT EXISTS (SELECT ...)`. Analisis penggunaan memory engine pada kedua pendekatan tersebut.
2. **Short-Circuit Verification**: 
   Jalankan query berikut di engine database Anda:
   ```sql
   SELECT COALESCE(10, 1 / 0);
   SELECT COALESCE(NULL, 1 / 0);
   ```
   Amati query mana yang berhasil dan query mana yang memicu *Division-by-Zero Exception*. Jelaskan bagaimana *query execution pipeline* menentukan kapan ekspresi dievaluasi.
