## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

SQL (Structured Query Language) adalah bahasa **deklaratif**, bukan imperatif. Artinya, Anda mendeskripsikan *apa* (hasil) yang Anda inginkan, bukan *bagaimana* cara database mengambilnya. Database engine memiliki komponen cerdas bernama **Query Optimizer** yang bertugas menerjemahkan deklarasi Anda menjadi serangkaian operasi fisik (disk I/O, memory scan) yang paling efisien.

Statement `SELECT` adalah fondasi dari Data Query Language (DQL). Secara konsep *Relational Algebra*, `SELECT` dalam SQL sebenarnya melakukan operasi **Projection** (memilih kolom tertentu) dan sering digabungkan dengan operasi **Selection** (memfilter baris via `WHERE`, yang akan dibahas di modul selanjutnya). 

Tujuan utama dari sintaks dasar `SELECT` adalah memproyeksikan data dari *storage engine* ke dalam bentuk *result set* (tabel virtual) di memori yang kemudian dikirimkan ke *client* melalui protokol jaringan.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah contoh penggunaan `SELECT` dari yang paling dasar hingga penggunaan ekspresi skalar dan *aliasing*.

```sql
-- 1. Basic Projection: Mengambil kolom spesifik (Best Practice)
SELECT 
    employee_id, 
    first_name, 
    last_name, 
    department_id 
FROM employees;

-- 2. Scalar Expressions & Math: Melakukan komputasi on-the-fly
SELECT 
    product_name,
    base_price,
    tax_rate,
    (base_price * tax_rate) AS tax_amount,           -- Menggunakan operator aritmatika
    base_price + (base_price * tax_rate) AS final_price -- Kolom virtual (Alias)
FROM products;

-- 3. String Manipulation & Constants
SELECT 
    'INV-' || invoice_id AS formatted_invoice_id,    -- Concatenation (Standar ANSI SQL)
    CURRENT_DATE AS report_generated_at,             -- Fungsi built-in / Konstanta
    status
FROM invoices;
```

**Penjelasan Kode:**
- `SELECT ... FROM ...`: Klausa dasar. `FROM` mendefinisikan sumber data (tabel), `SELECT` mendefinisikan proyeksi kolom.
- `AS` (*Alias*): Memberikan nama sementara pada kolom di *result set*. Sangat penting ketika membuat kolom hasil komputasi agar aplikasi *client* (misal: backend Node.js/Java) dapat memetakan key JSON/Object dengan benar.
- `||`: Operator standar ANSI SQL untuk menyambung string (beberapa RDBMS seperti SQL Server menggunakan `+`, dan MySQL menggunakan fungsi `CONCAT()`).

### 3. Cara Kerja di Balik Layar (Under the Hood)

Ketika Anda mengirimkan statement `SELECT` ke database, berikut adalah siklus eksekusinya:

- **Eksekusi & Runtime (Query Lifecycle)**:
  1. **Parser**: Memeriksa sintaks SQL. Jika ada salah ketik (misal `SELET`), proses berhenti di sini dan melempar *Syntax Error*. Outputnya adalah *Parse Tree*.
  2. **Binder / Analyzer**: Memeriksa semantik. Apakah tabel `employees` ada? Apakah kolom `first_name` ada di tabel tersebut? Apakah user memiliki hak akses? Outputnya adalah *Logical Query Plan*.
  3. **Optimizer**: Menentukan cara paling efisien untuk mengambil data (Cost-Based Optimization).
  4. **Executor**: Menjalankan *Physical Plan* dengan meminta data dari *Storage Engine* (misal: InnoDB di MySQL, atau Postgres Storage).

- **Logical Execution Order (Urutan Eksekusi Logis)**:
  Meskipun kita menulis `SELECT` di awal kalimat, database mengeksekusi klausa `FROM` **terlebih dahulu**. 
  Urutan logisnya: `FROM` -> (proses filter/join jika ada) -> `SELECT`. Ini alasan mengapa Anda tidak bisa menggunakan *Alias* yang didefinisikan di `SELECT` pada klausa `WHERE` (karena `WHERE` dieksekusi sebelum `SELECT`).

- **Alokasi Memori / Resource**:
  Data yang diambil dari disk (berupa *pages* atau *blocks*) akan dimuat ke dalam memori (Buffer Pool / Shared Buffers). `SELECT` yang mengambil data terlalu besar akan menyebabkan *buffer pool churn* (data lama yang berguna terlempar dari memori untuk memberi ruang bagi data baru yang mungkin hanya dibaca sekali).

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - **Selalu sebutkan nama kolom secara eksplisit.** Ini membuat kontrak antara database dan aplikasi menjadi jelas dan mencegah aplikasi *crash* jika skema tabel berubah.
  - **Gunakan konvensi penamaan yang konsisten.** Tulis *keyword* SQL dengan HURUF KAPITAL (`SELECT`, `FROM`) dan *identifier* (nama tabel/kolom) dengan huruf kecil (snake_case).
  - **Gunakan Alias (`AS`)** untuk kolom hasil kalkulasi agar mudah di-parsing oleh ORM atau kode backend.

- **Don'ts**:
  - **JANGAN gunakan `SELECT *` di production.** 
    - *Network I/O*: Mengirim data yang tidak dibutuhkan membuang bandwidth jaringan.
    - *Memory*: Membuang alokasi RAM di server aplikasi.
    - *Performance*: Mencegah database menggunakan *Covering Index* (indeks yang mencakup semua kolom yang di-SELECT, sehingga DB tidak perlu membaca tabel utama sama sekali).
  - **Jangan melakukan komputasi berat di `SELECT` jika bisa dilakukan di aplikasi.** Database lebih sulit di-scale (vertikal) dibandingkan server aplikasi (horizontal).

- **Edge Cases**:
  - **Operasi Matematika dengan `NULL`**: Jika Anda melakukan `base_price + tax` dan nilai `tax` adalah `NULL`, maka hasilnya akan selalu `NULL`. Anda harus menggunakan fungsi seperti `COALESCE(tax, 0)` untuk menangani ini.

### 5. Tantangan Eksplorasi Mandiri

1. Buatlah sebuah tabel dummy dengan 10 kolom. Jalankan `SELECT *` dan `SELECT col1, col2`. Gunakan fitur `EXPLAIN` atau `EXPLAIN ANALYZE` pada RDBMS Anda untuk melihat perbedaan *cost* dan waktu eksekusi (terutama jika tabel memiliki jutaan baris).
2. Cobalah membuat alias di klausa `SELECT` (misal: `SELECT salary * 12 AS annual_salary`), lalu cobalah memfilter data menggunakan alias tersebut di klausa `WHERE` (misal: `WHERE annual_salary > 50000`). Amati error yang terjadi dan pahami mengapa *Logical Execution Order* menyebabkan error tersebut.
3. Lakukan operasi matematika (penjumlahan/perkalian) antara sebuah angka integer dengan nilai `NULL`. Amati hasilnya dan cari tahu cara menggunakan fungsi `COALESCE` di RDBMS pilihan Anda.
