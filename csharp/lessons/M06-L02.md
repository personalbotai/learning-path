## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam ekosistem .NET, manajemen memori untuk objek terkelola (*managed objects*) ditangani secara otomatis oleh **Garbage Collector (GC)**. Namun, GC tidak memiliki pengetahuan tentang cara melepaskan **sumber daya tidak terkelola (*unmanaged resources*)** seperti *file handles*, koneksi database, *network sockets*, atau memori *native* (misal: pointer C/C++).

Jika kita hanya mengandalkan GC untuk membersihkan *unmanaged resources*, kita berhadapan dengan **Non-deterministic cleanup**—kita tidak tahu kapan GC akan berjalan. Hal ini dapat menyebabkan *resource exhaustion* (kehabisan *port* atau *file handle*).

Untuk mengatasi ini, C# menyediakan antarmuka `IDisposable` untuk **Deterministic cleanup** (pembersihan yang dapat diprediksi dan dikontrol secara eksplisit). 
Seiring dengan berkembangnya pemrograman asinkron, C# 8.0 memperkenalkan `IAsyncDisposable` untuk memungkinkan pembersihan sumber daya tanpa memblokir *thread* utama (misalnya, menunggu *buffer* jaringan selesai di-*flush* sebelum menutup koneksi).

Fitur `using` *statement* (dan `using` *declaration* di C# 8.0+) adalah *syntactic sugar* yang menjamin metode `Dispose()` atau `DisposeAsync()` dipanggil secara otomatis, bahkan jika terjadi *exception* di tengah eksekusi.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi komprehensif dari **Standard Dispose Pattern** yang menggabungkan `IDisposable`, `IAsyncDisposable`, dan *Finalizer*.

```csharp
using System;
using System.IO;
using System.Threading.Tasks;

public class ResourceHandler : IDisposable, IAsyncDisposable
{
    // Managed resource (objek yang juga mengimplementasikan IDisposable)
    private Stream? _managedStream;
    
    // Unmanaged resource (misal: pointer native OS)
    private IntPtr _unmanagedBuffer;
    
    // Flag untuk mendeteksi pemanggilan ganda (Double-Dispose)
    private bool _disposedValue;

    public ResourceHandler(string filePath)
    {
        _managedStream = new FileStream(filePath, FileMode.OpenOrCreate);
        _unmanagedBuffer = System.Runtime.InteropServices.Marshal.AllocHGlobal(1024);
    }

    // 1. Implementasi IDisposable
    public void Dispose()
    {
        // Teruskan true karena dipanggil secara eksplisit oleh user code
        Dispose(disposing: true);
        
        // Beritahu GC agar tidak memanggil Finalizer, karena resource sudah dibersihkan
        GC.SuppressFinalize(this);
    }

    // 2. Implementasi IAsyncDisposable (C# 8.0+)
    public async ValueTask DisposeAsync()
    {
        await DisposeAsyncCore();
        
        // Bersihkan unmanaged resource secara sinkron
        Dispose(disposing: false);
        
        GC.SuppressFinalize(this);
    }

    // Core logic untuk pembersihan asinkron
    protected virtual async ValueTask DisposeAsyncCore()
    {
        if (_managedStream is not null)
        {
            await _managedStream.DisposeAsync();
            _managedStream = null;
        }
    }

    // Core logic untuk pembersihan sinkron (Standard Dispose Pattern)
    protected virtual void Dispose(bool disposing)
    {
        if (!_disposedValue)
        {
            if (disposing)
            {
                // TODO: Bersihkan MANAGED state (managed objects).
                _managedStream?.Dispose();
                _managedStream = null;
            }

            // TODO: Bersihkan UNMANAGED resources (unmanaged objects) dan set field besar ke null.
            if (_unmanagedBuffer != IntPtr.Zero)
            {
                System.Runtime.InteropServices.Marshal.FreeHGlobal(_unmanagedBuffer);
                _unmanagedBuffer = IntPtr.Zero;
            }

            _disposedValue = true;
        }
    }

    // 3. Finalizer (Destructor)
    // HANYA implementasikan jika class memiliki unmanaged resource secara langsung!
    ~ResourceHandler()
    {
        // Teruskan false karena dipanggil oleh GC (Finalizer thread).
        // Jangan sentuh managed object di sini karena mungkin sudah di-collect oleh GC!
        Dispose(disposing: false);
    }
}

// --- Cara Penggunaan Modern (C# 8.0+ using declarations) ---
public class Program
{
    public static async Task Main()
    {
        // Sinkron
        using (var handler = new ResourceHandler("test.txt"))
        {
            // Lakukan sesuatu
        } // handler.Dispose() dipanggil otomatis di sini

        // Asinkron (Modern syntax tanpa kurung kurawal)
        await using var asyncHandler = new ResourceHandler("test2.txt");
        // Lakukan sesuatu secara asinkron
        
    } // asyncHandler.DisposeAsync() dipanggil otomatis di akhir scope metode
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: 
  Saat *compiler* melihat blok `using`, ia akan mengubahnya (*lowering*) menjadi blok `try/finally` di level *Intermediate Language* (IL). 
  ```csharp
  // Kode ini:
  using var x = new MyResource();
  
  // Di-compile menjadi:
  MyResource x = new MyResource();
  try { /* ... */ }
  finally { if (x != null) ((IDisposable)x).Dispose(); }
  ```
  Untuk `await using`, *compiler* menghasilkan *State Machine* asinkron yang memanggil `DisposeAsync().AsTask()` di dalam blok `finally`.

- **Alokasi Memori / Resource (Finalization Queue & F-Reachable Queue)**:
  Jika sebuah kelas memiliki *Finalizer* (`~Class()`), saat diinisiasi, GC akan menempatkan referensinya di **Finalization Queue**. Saat objek kehilangan referensi, GC tidak langsung menghapusnya. GC memindahkannya ke **F-Reachable Queue** dan sebuah *thread* khusus (*Finalizer Thread*) akan mengeksekusi *Finalizer*-nya. Ini menunda pengumpulan memori objek tersebut ke siklus GC berikutnya (biasanya naik ke Generation 1 atau 2), yang mana sangat mahal secara performa.
  Pemanggilan `GC.SuppressFinalize(this)` menghapus objek dari *Finalization Queue*, sehingga GC dapat langsung membersihkan memori tanpa menunggu *Finalizer Thread*.

- **Trade-offs**:
  Mengimplementasikan *Finalizer* menambah beban kerja GC. Oleh karena itu, *Finalizer* **hanya** boleh diimplementasikan jika kelas Anda secara langsung memegang *unmanaged resource* (seperti `IntPtr`). Jika kelas Anda hanya membungkus kelas lain yang sudah mengimplementasikan `IDisposable` (seperti `FileStream` atau `SqlConnection`), Anda **tidak perlu** menulis *Finalizer*.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan `using` *declaration* (tanpa kurung kurawal) untuk mengurangi *nesting* kode dan membuatnya lebih bersih.
  - Selalu pastikan metode `Dispose()` aman untuk dipanggil berkali-kali (*idempotent*). Gunakan *flag* `_disposedValue`.
  - Gunakan `IAsyncDisposable` jika proses penutupan resource melibatkan I/O (misal: mengirim pesan *logout* ke server sebelum menutup *socket*).

- **Don'ts**:
  - **JANGAN PERNAH** melempar *exception* dari dalam metode `Dispose()` atau *Finalizer*. Ini dapat menutupi *exception* asli yang terjadi di dalam blok `try`, atau lebih buruk, merusak *Finalizer Thread* yang akan membuat aplikasi *crash* (FailFast).
  - Jangan menyentuh objek *managed* lain di dalam blok `if (disposing == false)` (konteks Finalizer). Objek tersebut mungkin sudah dihancurkan oleh GC.
  - Jangan memanggil `Dispose()` pada objek yang diinjeksi melalui *Dependency Injection* (DI) jika Anda bukan pemilik siklus hidupnya (biarkan DI Container yang melakukan *dispose*).

- **Edge Cases**:
  - **HttpClient**: Meskipun mengimplementasikan `IDisposable`, `HttpClient` **tidak boleh** di-*dispose* setiap kali selesai digunakan (dapat menyebabkan *Socket Exhaustion*). Gunakan `IHttpClientFactory` atau jadikan *Singleton*.
