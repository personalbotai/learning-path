### 1. Konsep & Arsitektur Mendalam

Secara tradisional, arsitektur prosesor bekerja dengan paradigma **SISD (Single Instruction, Single Data)**: satu instruksi CPU dieksekusi untuk memanipulasi satu unit data skalar. Ketika melakukan komputasi array (misalnya menjumlahkan 1.000 angka), loop skalar memproses elemen satu per satu ($N$ siklus untuk $N$ data).

**SIMD (Single Instruction, Multiple Data)** mengubah paradigma ini dengan memproses satu instruksi secara paralel terhadap sekumpulan data (*vector lanes*) dalam satu *clock cycle*.

```
Skalar (SISD):
[ a0 ] + [ b0 ] = [ c0 ]  (Cycle 1)
[ a1 ] + [ b1 ] = [ c1 ]  (Cycle 2)
[ a2 ] + [ b2 ] = [ c2 ]  (Cycle 3)
[ a3 ] + [ b3 ] = [ c3 ]  (Cycle 4)

Vektorisasi (SIMD - 128-bit register untuk 4x 32-bit float):
[ a3 | a2 | a1 | a0 ]
        +                 (Cycle 1 - Operasi Paralel)
[ b3 | b2 | b1 | b0 ]
        =
[ c3 | c2 | c1 | c0 ]
```

#### Evolusi SIMD di .NET & RyuJIT
Dukungan SIMD dalam ekosistem C# terbagi menjadi tiga tingkatan arsitektur:

1. **Auto-vectorization (RyuJIT):** JIT compiler mencoba mengenali loop skalar sederhana dan mengonversinya menjadi instruksi SIMD secara otomatis. Namun, optimasi ini terbatas pada pola memori yang sangat terprediksi.
2. **Platform-Agnostic SIMD (`System.Numerics.Vector<T>`):** Diperkenalkan sejak .NET Core awal. Ukuran vektor bergantung pada lebar register CPU host saat runtime (128-bit pada SSE2/ARM NEON, 256-bit pada AVX2).
3. **Hardware Intrinsics (`System.Runtime.Intrinsics`):** Diperkenalkan pada .NET Core 3.0 dan dimatangkan di .NET 7/8/9. Ini memberikan akses 1:1 ke instruksi CPU spesifik:
   - x86/x64: `Sse`, `Sse2`, `Avx`, `Avx2`, `Avx512F`, `Fma`, dll.
   - ARM: `AdvSimd` (NEON), `ArmBase`.
   - Vektor dengan ukuran tetap: `Vector64<T>`, `Vector128<T>`, `Vector256<T>`, `Vector512<T>`.

#### Register Hardware CPU
CPU modern memiliki register khusus untuk SIMD:
- **XMM (128-bit):** Memuat 4 float (32-bit) atau 2 double (64-bit).
- **YMM (256-bit):** Memuat 8 float atau 4 double.
- **ZMM (512-bit):** Memuat 16 float atau 8 double (AVX-512).

Saat kode C# menggunakan tipe seperti `Vector256<float>`, RyuJIT memetakan tipe struct ini langsung ke register `YMM` fisik prosesor tanpa alokasi memori heap.

### 2. Implementasi & Contoh Kasus Nyata

Studi kasus: **Normalisasi Audio / Gain Multiplier**. Kita akan mengalikan buffer audio (array `float`) dengan sebuah nilai gain. Kode ini mengombinasikan SIMD 256-bit dengan penanganan sisa elemen (*tail processing*).

```csharp
using System;
using System.Runtime.CompilerServices;
using System.Runtime.InteropServices;
using System.Runtime.Intrinsics;
using System.Runtime.Intrinsics.X86;

public static class AudioProcessor
{
    public static void ApplyGain(Span<float> samples, float gain)
    {
        ref float sampleRef = ref MemoryMarshal.GetReference(samples);
        int length = samples.Length;
        int i = 0;

        // Cek dukungan hardware saat runtime: Vector256 (AVX2 pada x64 atau modern ARM)
        if (Vector256.IsHardwareAccelerated && length >= Vector256<float>.Count)
        {
            // Vector256<float>.Count bernilai 8 (256 bit / 32 bit float)
            int vectorStep = Vector256<float>.Count;
            int vectorLimit = length - vectorStep;

            // Broadcast nilai gain skalar ke semua 8 lane pada register YMM
            Vector256<float> vGain = Vector256.Create(gain);

            // Loop utama: Memproses 8 float per iterasi
            for (; i <= vectorLimit; i += vectorStep)
            {
                // Unaligned load dari pointer memori
                Vector256<float> vSample = Vector256.LoadUnsafe(ref sampleRef, (nuint)i);

                // Multiply: RyuJIT meng-emit instruksi VMULPS (x86)
                Vector256<float> vResult = vSample * vGain;

                // Unaligned store kembali ke memori
                vResult.StoreUnsafe(ref sampleRef, (nuint)i);
            }
        }
        // Fallback opsional ke Vector128 (SSE2/NEON) jika Vector256 tidak didukung
        else if (Vector128.IsHardwareAccelerated && length >= Vector128<float>.Count)
        {
            int vectorStep = Vector128<float>.Count; // 4 elemen (128 bit / 32 bit)
            int vectorLimit = length - vectorStep;
            Vector128<float> vGain = Vector128.Create(gain);

            for (; i <= vectorLimit; i += vectorStep)
            {
                Vector128<float> vSample = Vector128.LoadUnsafe(ref sampleRef, (nuint)i);
                Vector128<float> vResult = vSample * vGain;
                vResult.StoreUnsafe(ref sampleRef, (nuint)i);
            }
        }

        // Loop Skalar (Tail Processing): Tangani elemen sisa yang tidak pas dalam batas register
        for (; i < length; i++)
        {
            Unsafe.Add(ref sampleRef, i) *= gain;
        }
    }
}

public class Program
{
    public static void Main()
    {
        float[] audioBuffer = new float[19]; // Bukan kelipatan 8
        for (int idx = 0; idx < audioBuffer.Length; idx++)
        {
            audioBuffer[idx] = 1.0f;
        }

        AudioProcessor.ApplyGain(audioBuffer, 2.5f);

        Console.WriteLine($"Elemen 0  : {audioBuffer[0]}");  // Diproses SIMD
        Console.WriteLine($"Elemen 15 : {audioBuffer[15]}"); // Diproses SIMD
        Console.WriteLine($"Elemen 18 : {audioBuffer[18]}"); // Diproses Tail Processing
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Zero Overhead Abstraction:** Pemanggilan intrinsik seperti `Vector256.LoadUnsafe` atau operator `*` pada `Vector256<T>` bukan pemanggilan fungsi/metode biasa. RyuJIT mengganti metode tersebut secara langsung (*inlining opcode*) dengan instruksi mesin seperti `vmovups` (load/store) dan `vmulps` (perkalian vektor float). Tidak ada *overhead call-stack*.
- **Konstanta Runtime (`IsHardwareAccelerated`):** Properti seperti `Vector256.IsHardwareAccelerated` dievaluasi oleh RyuJIT sebagai *JIT-time constant*. Jika CPU tujuan mendukungnya, cabang fallback `else if` otomatis dieliminasi oleh JIT (*dead-code elimination*), menghasilkan kode assembly yang linier dan efisien.

#### Alokasi Memori / Resource
- **Zero Heap Allocation:** Tipe `Vector64<T>`, `Vector128<T>`, `Vector256<T>`, dan `Vector512<T>` adalah `readonly struct`. Struct ini hidup di dalam register CPU atau di *execution stack frame*. Tidak ada tekanan pada Garbage Collector (GC).
- **Alignment:** Instruksi SIMD x86 memiliki dua varian operasi memori:
  - *Aligned* (`vmovaps`): Memerlukan memori yang dialokasikan pada kelipatan 16, 32, atau 64 byte. Akses ke alamat non-aligned akan memicu CPU exception (`General Protection Fault`).
  - *Unaligned* (`vmovups`): Bekerja pada sembarang alamat memori. .NET APIs (`LoadUnsafe`/`StoreUnsafe`) secara default menggunakan unaligned load/store yang pada CPU arsitektur modern (Haswell ke atas / Zen) memiliki penalti performa yang sangat minim, kecuali jika data melintasi batas *Cache Line* (64-byte boundary).

#### Trade-offs
- **CPU Throttling (AVX-512 & AVX2):** Menjalankan instruksi 512-bit secara intensif pada mikroarsitektur Intel Skylake-X/Cascade Lake dapat menyebabkan CPU menurunkan frekuensi dasarnya (*thermal downclocking*) untuk menjaga konsumsi daya, yang berpotensi memperlambat thread lain yang mengeksekusi kode non-SIMD.
- **Ukuran Data Minimum:** Untuk data yang berukuran sangat kecil (misal: array berukuran < 16 byte), *setup cost* (branching, broadcast register skalar ke vektor) lebih mahal daripada sekadar loop skalar biasa.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Pattern "SIMD Loop + Scalar Tail":** Jangan pernah berasumsi panjang data selalu kelipatan ukuran register. Selalu sertakan loop skalar di akhir untuk memproses elemen sisa.
- **Manfaatkan `Vector<T>` Generic untuk Portabilitas:** Jika tidak membutuhkan instruksi spesifik platform (seperti shuffling atau ternary logic), gunakan `System.Numerics.Vector<T>` agar lebar bit menyesuaikan otomatis dengan kemampuan mesin host (cross-architecture).
- **Gunakan `Span<T>` dan Pointers/Ref Arithmetic:** Hindari array indexing `samples[i]` berulang di dalam inner loop SIMD untuk menghindari *array bounds checking overhead*.

#### Don'ts
- **Menghindari Conditional Branching di Inner Loop:** Jangan meletakkan `if-else` di dalam loop vektorisasi.
  ```csharp
  // SALAH: Menghancurkan performa SIMD
  for (; i <= limit; i += step) {
      if (condition) { /* Do SIMD */ }
  }
  ```
  Gunakan operasi *conditional selection/blending* via SIMD mask: `Vector256.ConditionalSelect()` yang diterjemahkan menjadi instruksi seperti `vblendvps`.
- **Jangan Mengabaikan Cache Locality:** SIMD memproses data sangat cepat sehingga *bottleneck* sering kali berpindah ke kecepatan transfer memori (*Memory Bus Bandwidth*). Pastikan data tersusun secara *Contiguous* di memori (AoS vs SoA — ubah *Array of Structures* menjadi *Structure of Arrays*).

#### Edge Cases
- **Handling NaN & Denormal Numbers:** Perhitungan floating-point SIMD dapat berperilaku beda tipis dengan FPU skalar terkait pembulatan dan penanganan NaN (terutama jika JIT meng-emit instruksi FMA - *Fused Multiply-Add* yang memangkas tahap rounding intermediate).
- **Cross-Page Memory Access:** `LoadUnsafe` yang membaca melewati batas halaman virtual memory (4 KB boundary) dapat memicu hardware *page fault* parsial jika penanganan indeks tail salah.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Penghitungan Karakter (String Search Vectorization):**
   Buat sebuah metode `int CountOccurrences(string source, char target)` yang menggunakan `Vector128<ushort>` atau `Vector256<ushort>` untuk menghitung frekuensi kemunculan sebuah karakter dalam sebuah teks berukuran besar (misalnya 1 MB string). Gunakan instruksi *Equality Comparison* dan konversi bitmask hasil perbandingan.

2. **RGB to Grayscale Converter (SoA Transformasi):**
   Diberikan tiga array paralel bertipe `byte[]` (`R`, `G`, `B`), lakukan konversi ke array `byte[] Gray` menggunakan formula luminansi standar:
   $$Y = 0.299R + 0.587G + 0.114B$$
   Gunakan `Vector256<byte>` yang di-*widen* menjadi `Vector256<float>` untuk komputasi presisi, kemudian lakukan *narrowing* kembali ke `byte` dengan saturasi. Bandingkan performanya terhadap loop skalar menggunakan `BenchmarkDotNet`.
