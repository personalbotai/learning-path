### 1. Konsep & Arsitektur Mendalam

Sebelum .NET 6, arsitektur ASP.NET Core Web API bertumpu pada arsitektur **MVC (Model-View-Controller)** melalui `ControllerBase`. Arsitektur MVC membebankan *overhead* runtime yang signifikan: *assembly scanning* saat startup, pembuatan instansiasi controller via DI per-request, eksekusi pipeline filter MVC yang berlapis (Authorization, Resource, Action, Exception, Result filters), serta metadata descriptor berbasis refleksi yang berat.

**Minimal APIs** diperkenalkan untuk memangkas *pipeline overhead* ini dengan mengekspos langsung route ke delegate tingkat rendah (`RequestDelegate`).

```
Request Pipeline:
[Kestrel HTTP Request]
         │
         ▼
[Routing Middleware (Endpoint Routing)]
         │
         ▼
[Endpoint Filter Pipeline (IEndpointFilter)] ◄─── Short-circuit jika invalid
         │
         ▼
[Model / Parameter Binding Engine]           ◄─── RequestDelegateFactory
         │
         ▼
[Route Handler (Delegate / Lambda)]
         │
         ▼
[IResult Execution (TypedResults)]
         │
         ▼
[HTTP Response]
```

#### Komponen Utama Minimal APIs:
1. **Route Handlers**: Titik akhir eksekusi berupa delegate (`Func<...>`, lambda, atau method group) yang dipetakan langsung ke URI template menggunakan extension methods seperti `MapGet`, `MapPost`, dll.
2. **Model/Parameter Binding**: Mekanisme inferensi tipe di mana runtime secara otomatis memetakan data dari HTTP request (Route, Query, Header, Body, Services) ke parameter handler tanpa anotasi wajib, berdasarkan aturan konvensi tipe dan *nullability*.
3. **Endpoint Filters (`IEndpointFilter`)**: Abstraksi *cross-cutting concerns* (validasi, logging, otentikasi kustom) yang berjalan tepat sebelum dan sesudah Route Handler dieksekusi. Berbeda dengan Middleware global, filter ini memiliki akses langsung ke parameter argumen yang telah di-*bind* dan konteks spesifik endpoint.

### 2. Implementasi & Contoh Kasus Nyata

Skenario: Sistem pemrosesan pesanan (*Order Processing*) dengan validasi payload via Endpoint Filter, *custom binding* untuk token otorisasi internal, dan respons terstruktur menggunakan `TypedResults`.

```csharp
using System.Security.Claims;
using Microsoft.AspNetCore.Http.HttpResults;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

var app = builder.Build();

// Route Group untuk memisahkan domain API dengan prefix dan context yang sama
RouteGroupBuilder ordersApi = app.MapGroup("/api/v1/orders")
                                 .WithTags("Orders");

// Registrasi endpoint dengan filter validasi dan typed results
ordersApi.MapPost("/", CreateOrderHandler)
         .AddEndpointFilter<OrderValidationFilter>()
         .WithName("CreateOrder");

ordersApi.MapGet("/{id:guid}", GetOrderByIdHandler)
         .WithName("GetOrderById");

app.Run();

// ==========================================
// Handlers & Contracts
// ==========================================

public record CreateOrderRequest(string Sku, int Quantity, decimal UnitPrice);
public record OrderResponse(Guid Id, string Sku, int Quantity, decimal TotalAmount, string CreatedBy);

public static class OrderHandlers
{
    public static async Task<Results<Created<OrderResponse>, BadRequest<string>>> CreateOrderHandler(
        CreateOrderRequest request,             // Otomatis di-bind dari Request Body (JSON)
        ClaimsPrincipal user,                   // Otomatis di-bind dari HttpContext.User
        CancellationToken ct)                   // Otomatis di-inject dari HttpContext.RequestAborted
    {
        var username = user.Identity?.Name ?? "Anonymous";
        var total = request.Quantity * request.UnitPrice;
        
        var response = new OrderResponse(
            Guid.NewGuid(), 
            request.Sku, 
            request.Quantity, 
            total, 
            username
        );

        // Simulasi I/O async
        await Task.Delay(10, ct);

        return TypedResults.Created($"/api/v1/orders/{response.Id}", response);
    }

    public static Results<Ok<OrderResponse>, NotFound> GetOrderByIdHandler(
        Guid id,                                // Otomatis di-bind dari Route parameter {id}
        [FromQuery] bool includeDetails = false) // Di-bind eksplisit dari Query String
    {
        // Dummy search
        if (id == Guid.Empty) return TypedResults.NotFound();

        var dummy = new OrderResponse(id, "SKU-PROD-01", 2, 200.00m, "System");
        return TypedResults.Ok(dummy);
    }
}

// ==========================================
// Endpoint Filter Implementation
// ==========================================

public class OrderValidationFilter : IEndpointFilter
{
    public async ValueTask<object?> InvokeAsync(
        EndpointFilterInvocationContext context, 
        EndpointFilterDelegate next)
    {
        // Ambil argumen pertama yang bertipe CreateOrderRequest
        var request = context.Arguments.OfType<CreateOrderRequest>().FirstOrDefault();

        if (request is null)
        {
            return TypedResults.BadRequest("Request payload tidak ditemukan.");
        }

        if (string.IsNullOrWhiteSpace(request.Sku))
        {
            return TypedResults.ValidationProblem(new Dictionary<string, string[]>
            {
                { nameof(request.Sku), ["SKU tidak boleh kosong."] }
            });
        }

        if (request.Quantity <= 0 || request.UnitPrice <= 0)
        {
            return TypedResults.ValidationProblem(new Dictionary<string, string[]>
            {
                { "Pricing", ["Quantity dan UnitPrice harus bernilai positif."] }
            });
        }

        // Lanjutkan eksekusi ke filter berikutnya atau Route Handler
        return await next(context);
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (`RequestDelegateFactory`)
Saat aplikasi melakukan *build* dan memetakan route (`MapGet`, `MapPost`), ASP.NET Core tidak menggunakan refleksi lambat di setiap request HTTP masuk. Sebaliknya, komponen internal **`RequestDelegateFactory` (RDF)** bekerja pada fase startup:
1. **Analisis Metadata**: Menginspeksi signature delegate menggunakan refleksi hanya sekali.
2. **Kompilasi Expression Tree / Code Generation**: RDF membuat *Expression Tree* yang mengompilasi logika binding, eksekusi filter, pemanggilan method handler, dan penanganan response menjadi satu buah delegasi `RequestDelegate` (`Func<HttpContext, Task>`).
3. Pada **.NET 8+ dengan Native AOT**, RDF digantikan oleh *Minimal API Source Generator*. Kode C# untuk binding dan invocation di-generate pada saat waktu kompilasi (*compile-time*), menghilangkan penggunaan `System.Linq.Expressions` dan refleksi runtime sepenuhnya.

#### Aturan Resolusi Model Binding
Minimal API mengurai parameter handler berdasarkan urutan prioritas deterministik:
1. **Special Types**: `HttpContext`, `HttpRequest`, `HttpResponse`, `ClaimsPrincipal`, `CancellationToken` disediakan langsung dari pipeline HTTP.
2. **Custom Binding**: Tipe yang mengimplementasikan method statis `BindAsync` atau `TryParse`.
3. **Route Values**: Nama parameter yang cocok dengan token di route template (e.g., `{id}`).
4. **Query String**: Tipe-tipe primitif (`int`, `string`, `Guid`, enum, dll.) atau array dari tipe primitif.
5. **Services (DI)**: Tipe yang terdaftar pada `IServiceProvider` (atau secara eksplisit dianotasi `[FromServices]`).
6. **Request Body**: Tipe kompleks (class, record, struct) yang tidak cocok dengan kriteria di atas secara default dianggap sebagai JSON payload (`[FromBody]`).

#### Alokasi Memori / Resource
- **Penghapusan Instansiasi Controller**: Menghindari alokasi `ControllerContext`, `ActionDescriptor`, dan objek controller per-request, yang secara masif mengurangi tekanan pada *Garbage Collector (GC Gen 0)*.
- **`ValueTask<object?>` pada Pipeline Filter**: Endpoint filter menggunakan `ValueTask` untuk memungkinkan eksekusi synchronous tanpa alokasi heap jika tidak ada operasi *I/O-bound* asinkron dalam rantai filter.

#### Trade-offs
| Keuntungan | Konsekuensi / Trade-offs |
| :--- | :--- |
| **Throughput & Latency**: Menghilangkan abstraksi MVC yang redundan. | **Organisasi Skala Besar**: Membutuhkan disiplin struktural tinggi (e.g., Route Groups, Extension Methods) agar `Program.cs` tidak menjadi *god-file*. |
| **Startup Time**: Jauh lebih cepat karena minimnya *assembly scanning*. | **Ekosistem Filter Tradisional**: Filter MVC (`IActionFilter`, `IExceptionFilter`) tidak dapat digunakan langsung; harus migrasi ke `IEndpointFilter`. |
| **Mendukung Penuh Native AOT**: Kompatibel dengan kompilasi ahead-of-time. | **Convention Overrides**: Aturan binding implisit terkadang ambigu jika penamaan parameter query dan route bertabrakan. |

### 4. Best Practices & Common Pitfalls

#### Do's:
- **Gunakan `TypedResults` bukan `Results`**: `TypedResults` mempertahankan metadata tipe kembalian yang mempermudah unit testing (tidak perlu unwrapping `IResult` kompleks) dan otomatis mengekspos OpenAPI metadata tanpa anotasi `[ProducesResponseType]` tambahan.
- **Ekstrak Handler ke Static Methods**: Hindari menaruh *inline anonymous lambdas* yang panjang di dalam `Program.cs`. Pindahkan handler ke static class dengan method yang jelas agar mudah di-unit test secara terisolasi.
- **Manfaatkan `RouteGroupBuilder`**: Gunakan `app.MapGroup()` untuk mengelompokkan otorisasi, policy CORS, dan Endpoint Filters per *bounded context*.

#### Don'ts:
- **Jangan Membaca Body Request Lebih dari Sekali**: Body HTTP berupa stream *forward-only*. Jika Anda membaca request stream secara manual di dalam filter kustom, model binding di handler akan gagal karena stream sudah mencapai EOF (End-of-File), kecuali `HttpRequest.EnableBuffering()` diaktifkan secara eksplisit.
- **Jangan Campur Aduk Parameter Tanpa Memperhatikan Nullability**: Dalam C# dengan *Nullable Reference Types (NRT)* aktif, parameter non-nullable seperti `string sku` wajib disediakan oleh client. Jika client mengirim null/kosong, runtime melempar `BadHttpRequestException` (HTTP 400). Gunakan `string? sku` jika parameter bersifat opsional.
- **Hindari Service Locator Pattern di Handler**: Jangan menginjeksi `IServiceProvider` ke parameter handler untuk memanggil `GetRequiredService<T>()`. Biarkan parameter binding menyelesaikannya langsung via DI secara deklaratif.

#### Edge Cases:
- **Ambiguitas Binding Tipe Primitif**: Jika parameter primitif didefinisikan tetapi tidak terdapat pada route template, ASP.NET Core akan mencarinya di Query String. Jika terdapat parameter bernama sama di Query String dan Header, secara default Minimal API **tidak** mengambil dari Header kecuali menggunakan atribut `[FromHeader(Name = "...")]`.
- **Parsing Khusus dengan `IParsable<T>`**: Jika menggunakan model kustom sebagai route/query parameter, implementasikan `IParsable<TSelf>` pada struct/class tersebut. Runtime otomatis mendeteksi method `TryParse` tanpa perlu mendeklarasikan `TypeConverter`.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Custom Model Binding dengan `BindAsync`**:
   Buat sebuah `readonly record struct PageRequest(int Page, int PageSize, string SortBy)`. Implementasikan method statis `BindAsync(HttpContext context, ParameterInfo parameter)` sehingga tipe ini dapat langsung membaca data paginasi dari Query Parameters secara terstandardisasi, lengkap dengan nilai default (misal: `Page=1`, `PageSize=10`, `SortBy="Id"`).
2. **Generic Validation Filter**:
   Buat kelas generic `ValidationFilter<T> : IEndpointFilter` yang mengintegrasikan library seperti `FluentValidation`. Filter ini harus mengekstrak instance `T` dari context arguments, mencari `IValidator<T>` dari DI container, memvalidasinya, dan langsung memutus request (*short-circuit*) dengan mengembalikan `TypedResults.ValidationProblem()` jika terjadi error validasi.
