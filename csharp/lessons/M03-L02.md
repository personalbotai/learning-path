### 1. Konsep & Arsitektur Mendalam

Sebelum rilis .NET 2.0, manipulasi data agregat di runtime CLR mengandalkan non-generic collection seperti `ArrayList` dan `Hashtable` yang bekerja secara eksklusif menggunakan tipe `System.Object`. Pendekatan ini memiliki dua kelemahan fatal:
1. **Kehilangan Type Safety**: Kompiler tidak dapat mendeteksi inkonsistensi tipe data saat *compile time*, sehingga meningkatkan potensi runtime error (`InvalidCastException`).
2. **Overhead Performa (Boxing/Unboxing)**: Setiap kali tipe nilai (*value type* seperti `int`, `struct`) dimasukkan ke dalam `ArrayList`, CLR harus mengalokasikan objek baru di *managed heap* (Boxing). Saat data dibaca, terjadi proses Unboxing kembali ke *stack*. Operasi ini menimbulkan latensi CPU dan membebani Garbage Collector (GC).

Generic Collections (`List<T>`, `Dictionary<TKey, TValue>`, `HashSet<T>`) diperkenalkan untuk menyelesaikan masalah tersebut dengan mekanisme **Generic Specialization** di tingkat Common Language Runtime (CLR):

- **JIT Specialization untuk Value Types**: Ketika `List<int>` atau `List<DateTime>` dikompilasi, JIT (Just-In-Time) compiler menghasilkan kode mesin khusus (*specialized native code*) di mana slot memori dialokasikan langsung sesuai ukuran byte *struct* tersebut tanpa boxing.
- **Code Sharing untuk Reference Types**: Untuk tipe referensi (seperti `List<string>` atau `List<Customer>`), JIT me-reuse implementasi kode mesin yang sama karena representasi memori untuk semua pointer referensi memiliki ukuran yang identik (4 byte di x86, 8 byte di x64).

Secara arsitektural, ketiga koleksi ini mewakili pola struktur data yang berbeda:
- **`List<T>`**: Abstraksi array dinamis (*contiguous memory buffer*). Mendukung random access $O(1)$ melalui pengindeksan, namun memiliki kompleksitas $O(N)$ untuk penyisipan atau penghapusan di tengah buffer.
- **`Dictionary<TKey, TValue>`**: Implementasi *hash table* berbasis *array-based chaining* (bukan *linked-list node* terpisah guna menjaga *cache locality*). Memetakan kunci (*key*) ke nilai (*value*) dengan lookup mendekati $O(1)$.
- **`HashSet<T>`**: Implementasi himpunan matematika yang menggunakan struktur internal serupa dengan `Dictionary`, namun hanya menyimpan elemen unik (*keys only*) tanpa nilai asosiatif, menjamin operasi keanggotaan (*set membership*) $O(1)$.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut menunjukkan implementasi pemrosesan pesanan *e-commerce*, di mana pesanan dikelompokkan, dicek duplikasinya, dan dianalisis status pembayarannya secara efisien.

```csharp
using System;
using System.Collections.Generic;
using System.Runtime.InteropServices;

public enum OrderStatus
{
    Pending,
    Processed,
    Failed
}

public readonly record struct OrderId(Guid Value);

public sealed class Order
{
    public OrderId Id { get; init; }
    public string CustomerId { get; init; } = string.Empty;
    public decimal TotalAmount { get; init; }
    public OrderStatus Status { get; set; }
}

public class OrderManager
{
    // List<T>: Digunakan saat urutan (insertion order) penting
    private readonly List<Order> _auditLog;

    // Dictionary<TKey, TValue>: Digunakan untuk lookup langsung O(1) berdasarkan ID unik
    private readonly Dictionary<OrderId, Order> _activeOrders;

    // HashSet<T>: Digunakan untuk validasi keunikan O(1) tanpa payload tambahan
    private readonly HashSet<string> _blacklistedCustomers;

    public OrderManager(int initialCapacity = 1000)
    {
        // Alokasi kapasitas awal untuk mencegah resizing berkali-kali
        _auditLog = new List<Order>(initialCapacity);
        _activeOrders = new Dictionary<OrderId, Order>(initialCapacity);
        
        // HashSet dengan StringComparer untuk keamanan parsing case-insensitive
        _blacklistedCustomers = new HashSet<string>(StringComparer.OrdinalIgnoreCase)
        {
            "FRAUD_001",
            "FRAUD_002"
        };
    }

    public bool RegisterOrder(Order order)
    {
        // 1. Validasi HashSet: O(1) amortized
        if (_blacklistedCustomers.Contains(order.CustomerId))
        {
            return false;
        }

        // 2. Dictionary TryAdd: Mencegah operasi double-lookup (ContainsKey lalu Add)
        if (!_activeOrders.TryAdd(order.Id, order))
        {
            return false; // Order ID sudah terdaftar
        }

        // 3. List Add: Amortized O(1) ke contiguous buffer
        _auditLog.Add(order);
        return true;
    }

    public bool TryUpdateStatus(OrderId id, OrderStatus newStatus)
    {
        // Menghindari lookup ganda: Mengambil referensi langsung jika ditemukan
        ref Order? order = ref CollectionsMarshal.GetValueRefOrNullRef(_activeOrders, id);

        if (Unsafe.IsNullRef(ref order) || order is null)
        {
            return false;
        }

        order.Status = newStatus;
        return true;
    }

    public HashSet<string> ExtractUniqueCustomers()
    {
        // Inisialisasi HashSet langsung dari koleksi lain
        var uniqueCustomers = new HashSet<string>(StringComparer.Ordinal);
        
        for (int i = 0; i < _auditLog.Count; i++)
        {
            uniqueCustomers.Add(_auditLog[i].CustomerId);
        }

        return uniqueCustomers;
    }
}

public class Program
{
    public static void Main()
    {
        var manager = new OrderManager(capacity: 100);

        var order1 = new Order 
        { 
            Id = new OrderId(Guid.NewGuid()), 
            CustomerId = "CUST_99", 
            TotalAmount = 150000m, 
            Status = OrderStatus.Pending 
        };

        bool registered = manager.RegisterOrder(order1);
        Console.WriteLine($"Order 1 Registered: {registered}");

        bool updated = manager.TryUpdateStatus(order1.Id, OrderStatus.Processed);
        Console.WriteLine($"Order 1 Status Updated: {updated}");

        var blockedOrder = new Order 
        { 
            Id = new OrderId(Guid.NewGuid()), 
            CustomerId = "fraud_001", // Match case-insensitive
            TotalAmount = 500000m, 
            Status = OrderStatus.Pending 
        };

        bool blockedRegistered = manager.RegisterOrder(blockedOrder);
        Console.WriteLine($"Blocked Order Registered: {blockedRegistered}"); // Output: False
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **List\<T>**: Bekerja di atas satu array internal kontinu (`T[] _items`). Properti `Count` merepresentasikan jumlah elemen yang terisi, sedangkan `Capacity` adalah panjang array internal (`_items.Length`). Ketika `Add()` dipanggil melebihi `Capacity`, runtime membuat array baru berukuran $2 \times \text{Capacity}$ dan memanggil instruksi `Buffer.BlockCopy` atau `Array.Copy` untuk menyalin elemen lama ke buffer baru.
- **Dictionary\<TKey, TValue> & HashSet\<T>**: 
  Keduanya tidak menggunakan *linked node pointer* (pola hash table klasik) untuk menangani *collision*, melainkan menggunakan **Closed Addressing via Array Indirection**:
  1. `int[] _buckets`: Array integer berukuran bilangan prima yang menyimpan indeks (berbasis 1) ke array `_entries`.
  2. `Entry[] _entries`: Array kontinu dari struct internal yang menyimpan metadata:
     - `uint hashCode`: Hash code dari Key (disimpan untuk mempercepat perbandingan).
     - `int next`: Indeks ke entry berikutnya jika terjadi tabrakan hash (collision chain).
     - `TKey key`: Kunci asli.
     - `TValue value`: Nilai payload (pada `HashSet<T>`, field ini tidak ada).

```
Hash Resolution Flow:
Key -> HashCode -> BucketIndex = (HashCode % BucketSize)
BucketIndex -> _buckets[BucketIndex] -> EntryIndex
EntryIndex  -> _entries[EntryIndex] -> Cocokkan Key & HashCode
```

- **Mekanisme Versioning**: Setiap struktur data generic memiliki field private `int _version`. Setiap mutasi (`Add`, `Remove`, `Clear`) akan mengeksekusi `_version++`. Saat enumerator (`foreach`) dieksekusi, nilai `_version` lokal akan dibandingkan dengan `_version` pada koleksi. Jika tidak sama, runtime langsung melemparkan `InvalidOperationException` untuk mencegah inkonsistensi konkurensi (*fail-fast design*).

#### Alokasi Memori / Resource
- Jika koleksi tumbuh secara eksponensial di heap tanpa estimasi kapasitas, array internal lama akan ditinggalkan menjadi *garbage*.
- Jika array internal `_items` atau `_entries` melampaui ukuran **85.000 byte**, alokasi akan langsung dialihkan ke **Large Object Heap (LOH)**. LOH tidak dikompaksi secara default pada GC Gen 2, sehingga memicu fragmentasi memori (*memory fragmentation*).

#### Trade-offs
| Tipe Koleksi | Kecepatan Read | Kecepatan Insert | Memory Overhead | Karakteristik Utama |
|---|---|---|---|---|
| `List<T>` | $O(1)$ by Index | $O(1)$ Amortized | Sangat Rendah | Data padat berurutan, ramah CPU cache (*cache locality*). |
| `Dictionary<TKey, TVal>` | $O(1)$ Amortized | $O(1)$ Amortized | Tinggi (~3-4x dari raw data) | Array bucket terpisah + struct entries; overhead alokasi prima. |
| `HashSet<T>` | $O(1)$ Amortized | $O(1)$ Amortized | Sedang (~2-3x dari raw data) | Cepat untuk operasi himpunan (Union, Intersect, Difference). |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Alokasikan Kapasitas di Awal (*Presizing*)**: Selalu tentukan kapasitas awal jika jumlah elemen dapat diperkirakan, misal `new List<T>(expectedSize)`. Ini mengeliminasi overhead resize $O(N)$ dan alokasi memory churn berulang pada GC.
- **Implementasikan `IEquatable<T>` untuk Custom Keys/Sets**: Saat menggunakan `struct` atau `class` kustom sebagai `TKey` di `Dictionary` atau elemen di `HashSet`, wajib implementasikan `IEquatable<T>` serta override `GetHashCode()` dan `Equals(object?)`. Jika tidak, CLR akan fallback ke `ValueType.Equals` yang menggunakan refleksi lambat untuk struct.
- **Gunakan Lookup Sekali Jalan**: Hindari memanggil `ContainsKey()` lalu memanggil *indexer* `[]`.
  ```csharp
  // Buruk: Melakukan hash traversal 2 kali
  if (dict.ContainsKey(id)) { var val = dict[id]; }

  // Baik: Hash traversal hanya 1 kali
  if (dict.TryGetValue(id, out var val)) { /* Operasi */ }
  ```

#### Don'ts
- **Memodifikasi Mutasi State pada Key**: Jangan pernah memodifikasi nilai properti objek yang mempengaruhi hasil `GetHashCode()` setelah objek tersebut dimasukkan ke dalam `Dictionary` atau `HashSet`. Hal ini merusak penempatan bucket dan menyebabkan objek "hilang" (tidak dapat ditemukan lagi meskipun ada di dalam memori).
- **Eksekusi Linq `.ToList()` Prematur**: Menjalankan `.ToList()` di dalam perulangan atau pipeline Linq yang belum final menciptakan alokasi array perantara yang tidak diperlukan.
- **Mengabaikan StringComparer**: Jangan menggunakan tipe `string` sebagai Key tanpa mendefinisikan perbandingan spesifik (seperti `StringComparer.Ordinal` atau `StringComparer.OrdinalIgnoreCase`). Default comparer terikat pada kultur lingkungan (*culture-sensitive*), yang lebih lambat dan rawan bug lokalisasi.

#### Edge Cases
- **Hash Collisions Degradation**: Jika algoritma `GetHashCode()` buruk dan menghasilkan nilai hash yang sama untuk semua item yang berbeda, struktur internal `Dictionary`/`HashSet` akan mengalami degradasi performa dari $O(1)$ menjadi $O(N)$ karena harus menelusuri collision chain secara sequential menggunakan `Equals()`.
- **Modifikasi Saat Iterasi**: Memodifikasi isi koleksi di dalam iterasi `foreach` akan melempar `InvalidOperationException` karena pelanggaran versioning token CLR.

### 5. Tantangan Eksplorasi Mandiri

1. **Analisis Memory Footprint dan LOH**:
   Buat proyek Console sederhana dan alokasikan `List<byte>` dengan 80.000 elemen, lalu tambahkan hingga 90.000 elemen. Gunakan `GC.GetGeneration` atau dotMemory/Visual Studio Diagnostic Tools untuk memverifikasi pada titik penambahan mana array internal `_items` dipindahkan dari Gen 0 Heap ke Large Object Heap (LOH).

2. **Benchmark Hash Collision Degradation**:
   Buat sebuah `struct BadKey` di mana method `GetHashCode()` selalu me-return nilai konstanta `return 42;`. Lakukan pengujian *benchmark* menggunakan `BenchmarkDotNet` untuk membandingkan kecepatan `Dictionary.TryGetValue` antara 10.000 elemen `BadKey` melawan 10.000 elemen yang menggunakan hash bawaan `int`. Analisis grafik latensi CPU yang dihasilkan.
