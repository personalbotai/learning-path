### 1. Konsep & Arsitektur Mendalam

Dalam pemrosesan data deklaratif berbasis LINQ, manipulasi dataset kompleks berpusat pada tiga operasi dasar: **Grouping** (pengelompokan), **Joining** (penggabungan relasional), dan **Aggregation** (reduksi nilai). 

```
[ Data Source A ] ──┐
                    ├─► [ Join / GroupBy ] ──► [ Lookup / Bucket ] ──► [ Aggregate ] ──► Scalar / Projection
[ Data Source B ] ──┘
```

#### Grouping (`GroupBy`)
Operator `GroupBy` mempartisi sequence sumber ke dalam sub-koleksi berdasarkan proyeksi kunci (`keySelector`). Hasil kembaliannya berupa `IEnumerable<IGrouping<TKey, TElement>>`. Struktur `IGrouping<TKey, TElement>` unik karena bertindak ganda:
1. Memiliki properti `.Key` yang merepresentasikan identitas partisi.
2. Mengimplementasikan `IEnumerable<TElement>`, memungkinkan iterasi atas seluruh elemen dalam partisi tersebut.

Berbeda dari klausa `GROUP BY` pada SQL yang mewajibkan agregasi langsung, `GroupBy` pada C# LINQ mempertahankan elemen mentah di dalam struktur bucket memori hingga dievaluasi lebih lanjut.

#### Joining (`Join` & `GroupJoin`)
LINQ menyediakan dua operator utama untuk menggabungkan dua dataset heterogen:
- **`Join` (Inner Equi-Join):** Menggabungkan elemen dari dua koleksi (`outer` dan `inner`) berdasarkan kesamaan kunci (`outerKeySelector` dan `innerKeySelector`). Menghasilkan pasangan elemen datar (*flat result*).
- **`GroupJoin` (Hierarchical Join):** Memetakan setiap elemen dari koleksi `outer` ke sekumpulan elemen yang cocok dari koleksi `inner`. Ini merupakan fondasi teknis untuk mengimplementasikan *Left Outer Join* di LINQ (dikombinasikan dengan `.DefaultIfEmpty()`).

#### Aggregation (`Aggregate`)
`Aggregate` adalah implementasi dari fungsi lipat *fold/reduce* dalam paradigma fungsional. Operator ini mengiterasi elemen koleksi dan mengakumulasi hasilnya ke dalam satu nilai akhir (skalar atau objek komposit) berdasarkan fungsi transformator akumulator (`Func<TAccumulate, TSource, TAccumulate>`). Operator LINQ lain seperti `Sum()`, `Average()`, `Count()`, dan `Min()/Max()` hanyalah spesialisasi tingkat tinggi di atas primitif `Aggregate`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah skenario analitik sistem inventaris e-commerce: menggabungkan pesanan dengan detail produk, mengelompokkannya per kategori, dan menghitung ringkasan keuangan via `Aggregate`.

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

public record Product(int Id, string Name, string Category, decimal Price);
public record OrderItem(int OrderId, int ProductId, int Quantity);

public record CategorySalesSummary(
    string Category, 
    int TotalUnitsSold, 
    decimal TotalRevenue, 
    decimal AverageItemPrice
);

public class Program
{
    public static void Main()
    {
        var products = new List<Product>
        {
            new(1, "Laptop Pro", "Electronics", 1500m),
            new(2, "Mechanical Keyboard", "Electronics", 120m),
            new(3, "Espresso Roast Beans", "Coffee", 20m),
            new(4, "Ceramic Mug", "Coffee", 15m),
            new(5, "Desk Chair", "Furniture", 250m) // Tidak terjual
        };

        var orderItems = new List<OrderItem>
        {
            new(101, 1, 2),  // 2 Laptop Pro
            new(101, 2, 5),  // 5 Keyboard
            new(102, 3, 10), // 10 Coffee Beans
            new(103, 4, 3),  // 3 Mug
            new(104, 1, 1)   // 1 Laptop Pro
        };

        // 1. INNER JOIN: Hubungkan Item Pesanan dengan Detail Produk
        var orderDetails = orderItems.Join(
            products,
            item => item.ProductId,     // outerKeySelector
            prod => prod.Id,            // innerKeySelector
            (item, prod) => new         // resultSelector
            {
                prod.Category,
                prod.Name,
                item.Quantity,
                LineTotal = item.Quantity * prod.Price,
                prod.Price
            }
        );

        // 2. GROUP BY: Kelompokkan item transaksi berdasarkan Kategori Produk
        var groupedByCategory = orderDetails.GroupBy(
            detail => detail.Category,
            detail => detail
        );

        // 3. AGGREGATE: Reduksi metrik agregat per kelompok secara custom
        var categorySummaries = groupedByCategory.Select(group =>
        {
            var seed = (TotalQty: 0, TotalRev: 0m, WeightedSum: 0m);

            var (totalQty, totalRev, _) = group.Aggregate(
                seed,
                (acc, current) => (
                    acc.TotalQty + current.Quantity,
                    acc.TotalRev + current.LineTotal,
                    acc.WeightedSum + (current.Price * current.Quantity)
                )
            );

            return new CategorySalesSummary(
                Category: group.Key,
                TotalUnitsSold: totalQty,
                TotalRevenue: totalRev,
                AverageItemPrice: totalQty > 0 ? totalRev / totalQty : 0m
            );
        }).ToList();

        // 4. GROUP JOIN (Left Outer Join): Produk dengan riwayat penjualannya
        var productSalesReport = products.GroupJoin(
            orderItems,
            prod => prod.Id,
            item => item.ProductId,
            (prod, items) => new
            {
                prod.Name,
                prod.Category,
                TotalSold = items.Sum(i => i.Quantity) // Mengembalikan 0 jika items kosong
            }
        );

        // Output Result
        Console.WriteLine("=== REKAPITULASI PENJUALAN PER KATEGORI ===");
        foreach (var summary in categorySummaries)
        {
            Console.WriteLine(
                $"[{summary.Category}] Qty: {summary.TotalUnitsSold} | " +
                $"Revenue: ${summary.TotalRevenue:N2} | " +
                $"Avg Price: ${summary.AverageItemPrice:N2}"
            );
        }

        Console.WriteLine("\n=== STATUS INVENTARIS PRODUK (GROUP JOIN) ===");
        foreach (var report in productSalesReport)
        {
            Console.WriteLine($"{report.Name,-22} | Terjual: {report.TotalSold}");
        }
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Hash Join vs Nested Loop
Operator `Enumerable.Join` mengimplementasikan algoritma **Hash Join**, bukan *Nested Loop Join* ($O(N \times M)$).
1. Runtime mengevaluasi koleksi `inner` terlebih dahulu secara eager (*pipeline breaker* untuk sisi inner).
2. Koleksi `inner` dimasukkan ke dalam hash table internal LINQ: `Lookup<TKey, TElement>`. Ini menghabiskan waktu $O(M)$.
3. Runtime kemudian melakukan *streaming* atas koleksi `outer` ($O(N)$), mengekstrak kuncinya, mencari kecocokan pada hash table dalam kompleksitas rata-rata $O(1)$.
4. Kompleksitas komputasi totalnya adalah **$O(N + M)$**.

#### Buffer State & Memori pada `GroupBy`
Berbeda dengan `Select` atau `Where` yang murni *streaming* (elemen diproses satu per satu secara *lazy* menggunakan `yield return`), `GroupBy` bersifat **deferred-execution tapi non-streaming (buffered)**.
- Ketika enumerasi pertama dipicu (`GetEnumerator().MoveNext()`), `GroupBy` membaca **seluruh** sequence sumber ke dalam memori untuk membangun linked list bucket internal per hash code kunci (`Lookup<TKey, TElement>`).
- Jika sumber data berisi 10.000.000 baris, eksekusi `GroupBy` akan mengalokasikan array bucket internal dan node wrapper untuk menampung seluruh referensi sebelum elemen pertama dari `IGrouping` dikeluarkan.

#### Struktur `Lookup<TKey, TElement>`
Di bawah naungan .NET Runtime, `Lookup<TKey, TElement>` dikonstruksi menyerupai `Dictionary<TKey, List<TElement>>`, namun dioptimalkan:
```
Lookup<TKey, TElement>
 ├── Grouping[] groupings (Hash table array)
 │     ├── [0] -> HashBucketNode { Key: "Electronics", Elements: [...], Next: nodeRef }
 │     └── [1] -> HashBucketNode { Key: "Coffee",      Elements: [...], Next: null }
 └── Grouping lastGrouping (Menjaga Insertion Order dari Key)
```
- Setiap `Grouping` mengimplementasikan `IList<TElement>`.
- `Lookup` mengunci integritas data (*immutable* publik) dan mempertahankan urutan kemunculan kunci asli (*insertion-order preserved*).

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan `EqualityComparer<TKey>.Default` atau Custom Comparer:** Jika tipe kunci kustom Anda adalah `class`, pastikan meng-override `Equals` dan `GetHashCode` atau sediakan `IEqualityComparer<TKey>`. Kegagalan dalam hal ini menyebabkan objek dengan nilai field identik masuk ke bucket terpisah karena fallback ke *reference equality*.
- **Manfaatkan Aggregation Spesifik jika ada:** Utamakan `Sum()`, `Count()`, atau `Any()` ketimbang menulis `Aggregate()` manual demi optimalisasi compiler dan keterbacaan kode (kecuali melakukan akumulasi multi-properti secara simultan).
- **Proyeksikan Elemen Lebih Dini:** Gunakan parameter `elementSelector` pada `GroupBy(keySelector, elementSelector)` untuk memotong beban memori objek besar, sehingga hanya field yang diperlukan yang dialokasikan ke dalam bucket memori internal.

#### Don'ts
- **Hindari *Double Enumeration* pada `IGrouping`:** Hindari membaca `group.Count()` kemudian memanggil `group.ToList()` di dalam query yang sama. Iterator partisi internal akan diulang ganda.
- **Jangan Gunakan `GroupBy` hanya untuk Agregasi Tunggal (Sebelum .NET 9):** Jika tujuannya hanya menghitung jumlah frekuensi kemunculan, pembuatan `GroupBy` membuang alokasi heap untuk `IGrouping`. Pada .NET 9+, gunakan API baru berkinerja tinggi seperti `CountBy()` dan `AggregateBy()` yang bekerja *streaming-accumulator* tanpa overhead alokasi bucket koleksi penuh.
- **Hindari Query N+1 Menggunakan LINQ-to-Objects In-Memory:** Memanggil operator `.Where()` di dalam proyeksi loop hasil pengelompokan akan merusak performa dari $O(N)$ menjadi $O(N^2)$.

#### Edge Cases
- **Handling `null` Keys:** Pada `GroupBy` LINQ-to-Objects, nilai kunci bernilai `null` adalah **valid**. Seluruh objek dengan kunci `null` akan dikumpulkan di bawah satu `IGrouping` dengan `.Key == null`. Hal ini berbeda dengan basis data SQL tertentu yang memisah atau mengabaikan null matching.
- **Side Effects dalam `Aggregate`:** Parameter akumulator pada `Aggregate` harus berstatus *pure function*. Jangan memodifikasi state eksternal atau memutasi referensi objek di luar konteks akumulator karena akan memicu *race condition* jika query dialihkan ke PLINQ (`AsParallel()`).

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Full Outer Join Manual:** LINQ tidak menyediakan operator bawaan `FullOuterJoin`. Rancang sebuah *extension method* generik:
   `public static IEnumerable<TResult> FullOuterJoin<TOuter, TInner, TKey, TResult>(...)`
   dengan menggabungkan primitif `GroupJoin`, `SelectMany`, dan `DefaultIfEmpty`. Pastikan kompleksitas memori tetap $O(N + M)$ dan tidak melakukan iterasi kuadratik ($O(N \times M)$).
2. **Memory Profiling `GroupBy` vs Manual Reduction:** Buat benchmark menggunakan `BenchmarkDotNet` untuk membandingkan alokasi memori (GC Gen 0/1/2) antara:
   - `collection.GroupBy(x => x.Key).Select(g => new { Key = g.Key, Sum = g.Sum(x => x.Val) })`
   - Melakukan loop imperatif menggunakan `Dictionary<TKey, int>` akumulator langsung.
   Analisis mengapa alokasi memori berbeda secara signifikan berdasarkan struktur `Lookup` yang dibahas di bagian Under the Hood.
