### 1. Konsep & Arsitektur Mendalam

Secara *default*, C# adalah bahasa yang bertipe aman (*type-safe*) dan berjalan di atas lingkungan terkelola (*managed runtime* / CLR). Runtime bertanggung jawab penuh atas masa hidup objek melalui *Garbage Collector* (GC), mencegah *buffer overflow*, dan mengisolasi eksekusi dari manipulasi memori langsung. Namun, untuk skenario komputasi performa ekstrem (*high-performance computing*), manipulasi grafis tingkat rendah, pengolahan sinyal, atau integrasi dengan library sistem operasi C/C++, batasan ini dapat diabaikan menggunakan dua mekanisme utama: **Unsafe Code** dan **Platform Invoke (P/Invoke)**.

#### Unsafe Code & Pointer Semantics
Fitur `unsafe` diaktifkan melalui compiler switch (`<AllowUnsafeBlocks>true</AllowUnsafeBlocks>` di file `.csproj`). Di dalam blok `unsafe`, C# mengizinkan tipe pointer tradisional ala C (`T*`), operator alamat (`&`), dan dereferensi pointer (`*` atau `->`).

Tantangan mendasar dari pointer di lingkungan managed adalah keberadaan GC bertipe *compacting*:
- GC secara periodik memindahkan objek di heap untuk mengurangi fragmentasi memori.
- Jika sebuah pointer mentah C# merujuk ke memori heap managed, relokasi oleh GC akan membuat pointer tersebut menjadi **dangling pointer** (merujuk ke lokasi memori yang salah/rusak).
- Untuk mengatasi ini, C# menyediakan *keyword* `fixed`. Instruksi ini menyematkan (*pins*) objek di heap managed, menginstruksikan GC untuk tidak memindahkan objek tersebut selama blok `fixed` berlangsung. Alternatifnya, memori dialokasikan langsung di native heap (`NativeMemory.Alloc`) atau stack (`stackalloc`) yang tidak terikat oleh siklus kompresi GC.

#### Native Interoperability (P/Invoke & LibraryImport)
P/Invoke adalah jembatan runtime antara kode managed CLR dan fungsi yang diekspor oleh *dynamic library* native (seperti `.dll` di Windows, `.so` di Linux, atau `.dylib` di macOS).

Secara historis, P/Invoke menggunakan atribut `[DllImport]`, di mana CLR secara dinamis menghasilkan *stub* IL (Intermediate Language) pada saat runtime untuk menangani transisi konteks eksekusi, penyesuaian konvensi pemanggilan (*calling convention* seperti `cdecl`, `stdcall`), dan marshalling data. 

Mulai C# 11 / .NET 7, arsitektur ini dimodernisasi menggunakan **Source Generated P/Invoke** via atribut `[LibraryImport]`. Compiler Roslyn menghasilkan kode C# marshalling secara eksplisit pada saat *build-time*, mengeliminasi overhead runtime stub generation, ramah terhadap *Ahead-of-Time* (AOT) compilation, serta memungkinkan developer mengaudit langsung kode marshalling yang digenerate.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengombinasikan manipulasi raw memory menggunakan `stackalloc` & pointer, serta integrasi modern native interop menggunakan `[LibraryImport]` untuk memanggil fungsi C runtime standar (`qsort` & `puts`).

```csharp
using System;
using System.Runtime.CompilerServices;
using System.Runtime.InteropServices;

namespace NativeInteropUnsafeDemo;

// Definisi delegasi callback native untuk fungsi qsort C
// Menggunakan UnmanagedCallersOnly untuk interop C-style callback berperforma tinggi
public static class Sorters
{
    [UnmanagedCallersOnly(CallConvs = new[] { typeof(CallConvCdecl) })]
    public static unsafe int CompareIntegers(void* a, void* b)
    {
        int valA = *(int*)a;
        int valB = *(int*)b;

        return valA.CompareTo(valB);
    }
}

public static unsafe partial class NativeMethods
{
    private const string CRuntime = "msvcrt.dll"; // Gunakan "libc.so.6" pada Linux

    // 1. Modern Source-Generated P/Invoke untuk fungsi pustaka C (qsort)
    [LibraryImport(CRuntime, EntryPoint = "qsort")]
    [UnmanagedCallConv(CallConvs = new[] { typeof(CallConvCdecl) })]
    public static partial void QuickSort(
        void* @base,
        nuint num,
        nuint size,
        delegate* unmanaged[Cdecl]<void*, void*, int> compare
    );

    // 2. Marshalling String menggunakan LibraryImport
    [LibraryImport(CRuntime, EntryPoint = "puts", StringMarshalling = StringMarshalling.Utf8)]
    public static partial int Puts(string str);
}

public class Program
{
    public static unsafe void Main()
    {
        // Kasus 1: P/Invoke dengan Utf8 Marshalling
        NativeMethods.Puts("=== Invoking Native libc/msvcrt via LibraryImport ===");

        // Kasus 2: Manipulasi Memori Stack dan Native Function Pointer
        const int elementCount = 8;
        // Alokasi memori di stack mesin (bukan GC Heap) - sangat cepat, zero-alloc GC
        int* data = stackalloc int[elementCount] { 42, 13, 99, 7, 25, 1, 88, 54 };

        Console.Write("Data Asli: ");
        PrintBuffer(data, elementCount);

        // Eksekusi C qsort melintasi batas managed/unmanaged
        NativeMethods.QuickSort(
            @base: data,
            num: (nuint)elementCount,
            size: (nuint)sizeof(int),
            compare: &Sorters.CompareIntegers
        );

        Console.Write("Data Terurut (qsort): ");
        PrintBuffer(data, elementCount);

        // Kasus 3: Pointer Arithmetic & Object Pinning (fixed keyword)
        Console.WriteLine("\n=== Pixel Manipulation via Fixed Buffer ===");
        byte[] managedBitmap = new byte[] { 255, 0, 128, 64, 32, 16 };

        // Pin array managedBitmap agar tidak digeser oleh GC selama operasi pointer
        fixed (byte* pBitmap = managedBitmap)
        {
            InvertColors(pBitmap, managedBitmap.Length);
        }

        Console.WriteLine($"Array Managed setelah Inversi: {string.Join(", ", managedBitmap)}");
    }

    // Invert warna dengan mengoperasikan 1 byte per siklus via pointer arithmetic
    private static unsafe void InvertColors(byte* ptr, int length)
    {
        byte* current = ptr;
        byte* end = ptr + length;

        while (current < end)
        {
            *current = (byte)(255 - *current); // Dereferensi dan modifikasi langsung
            current++; // Pointer arithmetic: maju sebesar sizeof(byte)
        }
    }

    private static unsafe void PrintBuffer(int* ptr, int count)
    {
        for (int i = 0; i < count; i++)
        {
            // Akses pointer menggunakan indexer syntax: ptr[i] ekivalen dengan *(ptr + i)
            Console.Write($"{ptr[i]} ");
        }
        Console.WriteLine();
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
1. **Transition Thunk (P/Invoke Boundaries)**: Ketika memanggil fungsi native, thread eksekusi berpindah dari mode *Managed Execution* ke *Preemptive/Unmanaged Mode*. Runtime harus menyimpan status *CPU registers*, frame pointer, dan mengelola struktur exception handling (SEH pada Windows).
2. **LibraryImport Source Generators**: Saat memakai `[LibraryImport]`, compiler Roslyn menganalisis tanda tangan metode saat kompilasi dan memproduksi kelas parsial yang berisi kode IL/C# interop murni. Tidak ada runtime code-emission (`Reflection.Emit`), sehingga waktu cold-start tereduksi signifikan dan kompatibel dengan *NativeAOT*.
3. **Function Pointers (`delegate*`)**: Sejak C# 9, keyword `delegate*` menghasilkan instruksi mesin `calli` langsung pada IL, melewati alokasi delegate heap managed `System.Delegate`.

#### Alokasi Memori & Marshalling
- **Blittable Types**: Tipe data yang memiliki representasi biner identik antara managed dan unmanaged memory (contoh: `byte`, `int`, `double`, `IntPtr`, serta struct yang hanya berisi tipe blittable dengan `LayoutKind.Sequential`). Tipe ini **tidak memerlukan konversi data** (*zero-copy marshalling*), hanya pointer yang diteruskan.
- **Non-Blittable Types**: Tipe data yang layout memorinya berbeda (contoh: `string`, `bool`, managed `class`, array of objects). Marshaller CLR harus mengalokasikan buffer native sementara, menyalin (*marshal*) data dari managed heap ke native buffer sebelum eksekusi, lalu mengonversinya kembali setelah selesai. Ini memperkenalkan overhead CPU dan memory churn.
- **The Pinning Cost (`fixed`)**: Keyword `fixed` memberitahu GC untuk memasukkan alamat memori objek ke dalam daftar internal *pinned objects*. Ketika GC melakukan siklus *compaction*, GC tidak dapat memindahkan blok memori ini. Hal ini menyebabkan fenomena **Heap Fragmentation** (*GC holes*), yang dapat menurunkan efisiensi alokasi memori managed di sekitarnya.

#### Trade-offs
| Pendekatan | Keuntungan | Kerugian |
| :--- | :--- | :--- |
| **Managed Code (Safe)** | Memory-safe, bounds checking, otomatisasi GC | Ada batas overhead bounds-check, abstraksi object layer |
| **Unsafe Pointers** | Performa raw memory (setara C), zero-overhead access | Rentan crash (Access Violation), mematikan jaminan keamanan |
| **LibraryImport** | Eksekusi AOT-friendly, native speed, deterministik | Memerlukan pemahaman layout memori platform target, potensi memory leak manual |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Tipe Blittable Sesering Mungkin**: Susun struct dengan `[StructLayout(LayoutKind.Sequential)]` jika ingin mentransfer data ke native code tanpa biaya marshalling.
- **Minimalkan Durasi Pinning**: Batasi cakupan blok `fixed` sesingkat mungkin agar tidak menahan ruang kerja compacting GC.
- **Manfaatkan Span / Memory**: Gunakan API modern yang aman seperti `Span<T>` atau `MemoryMarshal` untuk manipulasi memori pointer-like sebelum memutuskan turun ke pointer mentah `T*`.
- **Gunakan `[UnmanagedCallersOnly]` untuk Callback**: Hindari mengoper delegasi managed biasa ke native code; gunakan static method dengan atribut `[UnmanagedCallersOnly]` untuk menghindari alokasi GC dan overhead delegasi managed.

#### Don'ts
- **Jangan Mengembalikan Pointer Memory Stack**: Jangan pernah mengembalikan alamat pointer yang dialokasikan via `stackalloc` ke luar scope metodenya. Stack frame akan ditimpa, menghasilkan memory corruption (*undefined behavior*).
- **Hindari Marshalling String Berulang via `[DllImport]` default**: Hindari ketergantungan pada runtime marshaller bawaan untuk transformasi string yang frekuentif. Gunakan `ReadOnlySpan<byte>` dengan terminasi null UTF-8 secara langsung.
- **Jangan Mengabaikan Return Values Native Memory**: Jika library C mengalokasikan memori native (misalnya `malloc`), pastikan ada implementasi native wrapper untuk melepaskannya (`free`), atau manfaatkan `SafeHandle`.

#### Edge Cases
- **P/Invoke Error Handling**: Jangan menggunakan `Marshal.GetLastWin32Error()` atau `errno` secara manual setelah pemanggilan P/Invoke tanpa mengatur `SetLastError = true`. CLR sendiri mungkin mengeksekusi operasi sistem internal di latar belakang yang menimpa nilai last error tersebut. Gunakan `Marshal.GetLastPInvokeError()` bersamaan dengan `[LibraryImport(..., SetLastError = true)]`.
- **Data Alignment**: Struktur unmanaged yang menggunakan `LayoutKind.Explicit` harus memperhatikan arsitektur CPU target (x86 vs x64 vs ARM64). *Unaligned memory access* dapat memicu instruksi hardware penalty atau bahkan `Bus Error` pada platform arsitektur tertentu seperti ARM.

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Fast Memmove**: Tulis sebuah fungsi `FastCopy(byte* src, byte* dest, int length)` menggunakan pointer `ulong*` (64-bit chunk) untuk menyalin 8 byte sekaligus, kemudian tangani sisa bytes (*tailing bytes*) satu per satu. Bandingkan performanya dengan `Buffer.BlockCopy` menggunakan benchmark tool (`BenchmarkDotNet`).
2. **Reverse Interop dengan C-Style String**: Buat sebuah struct C# yang memetakan struct C native dengan array berukuran tetap (`fixed byte Name[32]`). Tulis metode konversi untuk membaca dan menulis UTF-8 string ke dalam buffer tetap tersebut tanpa menimbulkan alokasi memori baru di managed heap.
3. **Audit Native Memory Menggunakan SafeHandle**: Buat kelas turunan dari `SafeHandleZeroOrMinusOneIsInvalid` untuk mengapsulasi alokasi memori manual via `Marshal.AllocHGlobal` / `NativeMemory.Alloc`. Pastikan memori tersebut selalu aman dari memory leak meskipun thread mengalami interupsi atau exception.
