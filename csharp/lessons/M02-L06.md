## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam C#, tipe data dibagi menjadi dua kategori utama: **Reference Types** (seperti `class`) dan **Value Types** (seperti `struct`). `struct` adalah fondasi untuk menulis kode berkinerja tinggi (high-performance) di .NET karena mereka meminimalkan tekanan pada Garbage Collector (GC) dan meningkatkan *data locality* di CPU cache.

- **Struct (Value Type)**: Secara default dialokasikan di *Stack* (jika menjadi variabel lokal) atau di-inline di dalam objek lain di *Heap* (jika menjadi field dari sebuah class). Variabel `struct` menyimpan datanya secara langsung, bukan menyimpan *pointer* ke memori lain.
- **Readonly Struct**: Memaksa *immutability* (ketidakubah-ubahan) pada tingkat kompilator. Semua field di dalamnya harus `readonly`. Ini sangat penting karena mencegah kompilator membuat *defensive copies* (salinan defensif) yang memakan resource saat struct diakses melalui *reference* (misalnya menggunakan modifier `in`).
- **Ref Struct**: Diperkenalkan di C# 7.2, `ref struct` adalah tipe yang **dijamin** hanya hidup di *Stack*. Tipe ini tidak akan pernah bisa dialokasikan di *Heap* (tidak bisa di-*boxing*, tidak bisa menjadi field dari `class`, tidak bisa digunakan di dalam blok `async/await` atau *iterator*). `ref struct` adalah tulang punggung dari tipe memori-aman berkinerja tinggi seperti `Span<T>` dan `ReadOnlySpan<T>`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern yang membandingkan penggunaan `readonly struct` untuk data spasial dan `ref struct` untuk pemrosesan teks tanpa alokasi (zero-allocation).

```csharp
using System;

// 1. READONLY STRUCT
// Ideal untuk data kecil (<= 16-24 bytes) yang merepresentasikan nilai tunggal.
public readonly struct Vector3D
{
    public double X { get; init; }
    public double Y { get; init; }
    public double Z { get; init; }

    public Vector3D(double x, double y, double z)
    {
        X = x; Y = y; Z = z;
    }

    // Method ini tidak akan memodifikasi state (dijamin oleh readonly struct)
    public double CalculateMagnitude() => Math.Sqrt(X * X + Y * Y + Z * Z);
}

// 2. REF STRUCT
// Ideal untuk manipulasi memori sementara (stack-only) tanpa membebani GC.
public ref struct FastLogParser
{
    // ReadOnlySpan adalah ref struct bawaan .NET
    private ReadOnlySpan<char> _logLine;

    public FastLogParser(ReadOnlySpan<char> logLine)
    {
        _logLine = logLine;
    }

    public ReadOnlySpan<char> GetTimestamp()
    {
        // Mencari indeks tanpa mengalokasikan string baru (Substring)
        int bracketIndex = _logLine.IndexOf(']');
        if (bracketIndex == -1) return ReadOnlySpan<char>.Empty;
        
        // Slice beroperasi langsung di memori asli, O(1) time complexity
        return _logLine.Slice(1, bracketIndex - 1);
    }
}

public class Program
{
    public static void Main()
    {
        // Penggunaan Readonly Struct
        var v1 = new Vector3D(1.0, 2.0, 3.0);
        Console.WriteLine($"Magnitude: {v1.CalculateMagnitude()}");

        // Penggunaan Ref Struct
        string rawLog = "[2023-10-27T10:00:00Z] ERROR: Out of memory";
        
        // rawLog secara implisit dikonversi menjadi ReadOnlySpan<char>
        var parser = new FastLogParser(rawLog); 
        ReadOnlySpan<char> timestamp = parser.GetTimestamp();
        
        Console.WriteLine($"Timestamp: {timestamp.ToString()}");
    }
}
```

**Penjelasan Kode:**
- `Vector3D` menggunakan `readonly struct` dan `init` properties. Ini memastikan data aman dari mutasi dan kompilator dapat mengoptimalkan pengirimannya antar method.
- `FastLogParser` menggunakan `ref struct` karena ia menyimpan `ReadOnlySpan<char>`. Ini memungkinkan kita mem-parsing string log panjang tanpa memanggil `.Substring()` yang akan mengalokasikan string baru di Heap dan memicu GC.

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime**: 
  - Saat Anda mem-passing `struct` ke sebuah method, runtime melakukan *copy-by-value* (menyalin seluruh byte data). Jika struct berukuran 24 bytes, maka 24 bytes disalin ke stack frame method baru.
  - Saat Anda mem-passing `class`, runtime hanya menyalin *reference* (pointer) sebesar 8 bytes (pada arsitektur 64-bit).
- **Alokasi Memori / Resource**: 
  - `struct` biasa akan dialokasikan di Stack jika menjadi variabel lokal. Namun, jika ia di-*cast* ke interface (misal `IEquatable<T>`), ia akan mengalami **Boxing** (dibungkus ke dalam objek di Heap), yang menghancurkan benefit performanya.
  - `ref struct` memiliki aturan ketat di level CLR (Common Language Runtime). CLR memverifikasi bahwa `ref struct` tidak pernah "lolos" (escape) dari Stack. Oleh karena itu, ia tidak bisa di-boxing atau ditangkap oleh *closure* (lambda/delegate).
- **Trade-offs**: 
  - Menggunakan `struct` mengurangi *GC pause time* karena tidak ada memori Heap yang perlu dibersihkan. Namun, jika ukuran `struct` terlalu besar (> 24 bytes), biaya CPU untuk menyalin data (*copying cost*) akan melebihi keuntungan dari penghindaran GC.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - **Selalu jadikan struct `readonly`** jika memungkinkan. Mutasi pada struct sering menyebabkan bug "lost update" karena Anda mungkin memodifikasi salinan, bukan data aslinya.
  - Pertahankan ukuran struct di bawah 16-24 bytes. Jika lebih besar, pertimbangkan untuk menggunakan `class` atau pass-by-reference menggunakan modifier `in` atau `ref`.
  - Gunakan `ref struct` dan `Span<T>` untuk operasi I/O, parsing teks, atau manipulasi array berkinerja tinggi.
- **Don'ts**:
  - **Jangan membuat mutable struct**. Jika Anda memiliki properti bersetter publik pada struct, Anda mengundang bug tersembunyi.
  - **Jangan mem-boxing struct**. Hindari memasukkan struct ke dalam koleksi non-generic (seperti `ArrayList`) atau meng-cast-nya ke `object` / interface tanpa constraint generic.
- **Edge Cases**:
  - **Defensive Copies**: Jika Anda memiliki `struct` (non-readonly) yang disimpan di dalam field `readonly`, dan Anda memanggil method dari struct tersebut, kompilator C# secara diam-diam akan membuat salinan struct tersebut sebelum mengeksekusi method. Ini dilakukan karena kompilator tidak tahu apakah method tersebut akan memutasi state atau tidak. Menggunakan `readonly struct` mencegah penalti performa tersembunyi ini.
