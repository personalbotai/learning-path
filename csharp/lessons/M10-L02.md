## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam piramida pengujian perangkat lunak, *Unit Testing* mengisolasi logika bisnis pada level method/class menggunakan *mocks/stubs*. Namun, unit test tidak dapat memvalidasi serialisasi JSON, routing controller/minimal API, *model validation*, *middleware order*, hingga interaksi riil dengan basis data dan *Dependency Injection* (DI) container. Di sinilah **Integration Testing** berperan.

Di ekosistem .NET, paket `Microsoft.AspNetCore.Mvc.Testing` menyediakan kelas abstraksi inti: `WebApplicationFactory<TEntryPoint>`.

```
                    [ xUnit / NUnit Test Runner ]
                                 │
                   ┌─────────────▼─────────────┐
                   │ WebApplicationFactory<T>  │
                   └─────────────┬─────────────┘
                                 │ Inisialisasi & Konfigurasi
                   ┌─────────────▼─────────────┐
                   │        TestServer         │
                   └─────────────┬─────────────┘
                                 │ HTTP Pipeline (Memory-Only)
        ┌────────────────────────┼────────────────────────┐
        │                        │                        │
┌───────▼────────┐      ┌────────▼────────┐      ┌────────▼────────┐
│ Authentication │      │ Routing & CORS  │      │   Controllers   │
│   Middleware   │ ───► │   Middleware    │ ───► │  / Minimal APIs │
└────────────────┘      └─────────────────┘      └────────┬────────┘
                                                          │
                                                 ┌────────▼────────┐
                                                 │   DbContext     │
                                                 │ (TestContainer) │
                                                 └─────────────────┘
```

#### Komponen Arsitektur:
1. **`TestServer`**: Sebuah implementasi `IServer` yang tidak membuka TCP/IP socket network fisik pada sistem operasi. `TestServer` mengeksekusi *request pipeline* ASP.NET Core murni di dalam memori proses menggunakan abstraksi direct memory stream (`HttpContext`).
2. **`TEntryPoint`**: Biasanya kelas `Program`. Di era Minimal API (C# 10+), *top-level statements* secara default menghasilkan kelas internal `Program`. Agar dapat diakses oleh assembly test, file `.csproj` aplikasi web harus mengekspos visibilitas melalui `InternalsVisibleTo` atau mendefinisikan `public partial class Program { }`.
3. **`Custom WebApplicationFactory`**: Turunan dari `WebApplicationFactory<Program>` yang meng-override `ConfigureWebHost(IWebHostBuilder builder)`. Di sinilah developer mengganti implementasi *production services* (seperti koneksi database, payment gateway, bus antrean) dengan *test doubles* atau kontainer uji menggunakan `services.PostConfigure` atau re-registrasi pada `IServiceCollection`.

### 2. Implementasi & Contoh Kasus Nyata

Skenario: Menguji endpoint transaksi POS (Point of Sale) `POST /api/orders` yang memvalidasi stok dan menyimpan order ke database SQL, dengan database pengujian dijalankan via `Testcontainers` atau database in-memory terisolasi.

#### A. Konfigurasi Assembly Web (Program.cs)
Tambahkan deklarasi ini di akhir file `Program.cs` aplikasi utama:
```csharp
// Program.cs aplikasi Web API
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
builder.Services.AddDbContext<AppDbContext>(opts => 
    opts.UseNpgsql(builder.Configuration.GetConnectionString("DefaultConnection")));

var app = builder.Build();

app.UseRouting();
app.MapControllers();

app.Run();

// Wajib diekspos agar WebApplicationFactory di project test dapat mengakses entry point
public partial class Program { }
```

#### B. Implementasi Custom Factory & Fixture
```csharp
// CustomWebApplicationFactory.cs
using System.Data.Common;
using Microsoft.AspNetCore.Hosting;
using Microsoft.AspNetCore.Mvc.Testing;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.DependencyInjection.Extensions;

public class CustomWebApplicationFactory : WebApplicationFactory<Program>
{
    private readonly string _testDatabaseName = Guid.NewGuid().ToString();

    protected override void ConfigureWebHost(IWebHostBuilder builder)
    {
        builder.ConfigureServices(services =>
        {
            // 1. Lepas registrasi DbContextOptions asli
            services.RemoveAll<DbContextOptions<AppDbContext>>();

            // 2. Registrasi DbContext menggunakan In-Memory / SQLite In-Memory
            services.AddDbContext<AppDbContext>(options =>
            {
                options.UseInMemoryDatabase(_testDatabaseName);
            });

            // 3. Eksekusi database seeding jika diperlukan
            using var scope = services.BuildServiceProvider().CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
            db.Database.EnsureCreated();
            SeedTestData(db);
        });

        // Set environment ke Testing agar configuration builder memuat appsettings.Testing.json
        builder.UseEnvironment("Testing");
    }

    private static void SeedTestData(AppDbContext db)
    {
        db.Products.Add(new Product { Id = 1, Name = "Mechanical Keyboard", Stock = 10, Price = 1500000 });
        db.SaveChanges();
    }
}
```

#### C. Penulisan Integration Test (xUnit)
```csharp
// OrderControllerIntegrationTests.cs
using System.Net;
using System.Net.Http.Json;
using Xunit;

public class OrderControllerIntegrationTests : IClassFixture<CustomWebApplicationFactory>
{
    private readonly HttpClient _client;
    private readonly CustomWebApplicationFactory _factory;

    public OrderControllerIntegrationTests(CustomWebApplicationFactory factory)
    {
        _factory = factory;
        // Inisialisasi client yang terikat langsung ke TestServer in-memory
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task Post_CreateOrder_ReturnsCreated_WhenStockIsSufficient()
    {
        // Arrange
        var requestPayload = new CreateOrderRequest
        {
            ProductId = 1,
            Quantity = 2
        };

        // Act
        HttpResponseMessage response = await _client.PostAsJsonAsync("/api/orders", requestPayload);

        // Assert
        Assert.Equal(HttpStatusCode.Created, response.StatusCode);

        var responseData = await response.Content.ReadFromJsonAsync<OrderResponse>();
        Assert.NotNull(responseData);
        Assert.Equal(2, responseData.Quantity);
        Assert.Equal(3000000, responseData.TotalPrice);

        // Verifikasi mutasi state langsung ke database via Factory DI Scope
        using var scope = _factory.Services.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        var updatedProduct = await db.Products.FindAsync(1);
        
        Assert.NotNull(updatedProduct);
        Assert.Equal(8, updatedProduct.Stock); // 10 - 2
    }

    [Fact]
    public async Task Post_CreateOrder_ReturnsUnprocessableEntity_WhenPayloadIsInvalid()
    {
        // Arrange: Quantity tidak valid
        var requestPayload = new CreateOrderRequest
        {
            ProductId = 1,
            Quantity = 0 
        };

        // Act
        HttpResponseMessage response = await _client.PostAsJsonAsync("/api/orders", requestPayload);

        // Assert: Validasi model state middleware terpanggil dengan benar
        Assert.Equal(HttpStatusCode.BadRequest, response.StatusCode);
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime:
1. **Bootstrap Sequence**: Saat test runner mengeksekusi constructor kelas test, `WebApplicationFactory` mengeksekusi pipeline program target via method `CreateHost()`. Alih-alih memanggil `KestrelServer`, runtime menginstansiasi instance `TestServer`.
2. **Pintas Jaringan (Direct Memory Invocation)**: Method `_client.PostAsJsonAsync()` tidak membentuk koneksi socket TCP. `HttpClient` yang dibuat oleh `CreateClient()` menggunakan `HttpMessageHandler` kustom internal (`ClientHandler`). Handler ini memetakan objek `HttpRequestMessage` menjadi objek `HttpContext` ASP.NET Core secara langsung di memori, lalu menyalurkannya ke rantai middleware ASP.NET Core melalui delegasi `RequestDelegate`.

#### Alokasi Memori & Resource:
- **Lifetime Host**: Instansiasi `WebApplicationFactory` memakan resource komputasi besar (kompilasi regex routing, pembentukan graph dependency injection, kompilasi expression tree DbContext). Dengan mengimplementasikan interface `IClassFixture<TFactory>` di xUnit, host hanya dibangun **satu kali** per test class suite, bukan di setiap test case method (`[Fact]`).
- **Memory Footprint**: Database In-Memory EF Core tidak membersihkan GC collection secara otomatis antar test run. Objek state statis di level provider database dapat menyebabkan *memory leakage* jika suite test memiliki ribuan skenario dan scope service tidak didispose secara eksplisit.

#### Trade-offs:
- **In-Memory Database Provider vs Real DB**: `UseInMemoryDatabase` bukanlah relational engine. Ia tidak menegakkan *foreign key constraints*, tidak mendukung evaluasi transaction isolation level, dan tidak dapat mengeksekusi raw SQL. Untuk skenario produksi tinggi, lebih disarankan mengombinasikan `WebApplicationFactory` dengan **Testcontainers.PostgreSql / SqlEdge** via Docker container terisolasi.

### 4. Best Practices & Common Pitfalls

#### Do's:
- **Gunakan Test-Specific Scopes**: Selalu buat manual scope (`_factory.Services.CreateScope()`) saat ingin memeriksa database atau memodifikasi state sebelum dan sesudah test. Mengambil service *scoped* (seperti `DbContext`) langsung dari `_factory.Services` (root container) akan memicu exception `InvalidOperationException` di runtime.
- **Pindahkan Auth State Menggunakan Mock Authentication Handler**: Hindari memanggil endpoint `/login` sungguhan di setiap integration test. Pasang custom `AuthenticationHandler<AuthenticationSchemeOptions>` di pipeline test untuk menginjeksi *ClaimsIdentity* dummy secara instan.
- **Implementasikan IAsyncLifetime**: Jika menggunakan container eksternal (Testcontainers), implementasikan interface `IAsyncLifetime` pada custom factory untuk menangani lifecycle `StartAsync()` dan `StopAsync()` container secara asinkron.

#### Don'ts:
- **Jangan gunakan `services.BuildServiceProvider()` secara serampangan**: Memanggil `BuildServiceProvider()` di dalam `ConfigureServices` akan membuat salinan instance service container kedua (duplikasi *singleton*). Gunakan pendekatan `PostConfigure` atau delegasikan konfigurasi DbContext dengan opsi baru.
- **Hindari State Leak Antar-Test**: Jika satu test memodifikasi baris data ID `1`, test lain yang berjalan paralel tidak boleh bergantung pada baris ID `1` yang belum termutasi. Gunakan strategi isolasi database, seperti database per method, *Transaction Scope rollback*, atau reset skrip DB antar-test.

#### Edge Cases:
- **Divergensi Konfigurasi Lingkungan**: Jika aplikasi bergantung pada variabel environment sistem (seperti `ASPNETCORE_ENVIRONMENT`), pastikan `builder.UseEnvironment("Testing")` diatur sebelum builder membangun host. Jika tidak, aplikasi akan membaca konfigurasi `appsettings.Development.json` atau secrets produksi lokal yang menyebabkan kegagalan koneksi.

### 5. Tantangan Eksplorasi Mandiri

1. **Bypass Autentikasi JWT**:
   Buat subclass `AuthenticationHandler<AuthenticationSchemeOptions>` bernama `TestAuthHandler`. Konfigurasikan `CustomWebApplicationFactory` untuk mengganti *Authentication Scheme* default dengan skema uji coba tersebut, sehingga request HTTP dapat menyematkan header `Authorization: Bearer <dummy>` dan dikenali sebagai `User` yang memiliki *Role* "Admin" tanpa proses enkripsi/dekripsi token JWT asli.

2. **Migrasi ke Testcontainers**:
   Ubah `CustomWebApplicationFactory` di atas agar tidak lagi menggunakan `UseInMemoryDatabase`. Gunakan pustaka `Testcontainers.PostgreSql` atau `Testcontainers.MsSql`. Jalankan container database riil secara otomatis saat factory diinisialisasi dan terapkan migrasi EF Core (`db.Database.MigrateAsync()`) sebelum pengujian pertama dijalankan. Amati perbedaan integritas relasional data jika dibandingkan dengan database in-memory.
