### 1. Konsep & Arsitektur Mendalam

Clean Architecture (sering diasosiasikan dengan *Onion Architecture* dan *Hexagonal/Ports and Adapters Architecture*) berpusat pada satu aturan fundamental: **The Dependency Rule**. Aturan ini menetapkan bahwa dependensi kode sumber hanya boleh mengarah ke dalam (*inward-pointing*), menuju domain bisnis inti.

```
       +---------------------------------------------+
       | Presentation (API / UI / Minimal APIs)     |
       |   +---------------------------------------+ |
       |   | Infrastructure (EF Core, Redis, HTTP) | |
       |   |   +---------------------------------+ | |
       |   |   | Application (Use Cases, CQRS)   | | |
       |   |   |   +---------------------------+ | | |
       |   |   |   | Domain (Entities, Enums,  | | | |
       |   |   |   |        Value Objects)     | | | |
       |   |   |   +---------------------------+ | | |
       |   |   +---------------------------------+ | |
       |   +---------------------------------------+ |
       +---------------------------------------------+
```

Dalam ekosistem .NET, struktur ini dipartisi ke dalam beberapa Assembly (`.csproj`) terpisah:

1. **Domain Layer (`Core.Domain.csproj`)**:
   - **Tujuan**: Memodelkan state bisnis dan aturan invariansi bisnis enterprise.
   - **Karakteristik**: Bebas dari dependensi NuGet eksternal (bahkan tidak memiliki referensi ke Entity Framework Core atau ASP.NET Core). Berisi *Entities*, *Value Objects*, *Domain Events*, *Domain Exceptions*, dan *Repository Interfaces/Contracts*.

2. **Application Layer (`Core.Application.csproj`)**:
   - **Tujuan**: Mengorkestrasi aliran data dan mendefinisikan *use-case* spesifik aplikasi.
   - **Karakteristik**: Mengimplementasikan pola seperti CQRS (Command Query Responsibility Segregation), pipeline validasi, dan DTO. Hanya bergantung pada *Domain Layer*. Mendefinisikan antarmuka eksternal (misal: `IEmailService`, `IApplicationDbContext`).

3. **Infrastructure Layer (`Infrastructure.csproj`)**:
   - **Tujuan**: Berkomunikasi dengan sistem eksternal, I/O disk, jaringan, dan database.
   - **Karakteristik**: Mengimplementasikan antarmuka yang didefinisikan oleh *Application* atau *Domain*. Berisi implementasi EF Core (`DbContext`), migrasi, caching (Redis), klien HTTP pihak ketiga, dan antrean pesan (RabbitMQ/Azure Service Bus).

4. **Presentation Layer (`API.csproj` / `Presentation.csproj`)**:
   - **Tujuan**: Menjadi pintu masuk eksekusi runtime (*Entry Point*).
   - **Karakteristik**: Berisi Controllers, Minimal API endpoints, middleware, filters, dan konfigurasi Swagger. Lapisan ini juga bertindak sebagai **Composition Root** tempat Dependency Injection Container dikonfigurasi.

#### 2.1. Domain: Entity & Value Object
```csharp
// OrderSystem.Domain/ValueObjects/Money.cs
namespace OrderSystem.Domain.ValueObjects;

public readonly record struct Money
{
    public decimal Amount { get; }
    public string Currency { get; }

    public Money(decimal amount, string currency)
    {
        if (amount < 0)
            throw new ArgumentException("Amount cannot be negative.", nameof(amount));
        
        Amount = amount;
        Currency = currency ?? throw new ArgumentNullException(nameof(currency));
    }
}

// OrderSystem.Domain/Entities/Order.cs
namespace OrderSystem.Domain.Entities;

using OrderSystem.Domain.ValueObjects;

public sealed class Order
{
    public Guid Id { get; private set; }
    public Guid CustomerId { get; private set; }
    public Money TotalAmount { get; private set; }
    public DateTime CreatedAtUtc { get; private set; }

    // Parameterless constructor untuk ORM via reflection
    private Order() { }

    // Domain Invariant dijaga ketat di factory method / constructor
    public static Order Create(Guid customerId, Money totalAmount)
    {
        if (customerId == Guid.Empty)
            throw new ArgumentException("Customer ID is required.", nameof(customerId));

        return new Order
        {
            Id = Guid.NewGuid(),
            CustomerId = customerId,
            TotalAmount = totalAmount,
            CreatedAtUtc = DateTime.UtcNow
        };
    }
}

// OrderSystem.Domain/Repositories/IOrderRepository.cs
namespace OrderSystem.Domain.Repositories;

using OrderSystem.Domain.Entities;

public interface IOrderRepository
{
    Task AddAsync(Order order, CancellationToken cancellationToken = default);
    Task<Order?> GetByIdAsync(Guid id, CancellationToken cancellationToken = default);
}
```

#### 2.2. Application: Use Case (Command & Handler)
```csharp
// OrderSystem.Application/Orders/Commands/CreateOrderCommand.cs
namespace OrderSystem.Application.Orders.Commands;

using OrderSystem.Domain.Entities;
using OrderSystem.Domain.Repositories;
using OrderSystem.Domain.ValueObjects;

public record CreateOrderCommand(Guid CustomerId, decimal Amount, string Currency);

public sealed class CreateOrderCommandHandler
{
    private readonly IOrderRepository _orderRepository;

    public CreateOrderCommandHandler(IOrderRepository orderRepository)
    {
        _orderRepository = orderRepository;
    }

    public async Task<Guid> HandleAsync(CreateOrderCommand command, CancellationToken ct)
    {
        var money = new Money(command.Amount, command.Currency);
        var order = Order.Create(command.CustomerId, money);

        await _orderRepository.AddAsync(order, ct);

        return order.Id;
    }
}
```

#### 2.3. Infrastructure: Service Registration & Implementasi
```csharp
// OrderSystem.Infrastructure/DependencyInjection.cs
namespace OrderSystem.Infrastructure;

using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Configuration;
using OrderSystem.Domain.Repositories;
using OrderSystem.Infrastructure.Persistence.Repositories;

public static class DependencyInjection
{
    public static IServiceCollection AddInfrastructure(this IServiceCollection services, IConfiguration configuration)
    {
        // Pendaftaran DbContext, Service Broker, dsb.
        services.AddScoped<IOrderRepository, OrderRepository>();
        return services;
    }
}

// OrderSystem.Infrastructure/Persistence/Repositories/OrderRepository.cs
namespace OrderSystem.Infrastructure.Persistence.Repositories;

using OrderSystem.Domain.Entities;
using OrderSystem.Domain.Repositories;

public sealed class OrderRepository : IOrderRepository
{
    // Simulasi in-memory DB; praktiknya menggunakan DbContext dari EF Core
    private static readonly Dictionary<Guid, Order> Storage = new();

    public Task AddAsync(Order order, CancellationToken cancellationToken = default)
    {
        Storage[order.Id] = order;
        return Task.CompletedTask;
    }

    public Task<Order?> GetByIdAsync(Guid id, CancellationToken cancellationToken = default)
    {
        Storage.TryGetValue(id, out var order);
        return Task.FromResult(order);
    }
}
```

#### 2.4. Presentation: Minimal API & Composition Root
```csharp
// OrderSystem.Api/Program.cs
using OrderSystem.Application.Orders.Commands;
using OrderSystem.Infrastructure;

var builder = WebApplication.CreateBuilder(args);

// Register layers via Dependency Injection
builder.Services.AddInfrastructure(builder.Configuration);
builder.Services.AddScoped<CreateOrderCommandHandler>();

var app = builder.Build();

app.MapPost("/api/orders", async (CreateOrderCommand command, CreateOrderCommandHandler handler, CancellationToken ct) =>
{
    var orderId = await handler.HandleAsync(command, ct);
    return Results.Created($"/api/orders/{orderId}", new { Id = orderId });
});

app.Run();
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (Inversion of Control)
Secara struktur kode sumber (compile-time), lapisan `Presentation` dan `Infrastructure` bergantung pada `Application`, dan `Application` bergantung pada `Domain`. Namun, aliran kendali (*control flow*) runtime berjalan secara terbalik:
1. HTTP Request diterima oleh ASP.NET Core Kestrel (`Presentation`).
2. Kestrel memanggil `CreateOrderCommandHandler` (`Application`).
3. Handler mengeksekusi metode pada `IOrderRepository` (Interface milik `Domain`).
4. Eksekusi masuk ke `OrderRepository` (`Infrastructure`).

Mekanisme ini bekerja berkat runtime polymorphism yang diproses oleh CLR (Common Language Runtime) melalui **Virtual Method Table (vtable)**. Saat *interface method* dipanggil, CLR mengeksekusi instruksi IL `callvirt`. Runtime memeriksa *method table* dari instance konkrit yang di-inject oleh IoC Container (`IServiceProvider`) untuk menentukan alamat memori fungsi aktual.

#### Kompilasi & Assembly Boundary
Setiap project menghasilkan file biner `.dll` tersendiri. Roslyn Compiler memastikan aturan dependensi dipatuhi secara absolut saat fase kompilasi:
- Jika programmer mencoba menginstansiasi kelas `OrderRepository` di dalam proyek `OrderSystem.Application`, compiler akan melempar error `CS0246` (type not found) karena `Application.csproj` **tidak memiliki** metadata reference (`<ProjectReference>`) ke `Infrastructure.csproj`.
- Roslyn memverifikasi siklus dependensi; circular references antar `.csproj` ditolak secara mutlak oleh MSBuild sebelum kompilasi IL dimulai.

#### Trade-offs
1. **Memory Allocation**: Arsitektur ini menuntut pemisahan data model. Seringkali entity dipetakan ke DTO lalu dipetakan lagi ke ViewModel. Setiap pemetaan menghasilkan alokasi objek baru di Gen 0 Heap, meningkatkan frekuensi garbage collection (GC) jika tidak dioptimalkan dengan `struct`, compile-time source generator (seperti Mapperly), atau pemanggilan *projected query* via `Select`.
2. **Indirection Latency**: Abstraksi berlapis menambah kedalaman call-stack. Meskipun JIT compiler dapat melakukan *inlining* untuk pemanggilan fungsi sederhana, abstraksi interface virtual call (`callvirt`) membatasi kemampuan JIT untuk melakukan devirtualization dan inline agresif tanpa Profile-Guided Optimization (PGO).

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Value Objects untuk Primitif Domain**: Ganti string dan desimal telanjang dengan Value Object (contoh: `Money`, `EmailAddress`). Manfaatkan `readonly record struct` di C# untuk memangkas alokasi heap.
- **Enkapsulasi State Entitas**: Buat properti setter berstatus `private` atau `init`. Mutasi state harus melalui *behavior methods* eksplisit (seperti `Order.Cancel()`) untuk menjamin validitas bisnis invariant setiap saat.
- **Gunakan C# Internal Keyword & InternalsVisibleTo**: Jika tidak ingin kelas implementasi infrastruktur bocor secara sembarangan ke Presentation Layer, buat kelas tersebut `internal` dan hanya daftarkan lewat extension method DI di assembly tersebut.

#### Don'ts
- **Bocornya Atribut Database ke Domain**: Menaruh atribut EF Core seperti `[Table("Orders")]` atau `[Column(TypeName = "varchar(50)")]` di dalam `Domain Layer`. Pemetaan schema harus menggunakan `IEntityTypeConfiguration<T>` via Fluent API di Infrastructure Layer.
- **Anemic Domain Model**: Menjadikan Entity sekadar "tas data" yang hanya berisi properti *get/set* publik, sementara seluruh logika validasi ditaruh di Application Services/Command Handlers. Ini mereduksi Domain-Driven Design menjadi sekadar skrip prosedural.
- **Mengembalikan Entity Domain langsung ke HTTP Client**: Mengembalikan entitas `Order` di Minimal API / Controller merusak enkapsulasi, menyebabkan *circular reference serialization error*, dan membocorkan struktur internal domain. Selalu gunakan DTO kontrak API.

#### Edge Cases
- **Pendaftaran Composition Root**: `OrderSystem.Api` memerlukan referensi ke `OrderSystem.Infrastructure` *hanya* untuk mendaftarkan dependensi di `Program.cs`. Hal ini berisiko membuat developer menggunakan kelas infrastruktur langsung di API controller.
  - *Mitigasi*: Pisahkan registrasi DI ke assembly perantara atau enforce pembatasan menggunakan custom build analyzer / architecture unit tests.

### 5. Tantangan Eksplorasi Mandiri

1. **Architecture Enforcement via Tests**:
   Gunakan library seperti `NetArchTest.Rules` atau `ArchUnitNET`. Buat Unit Test yang memastikan secara otomatis bahwa **tidak ada** kelas di dalam `OrderSystem.Domain` yang mereferensikan namespace `Microsoft.EntityFrameworkCore` atau namespace `OrderSystem.Application`.
2. **Pola Result vs Exception**:
   Ubah flow alur kerja `CreateOrderCommandHandler` agar tidak melempar `ArgumentException` untuk validasi bisnis. Implementasikan generic `Result<T>` pattern (`OneOf` atau struct buatan sendiri) untuk melihat bagaimana error boundary dikomunikasikan secara murni melewati batas lapisan dari Domain ke API tanpa biaya performa *stack-trace unwinding* dari CLR Exception handling.
