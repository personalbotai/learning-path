### 1. Konsep & Arsitektur Mendalam

Secara tradisional, membuat koleksi data yang dapat diiterasi (`enumerable`) di C# mewajibkan developer mengimplementasikan antarmuka `IEnumerable<T>` dan `IEnumerator<T>` secara manual. Pendekatan ini membutuhkan penulisan boilerplate code yang masif: membuat class terpisah untuk enumerator, mengelola pointer penunjuk indeks, mengimplementasikan method `MoveNext()`, `Reset()`, property `Current`, serta logika `IDisposable`.

C# memperkenalkan kata kunci kontekstual **`yield return`** dan **`yield break`** sebagai *compiler-synthesized syntactic sugar* untuk menyederhanakan pembuatan iterator.

```
       Caller (Consumer)                     Iterator Method (Producer)
      +------------------+                      +-------------------+
      | foreach / MoveNext|                      |   yield return x  |
      +--------+---------+                      +---------+---------+
               |                                          ^
               | 1. Memanggil MoveNext()                  |
               +----------------------------------------> | (Resume eksekusi)
               |                                          |
               | 2. Mengembalikan nilai & jeda eksekusi   |
               | <----------------------------------------+ (Suspend eksekusi)
               v                                            Menyimpan local state
     Menerima Item (Current)
```

#### Karakteristik Utama:
1. **Deferred Execution (Evaluasi Malas / Lazy Evaluation)**: Kode di dalam iterator method **tidak dieksekusi** saat method tersebut dipanggil. Eksekusi baru dimulai saat pemanggil (consumer) meminta elemen pertama via `IEnumerator.MoveNext()` (misalnya melalui perulangan `foreach` atau pemanggilan `.First()`).
2. **State Preservation (Suspension & Resumption)**: Saat runtime menemukan `yield return`, eksekusi method dihentikan sementara (*suspended*), nilai dikirimkan ke caller via `Current`, dan seluruh konteks eksekusi (variabel lokal, execution pointer) dibekukan. Ketika `MoveNext()` dipanggil kembali, eksekusi dilanjutkan tepat dari baris setelah `yield return` terakhir.
3. **Short-Circuiting via `yield break`**: Mengindikasikan bahwa iterasi telah selesai secara permanen. Ini setara dengan mengembalikan `false` pada implementasi manual `MoveNext()`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah skenario pemrosesan log file berukuran gigabyte atau pagination data API secara streaming tanpa membebani RAM (memory footprint konstan $O(1)$).

```csharp
using System;
using System.Collections.Generic;
using System.IO;

namespace IteratorDeepDive;

public record LogEntry(DateTime Timestamp, string Level, string Message);

public static class LogProcessor
{
    // Best practice: Pisahkan validasi argumen dari iterator logic
    public static IEnumerable<LogEntry> StreamFilteredLogs(string filePath, string targetLevel, int maxEntries)
    {
        // 1. Eager validation: Validasi langsung melempar exception saat method dipanggil
        ArgumentException.ThrowIfNullOrWhiteSpace(filePath);
        ArgumentException.ThrowIfNullOrWhiteSpace(targetLevel);
        ArgumentOutOfRangeException.ThrowIfNegativeOrZero(maxEntries);

        if (!File.Exists(filePath))
        {
            throw new FileNotFoundException("Log file tidak ditemukan.", filePath);
        }

        // 2. Mendelegasikan iterasi ke local function (deferred execution)
        return StreamFilteredLogsInternal(filePath, targetLevel, maxEntries);
    }

    private static IEnumerable<LogEntry> StreamFilteredLogsInternal(string filePath, string targetLevel, int maxEntries)
    {
        int yieldCount = 0;

        // Resource disposal terintegrasi: using statement diterjemahkan ke state machine Dispose()
        using var reader = new StreamReader(filePath);
        string? line;

        while ((line = reader.ReadLine()) is not null)
        {
            if (string.IsNullOrWhiteSpace(line))
            {
                continue;
            }

            var parts = line.Split('|', 3);
            if (parts.Length < 3)
            {
                continue;
            }

            var level = parts[1].Trim();

            if (level.Equals(targetLevel, StringComparison.OrdinalIgnoreCase))
            {
                if (DateTime.TryParse(parts[0].Trim(), out var timestamp))
                {
                    // Menghasilkan nilai dan menangguhkan (suspend) eksekusi
                    yield return new LogEntry(timestamp, level, parts[2].Trim());
                    yieldCount++;

                    // Menghentikan iterasi sepenuhnya jika kuota terpenuhi
                    if (yieldCount >= maxEntries)
                    {
                        yield break; 
                    }
                }
            }
        }
        
        // Selesai membaca file secara alami (ekuivalen implisit dengan yield break)
    }
}

public class Program
{
    public static void Main()
    {
        // Simulasi pembuatan data log mini
        string tempPath = Path.GetTempFileName();
        File.WriteAllLines(tempPath, new[]
        {
            "2026-03-30 10:00:00 | INFO  | Server initialized",
            "2026-03-30 10:01:05 | ERROR | Database connection timeout",
            "2026-03-30 10:02:10 | WARN  | High memory usage detected",
            "2026-03-30 10:05:22 | ERROR | Deadlock occurred on transaction #42",
            "2026-03-30 10:06:00 | ERROR | Unhandled NullReferenceException"
        });

        try
        {
            // Method dipanggil: Belum ada file I/O yang berjalan di baris ini!
            IEnumerable<LogEntry> errorLogs = LogProcessor.StreamFilteredLogs(tempPath, "ERROR", maxEntries: 2);

            // Eksekusi dimulai saat foreach memanggil MoveNext() pertama kali
            foreach (var log in errorLogs)
            {
                Console.WriteLine($"[{log.Timestamp:HH:mm:ss}] {log.Level}: {log.Message}");
            }
            // Console Output hanya mencetak 2 data pertama, loop berhenti, stream langsung ditutup
        }
        finally
        {
            if (File.Exists(tempPath)) File.Delete(tempPath);
        }
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (Roslyn State Machine)
Ketika compiler Roslyn mendeteksi `yield return` atau `yield break` di dalam method:
1. Compiler mentransformasi method tersebut menjadi sebuah **private nested class** bertipe `class <MethodName>d__X : IEnumerable<T>, IEnumerator<T>, IDisposable`.
2. Method asli diubah menjadi method *stub* yang hanya menginstansiasi class state machine ini.
3. Seluruh variabel lokal (seperti `reader`, `yieldCount`, `line`) dielevasi (*hoisted*) menjadi **field** dalam class generated tersebut agar nilainya bertahan di antara pemanggilan `MoveNext()`.
4. Tubuh method diubah menjadi implementasi method `MoveNext()` yang berisi statement `switch (__state)`:
   - State `-1` biasanya menandakan iterasi belum dimulai / running.
   - State `0` adalah entry point.
   - State bernilai positif menandakan titik suspensi spesifik untuk setiap baris `yield return`.
   - State `-2` atau `-3` mengindikasikan enumerator telah selesai (*disposed/finished*).

#### Alokasi Memori / Resource
- **Heap Allocation**: Setiap pemanggilan method iterator mengalokasikan instance class state machine di Heap (GC Gen 0).
- **Life Cycle `finally` Block**: Jika consumer berhenti di tengah jalan (misalnya menggunakan statement `break` di dalam loop `foreach`), pemanggilan `IEnumerator.Dispose()` dipicu oleh blok `finally` tersembunyi yang digenerate oleh `foreach`. Class state machine akan mengeksekusi blok pembersihan (seperti `using var reader`) melalui mekanisme internal `IDisposable.Dispose()`.

#### Trade-offs
- **Kelebihan**: Alokasi memori sangat rendah ($O(1)$) untuk dataset tak terbatas (*infinite sequence*) atau sangat besar karena tidak ada buffering ke `List<T>`.
- **Kekurangan**: Terjadi overhead alokasi objek state machine dan pemanggilan method *indirect* (state dispatching) pada setiap pembacaan elemen. Jangan gunakan iterator di dalam jalur eksekusi berkecepatan tinggi (*nano-benchmarked hot path*) jika alokasi mikro menjadi bottleneck.

### 4. Best Practices & Common Pitfalls

#### Do's:
- **Pisahkan Validasi Argumen**: Gunakan method wrapper publik untuk validasi parameter (cek `null`, range value), lalu arahkan pemrosesan ke *local function* yang menggunakan `yield`. Jika tidak dipisahkan, *exception* baru akan meledak saat iterator di-*consume*, bukan saat method dipanggil, menyebabkan debugging yang membingungkan.
- **Manfaatkan Pembatalan (`CancellationToken`)**: Teruskan `CancellationToken` ke dalam method iterator streaming agar pemrosesan data panjang dapat dibatalkan di tengah iterasi.

#### Don'ts:
- **Multiple Enumeration**: Hindari melakukan iterasi berulang kali terhadap return value iterator (misal: memanggil `query.Any()` lalu `query.ToList()`). Setiap iterasi akan mengeksekusi ulang seluruh logika iterator dari awal (re-reading stream, re-executing query).
  ```csharp
  // BAD: File dibaca dua kali dari piringan storage!
  var logs = LogProcessor.StreamFilteredLogs(path, "ERROR", 10);
  if (logs.Any()) 
  {
      Process(logs.ToList()); 
  }
  ```
- **Side Effects yang Mengubah State Global**: Jangan memodifikasi global state secara tidak terprediksi di dalam iterator karena Anda tidak pernah tahu pasti kapan atau berapa kali consumer akan mengeksekusi loop tersebut.

#### Edge Cases & Batasan Compiler:
- **Larangan `try-catch`**: `yield return` **dilarang keras** berada di dalam blok `try` yang memiliki blok `catch` (`CS1626`). Namun, `yield return` **diizinkan** di dalam blok `try` yang hanya memiliki blok `finally`.
- **Larangan Modifiers**: Method iterator tidak boleh mengandung parameter `in`, `ref`, atau `out`, serta tidak boleh mengembalikan nilai dengan modifier `ref`.
- **Bukan Lambda / Anonymous Method**: Kata kunci `yield` tidak dapat digunakan di dalam lambda expression atau anonymous methods.
