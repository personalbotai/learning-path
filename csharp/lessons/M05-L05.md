## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum C# 8.0, representasi data sekuensial asinkron memiliki jurang pemisah (*impedance mismatch*):

1. **`IEnumerable<T>`**: Mendukung eksekusi tertunda (*deferred execution*) dan model tarik data (*pull-based*), tetapi sepenuhnya sinkron dan memblokir thread pemanggil jika ada operasi I/O.
2. **`Task<IEnumerable<T>>`**: Asinkron, tetapi mengharuskan **seluruh payload** diselesaikan dan dimuat ke dalam memori sebelum kumpulan data dapat mulai diproses oleh konsumen (*all-or-nothing*). Hal ini menyebabkan *high initial latency* dan lonjakan konsumsi memori (*memory spike*).
3. **`IObservable<T>` (Reactive Extensions - Rx)**: Mendukung *streaming* asinkron, namun berbasis *push-model*. Produsen mengontrol laju data, sehingga membutuhkan mekanisme mitigasi *backpressure* yang kompleks jika konsumen lebih lambat daripada produsen.

`IAsyncEnumerable<T>` hadir untuk menyelesaikan dilema ini dengan mengintegrasikan model **pull-based iteration** dari `IEnumerable<T>` dengan **asynchronous non-blocking invocation** dari `Task`/`ValueTask`.

```
        SINKRON                        ASINKRON
      +-----------------------------+-----------------------------+
Data  |  T                          |  Task<T> / ValueTask<T>     |
Tunggal|                             |                             |
      +-----------------------------+-----------------------------+
Banyak|  IEnumerable<T>             |  IAsyncEnumerable<T>        |
Data  |  (Pull: MoveNext())         |  (Pull: MoveNextAsync())    |
      +-----------------------------+-----------------------------+
```

#### Fondasi Antarmuka (Core Interfaces)

Di dalam namespace `System.Collections.Generic`, arsitekturnya disusun atas dua kontrak utama:

```csharp
public interface IAsyncEnumerable<out T>
{
    IAsyncEnumerator<T> GetAsyncEnumerator(CancellationToken cancellationToken = default);
}

public interface IAsyncEnumerator<out T> : IAsyncDisposable
{
    T Current { get; }
    ValueTask<bool> MoveNextAsync();
}
```

Perbedaan arsitektural krusial dibanding versi sinkronnya:
* `MoveNextAsync()` mengembalikan `ValueTask<bool>`, bukan `bool`. Jika data berikutnya sudah tersedia di buffer internal, transisi state terjadi secara instan tanpa alokasi objek `Task` baru di *managed heap*.
* `IAsyncEnumerator<T>` mengimplementasikan `IAsyncDisposable`. Pembersihan resource (misal: koneksi database, network socket) dieksekusi secara asinkron via `DisposeAsync()`.
* Kontrol laju pemrosesan (*backpressure*) terjamin secara alami: produsen tidak akan memproduksi elemen ke-*N+1* sebelum konsumen secara eksplisit memanggil `await enumerator.MoveNextAsync()` untuk meminta elemen tersebut.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah skenario ingest data log dari external API secara berkala menggunakan *cursor-based pagination* dan menyiarkannya sebagai *stream* asinkron.

```csharp
using System;
using System.Collections.Generic;
using System.IO;
using System.Net.Http;
using System.Runtime.CompilerServices;
using System.Text.Json;
using System.Threading;
using System.Threading.Tasks;

public sealed record AuditLog(Guid Id, string EventName, DateTimeOffset Timestamp);

public sealed class AuditLogClient
{
    private readonly HttpClient _httpClient;

    public AuditLogClient(HttpClient httpClient)
    {
        _httpClient = httpClient;
    }

    /// <summary>
    /// Menghasilkan stream AuditLog asinkron langsung dari API eksternal.
    /// Menggunakan [EnumeratorCancellation] agar CancellationToken dari 
    /// 'await foreach' diinjeksikan ke dalam method ini.
    /// </summary>
    public async IAsyncEnumerable<AuditLog> StreamAuditLogsAsync(
        string baseUrl,
        [EnumeratorCancellation] CancellationToken cancellationToken = default)
    {
        string? nextCursor = null;
        bool hasMore = true;

        while (hasMore && !cancellationToken.IsCancellationRequested)
        {
            var url = string.IsNullOrEmpty(nextCursor) 
                ? $"{baseUrl}/logs?limit=50" 
                : $"{baseUrl}/logs?limit=50&cursor={Uri.EscapeDataString(nextCursor)}";

            using var response = await _httpClient.GetAsync(
                url, 
                HttpCompletionOption.ResponseHeadersRead, 
                cancellationToken).ConfigureAwait(false);

            response.EnsureSuccessStatusCode();

            using var stream = await response.Content.ReadAsStreamAsync(cancellationToken).ConfigureAwait(false);
            using var doc = await JsonDocument.ParseAsync(stream, cancellationToken: cancellationToken).ConfigureAwait(false);

            var root = doc.RootElement;
            var dataArray = root.GetProperty("data").EnumerateArray();

            foreach (var element in dataArray)
            {
                var log = JsonSerializer.Deserialize<AuditLog>(element.GetRawText())!;
                
                // Yield data secara individu ke consumer
                yield return log;
            }

            if (root.TryGetProperty("next_cursor", out var cursorProp) && cursorProp.ValueKind == JsonValueKind.String)
            {
                nextCursor = cursorProp.GetString();
                hasMore = !string.IsNullOrEmpty(nextCursor);
            }
            else
            {
                hasMore = false;
            }
        }
    }
}

public class Program
{
    public static async Task Main()
    {
        using var httpClient = new HttpClient();
        var client = new AuditLogClient(httpClient);

        using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(10));

        try
        {
            // Mengonsumsi stream secara asinkron
            await foreach (var log in client.StreamAuditLogsAsync("https://api.internal.network", cts.Token)
                                            .WithCancellation(cts.Token)
                                            .ConfigureAwait(false))
            {
                Console.WriteLine($"[{log.Timestamp:O}] Event: {log.EventName} (ID: {log.Id})");
                
                // Simulasi pemrosesan tiap record secara asinkron
                await ProcessLogAsync(log, cts.Token).ConfigureAwait(false);
            }
        }
        catch (OperationCanceledException)
        {
            Console.WriteLine("Streaming dihentikan oleh CancellationToken.");
        }
    }

    private static ValueTask ProcessLogAsync(AuditLog log, CancellationToken ct)
    {
        // Operasi penulisan ke database / storage lain
        return ValueTask.CompletedTask;
    }
}
```

#### Penjelasan Komponen Penting:
1. **`yield return` dalam konteks asinkron**: Mengubah method biasa menjadi *state-machine* gabungan (*async-iterator*). Anda dapat menggunakan ekspresi `await` bersamaan dengan `yield return`.
2. **`[EnumeratorCancellation]`**: Atribut penanda ke compiler untuk memetakan token yang dipasang pada konsumen (`.WithCancellation(ct)`) ke parameter `cancellationToken` milik produsen.
3. **`HttpCompletionOption.ResponseHeadersRead`**: Membaca headers langsung tanpa memuat seluruh body HTTP ke buffer lokal, memungkinkan stream JSON diproses seketika (*early execution*).
4. **`.ConfigureAwait(false)`**: Mencegah pemanggilan context switching kembali ke `SynchronizationContext` asalnya (sangat krusial untuk library atau background process).

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & State Machine (Roslyn Lowering)
Ketika compiler Roslyn mendeteksi keyword `async` dan `yield return` yang mengembalikan `IAsyncEnumerable<T>`, ia tidak membuat task biasa. Compiler meng-*generate* struktur `class` privat tersembunyi yang mengimplementasikan:
* `IAsyncEnumerable<T>`
* `IAsyncEnumerator<T>`
* `IValueTaskSource<bool>` / `IValueTaskSource`
* `IAsyncStateMachine`

State machine ini memiliki penanda status numerik internal (misal: `-1` untuk *running*, `0` untuk *suspended di await pertama*, `1` untuk *yield return pertama*, `-2` untuk *completed/disposed*).

Saat pemanggilan:
1. **Inisialisasi**: Memanggil method tidak mengeksekusi satu baris pun kode pengguna; method hanya mengembalikan instance *state machine*.
2. **`await foreach` Lowering**:
   ```csharp
   // Kode Anda:
   await foreach (var item in stream) { ... }

   // Diubah oleh Roslyn menjadi:
   var enumerator = stream.GetAsyncEnumerator(cancellationToken);
   try
   {
       while (await enumerator.MoveNextAsync())
       {
           var item = enumerator.Current;
           // Body loop dieksekusi di sini
       }
   }
   finally
   {
       if (enumerator != null)
       {
           await enumerator.DisposeAsync();
       }
   }
   ```
3. **Penyimpanan State**: Variabel lokal (`hasMore`, `nextCursor`) diangkat (*lifted*) menjadi field dari class *state machine*, mempertahankan statusnya antar siklus iterasi `MoveNextAsync()`.

#### Alokasi Memori & Optimasi `ValueTask<bool>`
Penggunaan `ValueTask<bool>` pada `MoveNextAsync()` sangat krusial:
* **Synchronous Path**: Jika batch data sudah ada di memory buffer (`JsonElement` dalam array lokal), pemanggilan `MoveNextAsync()` berikutnya akan selesai secara tersinkronisasi (*synchronously completed*). `ValueTask<bool>` mengembalikan representasi *in-stack struct* murni dengan alokasi heap **0 byte**.
* **Asynchronous Path**: Hanya ketika network I/O tertunda (`await _httpClient.GetAsync()`), mekanisme alokasi task/state-machine callback terjadi.

#### Trade-offs
| Keuntungan | Konsekuensi / Trade-off |
| :--- | :--- |
| **Footprint Memori Rendah**: Konsumsi RAM stabil (O(1) relatif terhadap ukuran total dataset) karena data diproses per elemen/batch kecil. | **Throughput Overhead**: Jika latensi I/O per item sangat rendah, overhead transisi state machine pada setiap item secara individual bisa sedikit menurunkan raw processing throughput dibanding synchronous array iteration. |
| **Natural Backpressure**: Konsumen menentukan kapan item berikutnya diproses. | **Single-Consumer Nature**: Secara default, enumerator tidak aman untuk thread ganda (`thread-unsafe`). Tidak bisa dikonsumsi oleh multiple concurrent consumers secara paralel pada instance enumerator yang sama. |

### 4. Best Practices & Common Pitfalls

#### Do's
* **Gunakan `[EnumeratorCancellation]`**: Selalu sertakan atribut ini pada parameter token fungsi penghasil `IAsyncEnumerable<T>` jika Anda mengizinkan konsumsi token fleksibel via `.WithCancellation()`.
* **Gunakan `ConfigureAwait(false)` pada `await foreach`**:
  ```csharp
  await foreach (var item in stream.WithCancellation(ct).ConfigureAwait(false))
  ```
  Ini mengonfigurasi `ConfiguredCancelableAsyncEnumerable<T>`, memastikan iterasi dan pembersihan `DisposeAsync()` tidak mencoba kembali ke konteks thread UI atau ASP.NET request capture context.
* **Gunakan `IAsyncDisposable` untuk Resource Cleanup**: Pastikan koneksi DB, stream file, atau resource unmanaged selalu berada di dalam blok `using` atau `await using` di dalam fungsi generator.

#### Don'ts
* **Jangan Gunakan `Task.WhenAll` Langsung**: Mengubah `IAsyncEnumerable<T>` menjadi list hanya untuk menggunakan `Task.WhenAll` menggugurkan seluruh efisiensi streaming memori.
* **Hindari Operasi Pemblokir (Blocking Calls)**: Jangan gunakan `.Result`, `.Wait()`, atau `.GetAwaiter().GetResult()` pada operasi di dalam generator method; ini berisiko tinggi memicu thread-pool starvation atau deadlock.
* **Jangan Abaikan Token di Level Database**: Jika menggunakan EF Core (`AsAsyncEnumerable()`), teruskan selalu `CancellationToken` ke dalam query level agar pembatalan dieksekusi di level driver DB (membatalkan statement SQL pada server database).

#### Edge Cases
* **Double Iteration Hazard**: Mengulang iterasi pada `IAsyncEnumerable<T>` dapat memicu eksekusi ulang operasi I/O dari awal (re-query database atau re-fetching HTTP). Jika hasil ingin digunakan berkali-kali tanpa re-fetch, pertimbangkan untuk mencatatnya ke in-memory cache lokal terlebih dahulu.
* **Exception di Dalam Consumer**: Jika blok internal `await foreach` melemparkan exception, kontrol alur langsung melompat ke blok `finally` terselubung dan memanggil `DisposeAsync()`. Pastikan generator method menangani logika pembatalan/dispose di dalam `finally` secara tepat dan tidak menelan exception yang relevan.
