## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam paradigma Object-Oriented Programming (OOP), enkapsulasi adalah prinsip fundamental. C# memfasilitasi enkapsulasi melalui **Properties**, yang bertindak sebagai jembatan (abstraksi) antara *internal state* (fields) dan *external interface*. Alih-alih mengekspos *field* secara langsung (yang rentan terhadap mutasi tidak terkontrol), *properties* memungkinkan kita menyisipkan logika validasi atau komputasi saat membaca (getter) atau menulis (setter) data.

Seiring evolusi C#, kebutuhan akan **Immutability** (ketidakubah-ubahan data) dan **Developer Ergonomics** (mengurangi *boilerplate* konstruktor) semakin tinggi. Hal ini melahirkan dua fitur krusial:
1.  **Init-Only Setters (`init`)** *(C# 9.0)*: Memungkinkan properti diatur *hanya* pada saat inisialisasi objek (melalui *Object Initializer*). Setelah objek selesai dibuat, properti tersebut menjadi *read-only*. Ini adalah fondasi untuk membuat struktur data yang *immutable* tanpa harus menulis konstruktor yang panjang.
2.  **Required Members (`required`)** *(C# 11.0)*: Memaksa pemanggil (caller) untuk menginisialisasi properti atau *field* tertentu saat membuat instance objek. Sebelum fitur ini ada, developer harus membuat konstruktor dengan banyak parameter untuk memaksa inisialisasi. Dengan `required`, kita mendapatkan jaminan *compile-time* bahwa state objek valid sejak awal, dengan sintaks yang jauh lebih bersih.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern menggunakan C# 11+ yang menggabungkan *standard properties*, `init`, dan `required` dalam sebuah Data Transfer Object (DTO).

```csharp
using System;

public class UserProfile
{
    // 1. Standard Auto-Property dengan private setter
    // Hanya bisa diubah dari dalam class ini.
    public Guid Id { get; private set; } = Guid.NewGuid();

    // 2. Required & Init-Only Property
    // WAJIB diisi saat inisialisasi, dan TIDAK BISA diubah setelahnya (Immutable).
    public required string Username { get; init; }

    // 3. Required Property dengan Standard Setter
    // WAJIB diisi saat inisialisasi, tapi BISA diubah kapan saja setelahnya.
    public required string Email { get; set; }

    // 4. Init-Only Property (Opsional)
    // Tidak wajib diisi. Jika diisi saat inisialisasi, nilainya terkunci.
    // Jika tidak, menggunakan nilai default (null).
    public string? Bio { get; init; }

    // 5. Full Property dengan Backing Field (Validasi)
    private int _age;
    public int Age
    {
        get => _age;
        set
        {
            if (value < 0 || value > 150)
                throw new ArgumentOutOfRangeException(nameof(value), "Umur tidak valid.");
            _age = value;
        }
    }
}

public class Program
{
    public static void Main()
    {
        // Object Initializer Syntax
        var user = new UserProfile
        {
            Username = "developer_id", // Wajib & Init-only
            Email = "dev@example.com", // Wajib & Mutable
            Bio = "C# Enthusiast",     // Opsional & Init-only
            Age = 25                   // Opsional & Mutable (dengan validasi)
        };

        Console.WriteLine($"User {user.Username} created with ID: {user.Id}");

        // --- Demonstrasi Mutasi ---
        
        user.Email = "new_email@example.com"; // ✅ BERHASIL: Standard setter
        user.Age = 26;                        // ✅ BERHASIL: Standard setter
        
        // user.Username = "new_user";        // ❌ ERROR CS8852: Init-only property tidak bisa diubah setelah inisialisasi.
        // user.Bio = "New Bio";              // ❌ ERROR CS8852: Init-only property.
        // user.Id = Guid.NewGuid();          // ❌ ERROR CS0272: Private setter.

        // --- Demonstrasi Required ---
        
        // var invalidUser = new UserProfile 
        // { 
        //     Username = "test" 
        // }; 
        // ❌ ERROR CS9035: Required member 'Email' harus diinisialisasi.
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (Compiler Magic)**:
  *   *Properties* sebenarnya tidak ada di level CLR (Common Language Runtime). Compiler C# (Roslyn) mengubah properti menjadi dua metode terpisah: `get_PropertyName()` dan `set_PropertyName()`.
  *   Untuk *Auto-Implemented Properties*, compiler secara otomatis men-generate *hidden backing field* (misal: `<Age>k__BackingField`).
  *   **`init` modifier**: Di level IL (Intermediate Language), compiler menandai metode setter dengan `modreq` (modifier required) bernama `IsExternalInit`. Ini memberitahu compiler C# bahwa pemanggilan metode ini hanya diizinkan selama fase *Object Initializer*. Di runtime, ini hanyalah metode setter biasa.
  *   **`required` modifier**: Compiler menambahkan atribut `[RequiredMember]` ke properti tersebut di level IL. Saat objek diinisialisasi menggunakan `new`, compiler memverifikasi apakah semua anggota yang ditandai telah disertakan dalam blok *Object Initializer*.

- **Alokasi Memori / Resource**:
  *   Tidak ada *overhead* memori tambahan untuk *auto-properties* dibandingkan dengan *fields* biasa.
  *   JIT (Just-In-Time) Compiler sangat agresif dalam melakukan *inlining* pada metode getter/setter yang sederhana (seperti auto-properties). Artinya, di level *machine code*, mengakses properti sama cepatnya dengan mengakses *field* secara langsung.

- **Trade-offs**:
  *   Menggunakan `required` menghilangkan kebutuhan akan konstruktor raksasa (Telescoping Constructors), namun memindahkan tanggung jawab validasi kelengkapan data dari runtime ke compile-time via *Object Initializer*.
  *   Jika Anda menggunakan Reflection untuk membuat instance objek, Anda harus berhati-hati karena Reflection bisa mem-bypass aturan `required` jika tidak ditangani secara eksplisit.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  *   **Gunakan `init` untuk DTOs, Records, dan Configuration Classes.** Ini memastikan data yang dikirim antar layer aplikasi bersifat *immutable* dan *thread-safe*.
  *   **Gunakan `required` untuk dependensi atau data wajib** alih-alih membuat konstruktor dengan banyak parameter, terutama pada class yang merepresentasikan entitas database (seperti di Entity Framework Core).
  *   **Gunakan Auto-Properties secara default.** Hanya gunakan *full properties* (dengan *backing field* manual) jika Anda benar-benar membutuhkan logika validasi, *lazy loading*, atau notifikasi perubahan state (seperti `INotifyPropertyChanged`).

- **Don'ts**:
  *   **Jangan letakkan operasi berat (I/O, Database, Network) di dalam Getter/Setter.** Properti diharapkan mengeksekusi kode dengan sangat cepat (O(1)). Jika butuh komputasi berat, gunakan metode (misal: `GetTotalBalance()`).
  *   **Jangan melempar exception sembarangan dari Getter.** Getter harus selalu aman dipanggil. Exception diizinkan di Setter untuk validasi data.

- **Edge Cases**:
  *   **Deserialisasi JSON**: Pustaka modern seperti `System.Text.Json` mendukung penuh `init` dan `required`. Deserializer menggunakan Reflection/Source Generators untuk mem-bypass batasan `init` secara aman saat merekonstruksi objek dari JSON.
  *   **Konstruktor Kustom + Required**: Jika Anda memiliki class dengan properti `required` tetapi Anda *juga* ingin menyediakan konstruktor yang menginisialisasi properti tersebut, Anda harus menambahkan atribut `[SetsRequiredMembers]` pada konstruktor tersebut agar compiler tidak protes.

### 5. Tantangan Eksplorasi Mandiri

1.  Buatlah sebuah class `Product` dengan properti `SKU` yang bersifat `required` dan `init`, serta properti `Price` yang memiliki validasi tidak boleh negatif di dalam setter-nya.
2.  Gunakan *tool* seperti [SharpLab.io](https://sharplab.io/) untuk menulis class dengan properti `init` dan `required`. Inspeksi hasil dekompilasi C# (Lowered C#) dan kode IL-nya untuk melihat bagaimana compiler men-generate *backing fields* dan atribut `IsExternalInit` / `RequiredMember`.
3.  Cobalah melakukan serialisasi dan deserialisasi JSON menggunakan `System.Text.Json` pada class yang memiliki properti `required` dan `init`. Amati apakah proses deserialisasi berhasil tanpa *Object Initializer* eksplisit di kode Anda.
