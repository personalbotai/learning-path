## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Sebelum C# 12, ekosistem .NET mengalami fragmentasi sintaksis saat menginisialisasi koleksi. Developer harus menghafal dan menggunakan idiom yang berbeda-beda tergantung tipe data dan optimasi performa yang ditargetkan:

```csharp
int[] array = new int[] { 1, 2, 3 };
List<int> list = new() { 1, 2, 3 };
Span<int> span = stackalloc int[] { 1, 2, 3 };
ImmutableArray<int> immutable = ImmutableArray.Create(1, 2, 3);
```

**Collection Expressions** (C# 12 / .NET 8) memecahkan masalah ini dengan memperkenalkan sintaks seragam berbasis tanda kurung siku siku `[...]` yang bersifat *target-typed*. Compiler menentukan tipe data akhir berdasarkan konteks deklarasi variabel, return type fungsi, atau parameter method.

Fitur pelengkapnya, **Spread Operator (`..`)**, berfungsi membongkar elemen-elemen dari koleksi asal dan menyisipkannya ke dalam koleksi tujuan secara inline. Ini menggantikan operasi imperatif seperti `List<T>.AddRange()`, `LINQ Concat()`, atau chaining method yang memicu alokasi memori redundan.

#### Arsitektur Desain Compiler (Roslyn Lowering)
Compiler tidak sekadar memperlakukan `[...]` sebagai *syntactic sugar* untuk memanggil konstruktor biasa atau metode `.Add()`. Alih-alih:
1. **Capacity Pre-computation**: Jika tipe-tipe dalam *spread operator* memiliki properti penghitung yang diketahui (`Length`, `Count`, atau mengimplementasikan `ICollection<T>`), Roslyn menghitung total kapasitas di awal untuk mengeliminasi alokasi ulang (*resize buffer*) internal array/list.
2. **Zero-Allocation Memory Mapping**: Untuk target `ReadOnlySpan<T>` atau `Span<T>` yang berisi tipe primitif konstan, compiler memetakan data langsung ke segmen *Read-Only Data* (`.rodata` / RVA section) dari file PE/assembly, meniadakan alokasi heap sama sekali.
3. **Pola Ekstensibilitas (`[CollectionBuilder]` Attribute)**: Tipe koleksi kustom dapat mendukung sintaks ini dengan menandai kelas menggunakan atribut `CollectionBuilderAttribute` yang mengarah ke metode pembuat pabrik (*builder method*).

### 2. Implementasi & Contoh Kasus Nyata

Contoh implementasi komprehensif berikut mendemonstrasikan fleksibilitas sintaks, penggabungan koleksi heterogen menggunakan Spread Operator, serta integrasi dengan tipe kustom:

```csharp
using System;
using System.Collections.Generic;
using System.Collections.Immutable;
using System.Runtime.CompilerServices;

namespace AdvancedCollections;

public class Program
{
    public static void Main()
    {
        // 1. Target typing ke berbagai struktur data dasar
        int[] numbersArray = [1, 2, 3];
        List<int> numbersList = [4, 5, 6];
        
        // Zero-allocation: Mengacu langsung ke data section assembly
        ReadOnlySpan<int> spanBuffer = [7, 8, 9];

        // 2. Evaluasi Spread Operator [..items] dengan optimasi kapasitas
        // Compiler mengekstrak panjang dari numbersArray, numbersList, dan spanBuffer
        // lalu menginisialisasi List dengan Capacity = 3 + 3 + 3 + 2 = 11.
        List<int> consolidated = [0, ..numbersArray, ..numbersList, ..spanBuffer, 10];

        Console.WriteLine($"Total elemen: {consolidated.Count}"); // Output: 11
        Console.WriteLine(string.Join(", ", consolidated));

        // 3. Immutable collection parsing
        ImmutableArray<string> defaultHeaders = ["Content-Type", "Accept"];
        ImmutableArray<string> customHeaders = ["X-Request-ID", "Authorization"];
        ImmutableArray<string> allHeaders = [..defaultHeaders, ..customHeaders, "Trace-Parent"];

        // 4. Penggunaan pada Custom Type via [CollectionBuilder]
        PacketBatch batch = [100, 200, 300];
        Console.WriteLine($"Custom Batch Size: {batch.Count}");
    }
}

// -------------------------------------------------------------
// Arsitektur Custom Collection yang mendukung Collection Expression
// -------------------------------------------------------------
[CollectionBuilder(typeof(PacketBatchBuilder), nameof(PacketBatchBuilder.Create))]
public sealed class PacketBatch : IEnumerable<int>
{
    private readonly int[] _data;

    public PacketBatch(ReadOnlySpan<int> items)
    {
        _data = items.ToArray(); // Menyalin state
    }

    public int Count => _data.Length;
    public IEnumerator<int> GetEnumerator() => ((IEnumerable<int>)_data).GetEnumerator();
    System.Collections.IEnumerator System.Collections.IEnumerable.GetEnumerator() => GetEnumerator();
}

public static class PacketBatchBuilder
{
    // Compiler secara otomatis memanggil method ini saat PacketBatch diinisialisasi via [...]
    public static PacketBatch Create(ReadOnlySpan<int> values)
    {
        return new PacketBatch(values);
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime Lowering
Saat kode di-compile, Roslyn menerjemahkan sintaks ini ke pola IL (*Intermediate Language*) yang paling optimal:
- Jika target berupa `ReadOnlySpan<byte>` atau tipe primitif blittable lainnya:
  ```csharp
  ReadOnlySpan<byte> bytes = [0x01, 0x02, 0x03];
  ```
  Compiler *menurunkan* (lowering) kode tersebut menjadi:
  ```csharp
  ReadOnlySpan<byte> bytes = RuntimeHelpers.CreateSpan(
      __StaticArrayInitTypeSize=3(...) /* Pointer RVA Metadata */
  );
  ```
  Tidak ada objek array yang diinstansiasi di managed heap (`new byte[]` tidak dipanggil).

- Jika menggunakan Spread Operator:
  Compiler melakukan inspeksi runtime/compile-time terhadap *source* operand:
  - Jika tipe mengimplementasikan `ICollection<T>`: Panjang koleksi dibaca via `.Count`.
  - Jika struct mendukung indexing dan `.Length`: Compiler memakai blok `Span<T>.CopyTo` atau memory blitting via unmanaged instructions.
  - Jika hanya berupa `IEnumerable<T>` murni (non-counted): Compiler membuat builder dinamis berbasis `Pooling/Resizing` internal buffer yang mirip dengan `List<T>`, lalu memindahkan referensinya ke tipe akhir.

#### Alokasi Memori / Resource
- **Legacy LINQ (`Concat().ToList()`):** Memerlukan alokasi iterator object (`ConcatIterator`), beberapa interface method dispatch (`IEnumerable.MoveNext`), dan dynamic resize buffer (array doubling: 4 -> 8 -> 16).
- **Collection Expression:** Menghilangkan overhead iterator. Mengalokasikan array tujuan dengan kapasitas pasti di awal, kemudian melakukan direct-indexed copy atau block-copy via vectorized memory movement jika tipe data kompatibel.

#### Trade-offs
- **Binary Size vs Memory:** Inisialisasi collection expression berukuran masif yang dimasukkan ke inline stack/span dapat meningkatkan ukuran biner assembly (.dll) karena compiler menyematkan blob *raw bytes* langsung pada segment PE.
- **Syntactic Ambiguity:** Jika sebuah method memiliki overload `Method(int[])`, `Method(List<int>)`, dan `Method(ReadOnlySpan<int>)`, pemanggilan `Method([1, 2])` menimbulkan kompilasi ambigu kecuali type hint diberikan secara eksplisit.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Targetkan `ReadOnlySpan<T>` pada Read-Only Hot Paths**: Gunakan `ReadOnlySpan<T> buffer = [...]` alih-alih `new[]` saat membaca rangkaian data konstan di dalam loop berintensitas tinggi untuk mengeliminasi GC pressure.
- **Manfaatkan Target-Typing Function Return**: Gunakan ekspresi `return [];` untuk mengembalikan koleksi kosong daripada `new List<T>()` atau `Array.Empty<T>()` guna menyederhanakan kode.

#### Don'ts
- **Hindari Spread Operator pada Non-Materialized Deferred Queries**: Jangan melakukan `[..queryable]` langsung pada EF Core `IQueryable` atau infinite stream. Hal ini memaksa evaluasi enumerator terjadi seketika, berpotensi memicu query N+1 atau *Out of Memory* jika sequence tidak terbatas.
- **Jangan Mengabaikan Evaluasi Ganda**: Menyebarkan ekspresi yang memiliki *side-effects* (misalnya: `[..GenerateTokens()]`) dapat berbahaya jika generator membaca dari stream I/O yang *forward-only*.

#### Edge Cases
- **Null Safety pada Spread:**
  ```csharp
  IEnumerable<int>? source = null;
  List<int> result = [..source]; // Melempar ArgumentNullException / NullReferenceException saat runtime.
  ```
  Jika koleksi operand berpotensi `null`, lakukan defensive guard atau coalescing: `[..(source ?? [])]`.
