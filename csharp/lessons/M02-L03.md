### 1. Konsep & Arsitektur Mendalam

Inheritance (pewarisan) dalam C# adalah mekanisme yang memungkinkan suatu tipe (*derived class*) mengadopsi struktur data (field/property) dan perilaku (method) dari tipe lain (*base class*). C# mengadopsi model *single class inheritance*—sebuah kelas hanya dapat mewarisi langsung dari tepat satu kelas dasar, meskipun dapat mengimplementasikan banyak *interface*.

Di level arsitektur dan sistem tipe, pewarisan menyediakan landasan bagi **Subtyping Polymorphism**: kemampuan memperlakukan instansi dari tipe turunan sebagai instansi dari tipe dasarnya tanpa kehilangan perilaku spesifik tipe turunan tersebut.

```
┌────────────────────────────────────────────────────────┐
│                   Abstract Class                       │
│  - Partial implementation                              │
│  - Memaksa kontrak via 'abstract'                      │
│  - Menyediakan default behavior via 'virtual'          │
└───────────────────────────┬────────────────────────────┘
                            │ extends
         ┌──────────────────┴──────────────────┐
         ▼                                     ▼
┌──────────────────┐                  ┌──────────────────┐
│  Concrete Class  │                  │  Concrete Class  │
│  - 'override'    │                  │  - 'override'    │
│  - 'sealed'      │                  │  - 'sealed'      │
└──────────────────┘                  └──────────────────┘
```

#### Komponen Utama Polimorfisme C#
1. **Abstract Class & Members**:
   - `abstract class`: Kelas yang tidak dapat diinstansiasi secara langsung (`new Base()` ilegal). Berfungsi sebagai blueprint hierarkis yang menggabungkan deklarasi kontrak dan implementasi parsial.
   - `abstract member`: Method, property, event, atau indexer tanpa implementasi di base class. Mengharuskan kelas turunan konkret pertama untuk mengimplementasikannya via keyword `override`.
2. **Virtual vs. Override**:
   - `virtual`: Menandai method di base class bahwa resolusi pemanggilan method tersebut ditunda hingga runtime (*dynamic dispatch*). Method ini memiliki implementasi bawaan.
   - `override`: Menyediakan implementasi baru yang terdaftar ke dalam *Virtual Method Table* (vtable). Menggantikan slot vtable yang didefinisikan oleh keyword `virtual` atau `abstract`.
3. **Method Shadowing/Hiding (`new`)**:
   - Keyword `new` memutuskan rantai polimorfisme. Method bertanda `new` membuat slot baru di vtable dan menyembunyikan implementasi base class. Pemanggilan via pointer base class akan tetap mengeksekusi method base, bukan method derived.
4. **Sealed Modifier**:
   - Diterapkan pada kelas untuk mencegah pewarisan (`sealed class`), atau pada method override untuk menghentikan modifikasi rantai polimorfisme lebih lanjut oleh derived class di bawahnya (`sealed override`).

### 2. Implementasi & Contoh Kasus Nyata

Skenario: Pemrosesan transaksi finansial di gateway pembayaran. Base class memegang alur orkestrasi (*Template Method Pattern*), validasi umum, dan audit logging, sedangkan kelas turunan mengimplementasikan logika spesifik tiap channel.

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

// 1. Abstract Base Class
public abstract class PaymentProcessor
{
    public string ProcessorId { get; }

    protected PaymentProcessor(string processorId)
    {
        ProcessorId = processorId ?? throw new ArgumentNullException(nameof(processorId));
    }

    // Template Method: Menentukan alur eksekusi pasti
    public async Task<PaymentResult> ProcessAsync(PaymentRequest request, CancellationToken ct = default)
    {
        ArgumentNullException.ThrowIfNull(request);

        Console.WriteLine($"[{ProcessorId}] Memulai validasi transaksi {request.TransactionId}...");
        ValidateRequest(request);

        Console.WriteLine($"[{ProcessorId}] Melakukan autentikasi gateway...");
        await AuthenticateGatewayAsync(ct);

        Console.WriteLine($"[{ProcessorId}] Mengeksekusi transfer payload...");
        var rawResponse = await ExecuteTransactionCoreAsync(request, ct);

        // Virtual hook: Memberikan celah kustomisasi opsional bagi derived class
        OnTransactionCompleted(request, rawResponse);

        return rawResponse;
    }

    // Abstract Member: Wajib diimplementasikan oleh derived class
    protected abstract Task<PaymentResult> ExecuteTransactionCoreAsync(PaymentRequest request, CancellationToken ct);

    // Abstract Member berupa Property
    public abstract decimal MaximumTransactionLimit { get; }

    // Virtual Member: Memiliki default implementation, bisa di-override
    protected virtual void ValidateRequest(PaymentRequest request)
    {
        if (request.Amount <= 0)
            throw new ArgumentOutOfRangeException(nameof(request.Amount), "Nominal transaksi harus > 0");

        if (request.Amount > MaximumTransactionLimit)
            throw new InvalidOperationException($"Nominal melebihi limit {MaximumTransactionLimit}");
    }

    // Virtual Hook: Default no-op (kosong)
    protected virtual void OnTransactionCompleted(PaymentRequest request, PaymentResult result)
    {
        // Default telemetry / metric capture
    }

    private static Task AuthenticateGatewayAsync(CancellationToken ct)
    {
        // Internal infrastructure pipeline
        return Task.CompletedTask;
    }
}

// 2. Concrete Implementation 1: Credit Card
public sealed class CreditCardPaymentProcessor : PaymentProcessor
{
    public override decimal MaximumTransactionLimit => 50_000_000m;

    public CreditCardPaymentProcessor() : base("CC-GATEWAY-V1") { }

    protected override async Task<PaymentResult> ExecuteTransactionCoreAsync(PaymentRequest request, CancellationToken ct)
    {
        // Simulasi network I/O
        await Task.Delay(50, ct);
        return new PaymentResult(true, Guid.NewGuid().ToString("N"));
    }

    // Mengubah default validation logic
    protected override void ValidateRequest(PaymentRequest request)
    {
        base.ValidateRequest(request); // Tetap jalankan validasi standar

        if (string.IsNullOrWhiteSpace(request.Payload))
            throw new ArgumentException("Payload kartu kredit tidak valid", nameof(request));
    }

    protected override void OnTransactionCompleted(PaymentRequest request, PaymentResult result)
    {
        Console.WriteLine($"[Audit Log] Transaksi CC {request.TransactionId} Sukses: {result.ExternalReference}");
    }
}

// 3. Concrete Implementation 2: Crypto (Inheritance & Shadowing demonstration)
public class CryptoPaymentProcessor : PaymentProcessor
{
    public override decimal MaximumTransactionLimit => 1_000_000_000m;

    public CryptoPaymentProcessor() : base("CRYPTO-NODE-RPC") { }

    // Mengunci implementasi ini agar tidak bisa diubah oleh turunan CryptoPaymentProcessor berikutnya
    protected sealed override async Task<PaymentResult> ExecuteTransactionCoreAsync(PaymentRequest request, CancellationToken ct)
    {
        await Task.Delay(100, ct);
        return new PaymentResult(true, "0x" + Guid.NewGuid().ToString("N"));
    }
}

// Model Records
public record PaymentRequest(Guid TransactionId, decimal Amount, string Payload);
public record PaymentResult(bool IsSuccess, string ExternalReference);

// Execution Entry Point
public static class Program
{
    public static async Task Main()
    {
        // Polimorfisme: Variabel PaymentProcessor mereferensikan instansi konkret yang berbeda
        PaymentProcessor processor = new CreditCardPaymentProcessor();
        
        var request = new PaymentRequest(Guid.NewGuid(), 15_000_000m, "ENC_DATA_TOKEN_XYZ");
        PaymentResult result = await processor.ProcessAsync(request);

        Console.WriteLine($"Status: {result.IsSuccess}, Ref: {result.ExternalReference}");
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: IL Dispatch (`call` vs `callvirt`)
Ketika C# dikompilasi ke Intermediate Language (IL), pemanggilan method diterjemahkan ke dua instruksi utama:
- `call`: Melakukan resolusi method secara **statis** pada waktu kompilasi berdasarkan tipe referensi yang terlihat. Digunakan untuk static method, struct methods, private methods, atau pemanggilan eksplisit via keyword `base.Method()`.
- `callvirt`: Melakukan resolusi method secara **dinamis** pada waktu runtime (*late binding*). Instruksi ini memeriksa apakah pointer instansi bernilai `null` (melempar `NullReferenceException` jika null), membaca *MethodTable* dari objek, lalu mengekstrak pointer fungsi yang sesuai.

> **Catatan Kompiler**: C# compiler sering memancarkan `callvirt` bahkan untuk method non-virtual non-static semata-mata untuk mendapatkan pemeriksaan null pointer gratis secara native via proteksi hardware paging.

#### Virtual Method Table (vtable) & Memory Layout
Setiap objek class di managed heap memiliki layout memori internal:
1. **Object Header** (4 byte di x86, 8 byte di x64): Digunakan untuk sync-block (locking), hash-code caching.
2. **TypeHandle / MethodTable Pointer** (4 byte di x86, 8 byte di x64): Pointer langsung ke struktur `MethodTable` milik runtime untuk tipe tersebut.
3. **Data Fields**: Field instance dari base class diletakkan terlebih dahulu, diikuti oleh field instance derived class (memory alignment / padding otomatis berlaku).

```
Object Instance di Heap (x64):
┌─────────────────────────────────┐
│ Sync Block Index       (8 bytes)│
├─────────────────────────────────┤
│ MethodTable Pointer    (8 bytes)│ ───► MethodTable (EEType di CoreCLR)
├─────────────────────────────────┤      ┌─────────────────────────────┐
│ Base Class Fields               │      │ ... metadata tipe           │
├─────────────────────────────────┤      ├─────────────────────────────┤
│ Derived Class Fields            │      │ vtable slot [0]: Object.ToString
└─────────────────────────────────┘      │ vtable slot [1]: Object.Equals
                                         │ vtable slot [2]: Base.ExecuteTransactionCoreAsync
                                         │   └─► Pointer ke mesin CreditCard.ExecuteTransactionCoreAsync()
                                         └─────────────────────────────┘
```

Jika method di-`override`, CLR menimpa entri slot vtable yang diturunkan dari base class dengan pointer ke instruksi derived class. Jika menggunakan `new` (shadowing), runtime membuat slot baru terpisah di akhir tabel; slot base class lama tetap utuh.

#### Trade-offs & Overhead Performa
1. **Devirtualization Failure**: Pemanggilan `virtual` menghalangi JIT compiler untuk melakukan *inlining* jika JIT tidak dapat membuktikan tipe konkret objek secara mutlak (*Guarded Devirtualization*).
2. **CPU Cache Miss**: Pemanggilan virtual melibatkan dereferensi memori tak langsung: `Object Ref -> MethodTable -> vtable Slot -> Native Instructions`. Ini berisiko memicu branch misprediction pada CPU pipeline.
3. **Memory Footprint**: `MethodTable` memakan alokasi unmanaged memory per tipe, dan pointer `TypeHandle` menambahkan 8 byte overhead pada setiap instansi objek.

### 4. Best Practices & Common Pitfalls

#### Do's
- **Terapkan Liskov Substitution Principle (LSP)**: Kelas turunan harus dapat menggantikan kelas dasar tanpa merusak invariant atau ekspektasi caller. Jika turunan melempar `NotImplementedException` pada method override, abstraksi tersebut cacat.
- **Tandai class turunan akhir sebagai `sealed`**: Menerapkan `sealed` pada concrete class memungkinkan JIT melakukan *Devirtualization* dan *Inlining* secara agresif karena JIT tahu pasti tidak ada kelas lain yang meng-override-nya.
- **Gunakan pola Non-Virtual Interface (NVI)**: Buat method publik non-virtual yang menjadi gerbang utama, dan delegasikan variasi logika ke method `protected abstract` atau `protected virtual` (seperti `ProcessAsync` dan `ExecuteTransactionCoreAsync` pada contoh kode).

#### Don'ts
- **DILARANG memangil Virtual Members di dalam Constructor**:
  Ini adalah sumber bug fatal di C#. Ketika constructor base class berjalan, constructor derived class **belum dieksekusi** dan field-field derived class belum terinisialisasi.
  ```csharp
  // JANGAN LAKUKAN INI
  public abstract class BadBase
  {
      protected BadBase()
      {
          Init(); // BAHAYA: Pemanggilan virtual method di ctor
      }
      protected virtual void Init() { }
  }

  public class BrokenDerived : BadBase
  {
      private readonly string _state;

      public BrokenDerived()
      {
          _state = "Initialized";
      }

      protected override void Init()
      {
          // Crash atau bug: _state bernilai NULL di sini karena ctor derived belum dipanggil!
          Console.WriteLine(_state.Length); 
      }
  }
  ```
- **Hindari penggunaan keyword `new` untuk method hiding**: Hampir selalu merupakan indikasi kesalahan desain. Shadowing membingungkan caller karena perilakunya berubah bergantung pada tipe variabel pointer yang digunakan.
- **Jangan mewariskan class hanya demi reuse field/kode**: Gunakan komposisi (*Composition over Inheritance*). Pewarisan menciptakan coupling ketat (*Fragile Base Class problem*).

#### Edge Cases
- **Override property behavior**: Menimpa getter/setter dapat memutus thread safety atau state encapsulation dari base class jika `base.Property` tidak diakses dengan benar.
- **Kombinasi `new virtual`**: Diperbolehkan oleh sintaks untuk memulai rantai hierarki vtable baru, namun pola ini anti-pattern di level enterprise dan menyulitkan runtime tracking via reflection.

### 5. Tantangan Eksplorasi Mandiri

1. **Investigasi IL & Devirtualization**:
   Salin contoh kode implementasi ke [SharpLab.io](https://sharplab.io). Ubah target compiler dari Debug ke Release dengan optimasi JIT aktif. Bandingkan instruksi IL antara method yang memanggil method langsung, method bertanda `virtual`, dan pemanggilan method pada class bertanda `sealed`. Amati di mana instruksi `callvirt` digantikan oleh instruksi `call` atau di-*inline* seluruhnya.
2. **Simulasi Polimorfisme vs Shadowing**:
   Buat kelas `BaseWorker`, `VirtualChild` (menggunakan `override`), dan `ShadowChild` (menggunakan `new`). Masukkan ketiganya ke dalam `List<BaseWorker>` dan iterasi pemanggilan method-nya. Jelaskan mengapa output dari `ShadowChild` memanggil method base alih-alih method turunannya.
3. **Reproduksi Runtime Bug Konstruktor**:
   Implementasikan skenario *Virtual Call in Constructor* di atas menggunakan tipe non-nullable reference type (`string _state`). Amati bagaimana compiler C# dengan nullable reference type (`<Nullable>enable</Nullable>`) gagal mendeteksi dereferensi null pada runtime karena bug urutan inisialisasi vtable ini.
