### 1. Konsep & Arsitektur Mendalam

Class di C# adalah *reference type* yang dialokasikan pada *managed heap*, di mana variabel hanya menyimpan referensi (pointer) ke lokasi memori objek tersebut. Sejak C# 1.0, instansiasi kelas diatur oleh konstruktor instans (`.ctor` pada level Common Intermediate Language / CIL). Konstruktor bertugas mengalokasikan state awal sebelum referensi objek dikembalikan ke pemanggil.

Sebelum C# 12, *boilerplate code* menjadi masalah utama: developer harus mendeklarasikan *backing field*, menerima parameter pada konstruktor, dan memetakan parameter tersebut secara manual satu per satu ke dalam *field* (`this._field = field;`). Pola ini redundan, khususnya pada arsitektur modern yang mengandalkan *Dependency Injection* (DI).

```
// Evolusi Deklarasi State & Konstruktor
C# 1.0 - 11:
Class Declaration -> Field Declaration -> Constructor Signature -> Field Assignment

C# 12 (Primary Constructors):
Class Declaration + Constructor Signature -> Direct Parameter Scoping across Class Body
```

C# 12 memperkenalkan **Primary Constructors** untuk kelas dan *struct* standar (fitur yang sebelumnya eksklusif untuk `record` pada C# 9). Perbedaan fundamental antara Primary Constructor pada `record` dan `class`:
1. **Pada `record`**: Kompiler secara otomatis men-generate *public init-only property* dengan nama yang sama secara implisit (posisional).
2. **Pada `class`**: Kompiler **tidak** membuat *property* publik secara implisit. Parameter Primary Constructor berada dalam *scope* seluruh *body* kelas dan hanya diperlakukan sebagai parameter konstruktor yang dapat "ditangkap" (*captured*) jika diakses di luar inisialisasi awal.

### 2. Implementasi & Contoh Kasus Nyata

Berikut implementasi *service layer* pemrosesan transaksi yang mengombinasikan *Primary Constructors*, validasi, *explicit field initialization*, dan *secondary constructors*.

```csharp
using System;

namespace Enterprise.Billing;

public interface ICurrencyExchangeService
{
    decimal GetRate(string from, string to);
}

public interface IAuditLogger
{
    void Log(string message);
}

// 1. Deklarasi Class dengan Primary Constructor (C# 12)
public class PaymentProcessor(
    ICurrencyExchangeService exchangeService, 
    IAuditLogger logger, 
    string defaultCurrency)
{
    // Validasi saat instansiasi menggunakan field initializer
    private readonly string _defaultCurrency = defaultCurrency 
        ?? throw new ArgumentNullException(nameof(defaultCurrency));

    // Property yang diinisialisasi langsung dari parameter primary constructor
    public DateTime InitializedAt { get; } = DateTime.UtcNow;

    // 2. Secondary Constructor: WAJIB memanggil Primary Constructor via ': this(...)'
    public PaymentProcessor(ICurrencyExchangeService exchangeService, IAuditLogger logger) 
        : this(exchangeService, logger, "USD")
    {
    }

    public decimal ProcessPayment(decimal amount, string sourceCurrency)
    {
        // Parameter 'logger' dan 'exchangeService' dicapture secara otomatis
        logger.Log($"Processing {amount} {sourceCurrency} to {_defaultCurrency}");

        if (sourceCurrency.Equals(_defaultCurrency, StringComparison.OrdinalIgnoreCase))
        {
            return amount;
        }

        decimal rate = exchangeService.GetRate(sourceCurrency, _defaultCurrency);
        decimal finalAmount = amount * rate;

        logger.Log($"Conversion applied at rate {rate}. Final: {finalAmount}");
        return finalAmount;
    }
}

public class Program
{
    public static void Main()
    {
        // Mock implementasi manual untuk runnable demo
        var exchange = new DummyExchange();
        var logger = new ConsoleLogger();

        // Menggunakan Primary Constructor
        var processor = new PaymentProcessor(exchange, logger, "IDR");
        processor.ProcessPayment(100, "USD");

        // Menggunakan Secondary Constructor
        var fallbackProcessor = new PaymentProcessor(exchange, logger);
        fallbackProcessor.ProcessPayment(50, "EUR");
    }
}

public class DummyExchange : ICurrencyExchangeService
{
    public decimal GetRate(string from, string to) => 15500m;
}

public class ConsoleLogger : IAuditLogger
{
    public void Log(string message) => Console.WriteLine($"[AUDIT] {message}");
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (Compiler Lowering)
Kompiler Roslyn tidak memodifikasi CLR untuk mendukung Primary Constructors pada kelas. Sebaliknya, Roslyn melakukan *lowering* ke CIL standar:
1. **Jika parameter HANYA digunakan untuk menginisialisasi field atau base class:**
   Parameter hanya hidup selama eksekusi `.ctor`. Tidak ada alokasi field tambahan.
2. **Jika parameter digunakan di dalam *method body* (seperti `logger` dan `exchangeService` pada contoh di atas):**
   Kompiler secara otomatis menghasilkan *private backing field* tersembunyi dengan nama *mangled* (misalnya `<exchangeService>P`). Setiap akses parameter di dalam method akan dialihkan ke field privat ini.

#### Alokasi Memori / Resource
* **Object Overhead**: Setiap instans kelas memiliki alokasi memori heap minimum:
  * 64-bit platform: *Object Header* (8 bytes) + *MethodTable Pointer* / Type Handle (8 bytes).
* **State Bloat**: Jika Anda tidak sengaja mereferensikan parameter Primary Constructor di dalam method, ukurannya bertambah sesuai tipe data pointer/value type yang di-*capture*.
* **Semantik Mutabilitas**: Berbeda dari parameter reguler method yang *read-only* setelah eksekusi, parameter yang di-*capture* pada *body* kelas **bersifat mutable** bagi method-method di dalam kelas tersebut, kecuali secara eksplisit dipetakan ke field `readonly`.

#### Trade-offs
* **Keuntungan**: Mengeliminasi hingga 60% boilerplate code pada dependensi injeksi tanpa runtime cost tambahan dibanding pemetaan manual.
* **Kerugian**: Tidak ada modifier `readonly` bawaan pada parameter Primary Constructor. Kompiler memperbolehkan mutasi variabel parameter di dalam method, yang dapat memicu bug *accidental state mutation*.

### 4. Best Practices & Common Pitfalls

#### Do's
* **Gunakan untuk Dependency Injection**: Sangat ideal untuk *services*, *controllers*, dan *handlers* di mana dependensi tidak pernah dimutasi setelah inisialisasi.
* **Gunakan Field Initializer untuk Validasi**: Lakukan validasi `null` atau `range` langsung saat inisialisasi field (misal: `private readonly int _limit = limit > 0 ? limit : throw new ...;`).
* **Wajibkan Base Chaining**: Turunan dari kelas yang memiliki Primary Constructor harus mengoper parameter langsung pada deklarasi inheritance: `public class SpecialProcessor(...) : PaymentProcessor(...)`.

#### Don'ts
* **Jangan Samakan dengan Record**: Jangan mengira Primary Constructor pada `class` membuat *public getter property*. Parameter tersebut tidak dapat diakses dari luar kelas kecuali dideklarasikan secara eksplisit.
* **Hindari Mutasi Parameter**: Hindari menulis logika seperti `logger = new OtherLogger();` di dalam method kelas. Walaupun valid secara kompilasi, ini mengubah *captured field* dan merusak kejelasan state internal.

#### Edge Cases & Pitfalls
* **Double Storage (Penyimpanan Ganda)**:
  ```csharp
  public class BadExample(int id)
  {
      private readonly int _id = id; // Mengonsumsi 4 bytes
      public void Print() => Console.WriteLine(id); // Roslyn menangkap 'id' -> Kompiler membuat field tersembunyi! Total: 8 bytes untuk id.
  }
  ```
  *Solusi*: Jika Anda menyimpannya ke dalam `_id`, gunakan `_id` secara konsisten di seluruh *body* kelas agar Roslyn tidak membuat *backing field* ganda.

* **Eksekusi vs Konstruktor Sekunder**:
  Field initializer dieksekusi **sebelum** body konstruktor dipanggil. Dengan Primary Constructor, inisialisasi field terjadi tepat saat instansi dibuat melalui rantai delegasi Primary Constructor (`: this(...)`).
