### 1. Konsep & Arsitektur Mendalam

Kombinasi **xUnit**, **NSubstitute**, dan **FluentAssertions** merupakan standar de facto modern dalam ekosistem .NET untuk membangun *unit test suite* yang terisolasi, ekspresif, dan memiliki *maintainability* tinggi. Masing-masing pustaka menyelesaikan masalah spesifik dalam piramida pengujian perangkat lunak:

```
+-------------------------------------------------------+
|  FluentAssertions (Assertion Engine & Failure Graph)  |
+-------------------------------------------------------+
|  NSubstitute (Dynamic Test Double / Proxy Generator)  |
+-------------------------------------------------------+
|  xUnit.net (Execution Engine, Discovery & Isolation)  |
+-------------------------------------------------------+
|  .NET Core / CLR Runtime (Reflection & Emit Engine)   |
+-------------------------------------------------------+
```

#### 1. xUnit: Isolation by Design
Berbeda dari pendahulunya seperti NUnit atau MSTest yang menggunakan siklus hidup berbasis atribut kelas tunggal (`[TestFixture]` / `[TestFixtureSetUp]`), xUnit mengadopsi prinsip **Clean Room Execution**:
- **Fresh Instance per Test**: Setiap kali sebuah *test method* (`[Fact]` atau `[Theory]`) dieksekusi, xUnit menginstansiasi ulang kelas pengujian tersebut secara terpisah. Hal ini mengeliminasi *implicit state leakage* antar pengujian.
- **No Test Spills**: Tidak ada atribut `[SetUp]` atau `[TearDown]`. Konstruktor kelas digunakan untuk *Arrange/Setup*, dan `IDisposable` atau `IAsyncLifetime` digunakan untuk pembersihan (*Teardown*).
- **Parallelism**: xUnit secara *default* menjalankan *test classes* yang berbeda dalam *thread* paralel, sementara *test methods* di dalam kelas yang sama dieksekusi secara sekuensial. Pengelompokan paralelisme ini dikontrol melalui konsep `TestCollection`.

#### 2. NSubstitute: Dynamic Proxying Tanpa Lambat Expression Tree
NSubstitute adalah pustaka *mocking* yang dirancang untuk menggantikan pendekatan berbasis ekspresi deklaratif yang berbelit (seperti Moq `mock.Setup(x => x...)`).
- Beroperasi dengan menciptakan *dynamic proxy* dari antarmuka (*interface*) atau *abstract/virtual class*.
- Memanfaatkan sintaks yang *terasa* seperti kode C# biasa (`service.Execute().Returns(...)`).
- Komunikasi dengan objek tiruan direkam langsung di level *interceptor*, meminimalisasi *overhead parsing* ekspresi logika yang kompleks pada saat kompilasi maupun *runtime*.

#### 3. FluentAssertions: Intent-Revealing & Deep Graph Diffing
Assertion bawaan seperti `Assert.Equal(expected, actual)` memiliki kelemahan struktural: parameter mudah tertukar, ekspresi kaku, dan pesan kegagalan (*failure messages*) yang tidak deskriptif saat membandingkan *nested objects*.
- FluentAssertions menggunakan sintaks berbasis *method chaining* (`actual.Should().Be(expected)`).
- Menyediakan mesin rekursif `BeEquivalentTo` yang melakukan *deep object-graph comparison* menggunakan refleksi untuk mengidentifikasi selisih properti terdalam, memotong jejak *debugging* secara signifikan.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah skenario industri nyata: **Pemrosesan Pembayaran dan Pesanan (`OrderProcessingService`)**. Sistem ini bergantung pada gateway eksternal (`IPaymentGateway`), repositori data (`IOrderRepository`), dan layanan notifikasi (`INotificationService`).

#### Kode Domain (System Under Test / SUT)

```csharp
namespace Domain.Orders;

public record OrderItem(Guid ProductId, decimal UnitPrice, int Quantity);

public record Order(Guid Id, Guid CustomerId, List<OrderItem> Items)
{
    public decimal TotalAmount => Items.Sum(i => i.UnitPrice * i.Quantity);
    public OrderStatus Status { get; set; } = OrderStatus.Draft;
}

public enum OrderStatus { Draft, Paid, Failed }

public interface IPaymentGateway
{
    Task<bool> ChargeAsync(Guid customerId, decimal amount, CancellationToken ct = default);
}

public interface IOrderRepository
{
    Task SaveAsync(Order order, CancellationToken ct = default);
}

public interface INotificationService
{
    Task SendInvoiceAsync(Guid customerId, Guid orderId, CancellationToken ct = default);
}

public class OrderProcessingService(
    IPaymentGateway paymentGateway,
    IOrderRepository orderRepository,
    INotificationService notificationService)
{
    public async Task<bool> ProcessOrderAsync(Order order, CancellationToken ct = default)
    {
        ArgumentNullException.ThrowIfNull(order);

        if (order.Items.Count == 0)
            throw new InvalidOperationException("Pesanan tidak memiliki item.");

        bool paymentSuccess = await paymentGateway.ChargeAsync(order.CustomerId, order.TotalAmount, ct);

        if (!paymentSuccess)
        {
            order.Status = OrderStatus.Failed;
            await orderRepository.SaveAsync(order, ct);
            return false;
        }

        order.Status = OrderStatus.Paid;
        await orderRepository.SaveAsync(order, ct);
        await notificationService.SendInvoiceAsync(order.CustomerId, order.Id, ct);
        
        return true;
    }
}
```

#### Unit Test Suite (xUnit + NSubstitute + FluentAssertions)

```csharp
namespace Domain.Orders.Tests;

using Xunit;
using NSubstitute;
using NSubstitute.ExceptionExtensions;
using FluentAssertions;

public sealed class OrderProcessingServiceTests : IAsyncDisposable
{
    // Dependensi yang di-mock
    private readonly IPaymentGateway _paymentGateway = Substitute.For<IPaymentGateway>();
    private readonly IOrderRepository _orderRepository = Substitute.For<IOrderRepository>();
    private readonly INotificationService _notificationService = Substitute.For<INotificationService>();
    
    // System Under Test (SUT)
    private readonly OrderProcessingService _sut;

    public OrderProcessingServiceTests()
    {
        // Instansiasi SUT di constructor menjamin objek fresh untuk setiap test method
        _sut = new OrderProcessingService(_paymentGateway, _orderRepository, _notificationService);
    }

    [Fact]
    public async Task ProcessOrderAsync_WhenPaymentSucceeds_ShouldUpdateStatusSaveAndNotify()
    {
        // Arrange
        var customerId = Guid.NewGuid();
        var order = new Order(Guid.NewGuid(), customerId, new()
        {
            new OrderItem(Guid.NewGuid(), UnitPrice: 50_000m, Quantity: 2) // Total: 100,000
        });

        _paymentGateway
            .ChargeAsync(customerId, 100_000m, Arg.Any<CancellationToken>())
            .Returns(Task.FromResult(true));

        // Act
        bool result = await _sut.ProcessOrderAsync(order);

        // Assert (FluentAssertions)
        result.Should().BeTrue();
        order.Status.Should().Be(OrderStatus.Paid);

        // Assert Side-effects (NSubstitute verification)
        await _orderRepository.Received(1)
            .SaveAsync(Arg.Is<Order>(o => o.Id == order.Id && o.Status == OrderStatus.Paid), Arg.Any<CancellationToken>());

        await _notificationService.Received(1)
            .SendInvoiceAsync(customerId, order.Id, Arg.Any<CancellationToken>());
    }

    [Fact]
    public async Task ProcessOrderAsync_WhenPaymentFails_ShouldMarkAsFailedAndNotNotify()
    {
        // Arrange
        var customerId = Guid.NewGuid();
        var order = new Order(Guid.NewGuid(), customerId, new()
        {
            new OrderItem(Guid.NewGuid(), UnitPrice: 200_000m, Quantity: 1)
        });

        _paymentGateway
            .ChargeAsync(customerId, 200_000m, Arg.Any<CancellationToken>())
            .Returns(false); // NSubstitute otomatis meng-wrap value ke Task<bool>

        // Act
        bool result = await _sut.ProcessOrderAsync(order);

        // Assert
        result.Should().BeFalse();
        order.Status.Should().Be(OrderStatus.Failed);

        await _orderRepository.Received(1).SaveAsync(order, Arg.Any<CancellationToken>());
        
        // Memastikan tidak ada pengiriman invoice
        await _notificationService.DidNotReceive()
            .SendInvoiceAsync(Arg.Any<Guid>(), Arg.Any<Guid>(), Arg.Any<CancellationToken>());
    }

    [Theory]
    [InlineData(0)]
    public async Task ProcessOrderAsync_WhenNoItems_ThrowsInvalidOperationException(int itemCount)
    {
        // Arrange
        var emptyOrder = new Order(Guid.NewGuid(), Guid.NewGuid(), new());

        // Act
        Func<Task> act = async () => await _sut.ProcessOrderAsync(emptyOrder);

        // Assert (Deep exception assertion)
        await act.Should().ThrowExactlyAsync<InvalidOperationException>()
            .WithMessage("Pesanan tidak memiliki item.");

        // Memastikan tidak ada dependency yang dipanggil
        await _paymentGateway.DidNotReceiveWithAnyArgs().ChargeAsync(default, default);
    }

    [Fact]
    public async Task ProcessOrderAsync_WhenGatewayThrows_PropagatesExceptionWithoutSaving()
    {
        // Arrange
        var order = new Order(Guid.NewGuid(), Guid.NewGuid(), new()
        {
            new OrderItem(Guid.NewGuid(), 10_000m, 1)
        });

        _paymentGateway
            .ChargeAsync(Arg.Any<Guid>(), Arg.Any<decimal>(), Arg.Any<CancellationToken>())
            .ThrowsAsync(new HttpRequestException("Gateway Timeout"));

        // Act
        Func<Task> act = async () => await _sut.ProcessOrderAsync(order);

        // Assert
        await act.Should().ThrowAsync<HttpRequestException>()
            .WithMessage("Gateway Timeout");

        await _orderRepository.DidNotReceiveWithAnyArgs().SaveAsync(Arg.Any<Order>());
    }

    public async ValueTask DisposeAsync()
    {
        // Teardown async jika ada file descriptor, DbContext in-memory, dsb.
        await Task.CompletedTask;
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime (xUnit Engine)
1. **Discovery Phase**: xUnit me-*load* assembly pengujian menggunakan `Cecil` atau CLR Reflection API. Atribut `[Fact]` dan `[Theory]` didaftarkan ke dalam representasi `ITestCase`.
2. **Parallel Scheduling**: xUnit memecah *Test Cases* ke dalam *Execution Buckets* berdasarkan `TestCollection`. Secara bawaan, satu kelas adalah satu koleksi. Tiap *collection* dikirimkan ke `TaskScheduler` terpisah untuk eksekusi berbasis *thread-pool*.
3. **Activation Lifecycle**: Untuk setiap *test method*, pemanggilan internalnya setara dengan:
   ```csharp
   var testInstance = new OrderProcessingServiceTests(); // Arrange/Setup
   try {
       await testInstance.TestMethodAsync();             // Act & Assert
   } finally {
       if (testInstance is IAsyncDisposable asyncDisp)
           await asyncDisp.DisposeAsync();               // Teardown
       else if (testInstance is IDisposable disp)
           disp.Dispose();
   }
   ```

#### Proxy Generation (NSubstitute & Castle DynamicProxy)
NSubstitute tidak memodifikasi *IL code* assembly target secara statis. NSubstitute menggunakan **Castle.Core (DynamicProxy)**:
- Saat `Substitute.For<IPaymentGateway>()` dipanggil, DynamicProxy menggunakan `System.Reflection.Emit` untuk men-generasi sebuah kelas baru secara dinamis di memory (biasanya diberi nama seperti `ProxyInterface_PaymentGateway_...`).
- Kelas tersebut mengimplementasikan `IPaymentGateway` dan mengarahkan setiap pemanggilan *method* ke sebuah *Call Router* internal.
- Setiap pemanggilan yang di-*intercept* dialokasikan ke dalam koleksi internal untuk melacak metrik (jumlah pemanggilan, argumen yang di-*pass*).
- **Virtual/Interface Restriction**: Proxy generator tidak bisa meng-intercept *non-virtual methods* atau *sealed classes*. Pemanggilan non-virtual method akan bypass interceptor dan menjalankan implementasi riil secara langsung.

#### Object Graph Assertion (FluentAssertions)
Saat mengevaluasi assertions berbasis struktur objek (`BeEquivalentTo`):
- FluentAssertions melakukan traversal *breadth-first* atau *depth-first* terhadap *property tree* dari objek ekspektasi dan aktual melalui refleksi.
- Algoritma mendeteksi siklus (*cyclic dependencies*) menggunakan tabel `ReferenceEqualityComparer` untuk mencegah *StackOverflowException*.
- Menghasilkan representasi pohon perbedaan (*diff tree*) dalam `StringBuilder` yang kaya format, hanya jika verifikasi bernilai `false`.

#### Alokasi Memori & CPU Trade-offs
| Aspek | Mekanisme | Dampak Performa |
| :--- | :--- | :--- |
| **Substitute Creation** | `Reflection.Emit` Type Building | Ada biaya CPU & alokasi *Dynamic Assembly* di awal (sekali per tipe), lalu di-cache oleh runtime proxy. |
| **Call Recording** | `List<ICall>` per proxy | Mengonsumsi memori heap untuk setiap pemanggilan fungsi palsu. Berpotensi memicu GC pressure jika loop pengujian memanggil mock jutaan kali. |
| **Structural Equivalence** | Reflection Graph Walk | Jauh lebih lambat dibanding `IEquatable<T>.Equals`. Tidak boleh digunakan untuk assertions data masif (>100.000 records). |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Gunakan Argument Matchers dengan Benar**: Gunakan `Arg.Is<T>(predicate)` saat perlu mencocokkan kriteria payload yang spesifik, dan `Arg.Any<T>()` untuk tipe yang tidak berdampak langsung pada alur logika bisnis (seperti `CancellationToken`).
- **Gunakan Class Fixture untuk State Berat**: Jika ada inisialisasi yang memakan biaya I/O tinggi (misal: Docker Testcontainers, WebApplicationFactory), gunakan `IClassFixture<T>` atau `ICollectionFixture<T>` agar tidak dieksekusi ulang di tiap pengujian.
- **Prefer Interface Mocking**: Mock antarmuka, bukan kelas konkret. Jika harus mem-mock kelas konkret, pastikan method yang diuji dideklarasikan sebagai `virtual`.

#### Don'ts
- **Don't Over-Verify**: Jangan memverifikasi setiap baris kode dengan `.Received()`. Verifikasi hanya *side effects* penting (menulis ke DB, memanggil gateway transaksi). Terlalu banyak verifikasi membuat pengujian rapuh (*fragile tests*) terhadap refactoring internal.
- **Don't Mock Data Transfer Objects (DTO/Records)**: DTO, Entities, Records, dan Values Objects tidak boleh di-mock dengan NSubstitute. Instansiasikan secara langsung sebagai data konkret.
- **Don't Mix Async-Sync Context**: Jangan memanggil `.Result` atau `.Wait()` di dalam unit test. Buat *signature* method pengujian selalu mengembalikan `async Task`.

#### Edge Cases
- **Record Types dengan `BeEquivalentTo`**:
  C# `record` mengompilasi implementasi `IEquatable<T>` secara otomatis. Secara *default*, FluentAssertions memprioritaskan pemanggilan `Equals` bawaan tipe tersebut dibanding melakukan perbandingan properti mendalam. 
  *Solusi*: Jika ingin memaksa perbandingan struktural penuh pada Record, gunakan opsi:
  ```csharp
  actualRecord.Should().BeEquivalentTo(expectedRecord, options => options.ComparingByMembers<MyRecord>());
  ```
- **Extension Methods Mocking**:
  Extension method pada dasarnya adalah *static method*. NSubstitute tidak dapat mem-mock method tersebut. Anda harus membungkus (*wrap*) ekstensi tersebut ke dalam *adapter interface* terlebih dahulu.

### 5. Tantangan Eksplorasi Mandiri

1. **Investigasi Parallel State Corruption**:
   Buat dua buah *test class* xUnit terpisah yang mengakses sebuah *static in-memory cache* (`static Dictionary<Guid, string>`). Amati bagaimana parallel execution bawaan xUnit menghasilkan *race condition* atau *intermittent test failure* (flaky test). Pecahkan masalah tersebut dengan menyatukan kedua kelas ke dalam `[Collection("SharedCacheGroup")]` atau ubah arsitekturnya menggunakan isolasi dependensi via instance injection.

2. **Benchmarking DynamicProxy vs Concrete Instance**:
   Gunakan **BenchmarkDotNet** untuk mengukur alokasi memori (*GC allocations*) dan eksekusi waktu (*time elapsed*) antara pemanggilan method konkret secara langsung berbanding pemanggilan method yang telah di-substitute menggunakan NSubstitute. Analisis mengapa terjadi perbedaan alokasi pada level Gen 0 GC.

3. **Complex Deep-Graph Diffing**:
   Bangun sebuah objek hierarki yang memiliki 3 level *nested collections* dan sebuah *circular reference*. Buat assertion menggunakan FluentAssertions `BeEquivalentTo` dengan skenario: mengecualikan (*excluding*) properti `CreatedAt` (bertipe `DateTimeOffset`) dan `AuditLog.Id`, namun tetap memvalidasi kesetaraan seluruh data lainnya secara rekursif.
