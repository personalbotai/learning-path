### 1. Konsep & Arsitektur Mendalam

Dalam paradigma pemrograman berorientasi objek tradisional C#, *class* beroperasi menggunakan semantik **Reference Equality** (kesetaraan berbasis identitas referensi memori), sedangkan *struct* beroperasi menggunakan **Value Equality** (kesetaraan berbasis data). Namun, struct tradisional mengandalkan implementasi `System.ValueType.Equals` yang sering kali menggunakan refleksi pada saat runtime (apabila struct mengandung referensi atau byte padding), sehingga menimbulkan penalti performa yang signifikan dan potensi *boxing*.

Diperkenalkan pada C# 9 (dan diperluas dengan `record struct` pada C# 10), fitur **Records** hadir untuk menjembatani kebutuhan data-centric modeling, seperti *Data Transfer Objects* (DTO) dan *Value Objects* dalam Domain-Driven Design (DDD).

```
                      ┌────────────────────────────────────────┐
                      │             C# Type System             │
                      └───────────────────┬────────────────────┘
                                          │
            ┌─────────────────────────────┴─────────────────────────────┐
            ▼                                                           ▼
   [ Reference Types ]                                         [ Value Types ]
  Heap-allocated (GC)                                        Stack/Inline Memory
 ┌───────────────────────┐                                   ┌───────────────────────┐
 │ class                 │ Reference Equality                │ struct                │ Value Equality
 ├───────────────────────┤                                   ├───────────────────────┤ (via reflection/ValueType)
 │ record / record class │ Value Equality                    │ record struct         │ Value Equality
 └───────────────────────┘ (Synthesized IEquatable<T>)       ├───────────────────────┤ (Synthesized, No reflection)
                                                             │ readonly record struct│ Immutable Value Equality
                                                             └───────────────────────┘
```

#### Fondasi Desain & Kompiler Roslyn
Ketika Anda mendeklarasikan sebuah `record`, kompiler C# (Roslyn) tidak menciptakan tipe baru di level Common Intermediate Language (CIL), melainkan menghasilkan class atau struct biasa yang secara otomatis dilengkapi (synthesized) dengan *boilerplate* esensial:
1. **Implementasi `IEquatable<T>`**: Menjamin kesetaraan berbasis nilai yang sangat cepat dan *type-safe* tanpa memerlukan *boxing* atau *unboxing*.
2. **Override `Equals(object)` dan `GetHashCode()`**: Algoritma hashing terintegrasi yang menghitung hash berdasarkan nilai seluruh properti publik, bukan alamat memori.
3. **Overload Operator `==` dan `!=`**: Mengevaluasi nilai, bukan alamat pointer.
4. **Metode Kloning Mutasi Non-destruktif (`<Clone>$` / `with`)**: Mekanisme untuk membuat salinan baru dengan modifikasi parsial sambil mempertahankan prinsip *immutability*.
5. **Karakteristik Posisi (Positional Syntax)**: Konstruktor primer (*primary constructor*) yang secara otomatis memetakan parameter ke *init-only properties* (`init`) dan menghasilkan metode `Deconstruct()`.

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengilustrasikan perbedaan fundamental antara `class`, `record class`, dan `record struct`, serta perilaku *value-based equality* dan mutasi *non-destructive*:

```csharp
using System;

// 1. Deklarasi Positional Record Class (Heap-allocated, Value-equality)
public record Currency(string Code, decimal Amount);

// 2. Deklarasi Readonly Record Struct (Stack-allocated, Zero GC Allocation, Immutable)
public readonly record struct GeoLocation(double Latitude, double Longitude);

// 3. Class Biasa (Reference-equality baseline)
public class TraditionalCurrency
{
    public string Code { get; }
    public decimal Amount { get; }

    public TraditionalCurrency(string code, decimal amount)
    {
        Code = code;
        Amount = amount;
    }
}

public class Program
{
    public static void Main()
    {
        // --- Uji Coba Reference Equality (Standard Class) ---
        var tc1 = new TraditionalCurrency("USD", 100m);
        var tc2 = new TraditionalCurrency("USD", 100m);
        Console.WriteLine($"Traditional Class Equals: {tc1 == tc2}"); // Output: False (Alamat memori berbeda)

        // --- Uji Coba Value-Based Equality (Record Class) ---
        var rc1 = new Currency("USD", 100m);
        var rc2 = new Currency("USD", 100m);
        
        // Membandingkan nilai, bukan referensi pointer
        Console.WriteLine($"Record Class Equals: {rc1 == rc2}");     // Output: True
        Console.WriteLine($"Reference Equals: {ReferenceEquals(rc1, rc2)}"); // Output: False
        Console.WriteLine($"Hash Match: {rc1.GetHashCode() == rc2.GetHashCode()}"); // Output: True

        // --- Non-Destructive Mutation (with expression) ---
        // Membuat instance baru di Heap tanpa merusak rc1 (immutable)
        var rc3 = rc1 with { Amount = 150m };
        Console.WriteLine($"Mutated Record: {rc3}"); // Output: Currency { Code = USD, Amount = 150 }
        Console.WriteLine($"rc1 tetap asli: {rc1.Amount}"); // Output: 100

        // --- Deconstruction ---
        var (code, amount) = rc1; // Memanggil synthesized Deconstruct
        Console.WriteLine($"Deconstructed: {code} bernilai {amount}");

        // --- Value-Based Equality pada Record Struct ---
        var loc1 = new GeoLocation(-6.2088, 106.8456);
        var loc2 = new GeoLocation(-6.2088, 106.8456);
        Console.WriteLine($"Record Struct Equals: {loc1 == loc2}"); // Output: True (Bebas alokasi GC)
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
Di balik layar, saat Roslyn menemukan sintaks `public record Currency(string Code, decimal Amount);`, ia men-generate kode CIL yang setara dengan kelas berikut:

```csharp
public class Currency : IEquatable<Currency>
{
    protected virtual Type EqualityContract => typeof(Currency);
    public string Code { get; init; }
    public decimal Amount { get; init; }

    public Currency(string Code, decimal Amount)
    {
        this.Code = Code;
        this.Amount = Amount;
    }

    public virtual bool Equals(Currency? other)
    {
        return (object)other != null &&
               EqualityContract == other.EqualityContract &&
               EqualityComparer<string>.Default.Equals(Code, other.Code) &&
               EqualityComparer<decimal>.Default.Equals(Amount, other.Amount);
    }

    public override bool Equals(object? obj) => Equals(obj as Currency);

    public override int GetHashCode()
    {
        return HashCode.Combine(EqualityContract, Code, Amount);
    }

    public static bool operator ==(Currency? left, Currency? right) => 
        left?.Equals(right) ?? ((object)right == null);

    public static bool operator !=(Currency? left, Currency? right) => !(left == right);

    // Kloning untuk ekspresi 'with'
    public virtual Currency <Clone>$() => new Currency(this.Code, this.Amount);
}
```

#### Mekanisme `EqualityContract`
Pada hierarki pewarisan `record class`, Roslyn menyintesis properti virtual tersembunyi bernama `EqualityContract`. Properti ini mengembalikan `Type` dari instans konkret saat runtime. Tujuannya adalah mencegah dua kelas turunan yang memiliki properti identik dianggap sama (`Equal`) jika tipe runtime mereka berbeda.

#### Alokasi Memori: `record class` vs `record struct`
1. **`record class`**: 
   - Dialokasikan di **Managed Heap**.
   - Pointer referensi disimpan di **Stack**.
   - Terikat dengan overhead Object Header (8 byte pada sistem 64-bit) dan Method Table Pointer (8 byte).
   - Penggunaan operator `with` akan mengalokasikan blok memori baru di Managed Heap dan memicu aktivitas *Garbage Collector* (GC).
2. **`record struct`**:
   - Dialokasikan secara inline (pada **Stack** jika berupa variabel lokal, atau terintegrasi di dalam Heap jika menjadi field dari sebuah kelas).
   - **Tanpa Alokasi Heap** dan bebas dari tekanan Garbage Collection.
   - Tidak menghasilkan `EqualityContract` karena struct tidak mendukung inheritance.
   - Dibandingkan struct standar, `record struct` secara otomatis meng-override `Equals` dan `GetHashCode`. Kompiler mengkalkulasi kesetaraan field demi field secara statis, **menghindari penalti refleksi runtime** yang terjadi pada `System.ValueType.Equals`.

### 4. Best Practices & Common Pitfalls

#### Do's
- Gunakan **`readonly record struct`** untuk tipe data berumur pendek (short-lived) dengan frekuensi alokasi tinggi (*high-throughput*), seperti representasi koordinat, vektor matematis, atau *message payload* parsial berukuran kecil (kurang dari atau sama dengan 16-24 bytes).
- Gunakan **`record class`** sebagai representasi *Data Transfer Objects* (DTO), entitas konfigurasi *immutable*, dan DDD *Value Objects* yang memerlukan hierarki polimorfik.
- Manfaatkan ekspresi **`with`** untuk menjaga prinsip immutability saat perlu mengubah satu atau dua properti dalam struktur data kompleks.

#### Don'ts
- **Jangan menggunakan *mutable collection* di dalam record**: Kompiler Roslyn hanya mengeksekusi **Shallow Equality**. Jika record mengandung `List<T>`, perbandingan `record1 == record2` hanya akan memeriksa referensi instans list tersebut, bukan elemen-elemen di dalamnya.
- **Hindari mendeklarasikan `record struct` mutable secara sembarangan**: Selalu prioritaskan `readonly record struct` kecuali mutasi in-place benar-benar dibutuhkan untuk optimalisasi performa ekstrem. Struct mutable rentan memicu *defensive copying* terselubung.
- Hindari ukuran `record struct` yang terlalu besar (> 64 bytes), karena operasi passing parameter dan evaluasi kesetaraan akan menyalin (*copying*) seluruh byte data pada stack, yang justru lebih mahal daripada mengalokasikan satu pointer heap.

#### Edge Cases: The Shallow Reference Trap
```csharp
public record Order(int Id, List<string> Items);

var list = new List<string> { "Keyboard" };
var o1 = new Order(1, list);
var o2 = new Order(1, new List<string> { "Keyboard" });

// Menghasilkan False!
// Meskipun isi datanya sama, referensi List<string> berbeda di Heap.
Console.WriteLine(o1 == o2); 

// SOLUSI: Gunakan ImmutableArray<T> / IReadOnlySet<T> dengan 
// Custom Equals, atau override Equals untuk deep-comparison.
```

### 5. Tantangan Eksplorasi Mandiri

1. **Uji Performa Kesetaraan (BenchmarkDotNet)**:
   Buat struct biasa tanpa implementasi `IEquatable<T>`, sebuah `record struct`, dan sebuah `record class`. Lakukan komparasi kesetaraan (`Equals`) sebanyak 1.000.000 iterasi menggunakan BenchmarkDotNet. Amati perbedaan alokasi memori (GC Alloc) dan durasi eksekusinya. Apa alasan `record struct` jauh lebih cepat dibandingkan standard `struct`?
2. **Inspeksi Dekompilasi IL Pewarisan Record**:
   Buat `public record Parent(string Name);` dan `public record Child(string Name, int Age) : Parent(Name);`. Gunakan *tool* seperti ILDasm, ILSpy, atau sharplab.io untuk melihat implementasi `EqualityContract`. Amati apa yang terjadi pada evaluasi `parent == child` ketika instans `Child` di-cast secara implisit menjadi tipe `Parent`.
