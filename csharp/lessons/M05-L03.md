## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Dalam ekosistem C#, *Task-based Asynchronous Pattern* (TAP) adalah standar de-facto untuk menangani operasi asinkron. Inti dari TAP adalah tipe `Task` dan `Task<T>`, yang merepresentasikan sebuah "janji" (promise) bahwa suatu operasi akan selesai di masa depan.

Namun, seiring dengan tuntutan performa tinggi (seperti pada ASP.NET Core), alokasi memori menjadi isu krusial. 
- **`Task`** adalah *reference type* (class). Setiap kali metode mengembalikan `Task`, runtime mengalokasikan memori di *Heap*, yang pada akhirnya membebani *Garbage Collector* (GC).
- **`ValueTask`** diperkenalkan untuk mengatasi masalah ini. Ia adalah *value type* (struct) yang bertindak sebagai *discriminated union*. Ia dapat menyimpan hasil secara langsung (jika operasi selesai secara sinkron) ATAU menyimpan referensi ke `Task` (jika operasi berjalan asinkron). Ini meminimalisir alokasi Heap pada jalur eksekusi yang sering selesai secara sinkron (misalnya, membaca dari *cache*).

Untuk orkestrasi konkurensi, C# menyediakan *combinators*:
- **`Task.WhenAll`**: Menunggu sekumpulan task selesai secara bersamaan. Jika satu gagal, ia tetap menunggu yang lain selesai sebelum melempar *exception*.
- **`Task.WhenAny`**: Selesai segera setelah **satu** dari sekumpulan task selesai (baik sukses, gagal, atau dibatalkan). Sangat berguna untuk implementasi *timeout* atau *redundancy* (mengambil respons tercepat dari beberapa server).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern yang mendemonstrasikan penggunaan `ValueTask` untuk optimasi *caching*, serta `WhenAll` dan `WhenAny` untuk orkestrasi I/O.

```csharp
using System;
using System.Collections.Generic;
using System.Diagnostics;
using System.Linq;
using System.Threading;
using System.Threading.Tasks;

public class AsyncOrchestrationDemo
{
    private readonly Dictionary<int, string> _userCache = new();

    // Menggunakan ValueTask karena kemungkinan besar data ada di cache (sinkron)
    public async ValueTask<string> GetUserAsync(int userId)
    {
        // Jalur Sinkron: Tidak ada alokasi Heap (Task) baru!
        if (_userCache.TryGetValue(userId, out var cachedUser))
        {
            Console.WriteLine($"[Cache Hit] User {userId}");
            return cachedUser;
        }

        // Jalur Asinkron: Mengambil dari "Database"
        Console.WriteLine($"[DB Fetch] Mengambil User {userId}...");
        await Task.Delay(1000); // Simulasi I/O
        
        var user = $"User_{userId}_Data";
        _userCache[userId] = user;
        return user;
    }

    public async Task RunDemoAsync()
    {
        var sw = Stopwatch.StartNew();

        // 1. Demonstrasi Task.WhenAll
        // Catatan: ValueTask harus diubah ke Task (.AsTask()) untuk digunakan di WhenAll
        var userIds = new[] { 1, 2, 3 };
        var fetchTasks = userIds.Select(id => GetUserAsync(id).AsTask());
        
        Console.WriteLine("Memulai Task.WhenAll...");
        string[] results = await Task.WhenAll(fetchTasks);
        Console.WriteLine($"WhenAll selesai dalam {sw.ElapsedMilliseconds}ms. Hasil: {string.Join(", ", results)}\n");

        // 2. Demonstrasi Task.WhenAny untuk Timeout Pattern
        sw.Restart();
        var slowApiTask = FetchDataFromSlowApiAsync();
        var timeoutTask = Task.Delay(1500); // Timeout 1.5 detik

        Console.WriteLine("Memulai Task.WhenAny (Timeout Pattern)...");
        var completedTask = await Task.WhenAny(slowApiTask, timeoutTask);

        if (completedTask == timeoutTask)
        {
            Console.WriteLine($"[Timeout] Operasi dibatalkan karena melebihi batas waktu ({sw.ElapsedMilliseconds}ms).");
        }
        else
        {
            // Aman untuk di-await lagi untuk mendapatkan hasil/exception
            var data = await slowApiTask; 
            Console.WriteLine($"[Sukses] Data diterima: {data}");
        }
    }

    private async Task<string> FetchDataFromSlowApiAsync()
    {
        await Task.Delay(2000); // Simulasi API lambat (2 detik)
        return "Data Penting";
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (State Machine)**: Saat kompilator C# melihat kata kunci `async`, ia mengubah metode tersebut menjadi sebuah *State Machine* (mengimplementasikan `IAsyncStateMachine`). Setiap pemanggilan `await` memecah metode menjadi *continuation*. Jika task yang di-await belum selesai (`IsCompleted == false`), state machine akan mendaftarkan dirinya ke *awaiter* dan mengembalikan kontrol ke *thread pool*.
- **Alokasi Memori / Resource**: 
  - `Task` selalu mengalokasikan memori di Heap (minimal 72 bytes per instance di x64).
  - `ValueTask` berukuran 16 bytes (di x64) dan dialokasikan di *Stack*. Jika metode `ValueTask` selesai secara sinkron, tidak ada alokasi Heap sama sekali.
  - Untuk skenario asinkron tingkat lanjut tanpa alokasi, C# menggunakan antarmuka `IValueTaskSource` yang memungkinkan *pooling* objek state.
- **Trade-offs**: `ValueTask` memiliki batasan ketat. Karena ia adalah *struct* yang bisa di-reuse di bawah kap (melalui `IValueTaskSource`), Anda **tidak boleh** meng-await `ValueTask` lebih dari satu kali, dan tidak boleh memanggil `.GetAwaiter().GetResult()` sebelum operasi selesai. Jika butuh melakukan hal tersebut, konversikan ke `Task` menggunakan `.AsTask()`.

### 4. Best Practices & Common Pitfalls

- **Do's**:
  - Gunakan `Task.WhenAll` untuk mengeksekusi panggilan I/O independen secara paralel (misal: memanggil 3 API berbeda sekaligus).
  - Gunakan `ValueTask` pada metode yang berada di *hot-path* (dipanggil ribuan kali per detik) dan memiliki probabilitas tinggi untuk selesai secara sinkron (misal: membaca buffer, cache).
  - Selalu gunakan `CancellationToken` bersamaan dengan `WhenAny` jika mengimplementasikan *timeout*, agar task yang lambat benar-benar dihentikan, bukan hanya ditinggalkan berjalan di *background* (mencegah *resource leak*).

- **Don'ts**:
  - **JANGAN** meng-await `ValueTask` lebih dari sekali. Perilakunya *undefined* dan dapat menyebabkan *corrupted state*.
  - **JANGAN** menggunakan `.Wait()` atau `.Result` pada `Task`. Ini memblokir *thread* yang sedang berjalan dan merupakan penyebab utama *Deadlock* (terutama di aplikasi UI atau ASP.NET klasik tanpa `ConfigureAwait(false)`).
  - **JANGAN** menggunakan `ValueTask` secara default untuk semua metode. Ukuran struct `ValueTask` lebih besar dari referensi `Task`, sehingga jika metode selalu berjalan asinkron, `ValueTask` justru menambah overhead penyalinan data di *Stack*.

- **Edge Cases (Exception Handling di WhenAll)**:
  Jika beberapa task di dalam `Task.WhenAll` melempar *exception*, `await Task.WhenAll(...)` **hanya akan melempar exception dari task pertama yang gagal**. Untuk melihat semua error, Anda harus menangkap `Exception` dan memeriksa properti `Task.Exception.InnerExceptions` dari task gabungan tersebut.

### 5. Tantangan Eksplorasi Mandiri

1. **Custom Timeout Extension**: Buatlah sebuah *Extension Method* `Task<T> WithTimeout<T>(this Task<T> task, TimeSpan timeout)` yang menggunakan `Task.WhenAny` di dalamnya, dan otomatis melempar `TimeoutException` jika waktu habis.
2. **WhenAll Exception Aggregation**: Buatlah sekumpulan 3 `Task` di mana 2 di antaranya melempar exception yang berbeda (misal: `InvalidOperationException` dan `ArgumentNullException`). Gunakan `Task.WhenAll`, tangkap error-nya, dan cetak *semua* pesan error menggunakan `AggregateException`.
3. **IValueTaskSource Exploration**: Pelajari dan buat implementasi sederhana dari `IValueTaskSource<T>` untuk membuat *object pool* yang mengembalikan `ValueTask` tanpa alokasi memori sama sekali untuk operasi asinkron berulang.
