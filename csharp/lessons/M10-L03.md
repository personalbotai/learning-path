## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

**Structured Logging** adalah pergeseran paradigma dari mencatat log sebagai teks datar (plain text) menjadi mencatat log sebagai objek data terstruktur (biasanya JSON atau format *key-value*). Tujuannya adalah agar log dapat diindeks, dicari (queried), dan dianalisis secara efisien oleh sistem *log management* (seperti Elasticsearch, Seq, Datadog, atau Splunk).

Dalam ekosistem .NET, **Serilog** adalah standar *de facto* untuk *structured logging*. Serilog menggunakan konsep **Message Templates** yang memisahkan antara teks statis dan data dinamis. 

Di sisi lain, **OpenTelemetry (OTel)** adalah standar industri yang *vendor-agnostic* untuk *Observability* (Logs, Metrics, dan Traces). Menggabungkan Serilog dengan OpenTelemetry berarti kita menggunakan Serilog untuk ergonomi *developer* (API logging yang nyaman dan *enrichment*) dan menggunakan protokol OTLP (OpenTelemetry Protocol) untuk mengekspor data log tersebut ke *backend* observabilitas secara terstandarisasi, memastikan log terhubung erat dengan *Distributed Tracing* (TraceId dan SpanId).

**Arsitektur Serilog + OTel:**
1. **Log Event:** Representasi in-memory dari sebuah log (Timestamp, Level, MessageTemplate, Properties, Exception).
2. **Enrichers:** Middleware yang menyuntikkan properti tambahan ke setiap Log Event (misal: `MachineName`, `ThreadId`, `CorrelationId`).
3. **Sinks:** Destinasi output log. Dalam konteks ini, kita menggunakan `Serilog.Sinks.OpenTelemetry` untuk mengubah Serilog Event menjadi OTLP Log Record.
4. **OTLP Exporter:** Mengirim *batch* log via gRPC atau HTTP/Protobuf ke kolektor (seperti Jaeger, Aspire Dashboard, atau OTel Collector).

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi pada aplikasi ASP.NET Core (.NET 8) yang mengonfigurasi Serilog untuk mengekspor log terstruktur ke *endpoint* OpenTelemetry.

**Kebutuhan NuGet:**
```bash
dotnet add package Serilog.AspNetCore
dotnet add package Serilog.Sinks.OpenTelemetry
dotnet add package Serilog.Enrichers.Environment
```

**Program.cs**
```csharp
using Serilog;
using Serilog.Events;
using Serilog.Context;

var builder = WebApplication.CreateBuilder(args);

// 1. Konfigurasi Serilog
Log.Logger = new LoggerConfiguration()
    .MinimumLevel.Information()
    .MinimumLevel.Override("Microsoft", LogEventLevel.Warning) // Kurangi noise dari framework
    .Enrich.FromLogContext()
    .Enrich.WithMachineName()
    .Enrich.WithProperty("Application", "PaymentGateway.API")
    // 2. Konfigurasi OpenTelemetry Sink (OTLP)
    .WriteTo.OpenTelemetry(options =>
    {
        options.Endpoint = "http://localhost:4317"; // Endpoint OTel Collector (gRPC)
        options.Protocol = Serilog.Sinks.OpenTelemetry.OtlpProtocol.Grpc;
        options.ResourceAttributes = new Dictionary<string, object>
        {
            ["service.name"] = "PaymentGateway",
            ["service.version"] = "1.0.0"
        };
    })
    // Fallback ke console untuk debugging lokal
    .WriteTo.Console(outputTemplate: "[{Timestamp:HH:mm:ss} {Level:u3}] {Message:lj} {Properties:j}{NewLine}{Exception}")
    .CreateLogger();

// Ganti default logger .NET dengan Serilog
builder.Host.UseSerilog();

var app = builder.Build();

app.MapPost("/api/payments", async (PaymentRequest request, ILogger<Program> logger) =>
{
    // 3. Menggunakan LogContext untuk menyuntikkan CorrelationId ke semua log di scope ini
    using (LogContext.PushProperty("TransactionId", Guid.NewGuid()))
    {
        logger.LogInformation("Processing payment for user {UserId} with amount {Amount}", 
            request.UserId, request.Amount);

        try
        {
            await ProcessPaymentAsync(request);
            
            // 4. Destructuring operator (@) untuk melog seluruh objek sebagai JSON node
            logger.LogInformation("Payment successful. Details: {@PaymentRequest}", request);
            return Results.Ok();
        }
        catch (Exception ex)
        {
            logger.LogError(ex, "Payment failed for user {UserId}", request.UserId);
            return Results.Problem("Payment processing failed.");
        }
    }
});

app.Run();

async Task ProcessPaymentAsync(PaymentRequest request) => await Task.Delay(100);
public record PaymentRequest(string UserId, decimal Amount, string Currency);
```

**Penjelasan Kode:**
- `WriteTo.OpenTelemetry`: Mengirim log langsung ke OTel Collector menggunakan gRPC.
- `{@PaymentRequest}`: Simbol `@` (Destructuring) memberitahu Serilog untuk menserialisasi objek `request` menjadi struktur JSON, bukan memanggil `.ToString()`.
- `{UserId}`: Properti ini akan diekstrak dan dikirim sebagai *key-value pair* terpisah ke OTel, memungkinkan pencarian seperti `UserId = 'user-123'` di *dashboard* observabilitas.

### 3. Cara Kerja di Balik Layar (Under the Hood)

- **Eksekusi & Runtime (Message Template Parser):**
  Saat Anda memanggil `LogInformation("User {Id} logged in", 123)`, Serilog tidak langsung menggabungkan string. Ia menggunakan *parser* untuk memecah string menjadi *Abstract Syntax Tree* (AST) yang memisahkan teks statis dan token `{Id}`. Template `"User {Id} logged in"` ini kemudian di-**cache** dalam memori (menggunakan *hash table* internal). Pada pemanggilan berikutnya dengan template yang sama, Serilog melewati fase *parsing* dan langsung memetakan nilai `123` ke token `{Id}`.
- **Alokasi Memori / Resource:**
  - **Destructuring (`@`):** Menggunakan *Reflection* pada eksekusi pertama untuk membaca properti objek, lalu membuat *compiled delegate* (di-cache) untuk akses properti yang sangat cepat dan rendah alokasi memori pada eksekusi berikutnya.
  - **OTel Exporter:** Berjalan secara asinkron di *background thread* menggunakan `Channel<T>` (Bounded Queue). Log dikumpulkan dalam *batch* (misal: per 512 log atau per 2 detik) sebelum dikirim via jaringan. Ini memastikan aplikasi utama tidak terblokir (non-blocking) oleh latensi jaringan.
- **Trade-offs:**
  Menyimpan log terstruktur membutuhkan lebih banyak *bandwidth* jaringan dan penyimpanan (storage) di *backend* dibandingkan *plain text*. Namun, *trade-off* ini sangat sepadan dengan kecepatan dan akurasi saat melakukan *troubleshooting* insiden di *production*.

### 4. Best Practices & Common Pitfalls

- **Do's:**
  - **Gunakan penamaan properti yang konsisten (Semantic Naming):** Gunakan `{UserId}` di seluruh layanan, jangan mencampur dengan `{CustomerId}` atau `{Id}` untuk entitas yang sama.
  - **Manfaatkan `LogContext`:** Gunakan middleware untuk menyuntikkan `TraceId`, `TenantId`, atau `CorrelationId` di awal *request HTTP* agar semua log dalam *request* tersebut memiliki konteks yang sama.
- **Don'ts:**
  - **JANGAN PERNAH menggunakan String Interpolation (`$""`) di dalam parameter template log.**
    *Salah:* `logger.LogInformation($"User {userId} logged in");`
    *Alasan:* Ini akan membuat *Message Template* baru untuk setiap *user* (misal: `"User 1 logged in"`, `"User 2 logged in"`). Cache internal Serilog akan penuh (*Memory Leak*) dan log tidak bisa di-query berdasarkan *key*.
  - **Jangan men-destructure objek raksasa:** Hindari `{@Entity}` jika entitas tersebut memiliki relasi *database* yang dalam (misal EF Core *navigation properties*), karena dapat memicu *circular reference* atau alokasi memori masif.
- **Edge Cases:**
  - **Sink Failure:** Jika OTel Collector mati, *background queue* Serilog bisa penuh. Secara default, Serilog akan men-drop log baru (lossy) untuk mencegah aplikasi kehabisan memori (OOM). Pastikan Anda mengaktifkan `Serilog.Debugging.SelfLog.Enable(Console.Error)` untuk mendeteksi kegagalan internal Serilog.

### 5. Tantangan Eksplorasi Mandiri

1. **Custom Destructuring Policy:** Buatlah implementasi `IDestructuringPolicy` di Serilog untuk secara otomatis menyensor (masking) properti sensitif seperti `Password`, `CreditCard`, atau `Token` saat objek di-log menggunakan operator `@`.
2. **Trace & Log Correlation:** Integrasikan `OpenTelemetry.Instrumentation.AspNetCore` dan pastikan `TraceId` dan `SpanId` secara otomatis tersuntik ke dalam log Serilog Anda, lalu visualisasikan di Jaeger atau Aspire Dashboard.
3. **Dynamic Log Level:** Implementasikan mekanisme untuk mengubah *Log Level* (misal dari `Warning` ke `Debug`) secara dinamis saat aplikasi sedang berjalan (runtime) tanpa perlu me-restart aplikasi, menggunakan `LoggingLevelSwitch` milik Serilog.
