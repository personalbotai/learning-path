## 📖 Materi Lengkap

### 1. Konsep & Arsitektur Mendalam

Secara historis, `interface` dalam C# adalah kontrak murni (*pure contract*). Interface mendefinisikan *apa* yang harus dilakukan suatu tipe, tanpa menyediakan implementasi *bagaimana* hal tersebut dilakukan. Namun, evolusi runtime .NET memperkenalkan dua lompatan arsitektural besar:

1. **Default Interface Methods / DIM (C# 8.0, .NET Core 3.0+)**:
   Sebelum C# 8, menambahkan *member* baru ke interface yang telah dipublikasikan akan merusak semua tipe yang mengimplementasikannya (*breaking change*). DIM memungkinkan penambahan implementasi default langsung di dalam interface. Konsep ini memfasilitasi interoperabilitas dengan API Android (Java) dan iOS (Swift) yang memiliki fitur serupa (Traits), serta memungkinkan API berevolusi tanpa merusak *backward compatibility*.

2. **Static Virtual Members in Interfaces (C# 11, .NET 7+)**:
   Sebelum C# 11, interface hanya memodelkan polimorfisme pada tingkat *instance*. Metode static tidak dapat bersifat `virtual` atau `abstract`. Hal ini menghambat pembuatan abstraksi matematis atau pola *factory*. Static Virtual Members memungkinkan interface mendefinisikan *static contracts* (seperti operator overload, factory methods, dan parsing logika) yang harus diimplementasikan secara statis oleh tipe konkret. Fitur ini merupakan fondasi dari arsitektur **Generic Math** di .NET.

```
       +-------------------------------------------------------+
       |                       INTERFACE                       |
       +-------------------------------------------------------+
       | - Instance Contract       : void Execute();           |
       | - Default Implementation  : void Log() { ... }        |  <-- DIM (C# 8)
       | - Static Abstract Contract: static abstract T Parse() |  <-- C# 11
       +-------------------------------------------------------+
                                  ^
                                  | implements
       +-------------------------------------------------------+
       |                    CONCRETE STRUCT                    |
       +-------------------------------------------------------+
       | - Execute() implementation                            |
       | - Static Parse() implementation                       |
       | * No boxing overhead when constrained via Generics    |
       +-------------------------------------------------------+
```

### 2. Implementasi & Contoh Kasus Nyata

Contoh berikut mengimplementasikan domain finansial: sebuah interface `IMonetaryAmount<TSelf>` yang memanfaatkan kontrak statis untuk Generic Math & parsing, serta Default Interface Method untuk fallback audit logging.

```csharp
using System.Globalization;

namespace AdvancedInterfaceArchitecture;

// 1. Interface dengan Static Abstract Members & Default Interface Method
public interface IMonetaryAmount<TSelf> 
    where TSelf : IMonetaryAmount<TSelf>
{
    // Instance contract
    decimal Value { get; }
    string CurrencyCode { get; }

    // Static Abstract Members (Wajib diimplementasikan secara statis oleh TSelf)
    static abstract TSelf Zero { get; }
    static abstract TSelf operator +(TSelf left, TSelf right);
    static abstract TSelf Parse(string input, IFormatProvider? provider = null);

    // Default Interface Method (DIM) - Menyediakan fungsionalitas tanpa merusak implementor
    void LogTransaction(TextWriter writer)
    {
        // Implementasi default fallback
        writer.WriteLine($"[{DateTime.UtcNow:O}] Transaksi: {CurrencyCode} {Value:N2}");
    }
}

// 2. Concrete Implementation (Value Type untuk efisiensi memori)
public readonly struct Rupiah : IMonetaryAmount<Rupiah>
{
    public decimal Value { get; }
    public string CurrencyCode => "IDR";

    public Rupiah(decimal value)
    {
        Value = value;
    }

    // Implementasi Static Abstract Property
    public static Rupiah Zero => new(0m);

    // Implementasi Static Abstract Operator
    public static Rupiah operator +(Rupiah left, Rupiah right)
    {
        return new Rupiah(left.Value + right.Value);
    }

    // Implementasi Static Abstract Factory Method
    public static Rupiah Parse(string input, IFormatProvider? provider = null)
    {
        if (decimal.TryParse(input, NumberStyles.Currency, provider, out var val))
        {
            return new Rupiah(val);
        }
        throw new FormatException($"Input '{input}' bukan format Rupiah yang valid.");
    }

    // Override opsional terhadap DIM
    public void LogTransaction(TextWriter writer)
    {
        writer.WriteLine($"[AUDIT-IDR] {Value.ToString("C", new CultureInfo("id-ID"))}");
    }
}

// 3. Consumer yang memanfaatkan Polimorfisme Statis via Generic Constraints
public static class FinancialCalculator
{
    // Menggunakan Static Abstract Members tanpa mengalokasikan memori (Zero Boxing)
    public static T TotalAmount<T>(IEnumerable<T> transactions) where T : IMonetaryAmount<T>
    {
        T sum = T.Zero; // Mengakses static abstract property dari generic type parameter
        foreach (var item in transactions)
        {
            sum += item; // Menggunakan static abstract operator (+)
        }
        return sum;
    }
}

public class Program
{
    public static void Main()
    {
        var items = new List<Rupiah>
        {
            Rupiah.Parse("50000"),
            Rupiah.Parse("25000"),
            new Rupiah(15000)
        };

        // Static Polymorphism in Action
        Rupiah total = FinancialCalculator.TotalAmount(items);
        Console.WriteLine($"Total: IDR {total.Value}"); // Total: IDR 90000

        // Eksekusi DIM
        IMonetaryAmount<Rupiah> monetaryRef = total;
        monetaryRef.LogTransaction(Console.Out);
    }
}
```

#### Catatan Kode Penting:
1. `where TSelf : IMonetaryAmount<TSelf>`: Pola *Curiously Recurring Template Pattern (CRTP)*. Memungkinkan interface mereferensikan tipe implementor dalam tanda tangan *method/operator*.
2. `T.Zero` & `sum += item`: Pemanggilan langsung metode statis yang diikat pada tipe `T` pada saat kompilasi tanpa perlu instance objek.
3. Pemanggilan DIM (`LogTransaction`): Jika struct `Rupiah` tidak mendefinisikan implementasi sendiri, metode ini **hanya** dapat dipanggil jika variabel dicasting ke interface (`IMonetaryAmount<Rupiah>`).

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime
- **Virtual Stub Dispatch (VSD)**: Untuk instance interface biasa, CLR menggunakan mekanisme VSD (stubs bertingkat: *lookup stub*, *dispatch stub*, dan *resolve stub*) untuk menavigasi Interface Method Table (IMT).
- **Default Interface Methods (DIM)**: DIM **tidak** disalin ke dalam vtable milik class/struct implementor. DIM hidup di dalam tipe interface itu sendiri. Akibatnya:
  ```csharp
  Rupiah r = new Rupiah(100);
  // r.LogTransaction(Console.Out); // COMPILE ERROR jika Rupiah tidak mendefinisikannya!
  ((IMonetaryAmount<Rupiah>)r).LogTransaction(Console.Out); // VALID: Dispatch via Interface reference
  ```
  Resolusi resolusi pewarisan DIM menggunakan aturan *Most Specific Override*: Jika `IBase` menyediakan implementasi A, dan `IDerived : IBase` menimpanya dengan implementasi B, tipe yang mengimplementasikan `IDerived` akan selalu mengeksekusi B.

- **Static Virtual Members**: Ditangani oleh JIT compiler melalui kamus generic (*Generic Context Dictionaries*). Ketika metode generic seperti `FinancialCalculator.TotalAmount<T>` dikompilasi untuk `Rupiah` (sebuah struct), runtime menghasilkan spesialisasi native machine code (*monomorphization*). Akses ke `T.Zero` atau `operator +` diubah menjadi instruksi pemanggilan metode statis langsung (sering kali langsung di-*inlining* oleh JIT).

#### Alokasi Memori & Resource
- **Boxing/Unboxing**:
  - Mengakses instance method interface pada `struct` via referensi interface (misal: `((IMonetaryAmount<Rupiah>)r).LogTransaction(...)`) menyebabkan operasi **Boxing** (alokasi memori di managed heap).
  - Mengakses Static Virtual Member melalui generic constraint `where T : IMonetaryAmount<T>` bersifat **Zero-Allocation**. Struct `T` tidak pernah di-box menjadi `object` karena JIT langsung mengeksekusi static method tabel tipe `T`.

#### Trade-offs
- DIM memperkenalkan kompleksitas resolusi inheritance mirip *multiple inheritance* (seperti Diamond Problem). Developer harus mengerti hirarki interface untuk memastikan kode tidak memicu `TypeLoadException` akibat pemanggilan ambigu di runtime.
- Static Virtual Members meningkatkan beban *JIT Compilation* karena instansiasi generic pada *value type* menghasilkan kode assembly unik per tipe (bisa meningkatkan ukuran biner / *code bloat*).

### 4. Best Practices & Common Pitfalls

#### Do's:
1. **Gunakan Static Virtual Members untuk Factory & Parsing**: Gunakan `IParsable<TSelf>` atau `IFactory<TSelf>` untuk abstraksi instansiasi tipe dalam pemrograman generik daripada menggunakan refleksi `Activator.CreateInstance<T>()`.
2. **Gunakan DIM untuk Kompatibilitas API Non-Destruktif**: Tambahkan fitur baru pada interface yang sudah terdistribusi tanpa mematahkan kontrak implementor lama.
3. **Manfaatkan Generic Constraints**: Selalu gunakan `where T : IInterface` ketika berhadapan dengan `struct` agar runtime mengeliminasi *boxing* dan mengaktifkan JIT inlining.

#### Don'ts:
1. **Jangan Menyimpan State di DIM**: Interface tidak dapat memiliki instance field. Upaya meniru state menggunakan `ConditionalWeakTable` di dalam DIM membuat kode sulit di-debug dan berisiko menimbulkan *memory leak*.
2. **Jangan Menggantikan Abstract Base Class dengan DIM**: Jika suatu arsitektur membutuhkan state enkapsulasi internal (protected field, constructor logic lifecycle), gunakan `abstract class`, bukan interface dengan DIM.
3. **Jangan Mengekspos Method Eksplisit DIM di API Public**: Pahami bahwa DIM didesain untuk *explicit interface implementation*. Jika Anda ingin method tersebut tersedia langsung pada tipe instance tanpa casting, tipe tersebut harus mengimplementasikannya secara eksplisit.

#### Edge Cases (The Diamond Problem pada DIM):
Jika dua interface mendefinisikan DIM yang sama dan sebuah class mengimplementasikan keduanya:
```csharp
public interface IWriterA { void Write() => Console.WriteLine("A"); }
public interface IWriterB { void Write() => Console.WriteLine("B"); }

public class Document : IWriterA, IWriterB 
{
    // AMBIGUITAS: Kompiler akan melempar error jika Document tidak 
    // mendefinisikan ulang (re-implement) Write() secara eksplisit.
    public void Write() => Console.WriteLine("Resolved Document");
}
```

### 5. Tantangan Eksplorasi Mandiri

1. **Implementasi Serializer Generik Menggunakan Static Abstract**:
   Buat interface `IBinarySerializable<TSelf> where TSelf : IBinarySerializable<TSelf>`.
   - Definisikan metode static abstract: `static abstract TSelf Deserialize(ReadOnlySpan<byte> buffer);`
   - Definisikan instance method: `void Serialize(Span<byte> destination);`
   - Implementasikan pada struct `PacketHeader` dan tulis generic runner yang mendeserialisasi rentetan byte tanpa terjadi alokasi memori sama sekali (Zero-Allocation).

2. **Diagnosa Eksekusi DIM pada Value Types**:
   Tulis kode benchmark menggunakan `BenchmarkDotNet` yang membandingkan:
   - Pemanggilan metode biasa pada `struct`.
   - Pemanggilan metode DIM pada `struct` melalui generic constraint (`void Run<T>(T val) where T : IWithDim`).
   - Pemanggilan metode DIM pada `struct` yang di-cast ke interface (`((IWithDim)val).Execute()`).
   Amati perbedaan alokasi memori (heap allocation) dan waktu eksekusinya.
