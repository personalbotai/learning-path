### 1. Konsep & Arsitektur Mendalam

Dalam pemetaan objek-relasional (Object-Relational Mapping / ORM) dengan Entity Framework Core (EF Core), relasi antar entitas mendefinisikan bagaimana struktur tabel relasional (RDBMS) dipetakan ke dalam graf objek C#. Relasi ini ditopang oleh dua komponen fundamental: **Navigation Property** (properti navigasi pada level objek) dan **Foreign Key (FK)** (kunci asing pada level basis data).

```
   +-------------------------------------------------------------+
   |                        METADATA MODEL                       |
   |           (IModel / IEntityType / IForeignKey)              |
   +-------------------------------------------------------------+
          |                       |                        |
          v                       v                        v
     [One-to-One]           [One-to-Many]           [Many-to-Many]
   Principal <-> Dependent  Parent <-> Child(ren)   Left <-> Join <-> Right
     (Single Ref)             (Collection)            (Skip Navigation)
```

EF Core mengelompokkan relasi berdasarkan kardinalitas:
1. **One-to-One (1:1)**: Satu entitas berelasi tepat dengan satu entitas lainnya. Dalam model relasional, ini diwujudkan dengan FK unik pada salah satu tabel (*dependent entity*) yang merujuk ke *primary key* (PK) dari tabel lainnya (*principal entity*).
2. **One-to-Many (1:N)**: Satu entitas *principal* dapat memiliki referensi ke nol atau banyak entitas *dependent*. Sisi dependent menyimpan nilai scalar FK yang menunjuk ke PK principal.
3. **Many-to-Many (N:M)**: Dua entitas dapat saling memiliki banyak referensi. RDBMS murni tidak mendukung relasi N:M secara native tanpa tabel perantara (*join table*). Sejak EF Core 5.0+, EF Core mendukung **Skip Navigation**, memungkinkan pemetaan N:M secara langsung pada graf objek C# tanpa harus mendeklarasikan entitas *join table* secara eksplisit jika tabel tersebut hanya berisi komposit FK.

#### Metadata Engine & Convention vs Fluent API
Saat `DbContext` diinisialisasi pertama kali, EF Core membangun *In-Memory Metadata Model* (`IModel`) melalui tahapan:
1. **Convention Discovery**: Mendeteksi relasi berdasarkan konvensi penamaan properti (misal: properti `BlogId` otomatis dianggap FK untuk navigasi `Blog`).
2. **Data Annotations**: Atribut seperti `[ForeignKey]`, `[InverseProperty]`.
3. **Fluent API (`OnModelCreating`)**: Konfigurasi imperatif tingkat lanjut yang memiliki preseden tertinggi.

Di runtime, EF Core menggunakan metadata ini untuk melakukan **Relationship Fixup**, yaitu mekanisme otomatis untuk menyinkronkan properti navigasi dan FK saat entitas dimuat (*tracked*) ke dalam memori `ChangeTracker`.

### 2. Implementasi & Contoh Kasus Nyata

Berikut adalah implementasi modern menggunakan **.NET 8/9**, C# 12, dan EF Core dengan pendekatan Fluent API yang ketat (*fully explicit configuration*). Skenario ini memodelkan sistem e-commerce:
- **1:1**: `Customer` <-> `CustomerProfile`
- **1:N**: `Customer` <-> `Order`
- **N:M murni**: `Order` <-> `Tag` (melalui *skip navigation*)
- **N:M dengan Payload**: `Order` <-> `OrderItem` <-> `Product` (dengan atribut `Quantity` & `UnitPrice`)

```csharp
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;

namespace EfCoreRelationships.Domain;

// --- ENTITIES ---

public sealed class Customer
{
    public int Id { get; set; }
    public required string Name { get; set; }

    // 1:1 Navigation (Dependent: CustomerProfile)
    public CustomerProfile? Profile { get; set; }

    // 1:N Navigation (Children: Orders)
    public ICollection<Order> Orders { get; set; } = new List<Order>();
}

public sealed class CustomerProfile
{
    public int Id { get; set; }
    public string? Bio { get; set; }
    public string? PhoneNumber { get; set; }

    // Foreign Key ke Customer
    public int CustomerId { get; set; }
    public Customer Customer { get; set; } = null!;
}

public sealed class Order
{
    public int Id { get; set; }
    public DateTime OrderDateUtc { get; set; } = DateTime.UtcNow;

    // Foreign Key ke Customer
    public int CustomerId { get; set; }
    public Customer Customer { get; set; } = null!;

    // N:M dengan Payload via Join Entity
    public ICollection<OrderItem> OrderItems { get; set; } = new List<OrderItem>();

    // N:M Murni via Skip Navigation
    public ICollection<Tag> Tags { get; set; } = new List<Tag>();
}

public sealed class Product
{
    public int Id { get; set; }
    public required string Sku { get; set; }
    public decimal BasePrice { get; set; }

    public ICollection<OrderItem> OrderItems { get; set; } = new List<OrderItem>();
}

// Join Entity dengan Payload
public sealed class OrderItem
{
    public int OrderId { get; set; }
    public Order Order { get; set; } = null!;

    public int ProductId { get; set; }
    public Product Product { get; set; } = null!;

    public int Quantity { get; set; }
    public decimal UnitPrice { get; set; }
}

public sealed class Tag
{
    public int Id { get; set; }
    public required string Name { get; set; }

    public ICollection<Order> Orders { get; set; } = new List<Order>();
}

// --- CONFIGURATIONS (FLUENT API) ---

public sealed class CustomerConfiguration : IEntityTypeConfiguration<Customer>
{
    public void Configure(EntityTypeBuilder<Customer> builder)
    {
        builder.HasKey(c => c.Id);
        builder.Property(c => c.Name).HasMaxLength(150).IsRequired();

        // 1:1 Relationship Configuration
        builder.HasOne(c => c.Profile)
               .WithOne(p => p.Customer)
               .HasForeignKey<CustomerProfile>(p => p.CustomerId)
               .OnDelete(DeleteBehavior.Cascade);

        // 1:N Relationship Configuration
        builder.HasMany(c => c.Orders)
               .WithOne(o => o.Customer)
               .HasForeignKey(o => o.CustomerId)
               .OnDelete(DeleteBehavior.Restrict);
    }
}

public sealed class OrderConfiguration : IEntityTypeConfiguration<Order>
{
    public void Configure(EntityTypeBuilder<Order> builder)
    {
        builder.HasKey(o => o.Id);

        // N:M Murni (Skip Navigation) dengan Tabel Perantara Implisit
        builder.HasMany(o => o.Tags)
               .WithMany(t => t.Orders)
               .UsingEntity<Dictionary<string, object>>(
                   "OrderTagJoin",
                   j => j.HasOne<Tag>().WithMany().HasForeignKey("TagId").OnDelete(DeleteBehavior.Cascade),
                   j => j.HasOne<Order>().WithMany().HasForeignKey("OrderId").OnDelete(DeleteBehavior.Cascade));
    }
}

public sealed class OrderItemConfiguration : IEntityTypeConfiguration<OrderItem>
{
    public void Configure(EntityTypeBuilder<OrderItem> builder)
    {
        // Composite Key untuk Join Table
        builder.HasKey(oi => new { oi.OrderId, oi.ProductId });

        builder.HasOne(oi => oi.Order)
               .WithMany(o => o.OrderItems)
               .HasForeignKey(oi => oi.OrderId)
               .OnDelete(DeleteBehavior.Cascade);

        builder.HasOne(oi => oi.Product)
               .WithMany(p => p.OrderItems)
               .HasForeignKey(oi => oi.ProductId)
               .OnDelete(DeleteBehavior.Restrict);

        builder.Property(oi => oi.UnitPrice).HasPrecision(18, 2);
    }
}

// --- CONTEXT REGISTRATION ---

public class ApplicationDbContext : DbContext
{
    public ApplicationDbContext(DbContextOptions<ApplicationDbContext> options) : base(options) { }

    public DbSet<Customer> Customers => Set<Customer>();
    public DbSet<Order> Orders => Set<Order>();
    public DbSet<Product> Products => Set<Product>();
    public DbSet<Tag> Tags => Set<Tag>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        base.OnModelCreating(modelBuilder);
        // Memindai assembly untuk semua implementasi IEntityTypeConfiguration
        modelBuilder.ApplyConfigurationsFromAssembly(typeof(ApplicationDbContext).Assembly);
    }
}
```

### 3. Cara Kerja di Balik Layar (Under the Hood)

#### Eksekusi & Runtime: Relationship Fixup & SQL Generation
Saat EF Core mengeksekusi kueri berelasi menggunakan eager loading (`.Include()`):
1. **Query Compilation**: Expression tree LINQ dianalisis oleh `IQueryTranslationPreprocessor` dan diterjemahkan ke SQL. Jika foreign key didefinisikan *non-nullable*, EF Core mengompilasi navigasi tersebut menjadi `INNER JOIN`. Jika *nullable*, dikompilasi menjadi `LEFT JOIN`.
2. **Materialization & Identity Map**: Saat *data reader* membaca baris data, entitas dibuat di memori. `ChangeTracker` merekam entitas-entitas ini ke dalam struktur internal *Identity Map* berdasarkan PK-nya.
3. **Relationship Fixup**:
   - Jika Anda memuat `Customer` dan `Order` secara terpisah dalam scope konteks yang sama, EF Core otomatis menghubungkan `customer.Orders.Add(order)` dan `order.Customer = customer`.
   - Proses ini ditenagai oleh *snapshot generation* pada kelas internal `InternalEntityEntry`.

#### Alokasi Memori / Resource
- **State Tracking Overhead**: Setiap relasi yang dilacak memakan alokasi memori heap untuk menyimpan *reference state* dan *original values* (untuk *concurrency* dan *dirty checking*). Menggunakan kueri read-only tanpa `.AsNoTracking()` akan melipatgandakan footprint memori karena grafik relasi dipertahankan pada Change Tracker.
- **Collection Navigations**: EF Core mengharuskan navigasi bertipe `ICollection<T>` diinisialisasi (misalnya `new List<T>()`). Jika dibiarkan `null`, EF Core akan menginstansiasinya secara otomatis via reflection menggunakan tipe `HashSet<T>` secara default jika targetnya berupa antarmuka, yang mengonsumsi alokasi ekstra di heap.

#### Trade-offs
| Pendekatan | Kelebihan | Kelemahan |
| :--- | :--- | :--- |
| **Skip Navigation (N:M Implisit)** | Domain model bersih tanpa kelas penghubung artifisial. | Tidak dapat menambahkan metadata transaksi (misal: `CreatedAt`, `Discount`) tanpa merombak schema. |
| **Join Entity Eksplisit (N:M)** | Fleksibel; bisa memuat payload dan audit columns. | Menambah kompleksitas navigasi domain (harus melompat melalui join entity: `order.OrderItems.Select(x => x.Product)`). |

### 4. Best Practices & Common Pitfalls

#### Do's
- **Definisikan Properti Foreign Key secara Eksplisit**: Jangan hanya bergantung pada navigasi. Mendeklarasikan `public int CustomerId { get; set; }` menghindari pembuatan *Shadow Properties* yang tersembunyi dan mempercepat operasi mutasi tanpa perlu me-load objek navigasi secara penuh.
- **Gunakan Index pada Foreign Key**: EF Core otomatis membuat indeks pada FK di database migration, namun selalu pastikan integritasnya saat mendesain index komposit.
- **Gunakan `DeleteBehavior.Restrict` atau `NoAction` untuk Data Finansial/Audit**: Hindari `Cascade Delete` tidak sengaja yang dapat menghapus ribuan rekaman anak karena baris parent terhapus.

#### Don'ts
- **Hindari Mengembalikan Graph Entity Langsung ke API JSON Serializer**: Mengembalikan entitas yang memiliki relasi dua arah (bidirectional) memicu `JsonException: A possible object cycle was detected`. Selalu gunakan Projection ke DTO (`.Select()`).
- **Hindari Mengabaikan Nullability pada FK**: Jika FK bernilai `int` (non-nullable), EF Core mengasumsikan relasi bersifat *Required*. Jika bernilai `int?` (nullable), relasi dianggap *Optional*. Kesalahan penentuan tipe akan menghasilkan schema DB yang salah (`NULL` vs `NOT NULL`).

#### Edge Cases
- **1:1 Ambiguity on Dependent Selection**: Pada relasi 1:1, EF Core seringkali tidak tahu tabel mana yang menjadi pemegang Foreign Key jika hanya ditentukan lewat navigasi tanpa Fluent API. Selalu tentukan sisi dependent menggunakan `.HasForeignKey<DependentType>(d => d.PrincipalId)`.

### 5. Tantangan Eksplorasi Mandiri

1. **Self-Referencing Relationship**:
   - Buat sebuah entitas `Employee` yang memiliki properti `Manager` (1:1/1:N self-reference) dan `DirectReports` (koleksi bawahan).
   - Konfigurasikan relasi ini menggunakan Fluent API dengan `DeleteBehavior.Restrict`.
   - Periksa skema DDL hasil migrasinya (`dotnet ef migrations add`) dan telusuri mengapa `Cascade Delete` pada self-referencing relationship ditolak oleh SQL Server.

2. **Split Queries vs Cartesian Explosion**:
   - Buat skenario di mana satu `Customer` memiliki 20 `Orders`, dan setiap `Order` memiliki 10 `OrderItems`.
   - Jalankan kueri:
     ```csharp
     context.Customers.Include(c => c.Orders).ThenInclude(o => o.OrderItems).ToList();
     ```
   - Amati log SQL yang dihasilkan: Berapa banyak duplikasi baris data pada *result set* akibat Cartesian Product?
   - Tambahkan operator `.AsSplitQuery()` dan bandingkan jumlah eksekusi SQL kueri serta dampaknya terhadap penggunaan memori runtime.
